# 产品方向与交互偏好

修改产品方向、模型策略、表单交互或自动记录体验时查阅；已落地的详细合同以 [`docs/architecture.md`](../architecture.md) 与 [`docs/ui/design.md`](../ui/design.md) 为准，[工程记忆入口](memory.md)拥有协作偏好。

## 模型选择与自动记录偏好

- **切换模型生效边界**：更换 ClinMesh 模型后，新发起请求与新的人工重试使用新模型；已在途请求保持原模型，已有成功结果仅在显式重新生成时调用新模型（合同见[场景定义](../architecture/simulation.md)）。
- **安静直接记录与无短截止**：问诊自动整理直接写入病历草稿，医生直接编辑正文，界面不展示待补充提示、“查看依据”或逐条确认保留步骤，问诊栏不常驻堆叠“整理失败”；实时质控只检查本次就诊已提供资料，自动记录沿用常规模型超时配置而不设 6 秒短截止，且交付不捆绑真实模型固定压测（详见[统一直接记录](../decisions/implemented/architecture/2026-10-15-unified-direct-document-recording.md)与[病历质控收敛](../decisions/implemented/architecture/2026-10-19-recording-quality-consolidation.md)）。
- **保存反馈静默刷新**：设置或表单已成功保存且界面已应用返回值时只提示“已保存”，后续后台目录/查询自动刷新失败静默处理，不弹出“已保存但刷新失败”等内部同步噪声；首次加载与实际保存失败正常报错。

## 工作台布局与交互偏好

- **宿主分屏与层级**：ClinMesh 与 DSH 会话保持左右分屏（窄窗按比例收缩而不改上下堆叠或自动全屏，亦不采用左列镜像预设，见[镜像布局回退](../decisions/implemented/feature/2026-10-22-dsh-mirror-layout-rollback.md)）；DSH 原生文件全屏须完整覆盖 HIS，不抬高 Surface `z-index` 抢占宿主弹层；DSH 侧栏与新会话固定展示 ClinMesh 品牌标志与标语。
- **视觉动效与极简表单**：仅在 Agent 真实执行期间显示“环绕柔光”，人工审阅、批准、拒绝与手工提交保持静态；临床表单不写“留空表示未记录”等冗余说明，用必填项红色 `*` 区分，折叠组只留标题与展开动作，对默认免填患者弱化灰色显示“月经史、孕产史”（详见[临床 UI 设计合同](../ui/design.md)）。

## 长期方向与参考优先级

- **长期演进目标**：支持 Agent 扮演患者或岗位人员参与全院多方仿真、教学复盘与持续自我改进（RSI）；前端先立住贴合医护直觉的高密度临床工作台，再自然嵌入可见的 Agent 协作舞台。
- **外部参考优先级**：中国公立医院正向/逆向业务流与交接以 OpenHIS 为首要业务参照，FHIR R5 仓储、历史、Search 与审计以 Medplum 为首要基础设施参照，`references/DSH-AGUI-demo` 等案例仅参考交互布局；不照搬外部物理架构或未闭环的占位菜单。
