# 影像检查使用指南

本文面向第一次接触放射检查功能的管理员、医生和开发者，说明胸片与胸部 CT 平扫从准备到阅片的完整用法，以及界面上每种状态的含义。设计边界见 [系统架构](architecture.md) 的 8.7 与 10.7 节，素材来源与许可见 [影像素材清单](../imaging-assets/README.md)。

## 功能概览

门诊医生可以为合成病例开立胸片或胸部 CT 平扫，几秒后得到放射报告，在浏览器里阅片，确认已阅后才能完诊。

影像不是生成的，而是公开数据集 LIDC-IDRI 中已去标识的真实影像，称为素材。患者身份、病史和就诊过程仍然全部是合成的。系统按合成病例的来源疾病为它挑选一套相符的素材；找不到相符素材的病例不会得到影像，也不会被当成正常。

因此，一个病例能否看到片子取决于三件事同时成立：

1. 素材已经安装到本机并且已发布。
2. 病例已经运行过影像准备，且对应检查的结果是“已就绪”。
3. 病例已经开始门诊就诊，医生签发了放射申请。

第一件事由部署者完成一次，第二件事由管理员在“模拟数据”页完成，第三件事是医生的日常操作。下面按这个顺序说明。

## 部署者：安装素材

素材不随仓库分发，按清单从公开数据源下载到本机：

```sh
pnpm imaging:sync
pnpm imaging:verify
```

下载、离线修复、目录位置和备份见 [部署教程的影像素材一节](deployment.md#影像素材)。没有安装素材时系统照常运行，医生看到放射服务“本院当前未开展”。

开始门诊就诊还需要患者档案（Patient Persona），它由 `CLINMESH_AI_*` 配置的模型生成，见 [部署教程](deployment.md) 第 4 节。没有配置时“生成患者档案”无法完成，病例不能开始就诊，也就无法开立检查。

## 管理员：查看素材与准备病例

以管理员登录，进入“模拟数据”。与影像有关的入口有两个：页面上的“影像覆盖清单”，以及每位患者详情里的“影像准备”。两者只有管理员能看到。

### 影像覆盖清单

覆盖清单回答“本机现在能为哪些病例提供哪些检查”。它按检查列出适配条目，每个条目写明适用人群、所用素材，以及素材的两个状态：

| 显示 | 含义 | 处理 |
| --- | --- | --- |
| 已安装 / 未安装 | 像素是否在本机素材目录中且与清单一致 | 未安装时运行 `pnpm imaging:sync` |
| 已复核发布 | 报告通过了自动核对并有人工复核签署，可以用于病例 | 无需处理 |
| 未发布：尚未复核 等 | 素材还不能用于病例，冒号后是原因 | 点“复核预览”对照影像检查报告，再按界面给出的命令签署 |

清单下方列出“明确未覆盖的疾病”，以及当前患者库的统计：已准备多少例，每项检查已就绪、待处理、未覆盖各多少例。点“准备下一批病例”会为尚未按当前清单准备过的病例运行影像准备，每次最多 50 例。

### 为单个病例运行影像准备

打开患者详情，在“影像准备”里点“按当前清单重新准备”。准备只读取病例的来源病史并写下结果，不改动病例。

### 读懂“影像准备”面板

面板第一行是这次准备的编号和病例阶段：

- “准备修订 N”：这是该病例第 N 次准备的结果。每次准备都保留，旧结果不会被覆盖。
- “病例尚未开始，素材跟随最新一次准备”：病例还没有开始门诊就诊。此时清单更新或重新准备，结果可以变化。
- “病例已开始，已绑定的素材不再替换”：病例已经开始就诊，已经配好的素材被固定，重试、重放和以后的清单更新都不会换掉它。

下面每项检查各有一个状态。状态是“未覆盖”或“待处理”时，后面跟着原因：

| 状态 | 原因 | 含义 | 可以怎么做 |
| --- | --- | --- | --- |
| 已就绪 | — | 该检查已配好素材。下面一行是素材编号和报告修订，再下面是依据：来源中的哪条疾病或检查记录 | 让病例开始就诊，医生即可开单 |
| 未覆盖 | 来源没有可用依据 | 病例的来源病史里既没有适配规则认识的阳性疾病，本次就诊的疾病也不在可按阴性处理的范围内。系统不知道这位患者的胸部影像应该是什么样，所以不配片 | 这是正常结果，不是故障。需要能看片的病例时见下一节 |
| 未覆盖 | 疾病在明确未覆盖清单中 | 来源有肺炎、慢阻肺等会改变胸部影像、而目前没有相应素材的疾病 | 无法处理，除非新增对应素材 |
| 未覆盖 | 没有与年龄、性别相符的素材 | 疾病有对应条目，但患者的年龄或性别不在条目适用范围内，例如女性肺癌患者 | 无法处理，除非新增对应素材 |
| 未覆盖 | 适配条目没有该检查的素材 | 病例命中的条目只有另一种检查的素材。例如命中“仅 CT”的阴性条目时，胸片显示这一条 | 正常结果；该病例只能做另一种检查 |
| 未覆盖 | 素材尚未通过复核 | 条目对应的素材还没有发布 | 在覆盖清单中完成复核签署后重新准备 |
| 待处理 | 病例既有事实与素材冲突 | 来源里有与素材矛盾的既往手术史（例如肺移植、胸骨切开、瓣膜置换、起搏器），或者阴性条目的病例曾患肺癌 | 不配片；系统不会为了用上素材而改写病例 |

举例：一位来源病史只有体检和高血压随访的患者，两项检查都会显示“未覆盖 · 来源没有可用依据”。医生仍然可以为他开立检查，但申请会以“未取得结果”结束。

想知道一个病例为什么是某个结果，可以展开同一页的“本次病例真值”，查看来源中的本次就诊疾病，再对照覆盖清单中各条目的适用条件。

### 得到一个能看片的病例

当前清单覆盖两类病例，完整条件见 [覆盖矩阵](../imaging-assets/README.md#覆盖矩阵)：

| 病例 | 胸片 | 胸部 CT 平扫 |
| --- | --- | --- |
| 40–79 岁男性，来源有未缓解的疑似或确诊肺癌 | 右肺结节影 | 右肺实性肿块 |
| 本次就诊为急性支气管炎的成人 | 未见结节，或没有胸片素材 | 左肺微小结节，或未见结节 |

用默认设置生成的患者，本次就诊可以是任何疾病，大多数会得到“未覆盖”。要定向得到支气管炎病例，在“生成患者”的高级设置中勾选“限制 Synthea 模块”，只选 `bronchitis`，“患者人数”填 1，然后运行影像准备。患者人数大于 1 时，只要其中一位没有合格的本次就诊，整批都会失败。

支气管炎病例按病例来源稳定地落入两个阴性条目之一，所以有的病例胸片和 CT 都可用，有的只有 CT。存活的肺癌患者在 Synthea 中很少见，定向获得的方法记录在 [工程记忆](memory/memory.md)。

## 医生：开单、阅片、确认已阅

1. 在“待诊”选择患者，点“开始首诊”。
2. 打开“检验”页签，下半部分是“放射检查”。在“检查项目”中选择胸片或胸部 CT 平扫，填写“检查指征”，点“签发申请”。也可以先“保存草稿”。
3. 申请出现在下方列表中。放射系统在后台受理、检查并签发报告，页面会自行刷新，不需要手动刷新。
4. 报告出现后点“打开影像”阅片。
5. 影像成功显示之后，“确认已阅”才可以点击。确认后这份报告不再阻塞完诊。
6. 需要把结论写进病历时点“摘要插入病历”。摘要追加到病历“辅助检查”，写明报告版本与签发时间，随病历签署一并保存；同一版报告重复插入只会提示，不会写两遍。

医生看不到素材编号、来源信息或匹配原因。同一服务同时只能有一条进行中的申请。

### 申请状态

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| 已开具 | 申请已签发，等待放射系统受理 | 取消申请 |
| 已受理、检查中 | 放射系统正在处理 | 等待 |
| 已报告 | 报告已签发，尚未确认 | 打开影像、摘要插入病历、确认已阅 |
| 医生已阅 | 报告已确认 | 打开影像、摘要插入病历 |
| 未取得结果 | 这个病例的这项检查没有可用影像，或系统连续三次执行失败；没有报告 | 重试、取消申请 |
| 已取消 | 申请已取消 | — |

“未取得结果”通常对应管理员面板中的“未覆盖”或“待处理”；也可能是素材清单损坏等系统故障，修复后重试即可。重试只在原因已经消除时才有用，例如素材已经修复，或管理员在素材发布后重新运行了影像准备；否则应取消申请。

### 阅片器

| 操作 | 方式 |
| --- | --- |
| 翻片 | 鼠标滚轮、拖动“图像序号”滑块，或方向键与 PageUp/PageDown |
| 缩放 | “+”“−”按钮，或按住 Ctrl 滚动；只有一幅图像时直接滚动 |
| 平移 | 拖动图像 |
| 调窗 | CT 可选“肺窗”“纵隔窗”“骨窗”；打开“拖动调窗”后，左右拖动改变窗宽，上下拖动改变窗位 |
| 反相 | 胸片的“反相”按钮 |
| 切换序列 | 有多个序列时点“序列 1”“序列 2” |
| 全屏 | “全屏”与“退出全屏”；返回后病例和未提交的输入保留 |
| 恢复默认 | “复位” |

图像左侧是患者右侧，边缘的 R、L、A、P 标出方向。CT 的图像序号从头侧到足侧递增，报告中的“Im 85”就是第 85 幅。

阅片器显示“影像暂不可用”时，说明本机的像素文件缺失或损坏：报告仍可阅读，但不能确认已阅。由部署者运行 `pnpm imaging:repair` 修复，修复后无需重启。

## 管理员：更正报告

当前账号兼有管理员岗位时，每份报告下方有“更正报告（管理员）”。更正不能改写报告文字，只能填写同一素材另一份已复核发布的“报告内容修订号”和更正原因。提交后系统按该修订重新签发报告，原报告和原确认保留在“历史报告”中，新报告需要医生重新确认。

可选的修订号在“影像覆盖清单 → 复核预览”中查看。素材只有一份报告修订时无法更正；新增修订的步骤见 [影像素材清单](../imaging-assets/README.md#新增或修订素材)。

## Agent 与 CLI

Agent 通过报告参与诊疗，不读取像素。在 DSH 中，页面 Tools 可以读取放射申请与报告、替人展开阅片器、填写草稿，并准备开立、取消、重试、已阅和更正的提案；每个正式动作都由登录的人确认，影像没有在人面前显示过时已阅提案会被拒绝。各 Tool 的可用条件见 [Agent 操作与反馈](agent-capabilities.md)。

任务 Agent 通过 CLI 执行同样的操作，命令与输入格式见 `clinmesh-doctor` Skill：

```sh
clinmesh doctor case imaging-services list --case-id <case-id>
clinmesh encounter imaging-request draft set --input @imaging.json --idempotency-key <key>
clinmesh encounter imaging-request issue --input @imaging-issue.json --idempotency-key <key>
clinmesh imaging-request cancel --input @imaging-cancel.json --idempotency-key <key>
clinmesh imaging-request retry --input @imaging-retry.json --idempotency-key <key>
clinmesh imaging-report acknowledge --input @imaging-acknowledgement.json --idempotency-key <key>
clinmesh imaging-report correct --input @imaging-correction.json --idempotency-key <key>
```

## 常见问题

**放射服务显示“本院当前未开展”。** 本机没有该检查的已发布素材，此时可以保存草稿但不能签发。在“影像覆盖清单”查看素材是未安装还是未发布，分别运行 `pnpm imaging:sync` 或完成复核签署。这个状态与具体病例无关。

**签发后显示“未取得结果”。** 这个病例的这项检查没有配到素材。请管理员在患者详情的“影像准备”中查看原因；如果从未准备过，先运行影像准备再点“重试”。

**“影像准备”显示“尚未准备。”** 该病例还没有运行过影像准备。点“按当前清单重新准备”。

**“确认已阅”是灰色的。** 需要先点“打开影像”并等图像显示出来。如果阅片器提示影像暂不可用，先修复素材。

**完诊时提示有报告未确认。** 最新的放射报告尚未确认已阅，包括更正后重新签发的报告。

**页面提示没有可用的影像素材清单或适配规则。** Server 找不到 `imaging-assets/` 清单，例如使用了不包含清单的 Docker 一键镜像。阅片功能在源码运行方式下使用。
