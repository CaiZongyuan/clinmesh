# ClinMesh UI 设计合同

ClinMesh Web 与 Desktop 共享一套面向临床工作的界面语言：安静、高密度、可快速扫读。患者事实、业务状态和当前任务优先于装饰，界面通过表面、边线、排版和间距建立层级。

## 核心原则

1. **安静的密度**：在单个视口中呈现足够的临床上下文，但不用装饰色、大标题或重阴影竞争注意力。
2. **表面优先于阴影**：常驻区域使用中性背景、1px 边线和稳定间距；阴影只属于菜单、Dialog、Sheet 和 Toast 等临时覆盖层。
3. **动作紧邻对象**：确认诊断、签署病历、签发处方、签发申请、取消和更正位于所操作事实附近，长表单的提交区保持稳定。
4. **渐进展开**：默认只显示当前任务所需信息；使用 Tabs、Sheet 和菜单切换上下文，不把完整病例堆成一条长页面。
5. **工作区连续性**：侧栏、顶栏、当前岗位和设置入口在页面间保持稳定，避免重复 Dashboard 和跳转迷失。
6. **语义色克制**：色彩用于选中、焦点、成功、警告和风险，不作为大面积装饰。

| 内容 | Owner |
| --- | --- |
| 主题、语义色、字体、字号和圆角 token | [`packages/ui/src/styles.css`](../../packages/ui/src/styles.css) |
| Button、Field、Table、Tabs、Dialog 等 primitive | [`packages/ui/src/components/`](../../packages/ui/src/components/) |
| Web 工作区布局和平台交互 | [`apps/web/src/app/`](../../apps/web/src/app/) |
| 真实组件目录 | [`apps/web/src/app/component-catalog.tsx`](../../apps/web/src/app/component-catalog.tsx) |

`packages/ui` 不包含 Patient、Encounter 或 Medication 等业务概念。业务页通过公开组件入口和语义 token 组合界面，不复制 primitive 样式。Mobile 使用独立 React Native UI，不导入 DOM 组件。

## 应用框架

### 桌面端

| 区域 | 合同 |
| --- | --- |
| 设置侧栏 | standalone 设置保留 220px 导航，折叠为 48px；岗位工作台不显示应用侧栏，DSH 使用宿主导航 |
| 顶栏 | 48px；依次是队列开关、唯一页面 H1、当前患者、办理流程、助手状态摘要、全屏和人物菜单；页头窄于 40rem 时隐藏流程 |
| 主内容 | 可收起的队列卡和主卡；主卡依次是患者头部、页签、内容区与按需显示的操作栏，没有右栏 |
| 应用表面 | 主区域与侧栏通过背景、边线和最大 8px 圆角区分，无常驻阴影 |

岗位切换位于右上角人物菜单，按门诊、住院、系统分组（岗位名与显示姓名相同时只展示一次，保留真实姓名；单一病区环境隐藏多余病区选择器）。挂号、收费和药房的门诊／住院切换位于队列顶部，收费员与药师共用列表头下拉、挂号沿用分段切换，模式与页头标题及发布给助手的工作区保持同步。管理员以“模拟数据”为首页，分为“演示准备”（虚拟时间、患者生成、带影响说明与二次确认的重置及素材准备）和“患者库”（列表、详情、Persona 与来源历史）。DSH 工作台默认使用 `workspace` 左右分屏（左临床工作台、右原生会话），顶栏支持“全屏 ClinMesh / 返回 DSH 分屏”及“收起会话 / 展开会话”无刷新往返，见[DSH 原生 Surface 决策](../decisions/implemented/architecture/2026-08-30-dsh-native-clinmesh-surface.md)。

### 移动端

standalone 设置在 `< 768px` 时以 Sheet 承接侧栏。岗位布局使用下文的内容容器断点；多列表单回落为单列，表格在自身容器内水平滚动，不通过缩小字号隐藏数据。此处只描述 Web 的窄屏，原生 Mobile 不在该布局合同内。

## 密度与排版

| 用途 | 标准档尺寸 | 规则 |
| --- | ---: | --- |
| 顶栏标题 | 13px | 600 字重，单行截断 |
| 业务分区标题 | 13–16px | 与内容紧密对齐 |
| 正文与控件 | 14px | 1.5 行高，不随视口缩放 |
| 表格与数据 | 13px | 日期、时间、金额和检验值使用等宽数字 |
| 辅助信息 | 11–12px | 使用 `muted-foreground` |
| 按钮 | 24 / 28 / 32 / 36px | XS / SM / 默认 / LG |
| 常规控件圆角 | 6px | Button、Input、Select、Tabs |
| 业务表面圆角 | 最大 8px | 独立重复项、弹层和真正的工具容器 |

Web“设置 → 外观”的字号偏好提供“标准 / 较大 / 大”三档，按 `100% / 112.5% / 125%` 调整语义字体 token 并作为设备本地 Web 偏好持久化（“标准”兼具重置功能，Desktop 固定消费标准档 token）。字号比例只作用于语义字体 token，图标、控件高度、间距和页面几何尺寸保持不变；standalone 根字号保持 `16px`，DSH Surface 不修改宿主根元素。全局字距为 0，日期、时间、金额和检验值启用等宽数字特性，不使用负字距、视口缩放字号或超大仪表盘标题。

## 颜色与主题

业务组件只消费语义 token，不直接写入 Tailwind 色阶：

| Token | 用途 |
| --- | --- |
| `background` / `foreground` | 主画布与默认文字 |
| `card` / `popover` | 独立业务项与临时覆盖层 |
| `primary` | 中性主操作；浅色近黑、深色近白 |
| `info` / `ring` | 蓝色交互、选中、Agent 参与和键盘焦点 |
| `success` | 正常、通过和已完成 |
| `warning` | 待复核、偏高和需要注意 |
| `destructive` | 过敏、危急、删除和不可逆风险 |
| `secondary` / `muted` | 中性状态、辅助表面和弱化文字 |
| `border` / `input` | 分隔线和控件边界 |

Web、Desktop 与 DSH 使用同一套浅灰画布、白色卡片和中性主按钮；语义 token 优先读取 `--dsw-*` 宿主变量，standalone 使用相同回退值，浅深主题下普通文字与状态边界分别满足 4.5:1 和 3:1 对比度。DSH 中浮层底色保持不透明（浅色 `#ffffff`、深色 `#353638`），本地主题入口仅在 standalone Web 显示（写入 `clinmesh.preferences:v1`），DSH 完全跟随宿主，详见[Surface 与 Host 边界](../architecture/agent-integration.md#71-surface-与-host-边界)。

## 共用卡片工作台

应用侧 `workspace-card-layout.tsx` 统一承载队列开关、流程进度（放不下时缩为圆点、当前环节名与 `n/总数`）、患者头部、按实测宽度将尾部溢出收入“更多”的分区页签（页签旁黄色待办数 `> 0` 时显示，蓝色“助手 n”建议条数独立显示），以及仅在存在主动作或刚完成时出现的底部操作栏（包含关键数字、阻断／缺项说明与单一主按钮，不可逆动作原位切换为返回／确认条，纯等待或只读阶段不渲染空操作栏）；组合归属见[工作台卡片组合决策](../decisions/implemented/architecture/2026-10-30-workspace-card-composition.md)。

| ClinMesh 内容容器宽度 | 布局合同 |
| --- | --- |
| `>= 800px` | 队列卡与主卡并排撑满可用高度，内容在各自卡内独立滚动；收起队列时整列移除 |
| `< 800px` | 队列默认收起，主卡占满；顶栏按钮以浮层打开队列，选择、点遮罩或按 Esc 后收起并将焦点归还顶栏按钮 |

通用交互与内联 Agent 反馈模式：

- **提交态、缺项门禁与选项样式**：提交中主按钮换为转圈“正在…”并变暗锁定主卡，结束后焦点回到主按钮；缺少必填项时主按钮使用虚线框并写明“还差：…”。写入业务数据的表单选项选中后整块实心带勾（勾不计入无障碍名）；仅切换视图或筛选的按钮组与分段页签一致，采用浅灰底槽加 `Tabs.Indicator` 白色滑块且不带勾；队列选中行为浅蓝底加蓝边，系统减少动效偏好下关闭过渡动画。
- **患者队列行与完成通知**：门诊医生、分诊与药房共用患者行结构（姓名与状态、补充信息、完整业务号码与边界内复制按钮，超长号码或大字号完整换行不裁切；医生队列不设头像或额外灰底，三个等宽计数页签共享同一白色滑块 DOM 过渡）。Toast 挂载于 `.clinmesh-web-root` 右下角（`bottom: 62px; right: 18px`，最多堆叠 2 条、3.5 秒自动消退，正文指针穿透以免遮挡下方行内确认，仅显式操作与关闭按钮接收点击）。分诊与门诊收费处理完自动跳下一条；挂号与门诊药房保留当前结果并在操作栏提供“下一位：姓名”；门诊医生完诊后留在只读病例。
- **Agent 内联柔光与静态审阅条**：Agent 非 proposal 动作在工作区边缘绘制蓝色环绕柔光，草稿写入字段标虚线框与“助手”来源（人工修改后移除）；行级 `.propose` 在对象行内审阅，整页 `.propose` 在底部操作栏审阅，同一时刻仅一个且全程保持静态，详见[人工审阅语义](../architecture/agent-integration.md#75-人工审阅语义)。
- **收费与药房卡片编排**：门诊收费抬头姓名、说明与合计紧凑同排，应收表格与表尾排除已收挂号费（仅作只读说明），药品总项下附同版本原处方明细行（不参与二次合计）；费用更正、医保待遇与支付记录按需展开，“选择多项收费”独立弹窗承接跨筛选保留的已选清单（区分本页全选、清空勾选与二次确认丢弃草稿）及合并收款预览／逐分配原款退款（资金规则见[收费、结算与医保](../architecture/billing-and-insurance.md)）。门诊药房先展示一行审核结论与头部过敏警示，再在药品条目内就地展示批次与本次发放数量（发药与库存规则见[处方、医嘱与药事](../architecture/orders-and-pharmacy.md)）。

## 门诊医生工作台

患者头部最多占主卡一半高度（长主诉、多条过敏或大字号超出时独立纵向滚动，下方业务区独立滚动），依次呈现姓名、性别年龄、等宽可复制门诊号（`registrationNumber`，缺号显示“未记录”，加载失败不保留上一病例横幅，不以患者号补齐）、主诉、分诊、过敏、病例状态、生命体征标签、可展开“完诊清单 n/7”及“助手已准备”状态跳转行。无责任人的 `awaiting-doctor` 病例将开始接诊固定在页签上方，接诊前不开放写入；底部完诊操作栏原位列出缺项并支持跳转（门禁与生命周期见[门诊业务流程](../architecture/outpatient-workflows.md)）。

病例主区依次提供五个业务页签：

| 分区 | 界面承载内容 |
| --- | --- |
| 问诊记录 | 实线边框输入区，医生消息居右强调色、患者消息居左中性色，时间与说话人同行 |
| 病历记录 | 12 字段结构化编辑器、签署预览、签署后修订草稿暂存／放弃与线性修订表单 |
| 诊断 | 主次诊断组（最多八项）、自动保存草稿与可继续修订的正式确认视图 |
| 检验检查 | 检验、功能检查、放射与病理分类切换，开具入口、前置门禁直达引导、可筛选申请列表、两列事实详情及连续阅读窗口 |
| 处方 | 用药结论切换、「本院药房」与「国家参考目录」双页签选药、包装选择、前置门禁直达引导、开具／撤回与补充病历入口 |

关键表单与弹窗编排：

- **12 字段结构化病历网格**：双列断点下“主诉”与末尾“随访”通栏显示，中间按“现病史／既往史 → 家族史／过敏史 → 月经史／孕产史 → 体格检查／辅助检查 → 评估／处置”成对排列，必填项旁统一标红色 `*`，选填项不堆叠“可留空”赘述；`clinicalHistory.showByDefault === false` 时弱化文字，且两项均空时合并为单条跨两列折叠栏（展开后与双列网格齐平，仅全空时提供“收起”）。未提交病历按 `caseId` 在前端会话隔离；诊断、检验与处方草稿静止后自动保存，不设手动“保存草稿”按钮；住院证采用单栏病区与原因表单。
- **共享两栏开具窗口与连续报告阅读器**：诊断、处方与检验检查共用“左主列模式开关／选择入口 + 右辅助列推荐／待开具面板”布局，以及同款两栏 Dialog（左栏搜索与紧凑目录列表，在 1101×720 弹窗中至少容纳 11–12 行；右栏选中项目详情、填写项与待确认清单，左右独立滚动、窄视口上下排列；共享 Dialog 默认直属正文 `16px` 内边距，自定义分区留白 wrapper 显式设 `p-0`）。诊断首项默认主诊断、移除主诊断自动晋升首条；处方选药跨源候选在行内置灰说明需分开开具（见[外延处方分轨决策](../decisions/implemented/architecture/2026-11-05-outpatient-external-prescription-split.md)）；检查无已签发申请时直接平铺目录与待开清单，有申请后左侧保留列表、右侧展示选中两列详情（窄分栏支持列表与详情往返）。同次就诊全部报告在统一连续阅读窗口查看并集中勾选已阅，放射与病理须真实阅片器成功渲染后才允许勾选（见[检验、检查与报告](../architecture/examinations-and-reports.md)）。临床界面不添加“合成”前缀或“教学环境”横幅。

## 住院工作台

住院七岗位通过 `inpatient-layout.tsx` 组合“单行患者头部 + 条件第二提醒行 + 可访问阶段页签（入科分床、诊断医嘱、检查检验、手术、费用、出院结算、病案；溢出收入‘更多’，点开晋升为带 `×` 临时页签；对勾／圆点／待办状态图标设为装饰 `aria-hidden`） + 独立滚动正文 + 底部操作栏”，设计取舍见[住院原型组合决策](../decisions/implemented/architecture/2026-11-03-inpatient-prototype-composition.md)：

- **单行患者头部与惰性阶段挂载**：常态单行依次呈现姓名、性别年龄、状态、床位、按虚拟时间计算的住院日（已出区定格在 `departedAt`）及本岗主业字段（收费员为预交金与累计费用，病案员为病案号，登记员为住院号、预交金与登记时间，药师为住院号与校对时间，医保办为归档费用），右侧放置本岗首要入口（收费员为补退方向摘要，住院医生为常驻 DRG 费用进度小条与唯一助手跟进／AI 用量菜单），其余编号与病区收进“住院信息”菜单；第二行仅在有临床提醒、待确认 Agent 审阅／PCI 助手已准备菜单或检验异常摘要时出现（药师药物过敏提示常驻）。未访问阶段不挂载或请求详情，已访问阶段保持挂载以保留输入与预览基线，办理成功或后台刷新不抢走当前停留页签。
- **医生医嘱、报告与三步手术界面**：诊断医嘱与检查检验复用两栏开具弹窗、单条医嘱「执行记录 (n)」弹窗与连续阅读集中已阅窗口。手术页按“① 选型参数 → ② 手术耗材 → ③ 术前准备”渐进排列，首行、步骤与底栏主按钮共用单一当前动作判定；申请手术弹窗承载临床六要素（按术式类别默认推荐执行地点与麻醉方式并允许人工改选），术前知情同意通过「手术知情同意书」模态弹窗完整展示一术一议风险条款、替代方案及签署登记，签署后在手术卡片与病案页按需折叠区提供只读「查看知情同意书」弹窗；实际术式与计划一致时“开始说明”默认折叠在“添加备注”后，完术核实弹窗默认采用已登记量并展示差额预览（零差额且无未用预留或少用时默认折叠“核实说明”，存在术式变更、计划外／通用预留耗材或现场差额时自动展开必填说明）；术后以紧凑清单展示差异，单行横向排列“看术中登记、修改说明、需要跟进、按此说明确认”并在底部操作栏固定“一次全部确认”，手工预留维护与术后耗材更正均收敛于独立批量弹窗（业务规则见[住院与手术流程](../architecture/inpatient-workflows.md)）。
- **护士、药师、收费、病案与医保办界面**：护士队列按新入院、床位（零待办不写“轮到你 0 项”，空床单行显示床位费）与底部召回／历史分组，检查集中送检、新嘱校对、停嘱核对及给药／健康教育／PRN 均通过独立分页集中核对窗口办理（给药与教育须逐项核实事实后才可勾选，见[处方、医嘱与药事](../architecture/orders-and-pharmacy.md)）；全部集中办理弹窗的私稿隔离与逐项原回执恢复遵循[浏览器未提交私稿](../architecture/storage.md#浏览器未提交私稿)。住院药房待发与已发双页签独立分页惰性读取；收费员无需补交时省去收款表单直接从预览结算开始，补充预交金与结算后“费用差异核对”按需展开；病案与医保办首屏共用四列（窄屏两列）DRG 复核摘要，按归档快照与每页 10 份分页边界展示（见[住院与手术流程](../architecture/inpatient-workflows.md)与[收费、结算与医保](../architecture/billing-and-insurance.md)）。

## 组件与组合

- 命令使用 `Button`（新增、确认、签署、签发与删除采用统一 Lucide 图标加文字，纯图标按钮必须提供可访问名称）；表单使用 `FieldGroup + Field + FieldLabel`，错误同步设置 `aria-invalid` 与具体 `FieldError`；状态、集合加载、进行中与完整风险提示分别使用 `Badge`、`Skeleton`、`Spinner` 与 `Alert`；`Card` 使用淡边框与稳定间距，不做常驻阴影或嵌套卡片。
- 行内单行截断（`truncate`）必须配合 `min-w-0`（吃剩余空间时再加 `flex-1`）阻断固有最小宽度沿 flex 链上传到 `fieldset` 撑出横向滚动；严禁对依赖内容宽度参与分配的截断段使用 `[contain:inline-size]`，以免 `flex-basis` 塌缩为 0 导致文字不可见。
- DSH Surface 视觉反馈与页面动作定位依赖工作区根面板、页面标题、问诊区域、目录弹窗及诊断／处方／住院资金表单上的稳定 `data-agent-*` 与工作区 DOM 属性钩子，重构页面结构时必须保留对应定位属性与栏目枚举映射（见[DSH 页面操作与视觉反馈](../agent-capabilities.md#反馈时序)）。

## 开发者组件目录

设置中的“开发者 → UI 组件”与公开 `/components` 路由共享同一个真实目录实现，静态导入 `@clinmesh/ui/components/*` 并使用产品实际 token、主题和本地化文案在单栏流中展示控件与表单、临床数据与状态、弹层与反馈、基础与导航及会话组件；新增共享组件时必须同步增加至少一个可视状态。

## 可访问性与验证

所有交互控件必须有可访问名称，装饰图标使用 `aria-hidden`，键盘焦点使用 `ring` token 且不被裁切；Tabs 保留方向键移动焦点与 Enter / Space 激活，Dialog、AlertDialog 与原位确认条关闭后将焦点归还触发器（后台刷新改变按钮状态时不抢夺用户已移入其他输入框的焦点）。

共享 `Dialog` 与 `AlertDialog` 由调用方显式传入所属写操作的 `pending`（`AlertDialog` 必填，普通只读 `Dialog` 可省）：等待期间统一拦截用户取消、Escape、外部点击和右上角关闭，禁用 `DialogClose` / `AlertDialogCancel` 并设置 `aria-busy`；失败或结果未知后恢复关闭以便退出并通过原写意图回执恢复，不读取全局网络计数锁定无关窗口，见[共享弹窗关闭保护决策](../decisions/implemented/bug-fix/2026-11-10-shared-dialog-pending-dismissal.md)。产品可见改动从真实 Web 入口在桌面和窄屏视口运行覆盖当前 diff 的最小检查。
