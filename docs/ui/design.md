# ClinMesh UI 设计合同

ClinMesh Web 与 Desktop 共享一套面向临床工作的界面语言：安静、高密度、可快速扫读。患者事实、业务状态和当前任务优先于装饰，界面通过表面、边线、排版和间距建立层级。

## 核心原则

1. **安静的密度**：在单个视口中呈现足够的临床上下文，但不用装饰色、大标题或重阴影竞争注意力。
2. **表面优先于阴影**：常驻区域使用中性背景、1px 边线和稳定间距；阴影只属于菜单、Dialog、Sheet 和 Toast 等临时覆盖层。
3. **动作紧邻对象**：确认诊断、签署病历、签发处方、签发申请、取消和更正位于所操作事实附近，长表单的提交区保持稳定。
4. **渐进展开**：默认只显示当前任务所需信息；使用 Tabs、Sheet 和菜单切换上下文，不把完整病例堆成一条长页面。
5. **工作区连续性**：侧栏、顶栏、当前岗位和设置入口在页面间保持稳定，避免重复 Dashboard 和跳转迷失。
6. **语义色克制**：色彩用于选中、焦点、成功、警告和风险，不作为大面积装饰。

## 所有权

| 内容 | Owner |
| --- | --- |
| 主题、语义色、字体、字号和圆角 token | [`packages/ui/src/styles.css`](../../packages/ui/src/styles.css) |
| Button、Field、Table、Tabs、Dialog 等 primitive | [`packages/ui/src/components/`](../../packages/ui/src/components/) |
| Web 工作区布局和平台交互 | [`apps/web/src/app/`](../../apps/web/src/app/) |
| 真实组件目录 | [`apps/web/src/app/component-catalog.tsx`](../../apps/web/src/app/component-catalog.tsx) |

`packages/ui` 不包含 Patient、Encounter 或 Medication 等业务概念。业务页通过公开组件入口和语义 token 组合界面，不复制 primitive 样式。Mobile 使用独立 React Native UI，不导入 DOM 组件。

## 应用框架

### 桌面端

| 区域 | 合同 |
| --- | --- |
| 设置侧栏 | standalone 设置保留 220px 导航，折叠为 48px；岗位工作台不显示应用侧栏，DSH 使用宿主导航 |
| 顶栏 | 48px；依次是队列开关、唯一页面 H1、当前患者、办理流程、助手状态摘要、全屏和人物菜单；页头窄于 40rem 时隐藏流程 |
| 主内容 | 可收起的队列卡和主卡；主卡依次是患者头部、页签、内容区与按需显示的操作栏，没有右栏 |
| 应用表面 | 主区域与侧栏通过背景、边线和最大 8px 圆角区分，无常驻阴影 |

岗位切换位于右上角人物菜单，按门诊、住院、系统分组。挂号、收费和药房的门诊／住院切换位于队列顶部；模式、页头名称和收费员发布给助手的工作区保持一致。设置保留“设置”与“开发者”导航。管理员以“模拟数据”为首页，分为“演示准备”和“患者库”：前者包含时间、生成、带影响说明及二次确认的重置和素材准备；后者承接患者列表、详情、Persona 与来源历史。

右上角人物菜单按人员与岗位显示一个选项；岗位名称与显示姓名相同时只展示一次，真实姓名继续保留。选择项使用当前原岗位 ID；同一人员在旧库仍有多个实际授予的职责时，非住院岗位通过工作地点选择保留这些上下文，通过原岗位切换接口访问，不改变授权。住院工作台先绑定会话的单一病区，不显示工作病区选择；默认单科环境不显示多余的病区选择。

### 移动端

standalone 设置在 `< 768px` 时以 Sheet 承接侧栏。岗位布局使用下文的内容容器断点；多列表单回落为单列，表格在自身容器内水平滚动，不通过缩小字号隐藏数据。此处只描述 Web 的窄屏，原生 Mobile 不在该布局合同内。

## 密度与排版

| 用途 | 标准档尺寸 | 规则 |
| --- | ---: | --- |
| 顶栏标题 | 13px | 600 字重，单行截断 |
| 业务分区标题 | 13–16px | 与内容紧密对齐 |
| 正文与控件 | 14px | 1.5 行高，不随视口缩放 |
| 表格与数据 | 13px | 日期、时间、金额和检验值使用等宽数字 |
| 辅助信息 | 11–12px | 使用 `muted-foreground` |
| 按钮 | 24 / 28 / 32 / 36px | XS / SM / 默认 / LG |
| 常规控件圆角 | 6px | Button、Input、Select、Tabs |
| 业务表面圆角 | 最大 8px | 独立重复项、弹层和真正的工具容器 |

Web“设置 → 外观”的字号偏好提供“标准 / 较大 / 大”三档，分别按 `100% / 112.5% / 125%` 调整 ClinMesh 应用内容的语义字号。“标准”同时承担重置功能；选择即时生效并作为设备本地 Web 偏好持久化。Desktop 消费标准档 token，不拥有该 Web 本地偏好。

字号比例只进入语义字体 token。图标、控件高度、间距和页面几何尺寸保持不变；standalone Web 的文档根字号保持 `16px`，DSH Surface 不修改宿主根元素。持久化和作用域取舍见 [Web 应用级字号偏好](../decisions/implemented/feature/2026-09-02-web-font-size-preference.md)。

全局字距为 0。日期、时间、金额和检验值使用等宽数字特性。页面不使用负字距、视口缩放字号或超大仪表盘标题。

## 颜色与主题

业务组件只消费语义 token，不直接写入 Tailwind 色阶。

| Token | 用途 |
| --- | --- |
| `background` / `foreground` | 主画布与默认文字 |
| `card` / `popover` | 独立业务项与临时覆盖层 |
| `primary` | 中性主操作；浅色近黑、深色近白 |
| `info` / `ring` | 蓝色交互、选中、Agent 参与和键盘焦点 |
| `success` | 正常、通过和已完成 |
| `warning` | 待复核、偏高和需要注意 |
| `destructive` | 过敏、危急、删除和不可逆风险 |
| `secondary` / `muted` | 中性状态、辅助表面和弱化文字 |
| `border` / `input` | 分隔线和控件边界 |

Web、Desktop 与 DSH 使用同一套浅灰画布、白色卡片和中性主按钮。语义 token 优先读取 `--dsw-*` 宿主变量，standalone 使用相同取值作为回退。浅深主题独立映射画布、文字、边线与语义色；普通文字与状态边界分别满足 4.5:1 和 3:1 对比度。Agent 非 proposal 动作使用蓝色环绕柔光，减弱动效时只保留静态反馈。独立 Web 的主题选择写入 `clinmesh.preferences:v1`，公共组件目录使用相同机制；DSH 只跟随宿主，不显示本地主题入口，详见[Surface 与 Host 边界](../architecture/agent-integration.md#71-surface-与-host-边界)。

## 共用卡片工作台

收费员与药师的门诊、住院入口使用相同的列表头下拉，呈现方式由岗位组合统一传给模式上下文；切换模式保留同一种控件。挂号入口继续沿用原分段切换，身份、权限与模式状态的归属见[卡片组合决策](../decisions/implemented/architecture/2026-10-30-workspace-card-composition.md)。

应用侧的 `workspace-card-layout.tsx` 拥有队列开关与流程的页头投影、患者头部、分区页签与当前操作组合；`packages/ui` 只提供通用 primitive。队列收起后整列移除。页签根据实际宽度测量，将尾部收进“更多”，当前页签始终保留；展开后可换行，方向键与 Enter / Space 仍可操作。流程放不下时只显示圆点、当前环节名和“n/总数”。页签旁黄色数字是本岗待办数，为 0 时不显示（读屏仍说明）；蓝色“助手 n”是该页签内的助手建议条数，两者分开。

| ClinMesh 内容容器宽度 | 布局合同 |
| --- | --- |
| `>= 800px` | 队列卡与主卡并排，两张卡撑满可用高度，内容在卡内滚动 |
| `< 800px` | 队列默认收起，主卡占满；顶栏按钮以浮层打开队列，在队列内选择、点遮罩或按 Esc 后收起 |

交互反馈：

- 提交中主按钮换成转圈的“正在…”按钮，主卡其余部分不可编辑并变暗；不可执行的主按钮是虚线框，状态文字写“还差：…”。开具窗口已选项目但缺必填内容时同样使用这一样式，提示列明实际缺项；正在提交与尚需补全字段分开呈现。
- 成功后原位显示结果，右下角提示写明结果与交接对象；当前环节图标到达时放大一次。分诊和门诊收费处理完自动选中下一条；挂号和门诊药房的完成操作栏在队列仍有患者时提供“下一位：姓名”；门诊医生完诊后停在只读病例，操作栏写明回看位置。
- 完成通知的正文允许鼠标穿过，不遮挡下方的行内确认；仅通知内显式操作和关闭按钮接收点击。折叠堆叠中透明通知的按钮不接收点击，键盘聚焦展开后恢复；正文悬停不暂停自动消退，也不承担滑动关闭。取舍见[通知命中边界](../decisions/implemented/bug-fix/2026-11-04-toast-pointer-boundary.md)。
- 提交中焦点留在操作栏，结束后回到恢复的主按钮；浮层收起后焦点回到顶栏队列按钮。
- 队列选中行是浅蓝底加蓝边，悬停为浅灰；处理完的单行在原位淡出。
- 表单选项（选择后会写入业务数据，如诊断、处方、床位）选中后整块实心并带勾，勾不计入无障碍名称。以按钮组呈现的视图切换（只改变看到的列表或分区，如「门诊 / 住院」「病案整理状态」、挂号记录「今日 / 全部」、诊断、检验指标和检查申请的筛选）标记 `data-view-switch`，与分段页签同样是浅灰底槽里的白色选中块，不带勾。
- 分段页签的选中项是 `Tabs.Indicator` 渲染的白色滑块，下划线页签的选中线同样由指示器绘制；切换时滑到新页签。
- 系统减少动效时以上动画关闭，状态文字照常显示。
- DSH 中浮层底色不透明（浅色 `#ffffff`、深色 `#353638`），不沿用宿主半透明菜单色。

门诊医生、分诊和药房复用同一患者行边界，按姓名与状态、补充信息、完整业务号码组织内容，普通字号的标准号码与复制同排，超长号码或大字号完整换行而不裁切。复制操作位于边界内，未提供的人口属性不显示空分隔符。医生队列不使用头像和额外灰底容器，三个等宽计数页签使用共享白色滑块；切换完诊病例库时保留同一指示器的 DOM 和实际过渡，减少动效偏好继续关闭动画。组合与生命周期取舍见[门诊细节组合决策](../decisions/implemented/architecture/2026-11-04-outpatient-detail-composition.md)。

底部操作栏仅在存在主动作或刚完成操作时出现：关键数字、缺项／阻断原因、一个主按钮。空间不足时按钮可另起一行，说明保持自然横排，不挤成单字竖列。不可逆动作把操作栏转换为说明后果的确认条，提供返回与确认。纯等待、只读阶段的交接说明位于内容卡，不生成空操作栏。

助手填写的字段显示虚线框与“助手”来源，人工修改后移除。行级 proposal 在对象行内审阅，整页 proposal 在底部审阅；同一时间仅一个，保留已核对勾选、过期／中止失效、审批 gate 与正式 Command 合同。审阅批准和拒绝保持静态；详细信任边界见[人工审阅语义](../architecture/agent-integration.md#75-人工审阅语义)。

门诊收费队列的标题与计数同行，模式和类别筛选并排，四种缴费状态同排。账单合计、到账和未收金额归入表尾，抬头与费用表保持同一口径；收款说明只在操作栏出现，付款方式与模拟处理结果按容器宽度并排组合。费用更正、医保待遇与支付记录通过一排紧凑入口按需展开；恢复当前患者的冻结退款预览或待确认原操作时，费用更正区自动展开，返回其他患者不展示原预览。冻结退款审阅与来源选项共同使用冻结预览对应的原收款人类标签，不随患者往返重置为其他来源。

收费头部将姓名、费用说明和合计紧凑同排，正文只保留账单自己的标题；模式与类别筛选按内容宽度并排，长翻译可合理换行，当前值不裁切。医生队列的分级和就诊状态成组排列；长姓名可以另占一行，状态不被姓名挤散，大字号和长翻译允许合理换行。

药品总项下保留当前队列本页中同病例、同收费项及同版本的原处方明细，显示药名、数量、原单价和原小计；未取得明细时明确说明。原处方项目金额不替代更正后的账单金额，也不参与表尾二次合计。

门诊药房先审核再展示批次与数量，审核结论以一行真实时间和意见呈现，过敏风险位于头部；批次与本次发放数量直接放在药品条目内，不重复列出已选批次。发药成功后停留本次结果并提供下一位；批次与数量来自成功回执及已审阅操作快照，不扫描已发历史来恢复当前结果。历史队列投影没有实际发出批次，详情保留真实处方及累计发放数量，不用当前库存替代历史发药记录。当前页最后一条发完后，按真实队列总数读取仍有效的页准备下一位；空页不等于空队列，完成结果保留到用户明确继续。

## 门诊医生工作台

门诊医生复用共用卡片布局。患者头部保留姓名、性别年龄、门诊号、主诉、分诊、过敏和病例状态，下方是生命体征事实标签、可展开的“完诊清单 n/7”，以及“助手已准备”行：诊断、检验、放射检查、病理会诊和处方各写条数或状态（生成中、生成失败、待补充资料、确认诊断后生成），质控写待核实数，点击跳到对应分区。数据来自原服务查询；未取得预览时不显示完诊计数。住院助手呈现见[住院工作台](#住院工作台)。布局取舍见[外壳与反馈 Note](../decisions/implemented/architecture/2026-11-02-dsh-shell-feedback.md)。

患者头部最多占主卡一半高度，长主诉、多条过敏或大字号导致内容超出时，头部独立纵向滚动，保留业务页签的可用空间；业务区独立滚动，头部位置保持稳定。

挂号记录、分诊与医生工作台的“门诊号”取自本次就诊读模型的 `registrationNumber`，保留完整原值并提供复制；复制被拒绝时显示失败提示。医生横幅以等宽数字显示号码，号码与带标签的主诉可换行，窄窗口仍可完整核对。历史病例缺号显示“未记录”；病例加载或读取失败时不保留上一病例横幅。患者级标识展示时标为“患者号”，不用于补齐门诊号。

病例主区按以下顺序提供五个业务页签；没有 Consultation Record owner 的旧病例不显示“问诊记录”：

| 分区 | 内容 |
| --- | --- |
| 问诊记录 | 受控问题与按序追加的患者回答，不覆盖正式病历 |
| 病历记录 | 主诉、现病史、既往史、查体、辅助检查、临床评估、处置、随访、签署和受控修订 |
| 检验检查 | 检验、放射检查和病理会诊分类，目录与申请信息、申请列表与选中详情、追加、取消、重试、报告历史和已阅 |
| 诊断 | 受控诊断目录、主次诊断、自动保存草稿和可继续修订的正式确认版本 |
| 处方 | 用药结论、本院药房与国家参考目录分轨选药、按临床产品分组的真实包装选择、剂量、频次、疗程、数量、自动保存草稿、本院或电子外延处方正式开具和撤回 |

“检验检查”按当前病例、当前分类的完整已签发申请集合派生阶段：无申请且可编辑时直接显示融合目录与申请信息，右侧放待开具清单；已有申请时左侧保留开具表单、待办及可搜索筛选的申请列表，右侧显示选中申请详情。开具后目录结果默认收起，搜索行保持可见。取消记录与筛选为空仍保留管理阶段，草稿保存不切换阶段。三类目录、草稿与报告保持独立；分类切换保留未保存输入，刷新恢复已保存草稿。检验默认展示完整指标，可切换仅异常，历史默认收起；放射和病理保留各自阅读器与实际显示后的已阅门禁。药品 picker 显式分为「本院药房」与「国家参考目录」双页签（默认「本院药房」展示院内规格、包装与单价，不铺设适应证编码；本院无匹配或无可用项时可一键切换至「国家参考目录」，两侧均支持单字关键词搜药），不自动选择目录第一项；国家参考目录显示电子外延处方说明，医生必须明确选择真实产品 ID，同一临床产品的包装变体共享通用名、规格、剂型、厂家和批准文号信息；单张处方保持单一目录来源，跨源候选在行内置灰并写明需分开开具的原因，见[门诊本院药房与国家参考目录分轨决策](../decisions/implemented/architecture/2026-11-05-outpatient-external-prescription-split.md)。

没有病例责任人的 `awaiting-doctor` 病例在接诊动作成功前不开放病历、检验、诊断、处方或问诊写入；开始首诊动作固定在病例页签上方，切换业务页签仍可到达。病例进入 `first-visit` 后才启动普通草稿 autosave 和完诊预览；`awaiting-revisit` 继续显示开始复诊动作和服务端允许的既有修订入口。

完诊位于底部操作栏；缺项在原位列出并可跳转对应分区，满足服务端七项条件后才能确认。已完诊病例默认只读，完诊成功后刷新失败也不重新开放编辑；合法纠错入口先激活目标页签，再将焦点和滚动位置移到目标区域。管理员工作台有界搜索 orderable LOINC 候选，选择根项目并观察 enrichment publication job；医生检验选择器只显示发布成功的根服务，panel dependency-only 分项不平铺，不显示 Agent、Case Truth 或生成 capability。

问诊输入组的禁用外观只取决于文本编辑控件；空内容使发送按钮不可点时，输入区仍保持卡片底色与清楚的实线边框。有内容且允许发送时按钮使用主色；医生消息靠右并使用强调色，患者消息靠左使用中性色，时间与说话人同行。

分诊体征的可录入范围位于输入框内辅助区，并保留完整可访问描述与输入空间；min、max、step 和错误说明继续依据既有校验，不以范围提示替代实际测量值。

住院证保留单栏病区与原因表单，顶部显示当前患者、门诊号及真实已确认诊断；唯一收治病区直接显示文字，多病区仍使用选择控件。原因带字数，提示、取消和确认位于统一底栏。检验、放射与病理的选中详情采用项目标题、编码和两列事实表，价格并入事实，价目说明按需展开；短内容自然收缩，长目录与字段保留有界滚动。

未提交的 Clinical Document 输入以 `caseId` 隔离保存在当前前端会话状态中；切换页签或患者不会丢失输入，也不会将内容带入另一病例，刷新或关闭页面会丢弃未提交内容。诊断、检验和处方的有效修改在短暂静止后自动保存，界面只显示等待、保存中、已保存或保存失败，不提供普通“保存草稿”按钮。删除整个草稿、确认诊断、开立申请、正式开具和无需用药仍是明确命令；当前输入尚未自动保存或保存请求仍在进行时，这些终结动作保持禁用。界面不显示草稿版本、FHIR 版本或乐观锁版本，服务端继续执行 expected version、幂等、审计和冲突检查。

诊断确认不结束本次 Encounter 的诊断编辑。确认后仍显示当前主次诊断和添加、更换、删除、备注入口；修改自动形成新草稿，再次确认创建新的正式 revision 并保留上一版本。Encounter 完成后诊断页回到只读。

诊断、处方与检验检查三个开具页签共用同一结构合同：填写前左主列自上而下「页签模式开关（处方用药结论方式、检验检查分类切换）→ 选择入口」，目录浏览与表单填写在同一次弹窗内完成——弹窗共用两栏布局，左栏为搜索与紧凑目录列表，右栏为选中项目详情与填写项，左右栏独立滚动，宽度不足时上下排列；候选整行可选并显示选中标记，药品包装控件独立于选择按钮；多行候选按钮按内容自然增高，病理不可选原因独立成行；诊断与检验在 1101px 宽、720px 高弹窗中分别至少容纳 12 行和 11 行。未选项目时右栏提示选择，底部提示下一步，主按钮用虚线框区分不可用与提交中状态；点选目录项后在右栏填写表单，点「确认」将这一条落单到页签列表并关闭弹窗；未确认关闭即弃置弹窗内输入，页面草稿与自动保存不受影响；一次弹窗只落一条，追加多条重复打开入口；页签列表条目点击用同一弹窗重开编辑。右辅助列恒为一块推荐/待开具面板，不放置模式开关或草稿工具；无需用药结论在左主列内呈现，不空置栏位。共享 Dialog 容器为未声明布局的直属正文提供 16px 默认内边距，已有显式 p/px/py 样式覆盖对应方向，避免双重留白；内部正文和页脚已自行分区留白的表单 wrapper 显式使用 p-0。弹窗沿用项目 Dialog 惯例：桌面居中、宽高有上限，窄容器回落近全屏；表单字段短字段两列并排、说明/备注类独占整行。已确认诊断左侧保留目录、编辑、待办及可按主次筛选的列表，右侧显示选中正式诊断；已开具或撤回处方显示药品列表与选中只读详情，保留未开具项目的可见性及现有处方限制。窄分栏可在列表与详情之间返回，搜索、筛选与返回不删除记录或清空输入。确认诊断作用于整组，开具、删除草稿、撤回及无需用药保持明确的对象预览和确认，处方开具拦截按服务端细分原因在待开具面板原位提示具体可操作说明；开具窗口取舍见[共享两栏开具窗口决策](../decisions/implemented/architecture/2026-11-03-shared-order-composer.md)，布局与阶段归属见[开具工作区决策](../decisions/implemented/architecture/2026-10-19-clinical-order-workspace.md)，正式记录与处方生命周期继续见[两阶段视图决定](../decisions/implemented/architecture/2026-10-10-diagnosis-prescription-workspace.md)。

所有演示患者和岗位在底层仍带 synthetic provenance、FHIR extension、受控标识和审计边界。临床显示名称、岗位名称和患者抬头不添加“合成”前缀，也不显示“教学环境”等与当前诊疗无关的提示。

## 住院工作台

住院七岗位通过 `inpatient-layout.tsx` 组合两行患者头部、平铺页签、办理首行、条目行和队列分组，并复用工作台底部操作栏。主页签按本岗任务平铺，只读或放不下的环节放入“更多”；展开后显示环节名称、待办数与状态。每个环节第一行写明“轮到你”或等待的岗位，右侧给出办理顺序并突出本岗位。护士队列新入院置顶，床位显示待办数，空床显示床位费，召回窗口与出院后病历固定在底部；进入患者时优先落在本岗有待办的环节。收费员住院队列与门诊位于同一入口，队列行保留待收摘要；患者头部在未结算时从收退款账、结算后从当前财务更正账显示需补交或应退的方向，两者为零时只显示“无需补退”，未知资金与读取失败分别提示核对和重试。无需补交时省去补交与收款步骤，仅显示一次无需补交说明，从预览结算开始；不将未发生的步骤打勾，也不展示收款表单；需要额外预交金时通过“补充预交金”按需展开，原退款、渠道未知和回执恢复能力保持可达。挂号员切到住院后，队列上方是待转收的门诊住院证，下方是今日已登记（按场景虚拟时间判断日期）；选中住院证进入同一登记表单并只读展示证内容。病案人员的病案页签最上方是 DRG 复核，后续依次是患者信息、住院过程、正式诊断与操作、费用、审核归档记录。费用页签默认显示明细、退费及资金记录；财务差异通过默认收起的“费用差异核对”入口查阅和按本岗位处理，不扩大财务岗位读取权限。医保队列按已归档与已核定分组，主区按归档依据、模拟核定、历史核定排列。

病案人员首屏的 DRG 分组复核读取原有预分组入口：未归档显示当前已确认诊断与实际操作的分组，归档后显示冻结结果；历史归档未形成固定分组时明确说明缺失，不按当前规则回填，真实读取、权限和网络错误继续提示失败；术后核查与责任交接通过次级入口展开。病案诊断显示临床代码、名称与人类可读的入院病情，离院方式和费用分类同样转换为岗位用语；内部编码系统、发布身份和来源定位不在正文铺陈。医保核定主区保留模拟金额及差额需要复核、不会自动收退的事实，完整公式和参数说明放入来源详情。医生开出院医嘱时，已读取到的未收口手术、检查检验或转科按原 Command 边界说明处理岗位并提供返回入口；处理前禁用已知会失败的提交，不添加其他门禁。

报告首行和成功交接共用实际申请状态：忽略已取消申请后全部已阅时明确完成，全部取消、待送检、未出报告和待阅分别说明；读取失败优先显示需重试，不以缓存中的已阅状态报完成。护士在院时的出院清单同时列出医生出院医嘱与实际医嘱、给药和执行待办，办理实际离院的停嘱门禁不混入医生开出院医嘱的说明提示。

医保核定按归档索引每页最多 10 份病案，仅对可见页读取核定状态；已归档未核定与已核定两组的数量只说明本页，正在读取或失败的状态不归入任一组。提供上一页、下一页和失败重试；本页无下一份时说明本页完成，可显式继续下一页，不能代替全队列完成。继续进入新页后，状态就绪时只初选一次本页未核定病例；该页均已核定时显示本页暂无待核定，不自动扫描后页或选取已核定历史。首次选择、人工选择与显式“无下一份”分开，新增归档或后台刷新不替换已选病例，读取失败优先显示待确认。成功回执与“下一份”绑定当前住院，不因切换病例带入另一患者的完成状态，也不重复提交已恢复的核定；身份变化后重新初选。头部复用已有核定预览的窄病例摘要，展示归档时性别、年龄与住院天数；天数不是住院第 N 天。住院清单的病区与床位信息只有内部标识，床位标识为可选，核定摘要不提供可读名称，本页不扩读病区目录或患者资源来补齐。

医保和病案的 DRG 复核摘要使用同一四项事实排列：宽正文四列、窄正文两列；刷新位于标题旁，分组、病例和参数来源按需展开。医保归档费用来自原核定预览的归档收费，归档支付预估来自冻结分组；病案费用来自原病案快照，归档后不以当前住院金额替代。未提供的病组名称保持空值，不用诊断或手术名代填。

住院医生助手行使用短状态，完整说明保留可访问名称和按需入口；头部检验保留至多两项真实结果及实际异常摘要，完整结果从原检查检验页查阅。读取失败清除旧摘要，不宣称正常。当前环节的等待归正文清单与操作提示，头部保留跨环节事实；队列返回与刷新以独立图标和名称表达。药房单页不显示分页说明和操作，多页保留准确本页范围与显式继续。

默认环节在当前患者初次资料就绪后固定到客户端视图；办理成功、待办减少或后台刷新不抢走当前分区。新入院分床前保留入科落点，分床后进入诊断医嘱；当前分区失去访问条件时才回落到允许的环节。

住院医生六页分别围绕当前任务组织正文：诊断医嘱按诊断摘要、医嘱条目、紧凑开立表单排列，添加或修改诊断使用国家临床版 2022 两栏弹窗，费用预计作为操作栏次级入口就地展开；每条医嘱通过「执行记录 (n)」弹窗查阅，护士保留原执行流程。检查检验的待阅检验直接展示完整指标表、参考区间与签发时间，待阅影像直接显示印象和结论；已阅报告收为紧凑摘要，通过「查看全文」弹窗回看全文和既往修订。开立申请使用门诊同款两栏开具窗口，影像保持当前报告修订实际显示首帧后才能已阅的门禁。

手术先显示当前计划与“开始手术还差”，知情同意、取消、开始手术、术中逐笔登记与完成核实各填各的说明。PCI 关键选型参数、三项病变测量、行内指南摘要与耗材确认留在正文，完整预计依据、扩展参数、指南详情及手工预留维护按需进入标准弹窗；申请手术和术后耗材更正也使用弹窗，提交失败保留输入，提交中保护关闭。已完成手术保留最终耗材汇总；没有待实施或进行中手术时，未解决术后核查待办及负责岗位直接列出，来源与历史按需查阅。

DRG 预分组主块围绕医院支付参考监控已发生收费与未记费医嘱，计划手术收为“做完计划手术后”一行，随后承接已发生收费构成与分组核对。患者头部保留唯一自动跟进开关和本次住院 AI 用量入口，明确停止、权限失效与归档状态。住院累计覆盖各任务，当前跟进阶段与用途汇总明确限定任务范围；未决请求可进入原明细核查，归档后用量只读可查，详情查询和分页轮询按需启用。

医生出院页展示开出院医嘱前清单（手术、检查检验、转科、在用医嘱提醒）和必填出院处理说明，离院方式留给护士，召回患者需填召回理由；医生病案页展示提交首页前清单与诊断、手术操作，病案首页在出院结算完成后开放提交，在院有已实施操作时仍可选定主操作供 DRG 预分组使用，退回理由置顶。阅读密度调整不能丢失草稿、主操作选择、错误恢复或已有能力。

护士检查检验页按每页10项展示全部申请，支持名称和标本搜索；当前页全选只包含本页可送检项。每项保留类别、标本或检查前置说明、指征、状态与禁选原因，已送检但仍待受理的申请不可再次选择。跨页和搜索保留明确选择，完整待处理清单持续显示数量与20项上限；清空选择只取消勾选，移除与确认丢弃草稿分别操作。底部“集中送检”打开有独立滚动区的核对窗口，确认前重读当前状态与版本，变化项须返回更新核对。逐项结果保留成功、确定失败、结果待确认和未发送；原送检恢复后余项重新核对，不把送检显示成受理、执行、报告或收费完成。原逐行送检按钮由这一入口承接，报告与其他业务动作仍由各自入口提供。

护士的诊断医嘱页在底部操作栏显示剩余校对数量并提供下一条校对，行内逐条校对、停嘱核对与执行动作保持可达；本次校对完成后明确提示后续发药或执行。停嘱与 PRN 理由在对应医嘱展开并分别保留，确认后才发起原 Command。护士队列以新入院、床位和底部召回/历史分组排列，床位行以姓名和真实待办或住院状态为主，零待办不写“轮到你 0 项”，空床在单行显示床号和床位费；不重复铺陈床位标题与场景时间。返回列表收为队列头部的紧凑入口，页签展开“更多”后仍直接显示待办数字。

住院工作台以患者列表与患者详情承接实际岗位任务。列表可返回，详情页提供患者切换器；患者头部在业务区独立滚动时保持可见：第一行展示姓名、可读的性别年龄、状态、病区床位与住院日，右侧可放关键金额；第二行展示住院号、预交金与累计费用。事实标签和助手行没有内容时不占行。住院号超长时中间截断、悬停显示全文并提供复制，队列行只显示尾号；在院未结算是常态，结算状态仅在待结算与已结算时显示。下一办理岗位由各阶段面板说明，横幅不重复。住院药房待发页先按既有发药门禁保留在院患者，已发页保留完整历史；两页签保存独立页码，并按各自患者页惰性读取，每页最多 10 位患者；未访问页的详情不读取，药品仍按执行条目组织待发与已发队列。计数与空态只说明本页，并提供上一页、下一页入口，不将本页为空表述为全队列已处理。头部以药名为标题并显示患者、用法及真实校对时间。选中详情成功后，有过敏时显示真实风险标签，已读空时明确“未记录有效药物过敏”；更新或失败时说明状态，不误报无过敏。长期药嘱尚未生成执行单时保留只读上下文；发药后自动选择本页下一条，本页完成后可显式继续下一页，原页的已发记录与原回执保留可读。恢复回执时按患者当前状态定位对应列表；已离院患者转到已发历史中的原患者页。药师使用原有窄 DTO，不补造年龄、床位、校对人、费用或住院天数；库存批次只有内部标识、库存和效期，没有厂家批号，因此显示本页库存批次序号及真实库存效期，内部标识只用于 Command。单次执行仍须完整发出既定剂量，不提供不受 Command 支持的部分发药。

住院岗位有待确认的 Agent 审阅时，患者头部显示“助手已准备”行。医生有尚未开始、仍待审阅的 PCI 计划时，同一行分别显示选型草稿、耗材清单、费用说明与指南参考意见的状态，点击进入手术页；页签的“助手 n”只计入已准备的产物。已经发布的条件性指南意见仍计入就绪，同时写明患者资料待补充；读取失败、结果未知、来源变化及尚未生成分别说明，不显示内部失败码。摘要复用本次住院的共享查询，不挂载未访问阶段的业务表单，也不派发模型。

报告选型参数、清单与确定性费用在手术页同屏核对；报告带入或 AI 填写的字段使用“助手”标记，并提供“依据”入口，人工修改后标明修订。正式确认使用操作栏的助手确认条，参数、报告、清单、费用或原预留变化后撤销原审阅。指南参考摘要在耗材步骤行内展示真实任务结果；原句、名称、版本和物理页通过指南详情弹窗查看，重评不批准意见或改变清单。清单保存只在编辑区显示保存状态，允许继续输入，不触发全卡提交中或正式完成交接；正式确认保留操作栏忙态。数据与原子确认合同见[单次耗材预计](../architecture/clinical-workflows.md#手术计划的单次耗材预计)。

患者详情按“入科分床、诊断医嘱、检查检验、手术、费用、出院结算、病案”组织为可访问阶段导航，页签平铺并以“更多”承接溢出，初次进入根据当前岗位与真实住院状态定位工作区。每个阶段按住院登记的服务端字段推导主线状态并以装饰标记呈现：已完成（对勾）、进行中（圆点）、待办；检查检验、手术、转科保持各自的实际状态，未发生的环节不标为完成，结算完成即费用收口，归档后全部收口。患者横幅在无虚构成分前提下补充住院日，按场景虚拟时间与实际入科时间计算，场景时间不可读时隐藏。每次只显示一个阶段；患者头部和导航位于业务内容的独立滚动区之外；导航复用共享目录元数据，未访问阶段不挂载业务内容或查询业务详情，已访问阶段保留挂载以维持原输入、主操作选择基线与冻结的结算预览。状态标记均为装饰内容，不改变阶段的可访问名。切换阶段不会自动提交，也不会更换账户或岗位。跨病区环境另提供转科交接；默认一科一病区不展示转科入口。

每个阶段说明负责岗位、前置条件与实际办理路径，具体阻断仍以共享 Command 返回的业务事实为准。开具住院证后明确提示“登记员 → 住院登记 → 门诊住院证转收”，登记完成后提示病区护士接诊分床；出院沿用医生开医嘱、护士出区、收费员结算、护士清床的独立步骤。首页由医生提交、病案人员审核并归档，归档后通过病案区读取固定快照，诊疗写入入口关闭。界面只根据服务端已知状态给出下一办理环节，不复制原型状态机或显示虚构进度。

## 组件与组合

- 命令使用 Button。新增、确认、签署、签发和删除使用来自统一 Lucide 集合的图标加文字；熟悉的工具动作可使用带可访问名称的图标按钮。
- 表单使用 `FieldGroup + Field + FieldLabel`。错误同时设置 Field 状态、`aria-invalid` 和具体 `FieldError`。
- 状态使用 Badge，集合加载使用 Skeleton，操作中使用 Spinner，完整错误和风险提示使用 Alert。
- Card 包裹队列、患者、业务内容与只读参考区，使用淡边框、圆角和稳定间距，不做常驻阴影或嵌套卡片。
- 长表单的提交区使用顶边线和稳定高度，不用常驻阴影。
- `truncate`（`white-space: nowrap`）会让元素向祖先上报整行固有宽度：`min-w-0` 只解决布局期收缩，固有宽度仍沿 flex 链上传到 `min-inline-size: min-content` 的 fieldset，在窄视口撑出横向滚动。行内截断段用 `min-w-0` 阻断 min-content 上传，需要吃剩余空间时再加 `flex-1`（basis 归零即断开固有宽度链）；禁止对依赖内容宽度参与 flex 分配的截断段使用 `[contain:inline-size]`——content size 按空计算会使 flex-basis 塌缩为 0，内容整段不可见（2026-10 批次 6 曾因此让三页签目录行项目名全部 0 宽）。或改用 `break-words` 换行。窄视口合同与「名称可见宽度 > 0」断言在 DSH 浏览器合同中验证。

## 开发者组件目录

设置中的“开发者 → UI 组件”与公共 `/components` 路由共享同一个真实目录实现。目录静态导入 `@clinmesh/ui/components/*`，在单栏内容流中依次展示控件与表单、临床数据与状态、弹层与反馈、基础与导航、会话组件。

组件目录使用产品实际 token、主题和本地化文案，不维护第二套示例样式，也不使用同质化的名称清单代替真实组件。新增共享组件时，目录必须同步增加至少一个可视状态。

## 可访问性与验证

所有交互控件必须有可访问名称，装饰图标使用 `aria-hidden`，键盘焦点使用 `ring` token 且不被布局裁切。Tabs 保留方向键移动焦点和 Enter / Space 激活行为。Dialog 和 AlertDialog 在关闭后将焦点还给触发器。

原位确认出现时聚焦确认按钮；确认暂不可用时保留可取消入口。后台核对改变按钮可用状态时，用户已移到菜单或其他输入中的焦点保持原位；仍在确认条内时按当前可用按钮恢复焦点。可取消状态支持 Escape，关闭后回到原触发位置，身份或业务对象变化时不把焦点带入新上下文。请求进行时阻止关闭，失败或结果未知后可以退出审阅；原意图与回执继续保留，退出不代表撤销业务操作。

产品可见改动从真实 Web 入口在桌面和窄屏视口验证，检查导航、长中英文、Tabs、表格滚动、弹层、主题和焦点。只运行覆盖当前 diff 的最小检查。
