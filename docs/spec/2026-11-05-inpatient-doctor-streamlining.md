# 住院医生站减负收口：报告阅读与低频详情弹窗化

Status: implemented

## 问题与目标

住院医生工作站的报告全文、手术申请、术后耗材更正及医嘱执行记录仍存在页面内折叠入口，增加高频阅读操作并挤占临床主屏。手术选型、耗材预计与 DRG AI 展示的基础重排由 [Issue #401](https://github.com/CaiZongyuan/clinmesh/issues/401) 及 [PR #402](https://github.com/CaiZongyuan/clinmesh/pull/402) 承接，本规格在该前置交付合入后完成剩余减负项。

目标：沿用前置交付的单栏工作台、步骤化选型与耗材确认、行内指南摘要、患者头部跟进与用量入口，使待阅报告直接可读，已阅报告紧凑可查，低频表单与完整依据通过标准弹窗访问。服务端 Command、并发版本与指纹校验、影像首帧已阅门禁及跨岗位职责保持原有合同。

## 范围

适用住院医生工作站，以及与病区护士、病案、医保办共享子面板中面向医生展示的分支；覆盖 standalone Web、DSH Surface、简体中文与英文、浅色与深色主题，以及 `1101px`、`826px` 两档 Surface 宽度。

1. 「手术」页签：申请手术与术后耗材更正弹窗化，完整预计依据、扩展参数及仍适用的手工预留维护按需打开，保留前置交付的选型、耗材步骤和最终耗材汇总。
2. 「检查检验」页签：待阅报告直接展开结果或影像结论，已阅报告收拢为紧凑摘要，通过弹窗查看全文与既往修订。
3. 「诊断医嘱」「出院」「病案」页签：医嘱执行记录弹窗化，清理剩余重复制度说明、工程标识及医生无须阅读的编码范围尾注。
4. 复用患者头部的跟进与 AI 用量入口，核查累计摘要、未决请求、权限失效和归档状态的可见性，以及低频详情的查询启用条件。
5. 同步受影响单测、DSH React 18 / 19 浏览器合同与 Playwright E2E；实施时维护对应 Agent Note。

## 用户故事

1. 作为住院医生，我希望保留精简的选型参数与三项病变测量、确认后的摘要及手术耗材步骤，在主屏阅读指南摘要并确认预留，需要查看完整依据时再打开详情。
2. 作为住院医生，我希望通过「+ 申请手术」弹窗发起排程，在已完成手术的最终耗材汇总旁通过「更正耗材」弹窗处理修正。
3. 作为住院医生，我希望待阅的检验结果表和影像印象直接可读，已阅报告自动收拢，并可随时通过「查看全文」回看报告与修订。
4. 作为住院医生，我希望在患者头部统一管理自动跟进并查看 AI 用量，在存在未决请求或权限问题时获得明确提示和核查入口。
5. 作为住院医生，我希望医嘱执行记录按需查看，缺项由核对清单与操作栏说明，界面保留临床编码和必要恢复信息。

## 验收条件

### 继承前置交付

- [x] 基于 PR #402 合入后的最新 `main` 实施，沿用现有单栏主卡片、阶段页签与窄宽「更多」、两行患者头部、环节首行及 `WorkspaceActionBar`。
- [x] 保留页面内精简选型参数与三项病变测量、确认后的摘要和修改入口、耗材步骤顶部的行内指南摘要；扩展参数或完整依据才使用低频详情入口。
- [x] 保留「确认并预留 / 确认并更新预留」流程、选型修改后保留已确认数量并提示差异、术中收起术前预计、取消申请释放关联预留，以及分组差异行内说明。主流程无需展开旧「查看与调整」。
- [x] 耗材保存与确认沿用前置交付后的真实行为，保留编辑恢复和并发冲突处理；本票不额外恢复旧版 28 项参数表、750ms 自动保存、核对勾选或旧按钮组合。
- [x] 患者头部保持唯一跟进开关与「本次住院 AI 用量」入口；DRG 页不增加重复底部控制条，也不恢复独立「AI 解释」按钮或常驻 Token 大表。

### 手术申请、完整依据与术后更正

- [x] 移除页面底部「新增手术申请」折叠表单；在阶段头部提供「+ 申请手术」，无申请时空态或底栏提供主入口。弹窗填写计划术式、上海时间的计划手术时间和申请理由，成功后关闭，失败时保留输入与错误提示，提交中防止重复操作。
- [x] 对前置交付后仍适用的生成快照、完整指南依据、扩展参数和手工预留维护提供次级弹窗入口，保留已有编辑、重评或恢复能力；主屏继续显示关键测量、指南摘要、耗材清单和确认动作。
- [x] 预计或指南状态为 `unknown`、`failed`、`blocked` 时提供可定位原任务的核查或恢复入口，保留人工填写与既有恢复合同。
- [x] 保留已完成手术的最终耗材汇总，将「术后耗材更正与历史」改为「更正耗材」弹窗，保留更正理由、历史与并发校验，避免重复展示实际手术记录。
- [x] 在前置交付允许显示术后核查的状态下直接列出未解决待办及负责岗位，低频来源引用按需查看；有待实施或进行中手术时继续沿用前置交付的历史核查展示规则。

### 检查检验阅读状态

- [x] `reported` 检验报告直接展示完整结构化指标表，包括项目、结果、偏高/偏低标记、参考区间与签发时间；影像报告直接展示印象/结论正文与「查看影像」，无需先展开「查看完整报告」。
- [x] 检验报告可直接确认已阅；影像继续要求实际显示首帧后才解锁已阅，保留 `AgentReviewAnchor` 定位与报告修订后的门禁行为。
- [x] `acknowledged` 条目自动收拢为单行或双行摘要，包含项目、签发时间、关键结果与已阅状态；「查看全文」弹窗展示完整报告及既往修订，避免页面内逐层折叠。

### 其余页签与跟进用量

- [x] 医生医嘱条目的执行记录改为「执行记录 (n)」弹窗，保留内容与条数；病区护士仍沿用自己的执行流程。
- [x] 出院页保留前置核对清单、处理说明与办理时间线，病案页保留前置条件与首页核心字段；只清理剩余重复制度说明及医生分支中的编码范围尾注。
- [x] 医生界面清理剩余原始 UUID、内部修订号和 FHIR 引用串，正常显示 ICD-10、ICD-9-CM-3 与 DRG 编码；保留临床安全、权限、错误和恢复所需提示。
- [x] 复用患者头部的跟进开关与用量弹窗，累计调用及费用摘要、跟进停止、权限失效、归档和 `unknown` 未决请求均有可观察状态；未决请求有进入明细核查的快捷动作，停止跟进保留理由确认，归档后保持只读用量可查。
- [x] 用量弹窗保留汇总指标、阶段累计、请求分页、保留期提示及原有权限允许的管理员核对入口，无建议时不常驻空态说明大块。

### 弹窗、查询与跨宿主合同

- [x] 新增弹窗复用 `@clinmesh/ui` 的 `Dialog` / `AlertDialog` 与 `PortalContainerProvider`，兼容 React 18.3.1 / 19.2 的 ShadowRoot 宿主，具备键盘关闭与焦点归还，并保留提交中的关闭保护。
- [x] 手术主流程查询随页签激活且存在适用计划启用；行内指南摘要保留所需查询。只为低频详情服务的查询、请求分页及轮询在对应弹窗打开时启用，关闭后停止，无后台冗余轮询。
- [x] standalone Web 与 DSH Surface 在两档宽度、两种主题和两种语言下无横向裁切、双滚动卡死或患者队列姓名单字断行。

## 设计决定

- **以步骤化 AI 融合为基础继续减负**：本地预览 `.prototypes/2026-11-05-inpatient-streamlining/v1.html?variant=A` 仅提供单栏、减少折叠与低频弹窗的设计参考。与前置交付冲突的选型、指南和跟进入口布局，以 Issue #401 的正式规格及合入后的实现为基础，不把旧预览作为逐像素回退目标。
- **高频阅读直出、完整依据按需查看**：关键测量、指南摘要、耗材确认和待阅报告影响当前决策，直接展示；历史、工程计量与低频编辑使用详情入口。
- **按阅读状态整理报告**：待阅内容展开、已阅内容收拢，减少重复点击并为新待办留出空间。
- **共享业务合同保持一致**：新增弹窗不复制状态机，复用现有 Command、审计、版本与指纹校验和影像门禁。实施时在 [Agent Note](../decisions/README.md) 中记录最终组合与取舍。

## 测试策略

- 前端单测覆盖待阅直出、已阅收拢、报告修订与影像门禁，以及申请手术、更正耗材和执行记录弹窗的成功、失败、关闭与输入恢复；回归前置交付的步骤确认、修改选型后数量保留与差异提示。
- DSH 浏览器合同覆盖 React 18.3.1 / 19.2 下新增弹窗的挂载、键盘、焦点归还与提交保护；验证头部单一跟进/用量入口、归档后只读可查及未决请求核查。
- 查询合同断言详情弹窗关闭时不启动其专属请求与轮询，打开时读取正确患者和任务，关闭或切换患者后停止；行内摘要所需查询保持可用。
- 从真实产品入口更新 Playwright 旅程及辅助函数，使用 `inpatient-surgery-prototype.test.tsx`、`inpatient-doctor-clinical-pages.test.tsx`、`inpatient-doctor-stage-pages.test.tsx`、`inpatient-surgery-drg.test.tsx` 与受影响 PCI/DRG 旅程等现有入口，按合入后的文件归属补齐断言，不恢复已移除的旧面板选择器。
- 在两档宽度、两种主题及中英文下对照适用预览与最终规格验证；影像门禁以文字状态、自动断言和聚合结果验收，Agent 不读取影像像素或含影像截图。
- 文档检查运行 `pnpm verify:docs`、`pnpm docs:check`；实施修改 Agent Note 时加跑 `pnpm verify:agent-notes`，DSH 弹窗实现完成后检查对应构建产物体积。

## 依赖与风险

- **实施基线**：以 Issue #401 对应 PR #402 与前置岗位框架 PR #398 合入后的 `main` 为基础，继承步骤化选型、耗材确认和患者头部统一入口。
- **规格交付**：本文件与索引随本票实施提交；GitHub 跟踪票只引用正式规格及验收证据。
- **共享子面板与查询**：弹窗拆分只改变医生分支；保留护士、病案、医保岗位的原有职责、读取权限及边界，不把主屏摘要查询误设为仅弹窗打开时启用。
- **回归适配**：基于前置交付后的文件和选择器更新同一批相关测试，保留业务、审计与恢复断言，复用仍有效的验证证据。
