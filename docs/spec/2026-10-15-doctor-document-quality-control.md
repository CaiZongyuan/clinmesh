# 四项病历质控与签署前汇总

Status: implemented

实施跟踪：[Issue #178](https://github.com/CaiZongyuan/clinmesh/issues/178)。本文件拥有该切片的规则、提示、处理与验收合同；整体范围由[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)拥有。来源和自动整理沿用已实施的[全病历整理规格](2026-10-14-doctor-full-document-recording.md)。

## 问题与目标

医生录入病历时需要发现尚未记录的必要内容、已知事实遗漏、相互不一致的陈述，以及 Agent 新增但没有可靠来源的事实。现有自动整理的写入前核验和冲突处理不等同于整份病历的独立质控。

目标是在现有医生病历字段内显示具体事实矛盾和来源疑点，并在签署前汇总，帮助医生核实。界面不显示待补充提示或依据入口。提示不改写正文，不形成确定性的临床诊断，不新增签署阻断。

## 范围

- 面向当前病例的十字段病历草稿、本次患者问诊、医生补充、已发布报告，以及当前过敏、就诊表现、分诊和已确认诊断摘要；实时质控不自动加载来源历史、本院完诊病历全文或全量既往诊断清单。医生在本次问诊补充的既往史仍作为已提供事实检查，页面明确此检查范围，不声称已经核对患者全部历史。家族史、过敏史沿用[当前字段合同](2026-10-14-clinical-document-fields.md)，允许未记录，不增加签署必填项。不读取隐藏病例答案、Assistant reasoning 或影像像素。
- 首期缺项采用通用门诊病历规范与本项目已有文书模板，核对已有事实；不新增按病种的必问、必查清单。规则引用、门诊适用边界见[官方依据研究](../research/2026-10-15-outpatient-record-quality-rules.md)。
- 对主诉缺少持续时间等内容完整性建议，标为项目辅助提示，不冒称国家门诊强制条款。没有记录不等同于明确否认，不自动补为“无过敏”“无异常”。
- 质控随问诊、医生补充、报告和草稿变化更新。未保存编辑采用独立的去抖检查，不为质控隐式保存病历，不覆盖未保存输入。
- Agent 事实检查覆盖自动整理与 Agent 直接设置病历草稿的真实入口；保留写入归属和可核对的依据，不把医生自写文本因无引用误报为 Agent 无来源事实。

## 用户故事

1. 作为医生，我希望按本次就诊实际情况记录，不被模板缺项或其他待补充提示反复打扰。
2. 作为医生，我希望具体事实矛盾和来源疑点能定位到对应字段，直接结合问诊和报告核实，不增加依据展开入口。
3. 作为医生，我希望发现内容不对时直接修改病历，不需要对质控提示逐条确认、填写原因或标记保留。
4. 作为医生，我希望签署前看到仍未处理的问题，由我最终决定是否签署。

## 验收条件

- [x] A1：后台缺项检查仍绑定适用字段及规则依据，Web/DSH 不展示其待补充提示。已有元数据不要求在正文重复填写；没有检查结果不意味着必须接受检查，不把住院全套要求用于普通门诊，不凭 Encounter 数量推断初诊或复诊。
- [x] A2：后台已知事实遗漏和事实不一致结果保留相关来源原文及时间；界面隐藏归类为待补充的遗漏，仅展示待核实问题，不提供依据展开。不同时间的合理变化、明确更正、否定与不确定性不直接判为矛盾。
- [x] A3：Agent 无来源提示准确区分仍有效的 Agent 新增片段与人工文本；来源引用归属与语义支持分别验证，无来源或不支持的内容不得以模型自述作为依据。
- [x] A4：实时结果绑定病例、Workspace/Epoch、当前授权、草稿内容和来源版本。处理中继续编辑、保存、补充来源、切换病例或重置后，迟到结果不覆盖当前状态；已签文书不因质控变化而被修改。
- [x] A5：对应病历字段、旧处理记录和签署汇总均隐藏所有 `needs-completion` 问题，覆盖十字段；仅显示待核实问题，不使用模型猜测的风险等级。无“查看依据”按钮、展开面板或来源引文，适应 React 18/19 ShadowRoot、窄分屏、中英文和应用字号。
- [x] A6：医生通过编辑正文或补充信息解决问题后更新结果；Web/DSH 不提供“已核实，保留”、确认保留或原因填写，自动记录无需逐条确认。仍在展示范围内的已有核实记录以只读历史展示，不成为新患者事实。
- [x] A7：签署前汇总未处理问题，检查待完成、过期或失败时如实显示，提供恢复入口。新增提示、失败或未完成检查不新增签署门禁、勾选项或自动操作；原有必填、后台来源快照、签署预览版本和最终人工确认继续生效，不恢复旧自动整理的逐条核对流程。
- [x] A8：自动检查不抢焦点、不逐次向聊天播报，不自动修改、采纳或正式提交业务内容。未配置模型或模型失败时仍保留确定性检查和明确的语义检查状态，不宣称“质控通过”。
- [x] A9：公开 HTTP 与真实 SQLite 验证四类问题、应不提示的样本、历史处理兼容、权限、幂等、并发、迟到结果、重启和签署边界；真实页面验证直接编辑更新提示、无待补充或依据入口及无逐条确认的签署前汇总。

## 设计决定

ClinMesh 拥有质控输入、持久任务、校验、版本归属与人工处理记录，DSH 只提供辅助模型能力。复用现有 Command、outbox、模型绑定和授权机制，不把质控塞入诊疗建议的目录与指南分支，也不重建通用运行器。

病历的十字段、直接记录、变动提醒与签署继续沿用[当前字段规格](2026-10-14-clinical-document-fields.md)。质控不展示待补充问题和依据入口，也不给病历录入添加逐条来源、应用、核对、核实保留或撤销入口；具体展示边界由[安静质控提示决策](../../.agents/notes/implemented/architecture/2026-10-18-quiet-document-quality-hints.md)拥有。

确定性检查负责适用模板的空字段、来源身份和可确定的引用归属；模型负责已知事实是否遗漏、语义不一致和正文完整性的辅助核对，必须返回可验证的位置和依据。模型否定结论是合法结果，不能用结构化修复诱导改为肯定。输入超出处理能力时说明检查不完整，不截断后宣称全部检查完成。

同一输入的重复触发合并处理，旧代次和旧输入结果失效；录入控制版本不代替草稿与来源版本。未保存检查与临床草稿分别保存，签署摘要只呈现实际对应内容的结果，过期结果明确标识。已有人工保留只适用于该问题及其相关正文、证据，不以全病例永久忽略代替复核；既有公开接口保留兼容，页面不调用它生成新的核实记录。

输入身份与独立授权见[质控决策](../../.agents/notes/implemented/architecture/2026-10-15-doctor-document-quality-control.md)，实时输入范围与安静记录状态见[实时辅助边界决策](../../.agents/notes/implemented/architecture/2026-10-18-current-encounter-quality-and-quiet-recording.md)，直接编辑与历史处理兼容的取舍见[提示交互决策](../../.agents/notes/implemented/architecture/2026-10-18-advisory-quality-without-confirmation.md)。

## 测试策略

采用现有公开 HIS HTTP、共享 Command/Query 和 file-backed SQLite 作为主要 seam，仅替换外部模型网络边界。覆盖大量既往资料不进入实时检查、本次来源完整进入模型、实际本次正文超限仍明确不完整，以及正常问题和不应提示样本；使用可控的在途响应验证旧结果、源更新、并发编辑、病例切换、Epoch reset、任务重启和权限失效。

前端通过真实病历入口验证未保存编辑、结果身份、字段定位、所有待补充提示及依据入口隐藏、直接修改后提示更新、历史处理只读展示、失败恢复和签署汇总；不提供逐条核实动作，也不调用保留接口。交互覆盖 React 18/19 的键盘、焦点、长内容、窄分屏与 ShadowRoot。实际 DSH 宿主验收使用合成病例与模型替身，不读取影像像素或截图，不以替身结果证明真实模型的临床准确性。跨包与公开协议变化运行项目必需检查。

## 范围外

- 按病种的必问、必查清单，诊断合理性、检查适应证与完整用药安全质控。
- 住院病案首页、DRG、收费与医保结算质控。
- 语音、附件、Mobile 入口、独立自主仿真 Agent，以及自动代问或自动修正文书。
- 新增签署阻断、模型临床风险等级与全面监管合规认证。
