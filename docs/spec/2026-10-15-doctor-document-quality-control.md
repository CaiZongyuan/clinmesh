# 四项病历质控与签署前汇总

Status: implemented

A 与 B 条件对应已实施的 [Issue #178](https://github.com/CaiZongyuan/clinmesh/issues/178)；C 条件对应已实施的紧凑展示与问题定位增量 [#224](https://github.com/CaiZongyuan/clinmesh/issues/224)；D 条件对应任务复用与失败诊断修复 [#223](https://github.com/CaiZongyuan/clinmesh/issues/223)。本文件拥有该切片的规则、提示、处理与验收合同；整体范围由[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)拥有。来源和自动整理沿用已实施的[全病历整理规格](2026-10-14-doctor-full-document-recording.md)。

## 问题与目标

医生录入病历时需要发现尚未记录的必要内容、已知事实遗漏、相互不一致的陈述，以及 Agent 新增但没有可靠来源的事实。现有自动整理的写入前核验和冲突处理不等同于整份病历的独立质控。

目标是在现有医生病历字段内显示可定位、可查看依据的提示，并在签署前汇总未处理问题，帮助医生补充和核实。提示不改写正文，不形成确定性的临床诊断，不新增签署阻断。

## 范围

- 面向当前病例的十字段病历草稿及其已有患者问诊、医生补充、已发布报告和授权可见事实；家族史、过敏史沿用[当前字段合同](2026-10-14-clinical-document-fields.md)，允许未记录，不增加签署必填项。不读取隐藏病例答案、Assistant reasoning 或影像像素。
- 首期缺项采用通用门诊病历规范与本项目已有文书模板，核对已有事实；不新增按病种的必问、必查清单。规则引用、门诊适用边界见[官方依据研究](../research/2026-10-15-outpatient-record-quality-rules.md)。
- 对主诉缺少持续时间等内容完整性建议，标为项目辅助提示，不冒称国家门诊强制条款。没有记录不等同于明确否认，不自动补为“无过敏”“无异常”。
- 质控随问诊、医生补充、报告和草稿变化更新。未保存编辑采用独立的去抖检查，不为质控隐式保存病历，不覆盖未保存输入。
- Agent 事实检查覆盖自动整理与 Agent 直接设置病历草稿的真实入口；保留写入归属和可核对的依据，不把医生自写文本因无引用误报为 Agent 无来源事实。

## 用户故事

1. 作为医生，我希望录入时知道哪些内容待补充，并能定位到对应字段。
2. 作为医生，我希望事实遗漏或矛盾提示能展示原文和时间，方便核实。
3. 作为医生，我希望核实后保留原文，并避免相同依据反复打扰。
4. 作为医生，我希望签署前看到仍未处理的问题，由我最终决定是否签署。

## 验收条件

- [x] A1：缺项提示定位到适用字段并说明规则依据。已有元数据不要求在正文重复填写；没有检查结果不意味着必须接受检查，不把住院全套要求用于普通门诊，不凭 Encounter 数量推断初诊或复诊。
- [x] A2：已知事实遗漏展示相关来源原文；事实不一致展示待核对的正文与来源，或两处来源及其时间。不同时间的合理变化、明确更正、否定与不确定性不直接判为矛盾。
- [x] A3：Agent 无来源提示准确区分仍有效的 Agent 新增片段与人工文本；来源引用归属与语义支持分别验证，无来源或不支持的内容不得以模型自述作为依据。
- [x] A4：实时结果绑定病例、Workspace/Epoch、当前授权、草稿内容和来源版本。处理中继续编辑、保存、补充来源、切换病例或重置后，迟到结果不覆盖当前状态；已签文书不因质控变化而被修改。
- [x] A5：提示显示在对应病历字段，分类为“待补充”或“待核实”，不使用模型猜测的风险等级。默认紧凑，来源按需展开，能通过键盘操作并适应 React 18/19 ShadowRoot、窄分屏、中英文和应用字号。
- [x] A6：医生通过编辑或补充信息解决问题后更新结果；也可执行“已核实，保留”，原因选填，保存处理人、时间及原因。相同相关正文和依据不重复提示，相关正文或来源变化后重新检查，不把核实记录解释为新患者事实。
- [x] A7：签署前汇总未处理问题，检查待完成、过期或失败时如实显示，提供恢复入口。新增提示、失败或未完成检查不新增签署门禁、勾选项或自动操作；原有必填、后台来源快照、签署预览版本和最终人工确认继续生效，不恢复旧自动整理的逐条核对流程。
- [x] A8：自动检查不抢焦点、不逐次向聊天播报，不自动修改、采纳或正式提交业务内容。未配置模型或模型失败时仍保留确定性检查和明确的语义检查状态，不宣称“质控通过”。
- [x] A9：公开 HTTP 与真实 SQLite 验证四类问题、应不提示的样本、处理持久化、权限、幂等、并发、迟到结果、重启和签署边界；真实 DSH 入口验证实时提示、来源与签署前汇总。

## 说明与判断边界

用户要求同步改进病历质控说明，保留现有四类问题、处理记录和签署边界；本节拥有该增量，不改变诊疗建议的生成合同。

- [x] B1：新质控问题除具体字段和一句摘要外，还包含“影响”和“处理建议”，默认展示策略由 C 条件拥有；依据原文、时间和归属继续可展开。旧持久问题可读取，不伪造不存在的解释。
- [x] B2：确定性空字段与 Agent 来源问题也说明影响和可执行的核实或修改动作。来源无法核验只表明系统不能证明支持，不据此断言患者事实错误。
- [x] B3：缺项仅限当前适用模板及已确认的主诉内容完整性项目提示；非空正文不能通过任意 missing-field 变成按病种的必问、必查清单。没有血常规、CRP、病原学或其他未安排检查的结果不自动构成病历缺陷，家族史和过敏史继续允许未记录。
- [x] B4：生成与独立核验同时核对摘要、影响、处理建议及实际原文；区分患者自述与分诊 37℃等记录，不把不同时间、不同来源或不确定表达直接判成矛盾。检查不完整或不能确认时显示相应状态，不发布已证实事实错误的口吻。
- [x] B5：官方书写原则保持真实来源与适用边界，具体模型推断和项目内容建议明确为辅助提示，不冒称官方要求患者接受检查。说明内容参与问题关联指纹，新策略使旧缓存与旧核实保留的不同含义失效。
- [x] B6：公开 HTTP、真实 SQLite、真实 Web 及 React 18/19/原生 DSH 验证具体说明、应不提示的检查缺项或伪矛盾、未保存保护、核实保留及签署不增加门槛。没有以合成替身证明实模语义正确。

## 紧凑提示与问题定位

本节拥有已批准 v4 原型对应的质控展示要求，替代影响和处理建议默认全部展开的布局；A 与 B 的问题判断、来源核验、人工处理和签署边界继续生效。诊疗待办的自动准备和清单由[诊疗建议规格的 R 条件](2026-10-13-doctor-guideline-recommendations.md#自动准备与待开具清单)拥有。

- [x] C1：没有具体待处理问题时，不在诊疗或病历正文显示质控块、占位、模板说明、检查通过标记或系统状态长文。仅有检查未完成、预算不足、过期或失败时也不以“病历有问题”占据正文；这些状态在按需查看的说明内如实提供，不因此宣称检查通过。
- [x] C2：有具体问题时默认展示医生能直接理解的一条短提示，例如“过敏史与患者自述不一致，请核对”；多处问题以“一条提示＋另有 N 处”呈现，展开后逐项可操作。影响、处理建议、依据及检查范围放在按需查看的说明内，不要求医生阅读模板、预算和内部核验术语才能找到问题。
- [x] C3：点击问题可切到病历对应字段、滚动至可见位置、聚焦，并突出可验证的问题原句；缺项定位对应空字段。原文已被编辑导致精确位置失效时，不选中无关文字，至少定位当前对应字段并提供核对入口；定位不隐式保存或覆盖未保存输入。
- [x] C4：保留“已核实，保留原文”与现有处理人、时间、原因合同；核实保留不修改正文，相同相关正文和依据不反复提示，相关正文或来源变化后重新核对。问题解决后更新提示，全部解决后收起质控块。
- [x] C5：无问题与未完成状态必须分清；主页面隐藏检查状态不意味着后台已经完成，也不改变签署前既有校验、版本预览或人工确认。质控不新增签署门槛、勾选项、自动修正文书或逐条采纳流程，不改病历自动整理、字段状态及手改方式。
- [x] C6：从真实病历、诊疗栏目与说明入口验证无问题、多个问题、未完成、过期、失败、精确定位、缺项定位、未保存编辑、核实保留和问题解决。继续覆盖 Web、React 18/19、ShadowRoot、键盘、窄分屏及应用字号，且只有医生主动点击问题时才改变焦点。

## 任务复用与失败诊断修复

本节追踪 [Issue #223](https://github.com/CaiZongyuan/clinmesh/issues/223)，沿用本文件的检查范围、来源核验和签署边界。

- [x] D1：同一病例、Workspace/Epoch、当前授权、正文、相关可见来源、Agent 内容归属与策略版本对应一个规范质控任务。A → B → A 导航、栏目卸载重挂、无关工作流状态变化不新增任务或模型调用；成功、在途和失败均可复用。客户端请求身份随 QueryClient 保留，服务端任务随 SQLite 持久化。
- [x] D2：已保存草稿与真正未保存候选分别保留自己的正文及版本绑定；完整临床输入相同时共享规范任务，包括候选检查进行中保存同正文、多个 clientRevision 和重启恢复。草稿版本只约束读写归属，不独自触发新模型检查。正文、相关来源、Agent 归属或授权真正变化后重新检查，旧输入结果不覆盖新内容。
- [x] D3：检查失败后，导航、轮询、其他候选绑定或同正文保存不隐式重试。只有明确的重新检查请求推进该输入的任务代次；其他绑定随任务读取新代次，旧代次迟到结果不能覆盖。真正的新临床输入仍自动检查。
- [x] D4：保留生成或独立核验阶段，以及 JSON 格式、结构、来源、检查范围、核验覆盖、认证、超时、输入超限和服务失败等有限安全类别。说明使用医生可理解的短句，不把固定检查范围当成失败原因，不暴露模型原文、异常正文、密钥或未验证引用。旧持久状态没有新诊断字段时仍可读取。
- [x] D5：DSH 沿用当前 SDK 支持的文本流和严格 JSON/领域验证，接受可证明是单个 JSON 数据对象的既有返回方式；不传递 SDK 未支持的 `response_format`，不修改 DSH 官方源码或切换 Provider/模型。安全的具体校验类别进入有限纠正反馈，保持既有总 deadline、次数及限流边界；合法语义否定不作为格式错误纠正，无效引用或结论不能通过静默丢弃而变成成功。
- [x] D6：HTTP/SQLite、真实病历页面及 React 18/19 ShadowRoot 回归分别核对任务创建数与模型调用数，覆盖三态导航、保存与候选复用、显式重试、别名映射、并发迟到、重启和授权隔离。通常先生成，有候选或待核实 Agent 片段时再独立核验；每步的有限纠正不算新的质控任务。完整资料超过预算时仍直接报告检查不完整，不截断后宣称完成，不新增签署门槛。

## 设计决定

ClinMesh 拥有质控输入、持久任务、校验、版本归属与人工处理记录，DSH 只提供辅助模型能力。复用现有 Command、outbox、模型绑定和授权机制，不把质控塞入诊疗建议的目录与指南分支，也不重建通用运行器。

病历的十字段、直接记录、变动提醒与签署继续沿用[当前字段规格](2026-10-14-clinical-document-fields.md)。本切片的依据展开和核实保留只属于独立质控问题，不给自动整理重新添加逐条来源、应用、核对或撤销入口。

确定性检查负责适用模板的空字段、来源身份和可确定的引用归属；模型负责已知事实是否遗漏、语义不一致和正文完整性的辅助核对，必须返回可验证的位置和依据。模型否定结论是合法结果，不能用结构化修复诱导改为肯定。输入超出处理能力时说明检查不完整，不截断后宣称全部检查完成。

同一输入的重复触发合并处理，旧代次和旧输入结果失效；录入控制版本不代替草稿与来源版本。未保存检查与临床草稿分别保存，签署摘要只呈现实际对应内容的结果，过期结果明确标识。人工保留只适用于该问题及其相关正文、证据，不以全病例永久忽略代替复核。

输入归属、独立授权与人工处理的取舍见[质控决策](../../.agents/notes/implemented/architecture/2026-10-15-doctor-document-quality-control.md)。

## 测试策略

采用现有公开 HIS HTTP、共享 Command/Query 和 file-backed SQLite 作为主要 seam，仅替换外部模型网络边界。逐行为先确认目标失败再实现，覆盖正常问题和不应提示样本；使用可控的在途响应验证旧结果、源更新、并发编辑、病例切换、Epoch reset、任务重启和权限失效。

前端通过真实病历入口验证未保存编辑、结果身份、字段定位、来源、核实保留、失败恢复和签署汇总；新增交互覆盖 React 18/19 的键盘、焦点、长内容、窄分屏与 ShadowRoot。实际 DSH 宿主验收使用合成病例与模型替身，不读取影像像素或截图，不以替身结果证明真实模型的临床准确性。跨包与公开协议变化运行项目必需检查。

## 范围外

- 按病种的必问、必查清单，诊断合理性、检查适应证与完整用药安全质控。
- 住院病案首页、DRG、收费与医保结算质控。
- 语音、附件、Mobile 入口、独立自主仿真 Agent，以及自动代问或自动修正文书。
- 新增签署阻断、模型临床风险等级与全面监管合规认证。
