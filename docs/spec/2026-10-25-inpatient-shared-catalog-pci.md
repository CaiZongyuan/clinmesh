# 门诊住院共享目录与 PCI 数据准备

Status: implemented

## 问题与目标

门诊与住院已有诊断参考库、院内药品及检验服务目录的共享基础，但住院启用依赖少量固定示例，未配齐项目难以检索，医生本次用量也被限定为目录中的预设值。本需求补齐共享目录、医生填写用量、缺项展示，以及冠心病 PCI 所需的可追溯数据前置。

[Issue #303](https://github.com/CaiZongyuan/clinmesh/issues/303)承接本规格。[门诊住院共享支付与 DRG 一体化](2026-10-15-drg-prescription-budget.md)继续拥有支付、患者医保、DRG 和核定等总体要求，由 [#225](https://github.com/CaiZongyuan/clinmesh/issues/225)追踪；同一次冠心病／PCI 的完整跨岗位页面链和联合验收统一由 [#279](https://github.com/CaiZongyuan/clinmesh/issues/279)收口，#303 为其前置。

用户确认的完整目标保持不变：一例无复杂并发症、非急诊患者，经医生评估行冠脉造影并植入一枚支架，术后用药、稳定出院、费用结清、病案归档、DRG 分组及模拟核定。该完整流程只在 #279 验收，本规格不再建立第二份整链完成条件。

## 范围

### 共用主数据，分别声明使用范围

- 诊断共用既有参考库及版本；本次住院主次诊断、逐项入院病情和确认修订仍由住院业务拥有。
- 药品共用具体产品身份、厂家、剂型、规格、包装、已确认单位及价格，补齐住院使用所需配置，不按同名药合并不同产品。
- 检验共用已发布的院内项目、组合与子项、标本、结果类型、单位和参考范围；补齐住院开展范围及收费定义。
- 目录变更采用明确版本。旧医嘱、实施、报告、费用及回执保留原冻结快照，各次就诊事实分别保存。

### 医生填写本次用量

- 医生在本次医嘱中填写合法的每次剂量和频次，常用用法只作可修改建议，不把具体每次用量当作目录启用前必须列好的枚举。
- 产品规格、最小制剂单位、包装及发药/收费单位的关系属于主数据。只有依据明确或明确标记的合成换算关系才可自动换算，不从药名、模糊规格或未知价格分母猜算。
- 单位不匹配、数量非法或无法换算时说明具体原因。保留角色、过敏、本例明确声明的有界用药规则，以及发药时的有效批次和库存检查。
- 复用既有医嘱、校对、发药、给药和计费 Command，验证新增录入与目录配置能接入这些动作，不另建状态机。

### 显示待补项目

- 住院可搜索和分页查看共享目录中的可用项目及未配齐住院条件的候选。
- 候选显示具体缺项，例如规格、发药/计价单位、换算、院内价格或开展条件；不满足相应开立条件的条目不能绕过服务端检查提交。
- 医生尚未填写本次剂量只在医嘱表单提示，不标记为产品基础资料缺失。
- 单条资料缺项不影响其他完整项目，区分待补、停用、查询无结果和加载失败。

### PCI 前置数据

- 首批配齐固定冠心病／择期单枚支架示例所需的药品、检验、术式和冠脉耗材资料，以及单位、价格、库存和有界规则。
- 提供固定版本、可追溯的合成病例底稿及编码核对资料，供 #279 建立实际病例及来源绑定；本票不因准备底稿而自动创建门诊/住院就诊、挂号费用、临床诊断或已执行事实。
- 优先复用门诊已有完整资料及规则。缺项可另补明确标记的合成院内值；原始来源、空值和适用性保留，合成补充分别保存。
- 沿用已确认表价及口径；来源价格分母不明时保留原报价，演示收费另声明单位和模拟身份，不把猜测写回来源，不用零价掩盖缺价。
- r3 目录及报价作为固定参考输入。保留编码体系、来源版本和定位，不把医保药品序号当具体产品码，不无依据合并临床版与医保版编码。
- 可补充目标 PCI 病组所需的独立合成支付参数数据及版本，供既有核定机制消费；本票不定义新分组、支付或核定算法，不提供可手填的核定金额。
- 资料准备和院内目录补缺幂等，保留旧配置、患者、业务及回执；准备或重启不会自动执行诊疗、收费、归档或重置业务。

### 与整链交接

#303 负责目录搜索、医生用量录入和缺项说明的必要页面。正常启动的可执行 DRG 规则包装载、固定病例来源与就诊物化、医生/病案 DRG 结果页面、医保岗模拟核定入口，以及整链数据和权限接线统一由 #279 按原总体规格补齐并验收。既有机制由[临床流程](../architecture/clinical-workflows.md)、[存储与事务](../architecture/storage.md)及[住院规格](2026-10-20-inpatient-closed-loop.md)继续拥有；DRG 设计理由见[仿真链决策](../decisions/implemented/feature/2026-10-23-drg-inpatient-simulation-chain.md)。

## 用户故事

1. 作为住院医生，我希望检索到与门诊同源的药品、检验及诊断资料，减少重复维护。
2. 作为住院医生，我希望自行填写本次合法用量和频次，由系统核对单位和数量，常用值仅作建议。
3. 作为目录使用者，我希望看到未配齐的候选及具体原因，区分数据缺项、停用和查询失败。
4. 作为药师和护士，我希望新增目录配置能接入现有发药与给药流程，单位、数量和批次明确。
5. 作为数据维护者，我希望为固定 PCI 病例准备有版本的底稿、药耗及检查资料，并保留原始来源与合成补充的区别。
6. 作为资料维护者，我希望重复准备不覆盖旧配置和业务快照，不自动制造就诊、诊疗或费用。
7. 作为联合验收负责人，我希望 #279 能直接消费本票交付的数据与目录能力，复用同一套业务实现及证据。

## 验收条件

- [x] A1：两端按同一主数据身份和来源版本检索药品、检验和诊断；PCI 所需院内项目在住院端可选用。
- [x] A2：医生填写合法用量和频次，不受旧固定用量枚举限制；单位、换算、非法数量、角色和发药库存等门禁仍有效。
- [x] A3：待补候选可检索并显示具体缺项，不能绕过写入检查；医生未填本次剂量不成为产品缺项，其他完整项目正常使用。
- [x] A4：来源原文、空值和适用性保留，合成补充独立标注，已确认价格不被启动覆盖，缺价不当零价。
- [x] A5：重复准备不重复新增目录或库存基础数据，不覆盖旧业务和回执；旧版本医嘱、报告与费用继续可读。
- [x] A6：固定 PCI 底稿、所需药耗/检查/编码和合成参数数据具备明确身份、版本及来源，可供 #279 消费；底稿不冒充已发生的临床事实或真实分组结果。
- [x] A7：新增配置经现有公开开立、校对、发药/执行和费用路径取得局部接入证据，重复操作不重复记账；不另建一条业务状态机。
- [x] A8：目录、用量和缺项页面在实际入口可操作，覆盖加载失败、无结果、停用、缺项、非法量、库存不足及旧版本冲突。
- [x] A9：资料准备不会隐式创建门诊或住院就诊、挂号费、实际手术、归档或核定；病例来源与实际就诊由 #279 明确接入。
- [x] A10：交付数据入口、版本及局部验证证据供 #279 引用，不将 #303 完成视为 #279 或 #225 的整体验收完成。

## 设计决定

共用三类主数据，首批只配齐固定冠心病 PCI 路径所需项目；允许明确标记的合成院内补数，保留来源缺项和已确认表价。医生填写本次用量，候选缺项清楚展示。#303 是目录与数据前置，#279 是唯一整链验收出口，#225 保持总体归属。

复用已有数据发布、院内目录及共享 Command。具体模型及接口变更核对两侧调用者并保持旧数据兼容；非平凡实现取舍按工程规则记录 Agent Note。

## 测试策略

在既有公共目录准备/发布入口、业务 HTTP/Command 和真实目录/医嘱页面建立有效失败回归，再实现最少必要变更。使用合成 Provider、受控响应和临时数据库，验证检索、缺项、医生用量、换算、发药/执行计费、幂等、版本和历史读取；不依赖私有函数结构。

Playwright 验证本票新增页面和关键拒绝路径，涉及 DSH 共享表单时覆盖 React 18/19。完整入院、费用结清、归档、DRG 与模拟核定旅程只在 #279 建立和引用一组联合证据，不在本票重复完整矩阵。运行受影响类型、静态、文档及必要检查，并完成同一固定快照的 Standards/Spec 双轴审查；真实模型、压测及运行库变更仍按对应明确授权执行。

## 范围外

- #225 已有支付、患者医保、DRG、核定和归档后更正机制的重新建设。
- #279 拥有的完整跨岗位页面接入、病例来源/就诊物化、规则包装载及整链联合验收。
- 全院全部参考条目逐项住院化、通用临床规则平台、设备采集、全院供应链、真实医保平台、真实全成本与盈亏分析。
- 将用户原工作区未提交原型或其他 WIP 自动纳入交付。

## 依赖与风险

- r3 部分价格分母、规格、适用期及编码对应关系尚不完整，需按来源与演示边界补数据。
- 自由剂量、执行排程及库存/收费数量的接口两侧必须一起核对，不能仅把前端下拉框换成输入框。
- 当前住院检查来源依赖门诊物化底账；#279 须明确来源绑定及可能附带的行政/收费事实，本票不通过伪造来源或隐式门诊来解除门禁。
- 若出现影响本票范围的新实质性取舍，先澄清受影响部分，不静默转移或缩减验收。
