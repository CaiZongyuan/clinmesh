# DSH 上游升级通过 PR 标签跳过精确版本

Status: implemented

## 问题与目标

维护者决定跳过 DSH `0.2.1-rc.3` 并关闭升级 PR #298 后，发现流程仍把同一版本作为候选创建 PR #306。关闭记录和评论没有进入版本选择逻辑，重复候选使已作出的维护决定失效。

目标是让维护者通过 GitHub PR 标签表达跳过决定，无需每次修改仓库配置或合并一次策略提交；后续版本和其他组件继续正常发现。

## 范围

覆盖 DSH 上游只读发现、发布与相关 GitHub adapter。长期操作合同由[持续升级指南](../deployment.md#dsh-持续升级)拥有，取舍由[候选发现与验收决策](../decisions/implemented/process/2026-09-15-dsh-upstream-candidate-verification.md)拥有。

## 用户故事

1. 作为维护者，我希望给升级 PR 添加“跳过此版本”标签并关闭，就能停止重复收到相同目标。
2. 作为维护者，我希望移除跳过标签后能重新评估目标，同时保留后续正式版、RC 和其他组件的更新发现。

## 验收条件

- [x] 同仓库、同目标分支上带“跳过此版本”标签且已关闭未合并的自动升级 PR，形成可读取的跳过决定；已关闭的 PR 可以补加标签。
- [x] 跳过范围来自该 PR 精确 HEAD 的候选差异，只匹配变化组件的精确 npm 版本或源码 commit，不排除未变化的组件。
- [x] 即使当前基线摘要已变化或原升级分支已删除，历史跳过决定仍生效；读取候选不能使用可能已复用的分支名。
- [x] 相同目标不再产生升级差异；仅有被跳过目标时，发布不创建 PR、不改写候选、不输出验收 HEAD，也不推进已验证锁。
- [x] 后续正式版、RC、源码 commit 和其他组件继续发现；没有可用更新时保留基线，不产生回退。
- [x] 移除所有记录该目标的跳过标签后恢复评估；普通关闭、已合并、其他目标分支、普通 PR 和外部 fork 不形成跳过决定。
- [x] 查询覆盖全部历史分页；合法的已删除 fork 空仓库字段不会阻断发现。跳过记录或候选读取失败、内容非法时停止，不解释为没有跳过决定。
- [x] 只读发现与发布使用同一规则，既有活动候选撤销检查与失败证据保存顺序继续有效。

## 设计决定

PR 标签表达维护意图，PR 的精确提交拥有被拒绝目标的身份。每次跳过不增加仓库策略文件，也不从自由文本评论或普通关闭状态推断决定；详细规则链接当前操作合同。

## 测试策略

通过 `scripts/dsh-upstreams.spec.ts` 的发现、GitHub adapter 和真实 CLI process 入口，使用受控 npm/GitHub 响应验证精确匹配、后续版本、分页、标签移除、空仓库、错误与无发布副作用。`scripts/dsh-upstreams-verify.spec.ts` 保留既有候选验收及撤销合同。真实 GitHub 只读发现用于核对历史标签与候选读取接线，不执行候选安装或模型请求。

## 范围外

自动合并升级 PR、自动适配上游、修改已验证运行组合、改造日常 Profile，以及为跳过某一版暂停整个升级工作流。

## 依赖与风险

依赖 GitHub PR 标签、历史 PR 元数据及精确候选提交可读取。自动化修复需进入目标分支后才约束其工作流；读取失败时保留明确错误，维护者修复权限或候选可读性后再运行发现。
