# 检验真值单位换算与失败恢复

Status: implemented

## 问题与目标

[#203](https://github.com/CaiZongyuan/clinmesh/issues/203) 中，Synthea Case Truth 与冻结检验服务的单位不同，受支持的等价或比例转换被误判为结果无效。故障发生在模型调用前，重复尝试不能恢复；医生和 DSH 又缺少与后端一致的取消入口。目标是保留真实合成结果的数值语义，并提供准确的失败分类与恢复动作。

## 范围

- 已发布 Laboratory Service 的单项和组合报告，使用申请中冻结的单位、报告闭包及患者适用参考范围。
- 受控的 UCUM 换算：`10*3/uL → 10*9/L`、`10*6/uL → 10*12/L` 的因子为 1；`g/dL → g/L` 的因子为 10；明确匹配葡萄糖分析物时，`mg/dL → mmol/L` 使用现有审核映射的因子 `0.0555075`。
- 确定性真值兼容错误的自动尝试、人工重试，以及医生页面、DSH 与 CLI 的恢复合同。
- 存量失败申请沿用冻结输入重试；不改写已成功报告、Case Truth 或服务快照。

## 用户故事

1. 作为医生，我希望可换算的检验真值生成正确报告，以便读取实际结果和异常判读。
2. 作为医生，我希望明确知道哪些失败可以重试，并能取消没有生成报告的失败申请。
3. 作为 Agent，我希望恢复动作与人类界面及后端状态机保持一致，不反复执行确定失败的操作。

## 验收条件

- [x] 等价计数单位保留数值，质量浓度按比例换算；报告单位及参考范围来自冻结服务。
- [x] 葡萄糖转换有明确分析物约束，不能将其因子用于其他分析物。
- [x] 精确真值保持异常，不回退为健康基线，不以夹紧或不必要舍入改变真值；换算溢出或不兼容输入明确拒绝。
- [x] 任一组合叶子不兼容时整单失败，不生成部分正式报告或结果快照。
- [x] 真值兼容错误使用 `INVESTIGATION_TRUTH_INCOMPATIBLE`，首次自动尝试即失败；人工重试拒绝该已分类错误，并对既有不可恢复的 `INVESTIGATION_UNSUPPORTED` 落实相同后端限制。
- [x] 模型超时、连接失败及可恢复输出错误保持现有重试语义。
- [x] 旧 `INVESTIGATION_OUTPUT_INVALID` 申请仍可显式重试，支持的单位转换可恢复，不迁移原始真值或冻结服务。
- [x] 医生页面对所有有取消权限的 `generation-failed` 申请提供取消；仅确定性错误隐藏重试并显示准确原因。只读和进行中状态保留原有边界。
- [x] DSH 的 operation 可见性与目标申请校验均允许取消失败检验申请，仍保留岗位、病例绑定、人工批准和版本检查。
- [x] CLI 的 Operation Catalog、恢复指引与运行时错误合同一致。

## 设计决定

单位换算归属 Investigation 解析精确真值的共享路径，运行时只支持显式矩阵，不引入完整 UCUM 引擎或模型修正。精确结果保持换算后的有限数值；既有 precision 继续用于健康基线生成，不额外截断真实合成观察值。新分类只区分不可重试的精确真值兼容失败，不把所有 `INVESTIGATION_OUTPUT_INVALID` 一概禁用重试。取消复用既有共享 Command，不新增状态机或写入口。

## 测试策略

复用 Server HTTP／真实临时 SQLite 与 `InvestigationService.resolveForRequest` 公共边界验证转换、异常判读、冻结快照、整单原子性、自动尝试、旧单重试及 DSH 授权；复用医生页面测试验证错误信息、取消、重试及只读条件。通过 Playwright 的真实 Web 入口验证生成与恢复动作。按 TDD 逐项记录目标行为失败和通过证据；实施后对固定基线执行 Standards／Spec 双轴审查。

## 范围外

新增检验项目、完整 UCUM 引擎、任意分析物的质量／物质的量转换、病例能力过滤目录、放射／病理、真实医疗数据以及成功报告重写。

## 依赖与风险

JavaScript 数值保留 IEEE 754 语义，换算结果必须有限；葡萄糖因子沿用已有审核映射，不能用于未知分析物。存量错误码没有可靠的细分类信息，保留其显式重试入口，由新 resolver 重新分类。无外部数据迁移依赖。
