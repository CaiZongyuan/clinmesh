# 住院七岗位按原型重排

Status: approved

## 问题与目标

2026-11-02 用户确认住院七个岗位的交互原型（"都挺好的 就按这个来"），[DSH 外壳、交互反馈与助手呈现优化](2026-11-02-dsh-shell-feedback-redesign.md)据此写了住院页面的验收。那些验收以行为为主，例如"轮到你"、六步进度和队列分组；实施后行为都满足了，但页面结构没有按原型做。用户复审主线后决定："住院部分就照着那个做"。

复审和带数据巡检发现：

- 患者头部、页签、条目行和左侧队列都没有采用原型结构。
- 住院收费：
  - 头部只突出"需补交 ¥0"，应退的 ¥950 埋在下方；
  - 六步进度里没有发生的补交步骤直接打勾；
  - 已经无需补交时，仍然展示整套收款表单；
  - 费用页签露出核查待办和手术核查的开发文案。
- 住院药房的批次显示 `lot-…` 原始编号，没有采用原型的"药品为队列行、批次 + 数量 + 单位"结构。

2026-11-04 用户逐页复审住院医生六个页签，认为诊断医嘱页"整体使用不方便""诊断逻辑混乱"，其他页签也与原型有差距。走查发现：

- 诊断医嘱：院内诊断目录与国家临床版混在同一下拉框；选药有下拉和共享目录两个入口；底栏两个开立按钮；药品适应症被拒的真实原因被改写成"目录或业务规则已变化"。
- 检查检验：检验和检查是两套选择；检验指征被界面静默取第一项；报告签发后操作栏没有主按钮。
- 手术：签同意书、取消和开始共用一个说明框；开始前就显示实际术式；进行中重复整块 DRG 费用；完成核实露出耗材内部编号。
- DRG 预分组：支付参考藏在折叠区；露出 `coding-incompatible` 等内部码；六个折叠区重复展示费用和分组。
- 出院：医生开完出院医嘱后，护士因医嘱未停办不了离院，医生页没有提示；已离院时常驻空说明框和灰掉的召回按钮。
- 病案：在院时可以提交，但病案人员必然审核不过；核心字段折叠；退回理由藏在折叠区底部；提交前后状态相同。

逐页原型保存在 `.prototypes/2026-11-04-inpatient-{orders,investigations,surgery,drg,discharge,record}/`，经用户逐页确认，[住院医生](#住院医生)验收据此改写。

目标：住院登记、病区护士、住院医生、住院收费、住院药房、病案、医保核定七个岗位的页面结构与原型一致，同时修正上述金额、步骤和编号问题。业务流程、Command 和服务端合同不变。

## 范围

适用住院七个岗位，覆盖 standalone Web 和 DSH Surface，浅色和深色主题，宿主宽度 1600 和 1280 两档（对应 Surface 约 1101px 和 826px）。

- 共享结构：住院患者头部、平铺页签与"更多"、环节首行、条目行、底部操作栏、左侧队列卡。
- 各岗位的队列与主区结构。
- 住院收费的金额、步骤与表单显示规则。
- 住院药房的批次与数量展示。

1. 作为住院岗位用户，我希望患者头部第一行写明姓名、性别年龄、状态、病区床位和住院天数，以便一眼确认患者。
2. 作为住院岗位用户，我希望头部第二行列出住院号、预交金和累计费用，住院号中间截断、可以复制，以便核对又不挤占空间。
3. 作为住院医生或病区护士，我希望头部显示过敏和关键检验结果等事实标签，以便不用切页签就能看到重点。
4. 作为住院岗位用户，我希望页签平铺显示、带待办数，放不下的收进"更多"，以便知道哪里有事要做。
5. 作为住院岗位用户，我希望每个页签第一行写明"轮到你：…"或"等谁做什么"，右侧是办理顺序，以便知道当前在流程哪一步。
6. 作为住院岗位用户，我希望医嘱、检查、药品都以条目行展示，名称、时效、频次和剂量在左，状态和操作在右，以便逐条处理。
7. 作为住院岗位用户，我希望底部操作栏写明还差什么，主按钮在右，以便知道为什么不能提交。
8. 作为住院登记员，我希望队列上面是待转收的门诊住院证、下面是今日已登记，以便按顺序办理。

11. 作为病区护士，我希望队列分为新入院、床位两组，床位行写明"轮到你 n 项"或待清床，空床写床位费，以便安排本班工作。
12. 作为病区护士，我希望召回窗口和出院后病历固定在队列底部，以便随时进入。
13. 作为病区护士，我希望接诊分床使用床位网格，已占床位不可选，以便直观选床。
14. 作为病区护士，我希望医嘱校对、送检、术前核对、出院和清床都在对应页签里逐条完成，以便不遗漏。
15. 作为病区护士，我希望出院页签列出办理出院还差的每一项及负责人，以便知道该催谁。
16. 作为住院医生，我希望诊断医嘱页签上方是住院诊断，下面是医嘱条目和开立表单，诊断只在国家临床版里搜索，以便开医嘱时对照诊断、不选错编码体系。
17. 作为住院医生，我希望检查检验和门诊用同一种开具窗口和报告显示，逐份确认已阅，以便不用学两套操作。
18. 作为住院医生，我希望手术页签列出开始手术还差的条件及负责人，每个动作各写各的说明，以便知道何时能开始、写的说明归属清楚。
19. 作为住院医生，我希望 DRG 预分组页签直接显示当前病组、支付参考和费用还剩多少，以便盯住费用不超支付参考。
20. 作为住院收费员，我希望头部大字显示当前需要处理的金额：需补交时显示需补交，应退时显示应退，以便不漏收、不漏退。

22. 作为住院收费员，我希望已经无需补交时不再展示收款表单，直接进入结算，以便少一步。
23. 作为住院收费员，我希望费用页签只显示费用明细、退费和资金记录，以便专注账目。
24. 作为住院药师，我希望队列每行是一个药品，写明床位、患者和用法，以便逐条发药。

26. 作为住院药师，我希望发完一条后自动选中下一条，队列清空时说明下一步，以便连续工作。
27. 作为病案人员，我希望病案首页按患者信息、住院过程、诊断与操作、费用、审核记录分节展示，DRG 复核在最上方，以便逐节审核。
28. 作为医保办人员，我希望先看到归档时的分组与费用，再审阅、提交模拟核定，提交后进入历史核定，以便按顺序核定。
29. 作为 DSH 用户，我希望宿主 1280 宽时住院页面仍然完整可用，以便在笔记本上演示。
30. 作为使用深色主题的用户，我希望住院页面在深色下同样清晰。
31. 作为住院医生，我希望出院页签提前列出开出院医嘱和护士办理离院还差的事项，以便不被护士回头催停嘱。
32. 作为住院医生，我希望病案页签在出院结算后才开放提交，退回理由放在最上方，以便不做无效提交、及时按意见修改。

## 验收条件

### 共享结构

- [ ] 患者头部分两行：第一行是姓名、性别年龄、状态标签、病区床位和住院天数，右侧可放岗位关键金额；第二行是住院号（中间截断，悬停显示全文，可复制）、预交金和累计费用等。事实标签行和助手行按需出现，没有内容时不占行。
- [ ] 页签平铺，带待办数；宽度不够时多出的页签收进"更多"，"更多"中显示各页签的摘要。
- [ ] 每个页签第一行是"轮到你：…"或"等〈谁〉〈做什么〉"，右侧是办理顺序，本岗位那一步加粗。
- [ ] 医嘱、检查检验、发药项目以条目行展示：左侧名称和时效标签，下方是频次、剂量等元数据；右侧是状态和行内操作。刚完成的行短暂高亮。
- [ ] 底部操作栏左侧是提示（还差什么、进行中、已完成），右侧是主按钮。主按钮不可点时用虚线框，与提交中状态区分。
- [ ] 左侧队列卡用分组标题加计数组织条目，行内显示待办标签或状态。
- [ ] 界面不出现 `lot-…`、UUID、FHIR 引用等原始编号。

### 住院登记

- [ ] 队列：上面是"门诊住院证"分组，下面是"今日已登记"分组，已登记行显示"待入科"。
- [ ] 主区：入院途径为"门诊住院证转收 / 直接入院"分段切换，转收时住院证内容只读；入院病区、患者来源和预交金三栏填写，入院病区默认取住院证上的病区。
- [ ] 办理成功后显示登记摘要，操作栏提供"继续登记下一位"。

### 病区护士

- [ ] 队列：新入院分组置顶；床位分组按床号排列，在院患者写"轮到你 n 项"，待清床写"清床"，空床写床位费；召回窗口和出院后病历固定在底部，带计数。
- [ ] 待入科患者主区为床位网格，已占床位不可选，选床后操作栏提示"分到 n床，确认后开始计床位费"。
- [ ] 在院患者页签为入科、诊断医嘱、检查检验、手术、出院，诊断医嘱页签以条目行逐条校对医嘱。
- [ ] 底部操作栏提供下一条校对并说明剩余数量与完成后交接；停嘱或 PRN 理由只在对应医嘱展开，不同条目独立保留，填写理由并人工确认后才提交原动作。
- [ ] 出院页签在不能办理时列出每个缺项和负责人。
- [ ] 清床页显示结算时间和召回期限说明。

### 住院医生

页签为诊断医嘱、检查检验、手术、DRG 预分组、出院、病案，放不下时收进"更多"。各页签结构以对应的 2026-11-04 原型为准。

#### 诊断医嘱

- [ ] 顺序为住院诊断摘要、医嘱条目、开立医嘱。诊断块右上角固定"添加诊断 / 修改诊断"，点开为两栏弹窗：左侧只搜索国家临床版 2022 诊断，右侧是本次诊断；页面本身不变形。院内诊断目录不出现在住院诊断入口；服务端 Command 不变。
- [ ] 第一条加入的诊断自动为主诊断，改主诊断用"设为主诊断"，上下移动只调整次诊断顺序；入院病情为四个按钮，未选的条目标出并写进操作栏"还差"；备注默认收起。
- [ ] 未确诊时第一行和操作栏主按钮都是"确认住院诊断"；药品项目标明"先确认诊断"不可选，护理项目照常可开。
- [ ] 开立区为医嘱项目搜索框加"查询"，下方一行常驻医嘱时效、频次和每次剂量，未选项目时灰显且布局不跳；建议列表只在输入或查询时出现。
- [ ] 只有一个开立按钮；"费用预计"是操作栏次级按钮，结果显示在表单下方。
- [ ] 开立被拒时就地显示服务端真实原因，例如"本次住院确诊不符合该药品适应症"，并提供"修改诊断""换一个项目"；不改写为"目录或业务规则已变化"。
- [ ] 频次显示中文（每日一次 08:00、每日两次 08:00、20:00、按需）；目录只允许一种频次时直接显示，不给下拉；每次剂量旁显示换算结果。
- [ ] 申请停嘱在该条医嘱下原位填写理由，操作栏变为"确认申请停嘱"。

#### 检查检验

- [ ] 顺序为环节首行、申请条目、"开立住院检查"。条目直接显示结果、参考范围、签发时间，偏高、偏低标箭头；"完整报告"展开后使用门诊同款报告显示（检验为版本、报告时间、结论和项目表；影像为检查技术、检查所见、印象和签发版本）。
- [ ] 开立使用门诊同款开具窗口：左侧一个目录同时包含检验和检查（搜索框加候选），右侧为详情、住院价格和指征，底部写还差什么；不能开立的项目收成"另有 n 项暂不能开立 · 查看原因"。
- [ ] 检验适应证与门诊相同：目录只允许一项时只读显示，多项时下拉选择，界面不再静默取第一项；影像必填"检查指征"。
- [ ] 窗口按钮为"开立住院检查"，点击后直接开立交护士送检，没有门诊的准备清单、缴费状态、插入病历、AI 推荐和报告更正。
- [ ] 报告签发后操作栏主按钮为"已阅：项目名"，逐份确认；影像须先查看影像才能已阅，这一门禁保持不变。
- [ ] 以真实合成报告验收结果、参考区间、签发时间、已阅状态与完整报告入口；空态不能替代有报告条目的结构验收。

#### 手术

- [ ] 顺序为当前手术计划、"开始手术还差"清单、操作栏；每个阶段只有一个主按钮在操作栏，第一行、清单和操作栏说法一致。清单逐项写明事项、状态、负责岗位和已有的真实完成时间。
- [ ] 不再有共用的"手术记录说明"：签同意书在清单该行写签署说明，取消在计划块写取消理由，开始在弹窗写开始说明，登记写依据，完成写核实说明，各自必填。
- [ ] "实际术式"只在"开始手术逐笔登记"弹窗中出现，默认等于计划术式。
- [ ] 进行中显示"本台耗材"表（计划预留、本笔用量、费用，每笔可更正）和"登记本笔使用"一行；费用只写一行并链到 DRG 预分组，不重复整块分组和支付。
- [ ] 完成用弹窗：逐种填写最终总量、勾选是否释放剩余预留、写核实说明，预览差额后确认；不显示耗材内部编号。
- [ ] PCI 选型、耗材预计、指南评估和治疗耗材预留收成"术前耗材预计"块，只在开始手术前出现。"单次完整登记"改名"整台补录"，只在可开始阶段作为操作栏次级按钮。
- [ ] "术后核查与责任交接"在手术已完成阶段显示，DRG 预分组页签不再放置。

#### DRG 预分组

- [ ] 主块"费用与支付参考"显示当前病组、医院支付参考和还剩金额（超出时改为已超出），进度条由已发生收费和已开未记费医嘱组成，竖线标出支付参考，超过时整条变为警示色。状态只分未超和已超。
- [ ] 有计划手术时，主块内一行"做完计划手术后"写预计病组、支付参考、预计住院总费用和还剩金额，并说明预计总费用的组成；计划术式无法分组时用中文写原因，不显示内部码。
- [ ] 已发生收费超过支付参考 3 倍时，主块显示现有的高倍率提醒文案。
- [ ] "已发生收费构成"按收费类别列出金额和占比，逐笔明细链到"费用"页签，不在本页重复。
- [ ] 分组核对为清单（首页主操作、主诊断、计划操作、分组规则），每行一个"去…"小链接，AI 解释为该块的次级入口；住院自动跟进与手术耗材建议合为一块。
- [ ] 第一行写"随诊断、手术和收费自动更新"和更新时间，"重新计算"为小链接；页面不再有独立的标题和大按钮。归档冻结、重新审阅、未知结果和重试保持原合同。

#### 出院

- [ ] 在院时显示"开出院医嘱前"清单：手术申请、检查检验、转科、在用医嘱逐行打勾，未完成的写负责人并提供"去…"链接。前三项未收口时不能开出院医嘱；在用医嘱未停只提醒，不阻止开立，说明护士办理离院前须停止或完成。
- [ ] "出院处理说明"为必填多行输入，带填写示例和"病区护士办理离院时能看到"的说明；缺失时操作栏写"还差：出院处理说明"。
- [ ] 不再显示与环节首行重复的"出院办理状态"块。
- [ ] 待出院时显示"病区护士办理出院还差"：医嘱未停时第一行写"轮到你：停 n 条医嘱"，操作栏提供"去诊断医嘱停嘱"；并说明出院医嘱开立后不能撤回。
- [ ] 已离院未结算时显示离院时间和离院方式，"召回住院"为单独一块，点开后才出现"召回理由（必填）"，在操作栏确认；已结算后该块写明召回已关闭。
- [ ] 出院办理记录直接列出时间（到分钟）、事件和说明，不折叠。
- [ ] 不增加撤回出院医嘱、医生填写离院方式或自动取消手术等新语义。

#### 病案

- [ ] 出院结算前不能提交病案首页：第一行写"出院结算后才能提交"，正文列出"提交首页前"条件（主诊断唯一、诊断编码来自国家临床版、离院信息、主操作、费用）。
- [ ] 结算后核心字段直接列出（患者基本信息、住院过程、正式诊断、实际操作、病案费用），各节右侧有"去…"链接；有已实施操作时以单选列表确认本次主操作，并说明 DRG 分组按此计算。
- [ ] 病案费用只列合计、分类和结算时间，逐笔明细链到"费用"页签。
- [ ] 已提交待审核时第一行写"等病案人员编码审核"和提交时间，不显示提交按钮；被退回或提交后来源变化时，最上方提示条写明退回时间和理由或变化内容，操作栏为"重新提交病案首页"。
- [ ] 提交次数写"第 n 次提交"，不显示"修订 n"；"已归档"只在环节首行和操作栏各出现一次；时间显示到分钟。

### 住院收费

- [ ] 队列分组为待结算、在院、待入科，行内显示需补交、结算等待办标签和金额。
- [ ] 头部右侧大字只显示当前需要处理的方向：需补交大于 0 时显示"需补交"，应退大于 0 时显示"应退"，两者都为 0 时以小字显示"无需补退"。
- [ ] 出院页签只给实际完成的步骤打勾。无需补交时省去补交与收款三步，显示一次"无需补交"说明，不显示收款表单，直接从预览结算开始。
- [ ] 需要退款时，结算预览和结算结果写明应退金额，操作栏引导办理退款。
- [ ] 费用页签只包含费用明细表（日期、项目、金额、状态，带合计）、退费和资金记录，不出现核查待办和手术核查等开发文案。
- [ ] 1280 宽时六步进度只显示当前步骤名称，其余为编号。

### 住院药房

- [ ] 队列标题为"住院发药"，分"待发药 / 已发药"，每行是一个药品，元数据写床位、患者和用法。
- [ ] 主区头部以药品为标题，显示用法、患者床位和校对人。
- [ ] 发药批次下拉显示批号、库存和有效期，默认最早到期的批次，临期批次有标注；发药数量带单位，并说明可以部分发药。
- [ ] 发药后该行移出队列，自动选中下一条；队列清空时主区说明下一步由病区护士按时给药。

### 病案

- [ ] 队列筛选为全部、待整理、审核通过、已归档，带计数。
- [ ] 主区最上方是 DRG 复核，下面依次是患者基本信息、住院过程、正式诊断与实际操作、病案费用、审核与归档记录。
- [ ] DRG 复核读取已有许可接口的当前或归档冻结分组；空的术后核查收为次级入口，不能冒充实际分组摘要。诊断只铺临床代码、名称和可读入院病情，技术来源不在正文直铺。
- [ ] 待审核时操作栏为"退回医生修订"和"编码审核通过"，审核通过后为"归档病案"，归档后只读。

### 医保核定

- [ ] 队列分组为已归档病案、已核定。
- [ ] 主区依次是：归档时的分组与费用（只读）、模拟核定、历史核定。操作栏依次为"审阅模拟核定""提交模拟核定"；提交后提供"下一份"。
- [ ] 离院方式、入院病情与时间使用岗位可读格式；主区保留模拟金额与差额仅供复核、不会自动收退的事实，完整参数和公式说明放入来源详情。

### 通用

- [ ] 按岗位、页签与关键状态分别核对正文顺序、默认展开内容和真实操作；验证 Web 与 Surface 及受影响宽度和主题，无重叠或裁切。复用仍有效的截图，只有实际视觉变化补代表图，默认页外框矩阵不能替代全页内容验收。
- [ ] 待办数字始终可见；入院病情、离院方式、费用类别等临床字段采用可读标签，内部系统、发布身份与来源定位只在需要的来源入口呈现。
- [ ] [DSH 外壳规格](2026-11-02-dsh-shell-feedback-redesign.md)的住院行为验收和[卡片重构规格](2026-10-30-workspace-card-redesign.md#状态与回归)的门禁与状态要求全部保持。

## 布局与操作状态

- [ ] 收费员与药师在门诊、住院两种模式中使用同一种列表头下拉控件；共享控件的调用差异不能造成切换后的样式跳变。
- [ ] 药房队列不常驻多行分页或筛选实现说明；仅一页时不显示分页操作。多页仍如实标明本页计数并保留显式翻页、跨页继续及未知状态，不能把本页清空当成全部处理完成。
- [ ] 医保核定先展示分组状态、病组、归档费用与支付预估四项事实；病案 DRG 复核展示病组、病组名称、病案费用与支付预估。宽容器四列、窄容器两列；缺失字段保持明确空值，不能以其他事实代替。刷新为标题旁的紧凑次要动作，同一事实不在默认主区重复铺陈。
- [ ] 医生头部采用短状态助手标签，完整说明保持可访问；检验结果展示至多两项真实值与实际异常摘要，并可进入完整结果。未知或读取失败不报正常。当前环节的同一等待提示不在头部、环节首行和操作栏重复三次。
- [ ] 队列返回与刷新是两个独立图标动作，名称与图标含义相符；刷新使用刷新图标，不与返回箭头和文字拼成一个动作。
- [ ] 手术准备以逐项清单呈现事项、状态、负责岗位及已有的真实完成时间；未完成或未知不编造时间与人员。知情同意等主动作未满足条件时沿用虚线不可执行样式，提交中与缺项状态区分。

## 设计决定

- 以 2026-11-02 确认的住院原型（`.prototypes/2026-11-02-dsh-shell/inpatient.html`）为页面结构依据，冲突时以本规格条目为准。原型里没有对应真实能力的元素不实现，例如"打印结算单"和"让助手准备"按钮；助手入口沿用现有的助手行和 DSH 对话。
- 共享结构（患者头部、页签与"更多"、环节首行、条目行、操作栏、队列卡）抽成住院岗位共用的组件，七个岗位组合使用，不各写一份。
- 住院检查检验复用门诊开具窗口（`OrderComposerLayout`）和报告显示组件；住院列表与流程自管。门诊组件中直连门诊接口的已阅、取消、重试改为注入动作，门诊行为不变。
- 住院诊断入口只提供国家临床版检索，属于界面收窄；服务端 Command 仍接受院内编码，由病案审核拦截。
- 住院收费头部的金额方向从结算预览和资金记录推出，不新增服务端字段；步骤是否完成以实际发生的收款和结算为准。
- 住院药房不加药师审核，沿用 DSH 外壳规格的决定。
- 不改 Command、服务端合同和业务门禁；文案沿用[住院文案与助手话术](2026-10-30-workspace-card-redesign.md#住院文案与助手话术)。
- 门诊挂号员队列的"门诊 / 住院"切换不属于本规格；门诊侧收费、药房的左栏调整由[门诊与窗口岗位界面细节修整 Issue](https://github.com/CaiZongyuan/clinmesh/issues/387) 链接的规格负责。

## 现有能力边界

以下原型细节尚无真实能力支持，对应能力保持未验收；布局、CI 或默认页截图通过不构成这些能力的验收证据。

- 药房窄投影只有患者姓名、住院号、住院状态、药嘱、执行、库存与过敏；没有床位、校对人员和厂家批号。本次保持服务端合同，头部显示已提供的患者与校对时间，批次以本页库存序号区分并列出真实库存、效期，不把内部 `lot-…` 当厂家批号。
- 发药 Command 要求所选批次总量等于本次执行的完整剂量，不支持同一次执行部分发药。本次按真实执行逐条办理，不增加会被 Command 拒绝的数量输入或部分发药承诺。
- 护士许可的住院与离院事件投影没有结算时间，结算预览仅收费员可读。本次清床页显示实际结算状态、离院事件及召回关闭条件，不越权获取资金预览、不伪造结算时间或不存在的固定召回时限。
- 无需补交时默认隐藏收款表单；原有的补充预交金能力通过显式入口按需展开，退款与原支付恢复独立保留。
- 医生出院、护士离院、PRN 频次和病案提交沿用现有 Command 及岗位归属；不照抄原型的医生填写离院方式或自动取消手术。病案提交在界面上等出院结算后开放，服务端仍按原条件接受提交。具体取舍见[住院结构决策](../decisions/implemented/architecture/2026-11-03-inpatient-prototype-composition.md)。

## 测试策略

- 只验证公开可观察行为：可见文字、分组、按钮可用状态和截图对照，不断言组件内部结构。
- Web E2E（`apps/web/e2e`，Playwright）是主切入点，沿用现有住院旅程和 fixture：
  - `inpatient-card-workspaces.spec.ts`：七个岗位的头部两行、平铺页签与"更多"、环节首行、条目行和队列分组；
  - `inpatient-admission.spec.ts`：登记队列分组、转收只读、继续下一位，以及护士床位网格；
  - `inpatient-discharge.spec.ts`：收费头部金额方向、六步进度如实打勾、无需补交时跳过收款、应退金额引导，以及清床；
  - 住院药房旅程：批次显示批号、库存和有效期，数量带单位，发药后自动选中下一条；
  - `inpatient-insurance.spec.ts` 等病案与核定旅程：分节顺序和操作栏按钮。
- 住院医生六页旅程（`inpatient-doctor-pages.journey.ts`）按 2026-11-04 原型更新各页签的顺序、默认展开内容和操作栏断言；出院补"在用医嘱提醒"和召回理由，病案补"结算前不能提交"和退回理由置顶。
- 检查检验复用门诊开具窗口和报告显示后，门诊检验、影像的已阅、取消和重试改为由调用方注入动作；门诊检验检查现有 E2E 与组件测试作为回归。
- DSH Surface 浏览器合同（`apps/dsh-web/src/client/*.browser.test.ts`）：共享住院结构组件纳入 React 18/19 ShadowRoot 双版本测试，沿用 `workspace-card.browser.test.ts` 的写法。
- 交付前按岗位、宽度和主题截图，与原型逐项对照，并在 PR 中附对照结果。
