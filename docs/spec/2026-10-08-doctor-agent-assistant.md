# 医生 Agent 临床助手

Status: implemented

实施与整体验收由 [Issue #175](https://github.com/CaiZongyuan/clinmesh/issues/175) 追踪。本规格拥有医生助手的整体产品范围；各切片规格拥有详细行为与验收条件。

## 问题与目标

医生通过聊天与 Agent 协作，随诊疗过程整理病历草稿，在对应业务页面准备检查检验、诊断和处方，并辅助发现病历问题。后台工作保持安静，保留医生手改，正式诊疗动作和病历签署由医生最终确认。

## 用户故事

1. 作为医生，我希望与 Agent 讨论当前病例并明确委托任务，让它在授权范围内协助诊疗。
2. 作为医生，我希望患者问诊、医生补充和报告进入同一整理流程，并保留已保存及未保存的手改。
3. 作为医生，我希望在相应业务栏目直接调整人工与 Agent 共用的待办，确认后才形成正式记录。
4. 作为医生，我希望质控只提示具体问题，点击可定位；没有具体问题时保持正文清爽。
5. 作为医生，我希望后台更新不打断当前操作，依据和工作记录可按需查看。

## 验收条件

- [x] 医生可与 Agent 聊天；后台读取当前患者获准查看的本次就诊与历史资料，不切换医生页面，不读取仿真隐藏答案或影像像素。
- [x] 只有明确委托才可向虚拟患者代问；同一任务内可连续追问，任务结束、医生叫停或对象变化后停止。普通讨论、拟问题、教学和 Agent 自己的猜测不成为患者事实或执行授权。
- [x] 当前新病例自动开启整理并可暂停，患者回答、医生明确补充和已发布报告持续进入同一流程。旧病例的启用与补录沿用详细规格，不因打开历史病例隐式重处理。
- [x] 整理覆盖十个病历字段。体格检查、评估、处置和随访遵守各自来源限制；缺少信息不编造，患者自述与本院客观报告保持区别。
- [x] 草稿更新保留人工正文、已保存及未保存编辑；自动片段可按合法来源更新，人工内容的更正与矛盾另行记录并保留待核实措辞。来源关联、历史归属和审计保存在后台，页面沿用直接记录及变动提醒。
- [x] 诊断、检查检验和处方在接诊期间后台自动准备，随问诊、病历、报告和正式记录变化重新评估；支持暂停、恢复及手动刷新，旧结果不覆盖新资料或串入另一病例。
- [x] 可执行建议使用当前院内真实目录和实际指南、病例依据；处方字段缺证时保持待补充，没有足够依据时允许清单为空。待核实诊断或检查思路只读，不形成临床草稿或正式事实，不展示模型猜测的概率。
- [x] 各业务栏目共用人工与 Agent 的待办及有效字段，医生可修改、取消选择或移除。开具前目录与填写融合，开具后保留搜索、待办及正式记录，按需查看依据与说明；不增加独立的逐条采纳步骤。
- [x] 正式确认诊断、开立检查检验、提交处方和签署病历由医生最终确认，沿用 Command、权限、版本、幂等、审计及临床校验。后台更新不改写或撤回已确认记录，Agent 不可用时完整人工项目仍可独立开具。
- [x] 四项质控随当前输入变化更新，具体问题提供短提示和可验证的字段定位；无具体问题不展示占位或通过标记，未完成与失败仍如实保留在说明中。签署前汇总沿用现有合同，不新增签署门禁、勾选项或逐条确认。
- [x] 聊天默认简洁、专业，先说明结果及需关注事项；解释和教学按医生请求展开。常规整理、刷新和检查不逐次播报、不抢焦点；任务完成、需要医生决定或操作无法安全恢复时简短反馈。
- [x] 可恢复工具错误先核对对象、权限、任务及执行结果，符合既有安全条件才继续；授权对象变化或结果不明时暂停说明，不自动重放可能已执行的动作。
- [x] 公开 HTTP、真实 SQLite、Web、React 18/19 ShadowRoot 与实际 DSH 旅程验证来源、手改保护、病例隔离、后台更新、工具执行及医生最终确认边界。

## 设计决定

ClinMesh 拥有病例授权、持久任务、版本、来源、Command 和审计；DSH 提供现有 `clinmesh-assistant` 业务会话、原生输入证明与辅助模型能力。后台整理、质控及建议各自遵守详细规格的触发、输入和任务归属，不依赖主聊天模型自行调用 Tool 才能执行普通后台工作。当前装配见[业务会话](../agent-capabilities.md#业务会话)和[系统架构](../architecture.md)。

医生手改优先、建议与患者事实分离、后台安静执行和医生最终确认是整体边界。病历直接整理与后台来源、质控紧凑提示和诊疗待办直接开具的交互由上述已实施切片规格拥有，不再沿用早期来源展开、逐条应用或先采纳再开具的流程。

## 测试策略

公开 HTTP、真实 SQLite 和共享 Command/Query 验证授权、来源、幂等、错误恢复、并发手改、患者切换、迟到结果和签署冻结，仅在外部模型边界使用合成替身。Web 与 React 18/19 ShadowRoot 合同验证真实入口、键盘、焦点、窄分屏和未保存输入。

实际 DSH 验收核对原生医生输入、后台处理、真实 Session Tool、人工批准及 Command、审计与 Trace 关联。合成模型用于确定性工作流验证，有限实模样本仅证明实际模型链路和来源边界，不代表医学准确性。入口与分层责任见[测试策略](../testing.md)。

## 范围外

- 医患语音采集与识别、附件解析、Mobile 原生入口和独立自主仿真 Agent。
- 新增诊疗合理性、检查适应证和完整用药安全质控；既有临床与处方校验继续执行。
- 检查检验或药品的目录外可执行建议，以及未取得授权的指南全文服务。
- 住院病案首页、DRG、收费与医保结算质控；相关独立任务不构成本父任务的关闭依赖。

## 依赖与风险

#176–#181 与基础 #166–#172 已交付。源更新、工具绑定及输入版本可能在模型生成期间变化，结果发布和正式操作仍须重新验证当前对象、授权和版本；不能仅根据模型输出判断操作成功或自动重放未知结果。

指南覆盖及模型语义仍有限，引用完整不等于临床结论正确。资料不足、预算超限、生成或独立核验失败时保留医生草稿并如实反映状态，不通过扩大权限、截断资料或放宽临床依据换取可执行结果。
