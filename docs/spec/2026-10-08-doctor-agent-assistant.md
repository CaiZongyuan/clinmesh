# 医生 Agent 临床助手

Status: draft

当前病例读取与执行恢复的详细合同由 [#176 切片规格](2026-10-08-doctor-agent-context-execution.md)拥有；本文件保留整体产品范围与实施顺序。

## 问题与目标

医生需要通过聊天与 Agent 协作，让 Agent 随诊疗过程整理病历草稿，在对应业务页面提供检查检验、诊断和处方建议，并协助质控。以下产品行为、权限及实施顺序已确认；后台执行方式、生成依据及细化判断规则仍待设计，本规格保持 draft，不表示功能已经实现或完整技术方案已经批准。

## 范围

- 本轮定位为协助当前医生的临床助手，支持医生与 Agent 聊天。
- Agent 可后台读取当前患者中医生有权查看的本次就诊和既往记录，不受医生当前栏目限制，也不需要切换医生正在操作的页面；不包含仿真隐藏病例答案。
- 信息不足时 Agent 平时提示医生补充；只有医生明确委托代问时，才直接向虚拟患者提问，不自行开展补问。
- 一次明确代问委托可在本任务范围内连续追问；任务完成、医生叫停或病例变化后结束委托。
- 近期病历草稿整理同时使用医患文字问诊和医生向 Agent 提供的信息；后续医患语音识别接入同一整理流程，语音暂不实施。
- 进入当前病例后自动开启病历整理，跟随问诊和医生补充持续更新；医生可随时暂停。
- 近期实时整理覆盖整份病历：主诉、现病史、既往史、查体和辅助检查根据已有信息整理；评估、处置和随访只整理医生明确表达或已采纳的建议。缺少的信息不编造。
- Agent 整理的病历内容提供查看来源入口，默认不展开；医生核实时可查看对应原始问诊、医生补充或报告。事实一致性质控提示可展示涉及的两处来源。
- 医生手动修改优先。Agent 可以补充新事实；需要改写医生已修改的内容时展示修改建议，由医生采纳。
- 检查检验、诊断和处方建议分别显示在对应业务页面，与医生当前填写的内容分开。
- 近期检查检验和处方建议只使用当前医院可选目录中的具体项目或药品；采纳时准确映射到对应目录条目，不新增目录外建议。
- 处方建议覆盖药品、剂量、频次、疗程和数量，并说明推荐依据。资料或依据不足的部分明确标为待医生补充，不编造；完整方案建议不代表已完成全面用药安全质控，仍由医生核对。
- 诊断建议展示候选诊断、支持与不符合的信息，以及待核实信息；资料不足时不强行给出确定结论，不展示模型自行猜测的概率。医生采纳后进入诊断草稿，正式确认仍由医生完成。
- 每条建议提供采纳操作，医生采纳后加入对应草稿，并可继续编辑。
- 进入对应页面时自动分析当前病例；相关病情信息变化后更新建议，并提供手动刷新。建议更新不自动改写已采纳的草稿。信息不足时说明缺少什么。
- 正式确认诊断、开立检查检验、提交处方和签署病历由医生最终确认。Agent 可准备内容、检查完整性并打开提交确认界面。
- 近期 Agent 质控规划包含病历完整性和事实一致性；具体判断规则和交互尚未确定。诊疗合理性与用药安全质控暂不新增。
- 首期质控清单为病历缺项、已知信息遗漏、事实不一致，以及 Agent 新增事实缺少来源。每条提示说明问题位置和依据，由医生判断；不同时间的信息变化结合时间核对，不直接认定为矛盾。
- 问诊、医生补充信息或草稿变化后实时检查并更新相关质控提示；签署前集中展示尚未处理的问题。
- 新增 Agent 质控提示不自动阻止签署。医生可补充、修改或核实后保留当前内容；系统原有必填项和正式提交校验继续执行。
- 医生与 Agent 聊天默认采用简洁、专业的表达，先说明结果，再说明需要关注或确认的事项；医生追问原因或要求教学时再展开解释。
- 普通草稿自动更新、建议刷新和质控提示在对应页面体现；医生交代的任务完成、需要医生决定或核实、操作未能安全恢复时，再在聊天中简短说明。
- 常规后台整理与检查采用无感交互，不逐步播报、不抢夺焦点；医生手改优先和正式提交确认的边界继续适用。
- 可安全恢复的工具错误在后台处理，恢复成功不单独报告技术错误。系统重新读取并核对当前状态；仅在仍是原患者和原任务、确定原操作未执行且恢复符合已确认权限时继续。患者或其他授权对象变化、执行结果不明时暂停并说明，不自动重放可能已执行的动作，也不以错误本身推断患者已经切换。

## 用户故事

1. 作为医生，我希望与 Agent 讨论当前病例并表达任务，让它协助当前诊疗工作。
2. 作为医生，我希望医患文字问诊和我补充的信息自动整理进病历草稿，减少重复录入。
3. 作为医生，我希望手动核对和修改过的内容得到保留，需要改写时由我采纳。
4. 作为医生，我希望在检查检验、诊断和处方页面直接看到相应建议及理由，逐条采纳到草稿后继续编辑。
5. 作为医生，我希望正式业务动作由我最后确认，明确建议、草稿和正式结果的区别。
6. 作为医生，我希望 Agent 协助发现病历漏项及问诊、医生补充和病历之间的事实不一致，便于补充或核实。
7. 作为医生，我希望 Agent 在后台综合当前患者的授权资料，不需要为收集病例信息切换我正在使用的页面。

## 验收条件

以下条件记录已确认行为；未决规则确定后再补充完整边界。

- [ ] 医生可与 Agent 聊天，医患文字问诊和医生补充的信息都可用于整理当前病例的病历草稿。
- [ ] 进入当前病例后自动开启整理，跟随问诊和医生补充更新，医生可随时暂停。
- [ ] Agent 能后台读取当前患者的授权本次就诊和既往资料，不切换医生页面，不读取仿真隐藏答案。
- [ ] 信息不足时提示医生；直接向虚拟患者提问须有医生明确委托，不因发现漏项自行补问。
- [ ] Agent 自己提出的猜测或建议不会自动成为已经确认的患者事实。
- [ ] 自动整理覆盖主诉、现病史、既往史、查体、辅助检查、评估、处置和随访；后三类内容须来自医生明确表达或已采纳的建议，缺少信息时不编造。
- [ ] Agent 整理内容可查看对应原始来源，默认不展开；事实一致性质控提示可展示涉及的两处来源。
- [ ] 草稿更新保留医生手动修改；涉及改写的建议等待医生采纳。
- [ ] 对应业务页面分别展示检查检验、诊断和处方建议，医生能区分建议与当前草稿。
- [ ] 检查检验和处方建议对应当前医院可选目录中的具体条目，采纳可准确填入草稿，不包含目录外项目或药品建议。
- [ ] 处方建议覆盖药品、剂量、频次、疗程和数量并说明依据；不足信息明确标为待医生补充，不将方案完整性表述为全面用药安全质控通过。
- [ ] 诊断建议展示候选、支持与不符合的信息及待核实信息，资料不足时不强行下结论或给出模型猜测的概率；采纳只进入草稿。
- [ ] 医生逐条采纳建议后加入对应草稿，且可继续编辑。
- [ ] 进入相关页面自动生成建议，相关病例信息变化后更新；医生可手动刷新。
- [ ] 建议更新不自动改写已采纳的草稿；信息不足时明确指出缺少的信息。
- [ ] Agent 可准备正式操作并打开确认界面，最终由医生确认后生效。
- [ ] Agent 质控检查病历缺项、已知信息遗漏、事实不一致及 Agent 新增事实缺少来源，提示问题位置和依据；不同时间的信息变化结合时间核对。
- [ ] 问诊、医生补充信息或草稿变化后更新相关质控提示，签署前汇总尚未处理的问题。
- [ ] 新增 Agent 质控提示不自动阻止签署，医生可自行判断和处理；系统原有必填项及正式提交校验仍执行。
- [ ] 聊天默认简洁、专业，先报告结果及需要关注的事项，医生追问或要求教学时展开解释。
- [ ] 普通自动更新不逐次在聊天中报告；任务完成、需要医生决定或核实、操作未能安全恢复时提供简短聊天反馈。
- [ ] 可恢复工具错误在后台核对状态后恢复，成功后不单独播报技术错误；对象变化或执行结果不明时暂停说明，且不自动重放可能已执行的动作。

## 设计决定

### 已确认

- 医患文字问诊和医生与 Agent 的聊天均为病历整理来源；患者事实与 Agent 建议保持区别。
- 进入当前病例自动开启病历整理，医生可随时暂停。
- 近期覆盖整份病历的上述字段，评估、处置和随访只整理医生明确表达或已采纳的建议。
- 病历内容默认保持清爽，Agent 整理内容提供可按需查看的来源；事实矛盾提示展示相关来源。
- 后台读取范围为当前患者中医生有权查看的本次就诊与既往记录，独立于当前栏目；授权边界不因后台读取而扩大到隐藏答案。
- Agent 可在医生明确委托后向虚拟患者代问，平时发现信息不足只提示医生。
- 医生手动修正优先于 Agent 自动重整。
- 建议嵌入对应业务页面，每条建议由医生采纳后进入草稿。
- 近期检查检验和处方建议限定当前医院可选目录，建议及采纳使用明确的目录条目。
- 处方提供完整方案建议；资料或依据不足的字段待医生补充，完整建议仍须医生核对。
- 诊断建议采用候选诊断、依据与待核实信息的形式，不以模型猜测的概率表达确定性。
- 建议自动生成和更新，支持手动刷新。
- Agent 准备、医生最终确认正式操作。
- 近期质控先规划病历完整性和事实一致性，不新增诊疗合理性与用药安全质控。既有服务端流程和处方校验继续适用，能力边界见 [质控能力研究](../research/2026-10-08-clinical-quality-control.md)。
- 首期四项检查为病历缺项、已知信息遗漏、事实不一致及 Agent 新增事实缺少来源，提示需能定位内容并说明依据，时间变化不能直接判为矛盾。
- 质控采用实时检查与签署前汇总；新增 Agent 提示不自动阻止签署，处理由医生判断，系统原有校验继续执行。
- 默认聊天风格为简洁、专业；解释和教学按医生请求展开。
- 聊天采用关键事项通知，普通自动更新在对应页面体现。
- 常规后台整理、检查及可安全恢复的工具错误无感处理；结果不明和授权对象变化暂停说明，正式操作仍由医生确认。

### 未决

- 四项病历质控的细化判断规则、问题等级，以及提示的具体呈现和处理操作。
- 自动整理的具体更新时机和暂停范围，以及事实冲突、遗漏和修正的处理。
- 诊疗建议的证据来源、不确定性表达、候选排序和过时建议处理。
- 自动建议的更新频率、失败反馈和防止过期结果覆盖新病例的规则。
- 建议、澄清、执行成功、执行失败时的具体话术，以及可安全恢复错误的识别和核对机制。
- 技术方案、验证入口、交付范围与执行安排。

### 执行顺序与拆票

已确认按医生聊天与病历自动整理、基础质控、页面诊疗建议的顺序推进。执行 Issue 按可独立验收的业务切片拆分，不按类型、后端和前端分层拆票。

1. 当前病例聊天、跨栏目授权读取与稳定工具执行。
2. 在已有问诊病史自动记录上扩展全病历和医生补充来源，依赖第 1 项及已有自动记录的完整验收。
3. 四项基础质控、实时提示与签署前汇总，依赖第 2 项。
4. 院内检查检验建议与逐条采纳，依赖第 1、2 项。
5. 候选诊断建议、证据与逐条采纳，依赖第 1、2 项。
6. 院内完整处方方案建议与逐条采纳，依赖第 1、2 项。

先完成基础质控，再启动三个建议页面的实施，是已确认的交付顺序；三个建议页面之间不声明未经核实的技术依赖。父 Issue 追踪整体范围、顺序及集成验收，叶子 Issue 引用本规格。

已有 [问诊病史自动记录父任务 #166](https://github.com/CaiZongyuan/clinmesh/issues/166) 与子任务 #167–#172 继续拥有该基础功能的执行追踪；增量合并、局部手改保护、暂停补录、来源与撤销、签署边界的详细要求沿用其引用的[正式规格](https://github.com/CaiZongyuan/clinmesh/blob/4c947b325315d233b355dc19baaa843c54cc1406/docs/spec/2026-10-08-consultation-auto-record.md)。本轮不重建这些任务，只补充更广泛的医生助手能力和全病历扩展，不静默改写既有合同。

当前业务会话由 DeepSeek Harness 的 `clinmesh-assistant` preset 装配，见 [现有业务会话](../agent-capabilities.md#业务会话)。这是当前实现事实，不表示本轮自动任务方案已经确定。后台整理、质控和建议如何触发与执行，及其与 DSH 会话和既有模型桥接的关系，在技术方案中明确，不将新增后台能力描述为现有聊天 Agent 已自动具备。

## 测试策略

以下为待实施方案确认的验证方向，不表示已经运行或通过。

- 从当前医生工作台的公开界面验证文字信息进入草稿、手动修改保护和建议采纳。
- 验证信息不足、相互矛盾、生成失败、并发手改以及病例切换后的结果归属。
- 验证自动更新不改写已采纳草稿，并通过实际业务状态证明未确认不会产生正式操作。
- 复用现有 Web/DSH 页面、工具和 Command 的测试入口；具体检查由最终 diff 确定。

## 范围外

- 本轮近期交付暂不包含医患语音采集与识别。
- 近期不新增诊疗合理性与用药安全质控，包括诊断合理性、检查适应证及完整药学规则审查；该范围不影响已经确认的诊疗建议能力。
- 近期不新增检查检验项目或药品的目录外建议。
- 本轮不规划独立医生 Agent 或患者 Agent 的自主仿真执行。
- 不将尚未决定的质控规则或诊疗判断写成已经确认的要求。

## 依赖与风险

- 医生手改与 Agent 更新同一草稿，需要确定可靠的归属、冲突和版本处理。
- 模型可能沿用旧工具绑定；现有目录同步和报错恢复不能保证真实模型始终采用当前参数。该问题的解决方式须与本轮权限和业务流程共同确定，既有合同见 [DSH 业务 Agent Harness](2026-10-07-dsh-business-agent-harness.md)。
- 诊疗建议与内容质控的临床依据尚未确定，不能以模型输出本身作为事实或确定性规则。
