# 心血管手术耗材目录

Status: approved

## 问题与目标

现有手术耗材只有两项通用合成材料。将已核查的心血管价格参考表中 231 条记录持久纳入住院手术耗材目录，按表内中选价格制定合成本院演示收费，并完整保留来源、缺项与价格适用限制。

## 范围

- 固定来源文件 SHA-256 `76147edf46552c906750bb2a8697596cd47acf3450c322168f92a5b8e2348cc3` 的 231 条记录及 7 个来源组；原始工作簿不进入 Git，归一化公开来源快照纳入仓库并经 schema 校验。
- 复用 `inpatient_surgery_catalog` 与 Scenario 补缺 seed，新旧 Epoch 启动均可安装；保留旧 2 项耗材、8 个术式及已有配置。
- 52 条单位明确的记录按 E 列中选价作为合成本院收费可用，179 条单位缺失记录保存价格、单位为 null，明确不可计费；不填造规格、单位或现行价格声明。
- Web 手术执行复用既有选择与输入组件，只展开已选可收费耗材用量；CLI 目录提供全部条目及来源边界。

## 用户故事

1. 作为住院医生，我希望选择有明确计价单位的心血管耗材并记录真实用量，以便费用按已确认参考价格计算。
2. 作为 Agent，我希望读取完整目录及未启用原因，以便不把历史采购参考价或未知单位当成可执行收费项目。

## 验收条件

- [ ] 公开手术目录返回 233 项耗材：原 2 项与新增 231 项；新增 52 项可收费、179 项因单位未确认不可收费。
- [ ] E 列按元转换为精确整数分，Q 列拟供应价独立保留；产品、企业、原代码、注册证、规格/单位缺项、价格类型、地区、日期、原定位和来源组字段不丢失。
- [ ] 服务端拒绝使用缺单位耗材，失败不新增手术实施、Procedure、耗材使用或费用；可收费材料按真实用量收费。
- [ ] 重启与新 Epoch 补齐不重复记录，不覆盖已有价格、旧实施快照和原 Command receipt；旧快照仍可读取及重放。
- [ ] Web 只在选中耗材后出现对应数量输入，未知单位项不可选，不展开全量目录表单；既有手术流程和丢回执恢复可用。
- [ ] Agent Operation Catalog、住院 skill 与命令漂移测试同步目录合同；命令输入不作无关变化。

## 设计决定

采购来源价格与本院合成收费定义分别保存。可收费已实施项保持旧形状兼容，目录额外允许 `unit-unconfirmed` 条目。实际实施仍在共享 Command 事务按目录及版本校验、冻结和计费；目录变更不改写历史实施。当前合同归[临床流程](../architecture/clinical-workflows.md#82-住院闭环)，取舍由[Agent Note](../decisions/implemented/architecture/2026-10-22-cardiovascular-material-catalog.md)记录。

## 测试策略

- 现有 file-backed SQLite 与公共 HTTP 验证全量查询、来源价格、缺项、失败原子性、收费、重启补缺和回执重放。
- Playwright 真实手术入口验证选中后用量输入、不可收费项以及既有恢复流程；只写隔离临时业务库。
- 目录新增全局 seed，核对实际性能写入基线，运行跨包类型、静态与项目必需检查。

## 范围外

通用 Excel 导入平台、耗材管理页、采购库存供应链、起搏术式扩展、补造规格单位、核验官方当前价格、生成住院患者或修改当前运行业务库。

## 依赖与风险

179 条冠脉价格为历史参考，52 条起搏类来源仍有地区及合同限制；作为合成本院演示价不代表真实医院现行采购或收费价。7 组原附件未在本次独立联网复核。单位补齐与既有目录调价另行确认，不通过启动覆盖旧项。
