# DRG 旧格式登记的局部恢复与准备失败报告

Status: approved

## 问题与目标

从完整储存格式升级后，参考库可能同时保存旧格式登记与当前精简登记。准备入口吞掉已有清单的校验错误，随后登记当前清单并报告成功；Server 启动核验全部登记时仍因旧记录缺少 `storage` 而失败。本需求允许显式恢复已确认被当前资料替代的旧登记，保留临床参考目录和业务数据，并使准备入口准确报告失败。

## 范围

- 保留参考库的一致备份、目标旧登记原始内容及关联审计后，完整核验当前精简资料，核对新旧逻辑来源与覆盖，仅清理已明确被替代的旧格式登记。
- 保留诊断、药品、检验等临床参考目录、临床 Reference Release 配置、其他登记及既有审计，不修改业务数据库或旧来源文件。
- 准备入口区分数据库或登记表尚未建立与已有登记无效；只有全部现存登记通过格式及内容哈希校验，才可登记或复用当前清单并报告成功。
- 沿用当前精简格式与不可变身份合同，不增加旧格式运行时读取、自动迁移、自动清理或永久维护 CLI。

## 用户故事

1. 作为已有环境的维护者，我希望保留临床目录和业务数据，只移除有完整替代证据的旧格式登记，使升级恢复不要求重建整个参考库。
2. 作为协作者，我希望准备命令在已有登记无效时直接失败并提供排障入口，避免直到 Server 启动才发现相同错误。

## 验收条件

- [ ] 清理前保留可验证的一致参考库备份，以及目标登记的原始 `inventory_id/content_hash/inventory_json`、关联审计与恢复依据。
- [ ] 当前资料通过完整物理对象、逻辑文件覆盖、原 SHA-256 与既有清单语义校验；旧登记与当前清单的逻辑来源、版本、文件哈希和覆盖相符。
- [ ] 删除事务再次核对明确的旧身份、内容哈希及原始 JSON，只删除本次确认的记录；目标变化、未知旧记录或无替代证据时拒绝清理。
- [ ] 清理后全部现存登记、参考库完整性及当前清单回读通过；诊断、药品、检验等非目标数据与既有审计保持一致，业务数据库未被修改。
- [ ] 准备入口遇到无效登记、内容哈希不符或其他不可恢复的数据库读取错误时失败，保留数据库和已有资料，不以重试登记或成功结果掩盖错误。
- [ ] 当前登记位于前页、无效登记位于后页时仍失败；当前登记不在库中时也不能越过其他无效登记继续发布。
- [ ] 空库、尚未创建登记表的参考库和合法的重复准备继续可用；合法重复准备保持只读复用，check-only 不修改正式数据库、审计或安装目录。

## 设计决定

局部恢复是对已确认替代关系的一次显式维护，不修改旧登记内容或伪造 `storage`。已清理记录保留在本地备份与归档中，未知或损坏记录继续阻止成功；备份、核验、事务边界和恢复顺序由[部署指南](../deployment.md#旧格式-drg-登记的局部恢复)拥有。此决定部分取代原[当前格式决策](../decisions/implemented/simplification/2026-10-25-drg-current-format-only.md)的整库重建要求，理由见[局部恢复决策](../decisions/implemented/bug-fix/2026-10-26-drg-inventory-recovery.md)。

## 测试策略

使用已有公共 `runDrgReferenceSync` 与清单查询、参考库核验入口，以合成资料和临时 file-backed SQLite 验证旧格式残留、跨页无效记录、内容哈希错误、失败保旧及合法首次和重复准备。真实环境恢复先验证备份及原始归档，再完整核验当前固定资料；清理前后比较非目标参考数据与既有审计，回读当前登记并通过参考库核验。不开启真实模型或压测，不以重新准备临床目录代替保留数据的验收。

## 范围外

不修改临床 Reference Release、重新同步诊断药品检验目录、重建业务库或参考库，不兼容旧物理格式，不删除完整来源副本，不新增自动恢复、通用删除工具或患者分组与支付运行能力。

## 依赖与风险

物理储存不同但逻辑内容相同，必须以锁定来源、文件哈希和覆盖证明替代关系，不能仅凭发布日期或缺少 `storage` 判断可删除。SQLite 备份须覆盖 WAL 中已提交内容；恢复期间有并发写入、原记录变化、校验失败或归档不完整时保留原数据并停止清理。备份与原始归档保存在受忽略的本地资料目录，不进入 Git。
