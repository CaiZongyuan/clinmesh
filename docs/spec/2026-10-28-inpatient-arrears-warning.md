# 住院欠费预警与实际待收余额一致

Status: implemented

## 问题与目标

PCI 手测中，患者医保与补缴已完成，住院已结算、清床并归档，医生仍看到欠费预警。预警须反映当前正式患者待收，不再比较医疗费与预交金。

## 范围

住院概要提供最小待收事实，患者横幅、医生患者列表及临床提醒统一消费。复用首次资金及后续财务更正 owner 的计算，不向医生开放收退款或医保明细。

## 用户故事

1. 作为住院医生，我希望看到准确的患者待收或待确认状态，避免让已结清患者重复补缴。

## 验收条件

- [x] 合成 PCI 金额4036.18元，基金2169.73元、个人账户20元、预交金50元、成功补缴1796.45元后，三处均无欠费预警；结算、归档及刷新后保持正确。
- [x] 未结清且待收确定时，显示欠费及当前尚应收金额；医保抵扣、成功补缴及退款均按正式资金事实计算。
- [x] 未知收退款或医保来源待重审时显示待确认，不宣称已结清或提示重复补缴；原尝试恢复后更新。
- [x] 首次结算后及归档后的真实费用更正仍可体现新增待收，补收成功后清除预警；临床和归档状态保持原值。
- [x] 医生仍无法读取完整资金和后续财务明细，原病区隔离保持有效；旧回执缺少新字段仍能解析，不回退旧比较逻辑。

## 设计决定

住院概要增加可选、可空的 `outstandingFen`：确定金额为非负整数分，待确认时为 `null`，旧回执缺失时表示尚无当前摘要。业务历史不改写。依据见[决策](../decisions/implemented/bug-fix/2026-10-28-inpatient-arrears-summary.md)。

## 测试策略

公共住院 HTTP 验证医生读取的实际待收、资金恢复、医保重审、后续更正及权限；生产 `InpatientWorkspace` 挂载验证三处文案及已归档误报；Playwright 使用临时库、合成渠道和真实 Web 入口验证资金状态切换。测试不访问用户手测业务库、不调用真实模型或进行压测。

## 范围外

收费、医保、归档状态机及原资金合同的重写，真实支付渠道、数据迁移和手测环境部署。

## 依赖与风险

无外部阻塞。金额摘要必须复用财务 owner，不能放宽角色读取权限；缺失或待确认不能当作已结清。
