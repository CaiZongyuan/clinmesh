# 基于权威指南与当前病例的诊疗建议

Status: approved

本规格拥有三类诊疗建议及其自动准备、待开具清单的详细需求。G 与 E 条件对应已实施的 [#179](https://github.com/CaiZongyuan/clinmesh/issues/179)、[#180](https://github.com/CaiZongyuan/clinmesh/issues/180) 和 [#181](https://github.com/CaiZongyuan/clinmesh/issues/181)；R 条件为已批准、待实施的交互与自动准备增量。临床依据标准、授权和医生正式确认边界继续沿用已有合同。整体范围见[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)。本期使用可取得的官方指南条款，借鉴 Bio 的来源登记与引文核验流程；中华医学会全文库通过官方 SDK 或授权服务接入，未取得的全文不阻塞本期实施，也不作为已有证据。

## 问题与目标

医生需要在检查检验、诊断和处方页面获得与当前病例相符的建议，并核对其临床指南依据。模型需要结合可追溯的指南内容、医生有权查看的病历资料和院内实际目录；可采纳建议不能以模型记忆或自行编造的指南引用替代临床依据；没有相应指南时允许另行展示基于当前病例的待核实诊断或检查思路。

## 范围

- 三个建议页面提前进入设计与实施阶段，不再把 #177 或 #178 的整票关闭作为启动条件。新来源接入完成后复用其公开读模型；当前阶段不复制全病历整理或质控流程。
- 优先复用现成的权威指南库与官方来源，保留发布机构、文献性质、版本、适用范围和可核对出处。国家标准、卫生行业标准、诊疗规范、临床指南和专家共识分别标识。
- 使用现有 DSH 辅助模型，读取当前医生有权查看的问诊、病历草稿、报告、诊断及可见历史；不读取隐藏病例答案、影像像素或助手推理。
- 检查检验建议准确映射院内可选项目；诊断建议展示候选、支持信息、不符合信息及待核实事项；处方建议展示具体药品、剂量、频次、疗程、数量和各项依据。
- 当前病例接诊期间后台自动准备三类待办，不以进入对应页面作为触发前提；问诊、病历、报告及正式记录变化后重新评估，提供手动刷新，细节见 R 条件。来源、目录或资料不足时明确说明，不编造缺少的内容。
- 可执行建议直接进入相应可编辑待确认、待开具清单，不增加独立的“采纳建议”步骤；保留已保存与未保存的人工修改，更新不暗中覆盖医生选择。
- 正式确认诊断、开立检查和提交处方沿用既有入口及服务端校验，由医生最终确认。

## 用户故事

1. 作为医生，我希望在对应页面看到基于指南和当前病例的建议，并直接核对所引用的版本和条款。
2. 作为医生，我希望建议使用院内真实可选项目和药品，采纳后仍能检查和修改草稿。
3. 作为医生，我希望信息不足或指南不适用时明确看到缺少的依据，而不是得到无来源的完整方案。
4. 作为医生，我希望后台刷新与患者切换保留自己的修改，并且未经正式确认不会创建正式诊断、申请或处方。

## 验收条件

- [x] G1：接入的指南来源有可核验的发布机构、文献性质、版本、范围和内容取得方式；不能把公开可阅读等同于已取得全文集成授权。
- [x] G2：建议引用实际提供给模型的指南条款和当前病例资料；未知指南、虚构条款、错误引用或不属于当前病例的依据不能形成可采纳建议。
- [x] G3：检查检验建议准确映射当前可选目录，病理来源沿用既有授权手术选择；采纳保留其他人工编辑，不绕过单份当前申请草稿的合同。
- [x] G4：诊断候选包含支持、不符合和待核实信息；没有充分依据时保留不确定性，不展示模型自行猜测的概率。采纳复用实际诊断编码且不自动确诊。
- [x] G5：处方字段来自适用的指南、病例资料与真实药品规格，资料不足的字段标为待补充。目录允许值和编辑器默认值不能当作临床依据，缺失单位或包装换算不能被猜测补齐。
- [x] G6：刷新、失败、目录变化、患者切换及迟到结果不改写已采纳草稿，不丢失未保存的手改，不使旧版本建议归入新对象。
- [x] G7：只读、已正式提交和无需用药等状态沿用当前约束；采纳和自动生成均不创建正式 Condition、检查申请或 MedicationRequest。
- [x] G8：公开 HTTP 与真实 SQLite 验证授权、版本、错误和草稿边界；Web 与实际 DSH 入口验证建议、引用、采纳及医生正式确认，React 18/19 和 ShadowRoot 合同继续成立。
- [x] G9：超过 100 条可见历史与大检验目录不会仅因逐条展开触发预算拦截；系统自动装配本次资料、完整安全病史和相关历史，医生无需删病历或手工选择范围。
- [x] G10：全部可见历史先进入授权来源清单。诊断、过敏、用药、设备、手术和明确异常或不确定的检验解释保留完整状态、时间及出处；其余历史只在超预算时分批读取并选择原记录，不生成改写摘要，不以缺失标记推定正常。原始资料及完整目录继续参与过时判断。
- [x] G11：模型使用轻量目录，保留真实临床身份、标本、组合项目成员和临床适用条件；目录与必要资料仍不能同时容纳时，分批完整读取当前全部检验候选，再用所选原项目生成和独立核验，不只取第一页或截断组合定义。来源、目录、授权或本次资料变化后，旧结果不可采纳。
- [x] G12：生成、历史读取和独立核验均按实际传输封装检查预算；独立批次有限并发。必要资料自身过大、未读完历史、模型中断或引用无效时明确说明并保留草稿，不静默截断或无限重试。
- [x] G13：精简后可直接容纳的病例沿用一次生成和一次独立核验；仅溢出时增加历史筛选。同一授权及输入下复用已完成的筛选，减少三个建议页面的重复调用；记录请求数量、字节和端到端耗时，临床完整性与核验不为加速让步。
- [x] G14：溢出历史按单条完整原始记录筛选，选择后再无损打包；同包其他记录不能仅因邻近被带回。筛选使用与完整来源绑定的短句柄，模型可见 schema 限定本批合法编号，虚构、重复、跨批编号拒绝，最终引用与审计保留真实来源身份；必读资料、否定、时间与不确定性完整保留。
- [x] G15：真实模型限流以安全状态和有限等待提示透传；同一次结构化生成的路由解析、初次生成、格式修复及限流等待共用原始截止时间，格式修复最多共用一次限流重试，遵守剩余请求预算和取消信号。限流耗尽后明确停止并保留草稿，不再叠加 outbox 重试，不自动更换 Provider 或模型。

## 待核实思路与说明

用户已确认允许无指南命中时展示待核实的诊断或检查思路，并要求修改当前含混、矛盾和泛化的说明。建议输入、生成、独立核验和 UI 继续由现有 owner 实现，免费语料需求仍由[全文检索规格](2026-10-16-free-guideline-corpus.md)拥有。

- [x] E1：没有适用指南或没有可执行院内目录时，诊断与检查页面仍可依据当前授权病例生成“待核实思路”，展示推断理由、支持、反对及会影响该项判断的待核实信息。思路独立于可采纳建议，不提供采纳按钮，不创建任何临床草稿或正式事实；本增量不允许推断无依据的处方字段。
- [x] E2：思路必须引用本轮实际病例资料，身份唯一、数量有界；与候选合计最多 8 项。独立核验检查病例支持、适用性、否定、时间和限定语。病例支持或限定语不成立的内容不发布；仅缺少指南支持且其余核验成立的诊断或检查候选可降为待核实思路。
- [x] E3：说明区分病例相关待核实事项与指南覆盖、院内目录、独立核验和处理能力问题。系统限制由实际执行结果产生并明确归类，指出相关候选及具体未通过的环节，不将它们写成患者病历不足。不再直接展示模型顶层无关联的缺项长清单。
- [x] E4：生成与核验都区分患者自述、分诊记录和记录时间；“患者没量过”不能抹去分诊 37℃记录。“无检测结果”不自动成为拒绝推荐该检测的理由，未记录不等于阴性、异常或禁忌存在。仅列出能改变当前具体判断的补问、补查或核对事项，不输出统一全套前置检查。
- [x] E5：保留既有处方字段缺证、目录真实身份、完整资料预算、历史读取、模型失败和授权边界；候选、思路与核验均使用同一组已装配病例原文。资料确实无法完整处理时如实显示系统限制，不用无指南思路绕过预算。
- [x] E6：策略版本参与资料指纹，旧结果和在途旧任务失效；新增状态字段能够兼容读取已持久化旧数据。Web、DSH React 18/19 及原生旅程验证分类说明、来源、只读思路、手改保护与医生正式确认。

## 自动准备与待开具清单

本节拥有已批准 v4 原型对应的诊疗交互要求；质控展示与定位由[质控规格的 C 条件](2026-10-15-doctor-document-quality-control.md#紧凑提示与问题定位)拥有。本节替代进入建议页面才启用生成、先逐条采纳再正式开具的交互要求，不改变 G 与 E 中的证据、目录、独立核验和正式提交边界。原型中的合成临床情节不构成诊疗规则。

- [ ] R1：开始当前病例接诊后，Agent 自动准备诊断、检查检验和处方；医生停留问诊或其他诊疗栏目时仍执行，不要求逐一进入三个栏目或点击“让 Agent 准备”。
- [ ] R2：已保存的患者问诊原文、医生保存的病历、已发布的检查检验报告、已确认诊断及已开具记录变化后，重新评估受影响清单。读取问诊不等待病历自动整理完成；未保存输入不作为已保存问诊事实。连续变化合并、相同授权及资料版本去重，较旧结果不能覆盖新资料。
- [ ] R3：检查结果发布后，重新评估诊断、后续检查及处方，按适用结果增补、调整或移出尚未确认的自动项目；不能只刷新检查栏目。不要求每次报告都改变三类清单，也不按原型血钾情节写死临床规则；报告只使用医生获准查看的文字及结构化结果，不读取影像像素。
- [ ] R4：各业务栏目默认显示紧凑的待确认或待开具清单。完整、核验通过的项目默认选中，可调整、取消选择或移除；必要字段缺失时只显示与该项相关的短提示，未补齐并通过现有校验前不可开具。推测性的诊断、检查思路继续只读，收在说明中，不混入可执行清单。
- [ ] R5：诊断、检查检验和处方分别确认或开具选中项目，不提供跨三类的一键正式提交；取消单独的采纳步骤。诊断主次由 Agent 预拟、医生调整确认，正式动作继续走现有 Command、权限、版本及必需的确认与校验；准备不等于确诊或开具。
- [ ] R6：更新期间保留旧清单，当前更新模块的旧自动项暂不可开具，医生可继续手工编辑；其他已经就绪且未受该次更新影响的模块可继续操作。提交时重新验证当前授权、病例资料、目录和草稿版本，不能提交已过时的自动结果。
- [ ] R7：后台更新保留已保存和未保存的人工修改及取消选择；相同相关依据下不重新加回医生已移除的项目。新资料与医生选择冲突时保留人工内容，显示一句可操作的核对提示，由医生决定保留、修改或移除；不能悄悄覆盖或恢复为模型原值。
- [ ] R8：已确认诊断、已开具检查和处方不被自动改写或撤回。新资料影响既有决定时，在对应记录显示简短提醒，并能进入该记录的现有处理入口；正式调整或撤回由医生完成，不因后台重新准备而重复开具同一项目。
- [ ] R9：来源、指南条款、待核实思路、核对结果、质控详情及 Agent 工作记录统一由“依据与说明”按需查看，默认收起；清单只保留必要项目字段和一行任务状态。工作记录展示来源变化、执行步骤及结果，不展示模型内部推理，不把长篇说明铺在诊疗正文中。
- [ ] R10：问诊正文不显示“三类待办已按最新资料核对”等待办汇总块，以及该块的状态、三类数量、跳转、暂停按钮和引导文字；后台准备继续，待办在各自栏目查看。问诊补问、病历自动整理、字段状态和医生手改方式不在本增量中调整；原型顶部的模拟按钮不进入产品。
- [ ] R11：自动准备仅针对当前接诊病例。切换栏目不中断；切换患者后暂停旧患者的新任务并保留草稿，迟到结果不串入新患者，返回时按最新资料恢复核对。各业务模块保留暂停、恢复及手动刷新入口；接诊结束后停止自动准备，既有只读与已提交约束继续生效。
- [ ] R12：单模块更新失败时保留医生草稿，明确显示“更新失败，可重试”，旧自动项目在核对完成前不可开具，其他就绪模块继续操作。未完成、暂停、过期或失败的任务不宣称已按最新资料核对；沿用现有有界重试和失败码合同，不无限重试或自动更换 Provider、模型。
- [ ] R13：指南及免费来源使用范围、资料完整性预算、真实院内目录、可采纳与只读思路的区别、授权、完整审计和独立核验继续生效；目录允许值或默认值不充当临床依据。没有足够依据时允许清单为空，不承诺每次三类都有可开具内容。

## 设计决定

### 已确认

- 提前推进 #179–#181，保留原有正式操作边界。
- 权威指南与现有模型、授权病例资料组合生成，优先查找和复用现成指南库。
- 现有草稿 Command、目录与模型桥接继续拥有原有职责。
- 可采纳建议使用实际取得并核验的官方条款及其出处，不以模型记忆补齐临床依据。没有适用条款时允许展示独立标识的待核实诊断或检查思路；思路仅供查看，核对实际病例依据与限定语，不能一键采纳或推导无依据的处方字段。指南条款与病例资料分别保存身份、版本和来源定位。
- 按 R 条件在当前接诊期间后台准备，复用输入资料、目录和证据版本的指纹去重；资料变化后更新，手动刷新显式开启新一轮，过时结果不可执行。
- 处方缺失字段保持待补充，采纳不能代入编辑器默认值；只有现有草稿校验通过后才能保存，正式开具仍需医生最终确认。
- 已存在检查申请草稿时，采纳不能暗中覆盖另一条人工输入；沿用当前单份草稿及显式处理入口。
- 共享来源、调度和引用合同只有一个实现 owner，三个业务切片在独立 worktree 中实现并集成验收。
- 模型输入由本次资料、安全历史和其余历史组成。历史以有界完整记录组无损打包；全部可容纳时直接生成，溢出时按单条完整记录完整读取其余历史的所有批次，仅返回本批提供的短句柄。服务端将句柄映射回原始来源身份，并将所选记录重新无损打包；最终模型只读取本次资料、安全资料及所选原记录，来源清单保留完整覆盖范围。
- 历史筛选与建议种类无关，覆盖本次诊断、检查和用药可能相关或冲突的信息；已完成结果仅按同一授权、模型及完整来源内容复用。刷新建议不自动改写已采纳内容，输入变化使筛选复用失效。
- 筛选结果仍不能容纳时明确显示自动读取的实际缺口；不通过提高单次预算、丢弃旧记录或用模型摘要替换原文来隐藏限制。
- 检验目录分批筛选使用全部本次、安全和已选历史资料，结果只能返回本批实际项目编号。全部批次完整结束后才进入生成，未选中的目录编号不能成为可采纳建议。完整目录与读取、选择清单留在服务端；同一完整授权输入及目录下复用已完成筛选。
- 限流只根据受信模型桥的明确状态和有界等待时间重试，不读取私密错误正文。等待与后续请求共用原有单次预算，停止、卸载或取消后不继续调用；认证、配额与未知失败不作为限流重试。

### 外部接入边界

中华医学会现成指南库的全文机器使用许可和 SDK 调用方式尚未取得。该接入须基于内容权利方确认的合同与接口实施，本期不创建占位 SDK、抓取器或竞争全文库。已核验的公开来源及覆盖缺口见[研究记录](../research/2026-10-13-clinical-recommendation-guidelines.md)。

## 测试策略

1. 使用现有 Hono HTTP、file-backed SQLite 和 outbox 公开入口验证三类生成；仅替换外部模型网络，保留真实来源、目录和领域校验。
2. 使用已有检查、诊断和处方页面测试，验证准确采纳、未保存编辑保护、刷新、目录失效、缺信息、只读和旧病例结果。
3. 使用现有真实 Web 与 DSH 双版本浏览器合同核对来源引用、布局、焦点、采纳和正式提交边界；不读取真实影像像素或截图。
4. 完整交付 diff 执行跨包类型、静态检查、相关回归、文档检查与必要构建；真实模型样本独立记录语义质量及其局限。
5. 复用公开 HTTP 和真实 SQLite，验证 596 条合成历史与大目录恢复生成、远页和旧安全信息、限定语、筛选虚构编号、未完成批次、并发上限、筛选复用与输入变化失效；实际外部模型网络仍是唯一替身。
6. 同一病例记录快速路径与超预算路径的请求数量、字节和运行耗时；性能 hard gate 使用稳定的调用数量、覆盖范围与并发合同，不将机器或真实模型的墙钟时间写成固定阈值。
7. 以混合相关和无关记录的完整历史包验证逐条筛选、重新打包和短句柄到原始来源的追溯；通过真实模型桥验证限流恢复、有限等待、格式修复共享重试、取消及不叠加 outbox 重试。实模验证保存最终状态和阶段计时，不将最小连接成功或替身结果视为大病例可用性证明。

8. R 条件通过公开 HTTP、现有共享 Command/Query、真实 SQLite 与 outbox 验证触发、合并、版本失效、患者切换、暂停恢复、接诊结束和正式提交边界，仅替换外部模型网络；以报告发布作为入口验证三类待办联动、手改及移除保护、已开具提醒和不重复开具。
9. 真实 Web 与原生 DSH 入口按已批准 v4 体验验证清单、折叠说明、问诊页不显示汇总、单模块失败及旧项禁用；覆盖 React 18/19、ShadowRoot、键盘、窄分屏和应用字号。原型浏览器核对只证明交互，不替代真实目录、模型或正式 Command 验收。

## 范围外

- #177 的全病历自动整理、#178 的独立质控，以及患者病史总结的实现或当前失败队列恢复。
- 自动正式确诊、检查开立、处方提交和病历签署。
- 全面药学安全质控、模型概率、隐藏病例答案和未经授权的指南全文复制。
- 没有实际来源或接入条件的全病种覆盖承诺。

## 依赖与风险

依赖现有医生授权读取、独立业务草稿和 DSH 模型桥接；全病历整理的已发布读模型继续复用，不把其他任务的整票关闭作为依赖。外部全文接入以实际许可和接口为边界；本期只使用已取得且可核验的来源，指南库的存在与网页可读性不能代替实际条款。

指南的临床适用性、病例信息完整性和药品规格映射影响建议质量。仅能核对引用存在不能证明临床语义正确，医生最终确认和现有服务端校验继续执行。
