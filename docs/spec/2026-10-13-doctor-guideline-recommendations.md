# 基于权威指南与当前病例的诊疗建议

Status: implemented

本规格拥有 [#179](https://github.com/CaiZongyuan/clinmesh/issues/179)、[#180](https://github.com/CaiZongyuan/clinmesh/issues/180) 和 [#181](https://github.com/CaiZongyuan/clinmesh/issues/181) 的详细需求，保留已确认的建议展示、逐条采纳和医生正式确认行为，并补充权威指南与当前病例共同作为生成依据的要求。整体范围见[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)。本期使用可取得的官方指南条款，借鉴 Bio 的来源登记与引文核验流程；中华医学会全文库通过官方 SDK 或授权服务接入，未取得的全文不阻塞本期实施，也不作为已有证据。

## 问题与目标

医生需要在检查检验、诊断和处方页面获得与当前病例相符的建议，并核对其临床指南依据。模型需要结合可追溯的指南内容、医生有权查看的病历资料和院内实际目录；不能以模型记忆或自行编造的指南引用替代临床依据。

## 范围

- 三个建议页面提前进入设计与实施阶段，不再把 #177 或 #178 的整票关闭作为启动条件。新来源接入完成后复用其公开读模型；当前阶段不复制全病历整理或质控流程。
- 优先复用现成的权威指南库与官方来源，保留发布机构、文献性质、版本、适用范围和可核对出处。国家标准、卫生行业标准、诊疗规范、临床指南和专家共识分别标识。
- 使用现有 DSH 辅助模型，读取当前医生有权查看的问诊、病历草稿、报告、诊断及可见历史；不读取隐藏病例答案、影像像素或助手推理。
- 检查检验建议准确映射院内可选项目；诊断建议展示候选、支持信息、不符合信息及待核实事项；处方建议展示具体药品、剂量、频次、疗程、数量和各项依据。
- 进入对应页面自动生成，相关病例资料变化后更新，提供手动刷新。来源、目录或资料不足时明确说明，不编造缺少的内容。
- 每条建议由医生采纳进入现有可编辑草稿，保留已保存和未保存的手改；更新建议不自动改写已采纳内容。
- 正式确认诊断、开立检查和提交处方沿用既有入口及服务端校验，由医生最终确认。

## 用户故事

1. 作为医生，我希望在对应页面看到基于指南和当前病例的建议，并直接核对所引用的版本和条款。
2. 作为医生，我希望建议使用院内真实可选项目和药品，采纳后仍能检查和修改草稿。
3. 作为医生，我希望信息不足或指南不适用时明确看到缺少的依据，而不是得到无来源的完整方案。
4. 作为医生，我希望后台刷新与患者切换保留自己的修改，并且未经正式确认不会创建正式诊断、申请或处方。

## 验收条件

- [x] G1：接入的指南来源有可核验的发布机构、文献性质、版本、范围和内容取得方式；不能把公开可阅读等同于已取得全文集成授权。
- [x] G2：建议引用实际提供给模型的指南条款和当前病例资料；未知指南、虚构条款、错误引用或不属于当前病例的依据不能形成可采纳建议。
- [x] G3：检查检验建议准确映射当前可选目录，病理来源沿用既有授权手术选择；采纳保留其他人工编辑，不绕过单份当前申请草稿的合同。
- [x] G4：诊断候选包含支持、不符合和待核实信息；没有充分依据时保留不确定性，不展示模型自行猜测的概率。采纳复用实际诊断编码且不自动确诊。
- [x] G5：处方字段来自适用的指南、病例资料与真实药品规格，资料不足的字段标为待补充。目录允许值和编辑器默认值不能当作临床依据，缺失单位或包装换算不能被猜测补齐。
- [x] G6：刷新、失败、目录变化、患者切换及迟到结果不改写已采纳草稿，不丢失未保存的手改，不使旧版本建议归入新对象。
- [x] G7：只读、已正式提交和无需用药等状态沿用当前约束；采纳和自动生成均不创建正式 Condition、检查申请或 MedicationRequest。
- [x] G8：公开 HTTP 与真实 SQLite 验证授权、版本、错误和草稿边界；Web 与实际 DSH 入口验证建议、引用、采纳及医生正式确认，React 18/19 和 ShadowRoot 合同继续成立。
- [x] G9：超过 100 条可见历史与大检验目录不会仅因逐条展开触发预算拦截；系统自动装配本次资料、完整安全病史和相关历史，医生无需删病历或手工选择范围。
- [x] G10：全部可见历史先进入授权来源清单。诊断、过敏、用药、设备、手术和明确异常或不确定的检验解释保留完整状态、时间及出处；其余历史只在超预算时分批读取并选择原记录，不生成改写摘要，不以缺失标记推定正常。原始资料及完整目录继续参与过时判断。
- [x] G11：模型使用轻量目录，保留真实临床身份、标本、组合项目成员和临床适用条件；目录与必要资料仍不能同时容纳时，分批完整读取当前全部检验候选，再用所选原项目生成和独立核验，不只取第一页或截断组合定义。来源、目录、授权或本次资料变化后，旧结果不可采纳。
- [x] G12：生成、历史读取和独立核验均按实际传输封装检查预算；独立批次有限并发。必要资料自身过大、未读完历史、模型中断或引用无效时明确说明并保留草稿，不静默截断或无限重试。
- [x] G13：精简后可直接容纳的病例沿用一次生成和一次独立核验；仅溢出时增加历史筛选。同一授权及输入下复用已完成的筛选，减少三个建议页面的重复调用；记录请求数量、字节和端到端耗时，临床完整性与核验不为加速让步。

## 设计决定

### 已确认

- 提前推进 #179–#181，保留原有正式操作边界。
- 权威指南与现有模型、授权病例资料组合生成，优先查找和复用现成指南库。
- 现有草稿 Command、目录与模型桥接继续拥有原有职责。
- 首期提供实际取得并核验的官方条款及其出处；没有适用条款时显示缺少依据，不以模型记忆补齐临床建议。指南条款与病例资料分别保存身份、版本和来源定位。
- 生成在相关页面启用时触发，按输入资料与目录、证据版本的指纹去重；资料变化后更新，手动刷新显式开启新一轮。过时结果不能采纳。
- 处方缺失字段保持待补充，采纳不能代入编辑器默认值；只有现有草稿校验通过后才能保存，正式开具仍需医生最终确认。
- 已存在检查申请草稿时，采纳不能暗中覆盖另一条人工输入；沿用当前单份草稿及显式处理入口。
- 共享来源、调度和引用合同只有一个实现 owner，三个业务切片在独立 worktree 中实现并集成验收。
- 模型输入由本次资料、安全历史和其余历史组成。历史以有界完整记录组无损打包；全部可容纳时直接生成，溢出时先完整读取其余历史的所有批次，仅返回已提供的记录组编号。最终模型只读取本次资料、安全资料及所选原记录，来源清单保留完整覆盖范围。
- 历史筛选与建议种类无关，覆盖本次诊断、检查和用药可能相关或冲突的信息；已完成结果仅按同一授权、模型及完整来源内容复用。刷新建议不自动改写已采纳内容，输入变化使筛选复用失效。
- 筛选结果仍不能容纳时明确显示自动读取的实际缺口；不通过提高单次预算、丢弃旧记录或用模型摘要替换原文来隐藏限制。
- 检验目录分批筛选使用全部本次、安全和已选历史资料，结果只能返回本批实际项目编号。全部批次完整结束后才进入生成，未选中的目录编号不能成为可采纳建议。完整目录与读取、选择清单留在服务端；同一完整授权输入及目录下复用已完成筛选。

### 外部接入边界

中华医学会现成指南库的全文机器使用许可和 SDK 调用方式尚未取得。该接入须基于内容权利方确认的合同与接口实施，本期不创建占位 SDK、抓取器或竞争全文库。已核验的公开来源及覆盖缺口见[研究记录](../research/2026-10-13-clinical-recommendation-guidelines.md)。

## 测试策略

1. 使用现有 Hono HTTP、file-backed SQLite 和 outbox 公开入口验证三类生成；仅替换外部模型网络，保留真实来源、目录和领域校验。
2. 使用已有检查、诊断和处方页面测试，验证准确采纳、未保存编辑保护、刷新、目录失效、缺信息、只读和旧病例结果。
3. 使用现有真实 Web 与 DSH 双版本浏览器合同核对来源引用、布局、焦点、采纳和正式提交边界；不读取真实影像像素或截图。
4. 完整交付 diff 执行跨包类型、静态检查、相关回归、文档检查与必要构建；真实模型样本独立记录语义质量及其局限。
5. 复用公开 HTTP 和真实 SQLite，验证 596 条合成历史与大目录恢复生成、远页和旧安全信息、限定语、筛选虚构编号、未完成批次、并发上限、筛选复用与输入变化失效；实际外部模型网络仍是唯一替身。
6. 同一病例记录快速路径与超预算路径的请求数量、字节和运行耗时；性能 hard gate 使用稳定的调用数量、覆盖范围与并发合同，不将机器或真实模型的墙钟时间写成固定阈值。

## 范围外

- #177 的全病历自动整理、#178 的独立质控，以及患者病史总结的实现或当前失败队列恢复。
- 自动正式确诊、检查开立、处方提交和病历签署。
- 全面药学安全质控、模型概率、隐藏病例答案和未经授权的指南全文复制。
- 没有实际来源或接入条件的全病种覆盖承诺。

## 依赖与风险

依赖现有医生授权读取、独立业务草稿和 DSH 模型桥接；全病历整理的已发布读模型继续复用，不把其他任务的整票关闭作为依赖。外部全文接入以实际许可和接口为边界；本期只使用已取得且可核验的来源，指南库的存在与网页可读性不能代替实际条款。

指南的临床适用性、病例信息完整性和药品规格映射影响建议质量。仅能核对引用存在不能证明临床语义正确，医生最终确认和现有服务端校验继续执行。
