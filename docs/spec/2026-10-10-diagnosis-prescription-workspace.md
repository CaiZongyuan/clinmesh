# 诊断与处方两阶段工作台

Status: implemented

## 问题与目标

诊断与处方页目前通过独立目录弹窗添加条目，再在整组表格中填写信息；正式记录也集中显示在表格中。条目增加后，目录选择、编辑和记录阅读的上下文分散，窄分栏中的表单不易操作。

目标是将已确认的 [V1 交互预览](../../previews/diagnosis-prescription-v1.html) 落地为真实页面：首次填写直接提供目录与选中条目的编辑区，正式确认后提供可搜索的列表与选中详情。诊断确认、处方开具及逆向动作继续使用已有业务合同。

## 范围

- standalone Web 与 DSH Surface 共用的医生诊断、处方页，以及现有疾病、药品目录选择器。
- 诊断的主次角色、备注、自动保存、整组确认与确认后的修订。
- 处方的真实产品与包装选择、剂量、频次、疗程、数量、自动保存、整张处方开具、删除草稿、撤回与无需用药结论。
- 复用现有 Query、Command、权限、版本、幂等、审计、页面 Tools、UI primitives、主题、字号和中英文文案。

## 用户故事

1. 作为医生，我希望首次填写直接检索目录并明确选择项目，在同一工作区填写所选项目的临床信息。
2. 作为医生，我希望正式确认后按列表选择诊断或药品，集中阅读或按权限修订当前条目的详情。
3. 作为窄屏或键盘用户，我希望能返回列表、切换条目和恢复搜索，且这些操作不会丢失草稿或删除正式记录。

## 验收条件

- [x] 可编辑且尚未正式确认的诊断直接显示疾病目录与编辑区，不自动添加目录第一项；有效的已保存草稿恢复其真实条目。
- [x] 可编辑且尚未开具处方时直接显示药品目录与编辑区；医生明确选择真实产品与包装，已选、停用或组合不兼容的项目不能添加。
- [x] 已选条目可以切换编辑，诊断保留恰有一条主诊断、最多八条和备注限制；处方保留最多八条、本院药品选项约束、全局产品输入验证和组合限制。
- [x] 诊断确认成功后切换为可搜索、可按主次筛选的列表与选中详情；仍可添加、更换、移除和修改备注，再次确认保留旧正式 revision。
- [x] 已开具、缴费、调剂或撤回的处方以药品列表与选中只读详情展示真实状态与 DTO 已有元信息，不推测不存在的费用、库存、给药途径或业务时间。
- [x] 添加诊断在同一目录与编辑布局的弹窗中完成；关闭后保留当前修改，并恢复合理焦点。更换继续明确选择且保留既有临床字段合同。
- [x] 搜索、筛选为空或窄屏返回只改变展示，不删除条目、不切回首次阶段、不清空输入；查看全部与重新选择可恢复详情。
- [x] 确认作用于整组诊断；开具、删除草稿及撤回作用于整张处方。无需用药展示对象预览与显式确认，继续由现有 Command 清除未开具草稿。
- [x] 自动保存的等待、进行中、成功与失败可感知；失败保留输入并可重试。输入无效、未保存或正在保存时不能执行终结动作。
- [x] 未接诊、只读与已完诊状态不开放普通写入；现有明确授权的纠错入口、Agent 表单与页面 Tools 保持可用。
- [x] 中文与英文、亮暗主题、三档字号，1280px 桌面及390px窄屏下，列表、目录分页、编辑、弹窗和末尾操作可达且无页面横向溢出。
- [x] 通过现有页面公共交互与 React 18／19、ShadowRoot 合同验证，并从 standalone Web 与 DSH 真实入口核对关键旅程。

## 设计决定

阶段从真实诊断 confirmation 与处方事实派生，不增加服务端阶段或缓存。诊断已确认后形成的新草稿不让页面回到首次填写；处方撤回保留原正式记录。筛选结果不决定阶段。

阶段、目录布局与状态归属的替代方案见[两阶段视图决定](../../.agents/notes/implemented/architecture/2026-10-10-diagnosis-prescription-workspace.md)。

诊断与药品保持各自独立模型，目录搜索与包装分组复用现有选择器。页面拥有未提交输入，TanStack Query 继续拥有服务端事实；布局不复制 Command、持久化和 Agent action 逻辑。只使用 React 18.3.1 与 19.2 共有 API，并保持 PortalContainerProvider 的 ShadowRoot 边界。

预览仅作为布局和交互依据，模拟数据、保存定时器及状态选择器不进入正式运行。外层布局遵循 [UI 设计合同](../ui/design.md)。

## 测试策略

使用现有 DiagnosisPage、PrescriptionPage、目录选择器和医生工作台的公共渲染／交互 seam 按 TDD 验证新增行为。重点覆盖首次无默认选择、真实包装、重复与停用禁选、主次切换、阶段切换、失败后输入保留、搜索与筛选恢复、窄屏返回、整组确认与整张处方动作、只读和 Agent 表单。

复用 Playwright 的 standalone Web 与 DSH 入口、React 18／19 和 ShadowRoot 合同，验证长文本、窄分栏、主题、字号、滚动与焦点。所有数据使用合成 fixture，不读取真实影像像素。运行相关组件／工作台／浏览器回归、typecheck、lint、Web／DSH build 及文档检查。

## 范围外

- 预览控制栏、模拟业务状态、长期 mock 页面或新增依赖。

## 依赖与风险

现有目录、草稿与正式业务动作已提供所需能力。诊断与处方阶段切换、自动保存刷新和弹窗重挂载可能影响当前选择、输入和 Agent 发布，需要以真实提交结果为准并保留失败输入。DSH 窄分栏、ShadowRoot portal 和 React 18 兼容需独立验证。
