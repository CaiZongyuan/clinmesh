# 工作台扁平卡片重构（门诊与住院）

Status: approved

## 问题与目标

现状审计（[UI/UX 现状审计](../research/2026-10-29-ui-ux-current-state-audit.md)）确认：浅色状态色对比度不足；同类页面重复实现、观感不一致；ClinMesh 的靛紫主色与 DSH 宿主的中性主按钮和蓝色业务色并存，整屏不像一个产品；住院线入口分散，阶段工作台把办不了的环节也摆在页签上，点进去才提示由别的岗位办理；Agent 的草稿和正式值外观相同，`.propose` 动作用弹窗打断当前工作。

目标：所有岗位改用同一套扁平卡片工作台。整屏视觉与 DSH 宿主一致；每个岗位只看到要办的事，并清楚知道下一步是什么、卡在哪里；Agent 只填草稿或准备操作，正式提交由人在原位确认。业务能力、服务端合同与门禁保持不变，住院 Agent 能力的补充见下文「住院 Agent 能力」。

设计依据是用户已确认的两份可交互原型：门诊原型（挂号员、分诊护士、门诊医生、收费员、药师）和住院原型（住院医生、病区护士、收费员，采用 W1 分组页签，基准风格，不加特色层）。没有原型的页面按已出的页面功能规划执行，规划与原型冲突时以原型为准。原型只是设计依据，不是实现代码。

## 范围

- 平台：standalone Web 与 DSH Surface 两端。Desktop 消费同一套 token，但不单独验收；Mobile 不在范围内。
- 共用外壳：语义 token、页头、流程线、队列卡、患者卡、内容卡、右栏、底部操作栏、原位确认、Agent 草稿标记与响应式布局，覆盖全部岗位页面。
- 门诊五个岗位：挂号员、分诊护士、门诊医生、收费员、药师（有原型）。
- 住院三个岗位：住院医生、病区护士、收费员住院部分（有原型）。
- 没有原型、按规划执行的七处：住院登记（挂号员的住院部分）、住院药房、病案、医保核定、退费、模拟数据（管理员）、设置。
- 住院 Agent 能力：补充住院页面上下文，并新增「准备、等你确认」类工具。
- 界面文案：住院界面与助手话术按实际岗位用语改写，见「住院文案与助手话术」；门诊按门诊原型的文案。

## 用户故事

1. 作为任一岗位人员，我希望页面只显示本岗位要办的事和不得不看的只读资料，以便不被办不了的环节打断。
2. 作为任一岗位人员，我希望底部操作栏一直告诉我下一步按什么、为什么现在按不了，以便不用猜禁用原因。
3. 作为使用 Agent 的人员，我希望一眼看出哪些字段是 Agent 填的，并在原位决定采用或不采用，以便既省力又不失去把关。
4. 作为门诊医生，我希望在五个分区之间自由切换，并随时看到完诊还差什么、去哪个分区补，以便不按固定顺序也能完成本次就诊。
5. 作为住院护士或医生，我希望打开患者就落在「轮到我」的环节，页签上直接显示待办数，以便先处理到时间的任务。
6. 作为收费员，我希望门诊和住院收费在同一个队列卡里切换，以便不在外层页签之间来回跳。
7. 作为在 DSH 中工作的人员，我希望 ClinMesh 与宿主的颜色、字体、主按钮和明暗模式一致，以便整屏像一个产品。

## 验收条件

### 共用外壳与视觉

- [ ] 语义 token 来自 DSH 宿主变量：浅灰画布配白色卡片，卡片有圆角和淡边框，没有常驻阴影和渐变。主按钮使用中性色（浅色模式近黑、深色模式近白）。蓝色只表示交互、焦点、选中和 Agent 参与。字体使用系统字体栈。standalone Web 使用相同取值作为回退，不再使用靛紫主色。
- [ ] 浅色和深色两套主题都成立。DSH 中只跟随宿主的明暗，不提供本地主题入口。正文文字的对比度达到 4.5:1，状态色和非文本边界达到 3:1。
- [ ] 字号：正文和输入为 14px，表格与数据区为 13px。字号三档偏好继续生效，只缩放语义字号。日期、时间、金额和检验值使用等宽数字。
- [ ] 页头只放这些内容：页面名、当前患者、助手状态摘要、全屏按钮、人物菜单。岗位切换只在右上角人物菜单里，菜单分为门诊、住院、系统三组。
- [ ] 页头下方有一条流程线。门诊依次为挂号 → 分诊 → 接诊 → 缴费 → 发药；住院依次为住院登记 → 入科分床 → 在院诊疗 → 出区 → 结算 → 清床 → 病案归档 → 医保核定。流程线标出当前病例所在环节；队列开关放在流程线最左端。收起队列时整列移除，不留细条。
- [ ] 画布从左到右依次为：队列卡（可收起）、主区（患者卡、页签和内容卡）、右栏（只放做决定需要的只读资料）。没有只读资料的页面不设右栏，主区占满。
- [ ] 底部操作栏只在有主操作，或刚完成一个操作时出现。左边显示关键数字，中间显示禁用原因或「还差：…」，右边只放一个主按钮。完成后显示「已完成 …」和可以接着做的下一步。
- [ ] 不可逆的提交（确认收款、确认结算、确认完诊、提交支付、确认发药）先把操作栏变成确认条，说明后果，并提供「返回」和「确认」，不弹出模态框。
- [ ] 布局按 ClinMesh 内容容器的宽度切换，不按视口宽度：
  - 900px 以上：三栏。
  - 600–900px：队列与主区两栏，右栏移到主区下方。
  - 600px 以下：单栏，队列变成顶部的横向条。
  - 宽屏 944、分屏 720、窄屏 400 三档下都不出现横向页面滚动，标签文字不折行挤压。
- [ ] 页签放不下时，排在后面的页签自动收进「更多」，当前页签始终可见。展开「更多」后页签换行显示，宽度变化时重新测量。

### Agent 草稿与原位确认

- [ ] Agent 通过 `*.draft.set` 填写的字段显示虚线框和「助手」标记，人工修改后变回实线并去掉标记。
- [ ] Agent 的 `.propose` 动作不再弹出 AlertDialog：
  - 针对某一行的操作（校对、确认已阅、确认诊断）显示为该行内的确认框。
  - 针对整页的操作（挂号、分诊、开具处方、收款、发药）显示为底部操作栏的助手确认条。
  - 两种形式都并排提供「不采用」和确认按钮。
- [ ] 原位确认保留现有审阅合同，只改变呈现位置：
  - 同一时间只有一个待确认项。
  - 需要「已核对」勾选的请求，必须勾选后才能确认。
  - 请求被中止、或页面卸载时，确认框消失，调用方收到拒绝。
  - 批准和拒绝都是静态的，不播放 Agent 动效。
- [ ] Agent 执行非 proposal 动作时，工作区的环绕柔光改用蓝色交互色；系统开启减弱动效时，不播放柔光。
- [ ] DSH 对话区仍是唯一的模型对话位置，ClinMesh 页面内不另做聊天区。

### 门诊

- [ ] **挂号员。**
  - 队列卡顶部分为待挂号、检索、建档三个分段。
  - 主区：选中病例后显示患者卡和挂号信息（科室、号别及价格、就诊地点）。就诊日期显示为仿真日期，只读。
  - 右栏：今日挂号列表，门诊号可以复制；复制失败时显示提示。
  - 确认挂号后生成 `CM-OP-…` 门诊号，病例进入待分诊。
  - 队列卡顶部的「门诊 / 住院」切换替代原来的外层页签。住院部分见下文的无原型页面。
- [ ] **分诊护士。**
  - 队列分为待分诊、已分诊两个页签，去掉服务端恒为空的「异常」页签。
  - 主区：主诉，六项体征，以及四级分级的单选芯片。
  - 体征输入框显示可录入范围，超出范围时在原位报错，并写明范围。
  - 体征卡片标题说明「默认值不是测量结果」。
  - 右栏显示风险信息。
  - 操作栏写明还差哪些字段。
- [ ] **门诊医生。**
  - 五个分区沿用 `doctorCaseSectionSchema` 的顺序和名称：问诊记录、病历记录、检验检查、诊断、处方。
  - 分区页签可以任意切换，每个页签显示状态图标和待办数。
  - 患者卡有「完诊 n/7」按钮。
  - 右栏显示完诊清单，七项都写明对应的分区名，点击可跳转。生命体征放在完诊清单下方。
  - 现有的质控开放疑点和诊疗建议继续保留在右栏，改用新的卡片样式。
  - 点击完诊时，如果有未完成项，操作栏列出缺少的项，并给出「前往〈第一个缺项的分区〉」；全部满足时，操作栏变成确认条。
  - 原来的完诊 Dialog 不再使用。
  - 已完诊的病例为只读，服务端允许的纠错入口继续保留。
- [ ] **收费员（门诊）。**
  - 队列卡顶部是「门诊 / 住院」切换，下面依次是类别筛选（检验、放射、病理、药品）和 2×2 网格的状态筛选（待缴、已缴、已拒绝、结果未知）。
  - 主区：账单表格中挂号费只读，并注明「不在这里收取」。收款最多支持三种方式组合，金额填错时在原位报错。
  - 预览之后才能确认支付。支付拒绝时可以重新填写；结果未知时，主操作变为「查询原支付结果」。
  - 右栏显示支付尝试记录。
- [ ] **药师（门诊）。**
  - 队列分为待发药、已发药两个页签，去掉恒为空的「异常」页签。
  - 先审核，再发药。审核意见为空时不能审核通过。
  - 发药时批次默认选最早到期的，下拉选项显示库存和有效期。发药数量超过批次库存时在原位报错；允许部分发药，剩余数量留在待发药里。
  - 过敏只提示，不阻止审核或发药。

### 住院（有原型的岗位）

- [ ] **患者卡与环节页签。**
  - 患者卡显示：住院号、行政状态、姓名、性别年龄、住院第 N 天（从入科日算）、病区床位、预交金、累计费用。只有收费员显示「还需收取」这个大号金额。
  - 环节页签按岗位收敛：
    - 住院医生：诊断医嘱、检查检验、手术、DRG 推演、出院、病案；入科和费用收进「更多」。
    - 病区护士：入科、诊断医嘱、检查检验、手术、出院；费用和病案收进「更多」，不显示 DRG 推演。
    - 收费员：费用、出院；入科收进「更多」。
  - 本次住院没有发生的环节移进「更多」，并标注「未发生」。本岗位读不到的环节不显示。页签多于 3 个时，按「入院｜在院｜出院｜病案」分组显示。
  - 转科交接只在多病区环境出现，住院医生和病区护士按现有权限读取。
- [ ] **环节头与落点。**
  - 每个环节头显示办理顺序，本岗位那一步加粗。
  - 有待办时写「轮到你：…」；没有待办时，写这个环节在等谁。
  - 打开患者时，默认落在本岗位第一个有待办的环节；没有待办时，落在岗位默认环节。
- [ ] **病区护士。**
  - 队列：待接诊置顶，每个床位显示「轮到你 n 项」，空床显示床位费。召回窗口和出院后病历放在列表底部。
  - 医嘱：可以逐条校对；按需执行和停嘱需要先填理由。给药未到计划时间时，写明「〈时间〉后可给药」。
  - 检查检验：可以校对并送检。
  - 手术：术前核对需要先填核对说明。
  - 出院：办理出区受阻时，写明还差几条医嘱、几次给药，以及下一步由谁处理。
  - 右栏显示已出的检查检验结果，带参考范围。
- [ ] **住院医生。**
  - 右栏为临床提醒，只写平台已有的事实，并说清在等谁；没有提醒时写「目前没有提醒」。
  - 「开始手术」旁边直接列出还差的项及负责人，不靠悬停提示。
  - DRG 推演、耗材建议和后台跟进使用新文案，规则不变。
- [ ] **收费员（住院）。**
  - 队列按待结算、在院、待入科分组。
  - 出区补缴的流程：可以留空，按全额记为现金 → 预览收款 → 确认收款 → 预览结算（预览后锁定）→ 确认结算 → 等护士清床。账目变化后需要重新预览。

### 无原型的页面（按规划执行）

- [ ] **住院登记。** 放在挂号员页面队列卡的「住院」侧。主区是住院登记表（入院途径、患者来源、住院证、入院病区、预交金）和在册列表，门诊转住院与直接入院走同一个表单。
- [ ] **住院药房。** 放在药师页面队列卡的「住院」侧。主区是住院发药队列，样式与门诊发药一致，包括审核、批次和数量。
- [ ] **病案。**
  - 队列：全部、待整理、审核通过、已归档，行可以点击切换。
  - 主区：病案环节显示基本信息、住院过程、正式诊断与实际操作、病案费用、审核与归档记录。
  - 右栏：DRG 复核。
  - 病区和床位显示名称，不显示 ID。
- [ ] **医保核定。** 只保留核定队列一个入口，只列已归档的病案，去掉下方的住院表格。主区显示归档冻结的分组、复核说明和历史核定。主操作依次为「审阅模拟核定」→「提交模拟核定」。
- [ ] **退费。** 「费用更正与退款」改为当前费用下面的一张内容卡，只在有已缴费用时出现。操作依次为「预览退款」→「确认退款」。
- [ ] **模拟数据。**
  - 改为两个页签：演示准备、患者库。
  - 演示准备：虚拟时间、重置数据、生成患者、PCI 演示准备、影像和病理准备。
  - 患者库：搜索与翻页、患者详情、患者档案、开始门诊就诊、本次病例真值、来源历史。
  - 列表、详情、开始就诊等操作失败时，按实际失败的操作写错误文案。
- [ ] **设置。** 换成新外壳和卡片样式，导航与功能不变。

### 住院 Agent 能力

- [ ] 住院页面的 Agent 上下文包含当前患者和当前环节，替代现在的 `inpatient: []`。
- [ ] 新增以下 Agent 工具，均遵循窄 schema、受信 context binding、幂等键、预期版本与完整审计：
  - `inpatient.stage.select`：切换环节，只做导航。
  - 护士医嘱校对：准备后等护士确认。
  - 医生报告确认已阅：准备后等医生确认。
  - 收费员出区补缴：可以填写收款草稿，也可以生成收款预览。
  - 收费员结算：可以生成结算预览，只预览，不结算。
- [ ] 下列操作不提供 Agent 入口，由人工完成：
  - 直接提交校对、给药、收款、结算。
  - 替医生确认知情同意。
- [ ] Agent 工具变化要同步更新 Operation Catalog、对应的 `clinmesh-*` Skill 和命令示例漂移测试。

### 住院文案与助手话术

- [ ] 界面上的 Agent 统一称为「助手」，与 DSH 中的「ClinMesh 医院助手」同名，门诊和住院一致。代码标识符、工具名和文档里的 Agent 术语保持不变。
- [ ] 住院界面不出现以下系统用语：冻结、事实、口径、推演、派发、授权、版本、模型、草稿、仿真时间、虚拟时间、尚应收、净额。模型相关功能统一称为「AI」。
- [ ] 住院术语按下表显示：

  | 原来 | 改为 |
  | --- | --- |
  | 出区 / 已出区 | 办理出院 / 已出院 · 待结算 |
  | 出区补缴 · 尚应收 · 还需收取 | 出院补交 · 需补交 |
  | 冲正 | 退费 |
  | 费用净额 · 基金支付 · 患者现金应付 | 费用合计 · 医保统筹支付 · 个人自付 |
  | 签发医嘱 | 开立医嘱 |
  | 确认已阅 · 报告待阅 | 已阅 · 待阅 |
  | 请求按需执行 · 核停 | 按需给药 · 停嘱核对 |
  | 知情同意已签署 | 手术知情同意书已签 |
  | 术前检查核对 | 术前核对 |
  | DRG 与费用推演 · 正式事实分组 · 若计划手术实施 | DRG 预分组 · 按当前诊断和手术 · 如按计划手术 |
  | 后台跟进 | 自动跟进 |
  | 预览已冻结 | 账目已锁定 |
  | 待接诊 · 病区一览 · 空闲 | 新入院 · 本病区 · 空床 |
  | 执行科室 | 医技科室 |

- [ ] 住院文案的句式要求：
  - 先说结论或下一步，再说原因。
  - 状态写成「等〈谁〉〈做什么〉」。
  - 金额从患者的角度写，例如「需补交」「应退」「无需补退」。
  - 时间直接写到点，例如「08:00 可给药」。
  - 做不了时，写明还差什么、由谁处理。
  - 按钮只写动作。
- [ ] `apps/dsh-web/cordis.patch.yml` 中的助手人设改为按当前岗位回复：
  - 医生按姓名称呼患者，护士和收费员按床号称呼患者。
  - 回复先说结论，使用本岗位的用词和简写，数字带单位。
  - 需要确认时，写明按页面上的哪个按钮。
  - 不代办的操作，用一句话说明由谁办理。
  - 回复中不提工具名、模型、草稿等系统词。
- [ ] 住院 Agent 工具返回的提示语遵循同一套规则。

### 状态与回归

- [ ] 每张内容卡都覆盖以下状态：
  - 加载中：使用 Skeleton，不整页闪烁。
  - 读取失败：写明哪项失败，并提供重试。
  - 空列表：写明为什么是空的，以及去哪里处理。
  - 无权限：不显示该环节或入口，不显示「请由其他岗位办理」的空壳。
- [ ] 以下既有门禁全部不回归：
  - 门诊：挂号 → 分诊 → 接诊 → 缴费 → 发药的状态机；完诊清单；处方开具后不可修改、未发药前可撤回；支付结果未知时阻止重复收款。
  - 住院：校对 → 发药 → 给药；手术四步门禁；未出院处理不能结算；未结算不能清床；归档冻结。
- [ ] 所有交互控件都有可访问名称，装饰图标设 `aria-hidden`，键盘焦点使用 `ring` token 且不被裁切。页签支持方向键切换。原位确认出现时焦点移到确认按钮，确认框关闭后焦点回到原位置。

## 设计决定

- **视觉方向：** 扁平卡片加基准风格。不加住院日程、床头卡、品牌色、签名格等特色层；这几个方向在原型里比较过，均已否决。
- **token 归属：** token 仍由 `packages/ui/src/styles.css` 拥有。DSH `preserve` 模式下，取值从宿主 `--dsw-*` 派生，不改用 `shell: 'surface'`，原因见 [DSH 宿主研究](../research/2026-10-29-dsh-host-design-language.md#63-需要用户决定的问题)。现有的「基线青绿」和「靛紫」两套主题合并为一套。
- **[UI 设计合同](../ui/design.md) 随实现改写：**
  - 「页面分区不做浮动 Card」改为本规格的扁平卡片合同。
  - 门诊医生工作台原有的 1080 / 720 断点，改为上面的 900 / 600 三档。
  - 窄屏下建议栈原来是抽屉，改为右栏移到主区下方。
- **门诊结构：** 沿用现有结构，只做界面细化。`doctorCaseSectionSchema` 与 Agent 工具的分区枚举不变。
- **住院结构：** 沿用患者列表加阶段工作台（[住院阶段工作台](../decisions/implemented/architecture/2026-10-21-inpatient-stage-workspace.md)），把阶段导航改为按岗位收敛的分组页签。药师和医保办不进入阶段工作台。
- **门诊与住院切换：** 挂号、收费、药房的「门诊 / 住院」从外层页签移到队列卡顶部的分段切换。
- **界面称呼：** 面向使用者的界面和话术称「助手」，工程文档和代码继续用 Agent。
- **原位确认：** 在现有 `AgentReviewProvider` 的合同上换呈现位置，不另做一套审阅状态。理由写成一份新的 Agent Note，同时把[柔光 Note](../decisions/implemented/architecture/2026-10-07-agent-workspace-glow.md) 的颜色更新为蓝色交互色。
- **状态归属：** 队列收起、当前页签、「更多」展开等属于客户端视图状态，归 Zustand；服务端数据仍归 TanStack Query。
- **依赖：** 不新增运行时依赖。图标继续使用 lucide。

## 测试策略

- **静态与单元：** `pnpm typecheck`、`pnpm lint`，以及受影响包的 vitest。纯函数需要单测：待办推导、默认环节落点、岗位页签收敛、完诊清单到分区的映射、金额与体征的输入校验。
- **原位确认：** 迁移 `agent-review.test.tsx` 的现有断言，覆盖批准、拒绝、勾选、中止、卸载和同时只允许一项。原位确认属于对话框类组件，要纳入 `pnpm test:browser` 的 React 18/19 双版本合同测试。
- **Agent 工具：** 新增的住院工具要有服务端测试，覆盖 schema 拒绝、幂等重放、版本冲突、越权岗位和审计记录，并补齐 Operation Catalog 与 Skill 的漂移测试。只使用合成 Provider，不调用真实模型。
- **文案：** 新增一项检查，扫描住院界面源码中的中文文案，出现禁用的系统用语时失败。助手人设的修改纳入 `business-preset.test.ts`。
- **浏览器：** 在 `pnpm test:e2e` 中更新门诊全链路、住院闭环和各岗位的断言。可访问名称与文案按新文案重写，门禁断言保持不变。
- **截图证据：** 用 Playwright 从真实入口截图，覆盖：
  - 每个岗位 × 宽屏 944、分屏 720、窄屏 400 × 浅色、深色。
  - 空状态、错误状态、门禁拒绝、Agent 草稿、原位确认。
  - 截图不包含影像和病理像素。
- **DSH：** `pnpm --filter @clinmesh/dsh-web build` 通过 verify-artifact 体积关卡。
- **文档：** `pnpm verify:docs`、`pnpm docs:check`；修改 Agent Note 时加跑 `pnpm verify:agent-notes`。

## 依赖与风险

- **DSH 产物体积：** 现状审计记录产物已超出 5,000,000 字节预算。改造不能增加依赖，样式整合后要实测体积；超出时需要先处理预算问题，再合入。
- **`DoctorCaseController` 体量：** 约 2,760 行。门诊医生界面改造需要先按分区拆分，否则风险集中在一个文件。
- **测试定位：** 约 3,400 处测试按角色名或文案定位，文案改写后要批量更新。门禁类断言只能改定位方式，不能放宽条件。
- **新增住院 Agent 工具：** 涉及服务端、Operation Catalog 和 Skill 三处，是本需求中唯一的后端改动，可以作为独立切片验收。
- **工作区现状：** `main` 上有用户未提交的改动。实施在独立分支和仓库外 worktree 中进行，不覆盖这些改动。
- **原型来源：** 原型源文件位于会话临时目录，可能丢失。实现以本规格和[设计合同](../ui/design.md)为准，原型只用于视觉对照。
