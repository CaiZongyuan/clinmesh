# 移除自动记录后的独立语义核对，统一由病历质控检查

Status: implemented

## 问题与目标

自动记录通过程序校验写入草稿后，当前会为每个实际保存的片段分别调用一次模型进行语义核对。现有病历质控也检查 Agent 片段的来源支持性，并在有 Agent 片段或候选问题时独立复核。两套流程存在重复调用，页面和签署预览还会同时出现独立核对状态与质控问题。

目标是取消自动记录后的逐片段模型核对及其独立提示，由现有病历质控统一承担来源语义检查。自动整理继续直接保存草稿，医生通过现有病历编辑和质控流程审阅；调用减少以实际任务类型和次数证明，不承诺未经测量的 Token、费用或延迟降幅。

## 范围

- 实时整理、历史补录、显式重试和服务重启恢复统一停止创建或执行自动记录后的独立语义核对。
- 清理相关调度、模型绑定、恢复分支及 Web/DSH 病历和签署入口的独立核对提示，兼容已有任务、核对状态及审计数据。
- 保留来源存储、句子编号恢复、引用合法性、角色与字段约束、候选隔离、人工编辑和状态保护，以及现有病历质控及其独立复核。
- 明确旧事实保留、更正或冲突关系、被拒绝事实再次出现的检查归属，避免删除独立核对时一并丢失业务保护。

## 用户故事

1. 作为医生，我希望自动整理及时保存病历，并在现有质控中统一查看需要核实的问题，减少重复的核对状态和操作。
2. 作为维护者，我希望新增多个病历片段时不再产生同等数量的额外核对请求，同时保留可追溯来源及旧数据恢复能力。

## 验收条件

- [x] A1：新批次通过程序校验后按既有共享 Command 保存草稿和来源进度，不再为新增、更新、更正或冲突片段创建独立语义核对任务。无格式错误时，一批自动记录只有一次整理模型请求；片段数量增加不再增加 `consultation_history_verification` 请求，既有有界格式修复规则保持不变。
- [x] A2：实时、补录、显式重试、重复消费、刷新及服务重启均不调用独立核对模型；不能把同一工作改名、迁入每片段质控任务或作为缺省回退，重新引入额外调用。
- [x] A3：引用仍从不可变快照准确恢复，未知或重复编号、错快照、来源角色或字段不符、越界索引、超限和竞争替换仍按原规则拒绝；来源和候选错误保持可观察、可恢复，不被伪装成已记录。
- [x] A4：旧有效事实的保留、显式更正或冲突关系、拒绝事实在缺少新依据时不得重现的要求保持有效。可由程序判断的规则继续在写入前执行；需要语义判断的部分归现有质控，携带必要的变更前后事实、拒绝事实及来源上下文，不另建逐片段模型流程。资料不足或检查失败不能声明这些规则已经通过。
- [x] A5：现有质控继续检查 Agent 片段是否得到真实来源支持，保留时间、否定、不确定性和自述等限定，并沿用当前生成、独立复核、同输入复用及失败说明。质控保留“待核实”、影响和处理建议，不把无法核验直接当成患者事实错误，也不自动改写正文。
- [x] A6：Web/DSH 编辑器、签署对话框及 Agent 签署审阅入口不再显示自动记录独立的“尚未核对”“发现疑点”“语义核对暂未完成”及其计数、来源原文或核对专用重试。自动记录的暂停、恢复、补录和真实记录失败的重试继续可用，不新增逐条确认、确认保留或签署门禁。
- [x] A7：已有 pending、失败、否定或失效核对记录仍可追溯；旧 outbox 事件明确退役或兼容消费，不成为未知事件、不无限重试、不阻塞其他任务，也不再次请求模型。未执行的检查不能标记为已核验通过；历史状态不再驱动活动计数、独立提示或重试按钮。
- [x] A8：正文、来源、片段归属、人工编辑、幂等和预期版本、暂停、授权、Epoch、任务代次、签署准备冻结及迟到结果保护仍有效。已有已保存内容不重新生成，已有迁移文件及校验和不修改；需要数据迁移时使用前向兼容路径。
- [x] A9：同步实际受影响的 Query/Operation 合同、DSH 模型 schema 白名单、运行时 Skill、命令示例、owner 文档和 Agent Note；仅因兼容保留的字段或事件不再拥有执行核对的入口。不把其他功能的独立核验一起删除。

## 设计决定

来源存在及引用合法性由程序检查；来源是否支持病历含义由病历质控统一检查。取消的对象是自动记录写入后的独立核对，不是质控里的来源语义检查，也不是质控对候选问题的独立复核。质控沿用现有触发与输入复用机制，不为每个自动记录片段增加一套调用链。

变更前后事实与拒绝事实的必要上下文来自受信持久记录及批次快照，遵守本次就诊、授权、版本与输入预算；不为补齐上下文载入全量既往病历，不提高预算或截断证据掩盖检查不完整。具体取舍及对原决策的部分替代由[统一核对提案](../decisions/implemented/architecture/2026-10-19-recording-quality-consolidation.md)拥有。

## 测试策略

Server 纯函数及公开 HTTP/file-backed SQLite 回归验证草稿正文、准确来源、各类程序拒绝、人工编辑保护及每个 schemaName 的实际模型调用次数。使用受控合成 Provider，分别覆盖一个批次保存多个片段、合法空增量、格式修复、失败重试、补录及重复消费，断言自动记录核对请求为零，正常整理请求不随片段数量增加。

兼容回归构造含旧核对记录和 outbox 的非空数据库，覆盖待处理、失败及否定状态、重启和重复消费，验证无模型请求、无永久 pending、无未知事件重试，正文和审计不丢失。质控回归覆盖来源语义不支持、合理时间变化、明确更正、有效旧事实丢失和缺少新依据的拒绝事实重现，同时检查上下文不足时的不完整说明及既有输入预算。

沿用真实病历入口的 Web/DSH Playwright 回归及 React 18/19 共享签署合同，验证独立提示消失、质控问题仍可见、手工编辑和签署行为有效；不只通过删除文案测试来证明后台请求已停止。涉及跨包合同变化时运行对应类型、合同漂移和仓库必要检查；压测和真实模型调用均不在本任务授权内。

## 范围外

- 删除事实来源、句子引用或放宽程序引用校验。
- 删除病历质控、质控独立复核、指南建议核验或其他模型任务。
- 自动修正病历正文、恢复来源查看界面或逐条人工确认。
- 重做质控 UI、模型用量账本、预算、监控仪表盘或模型选择策略。
- 混入 PR #230 的句子编号改动，或追加压测、真实模型评测及未经实测的降本承诺。

## 依赖与风险

方向和交付边界已确认，作为一个独立纵向切片实施，不拆子任务；与[句子编号 PR #230](https://github.com/CaiZongyuan/clinmesh/pull/230)分开交付，整合时以实际主分支合同为准，不反向扩大该 PR。与[模型用量治理 #228](https://github.com/CaiZongyuan/clinmesh/issues/228)目标相关但可独立实施，无外部阻塞。

主要风险是只隐藏 UI 却继续产生后台请求、旧事件恢复时重新唤起核对，以及独立核对特有的旧事实或拒绝事实保护被一并删除。由模型调用计数、非空旧库恢复、明确的规则归属和质控语义回归共同约束。当前记录、质控和签署行为由[临床业务流程](../architecture/clinical-workflows.md)拥有，语义检查合并及历史归属取舍由[统一质控决策](../decisions/implemented/architecture/2026-10-19-recording-quality-consolidation.md)拥有；本规格保留本次交付的独有验收条件。
