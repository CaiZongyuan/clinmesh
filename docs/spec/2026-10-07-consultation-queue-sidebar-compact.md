# 门诊队列侧栏紧凑化

Status: implemented

## 问题与目标

门诊诊疗页左侧队列侧栏固定 240px，且在「在诊/待诊/完诊」分段 tab 之下还有一行「在诊 + 计数」标题行，文字与当前 tab 完全重复。用户反馈侧栏横向占用过大，压缩后可让主内容区（结构化病历等）获得更多宽度。

目标：侧栏压缩到 200px，删除重复标题行，卡片密度收紧，信息零丢失。

## 范围

- `DoctorWorkspaceLayout` 桌面双栏网格的队列列宽（240px → 200px）。
- `DoctorQueueModule`：删除「在诊 + 计数」标题行，计数徽章并入 tab 行右侧（可访问名称「{count} 例」）。
- 病例卡片密度：头像 36→32px、内边距 12→8px、最小高 80→64px、卡片间距与列表内边距收紧。
- 不改变：病例选择、分页、完诊流程、窄屏（<720px 容器）队列/详情切换模式、数据流与接口。

## 验收条件

- [x] 桌面宽度（≥1024px 视口）下队列侧栏列宽不超过 200px。
- [x] 不再存在「在诊 + 计数」独立标题行；计数在 tab 行内且具有可访问名称。
- [x] 卡片仍显示姓名、性别年龄、主诉、状态徽章；超长文本沿用截断规则，无横向滚动。
- [x] 既有行为不受影响：病例可选（可访问名称不变）、tab 切换、分页、窄屏往返全部通过既有测试。

## 设计决定

- 2026-10-07 与用户通过可视化对比页（`queue-sidebar-options.html`，会话临时产物，不入库）确认：两行都压 + 侧栏 200px（备选 176px/保持 240px 未采用）。
- 删除标题行的依据：标题文字与当前视图 tab 完全重复；计数以徽章并入 tab 行，信息不丢失。
- 用户指示：在头部紧凑化同一分支（`feat/consultation-header-compact`）交付，不另开 Issue；本 spec 为唯一正式需求记录。

## 测试策略

- 组件单测 `doctor-queue-module.test.tsx`：标题行不存在、计数徽章与导航同处 tab 行、病例按钮可访问名称不变、桌面网格列宽 200px；先行失败再实现。
- e2e `doctor-checklist.spec.ts`：桌面宽度循环内新增「队列侧栏 ≤200px」断言，作为布局合同。

## 范围外

- 卡片信息结构、队列排序、分页逻辑、完诊清单与诊疗流程。
- DSH 宿主的会话侧栏（另一套界面）。

## 依赖与风险

- 无外部依赖。风险：200px 下长姓名截断增多——沿用截断 + `title` 提示既有规则，可视化对比页已用 7 字姓名验证可接受。
