# 医生补充来源与全病历自动整理

Status: implemented

实施跟踪：[Issue #177](https://github.com/CaiZongyuan/clinmesh/issues/177)。本文件拥有该切片的来源、自动写入、人工保护和验收合同；整体产品范围由[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)拥有。

## 问题与目标

只依赖患者回答无法覆盖整份病历。医生在助手聊天中明确补充的查体、判断及安排，以及本院已发布报告，需要进入同一整理流程，减少重复录入。

目标是复用现有持久整理任务，综合患者问诊、医生明确补充和当前病例的授权公开报告，持续整理十个病历字段。通过来源与独立语义校验的内容直接更新草稿；人工正文保留，更正与矛盾另行追加并保留待核实措辞。交互沿用[病历字段补齐与问诊自动记录](2026-10-14-clinical-document-fields.md)。

## 范围

- 覆盖 DSH 当前医生病例的问诊与病历记录共享页面，不另建聊天 Agent 或后台运行器。
- 输入包括已保存患者文字回答、医生在当前病例的真实助手输入中明确提供的信息，以及当前病例已发布的报告文本。只保存相关原始来源，不复制整个 DSH Session 或 Assistant reasoning，不读取隐藏病例答案或影像像素。
- 字段覆盖主诉、现病史、既往史、家族史、过敏史、体格检查、辅助检查、评估、处置和随访。体格检查须有医生明确提供的依据；评估、处置和随访只整理医生明确表达或已采纳建议，不由患者提问或模型猜测生成。患者自述的居家测量、外院结论与本院报告保持来源区别。
- 当前新病例默认启用整理，跟随新的合法来源更新。已有历史但未启用整理的病例沿用显式首次补录，不因打开页面隐式重处理旧对话。
- 页面显示正文、变动提醒与异步核对状态，不提供待处理建议和撤销入口；页头继续提供紧凑状态、暂停、恢复、补录和重试。来源、历史归属及审计保留在后台。

## 用户故事

1. 作为医生，我希望患者问诊与我向助手补充的信息进入同一份病历草稿，减少重复录入。
2. 作为医生，我希望有依据的新增、补充和明确更正自动写入，不必逐项点击应用。
3. 作为医生，我希望已保存和未保存的手改保留，更正与矛盾另行记录。
4. 作为医生，我希望发生变动的字段提醒我查看，来源与审计保存在后台。
5. 作为医生，我希望暂停只停止整理，恢复后处理期间保存的来源，失败不影响问诊。
6. 作为医生，我希望签署固定已预览的正文和来源快照，签署后文书保持不可变。

## 验收条件

- [x] A1：通过确定性来源校验的内容直接写入草稿，独立语义核对异步执行，无须逐条应用或核对；变动字段按既有可见性规则提醒医生。
- [x] A2：十个字段均支持整理与后台来源关联。体格检查、评估、处置、随访不能仅由患者自述或 Agent 推测生成；家族史、过敏史独立分类，缺失的信息保持缺失。
- [x] A3：真实医生助手输入无须任何主会话 Tool 调用即可持久保存并排队；讨论、拟问题、假设或教学请求可得到空增量，不变成患者事实。
- [x] A4：医生来源绑定原生输入、Session、RPC、消息身份、原文 hash 与原病例锚点；仅凭浏览器申请的 permit 不得入库。同病例普通更新允许继续，换病例、身份、Session、Epoch 或切走后返回不能接受旧来源。
- [x] A5：同一医生输入重新申请 permit、重复提交或服务重启不重复来源、任务或正文；失败事务不保留部分写入。
- [x] A6：报告引用固定已发布版本并使用实际报告内容，不用卡片标题代替报告事实；后台来源区分患者回答、医生补充和报告，页面不增加来源入口。
- [x] A7：模型不能将草稿正文、Agent 建议或隐藏资料当作新的事实来源；逐字引用归属与语义忠实性分别核验，否定核验不触发格式修复来改变结论。
- [x] A8：自动更新仅替换有效自动目标片段，保留人工内容；人工片段更正另行记录，事实矛盾保留原文并追加带来源和待核实措辞的总结，不形成待采纳建议。
- [x] A9：后台更新、轮询、保存回执和病例切换不丢失未保存输入；首次自动创建草稿保留未涉及字段的预填，显式保存的空字段不被重新填回。
- [x] A10：来源、片段归属、处理状态和历史拒绝及逆操作持久化；升级保留原任务身份和人工内容，不恢复历史已拒绝的旧证据，当前界面不提供逐条撤销。
- [x] A11：暂停期间合法来源继续保存，恢复按同一队列补录；失败可观察与重试，模型选择、代次和失败恢复由[低延迟记录规格](2026-10-15-low-latency-document-recording.md)补充。
- [x] A12：签署准备使在途结果失效并禁止整理写入；取消或过期恢复未完成来源但保留显式暂停，已签文书不可变。只有医生补充的病例同样固定来源快照，不要求额外核对勾选。
- [x] A13：后台整理与状态更新不抢焦点、不逐次在聊天播报。中英文、应用字号和窄 DSH 分屏下正文与操作可达，变动提醒和签署符合 React 18/19 ShadowRoot 合同。
- [x] A14：公开 HTTP、真实 SQLite 与 Query 证明跨来源整理、权限、幂等、重启、并发手改、病例切换与签署；实际 DSH 入口证明右侧医生补充可独立触发左侧自动整理。

## 设计决定

本切片复用统一来源与任务，取代[字段内建议规格](2026-10-13-consultation-field-suggestions.md)的全部内容先应用方式；当前交互沿用直接记录、无来源界面、字段变动提醒与未保存输入保护。正式诊断、医嘱、处方及病历签署仍由医生确认。

签署在后台固定 Consultation 版本和来源快照，防止预览后新增来源被忽略，不引入医生核对门禁。未启用整理、没有问诊或医生补充的旧病例仅保存原始报告快照时，沿用原报告已阅与兼容签署合同。

ClinMesh 继续拥有来源验证、病历整理、共享 Command、持久任务、版本、幂等和审计；DSH 提供模型能力与原生输入证明。医生补充作为独立整理来源保存，不伪装成发给患者的问题，也不影响患者待回答状态。来源保存与任务/outbox 同事务提交，患者、医生和报告复用同一顺序处理机制。

医生输入的短期证明与 Tool 执行、代问许可相互独立，不消费或扩大原任务权限。真实输入和 permit 到达顺序均可配对，正常聊天结束不删除已接受来源；取消、丢弃和卸载清理尚未接受的输入。来源写入前重新核对当前认证与原病例锚点，不能靠 Command 幂等回放跳过授权。

自动整理保留原始时间、否定、程度和不确定性，患者自述不能转换为本院客观检查。已有自动片段的明确更新可以定向替换并保留逆操作；人工片段受到保护，更正与矛盾另行追加待核实内容。更新草稿不自动采纳新的诊疗建议。

来源归属和输入证明见[统一来源决策](../../.agents/notes/implemented/architecture/2026-10-14-doctor-full-document-recording.md)；十字段、直接记录和迁移兼容取舍见[整合决策](../../.agents/notes/implemented/architecture/2026-10-15-unified-direct-document-recording.md)。

## 测试策略

主要 seam 沿用公开问诊/录入 HTTP、病例 Query、共享 Command 与 file-backed SQLite，只替换外部模型网络边界。覆盖十字段、三类来源、非法与不忠实输出、重复/乱序、暂停恢复、重启、并发手改、历史拒绝、两分支非空迁移、签署准备和 Epoch reset。

DSH 输入证明用真实原生 inbox 生命周期及 Host HTTP seam 验证，无 Tool 也能保存来源，伪造正文、Session、RPC、页面绑定和过期凭证被拒绝；客户端测试同时覆盖原始提交正常退休与病例切换取消。原生宿主旅程从右侧聊天发送合成医生信息，通过左侧病历与服务端 Query 观察真实结果。

Playwright 从真实问诊与病历入口验证自动正文、人工输入保留、十字段、无来源入口、变动提醒、暂停与签署，覆盖 React 18/19 ShadowRoot。常规 CI 不依赖真实模型密钥或付费调用；不读取影像像素或截图。

## 范围外

- 语音识别、附件解析、Mobile 入口改造和独立自主仿真 Agent。
- [#178](https://github.com/CaiZongyuan/clinmesh/issues/178) 的四项独立质控及其签署前汇总。
- 生成新的诊断、检查和处方建议；该能力由[诊疗建议规格](2026-10-13-doctor-guideline-recommendations.md)拥有。
- 自动正式确认诊断、开立检查、提交处方、写入正式过敏记录或签署病历。

## 依赖与风险

[#176](https://github.com/CaiZongyuan/clinmesh/issues/176) 的当前病例读取和可信输入基础、[#172](https://github.com/CaiZongyuan/clinmesh/issues/172) 的自动记录组合验收均已合入主线。复用已有 DSH 模型桥接与字段内布局，不等待 #178 或重新建设运行器。

引用归属校验不能单独保证医学语义正确；独立核验、人工正文保护与明确的不确定性约束写入。统一来源迁移须保留旧任务身份、引用、模型绑定、人工归属、拒绝与逆操作历史，跨包/CLI 合同变化在同一 diff 同步 Operation Catalog、运行时 Skill 与漂移测试。

旧已启用病例优先恢复原任务的完整上下文及 Grant；缺少可恢复上下文时，通过明确的 `requiresContextBinding` 状态和现有受信激活入口恢复当前医生绑定，保留暂停、失败及控制版本。首次打开自动尝试，失败可重试；既有未启用历史仍由医生明确首次补录。
