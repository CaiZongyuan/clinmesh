# 新安装自动准备完整 DRG 参考资料

Status: implemented

## 问题与目标

现有离线清单能够核验本地资料，但新部署无法仅凭代码取得这些资料。新用户沿用正常安装及启动流程后，应自动拥有与固定清单一致的五目录 r3 与 OpenDRG 2026-10-20 完整资料，不需要向其他人索取文件、选择本地目录或单独执行导入。

## 范围

正常安装沿用 `.env.example` 的参考数据库配置；显式移除该配置的合成 fixture 模式继续跳过参考资料准备，不宣告 DRG 已就绪。

- 提供与仓库锁定哈希一致的固定版本资料包和自动获取入口；资料正文不提交 Git。
- 接入已有参考数据同步、独立 Server、DSH 和局域网准备流程；生产部署使用同一校验逻辑，资料由 Server 部署持有。
- 复用已有完整的当前精简资料，补齐缺失或损坏的自动安装资料，保留原始来源、单位、覆盖、缺参及隔离状态；储存格式由[精简规格](2026-10-25-drg-compact-storage.md)约束。
- 下载、解包、完整性核验和不可变清单登记完成后才报告就绪；失败保留既有资料与清单。

## 用户故事

1. 作为首次安装者，我希望正常安装启动时自动取得完整 DRG 资料，以便不需要人工复制开发者的本地文件。
2. 作为已有部署的维护者，我希望完整资料直接复用，缺失资料自动补齐，失败不破坏现有数据。

## 验收条件

- [x] 空数据目录能够从固定分发源取得完整两包，管理员清单回读与锁定资料一致。
- [x] 现成完整的当前精简两包直接复用；重复准备不重复下载，不覆盖不可变清单。
- [x] 已有临床参考目录但没有 DRG 资料时，正常准备仍安装 DRG，不被临床目录就绪判断跳过。
- [x] 哈希失配、下载失败、缺文件、错误版本、越界路径或危险归档条目均不产生假就绪或部分发布。
- [x] 自动安装目录损坏后能够重新获取；获取失败保留已有文件和数据库。
- [x] check-only 不写正式数据库、资料安装目录或正式审计。
- [x] 仓库快速开始、DSH 准备和生产部署说明包含自动准备行为及首次联网要求，不要求人工提供文件。

## 设计决定

继续使用已有离线资料清单作为内容身份与完整性依据；分发包另锁定下载地址、字节数与 SHA-256。安装阶段下载到临时目录，拒绝路径穿越及链接，逐包完整校验后安装和登记。Server 请求处理阶段不访问分发源，也不执行第三方包内程序。

本次用户授权覆盖创建执行 Issue 并完成整项任务；执行以一个集成 PR 交付，不拆分独立业务功能。

## 测试策略

公共入口为参考资料准备函数、现有 `reference:sync`、开发及部署准备 CLI 和管理员清单查询。使用合成资料、临时 SQLite 和受控本地 HTTP 测试首次获取、重复复用、失败保旧、归档约束和 check-only；另外使用真实固定资料在仓库外的空目录验证完整获取及重复准备。不开启真实模型或负载测试。

## 范围外

患者 DRG 分组、编码适配、处方预算、支付计算、真实医保结算及新的业务页面不属于本次交付。自动取得资料不改变 `offline-review`、`integrity-only` 和 `runtimeEnabled=false`，不把缺失参数补成可用参数。

## 依赖与风险

固定快照不能仅凭上游网页重建：五目录包含本地整理和复核结果，OpenDRG 来源网页也会变更。需要提供精确快照分发，下载失败必须明确阻止资料准备成功；既有使用条件和算法适用性待核验状态继续保留。
