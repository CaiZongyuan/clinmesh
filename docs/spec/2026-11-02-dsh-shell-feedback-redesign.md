# DSH 外壳、交互反馈与助手呈现优化

Status: approved

## 问题与目标

[工作台扁平卡片重构](2026-10-30-workspace-card-redesign.md)验收后，在隔离原生 DSH 宿主和 standalone Web 中逐岗位复审，发现以下问题：

- 外壳层级过多：页头、流程线、患者卡、页签和环节标题叠成三层导航；队列卡、主区和右栏不撑满高度；底部操作栏横跨整屏，状态文字离主按钮太远。
- DSH 宿主 1280 宽时 Surface 约 826px，右栏折到主区下方，编辑区只剩约 300px；宿主对话区加上 Surface 右栏，在屏幕上形成四栏。
- 交互反馈弱：提交中只变灰；选中态和悬停态难以区分；成功后跳到空白；Toaster 已挂载但几乎不用。
- 住院号等长编号整串外露，挤占患者头部。

目标是以 DSH Surface 的实际宽度为基准重排外壳，standalone Web 沿用同一布局；右栏并入主卡头部（方案 A），助手内容集中呈现；每个提交都有进行中、完成和受阻的明确反馈。

设计依据是两份使用合成数据的可交互原型：一份覆盖 DSH 外壳以及门诊医生、分诊、住院医生页面，另一份覆盖住院七个岗位。原型只作为设计参考，要求以本规格为准。

## 范围

- **平台：** DSH Surface 为设计基准，standalone Web 使用同一套布局和组件。Mobile 不在范围内。
- **外壳与交互反馈：** 覆盖全部岗位页面。
- **页面内容按原型重排：** 门诊医生、分诊护士，以及住院登记、病区护士、住院医生、住院收费、住院药房、病案、医保核定。
- **只换外壳与反馈，内容不变：** 挂号员（门诊侧）、门诊收费员、门诊药师、模拟数据、设置。
- **宽度基准：** 宿主 1600 → Surface ≈1101px；宿主 1280 → Surface ≈826px。

本规格取代旧规格中关于右栏的条款：

- [工作台扁平卡片重构](2026-10-30-workspace-card-redesign.md)：用户故事 24、画布三栏与「右栏移到主区下方」、各岗位「右栏显示…」条款。
- [AI 原生医生工作台改版](2026-10-19-ai-native-doctor-workspace.md)：A1、A2、A4、A7 中「Agent 建议栈」作为独立右栏的位置要求。建议栈的数据来源不变，仍是确定性服务。

## 用户故事

1. 作为任何岗位的使用者，我希望一条顶栏同时看到页面名、当前患者、办理流程和助手状态，以便少看一层导航。
2. 作为在 1280 宽 DSH 宿主中工作的医生，我希望编辑区不被右栏挤到 300px，以便正常书写病历。
3. 作为使用者，我希望主按钮就在状态文字旁边，不可点时直接写出还差什么，以便知道下一步。
4. 作为使用者，我希望点了提交后看到转圈和「正在…」，办完原地看到结果和下一步，以便确认操作生效、不重复点击。
5. 作为医生，我希望在患者头部的一行里看到助手准备了什么（几条诊断建议、几条检验建议、几个质控待核实、哪些还在生成），点一下就到对应页签，以便不依赖右栏也不漏看。
6. 作为医生或护士，我希望助手准备好需要我确认的内容时，原位出现蓝色确认条，由我点确认，以便清楚哪一步是我做的决定。
7. 作为病区护士，我希望检查检验结果连同参考范围出现在患者头部，以便执行医嘱时随时对照。
8. 作为住院收费员，我希望出院补交到结算的每一步都能看到当前在哪一步，以便不漏步。

## 验收条件

### 外壳

- [ ] Surface 顶部是一条 48px 顶栏，从左到右依次是：队列收起按钮、页面名、当前患者、办理流程、助手状态、人物菜单。原来的页头和流程线不再单独占行。
- [ ] 流程放不下时，只显示圆点和当前环节名，后面标「n/总数」；悬停圆点显示环节名。
- [ ] 画布只有「队列卡 + 主卡」两张卡，都撑满可用高度，内容在卡内滚动。队列卡可以收起，收起后主卡占满。
- [ ] Surface 窄于 800px 时：
  - 队列默认收起，主卡占满宽度。
  - 点顶栏的队列按钮，队列以浮层盖在主卡左侧；选中患者、点浮层外或按 Esc 后收起。
  - 队列不再叠到主卡上方。
- [ ] 主卡从上到下依次是：患者头部、页签、内容区、操作栏。原来独立的患者卡并入主卡头部。
- [ ] 操作栏在主卡底部：左侧是状态文字，右侧是主按钮。全页只有一个主按钮；内容区的按钮都是自适应宽度的描边或无边框按钮。
- [ ] 主按钮不可点时显示为虚线框，状态文字写「还差：…」；提交中的主按钮显示转圈和「正在…」，两种状态外观明显不同。
- [ ] 住院号等长编号只在患者头部显示，中间截断，悬停显示全文，可以复制；队列中只显示尾号。
- [ ] 1101px、826px 和 760px 三档宽度、浅色和深色两种主题下，都不出现横向滚动、文字被裁切，或按钮内单字换行。

### 浮层底色

- [ ] DSH Surface 中的浮层底色不透明，浅色为 `#ffffff`，深色为 `#353638`。浮层包括人物菜单（岗位切换）、下拉菜单、Select 选项、Dialog、AlertDialog、Sheet、Toast，以及医生页的目录选择对话框。不再沿用宿主半透明的 `--dsw-specific-menu`，也不加磨砂。
- [ ] standalone Web 的浮层外观不变。

### 右栏并入主卡（方案 A）

- [ ] 所有岗位都不设 Surface 右栏。原来的右栏内容按下面的方式并入主卡头部：
  - 门诊医生：生命体征是一个事实标签；完诊清单是一个可展开的标签，显示「完诊清单 n/7」，展开后每项写明分区名，点击可跳转。
  - 病区护士：已出的检查检验结果连同参考范围显示为结果标签，超出范围的标出。
  - 住院医生：临床提醒显示为一行事实，例如「等病区护士校对 2 条医嘱。」；没有提醒时不占行。
  - 病案：DRG 复核是主区内的第一张内容卡。
  - 门诊收费员的支付尝试记录、分诊的风险信息等其余右栏内容，改为患者头部的事实标签或内容区内的卡片，信息不丢失。
- [ ] 窄宽度时不再需要「右栏移到主区下方」或「资料」抽屉。

### 助手呈现

- [ ] 有规格列出的助手能力的岗位，患者头部显示「助手已准备」行，每项写明条数或状态，点击跳到对应页签：
  - 门诊医生：诊断建议 n、检验建议 n、质控待核实 n、病理会诊「生成中」、处方「确认诊断后生成」。
  - 病区护士：医嘱校对 n 条 · 等你确认。
  - 住院医生：报告已阅 n、DRG 预分组、耗材预计「生成中」。
  - 住院收费员：出院补交收款预览、结算预览。
- [ ] 没有可处理项时，助手行写明原因（例如「确认诊断后生成」）；没有助手能力的岗位（住院药房、病案、医保核定、住院登记）不显示空的助手行。
- [ ] 页签名旁的蓝色「助手 n」标签表示该页签内的助手建议条数，和黄色的待办数分开显示。
- [ ] 助手建议在原位出现：诊断页是「待确认诊断」块，检验检查页是「待开具检验」块；质控待核实挂在对应字段下方，并带「查看依据」入口。数据来自现有建议与质控服务；某一项生成失败时，写明是哪一项没生成。
- [ ] 助手填写字段时，顶栏助手状态显示正在做什么（例如「助手正在填写 体格检查…」），主卡出现蓝色柔光；填完后字段带「助手」标记和「依据」入口。
- [ ] 助手准备好需要人确认的内容时，操作栏变成蓝底确认条，并排显示「不采用」和确认按钮（例如「确认校对 2 条」「确认已阅」）。确认后的内容带「助手」标记；被准备的行显示为虚线蓝框。
- [ ] 助手相关的颜色一律用蓝色 token，不使用紫色。

### 交互反馈

- [ ] 每个提交主按钮都有进行中状态：按钮转圈，内容区变暗且不可编辑，状态文字写「正在…」。
- [ ] 成功后不跳到空白页：原位显示只读结果，流程圆点前进并闪动一次，右下角提示条写明结果和交给了谁，操作栏给出下一步（例如「下一位：李建国」「继续登记下一位」）。
- [ ] 处理完的队列行带过渡动画移出，自动选中下一条。
- [ ] 队列选中行是浅蓝底加蓝边，悬停只是浅灰；选项按钮选中后整块变实心并带勾。
- [ ] 系统设置为减少动态效果时，以上动画全部关闭，状态文字照常显示。

### 住院页面（按住院原型）

- [ ] 每个环节第一行写「轮到你：…」，或「等〈谁〉〈做什么〉」，右侧是办理顺序，本岗位那一步加粗。宽度不够时，办理顺序整体换到第二行。
- [ ] 住院登记：挂号员队列卡切到「住院」后，上面是待转收的门诊住院证，下面是今日已登记。门诊住院证转收与直接入院用同一张表单，转收时住院证内容只读展示。
- [ ] 病区护士：
  - 队列：新入院置顶；床位写「轮到你 n 项」；空床写床位费；召回窗口和出院后病历固定在底部。
  - 接诊分床使用床位网格，已占用的床位不可选。
  - 清床后，该床位在队列里变为空床。
- [ ] 住院收费：出院页签顶部显示六步进度（出院补交、预览收款、确认收款、预览结算、确认结算、等护士清床）。宽度不够时，只显示当前步骤的名称。收款后，队列和患者头部的「需补交」同步变化。
- [ ] 住院药房：沿用现有流程，没有药师审核。护士校对后进入队列，药师核对批次和数量后发药。发药后该行移出队列，自动选中下一条；队列清空时写明「护士校对医嘱后会自动进入这里」。
- [ ] 病案：编码审核通过或归档后，队列筛选跟随到该病案所在的分类，当前病案不会从列表消失。
- [ ] 医保核定：主区先显示归档时的分组与费用（只读），再依次「审阅模拟核定」→ 填写核定说明 →「提交模拟核定」；提交后记录出现在「历史核定」。

### 不回归

- [ ] [工作台扁平卡片重构](2026-10-30-workspace-card-redesign.md#状态与回归)列出的门诊、住院门禁和各内容卡状态要求全部保持。
- [ ] Agent 工具、Command 状态机、服务端合同和 `clinmesh-*` Skill 不因本次布局调整而改变。

## 设计决定

- 外壳以 DSH 布局为主设计，standalone Web 跟随（2026-11-02 用户决定）。
- 右栏采用方案 A，即「并入主区 + 助手行」，所有宽度一致（2026-11-02 用户决定）。
- 助手呈现、交互反馈和住院七个岗位的页面以两份原型为准（2026-11-02 用户确认「都挺好的 就按这个来」）。原型中标「待确认」的项随这次确认一并采纳：分诊成功后不跳空、住院号中间截断、页签「助手 n」标签、助手实时状态文字。
- 视觉基线沿用卡片重构：扁平卡片、中性主按钮、蓝色只表示交互、焦点、选中和助手参与；文案沿用[住院文案与助手话术](2026-10-30-workspace-card-redesign.md#住院文案与助手话术)。
- 浮层底色改为不透明，不跟随宿主的半透明加磨砂（2026-11-02 用户决定）。理由：与扁平卡片风格一致，且无论背后是什么内容都看得清；磨砂的对比度取决于背后内容和浏览器效果，不稳定。
- 住院药房不加药师审核，与现有代码一致（2026-11-02 用户决定）。本条更正[工作台扁平卡片重构](2026-10-30-workspace-card-redesign.md)中「住院药房……包括审核」的写法。以后如需增加审核，另立需求。
- Surface 窄于 800px 时，队列改为收起后按需浮层打开，取代现在「窄于 600px 时队列叠在主卡上方」的做法（2026-11-02 用户决定）。理由：主卡至少要留约 520px 才能正常编辑。
- 外壳组件归属沿用卡片重构的「业务组合组件」决定，放在 Web 应用内部，不进入共享 views 包。

## 测试策略

- **主入口：** Web Playwright E2E。扩展现有卡片工作台回归（`doctor-workspace-card.spec.ts`、`inpatient-card-workspaces.spec.ts` 等），在 1101px、826px 和 760px 三档容器宽度下断言：
  - 顶栏结构与流程收起后的形态；
  - 不存在右栏；
  - 760px 时队列默认收起，浮层打开后选中患者会自动收起；
  - 主按钮的不可点、提交中、完成三种状态；
  - 成功后的原位结果和下一步按钮；
  - 助手行条数与跳转。
- **DSH Surface：** 浏览器合同测试覆盖顶栏和助手确认条。另加一条测试：注入宿主半透明的 `--dsw-specific-menu` 后打开人物菜单，断言菜单的计算背景色不透明（alpha 为 1）。这条测试必须能在当前代码上失败。对话框类组件继续纳入 React 18/19 双版本合同测试。
- **文案：** 沿用 `inpatient-visible-copy.test.ts` 的禁用词检查，覆盖新增文案。
- **真实入口验证：** 隔离原生 DSH 宿主在 1600 和 1280 两档、浅色和深色主题下逐岗位截图核对；只使用合成 Provider 和临时数据库。

## 范围外

- Mobile 端。
- 新增 Agent 工具，或改变现有工具的 schema、门禁与审计。
- 住院药房增加药师审核。
- 按需给药理由、停嘱、退费确认、转床等交互的细化：沿用现有功能，只换外壳。
- 收费员、药师、挂号员门诊侧的页面内容重排。

## 依赖与风险

- 本规格在 `feat/workspace-card-redesign` 合入后实施。该分支在 `packages/ui/src/styles.css` 中把 `--popover` 映射到宿主半透明的 `--dsw-specific-menu`（浅色 `#f8f9fa94`、深色 `#43454a73`，宿主自己的菜单靠 `blur(40px)` 补上可读性），导致 DSH 中所有浮层半透明。浮层底色的修复属于本规格，见验收条件。
- DSH Surface 宽度随宿主对话区宽度变化。容器查询断点要以实测 Surface 宽度为准，不能以视口宽度为准。
