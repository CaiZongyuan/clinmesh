# 住院线结构重构（第一批）

Status: approved

## 问题与目标

住院线 7 个岗位界面以表格与下拉为主，床位状态、班内任务和流程门禁不直观；医保办（medical-insurance）角色登录后渲染空白页，DRG 支付模拟核定等已有服务端能力没有界面入口。

目标：按岗位工作台重组住院线界面，补齐后端已备的缺失 UI，使登记、护士、医生、药房、收费、病案、医保办在真实数据下获得与岗位任务匹配的布局与交互，且不回归住院闭环的任何门禁行为。

> 2026-10-26：原"纸张编辑风"视觉方案经用户确认否决并已剥离；本 spec 收窄为结构与信息组织部分，视觉语言继续沿用"方向四"。

## 范围

- 岗位：住院登记、护士站、住院医生站、住院药房、收费结算、病案、医保办；交付 standalone Web 与 DSH Surface 双端。
- 补齐后端已备的缺失 UI：病区一览板床位格、召回窗口入护士站、住院医生站 DRG 预分组卡、病案队列视图、欠费预警横幅、待接诊横幅、+1 天虚拟时间快捷入口、医保办 DRG 支付模拟核定 UI。
- 住院医生站右栏「临床提醒聚合」：当前选中患者的欠费、术前核对未完成、待校对/待执行医嘱。

## 用户故事

1. 作为护士，我希望在病区一览板上看到床位格与患者状态 chip，以便直接发现危重、待接诊与出区未结算患者并就地转床或召回。
2. 作为住院医生，我希望右栏聚合当前患者的欠费与医嘱、术前待办，以便开医嘱前看到门禁与风险。
3. 作为医保办人员，我希望登录后看到核定队列与 DRG 支付模拟核定页，以便执行核定并回查历史记录。
4. 作为登记员，我希望直接入院与门诊转收在同一界面完成，以便两条入院路径一致受预交金与床位互斥门禁约束。

## 验收条件

- [x] 住院 7 岗位界面交付；门诊各页面视觉保持现状不变。
- [x] 护士站一览板以床位格呈现占用/空闲与状态 chip，占用格可进入患者页转床；待接诊横幅与召回窗口（出区未结算、原床保留）在护士站可见，出区清床后患者入「出院后病历」区保持只读回查；召回动作由住院医生执行，沿用服务端 inpatient-doctor 授权。
- [x] 住院医生站为患者列表、工作区、右栏三栏；右栏按当前患者显示真实欠费、术前核对未完成、待校对/待执行提醒，无提醒时显示空态，不显示虚构建议。
- [x] medical-insurance 角色登录后呈现核定队列与核定页，可执行 DRG 支付模拟核定并回查历史核定记录，不再渲染空白。
- [x] DRG 预分组试算卡在住院医生站可见，调用既有 `/drg/pregroup`、`/drg/simulation`。
- [x] 病案岗位呈现按整理状态筛选的病案队列；首页四组、编码审核、归档冻结保持既有合同。
- [x] 危急值确认、体征网格、病程时间线、住院 Agent 执行回执抽屉不出现在界面，且不留空壳。
- [x] 既有住院闭环门禁全部不回归：校对→发药→给药、手术四步门禁、未出院处理不能结算、未结算不能清床、清床后床位可再次分配、归档冻结。
- [x] DSH Surface 住院页与 standalone Web 一致呈现；`pnpm --filter @clinmesh/dsh-web build` 通过 verify-artifact 体积关卡。

## 设计决定

- 聚合层在前端实现：TanStack Query 按患者复用既有 queryKey（admissions、clinical、surgeries）拼装提醒与护士任务视图，不新增后端合同或聚合端点。
- 右栏只呈现平台已有事实，不引入门诊式 recommendation 合同，不显示虚构建议；Agent 建议与执行回执抽屉本期不进入住院线。
- 召回沿用服务端授权（仅 inpatient-doctor）：护士站呈现召回窗口信息与去向指引，不提供越权入口。
- 登记护士医生跨岗位联动沿用现有 Command 与合同，界面重组不复制状态机。
- 视觉沿用共享语义 token 与"方向四"语言（[UI 设计合同](../ui/design.md)），不为住院线另立主题作用域。

## 测试策略

- 静态与单测：`pnpm typecheck`、`pnpm lint`、相关包 vitest。
- 浏览器：`pnpm test:e2e`（apps/web/e2e 住院链路回归＋新岗位断言 inpatient-bench.spec.ts）、`pnpm test:browser`（React 18/19 双版本合同）；住院共享代码只用两版本共有 React API。
- DSH：`pnpm --filter @clinmesh/dsh-web build`，末步 verify-artifact 体积关卡必须通过。
- 真实入口 Playwright 截图证据：7 岗位主路径，覆盖空态、欠费、待办与门禁拒绝状态。
- 文档：`pnpm verify:docs`、`pnpm docs:check`。

## 范围外

- 全站视觉风格重定（原纸张编辑风方案已否决，含其 token 作用域机制）。
- 门诊线界面重构。
- 危急值确认工作流、体征（vitals）实体、病程记录（progress note）、住院 Agent 工具与回执数据源、跨患者只读聚合端点——平台均无对应能力，另行立项。
- 一切后端合同、Command、审计与授权变更。

## 依赖与风险

- dsh-web 产物体积：当前产物约 3.57MB，正式预算 5,000,000 字节；结构组件增量已验证在预算内。
- 聚合为前端按患者逐个查询，仅适配病区规模；在院患者数显著增长时需另立聚合端点。
