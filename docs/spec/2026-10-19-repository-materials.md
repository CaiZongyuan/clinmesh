# 共享工程资料与本机 Agent 目录分离

Status: implemented

## 问题与目标

仓库将共享决策、开发 skills 和本机工具入口放在相近目录，难以判断哪些内容应同步。用户要求忽略 `.agent/`、`.agents/`、`.claude/` 和 `previews/`，不共享开发 skills，并把需要共享的工程资料及模板放入 `docs/`。参考 Bio Discovery X 将本机 Agent 配置与共享工程文档分离的布局，保留 ClinMesh 已有需求和决策合同。

## 范围

- `.agent/`、`.agents/`、`.claude/`、`previews/` 由仓库忽略；已跟踪的本机 skills、别名和预览停止 Git 跟踪，保留本地文件。
- 原 `.agents/notes/` 的共享决策迁入 `docs/decisions/`，保留 Agent Note 格式、生命周期、完整内容、未提交修改与决策关系。
- 开发 skills 只留本机，不复制到 `docs/` 或其他共享目录；运行时产品 `skills/` 继续同步。
- 项目自有规格、PR、实施 Issue 和 Agent Note 模板从 `docs/` 统一导航，GitHub 固定路径只保留平台所需入口；上游 skill 自带模板留本机。
- 同步项目规则、入站链接及文档/决策校验脚本；可用的本机 skills 按原合同使用，缺少时由仓库流程和原生工具承担，不以本机文件作为唯一共享规则。

## 用户故事

1. 作为维护者，我希望提交共享文档而不上传个人 skills、Agent 配置和本机预览。
2. 作为协作者，我希望从仓库文档找到需求、决策、模板和验证入口，无需依赖某台机器已安装的 skills。

## 验收条件

- [x] 四个目录的忽略规则生效，开发 skills、Claude 别名和预览不再由 Git 跟踪，本机内容仍在。
- [x] 全部原决策有新去向，正文和本任务前已有修改保留，仓库引用与校验入口指向新位置。
- [x] 共享目录没有新增开发 skill 源码，产品运行时 `skills/` 不受影响。
- [x] 开发模板与规格模板在 `docs/` 可达，GitHub PR 模板使用官方支持的路径，Issue 平台入口与正文模板职责清楚。
- [x] 文档检查、决策格式检查和公开文档构建通过；迁移保真、忽略边界与本地文件保留得到核对。
- [x] 同一基线和最终快照完成 Standards／Spec 双轴审查。

## 设计决定

沿用当前 Agent Note 体系，以 `docs/decisions/` 归拢架构、流程和测试等决策，不另建 ADR 制度。工程规则继续由现有 owner 负责；Bio 的目录职责是参考，不照搬其文档数量或产品模块。根 `AGENTS.md` 仍是共享入口，本机开发 skills 是可选能力。

## 测试策略

通过 Git 实际忽略和跟踪查询验证目录边界；逐文件核对决策迁移及本机 skills、别名和预览保留。复用 `pnpm doc-sync` 验证 Markdown、Agent Notes、投影及 VitePress 构建。校验脚本只有路径配置变化，不新增业务逻辑；不运行无关业务测试。

## 范围外

删除本机 skills、配置或预览；安装或升级 skills；改写上游 skill 正文；改变产品运行时技能、安全、业务、FHIR 或数据库合同；清理其他任务 worktree；推送或发布原有未提交内容。

## 依赖与风险

目录搬迁会影响相对链接与硬编码校验路径；已有文件只通过校验后的迁移或取消跟踪处理，保留完整本机输入，不以忽略规则掩盖共享文档缺失。
