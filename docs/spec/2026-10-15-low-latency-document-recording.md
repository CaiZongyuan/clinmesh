# 低延迟病历自动记录

Status: approved

本文定义实时记录的性能目标及已批准的异步写入规则，补充[全病历整理规格](2026-10-14-doctor-full-document-recording.md)与[问诊自动记录规格](2026-10-08-consultation-auto-record.md)拥有；未来语音方向沿用[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)。设计取舍见[增量记录决策](../../.agents/notes/implemented/architecture/2026-10-15-low-latency-document-recording.md)。

## 问题与目标

医生需要正常问诊时病历持续出现新内容，无须使用右侧 DSH 托管问诊或逐条下达记录指令。现有自动记录把全部既有来源发送给模型，串行执行整理与独立语义核对，失败后可能重跑整轮；来源按顺序等待，长模型请求还占用共用 outbox 消费循环。持续输入会形成积压。

目标是降低“已经确认的来源文字保存成功，到对应病历增量持久化并在页面可见”的时间，兼顾持续输入、人工编辑与故障恢复。预期以秒级持续记录替代分钟级整轮等待；不能用转写预览、动画、首个 token 或尚未保存的候选冒充完成。

## 范围

- 自动记录独立于右侧 DSH 会话，统一接收已保存的患者回答、受信医生补充与已公开报告。当前先复用文字来源验证记录速度；本切片不实施麦克风采集、语音识别、说话人识别或音频存储。
- 为未来语音保留确认片段与修订的接入约束：不稳定的中间转写只作临时显示，确认文字才参与记录；文字或说话人修正必须保留旧版本并使依赖旧版本的自动结果重新核对，不能原地改掉已有引用。
- 草稿继续允许不完整，医生手改优先。正式诊断、检查、处方和病历签署沿用原权限与人工确认要求。
- 将独立语义核对移出每次增量写入的等待路径，是已经确认的行为变化。程序可确定的来源、引用、角色、版本、归属与签署检查继续在写入前完成；语义核对尚未完成的增量不得被表示为已通过核对。

## 用户故事

1. 作为医生，我希望正常问诊后几秒内看到新增病历，不必等待整个对话重新整理。
2. 作为医生，我希望持续问诊时记录能跟上进度，一段整理失败不拖住后续全部内容。
3. 作为医生，我希望手动修改、暂停和病例切换仍可靠，有疑点时收到与具体内容相关的提示。
4. 作为医生，我希望右侧助手未参与问诊时也能自动记录，未来语音可接入同一能力。

## 验收条件

延迟数值是验收目标，不能当作已达标证据。固定以单份确认来源不超过 1,000 个汉字、10 个同时活动病例、每病例每 3 秒一份来源的连续 10 分钟负载作为评估基线；长来源与批量历史补录另测，不混入实时延迟统计。

- [ ] A1：对有效且包含可记录新事实的来源，端到端可见延迟 P50 不超过 3 秒、P95 不超过 8 秒。起点为确认来源在服务器保存成功，终点为真实页面读到已持久化的对应增量；分别报告来源丢失、失败及超时，不能只统计最快或成功的小部分请求。
- [ ] A2：持续输入时，将尚未处理的来源合并为有界小批，最长聚合等待不超过 500 毫秒（当前不主动延迟，下一次调度立即固定批次）；不能靠不断重置计时器或取消在途请求拖延处理。所有来源仍分别保留身份、顺序和来源版本。
- [ ] A3：每份来源最终有可查询的处理结果，包括已记录、无新增事实、需核实或失败；空增量不冒充病历更新。批次完成与对应增量在同一事务提交，重复消费及重启不重复写入、不跳过未处理来源。
- [ ] A4：失败限定到有稳定身份及完整引用的独立候选；不合格候选不得写入，互相依赖的更新须保持原子性。可独立成立的其它候选及后续来源继续处理，失败不被错误标记为已完成记录。
- [ ] A5：写入前继续拒绝不存在、错病例、错版本、截断或角色不合法的来源；人工片段与未保存输入受到保护。旧 Epoch、撤销授权、病例切换、暂停和签署冻结均限制迟到结果，已签文书不能被修改。
- [ ] A6：语义核对针对已经保存的确切片段及来源版本异步执行，结果关联片段身份和内容版本；旧核对不得改写新内容。发现疑点时提示相关片段和依据，不自动覆盖医生修改或通过反复询问核对模型得到肯定。
- [ ] A7：实时整理与语义核对、历史补录、建议生成和其它 outbox 事件分开调度，设置有界并发与公平性；慢任务不能独占整个消费循环。同病例原子写入与版本检查继续防止互相覆盖。
- [ ] A8：实时整理具有独立于主会话及重型后台任务的模型配置和总耗时预算。首次尝试与一次格式修复共享最多 6 秒预算，耗尽后保留来源和失败状态供恢复；不能为每次修复重新启动完整预算或自动重跑三轮。服务端取消须传到 Provider。
- [ ] A9：模型输入以新增来源、必要相邻上下文和相关既有事实为主。相关既有事实必须带可恢复的原始引用，支持跨轮指代、否定、更正、旧事实重复及远距离矛盾；不能以截掉所有旧证据换取延迟数字。单次输入预算与超限恢复策略须固定并验证。
- [ ] A10：写入成功后及时通知页面刷新对应 Query，断线后可通过重新读取恢复，不依赖通知恰好送达。页面保持正常编辑与滚动，不逐条播报或强制医生确认每一段。
- [ ] A11：公开状态及签署前展示准确区分记录失败、尚未核对与已发现疑点；不新增逐条确认门禁。现有签署完整性、权限、版本、预览和快照规则继续执行。
- [ ] A12：分别记录聚合等待、调度等待、模型首响应与完整结构化响应、程序校验、持久化、页面可见和异步核对耗时，只保存必要元数据及有界诊断，不把临床原文、提示词或凭证写入性能日志。

## 设计决定

用户已明确的要求是无感录入、速度优先于当前分钟级等待、可用于普通人工问诊与未来语音、独立于右侧托管问诊。本文的延迟阈值、负载基线与模型预算固定如下；先保存草稿并明确显示“尚未核对”，随后异步提示疑点，是已确认的写入方式。

采用统一记录模块：确认来源先持久保存，再按病例合并新增来源，调用一次适合低延迟结构化输出的模型，完成程序可确定的校验后通过共享 Command 写入草稿；语义核对与必要的全文润色另行执行。调用方不分别实现队列、增量合并或来源保护。每批最多 8 份来源、4,000 字；完整固定快照上限 128 KiB，包含全部有效旧事实及其原始引用。超限保留来源与失败状态，不静默截证据；医生可手动完成草稿，修改上下文或模型后显式重试。实时、核对、补录、建议和其他业务各有 10、4、1、1、2 个槽位。页面经有界等待通知刷新 Query，断线重连并以 1.5 秒轮询恢复。

已有来源和事实保留为可追溯的状态；模型任务使用确定的来源范围和版本快照。新来源到达时更新待处理范围，不重跑已经完成的整轮，不无限取消在途工作。批次身份、覆盖进度及失败候选分别持久化，避免把可见进度与事实处理进度混为一谈。

模型传输使用批次内短引用，写入前恢复持久身份并验证。未变化的事实可引用固定目标的事实索引，由服务端保留完整原文与来源；不要求模型每轮重复输出累计事实。未知索引、伪造引用与同一目标的竞争替换明确失败，不影响可独立成立的其他候选。完整快照与异步核对仍保存全部证据。

## 测试策略

通过公开来源写入入口、病例 Query、真实共享 Command 和 file-backed SQLite 测试有界合批、幂等、范围进度、部分失败、跨轮更正、远距离矛盾、并发手改、授权撤销、签署冻结及重启恢复。Provider 替身可控制响应和失败顺序，用来证明调度与保护合同，不用来证明真实模型延迟。

Playwright 从真实医生页面测量已持久化增量可见时间，覆盖 React 18/19 Surface、持续输入、未保存手改及重连。使用合成数据，对固定真实模型及指定负载单独测量端到端分位数、失败率、积压趋势、每病例公平性及有来源事实准确度；与现有流程比较时保持同一数据与计时口径。模型慢于目标时调整模型或部署，不通过仅显示临时文字宣称达标。

未来语音接入另设从说完一句到确认转写、再到病历可见的完整延迟；同时测量识别错误、说话人不确定与转写修订，文字链路成绩不能充当语音链路成绩。

## 范围外

语音设备与识别供应商接入、音频存储、正式业务自动提交、右侧 DSH 问诊托管重做，以及要求每次新增内容都重排润色整份病历。公开界面不恢复已移除的来源浏览器或逐条应用操作。

## 真实性能证据与剩余验收

A1 未通过，规格保持 approved；当前实现不能宣称在该负载下达到秒级目标。输入增长与实时模型容量仍需优化。该轮记录了完整失败分母、积压趋势、各病例结果及异步核对状态，但未做逐项临床语义准确度评分，失败阶段的完整时间分解也未齐备，A12 仍待补齐。合成 Provider 回归只能证明来源、事务、恢复和人工保护合同。

## 依赖与风险

需要实际模型能力满足小批结构化记录的延迟与准确度，两者均不能从模型名称或文本首 token 速度推断。模型选择须兼顾否定、数值、剂量、说话人、条件假设和跨轮更正。

语义核对后移使尚未完成语义检查的内容先进入草稿，必须明确该状态，保留后续问题展示与医生审阅；这不是正确性保证。共享 outbox 的调度调整还须维持现有其它事件的租约、幂等和恢复合同。扩大来源批次与缩小上下文会分别影响失败隔离和旧事实保留，需以组合测试约束。
