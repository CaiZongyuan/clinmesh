# 全站原型偏差收口与住院 AI 融合

Status: approved

## 问题与目标

基于 `origin/main`（`09efb16c`）对全站门诊、住院及管理与设置页面开展逐岗位、逐页签、逐状态原型对照走查，共发现 190 项界面偏差（A 组门诊前台与管理 59 项、B 组门诊医生 32 项、C 组住院非医生与 Surface Toast 77 项、D 组住院医生 22 项），并识别出住院旧 AI 面板硬塞堆叠与 17 项既有原型未覆盖状态：

- **住院 AI 面板与临床主流程割裂**：手术页「术前耗材预计 › 查看与调整」展开后堆叠 4 套复杂子面板（露原始 UUID 与 `v1`），① 选型参数与 ② 手术耗材重复要求填写耗材计划数量，开始手术后仍保持展开，且只要有过已完成造影即在手术页平铺整块「术后核查与责任交接」；DRG 预分组页在开启自动跟进后内嵌整块「手术耗材建议」与「本次住院 AI 用量」大表，分组核对差异与 AI 解释分离且将出院后才能选择的「首页主操作」计入在院待办。
- **门诊前台与管理页缺口（A 组）**：队列读取失败提示被重试按钮挤成单字竖排；挂号成功后跳回空白、建档默认预填 `1990-01-01 / 男` 且切换建档页签不切换主区；分诊完成后直接跳到下一位空表单、已分诊页签选中患者后主区空白；门诊收费在支付被拒绝或结果未知时误弹「收款完成」、队列空时仍挂虚线操作栏、未缴费即显示退费更正入口；门诊药房发药完成后缺少只读处方与批次表、数量堆三行、频次显示英文原码；模拟数据、设置、模型用量与组件目录暴露英文内部术语、多处重复主题切换、缺少虚线不可点与提交中按钮示例。
- **门诊医生工作台偏差（B 组）**：浅色模式 `Badge variant="warning"` 白字对比度不足 4.5:1；队列行与患者头部未按紧凑两行收口；「完诊清单」内联展开撑出内部滚动条、未开检查时默认算已完成；问诊输入框像禁用、结构化病历 10 字段单列堆叠且出现双主按钮、签署后铺开 11 字段修订表单并露 `Encounter`；检验/放射/病理二级页签多出重复黑底添加按钮、无门诊价格的目录项未置灰禁选导致加入草稿后整批锁死、三个开具弹窗高度不足；「完诊」病例库筛选塞进 232px 窄队列并露出 FHIR 资源标识；模型配额用尽时直接暴露内部开发文案。
- **住院七岗位与共享壳层偏差（C、D 组）**：`web-app.tsx` 将 `useRef(null)` 传给 `PortalContainerProvider` 导致 Toast 脱离 `.clinmesh-web-root` 与 DSH ShadowRoot；任意写操作成功后「已完成本次操作」绿色底栏跨页签常驻；已离院/清床/归档患者头部住院天数仍随虚拟时钟递增、双状态徽标并存且缺出院时间与病案号；从「更多」选中低频页签后插入平铺栏导致跳动且下拉菜单内重复残留，医生「入科」页仅重复一句话；病区护士新入院队列行折成 3 行、清床缺少必填理由快捷输入与完成条；住院收费在院患者头部误显「应退」、主流程常驻「合成渠道结果」故障模拟器、资金记录直接输出原始 ISO UTC 字符串；病案队列混入在院患者；医保审核员点击「审阅模拟核定」前被強制要求先填说明。

目标：按用户已确认的 6 套交互原型（总偏差对照页 `2026-11-05-ui-audit`、住院 AI 融合 `2026-11-05-inpatient-ai-fusion` 及四个补缺原型 `2026-11-05-{outpatient,doctor,inpatient,admin}-gaps`），一次性收口全部 190 项界面偏差与住院 AI 融合流程，补齐必要的窄范围服务端投影与选型/耗材合同，使全站 standalone Web 与 DSH Surface 在 `1600 / 1280`（Surface `1101px / 826px`）及浅色/深色主题下与原型完全一致。

## 范围

适用全站门诊四岗位（门诊挂号员、分诊护士、门诊医生、门诊收费员、门诊药师）、住院七岗位（住院登记员、病区护士、住院医生、住院药房、住院收费员、病案管理员、医保审核员）以及 standalone Web 管理与设置页（模拟数据、设置、模型用量、组件目录），覆盖 standalone Web 与 DSH Surface（React 18.3.1 / React 19.2）、浅色与深色主题、`1600px / 1280px`（Surface `1101px / 826px`）视口。

1. **住院 AI 融合与手术/DRG 闭环**（含关联服务端合同演进）。
2. **共享壳层、Toast 挂载与定位、徽标对比度及「更多」低频页签导航**。
3. **A 组：门诊挂号、分诊、门诊收费、门诊药师及管理设置页收口**（含已分诊详情服务端投影）。
4. **B 组：门诊医生队列、头部、问诊、病历、检验/放射/病理、诊断、处方、开具弹窗及完诊病例库收口**。
5. **C & D 组：住院七岗位队列、患者头部、各页签结构与办理顺序收口**（含已出院/归档头部字段服务端投影）。

## 用户故事

1. 作为住院医生，我希望在 PCI 手术前按「① 手术计划 → ② 选型参数（靶病变部位、治疗方向、三项病变测量）→ ③ 手术耗材（顶部指南参考与助手预填引语 + 耗材清单确认即占用预留）→ ④ 开始手术还差」的顺序在一处完成准备，不在选型参数里重复填计划数量，也不在 DRG 页看到重复的耗材建议卡，以便 AI 自然融入术前准备流程。
2. 作为住院医生，我希望确认选型参数后若耗材仍在生成中能看到「耗材生成中」并允许先手填，预留耗材后若修改选型测量则保留现有预留、将耗材步退回「待你核对」并仅标出与新测量不符的行，取消手术申请时自动释放已预留耗材，以便安全调整术前方案。
3. 作为住院医生，我希望在 DRG 预分组页直接看到每条分组核对项的绿勾/感叹号状态及行内自动生成的差异说明，「首页主操作」在院期间标为灰圈「等手术完成（出院后在病案首页选择）」且不计入待办徽标，AI 用量收敛为「本次住院 AI 用量」弹窗入口，以便专注盯住费用与实质分组差异。
4. 作为 DSH Surface 或 standalone Web 用户，我希望所有操作 Toast 挂载在 `.clinmesh-web-root` 内部、位于底部操作栏正上方（826px 宽时不遮挡底栏说明与主按钮）、最多叠 2 层（上一条收紧为单行）且标题写明具体动作与对象，以便在宿主与窄屏下获得清晰不挡路的操作反馈。
5. 作为门诊挂号员或分诊护士，我希望建档出生日期与性别、分诊生命体征与分诊级别默认不预填（未填时主按钮虚线不可点并提示还差项），挂号或分诊完成后主区保留只读摘要并提供「继续登记下一位 / 下一位」主按钮，切到「已分诊」页签能回看患者分诊评估详情，以便防呆录入并顺畅衔接下一位患者。
6. 作为门诊收费员或药师，我希望顶栏流程前序已完成步骤统一显示 `✓`，支付被拒绝或结果未知时显示感叹号警示卡并提供「查询原支付结果」而不误弹「收款完成」，缴清或发药完成后保留只读账单/处方批次表并提供「下一位」，用药频次统一显示中文，以便准确核对收款与发药。
7. 作为门诊医生，我希望五个开具弹窗统一 `min(720px, 100svh - 40px)` 双栏高密度布局且未配置门诊价格的项目在左栏置灰禁选并标明原因，检验/放射/病理二级胶囊页签去掉重复标题与多余黑底添加按钮，病历记录采用双列网格，点击「完诊清单」弹出 300px 单行浮层，「完诊」病例库筛选条置于右侧主卡顶部且不露内部英文标识，配额用尽时显示临床友好的降级提示与琥珀色虚线芯片，以便高效完成门诊接诊。
8. 作为住院医护、收费、病案或医保人员，我希望从「更多」选中的低频页签（如 `入科 ×`、`费用 ×`、`病案 ×`）作为临时标签固定在「更多」左侧且下拉内不重复残留，医生「入科」页展示 6 项真实入科事实，已离院/清床/归档患者头部住院天数按出院时间截止（「住院 N 天」）且只显示唯一状态徽标，护士清床提供常用理由胶囊一键填入，收费默认单金额补交并按需展开组合支付，医保审核员先点「审阅模拟核定」进入确认态后再填/选核定说明并提交，以便全院住院流程顺畅一致。
9. 作为使用模拟数据、设置、模型用量或组件目录的用户，我希望全站仅在设置页保留唯一主题切换，时间与金额全部采用中文可读格式，每屏只有一个实心主按钮，且组件目录完整展示主/次按钮的可点击、虚线不可点与转圈提交中三态。

## 验收条件

### 一、住院 AI 融合与服务端合同（D-04、D-12、D-13、D-16、D-17）

- [ ] **手术页步骤化融合**：待实施 PCI 手术主区按「① 手术计划 → ② 选型参数 → ③ 手术耗材 → ④ 开始手术还差」展示；开始手术进入术中态后自动收起术前选型与耗材预计步骤；只要当前存在待实施或进行中手术，主视图不平铺历史已完成手术的「术后核查与责任交接」（仅在已完成手术详情或对应折叠记录内查看）。
- [ ] **选型参数去重与耗材数量汇总合同**：
  - 步骤「选型参数」仅确认靶病变部位、治疗方向与术式（默认取当前手术计划）及三项病变测量（病变长度、近端参考直径、远端参考直径），移除「计划数量」表格；`inpatientPciSelectionParametersSchema` 的 `plannedQuantities` 在仅确认选型参数时允许为空或由步骤「手术耗材」确认时按类别自动聚合回写。
  - 临床指南参考（`inpatient-guideline-advice`）移至步骤「手术耗材」顶部，与助手预填引语合并为单个浅蓝底 `.guide` 说明块，并在三项病变测量与靶病变部位确认后即可生成，不再前置依赖手动填写的 `plannedQuantities`。
- [ ] **手术耗材预填、生成中与选型重改状态机**：
  - 医生确认「选型参数」后，若耗材预填仍在生成中，步骤「手术耗材」显示「耗材生成中」转圈提示，同时表格开放手填，不阻塞医生直接录入。
  - 医生在「手术耗材」确认数量并提交时，一步完成耗材预留（`approvedMaterialIds` 与按类别汇总的 `plannedQuantities` 同步落盘），无需先手动点「请求预计」再二次预留。
  - 已完成耗材预留后若医生修改「选型参数」中的病变测量，既有耗材预留保持不丢失，步骤「手术耗材」状态回到「待你核对 · 选型已改」，助手仅在规格与新测量不匹配的行内标出提示（不自动覆盖医生已确认的数量），底部提供「确认并更新预留」。
- [ ] **取消手术释放耗材预留**：执行 `inpatient.surgery.cancel` 取消手术申请时，服务端在同一事务内自动释放该手术申请关联的在途耗材预留（`inpatient_material_reservation`），避免残留无效占用影响 DRG 预计结余。
- [ ] **DRG 预分组页 AI 融合**：
  - 移除 DRG 页内嵌的「手术耗材建议」面板（统一归口至手术页步骤「手术耗材」）。
  - 「分组核对」每行前置状态图标（绿勾 `✓` / 橙色感叹号 `!` / 灰色圆圈 `○`），分组差异的 AI 解释自动生成并直接内联展示在对应差异核对行下方，移除独立的「AI 解释」按钮、规则集原始 ID、资源哈希及内嵌 Token 表。
  - 「首页主操作」在患者在院未出院结算期间固定显示灰圈 `○ 等手术完成 · 出院后在病案首页选择`，不计入 DRG 页签待办数字徽标。
  - 「住院自动跟进」收紧为单行状态条，模型 Token 明细通过「本次住院 AI 用量」按钮在弹窗（复用 `InpatientDrgUsagePanel`）中查看。
- [ ] **患者头部「助手已准备」芯片过滤与跳转**：患者头部「助手已准备」仅列出**非当前激活页签**的就绪或降级芯片（当前页签内部已直接展示步骤或 `.ai-block` 状态），点击芯片直接切换到对应页签；AI 尚未产出任何建议时不提前渲染空的「助手已准备」行或页签「助手 n」徽标。

### 二、共享壳层、Toast、徽标与「更多」页签栏（A-01～A-05、B-01、B-09、B-31、C-01～C-05、C-41、D-01、D-07、D-22）

- [ ] **DSH ShadowRoot Toast 挂载与叠层规则（C-01、A-04、C-05）**：
  - `apps/web/src/app/web-app.tsx` 使用 callback ref / state 保存 `.clinmesh-web-root` 容器并传给 `PortalContainerProvider`，确保 `Toaster` 始终挂载在 `.clinmesh-web-root`（及 DSH Shadow DOM）内部，绝不退回 `document.body`。
  - Toast 锚定在主工作台卡片右下角、底部操作栏正上方（`bottom: 62px; right: 18px`），在 1280 宿主（`826px` Surface）下不遮挡底部操作栏左侧说明与右侧主按钮；普通成功停留 3.5 秒、带跳转动作停留 4.5 秒；最多同时叠 **2 层**且上一条自动收紧为单行，文案写明具体动作与对象（如「已校对：美托洛尔缓释片 47.5mg」），严禁泛化为「已完成本次操作」。
- [ ] **消除跨页签常驻绿色底栏（D-01、C-66）**：移除 `inpatient-patient-workspace.tsx` 中因共享 `write.mutation.isSuccess` 在无底栏页签（DRG、手术已完成、入科、费用等）底部常驻渲染的「已完成本次操作」绿色操作栏。
- [ ] **浅色模式警告徽标对比度（B-01）**：`Badge variant="warning"` 在浅色模式下使用深琥珀色文字配浅米黄底（如 `#fbf1dc` 底、`#875b0c` 字），文字对比度 ≥ 4.5:1。
- [ ] **队列读取失败横排布局（A-02、A-09、A-27、A-43）**：`Alert` 内含操作按钮时，重试按钮置于第 2 列文字下方或尾部，不挤占第 1 列图标列导致错误提示变成单字竖排；队列读取失败时计数徽标显示 `—` 而非 `0`，重试按钮统一收归左侧队列卡内。
- [ ] **「更多」低频页签选中态与下拉去重（B-31、C-41、D-22）**：
  - 从「更多」下拉菜单选中低频页签（如 `入科`、`费用`、`病案`）后，该页签以带关闭 `×` 的临时激活标签固定在「更多」按钮左侧，主页签栏其余页签顺序与位置不跳动；
  - 打开「更多」下拉菜单时，不再重复列出当前已作为临时标签展示的页签，且下拉菜单内的其余页签完整保留蓝色 `助手 n` 与待办数字徽标。
- [ ] **顶栏流程条与环节首行样式（A-05、A-32、A-44、B-09、C-02、D-07）**：
  - 门诊顶栏流程已完成项只显示 `✓ 挂号`（去掉 `· 已完成` 后缀）；门诊收费员与门诊药师顶栏流程条的前序已完成步骤统一显示 `✓`（同步更新药房 E2E 断言）。
  - 住院各页签环节首行（`.clinmesh-inpatient-turn`）使用浅灰圆角底条，右侧办理顺序步间分隔符统一使用 `›` 并对齐各页签原型步数。

### 三、门诊前台与管理设置页（A-06～A-59）

- [ ] **门诊挂号员（A-16～A-27）**：
  - 左侧队列卡撑满画布高度，待挂号行去掉勾选 `✓` 与原始 `CMSYN…` 标识，选中行统一浅蓝底 + 蓝边；检索框占位完整显示不截断。
  - 切换到「建档」页签时主区与底部操作栏同步切换为「新患者临时建档」表单；出生日期与性别默认留空（不预填 `1990-01-01` 和 `男`），出生日期采用中文年月日格式，未填齐时底栏提示缺项并将主按钮置为虚线不可点。
  - 已选病例挂号表采用单行患者头部 + 右侧「重选患者」，只读「就诊日期」改为纯文本展示，底部操作栏左侧显示 `挂号费 ¥20.00`，去掉提交中黄色警示三角。
  - 挂号成功后主区保留刚挂号患者的只读「本次挂号摘要」与高亮今日挂号记录，底部操作栏提供主按钮 `继续登记下一位：<姓名> →`。

  - 出院页在待离院时顶部显示出院医嘱摘要块与已停嘱完成时间/责任人，在已离院、已结算、已清床时底部提供状态栏与「去病案首页」跳转（已清床隐藏召回卡）。
  - 病案页待办徽标在「已出院结算待提交」时计 `1`、在「已提交待审核」时计 `0`；补齐年龄、入出院床位、住院天数、编码版本副标题、术者姓名、分项费用 3 列网格及「提交首页前」清单跳转链接；在院期间禁用主操作单选与提交按钮，已归档隐藏修改跳转按钮。

## 设计决定

1. **视觉与交互唯一事实来源**：
   - 全量偏差对照基准：`.prototypes/2026-11-05-ui-audit/ui-audit.html`（含 `A-01～A-59`、`B-01～B-32`、`C-01～C-77`、`D-01～D-22` 逐条对照图与归属文件行号）。
   - 住院 AI 融合基准：`.prototypes/2026-11-05-inpatient-ai-fusion/inpatient-ai-fusion.html`。
   - 原型未覆盖窗口基准：`.prototypes/2026-11-05-{outpatient,doctor,inpatient,admin}-gaps/*.html`。
2. **四项跨规格/原型冲突的最终裁定**：
   - **分诊级别默认值（A-15）**：采用默认不选（`2026-11-02-dsh-shell` 方案），未选时底栏「完成分诊」虚线不可点。
   - **分诊页「助手」行（A-14）**：分诊主区不显示静态「助手」提示行。
   - **门诊收费、药房顶栏流程前序步骤（A-32、A-44）**：前序已完成步骤统一显示对勾 `✓`（修订 `2026-11-03-outpatient-detail-polish.md` 与 `apps/web/e2e/his-ui.spec.ts` 旧断言）。
   - **医保审核员「审阅模拟核定」顺序（C-76）**：保留点击前展示「模拟核定」区块，但点击「审阅模拟核定」前不要求先填说明；点击进入审阅确认态后再填/选核定说明并提交（修订 `2026-11-03-inpatient-prototype-restructure.md` 第 212 行）。
3. **窄范围服务端与合同变更边界**：
   - **PCI 选型与手术耗材聚合 + 取消释放**：修改 `packages/contracts/src/inpatient-pci-selection.ts`、`inpatient-guideline-advice.ts` 及服务端 `apps/server/src/application/inpatient-*.ts`，使选型参数步不再强制输入 `plannedQuantities`，改为在确认手术耗材数量并预留时按耗材类别聚合写入 `plannedQuantities` 与 `approvedMaterialIds`；指南参考在三项病变测量与靶病变部位确认后即可生成；取消手术申请（`inpatient.surgery.cancel`）同步释放关联耗材预留。
   - **住院列表与详情头部投影**：在 `inpatientAdmissionSchema`（`/api/his/v1/inpatient/admissions`）附带可选的 `departedAt`、`departureMethod`、`recordNumber`、`referralReason`，供前端截止计算「住院 N 天」、渲染已清床/归档头部第 2 行及医生「入科」只读摘要，避免跨接口 N+1 请求或角色权限拦截。
   - **分诊「已分诊」队列详情投影**：在 `triageQueue`（`status === 'completed'`）与 `triageQueueSchema` 附带最新 `triage_record` 摘要（分诊级别、主诉、六项生命体征、记录时间），供分诊护士在「已分诊」页签直接查看只读详情。
   - 除上述三项外，其余改动均为前端视图、样式 token、组件状态与临床文案映射，不改变既有 FHIR R5 资源、Operation Catalog 与 Agent CLI 合同。
4. **与既有规格和打开 Issue 的关系**：
   - 本规格合并吸收 `docs/spec/2026-11-02-inpatient-ui-ux-streamlining.md`（将其状态更新为 `superseded`），并作为 [门诊与窗口岗位界面细节修整](2026-11-03-outpatient-detail-polish.md) 与 [住院七岗位按原型重排](2026-11-03-inpatient-prototype-restructure.md) 的完整复审收口规格。
   - 实施过程由单个统一 GitHub Issue 追踪（不拆分子 Issue），通过内部并行 worktree 集成分支一次性合入交付。

## 测试策略

1. **原型 1:1 对照硬门禁（最高优先级验收 Seam）**：
   - **开发前必读原型源码**：每个窗口实施前必须直接对照对应 `.prototypes/` HTML 源码（`2026-11-02-dsh-shell`、`2026-11-03-order-dialogs`、`2026-11-03-outpatient-details`、`2026-11-04-inpatient-*`、`2026-11-05-inpatient-ai-fusion`、`2026-11-05-{outpatient,doctor,inpatient,admin}-gaps`）的 DOM 结构、CSS token、区块顺序、列对齐、按钮层级与显隐条件，严禁仅凭文字描述自由发挥或保留原型已删掉的旧块/外层边框。
   - **逐条并排截图复核**：每个窗口修改后，使用 Playwright 在真实应用入口（`1600 / 1280` 宿主对应 Surface `1101 / 826`，浅色/深色，含长页滚动分段 `s0 / s1`）截出与 `.prototypes/2026-11-05-ui-audit/ui-audit.html` 190 条偏差一一对应的修复后截图，逐条并排比对「原型图 vs 修复后真实截图」，确认结构、字重、间距、按钮状态、空态/完成态/错误态与原型完全一致后才可标为通过。
2. **契约与服务端单测 / 集成测试（`apps/server` & `packages/contracts`）**：
   - 复用既有服务端应用层测试入口（如 `inpatient-pci.test.ts`、`inpatient-closed-loop.test.ts`、`workflow-service.test.ts`），验证 PCI 选型参数无 `plannedQuantities` 确认、手术耗材确认自动聚合 `plannedQuantities` 与预留、修改选型保留预留并标记不匹配行、取消手术申请自动释放预留、指南参考基于病变测量生成，以及 `/api/his/v1/inpatient/admissions` 与 `/api/his/v1/outpatient/triage-queue?status=completed` 新增投影字段。
3. **DSH Surface 双版本浏览器合同测试（`apps/dsh-web`）**：
   - 复用既有双版本浏览器合同测试（`apps/dsh-web/src/client/*.browser.test.ts`），在 React 18.3.1 与 React 19.2 ShadowRoot 下验证 `PortalContainerProvider` 挂载 `Toaster`、826px 下 Toast 定位与最多 2 层叠放、`WorkspaceTabs`「更多」临时激活页签与下拉去重、浅色 `Badge variant="warning"` 对比度，以及弹窗打开、聚焦与关闭合同。
4. **Playwright 真实入口 E2E 旅程（`apps/web/e2e`）**：
   - 复用既有端到端旅程入口（`his-ui.spec.ts`、`inpatient-doctor-pages.spec.ts`、`inpatient-prototype-layout.spec.ts`、`inpatient-pci.journey.ts`、`inpatient-discharge.spec.ts`），验证门诊、住院及管理设置全流程外部行为与几何无溢出。
   - 严格遵守影像与病理素材隐私红线：自动化与人工核验均不读取含真实影像或切片像素的截图，仅核对文字快照与聚合统计。

## 依赖与风险

- **多文件并行修改冲突**：门诊医生、住院医生与共享壳层（`workspace-card-layout.tsx`、`inpatient-patient-workspace.tsx`）被多条偏差同时触及。实施时按文件归属切分并行 worktree（① 服务端合同与共享壳层/组件、② 门诊前台与管理页、③ 门诊医生、④ 住院非医生六岗位、⑤ 住院医生与 AI 融合），在集成分支统一合并并跑全量检查。
- **既有 E2E 选择器与断言更新**：药房顶栏流程条前序打勾、分诊级别默认不选、护士清床默认胶囊理由、医保审阅顺序调整后，需同步更新受影响的既有 Playwright E2E 断言。
