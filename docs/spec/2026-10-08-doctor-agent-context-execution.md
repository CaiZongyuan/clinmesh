# 医生 Agent 当前病例读取与执行恢复

Status: draft

实施跟踪：[Issue #176](https://github.com/CaiZongyuan/clinmesh/issues/176)。本文件拥有该切片的读取、执行恢复和验收合同；整体产品范围由[医生 Agent 临床助手](2026-10-08-doctor-agent-assistant.md)拥有，不重复定义自动病历、质控或诊疗建议。

## 问题与目标

医生 Agent 在患者回答、草稿更新或切换诊疗栏目后，可能复制历史调用的页面绑定参数，即使系统已发布最新工具，读取仍被拒绝。医生需要在原病例内顺畅聊天与读取资料，同时在患者、就诊、岗位或数据世代变化时停止旧任务，避免把旧意图作用到新对象。

## 范围

- 对话继续使用 DSH 的 `clinmesh-assistant`，模型由既有宿主会话配置决定；不另建 Agent 运行器。已有 #166–#172 的患者病史自动记录继续由 ClinMesh 编排并复用 DSH 辅助模型。
- 当前医生病例读取、当前未保存表单读取，以及按需读取的授权历史采用纯查询协议。模型只提交业务输入，不填写 `scopeKey`、`pageRevision`、Context token 或 proof。
- 复用现有病例 Query，补齐授权历史索引和单项详情。当前病例、Patient 和 Encounter 由服务端受信上下文确定，工具不接受任意病例、患者、Workspace 或 Actor 标识。
- 医生明确委托代问后，Agent 可在委托任务范围内连续追问；任务完成、医生叫停、病例或授权身份变化后结束委托。信息不足而没有委托时只提示医生。
- 导航、选择、问诊、草稿、预览与正式操作继续按各自精确绑定执行。正式动作保留医生最终确认，既有 Command、版本、幂等和审计规则继续适用。

## 用户故事

1. 作为医生，我希望当前病例的普通更新不会使 Agent 反复读取失败，也不需要我替它修正工具参数。
2. 作为医生，我希望 Agent 在后台查看合法的病例和历史资料，页面不跳转，手工编辑不丢失。
3. 作为医生，我希望旧任务遇到对象或权限变化时暂停，明确未执行的动作可安全恢复，结果不明的操作不自动重做。
4. 作为医生，我希望一次明确代问委托能完成该任务范围内的追问，结束后不继续自行问诊。

## 设计决定

以下为收敛后的待批准实施方案。只读绑定的动机和替代方案见 [Agent Note](../../.agents/notes/proposed/architecture/2026-10-08-doctor-agent-query-binding.md)。

### 运行与调用来源

使用 DSH 公开的 Session `requestHeader()` 和原生 `tool/call` 事件，关联 Session、用户回合、call ID、Tool 名及已记录输入。正常 AgentLoop 完整处理工具批次后才构造下一模型请求，原请求快照可在执行时取得。Header 单独不作为真实调用证明；没有对应原生调用、输入不一致或工具不在原请求目录时拒绝。只保存关联所需元数据，不复制主会话正文或 reasoning，不修改已记录 arguments，不新增持久 Task 表。

按 Session、call ID 和 Tool 复用有界 pending 关联，在进入 pre-execute 时捕获并消费来源证据，不依赖其他 hook 的等待顺序。重复 ID、防重放、一次 proof 签发、取消和卸载清理继续生效。

### 病例任务与代问委托

在真实医生输入进入宿主 inbox 时，记录该消息 ID、DSH Session 和当时唯一的 ClinMesh 受信页面绑定；消息被原生回合领取后，再关联 turn。输入来源限定为受信的人类提交入口，消息的 `source.kind === 'user'` 标签单独不作为证明；无法核实入口时暂停。执行时由 Server 从该绑定对应的 Page Context 解析病例和身份。当前页未就绪、来源不是实际医生输入、绑定缺失或存在歧义时，不能建立病例任务；注入的上下文、Tool 结果及模型消息不替代医生指令。只保留消息引用和绑定元数据，不复制聊天正文。

病例锚点在同一任务的全部 step 中保持不变，每次调用同时比较输入时锚点、原请求对象与当前执行对象。新 header、续签、栏目切换和普通内容更新不替换锚点；病例变化后旧任务进入暂停，即使页面又切回也不自行恢复。换目标须由新的真实医生输入或医生明确确认建立，先结束旧任务和代问委托。仅仅成功执行一个精确绑定的选择 Tool，不代表医生已把旧任务转移到新患者。

代问采用待确认的推荐交互：Agent 首次准备代问时，展示当前患者和本次追问范围，由医生确认一次；此后同一任务内可连续追问，不逐问确认。确认复用现有人工审阅 UI 与 decision gate，重新核对登录医生、原任务消息引用、病例锚点和当前权限，取得仅供该任务使用的代问许可；使用窄许可合同，不将确认冒充必须关联正式 Command receipt 的 proposal 完成。模型填写的“已经委托”、引用的历史聊天或原生 Tool 调用均不构成许可。该许可是当前回合的临时状态，不复用 CLI 的 Agent Capability Grant，也不新增持久 Task 或另一套后台任务框架。

每次问患者前，Host 与 Server 均核对许可仍关联同一任务、医生与病例；问诊动作继续精确绑定并使用现有版本和幂等规则。任务完成、医生叫停或拒绝、回合结束／取消、授权对象变化、宿主卸载后许可失效；结果不明时暂停，不因仍有许可而重放。中断或重启后不自动恢复许可，继续代问须重新确认。

### 纯查询与精确执行

纯查询只对白名单中的当前上下文、医生病例、历史索引和历史详情开放。读取 proof 同时绑定输入时任务锚点、原请求和实际执行 Context；Server 从既有 Page Context 记录解析对象身份，比较 User Account、Actor、Practitioner Role、DSH Session、Workspace/Epoch、Scenario Run、Case、Patient 和 Encounter。相同对象的栏目、草稿或普通内容版本变化允许读取最新状态；对象或授权变化则暂停。历史 Context 只证明原对象，不提供新的读取授权；仅因正常续签或同对象内容更新而过期／撤销的记录可以用于身份核对，不能据此恢复因对象变化而暂停的任务。所需历史记录缺失时停止，#176 不增加清理或延长保存策略；当前 token、责任医生、资源状态和 operation policy 仍须有效。

不能仅凭 `read-only` 标签放宽所有工具。会生成提交预览的操作仍采用精确绑定。所有写入和选择动作都不把旧参数自动改成最新值；明确拒绝且 body 未开始时，先读取、核对原任务，再生成新的调用。超时、body 已开始后的中断、响应不明、业务成功但 completion 或 handoff 失败均先核对结果，不自动重放。

### 当前快照与授权历史

Surface 从同一份当前有效且已提交的 frame 解析 binding、operation、action 与未保存状态，不使用旧注册闭包里的 action 或 readState。异步返回前核对对象和权限，晚到的旧对象结果不进入模型下一步。读取入口在实际 Query 时重新校验受信当前病例权限，不能仅在先前授权时检查一次，也不向 Agent 开放裸 `doctorCaseDetail` 的任意 caseId 能力。

历史分为已有本地完诊记录和 Visible Source History，使用现有投影。服务端从已授权当前病例解析物化关联；历史详情只接受当前患者授权索引中的条目。保留现有责任医生、Workspace/Epoch 和 visible-only 限制，不扩大到其他医生、其他轮次或管理员真值。结果明确来源、时间、覆盖范围与分页；未记录、没有关联、查询失败和无资料分别表达。工具只提供临床可见文本与结构化信息，不返回 Persona 全文、Case Truth、raw Bundle、影像像素或任意 URL。

### 反馈与恢复

同对象的纯查询同步失效可进行一次有界后台恢复；成功后不播报技术错误。不能安全恢复、对象变化或结果不明时暂停并简短说明。人工拒绝、医生取消和业务规则拒绝不自动重试。模型跨步仍须核对当前病例与医生原意图；读取失败不能表述为没有问诊记录，也不能从绑定拒绝推断患者已切换。

## 验收条件

- [ ] C1：医生纯查询工具不要求模型填写动态页面绑定；同病例问诊、草稿和栏目变化后可以继续读取，且不切换医生页面。
- [ ] C2：原请求、原生调用、实际执行 Context 和 receipt 的关联可验证；未知来源、未知锚点、输入不一致、重复 ID、错 Session 或错 Tool 均拒绝。
- [ ] C3：输入排队、生成期间、工具执行期间及同回合后续步骤的患者、Encounter、岗位、Actor、Session 或 Epoch 变化不会让旧任务读写新对象；新 header、选择成功及切回原病例均不自行恢复旧任务，新目标与新委托须从受信医生入口明确建立。
- [ ] C4：当前 action、binding、未保存表单来自一致的有效 frame；保留旧注册函数后调用也不会返回旧患者或丢失当前手工内容。
- [ ] C5：授权历史按需分页，详情只来自当前患者允许集合；责任医生、物化关联及隐藏／可见分离的负例实际通过。
- [ ] C6：写入、预览和正式审阅继续采用精确版本；只读改进不扩大到这些操作，不自动覆盖手改或重放结果不明的动作。
- [ ] C7：医生确认一次任务范围后可连续追问；伪造委托字段、历史消息、注入上下文和单独的原生调用均不能取得许可；未确认、完成、叫停、回合结束、对象变化或重启后不自行问诊。
- [ ] C8：正常后台读取及安全恢复不反复出现面向医生的技术绑定错误；真实失败简洁如实反馈，不谎称完成。

## 测试策略

以已有 Hono Agent HTTP 和真实 SQLite 作为授权主 seam，验证原请求锚点与当前授权，以及同病例更新／跨对象负例。复用 Host proof、原生 AgentLoop、Surface Tool／publisher 合同；原生脚本模型明确复制历史参数，并覆盖工具目录更新、生成期间换患者、并行、重试、重复 ID、取消和无原生来源的调用。

病例任务回归覆盖输入排队后换患者、相同 header 下的后续 step、选择 Tool 成功后仍沿用旧任务、切回原病例、多个 Session 和上下文注入。代问回归从真实人工审阅入口建立许可，验证一次确认后连续追问、取消／完成／中断清理、伪造来源、权限变化及结果不明不重放。实际 Query 与异步结果返回前分别覆盖责任医生或病例状态变化，不能用先前的 authorize 成功代替执行时检查。

用 Playwright 从真实 DSH 入口核对聊天、跨栏目读取、来源历史与暂停反馈。确定性 CI 替换模型网络边界，真实模型单独检查实际 request/header、调用参数、结果及业务状态；只看脚本模型或一次真实成功不替代权限负例。只使用合成数据，不读取影像像素。跨包 proof 和工具合同变更同步 owning Catalog、相关运行时 Skill 和示例漂移检查，按最终 diff 执行项目必需检查。

临时原生探针已证明公开 header 和调用事件的时序可用，未证明本方案的最终 proof、授权、历史或恢复实现通过。细节与原生接口证据见[病例读取研究](../research/2026-10-08-doctor-agent-case-read.md)和[绑定执行研究](../research/2026-10-08-doctor-agent-binding-execution.md)。

## 范围外

- 不实现 #166–#172 的自动记录，不实现 #177–#181 的全病历扩展、质控和建议。
- 不重写 DSH、维护宿主补丁、引入新的 Agent 框架或复制主会话 transcript。
- 不开放任意病例、SQL、FHIR、URL 或跨角色／跨 Epoch 数据访问。
- 不取消版本检查、来源校验、幂等、审计或医生最终确认。

## 依赖与风险

复用当前锁定 DSH 的公开 Session／Tool hooks、Page Context、execution proof、Query 和 Command。原请求 metadata 缺失、原 Context 不可核实或当前 frame 未就绪时必须停止或有界等待，不能猜测授权。Proof 合同在 Host、Web 与 Server 同一 diff 升级，混用旧产物应明确拒绝。原生模型时序探针不覆盖全部权限与恢复场景，实施时必须由 C1–C8 的真实合同证据补足。

待用户确认：是否接受首次代问显示任务范围并由医生确认一次、后续范围内连续追问的交互。该方案在确认前保持 draft，不将“一次聊天中的明确委托”静默改成已批准的新增确认步骤。
