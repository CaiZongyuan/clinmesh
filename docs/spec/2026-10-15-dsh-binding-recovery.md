# DSH 绑定失配诊断与只读恢复

Status: implemented

实施跟踪：[Issue #209](https://github.com/CaiZongyuan/clinmesh/issues/209)。原病例读取、精确动作和任务隔离继续遵循[医生 Agent 当前病例读取与执行恢复](2026-10-08-doctor-agent-context-execution.md)。

## 问题与目标

医生 Agent 对当前 Tool 的固定 `pageRevision` 多加一层数组时，Host 正确拒绝调用，但统一文案声称患者、岗位或页面已变化。医生纯查询已不要求模型填写绑定字段，恢复提示却继续从只读 schema 读取这两个 `const`，把已发布的只读工具误报为目录不可用。目标是准确说明绑定不匹配，并提供符合当前只读 schema 的恢复调用，让原任务在核对病例后继续。

## 范围

- ClinMesh DSH Host 的绑定失配诊断、当前上下文只读恢复参数及其现有测试。
- 医生已选病例时无绑定字段的纯查询，以及其他页面保留绑定字段的读取。
- standalone 页面动作、任务来源、医生代问委托、HIS Command、Patient/Encounter 隔离与精确绑定合同保持既有归属。

## 用户故事

1. 作为医生，我希望 Agent 能分辨参数错误与已确认的对象变化，不因错误文案要求我反复刷新。
2. 作为 Agent，我希望绑定失配后拿到可执行的当前只读调用，核对原任务与患者后再生成新的写调用。
3. 作为维护者，我希望真正缺失或无效的工具定义仍然失败关闭，错误参数和旧任务不会执行业务动作。

## 验收条件

- [x] 调用仍返回 `CLINMESH_BINDING_MISMATCH`，明确原动作尚未执行；当前绑定可比较时准确列出不匹配的 `scopeKey`、`pageRevision`，不把拒绝表述为已确认的患者或岗位变化。
- [x] 当前绑定定义不可用时说明定义状态，不猜测患者状态或编造不匹配字段。
- [x] 医生恢复要求可取得当前医生目录绑定，目录须具有有效的完整 object schema，旧式读取定义或损坏目录中残留的绑定 `const` 均不能替代它；无有效目录时不提供恢复调用。栏目目录无效时可以使用合法的病例选择目录。当前上下文只读工具已发布且具有有效的无参数 object schema 时，恢复调用是 `clinmesh_read_current_context`，参数为 `{}`。
- [x] 读取仍需要绑定的其他页面沿用真实只读定义中的两项有效 `const`；不复制 Context ID、额外字段或任意业务参数。
- [x] 只读工具确实不存在时说明目录尚未可用；工具存在但 schema 无效或缺少医生目录绑定时明确该状态，不误报工具缺失。两者均停止并等待有效定义，不返回猜测的恢复调用。
- [x] 恢复提示要求先读取并核对患者、岗位与原任务，再按最新写 Tool schema 的固定字符串生成新调用；Host 不自动改写原参数或重放原写入。
- [x] 同一原生 DSH 代问回合可以经过错误写参数被拒绝、无参数读取、最新正确参数追问，业务追问只执行一次。
- [x] 原任务、病例或权限变化后仍被既有保护阻止，读取恢复不赋予旧任务操作新患者的权限。

## 设计决定

`pageRevision` 仍是 `agentPageBindingRevision` 输出的序列化字符串，模型必须原样使用当前 schema 的固定值。失配诊断只公开字段名与受当前调用 Agent 限定的只读恢复调用，不放宽写入、导航或选择的比较。

恢复参数取决于实际只读 schema；无参数医生读取不以缺少写绑定字段判定目录缺失。读取定义无效时不通过宽松空对象恢复。沿用当前错误码、Host pre-execute hook、Tool registry、execution proof 与原任务核对；不新增操作、依赖、HTTP 路由或持久化字段。决定与替代方案记录在[医生 Agent 纯查询绑定](../decisions/implemented/architecture/2026-10-08-doctor-agent-query-binding.md)。

## 测试策略

采用 TDD，通过安装的真实 Host listener 验证拒绝 reason、恢复 JSON、原参数保真和业务 dispatch 是否发生；覆盖现代医生只读、传统绑定读取、缺失或无效定义、单字段与双字段不匹配。医生动作以及原请求属于医生的共享工具均覆盖目录缺失但旧式读取仍带 `const` 的组合，同时验证非医生页面保留绑定恢复。复用 `agent-proof-bridge.test.ts`，不导出私有诊断函数作为测试入口。

原生 DSH 测试复用真实 Cordis、Tool registry、AgentLoop 和合成模型，只替换浏览器传输与 HIS 响应，验证模型实际收到拒绝、按恢复 JSON 读取，并从当前 Tool schema 构造新的追问。跨患者与任务失效使用既有真实授权和 Surface 合同，不把 browserChannel 的合成成功响应当作患者隔离证据。

运行 DSH 包测试、相关 Surface/Server 任务隔离回归、类型与 lint、产物构建及文档检查。未修改可见 Web 控件，不以页面截图代替原生执行证据；真实模型对恢复指引的遵循不由合成模型测试保证。

## 范围外

- 自动归一化或补齐旧写入参数，放宽患者、岗位、任务来源、委托与版本校验。
- 自动重放拒绝、超时、已执行或结果不明的业务写入。
- 重设计绑定协议、把全部精确动作改成无参数绑定、升级 DSH 或修改上游宿主。
- 检验单位转换、病历整理、诊疗建议、模型选择和正式业务操作。

## 依赖与风险

复用锁定的 DSH `0.2.0-rc.2` 公开 Tool 与 Agent hooks，无新的外部依赖。模型可能继续填写错误参数；本需求保证诊断与恢复指引准确，精确调用仍会被安全拒绝。原生测试的合成模型不能替代真实模型行为验收；运行中宿主使用的已构建插件须在部署时重新构建并加载，本需求不自动重启现有工作台。
