# 病史整理中自述与疑问混合句的来源校验

Status: implemented

## 问题与目标

患者在同一句中表达明确自述并提出问题时，病史整理会将整个引用拒绝。例如合成回答“医生，那我今天到现在还没吃东西，水也就抿了两口，这样抽血行不行啊？”同时包含进食、饮水自述和对采血的提问。当前来源校验要求逐字完整引用，又拒绝引用中的所有中英文问号，导致这些自述无法进入独立事实核对。相同输入在真实 DSH 辅助模型的首次生成和一次修复中均触发来源校验，最终以 `AI_RESPONSE_INVALID` 停止整理。

目标是区分引用是否合法与总结事实是否得到支持：保留完整患者原话，允许明确自述与疑问共存的句子作为来源，只整理其中患者明确表达的事实。适用所有患者和病史整理入口。

## 范围

覆盖主诉、现病史、既往史中的共享病史来源检查、生成提示及独立事实核对，以及自动整理、历史补录和显式失败重试。沿用现有任务顺序、来源展示、人工编辑保护与签署边界。

## 用户故事

1. 作为医生，我希望患者把自述与问题放在同一句时，明确自述仍能被忠实整理，完整原回答仍可查看。
2. 作为医生，我希望患者的纯提问、假设和不确定表达不会被误写成确诊、客观检查结果或已满足某项条件。
3. 作为医生，我希望修复后可以重试未完成回答，继续后续队列，而不重复生成已经成功的病史。

## 验收条件

- [x] A1：包含明确自述和疑问的完整原句可以通过确定性来源检查；在总结得到独立事实核对认可后写入草稿，不因引用含 `？` 或 `?` 而整体拒绝。
- [x] A2：上述合成回答可形成“患者自述今日尚未进食，仅饮少量水”等忠实总结。不得推断“已空腹至少 8 小时”“符合空腹采血条件”或“已经完成采血”。持久来源保留完整问句和原标点；页面展示沿用[当前病历规格](2026-10-14-clinical-document-fields.md)。
- [x] A3：纯提问如“我是不是糖尿病？”“胸痛已经三天了吗？”不形成糖尿病确诊或胸痛持续三天的事实。假设、否定和不确定表述保持原语义；没有可总结事实时允许返回空增量并完成该回答的整理。
- [x] A4：逐字匹配、完整引用边界、患者 speaker、截至当前回答的来源范围及患者、病例、Workspace/Epoch 隔离继续有效。不存在、跨病例、医生发言或通过截断疑问制造肯定陈述的来源仍被拒绝。
- [x] A5：独立核对继续逐项检查事实依据、否定、时间、数值、程度、不确定性、来源限定、旧事实保留及关系。核对的否定结论是有效输出，不得作为格式错误反复要求模型改成通过；未通过核对的结果不写入草稿。
- [x] A6：自动整理、历史补录及显式失败重试使用相同处理规则，效果覆盖后续患者，不针对单一回答或病例硬编码。
- [x] A7：按“已完成 5 条、失败 1 条、后续排队 1 条”的持久场景验证恢复。显式重试后两条未完成回答可按序完成，`remainingCount` 归零、失败状态清除；已完成任务、已应用正文和既有来源保持原结果，不重新调用模型。
- [x] A8：失败期间患者回答独立保存；新逻辑仍遵守暂停、任务代次、人工编辑保护和签署限制。部署或打开病例不自动重写成功结果，也不自动复活已有失败任务。

## 设计决定

确定性检查负责可确定的原文归属、完整引用与目标边界；独立事实核对负责判断总结是否由患者明确自述支持。生成及核对要求明确区分混合句内的自述与提问，不能以问号本身判断所有内容是否可记录，也不能通过删除问号、截断原句或修改已保存回答规避校验。

使用现有共享病史服务和有界模型修复，不增加病例专用分支，不改变队列调度或持久重试合同。疑问来源的处理及语义核对限制由[总结与多轮溯源 Agent Note](../../.agents/notes/implemented/architecture/2026-10-12-consultation-agent-summary-sources.md)拥有。

## 测试策略

使用真实病史来源校验和 DSH Provider 集成回归，覆盖完整混合句、中英文问号、纯提问、条件假设、否定、不确定表达、引用截断及同一句内与跨句的自述关联。模型替身分别提供忠实总结、无依据推断和合法否定核对结果，验证允许混合引用不会放宽事实写入；保留对修复次数及拒绝后不写草稿的断言。

通过公开问诊 HTTP、病例 Query 和 file-backed SQLite 验证 A7 的顺序恢复、成功任务不重跑与状态持久化。真实 DSH 验收仅使用合成问诊，独立回放当前失败输入及反例，核对模型总结、完整来源和失败恢复；常规 CI 不依赖真实模型凭据或付费调用。仅在调整可见 UI 时补充对应 Playwright 验证。

## 范围外

本需求不扩展为自动诊断或治疗建议，不改写患者原话，不批量重生成成功病史，不增加跳过失败任务的队列策略，不放宽人工签署权限。实施验收使用隔离的合成问诊，不对现有工作病例执行重试或病历重写。

## 依赖与风险

依赖 [#198](https://github.com/CaiZongyuan/clinmesh/issues/198) 与 [PR #199](https://github.com/CaiZongyuan/clinmesh/pull/199) 已交付的病史总结、完整来源及独立核对能力。基础合同由[病史总结与患者自述溯源规格](2026-10-12-consultation-agent-summary-sources.md)拥有，混合句处理决定见[多轮溯源 Agent Note](../../.agents/notes/implemented/architecture/2026-10-12-consultation-agent-summary-sources.md)。

语义核对存在概率性局限，允许问句作为完整来源不等于认可其全部内容；必须用纯疑问和假设反例验证错误肯定结论不会进入草稿，正式签署仍由医生审阅。
