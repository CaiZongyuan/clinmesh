# 门诊住院共享支付与 DRG 一体化

Status: approved

首次成稿：2026-10-15。执行追踪：[Issue #225](https://github.com/CaiZongyuan/clinmesh/issues/225)。本文件为已批准的门诊住院共享支付与 DRG 一体化需求；2026-10-21 确认扩展范围并授权更新 Issue。原批准版本及其验收状态见[固定快照](https://github.com/CaiZongyuan/clinmesh/blob/309cbf0b5ab931dcc26daa7076c938e36a9530b1/docs/spec/2026-10-15-drg-prescription-budget.md)，旧实现证据不覆盖新增范围。业务实施及交付授权按[工程协作规则](../agent-development.md#实施与交付)执行。

## 问题与目标

当前主分支具有门诊分次组合收款，住院闭环具有独立预交金及多退少补。目标是门诊与住院共用支付账务能力，并让 DRG 读取同一次住院的正式临床与费用事实，贯通在院评估及后续结算场景。

患者医保待遇结算与医院侧 DRG 付费分别建模、展示和验收。患者自付、个人账户及基金分配不能由 DRG 参考额替代；收费、资金交易、预计收入与成本也不能混为一个金额或状态。全部患者和交易为合成数据，外部行为使用确定性模拟器。

## 范围

当前医生独立检验、放射及病理会诊的开单应收、门诊价目和取消退费边界，由[门诊独立检验检查开单与收费补充规格](2026-10-26-outpatient-investigation-billing.md)拥有。

- 门诊与住院共享支付底座，承接已有收款及住院预交金、多退少补与退款实现；包含账单、部分与组合支付、预交金及抵扣、补缴、关联原交易的部分退款、成功／拒付／结果未知及查询恢复、患者医保分摊、结算撤销和交易对账。
- 结算及归档后的受控财务更正、关联原交易退款、医保撤销及重结算；以追加记录保留原费用、原结算和原归档的历史含义，单独展示更正差异。
- 患者医保结算模拟覆盖普通门诊与普通住院，提供职工、居民两套明确标识的合成方案，处理目录内外、先行自付、起付线、报销比例、封顶线、年度累计及个人账户余额。
- DRG 采用 CHS-DRG 3.0 通用仿真与明确合成的医院支付参数，完成在院预分组及处方推演、病案审核归档后的冻结分组、模拟医保核定反馈及预估与核定差异对账。
- 新增医保办专岗及相应操作入口，与住院医生、收费员和病案人员按职责协作。
- 既有参考数据与新增 OpenDRG 资料的来源、版本及适用性核验，通过离线准备、审核映射和不可变版本发布进入运行时。

## 用户故事

1. 作为收费员，我希望门诊和住院采用一致的收退款规则，并能识别支付结果、历史及恢复动作。
2. 作为医生，我希望从当前住院病例查看 DRG 与费用变化，正式确认临床事实后能够解释评估变化。
3. 作为收费员，我希望查看预交金的收取、抵扣和剩余余额，完成补缴或关联原交易的部分退款，避免把收费变化等同于资金变化。
4. 作为医保办人员，我希望核对医院侧 DRG、模拟核定反馈和差异，能够追溯病例输入与规则，不承担患者收退款或病案编修。
5. 作为收费员，我希望收退款未知时查询原尝试并恢复，明确区分拒付和未查明结果，避免重复收退。
6. 作为收费员，我希望用职工或居民的合成待遇分别完成门诊和住院结算，解释基金、个人账户和患者自付的组成。
7. 作为收费员，我希望撤销及重结算补偿原待遇影响，并保留个人账户和年度累计中其他就诊的变化。
8. 作为护士，我希望依据确定的首次财务完成结果清床，资金恢复后可以继续原流程，不承担资金状态推断。
9. 作为住院医生，我希望区分计划、草稿与实际完成的操作，对处方和药耗做推演，及时识别过期评估且不丢失已发生费用。
10. 作为病案人员，我希望分组依据与已审核的归档快照一致，后续财务调整不改写原病案及其冻结结果。
11. 作为收费员，我希望在结算或归档后受控更正财务错误，保留原始引用和差异，不通过恢复床位或解档办理退款。
12. 作为数据维护者，我希望核对资料来源、哈希、编码兼容与适用范围，隔离缺失或不兼容记录，复现历史分组和报价。
13. 作为管理者，我希望分别核对患者医保分配、资金收付、医院 DRG 支付参考与已覆盖成本，避免重复计算收入或把差额当完整盈亏。
14. 作为业务操作者，我希望在独立 Web 和 DSH Surface 使用一致的权限、预览和人工审阅流程，并能在刷新或请求丢失后核对实际结果。

## 验收条件

- [ ] 门诊和住院通过共享支付账务能力完成已确认范围的收退款；可关联就诊、账单、费用和原支付交易。
- [ ] 住院 DRG 评估读取临床及费用 owner 的事实，不形成可独立编辑的第二套临床记录或收费账。
- [ ] 同一次住院分别展示费用、患者医保待遇分配及医院 DRG 付费结果，规则与金额来源可追溯。
- [ ] 同一账单支持部分与组合支付；预交金及抵扣、补缴、关联原交易的部分退款可追溯，未分配余额与已使用金额可以核对。
- [ ] 成功、拒付与结果未知有不同状态及可执行的恢复路径，重复提交和重复结果不重复入账。住院补缴或退款结果未知时不判成功、不封账、不清床，查询确认后方可继续财务结算及清床；出院医嘱和护士出区仍按各自临床条件执行。
- [ ] 普通门诊及普通住院分别验证职工、居民合成待遇，年度累计及个人账户余额参与结算与撤销核对，不使用 DRG 参考额替代患者分配。
- [ ] 选定 CHS-DRG 3.0 方案的仿真分组能够复现并解释，提供固定版本的规则与对照测试；无法入组、歧义或缺参数显式呈现，不虚构可用结果。
- [ ] 在院预分组读取已确认事实，草稿及计划只做推演；归档后结果绑定不可变病案快照；模拟核定反馈单独记录并展示差异依据。
- [ ] 评估绑定病例及其依赖版本；切换患者，或临床 revision、处方草稿、其他科室费用、异步执行、价格、成本及规则变化时，旧评估标为过期，迟到响应不得覆盖当前结果。正式开具前在服务端重新核对依赖，发生变化时要求更新预览并重新审阅，不依赖客户端最后一次评估直接开具。
- [ ] 并发开具、重复提交、超时重试及重复回执不重复生成医嘱、收费或评估；依赖版本冲突有明确反馈及恢复路径。
- [ ] 已结算、已清床或已归档后，授权岗位可追加关联原费用及交易的财务更正、退款、医保撤销与重结算；原账、原结算及原归档快照均可回查，更正后的费用、分摊和待收退金额单独展示。
- [ ] 后续财务更正不恢复床位、不撤销临床出区、不解档修改诊断或操作；首次结算完成与后续调整完成分别表达，后续资金未知只保持该调整待处理，不把既有清床或归档倒退。
- [ ] 退款不得超过原交易可退余额；医保撤销与重结算以关联的补偿及新结算记录核对个人账户和年度累计，不覆盖其他就诊后来已发生的余额变化。重复更正或恢复不重复收退、分摊或累计。
- [ ] 新增医保办专岗查看医院侧 DRG、模拟核定反馈并进行差异复核；收费员仅取得患者结算所需信息，病案人员继续拥有编码审核及归档。越岗访问或执行被拒绝，读取与正式动作保留审计。
- [ ] 冠心病／PCI 为主要演示，心力衰竭为辅助，既有肺炎病例和冻结历史保留兼容验证。PCI 计划与完成确认、药品及支架／球囊／导丝／导管的计量、预留替换分别有可观察结果。
- [ ] 费用进度、参考额差额、预计收入及已覆盖成本分别展示；收费超过 DRG 参考额不直接命名为亏损，不设置固定比例、目标结余率或费用审批门禁。
- [ ] 缺价格、单位、分组、支付参数或成本时分别标明不完整，不以零值或跨方案参数填充；新版本不覆盖旧费用价格和评估依据。
- [ ] 原分支的肺炎模拟测试不计为本次完整支付、医保待遇或 CHS-DRG 3.0 分组的完成证据。
- [ ] 四个交付切片分别通过对应验收，最终在同一次冠心病／PCI 合成住院中贯通临床事实、费用、患者医保与资金、归档分组、模拟核定差异及后续财务更正；任一切片未完成，不能将 #225 标记为完整交付。

## 设计决定

### 职责与协作

| 范围 | 归属 |
| --- | --- |
| 入院、入出转、临床医嘱与执行、出院及清床门禁、病案首页审核归档 | 同事的[住院闭环 #245](https://github.com/CaiZongyuan/clinmesh/issues/245)及关联切片 |
| 门诊住院共享账务、收款、退款及支付结果 | #225 承接已有实现并统一 |
| 患者医保待遇结算模拟、医院 DRG 评估 | #225；两者拥有独立的规则、状态与结果 |
| 计费来源与正式临床事实 | 保留各业务 owner；通过共享账务及只读投影交接 |

住院端依赖共享账务结果推进财务门禁，继续拥有出院和清床流程。#225 不复制临床状态机；DRG 不写诊断、操作或执行事实。分工理由及待落实交接见[支付与住院职责提案](../decisions/proposed/architecture/2026-10-21-payment-inpatient-drg-boundaries.md)。

### 资金结果与住院门禁

保留 [#249](https://github.com/CaiZongyuan/clinmesh/issues/249) 的财务结算后清床门禁。支付或退款结果未知时，财务结算保持未完成，不封账、不清床；只能通过结果查询与恢复取得确定资金事实，不能把超时当拒付或成功，也不能通过再次收付绕开未知交易。医生出院医嘱及护士出区按各自临床条件执行，不以资金结果未知代替临床条件。

确定失败的收付尝试保留记录，按最新有效预览及余额恢复；未知尝试未查明前不得对同一应收或应退重复收付。所需补缴、退款及待遇分配全部达到确定且可核对的完成状态后，住院 owner 才可完成财务门禁，护士再按既有条件清床。

### 结算及归档后的财务更正

已结算、已清床或已归档后发现多收费等财务错误，允许在共享账务 owner 中追加受控更正记录、关联原交易退款、患者医保撤销及重结算。原费用、资金交易、结算及病案快照继续保存，更正通过明确的原始引用及调整关系影响当前账务；不能另建可任意编辑、与正式账无关的影子账。

归档页面保留原冻结费用和分组依据，后续财务更正与原归档的差异单独展示。后续财务状态不倒退临床出区、清床或归档事实；本次不开放病案解档及归档后诊断、操作更正。医院 DRG 模拟核定差异也不自动触发患者退款，必须按相应收付和待遇 owner 的业务依据处理。

首次结算仍遵循资金确定后才能清床的门禁；清床后的调整有独立待处理及完成状态，未知退款或重结算不能把旧完成事实改成未发生。患者医保撤销按原结算影响形成补偿，保留原结算与新结算关系，不直接重置个人账户余额或年度累计。

原住院实现没有结算后补费、独立部分退款、撤销或重结算入口，且归档时核对原结算与费用、资金快照一致。因此本需求需要与 #249／#250 明确首次冻结结算及后续调整的引用和校验，不通过放开普通归档锁实现。对于已完成的 Scenario Run，只开放该范围内的窄财务更正及恢复能力，原有临床写入和 Workspace／Epoch 边界继续生效。

### 岗位入口与信息范围

| 岗位 | 首期入口与职责 |
| --- | --- |
| 住院医生 | 当前住院病例内查看预分组、费用及处方推演；正式临床事实仍由各临床 owner 确认 |
| 收费员 | 门诊与住院账单、收退款、预交金、患者医保结算及关联财务更正；只读所需的窄财务信息 |
| 病案人员 | 延续编码审核、首页修订及归档职责，查看与病案快照对应的分组依据 |
| 医保办 | 新增专岗入口，查看医院侧 DRG、模拟核定反馈、差异及复核所需的病例和来源摘要 |

医保办只取得其复核所需的正式临床与费用投影，不因此取得临床写入、患者退款或病案编修权限。模拟核定由受控仿真流程提供，医保办不能把任意手填金额伪装成医保返回结果；原结果、后续复核与调整各自保留来源。

医院侧 DRG 核定反馈可发生在归档之后，不作为患者出区、首次结算清床或病案归档的前置条件。独立 Web 与 DSH Surface 复用同一业务能力和岗位边界，新增正式动作沿用窄 Command、预览、人工审阅及审计约束。

### 首期方案与资料身份

DRG 完成标准为选定方案下可复现、可解释、接入住院流程的完整仿真及对照验证，持续标明来源和适用边界；本次不承诺与某地正式分组器逐病例一致。CHS-DRG 3.0 通用方案与明确合成的医院支付参数分别固定版本，不把通用分组结果乘以浙江城市点值后称作浙江结算。

患者医保使用职工、居民两套合成待遇，其参数与医院侧 DRG 支付参数独立。现有浙江服务价格及药耗来源按各自口径保留，不能因采用通用 DRG 仿真而改成合成本院价格、采购成本或患者待遇参数。

新增 OpenDRG 包的文件核验、实际覆盖及缺口见[资料核验](../research/2026-10-21-opendrg-public-data-inventory.md)。完整程序在原始 JavaScript 中，参数 JSON 仅有 CC、MCC、排除关系与有效操作；静态发现函数不等于已验证分组正确性。编码适配与来源核验是运行时启用的前置条件。

### 费用与临床展示

延续原规格的心内科主线：冠心病／PCI 作为主要演示、独立心衰病例作为辅助，肺炎病例及历史评估用于兼容回归。PCI 计划不成为实际操作；计价数量不更改临床事实或病组；药品、手术服务和耗材逐项表达，预留转正式医嘱须通过业务引用替换，不能重复计费。

正式收费、未记费承诺、当前草稿推演和后续治疗预留分别归集，收费与成本分别流转。临床撤回不删除已发生费用或已执行成本；退款改变资金，不自动撤销收费或执行事实。收费金额以整数分保存，原始单价及权重等按来源精度保存并在明确边界舍入，不用二进制浮点累加金额。

DRG 支付参考、患者医保分配、医院预计收入及成本有独立口径；不再沿用原型中患者另付为零、参考额等于完整收入的简化假设。只有取得明确组成和覆盖范围后才展示预计收入或结余；部分成本只能称已覆盖成本估算，不作为完整住院盈亏。费用提示不自动更改治疗、补录诊断、提高病组或阻止临床必要开具。

### 交付切片与集成顺序

四片全部纳入本次范围，切片验收用于定位责任及验证进度，最终沿冠心病／PCI 主线进行一次联合验收，不把支付或独立 DRG 原型单独通过视为 #225 完成。

| 切片 | 可观察交付 | 前置依赖 |
| --- | --- | --- |
| ①共享账单与收退款 | 门诊和住院采用一致的账务、部分与组合支付、预交金抵扣及关联退款规则；确定、拒付和未知结果可恢复，并接入住院首次结算与清床门禁 | 固定住院集成版本，明确计费来源、资金记录与门禁交接；保留现有门诊兼容性 |
| ②患者医保待遇与组合结算 | 职工、居民的普通门诊及住院合成待遇可解释，基金、个人账户及自付分配可核对，支持撤销补偿并与资金收付协作 | ①的账单、资金和幂等合同；独立版本的合成待遇方案 |
| ③CHS-DRG 3.0 与住院评估 | 通过来源及编码核验的分组仿真，贯通在院预分组、处方推演、已覆盖成本提示与归档冻结分组 | 核验通过的规则、编码映射与对照集；固定版本的在院事实、正式费用及归档快照读取接口；在院只读投影可先于完整资金链接入 |
| ④医保办对账与后续更正 | 医保办专岗复核模拟核定差异；收费员可受控处理结算后的财务更正、退款及医保撤销重结算，保留原冻结事实 | ①②③；首次结算与后续调整引用、归档校验及已完成 Scenario Run 的窄写入边界 |

资料核验和门诊兼容可独立推进。住院接入以已合并闭环为基础，实施前固定实际集成提交、双方 owner 及交接合同，不能持续追随未锁定的分支头。对共享账务、首次结算及归档校验的调整在同一集成版本验证，临床流程继续由住院 owner 维护。

联合验收从同一冠心病／PCI 合成住院开始：正式确认诊断、执行与药耗计费，医生查看预分组及草稿推演；收费员完成待遇分配、预交金抵扣和补收退款，演示未知结果阻断首次财务完成并查询恢复；满足住院条件后清床，由病案人员审核归档并形成冻结分组；医保办查看模拟核定与预估差异；再由授权收费员处理一笔归档后财务更正及关联退款／医保重结算，核对旧快照保留、当前账务更新且临床不回退。门诊闭环和心衰辅助病例另行回归，不能只凭主线的单次成功路径验收。

## 测试策略

主要测试入口沿用现有的公开 HIS Query／Command，经真实 HTTP adapter、响应 schema 及临时文件 SQLite 驱动同一业务 owner；确定性支付、待遇与核定模拟器只替代外部系统边界，不 mock 内部账务和临床状态机。继续使用门诊收款的预览／确认、拒付与未知结果、幂等和跨岗 HTTP 场景作为支付先例，CLI receipt 的响应丢失恢复作为查询恢复先例，不新增供测试绕开权限或直接改数据库的业务入口。

Playwright 在 standalone Web 与 DSH Surface 的真实岗位入口验证关键旅程及同一业务结果；React 18／19 的共享视图与审阅弹窗沿用既有浏览器合同。CLI／Agent adapter 验证 Catalog、窄 schema、context binding、人工审阅及 receipt 接线，不复制完整业务矩阵；扩展命令时同步对应 Operation Catalog、产品 Skill 及示例漂移测试。测试及人工审阅证据随实现补齐，不能用内部函数通过替代联合入口验收。至少覆盖以下断言：

- 支付核对账单、分配、原交易可退余额及预交金余额；重复提交、并发竞争、未知结果查询与重复回执不重复入账，未知资金结果阻断首次财务完成及清床，恢复后可继续。
- 待遇核对两类就诊与两类合成方案的目录内外、先行自付、起付线、比例、封顶、年度累计和个人账户；撤销及重结算不覆盖其他就诊后来的余额变化，不重复记累计。
- DRG 以固定规则和编码映射核对可复现的输入、分组及解释，覆盖无法入组、歧义、缺参数与编码不兼容；计划不当实际执行，预留替换不双计，既有收费和执行成本不被临床撤回抹去。
- 并发修改临床 revision、处方、他科费用或执行事实时，评估被标为过期；切换患者后的迟到响应隔离。价格、成本及规则更新不覆盖历史依据，正式开具前服务端重验依赖；过期审阅不能完成开具，重试不重复生成医嘱、收费或评估。
- 归档分组绑定冻结快照及来源哈希，模拟核定差异独立可查；后续更正、退款及医保补偿可核对，既有清床和归档不倒退，跨岗与跨 Workspace／Epoch 操作被拒绝。
- 四片验证后执行上述冠心病／PCI 联合验收，保留心衰、旧肺炎与冻结历史回归；界面同时验证空、加载、拒付、未知、过期、缺参数、无权限和恢复状态。

## 范围外

- 真实患者、真实支付渠道、真实医保或财政票据平台接入。
- 财政电子票据模拟、收费员交班交账及总账会计。
- 完整医院成本核算与分摊；沿用原规格的已覆盖成本估算及缺项说明。
- 门诊慢特病、异地、生育和大病保险等扩展待遇。
- 病案解档以及归档后诊断、手术操作和临床文书更正。
- 根据费用目标自动生成或修改诊断、操作和治疗事实。
- 在未核验来源、规则与对照结果前宣称正式地区分组或结算一致性。

## 依赖与风险

住院闭环已由 [PR #260](https://github.com/CaiZongyuan/clinmesh/pull/260) 合入，固定集成提交为 `93e79e53822824f7efd22f8aa825ee81ff943b31`；其范围由[住院规格](2026-10-20-inpatient-closed-loop.md)拥有。新增支付、医保与后续财务更正仍须在同一集成版本验证，不能以既有临床闭环验收替代。

住院端现有确定性预交金与补缴退款记录尚无支付尝试及结果未知恢复；主分支支付表则绑定门诊病例，两者需要共同明确账务交接。病案端临床编码与新增资料所需医保编码尚未证明兼容；资料包的病组权重和费用参考不能补齐患者待遇规则、本院项目价格或成本。

参考数据沿用离线准备、来源哈希固定、审核映射及不可变发布的方式，不让运行时扫描桌面 ZIP 或每次评估临时抓取公开网站。来源与使用条件、编码兼容、计价单位及可靠对照集由实施前的数据核验切片解决；未通过核验的记录或程序保持隔离，不静默启用。原件和生成资料继续保留在本地，公开源码只承载可公开的清单、实现及合同。
