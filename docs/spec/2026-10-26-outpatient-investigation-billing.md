# 门诊独立检验检查开单与收费

Status: approved

首次成稿：2026-10-26。执行追踪：[Issue #288](https://github.com/CaiZongyuan/clinmesh/issues/288)。本文件补充[门诊住院共享支付与 DRG 一体化](2026-10-15-drg-prescription-budget.md)中当前医生独立检查入口的接入范围；门诊合成价目、放行和取消退款规则已确认并获准实施。

## 问题与目标

当前医生从“检验检查”正式开立的独立检验、放射和病理会诊申请直接进入受理队列，没有生成门诊应收；现有门诊收费只接通兼容检验及药品。目标是从同一医生真实页面走通“正式开单 → 原申请应收 → 收费员分次或组合收款 → 全额覆盖后执行原申请”，并保留取消、失败、退款及结果未知的完整历史。

## 范围

- 门诊独立检验、本院胸片、胸部 CT 平扫及既往乳腺 H&E 切片病理会诊；继续遵守各类服务的启用、病例适用性和素材就绪条件。
- standalone Web、DSH Surface、CLI 和 Agent 复用共享 Command；负责医生管理申请，收费员处理资金，系统执行者按资金门禁受理和执行。
- 每个原申请关联唯一正式费用及同一次门诊的 Account、Encounter、Patient。相同就诊、相同类别的多个申请可以分别收费、恢复和放行；整次就诊账单聚合这些原费用。
- 新开立申请采用本规格的计价及放行规则。升级前没有收费关联的独立申请保留原行为与历史，不追溯收费；已有兼容检验、药品和住院流程保留原合同。

## 用户故事

1. 作为医生，我希望开单前看到本院项目价格和缺价原因，正式开立后区分待缴费、已放行及执行失败。
2. 作为收费员，我希望从收费队列找到原申请、服务名称和金额，分别办理部分收款、组合收款及未知结果查询。
3. 作为医生，我希望在允许的阶段取消原申请，保留原费用和已付资金，并由收费员办理原交易退款。

## 验收条件

- [ ] 从当前医生页面保存或修改三类草稿不产生费用；正式开立在同一 Command 事务创建原申请、冻结价目和唯一应收。响应丢失重放、并发提交及重复回执不重复计费。
- [ ] 同次就诊至少开立两个不同检验及一项放射申请，收费员按原 ChargeItem 选择、预览、确认和恢复；支付其中一项不会支付或放行另一项，账单与逐项明细可核对。
- [ ] 病理会诊的费用关联原病理申请及其冻结服务，来源手术仍只是既往病史引用，不成为本院手术收费。
- [ ] 医生及收费员能看到金额、币种、单位、数量、价格来源和版本；缺价、无效价目或不适用服务明确提示，正式开立失败且保留草稿，不产生零价应收或半成品申请。
- [ ] 未付、部分支付、拒付及未知结果不进入受理或执行；成功净资金与有效医保分配覆盖应收且无未知资金后，只放行原申请一次。原支付查询成功和医保全额覆盖也使用同一门禁。
- [ ] 取消与受理、付款并发时结果一致；取消后的旧 outbox、迟到支付结果或重复恢复不放行申请。未付款取消不产生退款；部分或全部付款取消后可关联原交易退款，退款未知不被当作成功。
- [ ] 原申请失败后重试沿用原价、费用及支付，不重复收费；失败后取消按本规格保留原账并办理退款。当前处于 `accepted`、`in-progress`、`reported` 或 `acknowledged` 的申请拒绝普通取消；`generation-failed` 按失败例外处理，报告与执行事实继续保存。
- [ ] 全额覆盖后受理与首次放行快照原子保存；已受理尚未开始时撤销待遇不使申请停滞或重复受理。取消后先完诊或发药仍可退款，待退及未知资金收敛前 Scenario Run 不提前完成，退款完成后可正常结束。
- [ ] 刷新、服务重启、原 Command receipt 恢复、跨岗位拒绝、负责医生校验及 Workspace/Epoch 隔离有回归；旧库非空迁移保留历史费用、预览、收付及在途申请。
- [ ] standalone Web 与 DSH Surface 均从医生真实开单入口贯通收费及后续执行；CLI/Agent 的窄 schema、精确目标、人工审阅与 receipt 复用同一 Command。
- [ ] 兼容检验 LIS、已完诊处方药房、住院送检及实际完成执行计费保持原行为，报告修订和原申请重试不重复记费。

## 设计决定

本节为已确认的业务规则。当前合同见[门诊原申请应收与执行](../architecture/clinical-workflows.md#门诊独立检查的应收与执行门禁)，架构取舍见[门诊申请应收与执行门禁决策](../decisions/implemented/architecture/2026-10-26-outpatient-investigation-billing.md)。

### 价目与计费时点

收费项目以本院服务的固定身份关联版本化 Charge Definition，声明门诊用途、单位、CNY 币种、整数分单价、生效日期及来源。正式开立数量固定为 1：检验按所选根项目计价，不把报告成员重复收费；放射按一次检查；病理按一次会诊，包含当前服务的一张既往切片，不包含取材、制片、免疫组化或分子检测。

已有仍有效且明确适用于门诊的本院正价可继续使用；默认国内检验目录的占位 `priceFen=0` 按缺价处理。本次新增独立版本的合成门诊价目 `synthetic-outpatient-investigation-2026-10-26-v1`，生效日为合成医院 Virtual Time 的 `2026-08-24`，覆盖当前基线病例。以下金额为已批准的仿真参数，不是已核验的浙江或真实医院价格；不从住院计价配置读取或继承价格。

| 服务身份 | 合成门诊价格 | 计价单位 |
| --- | --- | --- |
| `laboratory-panel-cn` / `2026-09-01` / `CN-LAB-CBC` | 2500 分 | 项目 |
| `wst-886-2026` / `2026` / `0100101A` | 800 分 | 项目 |
| `wst-886-2026` / `2026` / `0100501A` | 800 分 | 项目 |
| `imaging-chest-radiograph` | 8000 分 | 次检查 |
| `imaging-chest-ct-plain` | 30000 分 | 次检查 |
| `pathology-breast-slide-consultation` | 20000 分 | 次会诊 |

前两种检验编码系统的完整 URI 分别为 `https://caizongyuan.github.io/clinmesh/fhir/CodeSystem/laboratory-panel-cn` 与 `https://caizongyuan.github.io/clinmesh/fhir/CodeSystem/wst-886-2026`。国内检验按固定 `system + version + code` 映射，不按名称或旧基线服务 ID 猜价。其他项目有经过明确发布的门诊价目即可纳入同一接线；未配价时允许草稿、阻止正式开立，页面明确说明缺少本院门诊价格。

医生开立审阅展示当前价目；确认时服务端重验服务和价格版本，版本变化要求重新审阅。正式费用冻结价格、服务身份与单位；之后改价、参考资料同步、报告修订或原申请重试不覆盖原费用。

### 精确收费与临床放行

支付预览、持久化预览、确认、支付历史和查询恢复都绑定原 `ChargeItem`；`caseId + category` 仅可用于筛选，不能用于选择本次资金目标。新增放射和病理分类沿用共享账务、分次组合支付和原交易恢复；一个类别多笔费用的选择不得依赖数据库首行。

开立后的申请保留 `issued` 临床状态，另展示财务状态“待缴费／部分支付／结果待确认／已满足放行”。收款前不安排受理；共享申请内核在受理时重验当前资金、门诊费用关联及取消状态，在同一事务将申请改为 `accepted` 并冻结首次财务放行快照，记录原费用版本及确定资金依据。开始执行校验该原申请的有效放行快照与临床状态，拒绝没有许可的过早事件及已取消的迟到事件。住院和升级前未计费申请由其原有策略处理。

财务全额覆盖由成功收款减成功退款加有效基金、个人账户分配计算，必须没有未知收款或退款；取消申请即使净应收为零也不满足放行。放行事实唯一关联原申请，重复支付确认、查询恢复、医保确认及 outbox 派发不重复受理、执行或生成报告。付款后、受理前发生待遇撤销时仍按最新余额等待补收，再由同一门禁重新安排受理；受理成功后的待遇撤销及财务调整保留原放行快照，形成独立财务待办，不阻塞原开始事件、不回退或重复执行。

既有检验的合成医保映射继续适用于检验分类；新增放射和病理在本票显式映射为合成待遇目录外，页面可解释其自费金额，不套用检验先行自付比例。本票不新增待遇方案或真实医保规则。

### 取消、执行失败与退款

| 原申请状态及资金条件 | 允许动作与账务效果 |
| --- | --- |
| `issued`、未收款、没有未知资金或有效医保分配 | 原负责医生可取消；同一 Command 取消申请并追加关联原费用的全额冲减，保留原应收及原因，不创建资金退款 |
| `issued`、部分或全额已收款、没有未知资金或有效医保分配 | 原负责医生可取消并全额冲减；形成可退依据，收费员另行预览、审阅并按各原成功支付退款；临床取消不表示退款已完成 |
| `generation-failed`、未产生报告，资金条件同上 | 可重试原申请并沿用原费用；也可取消并全额冲减，已付资金由收费员按原交易退款 |
| `accepted`、`in-progress`、`reported`、`acknowledged` | 不开放普通取消；完成后的费用错误沿用收费员受控财务更正，不删除报告、执行、费用或原支付 |
| 任何允许取消状态，但存在未知收款或退款 | 拒绝取消及新的冲减、收退款，提示查询原尝试；取得确定结果后按最新状态继续 |
| 任何允许取消状态，但有有效医保分配 | 拒绝取消，提示收费员先按原结算撤销待遇，再按最新申请及资金状态处理 |

取消产生的冲减是受信临床事件派生的窄效果，只能覆盖该原申请尚未冲减的金额；医生不获得任意财务更正或退款权限。未取消的新独立申请在首次放行前不允许通过普通费用冲减降低放行金额；发现价格错误应先取消再按正确价目重新开立。已取消申请拒绝新收款、重试和受理，允许查询原未知资金及退还原成功款。

退款复用已交付的 [#269](https://github.com/CaiZongyuan/clinmesh/issues/269) 原交易退款，不新增自动退款渠道。原款可退余额、各方式余额、跨交易共享冲减额度、未知退款预占及查询恢复沿用[现有退款合同](../architecture/clinical-workflows.md#85-收费支付与退款)。部分付款取消时全额冲减原应收，但只退实际净收款；未收部分不形成虚构退款。取消与受理、付款确认或医保确认竞争时在共享 Command 事务重验版本及资金状态，过期动作返回冲突并要求刷新。

本票取消产生的待退款或未知退款未收敛前，Scenario Run 保持 active；医生可按原临床条件完诊，药房可按原条件发药，不能仅由这两项动作提前完成 Run。全部应退资金确定成功、没有其他未决资金且原有病例完成条件已满足后，沿用统一完成检查结束 Run；退款确认及查询恢复都调用该检查。此门禁仅针对本票产生的取消退款责任，不重新打开升级前已经完成的 Run。

### 兼容与恢复

新申请持久化其计费策略和唯一原费用关联，不能通过“是否碰巧找到费用”来猜测历史策略。升级前没有计费关联的独立申请不补收、不阻断；旧兼容检验和药品已存在的零元兼容行为仍仅适用于旧流程。新旧策略在重启后保持不变，当前开放的旧支付预览必须仍能精确恢复其原费用，不能绑定到迁移后新增申请。

门诊独立申请不占用兼容流程的病例级单个 `service_request_id`，不把整个病例切成旧 `awaiting-lab-payment`，也不因某一项收费关闭当前医生工作任务。多申请的收费、执行、报告及完诊门禁仍由各自 owner 判断。

## 测试策略

主要业务矩阵通过公开 HIS HTTP Query/Command、响应 schema 和临时文件 SQLite 验证。采用确定性支付模拟器、合成病例和受控检验结果 Provider，覆盖精确费用目标、两项同类申请、跨类申请、医保全额覆盖、部分与组合支付、拒付、未知查询三结局、取消竞争、执行失败重试、冲减退款及重启。增加受理前及受理后撤销待遇的时序断言，并从“已付取消 → 完诊／发药 → 原交易退款”验证 Run 不提前完成，退款查询收敛后只完成一次。迁移从非空旧库开始，核对原费用、旧预览、资金、原申请及历史免费策略；对受理的资金守卫和开始的放行快照守卫分别验证，不能只证明没有入队。

Playwright 在 standalone Web 与 DSH Surface 从当前医生“检验检查 → 添加 → 加入申请 → 开具选中项目”真实入口开始，分别覆盖检验、放射和病理，再切收费员查看原费用并完成收费，返回医生观察原申请执行。至少保留一次部分组合支付、一次未知刷新后原尝试恢复，以及一次取消后原交易退款的浏览器旅程；页面检查空、缺价、过期审阅、待缴费、部分支付、未知、取消待退款及跨岗拒绝。DSH 共享审阅组件验证 React 18/19 与 ShadowRoot；其接线证据不能由 standalone 或单独挂载收费组件替代。

CLI/Agent 只验证精确 ChargeItem 目标、context binding、权限、人工审阅和 receipt 接线，复用服务端完整业务矩阵。Agent-facing schema 或错误恢复合同变化时，同一 diff 更新 owning Operation Catalog、对应 `clinmesh-*` Skill 和命令示例漂移测试。

不通过直接插入费用、调用旧 `issue-laboratory-order` 预造应收或真实模型请求替代新入口验收。放射及病理只观察文字状态、报告引用和聚合统计，不读取真实影像像素或截图。

## 范围外

- 真实医院价目核定、浙江服务价格资料的新增采集和完整自动映射，以及真实支付或医保渠道。
- 急诊绿色通道、先执行后补款、减免审批、动态折扣、未配价项目免费执行。
- 新增放射模态、病理取材制片、按多张切片收费及新增检验生成能力。
- 对升级前未计费独立申请追收；改变住院送检、执行后计费或出院结算规则。

## 依赖与风险

当前本地 Reference 接线不含浙江医疗服务价目；默认国内检验价格是零占位，放射只有住院专用价格，病理没有现成价格。本规格采用独立的合成门诊价表及明确适用范围，不能将其金额写成已有真实价格。真实参考价的来源核验和逐项映射不属于本次实施。

当前收费与支付类别限制为兼容检验和药品，支付预览按病例与类别关联费用；需同步迁移存储、contracts、共享账务、医保映射及各 adapter。以任务起点 `91f3cce7` 为集成基线；#268、#269、#270、#271 的已交付能力可复用，本票不再等待原交易退款切片。
