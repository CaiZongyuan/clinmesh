# AI 原生医生工作台改版

Status: draft

本文定义医生岗工作台从"左队列 + 右病例"到 AI 原生三栏布局的正式需求与验收条件，覆盖独立 Web 与 DSH Surface 两个面。方向选型与队列安放的本机设计参考为 `docs/ui/references/2026-10-19-ui-direction-comparison.html`（不随 Git 同步）；已确认结论、验收条件与回落边界由本文拥有。视觉 token 合同由 [ClinMesh UI 设计合同](../ui/design.md) 拥有，本改版实施时同步更新该合同；DSH Surface 挂载合同见 [Surface 与 Host 边界](../architecture/agent-integration.md#71-surface-与-host-边界)。镜像布局预设相对会话嵌入路线（B）的取舍在实施时以 Agent Note 记录理由。

## 问题与目标

用户对整体 UI 不满意：视觉气质平淡（接近后台工具，缺乏产品感），且六个岗位共享同一"左列表 + 右表单"骨架，未能体现"Agent 参与整个 HIS"的产品定位。医生工作台是旗舰岗位与演示门面。

目标是把医生工作台重构为 `[医生↔助手对话 | 病例工作区 | Agent 建议栈]` 的 AI 原生布局，并以此带动全局视觉基线升级：独立 Web 与 DSH 两个面一致受益，助手能力完全复用 DSH 原生助手，不自建。

## 范围

- 医生岗门诊诊疗工作台的信息架构改版，覆盖独立 Web（`apps/web` 自有壳）与 DSH Surface（`apps/dsh-web` 桥接）两个入口。
- 全局视觉 token 基线（色彩、字重、密度、选中与反馈语言）应用于共享 `packages/ui` 组件；其余五个岗位只接受共享 token 的视觉刷新，不改骨架。
- 助手为 DSH 原生助手；其会话列经 `dsh-react-surface`（自有桥接仓库）新增的"会话在左"镜像 workspace 预设移到 ClinMesh 内容区左侧。
- 队列在 DSH 面以"助手管辖的队列卡片"存在于助手列；独立 Web 保留左队列列。
- 建议栈为共享组件，数据源为确定性服务。
- 独立 Web 深色主题 selector 缺陷（`.dark` 与 `[data-clinmesh-app]` 选择器错位）作为本需求前置修复。
- 既有 Agent section 合同（`data-agent-section`、`data-agent-selection`、`data-agent-consultation`、`DoctorCaseSection` 枚举）、portal 合同、React 18/19 共有 API 约束、宿主 overlay 层级与单文件产物预算保持不变。

## 用户故事

1. 作为医生，我希望进入门诊诊疗就看到助手对话在左、病例在中、建议栈在右，Agent 的参与一目了然。
2. 作为医生，我希望在助手列顶部一眼扫到今日队列，点击即切换患者，或直接对助手说"叫下一个"。
3. 作为医生，我希望病例区五个业务页签的操作习惯不变，完诊进度和生命体征仍然首屏可见。
4. 作为医生，我希望右栏持续告诉我完诊还缺什么、质控有什么疑点、有什么推荐，不依赖我主动询问。
5. 作为独立 Web 的使用者或演示者，我希望没有助手时布局自然退化为"队列 | 病例 | 建议栈"，视觉同样现代。

## 验收条件

- [ ] A1 独立 Web：门诊诊疗呈现"左队列 | 中病例 | 右建议栈"，无助手列；左队列的选择、在诊/待诊/完诊页签与现状等价。
- [ ] A2 DSH 面：镜像预设生效，原生助手会话列位于 ClinMesh 内容区左侧，内容区为"中病例 + 右建议栈"；宿主对侧栏、主题、locale 的所有权行为不变。
- [ ] A3 队列卡片（DSH 面）：可扫读（在诊/待诊计数与患者列表）、点击切换当前病例、支持经对话指令叫号切换。若宿主不支持会话内钉顶，卡片以默认收起形态贴内容区左缘，功能等价。独立 Web 不要求队列卡片。
- [ ] A4 建议栈：内容来自确定性服务（完诊清单未完项、质控疑点、医生推荐），不依赖助手会话存在；空态、加载态、服务失败态有明确展示，不把失败表示为建议缺失之外的成功状态。
- [ ] A5 病例区：问诊记录、病历记录、检验检查、诊断、处方五个页签功能与现状等价；患者横幅压缩后仍提供身份、分诊级别、完诊进度与生命体征；Agent 工具依赖的 section 钩子与选择合同不变。
- [ ] A6 视觉基线：新 token 基线应用于两面的医生工作台与共享组件；独立 Web 深色主题真实生效（深色 token 作用于应用子树）；DSH 面随宿主 colorScheme 切换正确渲染；三档字号与 zh-CN/en-US 组合可用。
- [ ] A7 响应式：布局断点全部基于容器查询；在 Surface 最小 360px 与 `shrink` 回落约束下，窄宽度时建议栈折叠为页签或抽屉，任何宽度不产生横向滚动或内容截断。
- [ ] A8 工程合同：共享代码只用 React 18.3.1 与 19.2 共有 API；浮层统一挂载 ShadowRoot portal root；不抬高宿主 overlay 层级；DSH 单文件 lazy-CJS 产物通过 `verify-artifact` 校验。
- [ ] A9 既有 Agent 反馈语言在新布局中继续工作：`agent-workspace-glow`、`agent-action-feedback`、`agent-review` 在三栏结构下可见且位置正确。

## 设计决定

以下为已确认结论：方向取 AI 原生工作台（对比页方向四）；助手直接使用 DSH 原生助手，不自建任何助手能力；助手左移采用 `dsh-react-surface` 镜像布局预设——助手保持 100% 原生（会话 UI、工具绑定、Composer 零迁移），改动为布局几何级、可回退；会话嵌入主面板的路线 B 保留为终态候选（能力对比见 [DSH 插件路线研究](../research/dsh-plugin-integration-options.md)）。队列采用方案 C：队列卡片置顶助手列，队列是助手管辖的工作流状态而非独立界面部件。独立 Web 只承接共享部分受益，不补助手。建议栈数据源为确定性服务，助手增强后置。视觉基线采用对比页方向四的视觉语言（浅色画布、靛紫点缀、环绕柔光反馈），两主题同等成立。

实施顺序：第一步在 `apps/web` 完成三栏骨架、病例区现代化、建议栈组件与共享视觉 token（独立 Web 面就此完整受益）；第二步并行推进 `dsh-react-surface` 镜像预设与原型验证点（队列卡片钉顶、单 Composer、窄屏回落）；第三步在 DSH 宿主集成验收。

## 测试策略

组件层：扩展 `responsive-layout` 与医生工作台组件测试，断言三栏模板、折叠断点与队列列行为；文案覆盖中英文。独立 Web 真实入口：Playwright 覆盖浅/深主题、三档字号与窄视口回落，入口遵循[测试策略](../testing.md#用户界面验证)。DSH 面：扩展 `apps/dsh-web` browser fixtures（React 18/19、ShadowRoot、container query），并以 `dev:dsh` 手工验收镜像布局、队列卡片与双主题。上游：`dsh-react-surface` 预设改动在该仓库测试并提 PR，随后推进 `dsh-upstreams.lock.json` 并通过 `verify-artifact` 升级验收。

## 范围外

独立 Web 自建助手能力；路线 B（助手会话嵌入应用主面板）迁移；其余五岗位的信息架构变更；[独立 Web UI 评审](../research/2026-10-19-workspace-ui-review.md)中与本改版无关的缺陷（枚举与内部数据泄漏、目录默认排序、药品包装文案、问诊聊天密度细节），另立任务；移动端；患者问诊对话的交互重做（保留为病例区页签）。

## 依赖与风险

在上游原型与锁定升级验证通过前，本规格保持 `draft`。`dsh-react-surface` 布局引擎需支持会话列换位；若几何模型不支持，回落为"助手留在宿主右列 + 内容区两栏"，重新确认布局决定。队列卡片钉顶依赖宿主会话内卡片能力，回落方案已在 A3 定义。DSH Surface 宽度为宿主扣除侧栏、会话与右栏后的剩余空间，三栏在窄屏会频繁触发回落，须以容器查询与折叠设计兜底。`dsh-upstreams.lock` 推进须走既有升级验收，期间 DSH 面新布局不得先行合入 main 宣称验收。
