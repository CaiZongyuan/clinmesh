# 文档归属与结构整理

Status: implemented

## 问题与目标

系统架构把当前合同、研究、测试和实现状态放在同一长文中；工程记忆混合协作偏好、产品描述及多种运行经验。读者难以按任务找到唯一的事实归属，文档入口和公开导航也有遗漏。借鉴 Bio Discovery X 的渐进式导航、文档职责划分及生命周期管理，按 ClinMesh 已有 owner 和 Agent Note 体系整理。

## 范围

- 保留 `docs/architecture.md` 作为系统架构唯一入口，将详细合同拆入少量按职责划分的架构文档；当前合同、参考研究和测试要求分别回到对应 owner。
- 保留 `docs/memory/memory.md` 作为工程记忆入口及稳定协作偏好 owner，把低频操作经验按使用场景拆分，保留仍有价值的条件、失败模式、验证方法和来源。
- 明确当前合同、Agent Note、正式需求、研究和记忆的职责，补齐导航与规格生命周期；保留现有未完成或仍承担独有验收合同的规格。
- 同步仓库内引用、文档站 manifest 和导航；公开架构入口 URL 保持可用，新详细文档拥有独立页面。
- 保真保留任务开始时已有的规则、文档和其他工作区修改。

## 用户故事

1. 作为开发协作者，我希望从短入口找到当前任务的 owner，而不必读完整架构或全部工程记忆。
2. 作为维护者，我希望当前合同、决策理由和任务验收各有唯一归属，避免改一处遗漏另一处。
3. 作为文档读者，我希望导航及引用在整理后仍能到达对应内容。

## 验收条件

- [x] 系统架构入口列出详细 owner、适用任务及相邻文档；迁移前的有效合同、失败边界和安全约束均有去向。
- [x] 工程记忆按场景可检索，稳定偏好和原有有价值的操作经验得到保留，产品合同继续引用正式 owner。
- [x] 文档归属表覆盖架构、指南、UI、领域、规格、Notes、研究和记忆；规格完成后的维护与删除条件明确。
- [x] 未完成规格、仍有独有验收信息的已完成规格及有效决策得到保留，不把整理当作业务验收。
- [x] 仓库内迁移路径与锚点引用同步，公开入口与指南侧栏可达；文档投影检查和构建通过。
- [x] Standards 与 Spec 使用相同任务前快照和完整最终变更并行审查；已有未提交内容未经授权不被覆盖或丢弃。

## 设计决定

沿用 ClinMesh 的 `docs/spec/` 正式需求和 `docs/decisions/` 决策体系，不新增 ADR、归档目录或另一份当前合同。拆分按阅读任务和事实归属，不照搬参考项目的目录数量。架构章节的有效要求和记忆条目优先保真迁移；只清理已核实重复、已被替代或纯导航性的文字。已完成规格只有在独有要求已经迁入当前 owner、活跃任务不再依赖且引用修复后，才可删除。

分工与取舍见[文档归属决策](../decisions/implemented/process/2026-10-19-documentation-ownership.md)。本地文档预览的仓库源码链接默认指向本仓库 `main`，显式构建环境仍可绑定仓库与精确 revision。

## 测试策略

使用 `pnpm doc-sync` 覆盖 Markdown、Agent Note、文档投影测试及 VitePress 构建。针对迁移额外核对原章节／记忆条目的去向和旧锚点引用，避免仅靠文件存在检查判断完整性。通过文档站实际入口验证新增 owner 和指南导航。纯文档与发布导航配置变更不运行无关业务测试或真实模型验收。

## 范围外

业务行为、FHIR/API/数据库和授权合同变更；GitHub 仓库设置；skills 安装或上游内容修改；批量清理其他任务 worktree；自动标记未完成需求为已验收；无依据删除规格或决策。

## 依赖与风险

迁移可能遗漏相对链接、旧锚点或条件语义。任务基于当前工作区完整文档快照实施，迁移后核对去向及引用，并在最终集成结果上验证和审查。既有未提交修改与本次变更分别核对。
