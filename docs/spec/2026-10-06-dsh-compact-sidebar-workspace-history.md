# DSH 固定窄栏与工作区会话历史

Status: approved

## 问题与目标

当前 DSH 左栏同时承载品牌、新会话、岗位导航、工作区和会话浏览，占用诊疗与对话的横向空间。目标是在 DSH 分屏中保持可识别的窄栏，把会话与工作区操作放进对话区历史弹层，同时保留真实 DSH 会话和工作区状态。

## 范围

- 左栏默认收起，保留宿主手动展开与收起能力；收起和展开时都只显示 ClinMesh 品牌、当前岗位入口及底部“医院工作台”“设置”。收起态品牌沿用宿主的展开按钮；岗位入口保留导航、选中态、可访问名称与悬停提示，左栏跟随宿主主题。宿主原生新会话和工作区浏览区域不再显示。
- 对话区顶部提供新会话 `＋` 和历史按钮；无会话和已有会话时均可使用。新会话沿用 DSH 对当前、选中或最近工作区的选择规则。
- 历史弹层默认只显示当前工作区选择、搜索、最近会话和归档入口；工作区新增、重命名和删除进入更多菜单。新增沿用 DSH 目录选择与注册语义；删除只移除注册，不删除会话日志或文件。
- 会话行支持切换、重命名、置顶与取消置顶、fork、归档和恢复。归档活动会话时沿用 DSH 的拒绝及确认停止边界；已归档会话可从归档入口或搜索结果找到。
- 搜索沿用 DSH 的标题、工作区和会话内容匹配能力，结果、取消和失败状态以宿主为准。弹层只保存打开、输入和菜单等界面状态，不复制会话、工作区或医院业务数据。

## 用户故事

1. 作为医生，我希望窄栏保留当前岗位图标和提示，以便快速返回岗位页面。
2. 作为用户，我希望左栏初次打开时收起，需要时仍能通过宿主品牌控制展开或收起。
3. 作为用户，我希望通过对话区 `＋` 创建会话，并沿用当前工作区上下文。
4. 作为用户，我希望在无当前会话时仍能搜索和打开历史会话。
5. 作为用户，我希望按标题、工作区或内容搜索会话，并切换到结果。
6. 作为用户，我希望选择、新增、重命名或删除工作区，同时清楚知道删除范围。
7. 作为用户，我希望从会话行完成重命名、置顶、fork 和归档，而不离开对话区。
8. 作为用户，我希望查找并恢复归档会话，搜索时也能看到匹配的归档结果。
9. 作为用户，我希望操作失败或请求过期时保留当前选择并收到可理解的提示。
10. 作为键盘用户，我希望能打开、操作和关闭弹层及菜单，并看到焦点位置。

## 验收条件

- [ ] DSH 分屏中的左栏默认收起并允许手动往返；两种形态都只显示品牌、岗位及底部入口，岗位与底部入口仍按权限和当前状态工作。
- [ ] 历史按钮和新会话 `＋` 在无会话与已有会话的标题栏均可到达；打开的弹层不遮挡自身必要操作。
- [ ] 最近会话、当前选择、工作区及搜索结果来自 DSH；切换后显示正确会话，迟到结果不覆盖更新的选择。
- [ ] 工作区新增、重命名、删除与会话重命名、置顶、fork、归档、恢复均执行 DSH 原有操作与错误边界。
- [ ] 归档入口与搜索能到达已归档会话；恢复后列表状态更新，活动会话归档拒绝可恢复。
- [ ] 空、加载、失败和无权限状态有可见反馈；主题、窄窗口、键盘与全屏往返不丢失可用入口或会话草稿。
- [ ] 插件卸载后释放新增入口并恢复宿主原有行为；独立 Web 的侧栏不受影响。

## 设计决定

- 弹层界面归 ClinMesh 的 DSH client adapter；Session 与 Workspace 的读取、搜索和变更仍由 DSH 控制器拥有。
- 默认弹层保持紧凑，低频操作放在更多菜单或会话行菜单；不提供分组/树形/平铺视图切换、手动排序和“全部/最近/已归档”筛选栏。
- ClinMesh 不修改 DSH 官方源码。默认收起调用宿主公开布局操作一次，后续手动展开由宿主拥有；工作区区域经现有 Slot 处理，原生新会话按钮使用限定在当前宿主侧栏的显示兼容规则，并通过真实入口及升级回归验证。
- 此需求改变了 [既有侧栏导航决定](../../.agents/notes/implemented/architecture/2026-09-14-dsh-inline-workspace-routes.md) 中的展示位置；实施时更新对应 Agent Note 和当前状态文档。

## 测试策略

以真实 DSH 页面上的可观察行为为主要验收入口；Slot/Adapter 测试覆盖注册与卸载、会话及工作区操作、失败与过期结果。测试通过公开交互和控制器结果断言，不锁定弹层私有结构。浏览器验证覆盖无会话与已有会话、亮暗主题、窄窗口、键盘及全屏往返；仅使用合成数据。

## 范围外

- 独立 Web、HIS 临床业务流程、Agent Tool、模型输入与会话持久化协议。
- 已取消的视图切换、手动排序和筛选栏；不因迁移恢复这些控件。
- 固定锁定窄栏与把收起态品牌改为静态标志；用户仍可手动展开。
- 修改 DSH 官方发行包或维护宿主补丁。

## 依赖与风险

DSH `0.2.0-rc.2` 没有独立替换原生新会话按钮的 Slot。兼容规则必须只影响该按钮，不影响对话区的新会话入口、品牌展开控制、设置或其他应用；宿主升级时重新验证选择器和窄栏行为。弹层重做展示，但 Session 与 Workspace 的操作仍使用 DSH 公共控制器，不复制其持久化状态。
