# 医生主诉展示同步与分诊差异质控优化

Status: implemented

## 问题与目标

医生修改病历主诉后，门诊号旁仍展示分诊员记录的旧版主诉，容易让医生误以为修改没有生效。医生还反馈，修改后有时仍收到主诉有区别的质控提醒。页头固定读取分诊投影的问题已用合成组件探针复现；偶发质控提醒尚未完整复现，不能把输入结构上的风险直接当成已确认的全部根因。

目标是让医生工作台页头反映当前病历主诉，并让质控区分分诊初记、后续补充、明确更正与尚未解释的事实冲突。分诊原记录继续保留，医生直接编辑病历，不增加逐条确认步骤。

## 范围

- 独立 Web 与 DSH 共享医生工作台中，门诊号旁的主诉展示，以及当前病历主诉相关的质控输入和提示。
- 当前病例的工作稿、已保存草稿与最新签署文书之间的展示归属，以及保存、刷新、病例切换和只读状态。
- 分诊原文及其派生摘要的来源身份、可用时间和更正上下文；沿用本次就诊的质控范围、生成与独立复核机制。
- 保留既有显式保存、版本冲突、授权、审计、不可变签署和质控仅提示的边界，详见[临床业务流程](../architecture/clinical-workflows.md)与[病历质控规格](2026-10-15-doctor-document-quality-control.md)。

## 用户故事

1. 作为医生，我希望修改主诉后页头立即反映当前工作稿，保存并刷新后仍显示同一版，清楚区分未保存内容。
2. 作为医生，我希望补充症状、调整措辞或依据问诊更正分诊初记时，不因两版文字不同而反复收到提醒。
3. 作为医生，我希望患者原话、医生补充或报告与病历存在真正冲突时，仍能看到具体需要核对的事实，并直接修改正文处理。

## 验收条件

- [x] A1：当前病例存在编辑工作稿时，页头主诉与病历编辑器使用同一份当前正文；主诉有未保存修改时呈现未保存状态，不为页头同步或质控隐式保存病历。
- [x] A2：保存成功、刷新和病例切换后，页头恢复该病例当前已保存的主诉；只读文书展示最新签署版本。无医生文书时沿用分诊初记，分诊也缺失时如实显示未记录。保存失败或版本冲突不能显示为保存成功，也不能丢失当前工作稿。
- [x] A3：医生明确清空已有文书的主诉后，编辑期间和保存刷新后均保持为空或显示未记录，不回退到旧分诊内容；质控仍可提示适用的实际空字段。
- [x] A4：保留分诊原记录及其可追溯身份，医生修改病历不覆盖分诊原文。质控能够识别分诊初记及其派生摘要，同一底层分诊事实不作为两份独立佐证；去重不丢失生命体征等独有事实。
- [x] A5：分诊初记、患者问诊、医生补充、报告和病历版本保留各自来源及可用时间；明确更正由实际来源和关系支持，不按保存时间先后自动判断谁正确，不伪造旧数据缺失的时间。医生编辑归属是版本上下文，不自动成为该正文正确的独立证明。
- [x] A6：同义改写、合理概括、有来源的补充、不同时间的合理变化及已有依据的明确更正，不仅因与分诊文字不同而产生不一致提醒。例如分诊记“头晕”，问诊支持医生补充为“反复头晕一周，近两日加重”时，不应提示两版主诉必须一致。
- [x] A7：同时间、同语境且尚未解释的实质冲突继续提示具体事实及最小核对动作。例如本次患者明确否认胸痛而病历写有胸痛时，不能因医生编辑过该字段就压制问题；不使用笼统的“主诉有区别”代替事实说明。
- [x] A8：正文或相关来源变化后，旧质控结果失效并按现有机制更新；迟到结果不能恢复旧提醒或覆盖新正文。未保存候选与持久草稿继续隔离，病例、授权、Workspace/Epoch 和版本边界保持有效。
- [x] A9：Web/DSH 不新增“已核实”“确认保留”、原因填写或逐条确认，不增加签署阻断。医生通过编辑正文或补充实际信息处理问题；检查未完成、失败或资料不足时，不宣称质控通过。
- [x] A10：回归同时覆盖不应提示的正常整理样本和仍须提示的真实冲突样本，并从真实 Web 与 DSH 共享入口验证主诉编辑、清空、保存刷新、切换病例和签署后只读展示。

## 设计决定

当前病历拥有医生主诉，页头从其投影，不额外维护第三份可写主诉。当前病例工作稿只影响当前工作台的展示；持久服务端状态仍由 TanStack Query 管理。分诊记录是初始观察，不能作为要求医生病历逐字一致的模板，也不能因存在较新文书就失去全部证据价值。

质控沿用[现有输入归属与独立复核](../decisions/implemented/architecture/2026-10-15-doctor-document-quality-control.md)，在必要上下文中表达来源角色、版本及有依据的更正关系。不得把待检查正文复制成一条可信医生来源，以此消除来源矛盾；也不通过整体排除分诊证据、永久忽略主诉或单纯过滤提醒文字解决问题。提示和签署边界继续遵循[直接编辑与仅提示决策](../decisions/implemented/architecture/2026-10-18-advisory-quality-without-confirmation.md)。

来源投影与更正关系方案见[当前主诉决策](../decisions/implemented/bug-fix/2026-10-20-current-chief-complaint.md)；当前行为由[临床业务流程](../architecture/clinical-workflows.md)拥有。

## 测试策略

以现有 `apps/web/src/app/doctor/patient-summary.test.tsx` 和医生病例控制器、病历编辑及质控测试作为前端 seam，验证页头和编辑器一致、清空不回退、保存失败不丢稿、当前病例隔离及最新签署件展示。通过公开 HIS HTTP 和 file-backed SQLite 验证分诊原记录保留、输入来源身份及去重、人工编辑归属、更正关系、当前结果指纹和迟到结果保护。

语义回归只替换外部模型网络边界，覆盖生成候选与独立复核的不应提示、应提示及否定结果；替身测试不证明真实模型的临床准确性。实施前将偶发差异提醒收敛为可运行的合成场景；若没有复现，明确区分已验证的页头修复与未证实的质控根因。按[用户界面验证](../testing.md#用户界面验证)使用 Playwright 验证真实病历入口，并覆盖共享代码的 React 18/19 与 ShadowRoot 合同。

合成语义场景固定为：分诊“头晕一周”后的同义改写、体位相关概括、问诊支持“近两日加重”、早上头晕目前缓解、患者明确更正为三周，以及患者明确否认本次胸痛而正文肯定胸痛。前五类的差异候选应能被独立复核拒绝，最后一类须保留具体冲突；并保留患者自述发热与分诊测温的既有来源边界。生成与复核同时读取原始来源和派生关系，待检查正文不能新增为可信医生证据。

文档阶段只运行相应文档检查；实现阶段按实际变更运行最小回归，跨包接口或协议变化再执行仓库要求的完整检查。

## 范围外

- 覆盖或删除分诊原始记录，按编辑时间自动认定临床事实正确，或将所有主诉差异永久忽略。
- 新增自动修正文书、自动确认事实、逐条来源展开、核实保留流程或签署门禁。
- 重做候诊队列、分诊工作台、Mobile、全量既往病历加载、诊疗合理性质控或模型用量监控。
- 真实模型评测、压测、影像像素读取和未经测量的准确率、费用或延迟承诺。

## 依赖与风险

无已知外部实施阻塞。本项作为一个纵向切片追踪，页头同步与质控对当前主诉的解释共同验收。真实模型偶发误报的完整输入及全部根因尚未复现；合成回归证明来源投影及双阶段复核接线，不代替真实模型质量评测。来源缺失、语义判断失败及历史数据不完整继续如实表示，不能通过重复投喂待检查正文或扩大模型预算伪造确定性。
