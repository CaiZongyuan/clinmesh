# 问诊病史的 Agent 总结与患者自述溯源

Status: implemented

本文拥有总结忠实性、多轮事实归并与患者自述溯源要求。五字段分类、直接写入、页面展示和签署行为由[病历字段补齐与问诊自动记录](2026-10-14-clinical-document-fields.md)拥有。

## 问题与目标

PR #165 测试中，自动记录把患者回答按句拆成原文摘录，再加上“患者自述：”写入病历。现有来源校验与追踪解决了摘录真实性，但正文仍是对话片段堆积，医生需要再次整理。目标是让 Agent 理解本次问诊的已公开患者自述，生成简洁、连贯的病史总结，并在后台保留支撑它的患者原话关联。

## 范围

承接现有 DSH 门诊问诊自动记录，覆盖主诉、现病史、既往史、家族史及过敏史，用药自述归入既往史。正文是 Agent 总结；可信来源是本次 Consultation Record 中已保存的患者回答。一个总结可以汇集多轮回答，同一轮回答可以支撑多个总结事实。患者自述证明患者表达了什么，不等同于已经核实的客观事实。

## 用户故事

1. 作为医生，我希望 Agent 合并跨轮的相关病史、去除重复与无关措辞，并按病历字段整理，而无需再次改写原话列表。
2. 作为医生，我希望自动整理有可追溯的原始患者回答依据，病历页面只显示整理后的正文。
3. 作为医生，我希望总结保留患者的否定、时间、数值、程度和不确定性，且新增回答或更正不会静默覆盖人工编辑。

## 验收条件

- [x] A1：完整患者回答保存后，Agent 自动生成病史总结；可归并相关信息、去重并改写口语，不以逐句复制并统一添加“患者自述：”作为总结结果。
- [x] A2：多轮相关回答形成连贯病史；相同事实再次出现不重复堆积，明确更正更新相关自动总结，无法确定的矛盾保留原陈述并追加待核实措辞。
- [x] A3：每项总结中的患者事实均能追溯到实际保存的患者自述；后台保留原回答、对应轮次与相关引用，合并多轮信息时保存全部必要来源，来源原文保持不变。
- [x] A4：总结不补造患者未表达的信息；保留否定、时间、数值、程度和不确定性。不把自述的居家测量、外院诊断转成本院查体、检查结果或医生诊断。
- [x] A5：没有可总结事实时不生成占位病史或阴性结论；总结中无依据的事实、伪造来源和错误关联不得自动写入草稿。
- [x] A6：总结与来源关联在保存、刷新、切换病例后仍持久保留，并严格保持患者、Encounter、Workspace/Epoch 隔离。
- [x] A7：沿用自动触发、局部人工编辑保护、暂停补录、重试和签署冻结边界；模型失败不阻断已保存的问诊，迟到结果不覆盖人工内容或已签署文书，无逐条确认或撤销流程。
- [x] A8：用多轮合成问诊从真实 DSH 入口验收实际总结质量及后台来源关联，人工核对结果确实归纳病史并忠实于自述；仅有合法 JSON、原文匹配或调用成功不足以通过本需求。

### 合成验收示例

患者第一轮回答：“昨天晚上开始发烧，最高量到38.5度，还咳嗽，但是没有痰。”第二轮回答：“咳嗽也是昨晚开始的，胸口不疼，也不觉得喘。”

可接受的现病史总结为“昨晚起发热伴干咳，自述最高体温38.5℃；否认胸痛、气促。”起病、症状和体温关联第一轮自述，咳嗽起病及胸痛、气促的否定关联第二轮自述。措辞不要求逐字相同，但信息必须准确、无重复且关联两轮原话；不得新增“考虑肺炎”等诊断或“听诊正常”等检查事实。

## 设计决定

正文总结与患者原话承担不同职责：总结服务病历阅读，原话服务依据核对。允许总结改写、归并并引用多轮来源；不能继续要求病历正文与单条引用逐字相同。沿用 ClinMesh 的 Query、共享 Command、持久任务、模型桥接和审计，不读取 Case Truth、未公开档案或 Assistant reasoning。

总结以语义片段保存，有序事实分别关联全部必要患者引用。确定性来源检查与独立模型忠实性核对共同把关；核对失败不写草稿。相关新信息更新一个自动片段，保存前一版本的来源历史；组内人工编辑保护该总结组，后续患者更新另行记录。后台持久保留逐项来源关联；页面无自动记录来源区和来源弹窗。旧摘录保留原文和来源，旧回执兼容缺省的新字段。取舍与概率性语义核对限制见[Agent Note](../../.agents/notes/implemented/architecture/2026-10-12-consultation-agent-summary-sources.md)。

## 测试策略

通过公开问诊 HTTP、病例 Query 和 file-backed SQLite 验证总结、来源关系及人工保护，覆盖跨轮归并、重复、否定、不确定表述、数值与时间、明确更正、矛盾、伪造引用、无依据事实、并发编辑、重试与签署。外部模型边界可使用确定性替身，但替身必须输出改写后的总结并关联真实原话，避免把逐字摘录等同于总结。

Playwright 从真实产品入口验证总结可读性与无来源入口；共享 Surface 交互按需覆盖 React 18/19 和 ShadowRoot。真实 DSH 辅助模型使用合成病例有限样本，逐项核对总结是否忠实且有用；常规 CI 不依赖真实凭据或付费调用。

## 范围外

本需求不扩展为自动诊断、检查检验推荐、治疗计划、处方或自动签署。医生聊天补充来源和全病历整理由 [#177](https://github.com/CaiZongyuan/clinmesh/issues/177) 追踪，本需求仅完善患者问诊病史的总结与溯源。

## 依赖与风险

依赖已合入 main 的 PR [#165](https://github.com/CaiZongyuan/clinmesh/pull/165) 的自动记录基础及 DSH 辅助模型能力。

总结已通过确定性来源检查与独立语义核对后写入，兼容既有草稿、旧摘录和人工编辑。语义模型仍有概率性限制；合法 JSON 与原文匹配不能单独证明事实忠实性。自动触发与任务恢复要求见[问诊自动记录规格](2026-10-08-consultation-auto-record.md)。
