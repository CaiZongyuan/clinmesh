# 问诊病史的 Agent 总结与患者自述溯源

Status: draft

## 问题与目标

PR #165 测试中，自动记录把患者回答按句拆成原文摘录，再加上“患者自述：”写入病历。现有来源校验与追踪解决了摘录真实性，但正文仍是对话片段堆积，医生需要再次整理。目标是让 Agent 理解本次问诊的已公开患者自述，生成简洁、连贯的病史总结，并让医生从总结查看支撑它的患者原话。

## 范围

承接现有 DSH 门诊问诊自动记录，覆盖主诉、现病史、既往史及其中的用药、过敏自述。正文是 Agent 总结；可信来源是本次 Consultation Record 中已保存的患者回答。一个总结可以汇集多轮回答，同一轮回答可以支撑多个总结事实。患者自述证明患者表达了什么，不等同于已经核实的客观事实。

## 用户故事

1. 作为医生，我希望 Agent 合并跨轮的相关病史、去除重复与无关措辞，并按病历字段整理，而无需再次改写原话列表。
2. 作为医生，我希望从总结查看对应的原始患者回答及必要上下文，以便判断是否准确、完整并确认其来源。
3. 作为医生，我希望总结保留患者的否定、时间、数值、程度和不确定性，且新增回答或更正不会静默覆盖人工编辑。

## 验收条件

- [ ] A1：完整患者回答保存后，Agent 自动生成病史总结；可归并相关信息、去重并改写口语，不以逐句复制并统一添加“患者自述：”作为总结结果。
- [ ] A2：多轮相关回答形成连贯病史；相同事实再次出现不重复堆积，明确更正更新相关自动总结，无法确定的矛盾保留为待核对内容。
- [ ] A3：每项总结中的患者事实均能追溯到实际保存的患者自述；查看来源展示原回答、对应轮次与相关引用，合并多轮信息时展示全部必要来源，来源原文保持不变。
- [ ] A4：总结不补造患者未表达的信息；保留否定、时间、数值、程度和不确定性。不把自述的居家测量、外院诊断转成本院查体、检查结果或医生诊断。
- [ ] A5：没有可总结事实时不生成占位病史或阴性结论；总结中无依据的事实、伪造来源和错误关联不得自动写入草稿。
- [ ] A6：总结与来源关联在保存、刷新、切换病例后仍可查看，并严格保持患者、Encounter、Workspace/Epoch 隔离。
- [ ] A7：沿用现有自动触发、局部人工编辑保护、冲突核对、暂停补录、重试、撤销和签署边界；模型失败不阻断已保存的问诊，迟到结果不覆盖人工内容或已签署文书。
- [ ] A8：用多轮合成问诊从真实 DSH 入口验收实际总结质量及来源查看，人工核对结果确实归纳病史并忠实于自述；仅有合法 JSON、原文匹配或调用成功不足以通过本需求。

### 合成验收示例

患者第一轮回答：“昨天晚上开始发烧，最高量到38.5度，还咳嗽，但是没有痰。”第二轮回答：“咳嗽也是昨晚开始的，胸口不疼，也不觉得喘。”

可接受的现病史总结为“昨晚起发热伴干咳，自述最高体温38.5℃；否认胸痛、气促。”起病、症状和体温关联第一轮自述，咳嗽起病及胸痛、气促的否定关联第二轮自述。措辞不要求逐字相同，但信息必须准确、无重复且可查看两轮原话；不得新增“考虑肺炎”等诊断或“听诊正常”等检查事实。

## 设计决定

正文总结与患者原话承担不同职责：总结服务病历阅读，原话服务依据核对。允许总结改写、归并并引用多轮来源；不能继续要求病历正文与单条引用逐字相同。沿用 ClinMesh 的 Query、共享 Command、持久任务、模型桥接和审计，不读取 Case Truth、未公开档案或 Assistant reasoning。

以下实施取舍尚未确定，因此规格保持 draft：总结与事实来源的存储粒度及校验合同；多轮总结更新时的局部编辑、撤销与冲突定位；来源查看的具体交互；既有摘录与归属数据的兼容方式。实施前明确这些取舍，必要的非平凡架构决定记录为 Agent Note。

## 测试策略

通过公开问诊 HTTP、病例 Query 和 file-backed SQLite 验证总结、来源关系及人工保护，覆盖跨轮归并、重复、否定、不确定表述、数值与时间、明确更正、矛盾、伪造引用、无依据事实、并发编辑、重试与签署。外部模型边界可使用确定性替身，但替身必须输出改写后的总结并关联真实原话，避免把逐字摘录等同于总结。

Playwright 从真实产品入口验证总结可读性与来源查看；共享 Surface 交互按需覆盖 React 18/19 和 ShadowRoot。真实 DSH 辅助模型使用合成病例有限样本，逐项核对总结是否忠实且有用；常规 CI 不依赖真实凭据或付费调用。

## 范围外

本需求不扩展为自动诊断、检查检验推荐、治疗计划、处方或自动签署。医生聊天补充来源和全病历整理由 [#177](https://github.com/CaiZongyuan/clinmesh/issues/177) 追踪，本需求仅完善患者问诊病史的总结与溯源。

## 依赖与风险

依赖 PR [#165](https://github.com/CaiZongyuan/clinmesh/pull/165) 的现有自动记录基础及 DSH 辅助模型能力。该 PR 先合入 main，本需求在新的 Issue 工作分支实施；当前阶段仅登记需求，不开始功能开发。

现有实现把增量正文构造为患者原话，校验与片段归属均围绕摘录建立；仅修改提示词无法完整交付总结与多来源追踪。设计须兼容既有草稿、来源与人工编辑，且不能因放宽正文措辞而丢失来源完整性和事实忠实性。现有基础验收由[问诊自动记录规格](https://github.com/CaiZongyuan/clinmesh/blob/1c025642795e9448a9c58bbed00defd06bed404c/docs/spec/2026-10-08-consultation-auto-record.md)拥有，本规格追踪新的总结行为。
