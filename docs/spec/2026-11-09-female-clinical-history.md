# 月经史与孕产史文本记录及动态必填

Status: implemented

## 问题与目标

当前工作分支已提供月经史、孕产史两个文本框，但只要患者为女性，就会在门诊结构化病历签署、正式修订时要求两项均非空。这不能区分普通门诊、专科初诊、未初潮和绝经等场景，容易造成无关询问与应付式填报。

目标是保留简单文本采集，按可信的患者属性、文书类型和就诊场景决定是否必填，允许普通门诊重点记录与本次诊疗相关的内容。现有代码和旧验证结果不代表动态规则已实现或验收。

## 范围

本期已确认采用“文本框＋动态必填”。保留月经史 `menstrualHistory`、孕产史 `obstetricHistory` 两个多行文本框，每项最多 4,000 字；覆盖当前门诊结构化 Clinical Document 的草稿、签署预览、提交、正式修订、质控、自动整理及 Agent 入口，以及 standalone Web 和 DSH 共享页面。

“孕产史”记录妊娠、生育等经历，不直接改名为“婚育史”；后者还包含婚姻、配偶等信息，需另有采集合同。不得以未婚推定未孕、没有生育史或不适用。

住院入院记录、急诊抢救例外、结构化专科表单、妊娠／哺乳状态和用药／放射安全联动列入后续阶段，不在本期宣称覆盖。旧 `assessment`／`plan` 组合接口沿用已有兼容合同。

## 用户故事

1. 作为普通门诊医生，我希望按本次诊疗需要填写两个文本框，不因患者为女性而被统一要求补齐完整病史。
2. 作为相关专科医生，我希望在适用的初诊文书中看到明确的必填标识和触发原因，避免遗漏与诊疗相关的病史。
3. 作为医生，我希望复诊、未初潮、已绝经及信息不全的患者得到符合场景的提示，而不是被系统自动写入“正常”或“无”。

## 动态规则

以下为本期默认院内策略，不是全国统一年龄或科室强制标准。年龄按业务就诊日计算，边界必须连续且可测试；本期使用一份有版本的受控策略，不建设通用规则编辑器。

| 场景 | 文本框与签署要求 |
| --- | --- |
| 男性，或女性未满 10 岁 | 默认收起，不要求两项；医生可因临床相关性主动展开，已有正文和历史原件仍可查看 |
| 女性 10 至不足 12 岁 | 默认可填，不因处于年龄阈值间隙而自动必填；与本次诊疗有关的内容由医生据实记录 |
| 女性满 12 岁，妇科／产科／生殖医学科／乳腺科的明确初诊文书 | 两项必填；根据真实情况填写未初潮、绝经及既往孕产经历，不强求适用性不符的月经周期或末次月经日期 |
| 上述专科的明确复诊／随访文书 | 默认不要求每次重新填写完整两项；本次相关变化和安全信息仍需医生核实，不能把旧文本视为当前状态 |
| 其他普通门诊，包括高龄女性 | 两项可填，不设置女性统一签署拦截；年龄本身不证明已绝经、未孕或没有哺乳 |
| 性别、年龄或适用专科的临床初复诊上下文不明 | 保留可见的采集入口，显示待核实提示，不新增签署阻断，不自动隐藏为“不适用”；负责医生可核实文书分类，不能伪造上下文以匹配某条规则 |

默认展示的收起不等于禁止记录，也不影响医生查看历史。必填只控制适用文书的正式完成，不阻止草稿保存，不自动阻断接诊、处方或检查开立。

### 规则输入与执行边界

- 服务端以权威 Patient、业务就诊日、科室稳定 ID／编码及明确的文书／初复诊分类计算适用性；前端、质控和 Agent 消费同一结果与原因，不各自推导。
- 不按科室显示名称、机器当前日期、历史 Encounter 数量或当前页面步骤推断规则。当前 `visitTypeId` 表示挂号收费类型，`first-visit`／`revisit-draft` 表示本次就诊的流程阶段，均不能直接当作临床初复诊。
- 签署预览、提交和正式修订按同一策略重新校验；患者属性、规则版本或就诊上下文改变后，旧预览不能绕过当前适用要求。历史签署原件保持不可变。
- 不通过文本关键词猜测是否绝经、是否妊娠或是否完成采集；“情况不详”不是系统自动填充的默认答案。草稿缺失与明确阴性事实继续区分。

科室按受控代码 `GYN`、`OB`、`OBGYN`、`REPRO`、`BREAST` 识别，现有 `GM` 普通门诊不适用专科必填；不增加专科诊疗目录或按显示名称匹配。负责医生通过独立的文书分类操作选择初诊／随访并填写核实理由，保存到 Encounter 的项目专用 type coding，采用 Encounter 预期版本与完整 Command 审计。该操作不进入 Agent Operation／Tool Catalog；Agent 只能读取结果，不能通过正文保存改分类。未知分类不从旧数据猜测补齐。

## 历史与自动整理

自动整理只使用当前允许的、有明确来源的事实，不补造“平素月经规律”“G0P0”“未孕”等内容，不依据年龄、婚姻或性别自动生成正文。

本期两个字段均为混合自由文本，不跨次就诊自动复制整段内容，避免连同旧 LMP、当前经量、痛经变化或妊娠状态一起带入。本次就诊内的草稿恢复、已签署历史只读查看和有来源的人工编辑继续保留。后续结构化方案才讨论稳定病史的候选引用、医生确认与时效控制。

## 验收条件

- [x] 两个文本框可保存恢复，字段名、长度限制、来源和历史签署展示保持兼容。
- [x] 普通门诊女性可在两项为空时签署；不因高龄或年龄未知自动记录绝经、未孕或阴性病史。
- [x] 对于已确认的专科初诊规则，页面标明必填及原因，空白或仅空白字符在签署预览、提交和正式修订中被一致拒绝；补齐后可完成。
- [x] 男性、低龄女童、10／12 岁边界、专科复诊和上下文缺失均执行最终批准的规则，不误用就诊流程阶段或挂号收费类型。
- [x] 草稿可暂存；收起字段不删除已有正文；不因动态必填缺项新增处方、检查或接诊门禁。
- [x] Web、React 18/19 DSH、质控与 Agent 使用相同适用性结果；规则或权威上下文改变后，旧签署预览不可绕过新要求。
- [x] 无来源时不补正常／阴性病史，不跨次自动复制两个文本框中的时效性内容，旧原件和来源仍可读取。

## 测试策略

使用合成患者、科室配置、文书分类、受控 Provider 与临时数据库，先验证共享规则的年龄边界、普通／专科、初诊／随访、未知输入与业务日期，再通过公开 Command 验证草稿、签署、修订及旧预览失效。测试须覆盖普通门诊女性不再被统一阻断，而不是沿用旧的“所有女性必填”断言。

Playwright 覆盖真实 Web 与 React 18/19 DSH 的动态标识、展开、保存恢复和签署结果；自动整理及历史回归覆盖来源、不生成阴性事实、不跨就诊复制与签署原件保全。原实现的成功证据仅证明旧规则，不能用于勾选本规格的新验收项。

## 后续阶段

1. 住院入院记录及特殊场景：先建设明确的入院文书合同，再制定适用女性的月经史、婚育／孕产史完整性要求，包含绝经后的历史记录；不扩散到每日病程记录。急诊／昏迷例外需有明确场景、无法采集原因、经办人、时间、补记责任及审计，不以占位文字作为统一绕过机制。
2. 当前生殖安全状态：按就诊采集妊娠、哺乳、备孕等信息，区分未知、否认和确认；这些状态可能同时存在，不能简单塞进一个互斥选项。采集时点、复核期限与临床责任需先确认。
3. 专科结构化及安全联动：在明确 LMP、G／P／A／L 语义、来源和时效后设计快捷控件；药品风险依赖可追溯规则，放射依赖真实项目属性，分别覆盖未知状态、复核、紧急例外及审计。不能把普通病历非空等同于用药或检查安全。

后续阶段不在本期创建实施承诺或以旧测试宣称完成；是否拆新 Issue 由对应需求确认后决定。

## 依赖与实施约束

- 默认年龄展示阈值为 10 岁，专科初诊阈值为 12 岁，不混用参考方案中的 14／50／55 岁范围作为全局规则。
- 当前门诊详情没有完整的规则上下文，baseline 也未提供上述专科目录；实施时补齐可信规则投影及医生文书分类入口，使用合成专科目录验收规则，不宣称增加专科诊疗能力。
- 未知上下文以提示为主；已确认初诊、性别和年龄满足专科规则时执行必填。科室与人口学来自权威对象，不能由正文保存请求任意覆盖。
- 当前没有住院入院记录、急诊例外或妊娠／哺乳安全合同；本期不以通用门诊字段冒充这些能力。
