# 月经史与孕产史文本记录及女性必填

Status: implemented

## 问题与目标

当前病历没有独立的月经史和妊娠史记录项。医生需要直接填写这两类病史，并对女性患者执行必填要求。

## 范围

本规格适用于当前结构化 Clinical Document 模板。旧 `assessment`／`plan` 组合接口沿用已有兼容合同，不扩展为妇产科文本采集入口；当前结构化病历页面与 Agent Catalog 不使用该组合接口。

在现有病历中新增月经史 `menstrualHistory` 与孕产史（妊娠史）`obstetricHistory` 两个自由文本框，与既往史、家族史等章节采用相同的填写方式。女性患者的这两项必填，不拆成初潮年龄、孕次、产次等结构化子字段，不新增采集状态选择。

适用入口包括 standalone Web、DSH 共享病历界面，以及对应的病历保存、签署、修订和 Agent 接口。问诊自动整理将有明确来源的相关内容归入对应章节；没有来源时不自动填充正常或阴性病史。

## 用户故事

1. 作为医生，我希望在两个文本框直接记录实际问到的月经史和孕产史，以便保持现有病历填写习惯。
2. 作为医生，我希望女性患者的相关病史缺失时得到必填提示，以便补充记录。

## 验收条件

- [x] 病历编辑、签署预览、签署结果和修订入口包含两个独立文本章节，内容保存后可以恢复。
- [x] 女性患者的两个文本框标明必填，空白或仅含空白字符的内容不满足必填要求。
- [x] 页面与 Agent 接口执行一致的女性必填规则。
- [x] 自动整理仅使用已保存来源，不将未询问或未知内容改写为正常、无妊娠史或当前未孕。
- [x] 旧病历仍可读取，已签署原件保持不可变；新字段缺失不自动补写。

## 设计决定

使用自由文本框，女性必填。字段名为 `menstrualHistory` 和 `obstetricHistory`，沿用现有病史字段每项 4,000 字的限制。

允许未填写的草稿暂存，在签署及正式修订时执行必填校验；其他性别允许留空。不额外按年龄或婚姻状态推定病史。

## 测试策略

通过公开病历接口验证女性缺项拒绝、补齐后签署、草稿暂存、旧病历读取和修订保留内容；通过现有受控 Provider 验证问诊自动整理及来源保留。使用 Playwright 检查真实 Web 与受影响的 React 18/19 DSH 共享入口中的文本框、必填标识和保存恢复。验证仅使用合成数据及临时数据库。

## 范围外

不新增结构化妇产科表单、问诊完成状态、当前妊娠风险判定或相关检查与用药规则。

## 依赖与风险

数据库扩展需要保留旧病史、来源、人工正文、签署原件及审计记录。
