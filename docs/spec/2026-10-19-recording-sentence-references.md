# 自动整理病历使用句子编号引用来源

Status: implemented

## 问题与目标

自动整理病历目前要求模型为每条事实返回来源编号和逐字完整原句。病历页面已移除来源展示，但后台仍依赖完整引用核对事实、归并多轮信息、处理更正与矛盾，以及防止已拒绝事实在没有新依据时重新出现。让模型再次抄写原文增加输出体积，也引入标点、换行和句界抄写错误。

目标是由服务端为固定来源中的完整句子分配短编号，模型只返回事实文字及引用编号，服务端确定性恢复原文与来源关系。减少模型复述负担，同时保留现有来源、人工编辑与异步核对边界。

## 范围

- 统一病历自动整理模块的实时记录、历史补录及显式恢复入口，覆盖患者回答、受信医生补充和已公开报告。
- 调整整理模型输入、输出 schema、提示词及服务端解码；保留既有 `retainedFactIndexes`，未变化的目标事实继续由服务端原样保留。
- 在调用模型前固定句子与持久来源的映射，恢复为既有事实来源结构后再执行校验、写入和异步语义核对。
- 保持 Web/DSH 病历直接写入草稿、医生直接编辑正文的体验，不恢复来源查看或逐条确认流程。

## 用户故事

1. 作为医生，我希望自动整理少花时间重复抄写问诊原文，病历持续更新，后台仍能核对每项事实的真实依据。
2. 作为维护者，我希望引用由程序准确恢复，避免模型改变标点或换行导致本可记录的事实失败。

## 验收条件

- [x] A1：模型调用前，服务端从已授权的固定来源快照构造完整句子的短编号映射。每个编号唯一关联原始来源身份、原文位置及该快照；不同来源中相同文字不能混为同一来源。
- [x] A2：新整理请求要求模型仅返回事实文字及句子引用编号，不再要求输出原文 `quote`。每条新增事实仍须有真实来源，支持多句、多轮引用；来源数量是容量限制，不要求凑满。既有未变化事实仍可按 `retainedFactIndexes` 原样保留。
- [x] A3：服务端仅使用本次任务快照解码编号，恢复完整 `sourceTurnId` 与逐字 `quote`，不得靠模糊匹配、模型补写或当前最新来源猜测映射。未知、重复、错快照或无法恢复的引用明确失败，不自动绑定到相似来源。
- [x] A4：句子划分与既有完整句界校验一致，保留中英文问号、否定、条件、数值和不确定性，以及 LF、CRLF 和重复原句的定位。混合自述与疑问不能因编号化被截断或删除问号；纯提问仍允许合法空增量。
- [x] A5：恢复后的事实继续接受来源角色、字段、目标片段、当前新增来源、已拒绝事实及语义忠实性校验。多轮更新不能丢失有效旧事实，更正和冲突保留必要双方证据；合法引用不等于语义成立，否定核验不触发格式纠错。
- [x] A6：保留独立候选失败隔离、草稿版本及人工编辑保护、暂停、授权撤销、Epoch、任务代次和签署冻结边界。编号映射、来源进度及完整引用支持重复消费与服务重启，不因重试错配或丢失来源。
- [x] A7：已保存事实、旧任务快照和 Command 回执继续可读；旧格式的在途或恢复任务按其固定协议处理，不静默丢掉引用，也不为协议升级重新生成已完成内容。新模型协议在服务端还原为既有来源结构，避免无必要的公开 API 与持久格式变更。
- [x] A8：完整输入预算包含句子映射、来源文本、schema 和修复提示的实际序列化体积，不因编号化遗漏必要证据。超过既有限制时保留来源和可恢复失败，不截断原句或提高预算掩盖问题。
- [x] A9：使用固定合成多轮病例比较新旧响应的序列化字节，证明省去逐条复述完整引文后响应更小，并记录输入体积变化。句子编号和原文恢复不新增模型请求，校验及恢复继续遵守既有有界调用策略；不将字节变化冒充真实 Token、费用或延迟实测。
- [x] A10：真实病历入口仍只显示正文、现有整理控制和允许的问题提示，不新增来源入口、确认保留或原因填写。通过合成 Provider 与离线 fixture 验证接线及兼容性，不执行压测或真实模型调用。

## 设计决定

句子引用是模型传输层的短身份；后台事实仍拥有完整持久来源。服务端负责句界、映射和逐字原文，模型负责选择支撑事实的引用与整理事实文字。映射随任务的不可变快照固定，短编号不作为跨批次或跨病例的持久身份。

新协议可以用 `sourceIds: ["s0", "s3"]` 表达一条事实的多句来源；服务端恢复为现有 `sources: [{ sourceTurnId, quote }]` 后复用业务校验。具体命名属于实现选择，但不允许模型自行生成引文、位置或来源身份。既有每条事实最多 12 条来源的限制本次保留，句子划分须验证与旧引用表达的兼容；无法完整表达的输入明确失败，不删减证据凑入上限。

取舍及替代方案由[句子引用决策](../decisions/implemented/architecture/2026-10-19-recording-sentence-references.md)拥有。现有异步写入、调用预算和调度边界由[低延迟记录规格](2026-10-15-low-latency-document-recording.md)拥有，前端隐藏来源的决定继续适用。

## 测试策略

纯函数回归验证确定性句子映射与恢复，覆盖中英文标点、无句末标点、LF/CRLF、同句自述与疑问、重复原句、未知和错快照编号、多句和跨轮引用。断言恢复后的原文与持久来源完全一致，不仅检查编号存在。

Server 公开来源写入、病例 Query 与 file-backed SQLite 回归覆盖实时整理、补录、失败隔离、更新更正、已拒绝事实、人工修改、暂停、签署冻结、重复消费及重启；覆盖旧事实、旧快照和在途任务兼容。通过真实 `DshModelProvider` 与宿主 handler 的合成集成边界检查新 schema、提示词和格式修复，不依赖绕过传输层的替身证明完整接线。若公开 Agent-facing 合同确需变化，同一 diff 更新 owning Catalog、运行时 Skill 及漂移测试。

沿用 Playwright 的 Web 与 DSH 共享病历入口回归，验证正文、刷新恢复及来源界面继续隐藏；不以新建来源展示替代后台断言。固定少量合成 fixture 比较输入和输出字节，不持续注入负载，不调用真实 Provider。

## 范围外

- 删除后台来源、放宽语义核对或将编号存在当成事实正确。
- 重做病历 UI、恢复来源查看、逐条确认或新增签署门禁。
- 改变患者回答、诊疗建议、病历质控等其他生成任务的输出合同。
- 新增累计预算、费用账本或监控；这些属于[模型用量治理 Issue #228](https://github.com/CaiZongyuan/clinmesh/issues/228)。
- 执行压测、真实模型评测或承诺未经实测的 Token、费用及延迟降幅。

## 依赖与风险

无外部实施阻塞，不依赖模型用量治理完成。主要风险是句界划分改变原引用语义、短编号跨任务误用、多句引用触及既有上限及新旧任务混用协议；由固定快照、完整恢复、容量失败和兼容回归约束。协议交付时须同步更新现有 owner 文档及 Agent Note 状态。
