# 住院闭环

Status: implemented

## 问题与目标

本需求建设通用住院闭环，让一名合成患者从入院登记走到病案归档，全程由真实岗位操作产生可审计的住院事实，并与既有门诊、药房、检查检验及收费流程衔接。

目标是落地 [临床业务流程](../architecture/clinical-workflows.md#82-住院闭环) 的完整链路：入院申请、预入院、住院登记、入科、分床、在院诊疗（长期/临时医嘱、校对、执行、检查检验、手术最小闭环、转科）、出院、财务结算、清床、病案首页、编码审核与归档。

手术采用最小闭环（申请、术前准备、执行记录、术后医嘱），覆盖 DRG 后续所需的"本次实际实施操作"事实；手术室排班调度、麻醉与监护设备采集、耗材供应链不在本次范围。

## 范围

- 新增住院医生、病区护士、病案人员三个岗位；登记员、药师、收费员增加住院语义入口；administrator 不承担住院业务。
- 病区、病房、床位结构作为 Scenario 环境种子数据提供；运行中床位状态由领域互斥事实维护，Encounter.location 仅作互操作投影。
- 首期入院入口为门诊收住院与登记处直接入院；入院途径含转院字段值。
- 业务时间使用虚拟时间，由场景控制手动推进；推进过夜触发床位费与长期医嘱当日执行。
- 出院、财务结算、清床、病案归档是四个独立动作，前置动作完成是后置动作的门禁。
- 手术最小闭环：住院医生开手术申请（术式与计划虚拟时间），术前检查核对与知情同意签署完成前不得执行；手术执行形成本次实际实施操作事实与耗材记录，术后医嘱引用手术事实。
- 病案首页按核心字段集实现，诊断与手术操作按病案编码规范编码，手术操作来自手术执行记录而非申请；编码审核通过后才能归档。
- 入口覆盖 Web 岗位工作台与对应 clinmesh-* CLI skills。

## 用户故事

1. 作为门诊医生，我希望完诊时为患者开住院证，以便患者进入住院流程。
2. 作为登记员，我希望为患者办理住院登记并收取预交金，以便患者正式入院。
3. 作为病区护士，我希望接诊入院患者并分配床位，以便病区开始护理责任。
4. 作为住院医生，我希望开具长期与临时医嘱并确认诊断，以便病区执行诊疗。
5. 作为病区护士，我希望校对并执行医嘱、记录给药，以便诊疗按医嘱落地。
6. 作为药师，我希望按住院医嘱摆药发药，以便病区给药有据。
7. 作为住院医生，我希望发起转科并移交责任，以便患者在新科室继续治疗。
8. 作为住院医生，我希望开立手术申请并在术后记录实际操作与耗材，以便病案与后续分析拥有本次实际实施事实。
9. 作为收费员，我希望在出院时按费用账多退少补完成结算，以便住院费用结清。
10. 作为病案人员，我希望审核病案首页编码并归档，以便病案进入正式存档。

## 验收条件

- [x] 登记员可通过直接入院或门诊住院证创建住院 Encounter，记录入院途径并分配住院号；同一患者多次住院形成相互独立的住院事实。
- [x] 床位同一时刻只被一次有效住院占用；对已占床位再次分配返回业务冲突；转床与换床以原子命令完成，不产生中间占用状态。
- [x] 场景控制推进虚拟时间到下一日后，系统产生床位费与当日到期长期医嘱执行任务；未推进时不产生。
- [x] 长期与临时医嘱经护士校对后才可执行；执行记录引用已校对的有效医嘱；停嘱后不再产生新的执行时点。
- [x] 住院药房按已校对药品医嘱摆药发药；给药形成给药事实，未发药不得给药。
- [x] 病区可申请检验与影像检查，按病区送检语义进入既有执行闭环，报告回到本次住院病历。
- [x] 转科后医嘱开立权、护理责任与后续费用归属切换到新科室；原科室在途任务按规则收口。
- [x] 各类项目按声明的计费触发点生成逐项费用；冲正保留原始记录并形成关联，不物理删除。
- [x] 出院医嘱由住院医生开具，护士出院处理完成后患者出区；未出院处理不能结算，未结算不能清床。
- [x] 出院结算按预交金与费用账多退少补，金额与逐项费用账核对一致；退款形成关联原交易的反向记录。
- [x] 清床后床位可再次分配；召回仅在规定状态窗口内可用并生成完整审计与逆向事件。
- [x] 住院医生可开立手术申请（术式、计划虚拟时间）；术前检查核对与知情同意签署完成前手术不能执行。
- [x] 手术执行形成本次实际实施操作事实与耗材记录，并按计费触发点生成手术与耗材费用；术后医嘱引用手术事实并进入正常校对执行流程。
- [x] 病案首页的手术操作来自手术执行记录；无执行记录时首页不得宣示已实施的手术。
- [x] 主管医生可填写病案首页核心字段；病案人员编码审核通过后才能归档，归档后病案只读可查。
- [x] 关键操作全程生成审计记录；住院行政状态不压缩进单一 Encounter.status，按分层状态模型表达。
- [x] 默认环境仅有一个住院科、一个病区，住院医生与病区护士各一个默认岗位上下文；新登记不再要求选择内外科。
- [x] 人物切换中同一人员同一岗位只显示一个选项，岗位与同名人员文字不重复；旧库的原岗位、患者归属、床位、费用、审核归档与原操作回执保持可查询和恢复。
- [x] 住院界面采用持续可见的患者横幅与阶段导航，默认展开当前任务，诊断医嘱、检查手术、出院结算及病案采用独立工作区域；不将全部业务表单纵向堆叠。
- [x] 每个阶段明确显示当前状态、负责岗位、前置条件与下一办理入口；开出住院证后能找到登记员办理住院的入口或明确交接提示。跨岗位导航不代替服务端授权。

## 设计决定

- 当前默认演示环境收敛为一个住院科、一个病区；多科室拆分暂缓。已实现的跨科责任与转科合同通过显式双病区测试环境验证，不作为默认新入院的配置要求。
- 原工作区的 `apps/web/src/app/inpatient-prototype.tsx` 完整流程视图与 `docs/ui/references/2026-10-19-ui-direction-comparison.html` 是布局参考，正式界面的独有要求由上述验收条件拥有；原型内存状态不进入生产业务。沿用共享组件、真实 Command、受信岗位、原意图恢复和现有浅深主题合同。
- 单科配置不物理合并历史病区，不自动执行临床转科或停嘱。旧库保留原资源与岗位；人物项按人员与岗位合并展示。住院工作台先绑定会话的单一病区，不提供工作病区选择；旧职责与回执授权保留在服务端会话中，原授权与回执绑定不改变。
- 岗位配置为新增住院医生、病区护士、病案人员，复用登记员、药师、收费员；administrator 保持平台管理者边界。
- 状态模型遵循 [临床业务流程](../architecture/clinical-workflows.md#82-住院闭环)：Encounter.status 表达标准生命周期，入科、转科、待出院、已出区、待清床、召回使用有明确取值约束的扩展与独立任务表达。
- 虚拟时间推进是场景控制能力，不属于医院业务岗位；测试可显式推进到任意住院日。
- 医嘱生命周期、执行引用与计费触发点沿用 [临床业务流程](../architecture/clinical-workflows.md#83-医嘱生命周期) 的既有约束，按项目类型声明。
- 病案首页与编码审核是归档流程组成部分；诊断与操作编码目录采用下述固定来源与版本，为后续 DRG 只读投影预留事实位置，本次不实现分组。
- 手术取最小闭环：申请 → 术前准备 → 执行记录 → 术后医嘱；手术排班调度、麻醉与监护设备采集、耗材供应链管理后置（依据 [DRG 前置研究](../research/2026-10-20-drg-operations-prerequisites.md) 的建设顺序建议）。
- 召回窗口限定为护士已经办理出区、尚未结算、未清床且原床仍由本次住院保留；召回与结算竞争时同一事务只允许一个状态变更成功。召回保留原出区及逆向事件，不自动恢复已停或取消的医嘱；结算后再次收治创建新的住院事实。
- 病案首页核心字段分为患者基本信息、住院过程、诊断与实际操作、费用四组，并保存独立修订、编码审核与归档事实。患者与住院号、实际入科及出区时间、转科、主次诊断及入院病情、实际操作及主次、费用净额均追溯本次正式事实；审核绑定当前修订，归档后只读。
- 诊断编码沿用项目固定的临床版 ICD-10 来源及其版本、Release 和来源限制；手术操作采用经核验的临床版 ICD-9-CM-3 工作表 `3.0` 固定有界子集。完整身份与来源定位见[编码依据](../research/2026-10-20-inpatient-record-coding-and-recall.md)，不将临床版视为医保版或把核心字段集宣称为完整上报数据。

## 测试策略

- 服务端 Command 与门禁边界用仓库现有测试体系覆盖床位互斥、医嘱校对、出院门禁、结算核对与召回窗口。
- 关键岗位流程通过真实入口做浏览器验证，运行入口与证据规则见 [测试策略](../testing.md#用户界面验证)。
- CLI 与 skills 扩展遵循 Agent-facing CLI 合同；合同变化时在同一变更中更新对应 clinmesh-* skill 与命令示例漂移测试。

## 范围外

- DRG 分组引擎、在院预分组、处方推演、归档冻结分组与医保办模拟核定：由[门诊住院共享支付与 DRG 一体化](https://github.com/CaiZongyuan/clinmesh/blob/e322fef689b009cc0175931b4070b8713c8dedff/docs/spec/2026-10-15-drg-prescription-budget.md)规格承载，决策口径见 [Agent Note](../decisions/implemented/feature/2026-10-23-drg-inpatient-simulation-chain.md)；支付参数对接、成本、盈亏分析另行讨论。
- 急诊收住院入口与急诊闭环。
- 医保结算清单、地方支付参数与实际结算比对。
- 体温单与完整护理文书体系。
- 手术室排班调度、麻醉与监护设备采集、耗材供应链管理。

## 依赖与风险

- 病案首页仅验收设计决定中声明的核心字段集；编码和来源版本不等于完整国家首页上报或医保目录兼容证明。
- 检验与影像的病区送检依赖既有执行闭环，责任与报告来源合同见[临床业务流程](../architecture/clinical-workflows.md#82-住院闭环)。
- 虚拟时间推进须保持既有 Workspace/Epoch 隔离，时钟、跨日费用与长期医嘱任务合同见[仿真与场景](../architecture/simulation.md)。
