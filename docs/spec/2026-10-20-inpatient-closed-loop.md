# 住院闭环

Status: approved

## 问题与目标

当前系统只交付门诊闭环：Encounter 固定门诊类别，岗位枚举、Location 种子与运行时 skills 均无住院内容，药品和服务目录的 `availableScopes` 虽预留 `inpatient` 但种子与查询全部过滤。本需求建设通用住院闭环，让一名合成患者从入院登记走到病案归档，全程由真实岗位操作产生可审计的住院事实。

目标是落地 [临床业务流程](../architecture/clinical-workflows.md#82-住院闭环后续) 规划的完整链路：入院申请、预入院、住院登记、入科、分床、在院诊疗（长期/临时医嘱、校对、执行、检查检验、手术最小闭环、转科）、出院、财务结算、清床、病案首页、编码审核与归档。

手术采用最小闭环（申请、术前准备、执行记录、术后医嘱），覆盖 DRG 后续所需的"本次实际实施操作"事实；手术室排班调度、麻醉与监护设备采集、耗材供应链不在本次范围。

## 范围

- 新增住院医生、病区护士、病案人员三个岗位；登记员、药师、收费员增加住院语义入口；administrator 不承担住院业务。
- 病区、病房、床位结构作为 Scenario 环境种子数据提供；运行中床位状态由领域互斥事实维护，Encounter.location 仅作互操作投影。
- 首期入院入口为门诊收住院与登记处直接入院；入院途径含转院字段值。
- 业务时间使用虚拟时间，由场景控制手动推进；推进过夜触发床位费与长期医嘱当日执行。
- 出院、财务结算、清床、病案归档是四个独立动作，前置动作完成是后置动作的门禁。
- 手术最小闭环：住院医生开手术申请（术式与计划虚拟时间），术前检查核对与知情同意签署完成前不得执行；手术执行形成本次实际实施操作事实与耗材记录，术后医嘱引用手术事实。
- 病案首页按核心字段集实现，诊断与手术操作按病案编码规范编码，手术操作来自手术执行记录而非申请；编码审核通过后才能归档。
- 入口覆盖 Web 岗位工作台与对应 clinmesh-* CLI skills。

## 用户故事

1. 作为门诊医生，我希望完诊时为患者开住院证，以便患者进入住院流程。
2. 作为登记员，我希望为患者办理住院登记并收取预交金，以便患者正式入院。
3. 作为病区护士，我希望接诊入院患者并分配床位，以便病区开始护理责任。
4. 作为住院医生，我希望开具长期与临时医嘱并确认诊断，以便病区执行诊疗。
5. 作为病区护士，我希望校对并执行医嘱、记录给药，以便诊疗按医嘱落地。
6. 作为药师，我希望按住院医嘱摆药发药，以便病区给药有据。
7. 作为住院医生，我希望发起转科并移交责任，以便患者在新科室继续治疗。
8. 作为住院医生，我希望开立手术申请并在术后记录实际操作与耗材，以便病案与后续分析拥有本次实际实施事实。
9. 作为收费员，我希望在出院时按费用账多退少补完成结算，以便住院费用结清。
10. 作为病案人员，我希望审核病案首页编码并归档，以便病案进入正式存档。

## 验收条件

- [ ] 登记员可通过直接入院或门诊住院证创建住院 Encounter，记录入院途径并分配住院号；同一患者多次住院形成相互独立的住院事实。
- [ ] 床位同一时刻只被一次有效住院占用；对已占床位再次分配返回业务冲突；转床与换床以原子命令完成，不产生中间占用状态。
- [ ] 场景控制推进虚拟时间到下一日后，系统产生床位费与当日到期长期医嘱执行任务；未推进时不产生。
- [ ] 长期与临时医嘱经护士校对后才可执行；执行记录引用已校对的有效医嘱；停嘱后不再产生新的执行时点。
- [ ] 住院药房按已校对药品医嘱摆药发药；给药形成给药事实，未发药不得给药。
- [ ] 病区可申请检验与影像检查，按病区送检语义进入既有执行闭环，报告回到本次住院病历。
- [ ] 转科后医嘱开立权、护理责任与后续费用归属切换到新科室；原科室在途任务按规则收口。
- [ ] 各类项目按声明的计费触发点生成逐项费用；冲正保留原始记录并形成关联，不物理删除。
- [ ] 出院医嘱由住院医生开具，护士出院处理完成后患者出区；未出院处理不能结算，未结算不能清床。
- [ ] 出院结算按预交金与费用账多退少补，金额与逐项费用账核对一致；退款形成关联原交易的反向记录。
- [ ] 清床后床位可再次分配；召回仅在规定状态窗口内可用并生成完整审计与逆向事件。
- [ ] 住院医生可开立手术申请（术式、计划虚拟时间）；术前检查核对与知情同意签署完成前手术不能执行。
- [ ] 手术执行形成本次实际实施操作事实与耗材记录，并按计费触发点生成手术与耗材费用；术后医嘱引用手术事实并进入正常校对执行流程。
- [ ] 病案首页的手术操作来自手术执行记录；无执行记录时首页不得宣示已实施的手术。
- [ ] 主管医生可填写病案首页核心字段；病案人员编码审核通过后才能归档，归档后病案只读可查。
- [ ] 关键操作全程生成审计记录；住院行政状态不压缩进单一 Encounter.status，按分层状态模型表达。

## 设计决定

- 岗位配置为新增住院医生、病区护士、病案人员，复用登记员、药师、收费员；administrator 保持平台管理者边界。
- 状态模型遵循 [临床业务流程](../architecture/clinical-workflows.md#82-住院闭环后续)：Encounter.status 表达标准生命周期，入科、转科、待出院、已出区、待清床、召回使用有明确取值约束的扩展与独立任务表达。
- 虚拟时间推进是场景控制能力，不属于医院业务岗位；测试可显式推进到任意住院日。
- 医嘱生命周期、执行引用与计费触发点沿用 [临床业务流程](../architecture/clinical-workflows.md#83-医嘱生命周期) 的既有约束，按项目类型声明。
- 病案首页与编码审核是归档流程组成部分；诊断与操作编码目录及版本在实施设计时按病案编码规范核定，为后续 DRG 只读投影预留事实位置，本次不实现分组。
- 手术取最小闭环：申请 → 术前准备 → 执行记录 → 术后医嘱；手术排班调度、麻醉与监护设备采集、耗材供应链管理后置（依据 [DRG 前置研究](../research/2026-10-20-drg-operations-prerequisites.md) 的建设顺序建议）。

## 测试策略

- 服务端 Command 与门禁边界用仓库现有测试体系覆盖床位互斥、医嘱校对、出院门禁、结算核对与召回窗口。
- 关键岗位流程通过真实入口做浏览器验证，运行入口与证据规则见 [测试策略](../testing.md#用户界面验证)。
- CLI 与 skills 扩展遵循 Agent-facing CLI 合同；合同变化时在同一变更中更新对应 clinmesh-* skill 与命令示例漂移测试。

## 范围外

- DRG 分组引擎、预分组提示与支付、成本、盈亏分析：住院闭环完善后另行讨论。
- 急诊收住院入口与急诊闭环。
- 医保结算清单、地方支付参数与实际结算比对。
- 体温单与完整护理文书体系。
- 手术室排班调度、麻醉与监护设备采集、耗材供应链管理。

## 依赖与风险

- 病案首页核心字段集尚待实施设计核定；核定前归档验收以声明字段集为准。
- 检验与影像闭环的病区送检适配量待实施核定，可能影响对应切片的规模。
- 虚拟时间推进与 Scenario 模型的衔接细节待实施设计，须保持既有 Workspace/Epoch 隔离。
