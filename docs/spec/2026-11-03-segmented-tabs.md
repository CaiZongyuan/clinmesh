# 分段页签滑块与视图切换样式

Status: approved

## 问题与目标

[DSH 外壳、交互反馈与助手呈现优化](2026-11-02-dsh-shell-feedback-redesign.md)合入后复查，发现页签与切换控件仍有三处问题：

- 分段页签的选中项看不清。浅色主题下，选中项底色 `--background` 与底槽 `--muted` 同为 `#f5f6f7`，只靠字色深浅区分。门诊医生队列的「在诊 / 待诊 / 完诊」最明显。
- 「门诊 / 住院」、病案员的「病案整理状态」等控件只是切换视图或筛选列表，却命中了 #372 的选项规则，显示为实心黑底加「✓」，看起来与表单里已勾选的选项一样。
- 主卡分区页签切换时，下划线直接跳到新位置。

目标：所有分段页签的选中项都能一眼看出，并带滑动过渡；视图切换和表单选项在外观上明显不同。

## 范围

- 共享组件 `packages/ui` 的 Tabs：
  - 默认变体（分段）：门诊医生队列、分诊、挂号、门诊收费的两组 2×2 页签、门诊药房、模型用量分区，以及医生的「检验 / 放射检查 / 病理会诊」子页签。
  - line 变体（下划线）：主卡工作分区和组件目录。
- 视图切换（以下控件只改变看到的列表或分区，不写业务数据）：
  - 「门诊 / 住院」：挂号、门诊收费、门诊药房及对应住院岗位，见 `workspace-mode.tsx`。
  - 病案员队列的「病案整理状态」（全部、待整理、审核通过、已归档）。
  - 挂号记录的「今日 / 全部」。
  - 医生诊断页的诊断筛选（全部、主要诊断、次要诊断）和检验报告的指标显示范围（全部指标、仅异常）。
- standalone Web 和 DSH Surface，浅色与深色主题。
- 在 `docs/ui/design.md` 写明「视图切换」与「表单选项」的外观区分。

## 用户故事

1. 作为门诊医生，我希望一眼看出队列当前停在在诊、待诊还是完诊，以便不在错误的列表里找病人。
2. 作为挂号员、收费员或药师，我希望「门诊 / 住院」看起来是在切换视图，而不是一个已勾选的选项。
3. 作为病案员，我希望整理状态的筛选和其他队列筛选外观一致。

## 验收条件

- [ ] 分段页签：
  - 选中项是一块与底槽颜色不同的滑块。浅色为白底加细边和轻阴影，深色同样能与底槽区分。
  - 未选中项悬停时显示浅灰底。
  - 浅色和深色主题下，选中块背景色都不同于底槽背景色。
- [ ] 切换分段页签时，滑块从原位置平滑移到新选项。页签换行或排成 2×2 网格（门诊收费）时，滑块对准新选项所在的行和列，不错位，也不遮挡文字。
- [ ] line 变体：下划线随切换平滑滑到新页签。分区换行或收进「更多」后，下划线仍对准当前页签。
- [ ] 视图切换：
  - 范围中列出的视图切换都与分段页签外观一致，不再显示实心黑底和「✓」。
  - 队列卡里「门诊 / 住院」与下方页签之间留出间距，两条底槽不相连。
  - 仍可用键盘切换，读屏仍能读出当前选中项。
- [ ] 表单选项保持「选中后实心带勾」，例如诊断类型、处方结论方式、检验检查申请、住院资金、床位网格、分诊级别的选项按钮。
- [ ] 系统设置为减少动态效果时，滑块和下划线直接到位，没有过渡。
- [ ] 页签禁用时（例如收费提交中），滑块停在当前项，整组显示为禁用。
- [ ] 1101px、826px、760px 三档宽度和浅深两种主题下，不出现横向滚动、文字裁切或按钮内单字换行。
- [ ] DSH Surface（React 18.3.1）和 standalone Web（React 19.2）表现一致。

## 设计决定

- 在共享组件中统一实现（用户决定），所有分段页签同时改善，不会出现两种页签外观。位置由已安装的 `@base-ui/react` 1.7 `Tabs.Indicator` 提供（`--active-tab-left`、`--active-tab-top`、`--active-tab-width`、`--active-tab-height`），不新增依赖。
- 按语义区分视图切换和表单选项：
  - 切换视图（只改变看到的列表或分区）用分段页签外观。
  - 填写选项（会写入业务数据）保留 #372 的实心带勾。
  - 视图切换保留 ToggleGroup，以 `data-view-switch` 标记并改为分段外观，键盘操作、读屏语义（按钮加 `aria-pressed`）和测试定位都不变；滑动过渡只用于 Tabs。
- 不做队列卡拖动调宽。原型核对的结论：比默认 14.5rem 更窄时，「病理会诊费用」等页签会折行；826px Surface 下最多只能拖宽约 2rem，收益小。
- 本地原型覆盖了现状、滑块页签、滑块加拖动调宽三种方案，以及门诊医生、收费、药房、挂号四个岗位的队列，每个岗位都按三档宽度和浅深主题核对过。

## 测试策略

- **React 18/19 Surface 合同测试**（浏览器）：
  - 浅色和深色下，选中块背景色不等于底槽背景色。
  - 切换后，指示器的矩形与选中页签的矩形重合，覆盖门诊收费 2×2 网格和换行的情况。
  - 减少动态效果下，指示器的 `transition-property` 为 `none`。
  - 视图切换不渲染「✓」，表单选项仍渲染「✓」。
- **组件测试**（jsdom）：现有测试覆盖视图切换的角色、选中状态和键盘切换，保持通过。
- **Playwright Web 旅程**：更新依赖「门诊 / 住院」切换外观或选中属性的现有断言，运行受影响的 spec。
- **原生 DSH 宿主**：环境具备时，人工核对 1600 和 1280 宽度、浅深两种主题。

## 范围外

- 队列卡拖动调宽和拖动收起。
- 表单选项按钮的外观。
- 页签的文案、数量、分组和收进「更多」的逻辑。

## 依赖与风险

- 指示器依赖布局测量。页签收进「更多」、字号切换或容器宽度变化后都要重新对准，需要合同测试覆盖。
- 改动共享组件会影响所有 Tabs 使用处，回归范围扩大到组件目录、模型用量页和医生检查子页签的相关测试。
