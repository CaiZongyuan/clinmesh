# 主 Agent 统筹的开发方式

Status: implemented

## 问题与目标

用户希望直接描述开发需求，由主 Agent 承担拆分、跟进、集成和交付，减少选择 skills 与协调多个 Agent 的负担。更新后的 Matt 入口需要接入现有规则，同时保留上游原文、显式调用策略及项目授权。

## 范围

更新用户提供的通用规则正文，对齐本机 Claude 与 Codex 的该文档副本，以及 ClinMesh 的开发入口、工程记忆、Issue 关系、PR 模板和流程决策引用。自动编排由规则驱动，项目具体执行细节由 [Agent 工程开发](../agent-development.md)拥有。

## 用户故事

1. 作为开发者，我希望只向主 Agent 描述需求，由它安排直接实施或独立 worktree 并行开发，并统一交付结果。

## 验收条件

- [x] 全局与仓库入口均明确由主 Agent 负责协调，用户无需记住 skill 名称或手工分派。
- [x] 单任务与多切片路由有明确条件；并行写入隔离 worktree，依赖、基线、集成和证据由主 Agent 核验。
- [x] Matt skill 文件、元数据和共享链接不因流程适配改变；不能调用时采用明确的项目流程并如实报告。
- [x] 需求 owner、完整 WIP 审查、草稿交付、任务关闭和 worktree 清理与既有授权一致。
- [x] PR 正文复用中文模板及真实验证、媒体合同；复盘按需进行，建议不自动触发额外实施。
- [x] 文档、Agent Note 格式、链接和文档站检查通过；未受本次修改影响的工作区内容保留。

## 设计决定

采用规则驱动的默认编排，保留 Matt 显式入口；理由与替代方案见 [Agent Note](../decisions/implemented/process/2026-10-16-primary-agent-worktree-development.md)。已有需求确认及授权继续有效。

## 测试策略

检查完整任务差异及全局规则的实际目标文件，运行文档校验、Agent Note 格式检查、文档投影测试和文档站构建。比较任务前指纹，确认 Matt 文件及链接没有变化；并行进行 Standards 与 Spec 审查。此项交付是流程文档，不以业务单测或真实多 Agent 任务证明规则已生效或效率已提升。

## 范围外

修改 Matt 原文或调用元数据、安装编排平台或其他 skills、修改产品行为、发布 Issue/PR、提交和推送，以及清理现有 worktrees。通用规则文档之外的宿主配置不在此次范围。

## 依赖与风险

执行依赖宿主实际允许的委派、Git 和工作区能力。全局规则对加载它的会话适用；尚未重载或使用其他宿主的会话不据此声明采用新流程。真实并行效率需在后续任务中观察。
