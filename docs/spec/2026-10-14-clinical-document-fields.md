# 病历字段补齐与问诊自动记录

Status: implemented

## 问题与目标

共享 Web/DSH 病历补齐独立家族史、过敏史，并贯通保存、预览、签署与修订。Agent 整理通过校验后直接记录，无须医生确认。执行由 [Issue #205](https://github.com/CaiZongyuan/clinmesh/issues/205) 追踪。

## 范围

覆盖病历编辑、预览、签署、病例库、修订、自动记录、后台来源持久化和旧建议恢复。正式签署及其他临床高风险操作沿用原授权。

## 用户故事

1. 作为医生，我希望独立录入家族史、过敏史，并在刷新和文书修订时恢复完整内容。
2. 作为医生，我希望问诊事实自动进入病历，只显示记录正文和整理状态，无须重复应用或确认。

## 验收条件

- [x] A1：病历新增家族史、过敏史，允许留空和主动清空，每字段最多 4,000 字；留空或缺失表示未记录，不自动生成阴性结论，不增加签署必填项。
- [x] A2：两字段保存后在刷新、切换病例、服务重启、签署预览、签署文书及修订中保留；新文书以稳定章节编码保存，体格检查章节标题与编辑、预览和只读展示一致。
- [x] A3：缺少新字段的存量草稿、签署件和旧回执仍可读取；读取与升级不改写原件或将旧过敏片段从既往史搬走。旧文书通过章节编码读取，不依赖原来的“查体”标题。
- [x] A4：新家族及过敏自述直接归入各自字段；保留否定、不确定性与来源，不推断未问及的阴性。
- [x] A5：移除建议区、待处理计数、应用、忽略、逐条核对和撤销。移除自动记录来源区和查看来源弹窗；保留进度、暂停、恢复、补录和失败重试。
- [x] A6：通过来源及独立语义校验后，经共享 Command 原子写入正文、来源和任务事实。保留人工正文及未保存输入；更新有效自动片段，人工片段的患者更正或矛盾另行记录。
- [x] A7：签署移除问诊核对摘要、勾选框及门禁；保留完整性、负责身份、预览令牌、期限和草稿版本校验，冻结在途提取，取消恢复，原件不可变。
- [x] A8：旧有效 pending 经升级重新整理，读取不写正文；暂停和失效身份继续限制任务，失败可重试，重启不重复记录。
- [x] A9：真实 Web、原生 DSH 旅程与 React 18/19 ShadowRoot 合同覆盖直接记录、无来源入口、未保存编辑、签署恢复，以及主题、语言、字号、窄分屏和长文本可达性。

## 设计决定

字段可缺失或为空，不回填旧件。当前自动记录取舍由[直接记录决策](../../.agents/notes/implemented/architecture/2026-10-14-consultation-direct-recording.md)拥有；独立字段与旧文书兼容见[病历字段决策](../../.agents/notes/implemented/architecture/2026-10-14-clinical-document-fields.md)。

## 测试策略

Contracts 验证五字段和移除的操作合同。Server HTTP 与 file-backed SQLite 覆盖直接记录、来源、重启、迁移、失败、签署冻结与原件不可变；Playwright 从真实 Web 和原生 DSH 验证旅程，React 18/19 合同覆盖记录正文、无来源入口与签署弹窗。

## 范围外

自动写入正式 AllergyIntolerance、推断家族疾病或未问及的阴性、全病历生成、Mobile 改造、自动签署和修改已签原件。医生补充来源与全病历整理由 [#177](https://github.com/CaiZongyuan/clinmesh/issues/177) 追踪。

## 依赖与风险

基于已合入的 #204。SQLite 建议字段 CHECK 需通过新增有序迁移扩展，完整保留旧数据及 rowid 顺序。模型分类由独立语义核对约束，确定性来源校验仍只证明引用归属，不能证明自然语言事实。
