# 病历字段补齐与自动整理建议区分

Status: implemented

## 问题与目标

医生病历记录缺少独立家族史、过敏史；自动整理建议与正文共享背景，缺少标题和结构边界。目标是在共享 Web/DSH 病历入口补齐字段并贯通保存、预览、签署与修订，让医生清楚辨认尚未应用的建议和当前正文。执行由 [Issue #205](https://github.com/CaiZongyuan/clinmesh/issues/205) 追踪。

## 范围

覆盖病历编辑、签署预览、已签只读展示、病例库和后续修订，以及字段内自动建议、页头状态与来源弹窗。沿用[字段内建议规格](2026-10-13-consultation-field-suggestions.md)的显式应用、版本、来源、撤销和签署保护合同。

## 用户故事

1. 作为医生，我希望独立录入家族史、过敏史，并在刷新和文书修订时恢复完整内容。
2. 作为医生，我希望先读正文，再在独立建议区审阅待应用内容，并看清应用影响的范围。

## 验收条件

- [x] A1：病历新增家族史、过敏史，允许留空和主动清空，每字段最多 4,000 字；留空或缺失表示未记录，不自动生成阴性结论，不增加签署必填项。
- [x] A2：两字段保存后在刷新、切换病例、服务重启、签署预览、签署文书及修订中保留；新文书以稳定章节编码保存，体格检查章节标题与编辑、预览和只读展示一致。
- [x] A3：缺少新字段的存量草稿、签署件和旧回执仍可读取；读取与升级不改写原件或将旧过敏片段从既往史搬走。旧文书通过章节编码读取，不依赖原来的“查体”标题。
- [x] A4：新整理的家族自述归入家族史，过敏自述归入过敏史，既往史保留既往疾病、手术和用药；保留否定与不确定性，不推断未问及的阴性。生成、轮询和刷新只展示建议，应用后才修改对应正文。
- [x] A5：每字段编辑框下设置带标题“自动整理建议”、待处理数量、内边距、边框和主题语义背景的紧凑区域。无建议或历史时不显示面板。待应用内容明确标注“待应用”，不作为真实输入值或 placeholder。
- [x] A6：建议文本优先阅读，应用建议为主要操作，忽略和来源为次要操作。替换建议显示“当前内容”“拟应用内容”并说明仅替换所示片段；更正和冲突有文字标记，失效目标、未保存输入与操作失败就地提示。
- [x] A7：已应用正文正常展示；来源、局部撤销和已处理条目放在默认折叠的“已应用与历史”。旧未核对与撤销待核对内容保持展开，不被历史折叠隐藏。
- [x] A8：应用、忽略、来源、历史、撤销、未保存编辑、失败恢复、签署准备、已签及无写权限继续遵守原合同；页头状态与待处理事项一致。
- [x] A9：真实病历入口及 React 18/19 ShadowRoot 合同覆盖明暗主题、中英文、应用字号、窄分屏、长文本与多建议；正文不受挤压，末尾操作可达，无横向溢出，按钮可键盘操作，关闭来源后回到原入口焦点。

## 设计决定

新增字段使用可缺失且可为空的文本合同；不回填存量数据，签署时保留已录入内容。建议归属扩展为五个病史字段，旧条目保留其持久 field。字段内区域以标题、计数、边框和分隔线表达层级，状态使用文字，颜色只作辅助。取舍由[病历字段决策](../../.agents/notes/implemented/architecture/2026-10-14-clinical-document-fields.md)拥有。

## 测试策略

Contracts 验证空值、缺失、长度与五字段建议。Server HTTP 与真实 file-backed SQLite 验证保存、重启、建议应用与撤销、签署章节、修订和旧件不可变；迁移覆盖存量建议的来源、锚点、审阅及逆操作数据。Playwright 从真实产品入口验证字段恢复和签署；共享来源弹窗使用 React 18/19、ShadowRoot、窄宽度、主题和字号合同验证层级、滚动和焦点。

## 范围外

自动写入正式 AllergyIntolerance、推断家族疾病或未问及的阴性、全病历生成、Mobile 改造、自动签署和修改已签原件。医生补充来源与全病历整理由 [#177](https://github.com/CaiZongyuan/clinmesh/issues/177) 追踪。

## 依赖与风险

基于已合入的 #204。SQLite 建议字段 CHECK 需通过新增有序迁移扩展，完整保留旧数据及 rowid 顺序。模型分类由独立语义核对约束，确定性来源校验仍只证明引用归属，不能证明自然语言事实。
