# 门诊诊疗页头部紧凑化

Status: implemented

## 问题与目标

门诊诊疗页的病例头部由患者信息行、分级·过敏徽章行、完诊清单、生命体征五列网格和章节标签栏纵向堆叠，源码估算约 250px。在 1280×800 等常见笔记本视口上约占内容区三分之一；矮视口下 banner 触发 `max-h-[50%]` 内部滚动，需要滚动才能看到生命体征，主内容区可用空间不足。

目标：在不删除任何信息、不新增交互状态的前提下，把头部压缩为「一行患者身份 + 一行完诊清单 + 一行生命体征 + 标签栏」，桌面宽度下约 140px。

## 范围

- 医生门诊诊疗页病例头部：`apps/web/src/app/doctor/` 的 `PatientBanner`、`EncounterCompletionChecklist` 与章节标签栏高度。
- 患者身份行合并：头像缩小；性别与年龄合并展示；分诊分级徽章、过敏徽章并入身份行；门诊号与主诉作为小字同行显示，空间不足时截断。
- 生命体征由五列网格改为单行横向摘要，窄屏允许换行。
- 完诊清单 chip 收紧高度，保持固定等宽。
- 章节 `TabsList` 高度收紧。
- 适用桌面与移动宽度；不改变任何数据流、接口与业务规则。

## 用户故事

1. 作为医生，我希望头部更薄，以便在笔记本视口下看到更多病历内容。
2. 作为医生，我希望完诊清单与生命体征保持常驻可见，以便随时掌握完诊门禁进度和体征依据。
3. 作为医生，我希望分诊分级与过敏信息在患者身份行一眼可见，以便不漏风险信息。

## 验收条件

- [ ] 视口宽度 ≥1024px 时，自 banner 顶到章节标签栏下缘的头部总高度不超过 160px。
- [ ] 分诊分级与过敏徽章出现在患者身份行内，不再存在独立的徽章行。
- [ ] 生命体征五项在同一水平行展示（窄屏允许换行），保留「体温（℃）/脉搏（次/分）/呼吸（次/分）/血压（mmHg）/血氧饱和度（%）」完整标签文本。
- [ ] 完诊清单仍位于患者信息与生命体征之间，chip 等宽且无横向滚动。
- [ ] 390px 与 320px 视口下头部可用、内容面板完整可达；banner 超高时保持内部滚动。
- [ ] 完诊按钮、状态徽章、字体大小设置等现有行为不受影响。

## 设计决定

- 采用「紧凑密度」方案：2026-10-07 与用户对比四个交互原型（紧凑密度、摘要折叠、信息侧移、滚动自适应）后确认。完诊清单是完诊流程门禁、生命体征是诊疗依据，两者必须常驻，紧凑密度是唯一不牺牲二者的方案；其余三个方案未获确认。
- 只做样式与结构密度压缩，不引入折叠、侧栏或滚动监听等新交互状态。
- 保持「清单在患者信息与体征之间」的 DOM 顺序与 `dl` 语义，e2e 位置断言不放松。
- 生命体征保留完整中文标签，不使用缩写（e2e 依赖精确文本）。
- 对比原型（`header-layout-options.html`，会话临时产物）仅作为设计依据，不进入版本库。

## 测试策略

- 组件单测：新增 `patient-summary` 渲染用例（jest-dom 断言身份行包含分级/过敏徽章、体征标签完整），先行失败再实现。
- e2e：`e2e/doctor-checklist.spec.ts`（1440/390/320 宽度循环、chip 等宽、清单位置、320px banner 内滚与体征可达断言）作为布局合同。
- 命令：`pnpm typecheck`、`pnpm lint`、`pnpm test`（apps/web 相关用例）、`pnpm test:e2e` 中 `doctor-checklist` 用例。

## 范围外

- 左侧排队列表、各章节页签内容区、完诊清单业务规则与完成判定。
- 摘要折叠（方案 B）、信息侧移（方案 C）、滚动自适应（方案 D）。

## 依赖与风险

- 无外部依赖。风险：身份行在窄屏换行使头部变高——用换行与截断控制，e2e 已有等宽与可达断言兜底。
