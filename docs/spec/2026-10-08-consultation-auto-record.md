# 问诊病史自动记录

Status: implemented

本文拥有自动触发、来源校验与任务恢复要求。来源扩展和十字段整理由[全病历整理](2026-10-14-doctor-full-document-recording.md)拥有；独立家族史、过敏史、直接写入、页面展示和签署行为由[病历字段补齐与问诊自动记录](2026-10-14-clinical-document-fields.md)拥有。

## 问题与目标

患者完整回答保存成功后自动整理已明确表达的病史并更新病历草稿，医生可继续编辑并负责正式签署。

## 范围

优先支持 DSH 中的门诊问诊。默认启用自动记录，按[十字段合同](2026-10-14-doctor-full-document-recording.md)分类患者病史；本文保留患者来源的触发与校验要求。患者来源为本次 Consultation Record，不读取 Case Truth、患者未公开档案或 DSH Assistant reasoning。

## 用户故事

1. 作为医生，我希望每次患者完整回答保存后自动整理病史，不必另行向 DSH 下指令。
2. 作为医生，我希望问诊不等待病历提取，以便继续与患者交流。
3. 作为医生，我希望仅记录患者明确表达的信息，未问及的事项不能自动变成阴性结论。
4. 作为医生，我希望患者自述的居家测量和外院诊断注明来源，而不是变成本院查体、检查结果或我的诊断。
5. 作为医生，我希望通过校验的新信息直接进入草稿。
6. 作为医生，我希望病历页面只展示正文和整理控制，不增加自动记录来源区域。
7. 作为医生，我希望重复处理不重复记录，旧拒绝证据继续保留。
8. 作为医生，我希望仅保护自己修改过的部分，其他病史仍能继续自动补充。
9. 作为医生，我希望人工写入的部分不被自动覆盖，患者更正另行记录。
10. 作为医生，我希望患者明确纠正时更新有效自动片段，无法判断的矛盾保留原陈述并记录待核实措辞。
11. 作为医生，我希望默认启用自动记录，并可暂停，以便暂时保持草稿稳定。
12. 作为医生，我希望恢复后自动补录暂停期间遗漏的回答，以便不丢失问诊信息。
13. 作为医生，我希望已有就诊先提示可补录，点击一次后再整理历史对话，以便避免进入旧病例就改变手工病历。
14. 作为医生，我希望提取失败时显示待更新状态并可重试，而已保存的问诊不受影响。
15. 作为医生，我希望刷新、切换病例和重连后仍保留来源、修改归属和处理进度。
16. 作为医生，我希望查看整理进度并按需重试，正式签署沿用病历完整性和版本校验。
17. 作为医生，我希望已签署文书不被迟到结果修改，不同患者与数据世代不会相互污染。

## 验收条件

- [x] A1：每次完整患者回答保存后自动触发提取；患者回复不等待提取，失败不阻断问诊。
- [x] A2：按五字段合同整理病史；用药与过敏自述不顺带修改正式记录。
- [x] A3：只记录明确自述；提问、未问及、患者不知道均不能写成肯定或阴性事实，患者自述不成为本院查体、检查结果或医生诊断。
- [x] A4：通过校验的事实直接进入草稿；不提供自动记录来源区，不形成待应用建议。
- [x] A5：每条自动增量在后台关联对应患者回答；来源关联在刷新后仍有效，页面不提供查看来源入口。
- [x] A6：重复处理不重复记录；旧拒绝证据保留，新来源通过当前校验后才能支持新记录。
- [x] A7：仅保护医生修改过的部分，其余自动片段继续更新；不替换人工正文。
- [x] A8：患者更正和矛盾沿用当前直接记录合同，保留人工内容与原陈述。
- [x] A9：新开始的 DSH 问诊默认启用，可暂停；暂停只停止自动整理，不停止问诊和对话保存。
- [x] A10：恢复时自动补录暂停期间未处理的回答，沿用人工修改保护与来源记录。
- [x] A11：已有就诊提示未整理内容，首次补录需医生点击一次，不因打开页面就改变既有草稿。
- [x] A12：提取失败显示待更新状态，允许重试；尚未写全的病历也能保存为草稿，正式签署仍校验必填内容。
- [x] A13：记录状态、来源、人工修改归属与处理进度持久化，刷新、重连与服务重启不丢失。
- [x] A14：重试、重复事件与乱序结果不重复记录或覆盖新内容；并发人工修改不被迟到结果覆盖。
- [x] A15：患者、Encounter、Workspace/Epoch 严格隔离，切换患者与重置后旧结果不能写到新上下文；写入仍受岗位、就诊责任、版本、幂等和审计规则约束。
- [x] A16：签署无需问诊核对摘要或勾选确认，沿用病历完整性和版本校验。
- [x] A17：签署准备期间停止自动写入，迟到结果不得修改已签署文书；取消签署后允许恢复未完成记录。

## 设计决定

ClinMesh 拥有自动编排、病史提取规则、增量合并与共享 Command；DSH 提供辅助模型能力。设计理由见 [自动记录决策](../../.agents/notes/implemented/architecture/2026-10-08-consultation-auto-record.md)。

自动记录消费已保存的 Consultation Record，不复制或监听整个 DSH Session。来源和人工修改归属保存在服务端；增量合并不能依靠整篇模型重生成或仅在浏览器维护编辑保护。复用现有模型桥接、Query/Command 和持久任务机制，不新增任意 HTTP、SQL、FHIR write 或宿主源码补丁。自动记录的新 schema、HTTP 或 CLI 合同变化须同步 owning Operation Catalog、运行时 Skill 和命令示例漂移测试。

病历草稿允许不完整，签署合同仍负责完整性校验。人工未保存修改必须在并发更新中被保留；片段归属与三方合并保护局部内容，不能以整字段锁定代替部分保护。

## 测试策略

主要 seam 使用现有公开问诊 HTTP 与病例 Query：驱动真实 runtime、Command、file-backed SQLite 和持久任务处理，仅替换外部模型网络边界。通过重新读取草稿、记录状态、来源和审计证明行为，不以模型声称成功、私有函数调用次数或组件内部状态作为验收。现有问诊 HTTP 合同、模型桥接合同及持久 outbox 恢复测试提供先例。

同一主要 seam 覆盖 A1–A3、A7–A17 的业务矩阵，包括非法模型 JSON、伪造来源、提问被误提取、否定、更正、矛盾、重复/乱序、并发编辑、重试、重启及 Epoch reset。模型桥接合同只验证平台 wiring、辅助调用与输出约束，不复制业务矩阵。

Playwright 覆盖直接记录、无来源入口及去重，以及暂停、补录和签署恢复的交互。Surface 与对话框覆盖 React 18/19 和 ShadowRoot；组件合同不能替代真实 DSH Session。最终从统一 launcher 的原生 DSH 入口验证：人类在问诊界面发送问题、患者回答后无需宿主主会话额外指令即更新草稿，同时验证已有 Agent 草稿 action 和人工签署路径不回归。只使用合成数据，常规 CI 不依赖真实模型凭证或付费调用。

## 范围外

自动诊断、治疗计划、正式过敏记录写入、自动开药与自动签署；本次不要求 standalone Web 具有模型配置或入口体验 parity。

## 依赖与风险

依赖已配置的 DSH 辅助模型桥接。模型输出必须校验并关联公开问诊原文；不可把未验证输出或整篇重生成结果直接覆盖草稿。

自动记录、局部人工编辑保护、暂停补录、失败恢复、来源追溯与签署冻结均已实现。当前写入边界由[直接记录决策](../../.agents/notes/implemented/architecture/2026-10-14-consultation-direct-recording.md)拥有；[片段归属决策](../../.agents/notes/implemented/architecture/2026-10-08-consultation-history-ownership.md)和[记录恢复决策](../../.agents/notes/implemented/architecture/2026-10-08-consultation-recording-recovery.md)保留仍有效的理由。分层证据边界见[组合验收决策](../../.agents/notes/implemented/testing/2026-10-10-native-consultation-recording-journey.md)。真实模型验收需要有效模型能力；确定性替身证明合同，真实模型成功样本不代表医学语义质量保证。
