# 门诊处方开具具体报错反馈与本院/国家参考药品目录分轨闭环

Status: implemented

## 问题与目标

门诊全流程走查中暴露出两个相互关联的处方开具与目录流转卡点：

- 右侧「待开具处方」区域点击「正式开具处方」被服务端拒绝时（例如已确认主诊断 `R50.9` 不在磷酸奥司他韦胶囊允许适应证 `J11.1` 范围内、尚未确认主诊断、与活动药物过敏冲突，或剂量与数量超出目录限制），服务端虽已返回细分 `reason` 错误码，但待办确认入口将所有 `CATALOG_CONFLICT` 与 `WORKFLOW_CONFLICT` 一律合并为笼统提示“当前诊断、过敏信息、目录或处方状态不允许正式开具，请检查后重试。”，导致医生无法判断具体拦截项，只能逐项盲目排查。
- 当运行环境已同步国家医保药品分类与代码参考库（共 `269,110` 条品规）时，「选择药品」弹窗默认直接展示参考目录分页结果，将本院有定价、有库存批次与处方规则的院内药房目录完全掩盖；医生从国家参考目录选药并正式开具后，服务端虽将其标记为院外参考品规（`external: true`、单价 `0` 分），却仍无条件创建金额为 `0 元` 的 `ChargeItem` 与 `charge_record`，导致门诊收费预览因收款明细要求正数金额而报错卡死，门诊药房队列又因仅关联院内目录而无待发记录，若单张处方混用院内与院外药品还会使处方永久停留在部分调剂状态。

目标：在不堆砌药品列表行内适应证标签的前提下，让门诊处方待办开具失败直接给出具体可操作的中文原因；同时在药品选择弹窗中将「本院药房」与「国家参考目录」显式分轨且默认展示「本院药房」，禁止单张处方混开两类来源，并打通纯「国家参考目录」电子外延处方不进院内收费与药房的完整闭环。

## 范围

适用门诊医生、门诊收费员、门诊药师及对应 Agent 工具入口，覆盖 standalone Web 与 DSH Surface、简体中文与英文界面、浅色与深色主题，以及 `1101px`、`826px` 两档 Surface 宽度。

1. 门诊医生右侧「待开具处方」确认入口与处方页正式开具入口的错误原因展示统一。
2. 门诊「选择药品」两栏弹窗的「本院药房 / 国家参考目录」分段切换、默认来源、空状态引导与院外外延处方说明。
3. 门诊处方草稿与正式处方的同源约束（禁止同一张处方混用「本院药房」与「国家参考目录」药品）。
4. 纯「国家参考目录」外延处方正式开具后的领域事实、费用豁免、完诊门禁与撤回边界。
5. 相关架构文档、[医生运行时 Skill](../../skills/clinmesh-doctor/SKILL.md) 及 [Agent Note](../decisions/README.md) 同步。

## 用户故事

1. 作为门诊医生，我希望在右侧「待开具处方」点击「正式开具处方」被拦截时直接看到具体原因（如已确认诊断不在该药适应证范围、尚未确认主诊断、存在活动药物过敏冲突或用法用量超限），以便一步调整诊断或处方，而不用在多个条件之间盲猜。
2. 作为门诊医生，我希望打开「选择药品」弹窗时默认看到「本院药房」有库存定价的药品，并在需要院外品规时显式切换到「国家参考目录」，以便日常院内开药不被 26.9 万条国家参考目录淹没。
3. 作为门诊医生，我希望切换到「国家参考目录」时清楚看到院外外延处方不在本院收费和发药的说明，且同一张处方不会误把本院药房药品与院外参考药品混在一起，以便患者院内缴费取药和院外购药互不阻塞。
4. 作为门诊医生，我希望开具纯「国家参考目录」外延处方后能够正常满足用药结论门禁并完成接诊，在未调剂前仍可按规则撤回，同时不会给门诊收费员制造无法结清的 `0 元` 账单。
5. 作为门诊收费员和门诊药师，我希望收费待缴队列和药房待发队列只出现真实需要在本院收款与发药的「本院药房」处方，以便正常完成收款、审方和按批次发药。

## 验收条件

### 处方开具失败原因反馈

- [x] 在门诊医生右侧「待开具处方」面板点击「正式开具处方」失败时，前端按服务端返回的细分 `reason` 展示具体可操作说明，覆盖主诊断未确认、已确认诊断不在所选药品允许适应证范围、与已确认活动药物过敏冲突、用法剂量或数量不符合目录规则、单张处方混用本院药房与国家参考目录药品、本次就诊已有有效处方、已记录无需用药结论、当前就诊不处于可开方活动状态等场景；仅在服务端未返回已知细分 `reason` 时才回退通用冲突提示。
- [x] 右侧「待开具处方」与处方页直接开具共用同一套处方错误原因映射，中英文文案一致，不暴露内部异常堆栈、SQL 字段或原始枚举名。
- [x] 「选择药品」弹窗的候选列表保持紧凑整洁，不在每一行常驻铺设适应证编码或长串适应证徽标。

### 「本院药房」与「国家参考目录」显式分轨

- [x] 点击「添加药品」打开「选择药品」弹窗时，左栏顶部提供「本院药房」与「国家参考目录」显式分段切换，默认选中「本院药房」。
- [x] 点击草稿中已有的药品条目进入编辑弹窗时，自动定位到该条目所属目录来源（「本院药房」或「国家参考目录」）及对应详情填写区。
- [x] 「本院药房」页签展示当前启用的本院门诊药品及其规格、单价，按关键词在院内目录内检索；检索无匹配项或本院无可用项时显示明确空状态，并提供一键切换至「国家参考目录」的引导动作。
- [x] 「国家参考目录」页签按关键词检索国家参考药品品规，并在列表上方或详情区明确提示：国家参考目录药品仅生成电子外延处方，不在本院收费与药房发药。国家参考目录接口请求失败时保留重试入口，且不影响切回「本院药房」选药。
- [x] 保持两栏开具弹窗既有布局、Agent 目录定位属性以及「本院药房」受控下拉、「国家参考目录」自由文本用法填写方式不变，与[门诊与窗口岗位界面细节修整](2026-11-03-outpatient-detail-polish.md)兼容。

### 单张处方禁止跨源混开

- [x] 当前处方草稿或待开具人工清单已包含「本院药房」药品时，「国家参考目录」页签中的候选行置为不可选并在行内写明需与本院药房处方分开开具的原因；反之已包含「国家参考目录」药品时，「本院药房」页签中的候选行同样置为不可选并写明原因（编辑当前唯一条目自身除外）。
- [x] 服务端在保存处方草稿、直接正式开具处方以及通过诊疗建议待办确认处方时统一校验来源一致性；同一请求混含本院目录药品与国家参考目录药品时，返回 `CATALOG_CONFLICT` 及细分原因 `PRESCRIPTION_MIXED_CATALOG_SOURCES`，前端展示对应具体中文提示。

### 纯「国家参考目录」外延处方与「本院药房」处方闭环

- [x] 正式开具纯「国家参考目录」处方时，服务端照常创建正式 `Prescription` 与 FHIR R5 `MedicationRequest` 记录、清空处方草稿并记录审计与 Action Trace，满足门诊完诊门禁中的「用药结论已记录」条件，且在未撤回状态下支持按既有 `prescription.withdraw` 合同撤回。
- [x] 正式开具纯「国家参考目录」处方时，服务端不创建 `0 元` 的 FHIR `ChargeItem` 与 `charge_record`，命令 `effects` 不包含虚构 `ChargeItem` 引用；该处方不进入门诊收费「药品费用」待缴队列，也不进入门诊药房待发队列。
- [x] 正式开具「本院药房」处方时，继续按本院真实目录单价创建 `ChargeItem` 与 `charge_record`，完诊前后按既有规则进入门诊收费待缴队列，缴清后进入门诊药房审核与按批次调剂发药。

### 跨宿主与响应式兼容

- [x] 上述改动在 standalone Web 与 DSH Surface（覆盖 React 18.3.1 / 19.2 ShadowRoot 双版本对话框合同）、浅色与深色主题、`1101px` 与 `826px` 宽度下正常渲染与交互，分段切换、外延处方提示与错误横幅无重叠、无横向裁切。

## 设计决定

- **按需报错替代常驻适应证标签**：国家参考目录包含 `269,110` 条品规且不含结构化适应证约束，本院药房默认仅 `4` 种（执行 PCI 数据准备后共 `9` 种）演示药品；在列表每行铺设适应证徽标会造成视觉噪音且对国家目录形成误导，因此保持列表干净，在开具拦截时精准提示原因。
- **双源分段默认「本院药房」**：公立医院门诊日常开方以本院药房有库存目录为主，院外国家参考目录作为本院无药时的外延处方补充；显式页签切换消除“本地同步参考库后院内目录消失”的隐式回退行为。
- **单张处方单一履约来源**：本院药房处方绑定院内收费、医保结算与药房批次调剂状态机，院外外延处方不在本院收费或发药；禁止单张处方混开两类来源可从根源消除部分计费和永久 `partial` 调剂死锁，无需拆分双轨子处方聚合。
- **外延处方零院内账项**：纯「国家参考目录」处方保留正式临床请求事实（`Prescription` + `MedicationRequest`）以满足临床记录、完诊门禁与可撤回追溯，但不生成 `0 元` 院内 `ChargeItem`，遵循[临床业务流程](../architecture/clinical-workflows.md)中“临床请求与计费触发点分离”的约束。流程边界变化见[门诊本院药房与国家参考目录分轨决策](../decisions/implemented/architecture/2026-11-05-outpatient-external-prescription-split.md)。

## 测试策略

- 服务端单元与集成测试（`apps/server/tests/`）：
  - 验证保存处方草稿、直接开具处方与 `doctor/cases/:caseId/recommendations/prescription/actions/confirm` 在混用本院与参考目录药品时统一返回 `CATALOG_CONFLICT` 与 `PRESCRIPTION_MIXED_CATALOG_SOURCES`。
  - 验证纯「国家参考目录」处方正式开具后生成 `Prescription` 与 `MedicationRequest`、满足 `GET /api/his/v1/encounters/:id/completion` 的 `medication-conclusion` 门禁、支持 `prescription.withdraw` 撤回，且不产生 `ChargeItem` / `charge_record`、不出现在收费与药房队列。
  - 验证「本院药房」处方继续生成真实金额 `ChargeItem`，收费预览、收款提交与药房审方发药全链路通过。
- 前端组件与工作台测试（`apps/web/src/app/doctor/*.test.tsx`）：

- DSH Surface 浏览器合同与 Web E2E（`apps/dsh-web/src/client/*.browser.test.ts`、`apps/web/e2e/diagnosis-prescription.spec.ts`）：

  - 在 Playwright 端到端旅程中验证默认从「本院药房」选药走通收费发药，以及切换「国家参考目录」开具外延处方走通完诊且不产生 `0 元` 待缴账单。
- 文档与 Skill 同步检查：更新 [临床业务流程](../architecture/clinical-workflows.md)、相关 [医生 Skill](../../skills/clinmesh-doctor/SKILL.md) 错误恢复说明与新增 Agent Note 后运行 `pnpm doc-sync` 及对应漂移测试。

## 范围外

- 门诊患者头部「助手已准备 / 助手准备中」与建议失败状态的联动展示，由 [Issue #397](https://github.com/CaiZongyuan/clinmesh/issues/397) 负责。
- 在药品选择列表行内常驻展示适应证标签，或为 `269,110` 条国家参考目录补充适应证规则。
- 住院医嘱的药品目录检索、剂量换算与计费规则（沿用现有住院目录合同）。
- 院外社会药房电子处方流转平台对接、院外医保结算或药品配送状态追踪。

## 依赖与风险

- 药品选择弹窗默认定位「本院药房」，检索国家参考目录品规时需显式切换到「国家参考目录」页签。
- 单张门诊就诊仅承载一份正式处方，且禁止混用「本院药房」与「国家参考目录」两类履约来源；与[门诊与窗口岗位界面细节修整](2026-11-03-outpatient-detail-polish.md)和 [Issue #397](https://github.com/CaiZongyuan/clinmesh/issues/397) 共享 `catalog-picker-dialogs.tsx` 与 `doctor-recommendations.tsx` 布局边界。
