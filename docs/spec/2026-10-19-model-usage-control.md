# 模型调用停用、预算与用量监控

Status: draft

## 问题与目标

ClinMesh 的患者回答、自动记录与核验、病历质控、五类诊疗建议等功能会随业务输入自动调用模型。一次操作可能产生多个任务和多次生成、格式纠错或恢复请求。当前 DSH 模型桥直接使用底层模型流，不创建原生聊天会话，也没有持久保存返回的 Token 用量；部分任务虽有模型路由绑定，但不能据此统计每次实际请求及其费用。前端暂停、分通道并发与超时限制不能提供累计费用保护。

目标是让管理员看清哪些功能在调用哪个 Provider 和模型、消耗多少、因何触发，并能在服务端统一停用和限制额度。现有自动记录压测入口已无继续保留的需求，应删除入口及引导其执行的当前文档。开发验证的执行授权由根 [AGENTS.md](../../AGENTS.md) 拥有；负载目标、既有规格和脚本不构成用户允许实际压测或失败后继续尝试的依据。

各 Agent 的触发、模型阶段、取消、重试和恢复的固定基线证据见[调用生命周期审计](../research/2026-10-19-agent-model-call-lifecycle.md)。本草案仍须覆盖建议暂停、质控旧正文任务和检验关闭信号等全局控制缺口，并明确原生会话及自动压缩的监控边界；患者回复并发去重及局部请求恢复由下述独立规格拥有，不能据此认定全局保护已经实施。

同正文保存引起的建议重算、同题回答推理去重及建议任务阶段恢复，详细行为与请求次数限制由[请求复用与恢复规格](2026-10-19-model-request-reuse-recovery.md)拥有。本规格继续拥有全系统停用、用量账本和 Token／金额额度；局部修复不代表这些全局保护已经实施。

## 范围

- 删除 `apps/web/e2e/recording-benchmark.ts` 废弃入口，并清理对应命令、当前部署教程、验证要求和引用；不另建、改名或保留可执行副本。历史记录应明确其不可作为当前执行入口或授权，不能删除历史消耗事实以掩盖问题。
- 对 ClinMesh 发起的直接模型调用与 DSH 桥接调用提供统一服务端停用和预算保护，覆盖患者人设、患者回答、实时记录、补录、来源核验、病历质控、五类诊疗建议、检验结果生成、目录补全，以及 DSH Host 中独立发起的医生代问意图识别。
- 建立逐次模型调用账本和可访问的监控仪表盘，保存实际 Provider、模型及调用策略，展示自动触发原因、请求次数、Token、费用估算、任务状态和预算余量。
- 对各功能的自动生成、格式纠错、限流重发、队列恢复及人工重试建立统一归属；所有实际请求均受同一停用与额度规则约束。

## 用户故事

1. 作为管理员，我希望一次停用 ClinMesh 的模型生成，阻止后台任务继续消耗，并能在刷新与重启后保留设置。
2. 作为管理员，我希望为模型调用设置明确额度，自动任务和重试都不能绕过额度继续请求。
3. 作为管理员，我希望查看每次调用的功能、原因、实际模型和用量，识别连锁触发、重复请求及费用待确认的请求。
4. 作为开发协作者，我希望用合成 Provider 验证计量与额度保护，不因执行需求或性能目标而自行进行压测、真实模型验证或失败后继续尝试。

## 验收条件

- [ ] A1：废弃自动记录压测入口及当前执行指引被移除，仓库不提供改名后的等价入口；引用完整，无失效路径。历史证据不会被表述为当前授权或待执行验收要求。
- [ ] A2：授权管理员可以从界面及受保护接口统一停用、恢复 ClinMesh 模型生成；无权限用户不能修改开关、预算或访问其他工作区的账本。停用设置在刷新和服务重启后仍生效，不依赖医生页面是否打开。
- [ ] A3：停用后，新的自动任务、手动生成、格式纠错、限流重发及恢复任务均不能发起模型生成请求；在途请求尽力取消，仍可能计费的请求有明确记录。已保存的来源和业务草稿保留，正常 HIS 读写及不调用模型的确定性检查仍可使用。
- [ ] A4：可配置的请求次数、Token 和费用额度在真实生成请求发出前由服务端检查，并为并发请求预占额度；所有调用入口及重试共享限制。达到上限后，界面明确显示停止原因，重启、重连和后台队列恢复不能绕过限制。
- [ ] A5：记录每个实际请求尝试的稳定身份、所属任务与调用种类、触发原因、工作区和必要的业务关联、Provider、模型、推理策略、配置的输出上限、开始与结束时间及结果；可关联服务商请求 ID 时一并保存。不能仅按一次逻辑任务记一条成功记录而遗漏重试。
- [ ] A6：DSH 桥接和直接调用均提取服务商返回的用量，按服务商语义保存输入、输出、缓存及推理用量，避免重复累加；费用估算保留币种与价格依据。缺少用量或价格、失败、取消、断流和超时均明确标为未知或待确认，不能显示为零消耗。
- [ ] A7：仪表盘可按日期、功能、Provider、模型及授权业务范围查看汇总和逐次请求，展示失败、拒绝、在途、费用待确认及预算剩余状态；空、加载与读取失败状态明确。已保存的历史实际模型不被当前模型设置覆盖。
- [ ] A8：界面说明监控覆盖 ClinMesh 主动发起的调用，区分后台调用、DSH 原生会话统计、费用估算和服务商实际账单；第三方费用不冒充 DSH 官方账户费用。
- [ ] A9：统一停用和额度限制在 DSH Host 独立调用入口同样有效，医生代问意图识别不能绕过；覆盖不到的 DSH 原生请求必须明确显示边界，不声称统一拦截整个宿主的所有请求。
- [ ] A10：模型失败后的自动继续策略可识别、可限制并可审计；本需求不授权开发 Agent 为验证而自行继续请求，也不默认授权新增付费重试。运行时默认策略须在设计确认后明确写入实现合同。
- [ ] A11：账本、日志与监控不保存提示词、患者正文、模型正文、凭证、Authorization 或带敏感参数的地址；任务与模型元数据在运行时边界验证。价格未知和账本故障时的额度保留与拒绝策略明确，不能静默绕过保护。
- [ ] A12：使用合成 Provider 的确定性验证证明停用、预算预占、超限拒绝、重试分别计量、断流与未知用量、权限、重启恢复和 DSH 独立入口保护；不进行压测或真实模型调用。

## 设计决定

本规格记录已确认的需求范围，尚未确定的交互、存储和预算策略不标为已批准。现有模型桥接可以保留，但监控不能依赖创建虚假的原生聊天会话。逐次账本必须反映实际请求与真实返回，现有任务模型绑定可以作为关联来源，不能代替调用账本。

停用与额度检查由实际请求的服务端边界执行；前端暂停仅属于视图行为，不能承担计费保护。DSH Host 独立意图识别与 ClinMesh Server 的模型请求必须共享受信控制策略。具体跨进程协议、失败恢复和存储取舍在实施前另以 Agent Note 固定，不修改 DSH 上游源码或维护宿主补丁。

以下设计项待确定：仪表盘所在入口与权限细节、预算周期与作用域、缺省额度及启用条件、不同 Provider 的价格与用量映射、单次输出及推理上限、运行时自动重试与格式纠错的默认策略、在途未知费用的预占与对账规则、统一控制在多进程部署下的一致性，以及账本保留周期。

## 测试策略

常规验证只使用合成数据、受控模型适配器和临时数据库；通过公开接口验证授权、设置持久化和账本查询，通过受控模型边界验证每次实际尝试前的停用及额度检查。使用少量确定性请求与调度屏障证明并发预占和去重，不通过持续注入、饱和负载或真实服务调用验证预算。界面覆盖空、失败、未知费用、已停用和额度耗尽状态。

任何后续压测或真实模型开发验证均遵守根 AGENTS.md 的执行授权规则；规格批准、Issue 创建与实施授权本身不构成该类执行许可。失败后保留诊断并停止，不自行重复请求。

## 范围外

- 不新增压测入口，不以限额压测替代删除，不执行或恢复既有压测。
- 不修改 DSH 官方账单、上游源码或原生会话 transcript，不承诺完整汇总由其他 DSH 插件或外部 Agent 自行发起的请求。
- 不重建缺少用量数据的历史精确账单，不把价格估算当成服务商扣费凭证。
- 不擅自修改自动记录、诊疗建议和质控的临床触发条件，不新增逐条确认流程。

## 依赖与风险

实际金额依赖各服务商的价格、用量与账单能力；服务端取消不能保证服务商停止生成或停止收费。上游内部重试和未返回用量的请求可能存在观测缺口，须通过受支持的扩展边界确认覆盖程度并明确展示。预算具体值和上述设计项尚未确认，Issue 保持待梳理状态；实施及任何真实服务验证均不由本次提 Issue 自动授权。
