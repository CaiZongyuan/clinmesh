# 模型用量监控与可选额度控制

Status: approved

## 问题与目标

ClinMesh 的患者回答、自动记录与核验、病历质控、五类诊疗建议等功能会随业务输入自动调用模型。一次操作可能产生多个任务和多次生成、格式纠错或恢复请求。当前 DSH 模型桥直接使用底层模型流，不创建原生聊天会话，也没有持久保存返回的 Token 用量；部分任务虽有模型路由绑定，但不能据此统计每次实际请求及其费用。前端暂停、分通道并发与超时限制不能提供累计费用保护。

目标是让参与者看清哪些功能在调用哪个 Provider 和模型、消耗多少、因何触发，以用量监控为主要能力，提供可选的服务端停用和额度保护。控制系统默认启用，请求次数、Token 与人民币费用上限分别默认为“无限”；本地模型和不需要限额的部署无需填写预算或价格即可使用，仍须可靠记录每次调用。默认启用控制系统不改变各临床功能已有的触发与启用条件。

现有自动记录压测入口已无继续保留的需求，应删除入口及引导其执行的当前文档。未经用户针对本次执行明确允许，不得运行压测或真实模型开发验证；失败后不得自行重试、改参重跑、换模型继续或扩大负载。实施须将该执行约束补入根 [AGENTS.md](../../AGENTS.md)；负载目标、既有规格、脚本和 Issue 实施授权均不构成该类执行许可。

各 Agent 的触发、模型阶段、取消、重试和恢复的固定基线证据见[调用生命周期审计](../research/2026-10-19-agent-model-call-lifecycle.md)。该审计保存历史基线；其中已由请求复用与恢复规格交付的取消、去重和阶段恢复不重复建设。全局控制仍须覆盖所有实际派发边界，包括检验生成和 Host 独立识别，并明确原生会话及自动压缩的覆盖边界。

同正文保存引起的建议重算、同题回答推理去重及建议任务阶段恢复，详细行为与请求次数限制由[请求复用与恢复规格](2026-10-19-model-request-reuse-recovery.md)拥有。本规格继续拥有全系统停用、用量账本和 Token／金额额度；局部修复不代表这些全局保护已经实施。

## 范围

- 删除 `apps/web/e2e/recording-benchmark.ts` 废弃入口，并清理对应命令、当前部署教程、验证要求和引用；不另建、改名或保留可执行副本。历史记录应明确其不可作为当前执行入口或授权，不能删除历史消耗事实以掩盖问题。
- 对 ClinMesh 发起的直接模型调用与 DSH 桥接调用提供统一服务端停用和预算保护，覆盖患者人设、患者回答、实时记录、补录、来源核验、病历质控、五类诊疗建议、检验结果生成、目录补全，以及 DSH Host 中独立发起的医生代问意图识别。
- 建立逐次模型调用账本和可访问的监控仪表盘，保存实际 Provider、模型及调用策略，展示自动触发原因、请求次数、Token、费用估算、任务状态和预算余量。
- 对各功能的自动生成、格式纠错、限流重发、队列恢复及人工重试建立统一归属；所有实际请求均受同一停用与额度规则约束。

## 用户故事

1. 作为管理员，我希望一次停用 ClinMesh 的模型生成，阻止后台任务继续消耗，并能在刷新与重启后保留设置。
2. 作为管理员，我希望按需自定义额度，也能将任何一项设为无限；已设置的有限额度不能被自动任务和重试绕过。
3. 作为 Workspace 成员，我希望查看本工作区用量汇总，并在原有业务权限内查看请求的功能、原因、实际模型、任务与消耗。
4. 作为开发协作者，我希望用合成 Provider 验证计量与额度保护，不因执行需求或性能目标而自行进行压测、真实模型验证或失败后继续尝试。

## 验收条件

- [ ] A1：废弃自动记录压测入口及当前执行指引被移除，仓库不提供改名后的等价入口；引用完整，无失效路径。历史证据不会被表述为当前授权或待执行验收要求。
- [ ] A2：默认启用且请求次数、Token、人民币费用上限各自为无限。部署维护者通过部署配置管理总开关、总额度、统一价表和汇率；Workspace 管理员通过界面及受保护接口管理本工作区开关和额度，不能放宽部署限制或修改统一价表。刷新、重启及 Epoch 重置不改变设置和累计数据。
- [ ] A3：停用后，新的自动任务、手动生成、格式纠错、限流重发及恢复任务均不能发起模型生成请求；在途请求尽力取消，仍可能计费的请求有明确记录。已保存的来源和业务草稿保留，正常 HIS 读写及不调用模型的确定性检查仍可使用。
- [ ] A4：每次真实生成请求均同时检查部署与 Workspace 限制，并对所有适用的有限额度原子预占。只有全部检查通过才派发；并发、重试、重启和队列恢复不能绕过。请求次数、Token 与人民币费用可独立自定义非负上限或无限，零上限与无限含义不同。
- [ ] A5：记录每个实际请求尝试的稳定身份、所属任务与调用种类、触发原因、工作区和必要的业务关联、Provider、模型、推理策略、配置的输出上限、开始与结束时间及结果；可关联服务商请求 ID 时一并保存。不能仅按一次逻辑任务记一条成功记录而遗漏重试。
- [ ] A6：DSH 桥接和直接调用均提取服务商返回的用量，按服务商语义保存输入、输出、缓存及推理用量，避免重复累加。缺少用量、价格或汇率时明确标为未知、价格未配置或待换算，不能显示为零消耗；明确配置为零的适用单价才支持零费用估算。失败、取消、断流和超时保存已知用量，未知部分保持待确认。
- [ ] A7：Web 和 DSH 从 ClinMesh“设置 → 模型用量”进入完整页面，默认展示用量总览：请求、Token、费用与在途预占摘要，调用趋势、功能分布及最近请求；通过独立页签进入请求明细、额度与策略、只读计价说明。可按日期、功能、Provider、模型、结果及授权业务范围查看汇总和逐次请求，展示失败、拒绝、在途、费用待确认及预算状态。已结算、预占和未知量分别展示；金额汇总不能用已知部分冒充完整总额。空、加载与读取失败状态明确，历史实际模型不被当前设置覆盖。
- [ ] A8：界面说明监控覆盖 ClinMesh 主动发起的调用，区分后台调用、DSH 原生会话统计、费用估算和服务商实际账单；第三方费用不冒充 DSH 官方账户费用。
- [ ] A9：统一停用和额度限制在 DSH Host 独立调用入口同样有效，医生代问意图识别不能绕过；覆盖不到的 DSH 原生请求必须明确显示边界，不声称统一拦截整个宿主的所有请求。
- [ ] A10：默认保留现有有界格式纠错和明确可恢复故障重试，提供关闭自动重试的选项，不增加各任务原有重试机会。每次尝试独立记账并共享所有适用额度；已派发而结果未知的请求停止自动重发。请求复用与恢复规格已有的单元、generation、人工继续及成功步骤复用合同保持有效。
- [ ] A11：账本、日志与监控不保存提示词、患者正文、模型正文、凭证、Authorization 或带敏感参数的地址；边界元数据须验证。即使所有额度无限，不能在账本无法持久写入时派发新请求；无法核算某项有限额度时也必须拒绝。价格或汇率缺失本身不阻止未设置有限金额额度的请求。
- [ ] A12：使用合成 Provider 的确定性验证证明停用、预算预占、超限拒绝、重试分别计量、断流与未知用量、权限、重启恢复和 DSH 独立入口保护；不进行压测或真实模型调用。
- [ ] A13：部署与 Workspace 的每项额度首次设为有限时建立独立累计起点，只计入该起点之后派发的请求。之后调整上限、暂时切回无限、重启或重置 Epoch 均不重置起点；无限期间仍累计。监控统计始终保留起点之前的用量。
- [ ] A14：预占不足时拒绝请求，展示剩余量与需要的预占量；不自动降低输出上限、截断输入或改变推理策略。价格、汇率、用量映射或请求边界不足以支持可信预占时，阻止对应有限额度下的新派发；全部无限时继续记录可获取的用量与未知状态。
- [ ] A15：已派发或无法证明未派发的请求，在取消、超时、断流或重启后保留未知状态及适用预占，直到取得可信用量或管理员显式核对。人工核对留审计和依据，不修改原始服务商用量；不能因计时器到期自动释放，也不能将取消推断为零费用。无限额度下的未知记录不单独阻止后续调用。
- [ ] A16：重新启用、提高额度或账本恢复后，自动接续仍有效的待办步骤，沿用现有并发限制并复用成功步骤。过期或失权任务不执行；未处理来源保留；已派发而结果未知的请求仍须人工明确继续，不因恢复控制条件自动重发。
- [ ] A17：人民币费用估算保存原始计价币种、原币金额、价格版本、汇率版本及换算结果，价格和汇率均由部署维护者统一配置。修改价表或汇率只影响后续调用；仍保留的缺价或缺汇率明细可显式补算，并保留补算依据和修订记录，不伪装成调用时已知费用。
- [ ] A18：所有当前 Workspace 成员可看本工作区跨 Epoch 汇总；普通成员仅能查看活动 Epoch 内原业务权限允许的明细，旧 Epoch 明细仅管理员可看。管理员可看本工作区完整明细并管理自身控制设置；跨工作区明细、部署完整账本及统一价表写权限不能借此开放。
- [ ] A19：请求可可靠关联到执行阶段、任务、病例及明确来源。合批保留多个关联来源，区别直接触发与读取的证据；未知关联明确标注，不虚构单一根操作或将全部费用归给首个来源。首次监控之前的用量不补造为精确逐次记录。
- [ ] A20：逐次明细默认保留 90 天，管理员可设置保留天数或永久。清理保留跨日汇总、累计额度、累计起点及其必要审计；未结算记录在结算前不清理。清理不产生新额度，超期明细不承诺恢复、逐次核对或补算。
- [ ] A21：开发和验收不调用真实模型、不运行压测。移除废弃入口并同步根工程授权规则后，仍不能把需求批准、Issue 实施、历史测试或既有脚本当作新的执行许可。

## 设计决定

### 监控优先与双层控制

部署与 Workspace 各有一个总开关和三项额度，全部默认启用、无限；任一层停用都阻止新派发。首期不增加按功能、Provider 或模型设置的子额度，监控筛选不受此限制。无限是明确配置值，不用零或无法解析的数值表示。普通 HIS 读写及确定性检查独立于模型开关。

每项额度具有持久累计起点，第一次有限配置生效时建立，之后无限只是停止拦截，仍保留同一起点和持续消耗。金额控制以部署统一价表及汇率计算的人民币估算为依据，不等于第三方账户实际扣费。部署维护者通过配置文件管理全局政策与计价，不为本需求新增平台管理员角色。

### 逐次账本与真实归因

一次实际外部请求对应一条稳定尝试记录；原任务、阶段、批次、人工意图和重试关系均作为关联，不能用一条逻辑任务的最终结果覆盖多次请求。获准后可确认未派发的尝试与已派发或未知派发的尝试须区分；只有前者能够释放对应请求占用。拒绝事件可查询，但不冒充真实模型调用或产生 Token 费用。

直接 Provider、DSH bridge 和 Host 独立代问识别使用同一受信账本与控制服务。现有桥接保留，扩展用量和终态元数据，不创建虚假的原生聊天会话。Host 必须在实际 stream 前取得受信派发许可，取消与失联按在途未知处理；客户端传入的 workspace、角色、模型或估价不直接成为计费权限事实。

首期归因呈现请求到任务、阶段、病例、医生轮次、批次来源或报告等已有可信关联。自动记录存在多来源合批，建议由页面输入有效性变化触发，不能将当前关联推断为完整因果图。普通成员明细查询在服务端下推业务授权条件，不能以“请求由本人发起”代替病例责任权限，也不先取全部明细再在前端过滤。

### 预占、未知与恢复

每次实际派发前先持久记录并检查所有适用上限、原子预占；网络等待不占数据库事务。无限模式允许缺价、缺汇率或缺少实际用量的模型，界面如实展示未知；但账本不可写时统一停止新请求。有限模式必须能为对应维度给出可信预占边界，不能用期望消耗或一次历史均值冒充上界。

输入、输出、缓存与推理 Token 按各 Provider 实际语义归一化；缓存或推理字段可能已包含于其他计数，不盲目求和。保留原始用量计数字段、归一化版本与计价依据，不保留原始模型正文。请求结束时按可信已知量结算，释放可确认的剩余预占；未知部分跨重启保留，人工核对作为独立审计修订。

控制阻止造成的待办与模型技术失败、结果未知分别表示。控制恢复后调度有效待办，成功步骤不重做；取消或未知请求不能因开关恢复、人工改额度或队列重领而获得自动重发机会。关闭自动重试时不取消各业务原有的正常生成、筛选或独立核验步骤。

### 计价与保留

统一价表按实际 Provider、模型和可用计量项定义单价及币种，人民币汇率和单价均保留版本；明确的零单价可用于本地模型。计价版本在调用时冻结，历史补算独立标记。普通成员及 Workspace 管理员仅查看统一价表，不从界面修改全局计价。

90 天明细保留期可配置为其他正天数或永久；汇总与额度计数独立于明细生命周期。未结算明细不受到期清理影响，价格及汇率依据随必要引用保留。统计按真实调用时间，不能用仿真 Virtual Time 或 Epoch reset 重新获得额度。

### 界面与实施边界

采用交互预览的 A 方案，以用量总览为默认首页：顶部展示已派发请求、已知 Token、已知人民币费用及在途与未决预占，中部展示调用趋势和功能调用分布，下方展示最近请求并支持下钻。请求明细、额度与策略、计价说明使用独立页签，监控覆盖范围始终可见。该层级服务于默认无限、监控优先的目标，额度设置不占据首页主要区域。

管理员可以编辑本工作区开关、三项上限、自动重试与保留期，核对待确认用量；部署总政策只读，非管理员仅开放其授权的读能力。隔离交互预览只保存内存中的合成状态，不作为认证、持久化或真实模型控制的实现证据。

沿用[当前单实例部署](../demo-architecture.md)的单 Hono/SQLite writer；拟让 Host 与 Server 两进程共同遵守统一控制，本期不扩展为多个 Server writer 或分布式配额系统。模块接缝、持久边界及权衡由[统一调用账本与控制提案](../decisions/proposed/architecture/2026-10-21-model-usage-accounting-control.md)说明。

## 测试策略

常规验证只使用合成数据、受控模型适配器和临时数据库；通过公开接口验证授权、设置持久化和账本查询，通过受控模型边界验证每次实际尝试前的停用及额度检查。使用少量确定性请求与调度屏障证明并发预占和去重，不通过持续注入、饱和负载或真实服务调用验证预算。界面覆盖空、失败、未知费用、已停用和额度耗尽状态。

覆盖默认无限与零上限、三项首次设限的独立累计起点、无限切换不重置、部署与 Workspace 并发预占、单价和汇率缺失、格式纠错与所有恢复的逐次计量、同一尝试幂等结算、取消和崩溃窗口的保守占用，以及额度恢复与未知请求的不同处理。直接 fetch、DSH bridge、Host 代问分别验证，不能只在 completeJson 最外层计数。

通过公开界面及 HTTP 验证权限查询、当前与旧 Epoch、全局只读计价、有限额度编辑、人民币换算快照、补算、90 天清理保留汇总与未结算占用。实际 UI 实施后使用 Playwright 从 Web/DSH 真实入口验证，新对话框覆盖 React 18/19；原型点击只证明交互设计，不替代真实持久化或授权验收。

任何后续压测或真实模型开发验证均须另有针对本次执行的明确许可；规格批准、Issue 创建与实施授权本身不构成该类许可。失败后保留诊断并停止，不自行重复请求。

### 测试接缝与既有先例

优先从已有公开边界验证外部行为，复用真实 Provider、Hono 与临时 SQLite，将替身放在外部网络、合成模型流与受控调度输入。完整额度与权限矩阵由 HTTP 集成测试拥有，其他层验证自身接线与不可由该边界观察的行为。

| 验证归属 | 观察结果与现有先例 |

## 范围外

- 不新增压测入口，不以限额压测替代删除，不执行或恢复既有压测。
- 不修改 DSH 官方账单、上游源码或原生会话 transcript，不承诺完整汇总由其他 DSH 插件或外部 Agent 自行发起的请求。
- 不重建缺少用量数据的历史精确账单，不把价格估算当成服务商扣费凭证。
- 不擅自修改自动记录、诊疗建议和质控的临床触发条件，不新增逐条确认流程。
- 不增加按功能或模型的子额度、自动汇率抓取、完整跨功能因果图、平台管理员角色或多个 Server writer。
- 不将部署总限制或其他 Workspace 的明细向普通 Workspace 成员公开。

## 实施切分

1. 合同与持久内核：统一控制、逐次尝试、预占与结算、计价快照、权限查询及非空旧库迁移；使用合成派发边界验证，不提前宣称覆盖全部入口。
2. 全部实际调用接入：直接 Provider、DSH Provider/bridge、Host 代问识别以及后台任务取消和恢复；与已有请求次数及阶段恢复合同共同检查。
3. 仪表盘与管理：设置入口、汇总与下钻、Workspace 控制、人民币估算与只读价表、待确认核对及明细保留；完成真实入口和双版本浏览器验证。
4. 入口与文档收尾：删除废弃压测脚本与当前执行引导，补齐工程授权约束，更新当前架构、部署与测试 owner，完成完整变更审查。

以上为施工与集成顺序。执行票按可独立验收的端到端行为组织，每票包含所需合同、持久化、接口、视图与验证；分票结构及原生依赖由 [Issue #228](https://github.com/CaiZongyuan/clinmesh/issues/228) 追踪，确认后创建，最终使用一个集成 PR 完成整体验收。

## 依赖与风险

实际金额依赖各服务商的价格、用量与账单能力；服务端取消不能保证服务商停止生成或停止收费。上游不可见请求、没有可靠输出边界或缺少计量映射的模型须明确支持程度；无限监控与有限额度的能力不能混为一谈。旧历史因果、旧 Epoch 普通成员授权和清理后的逐次明细不能推断恢复。

本规格已批准，作为 Issue #228 的正式需求与验收依据。规格批准与授权实施是不同动作；本次需求讨论不自动授权业务代码、提交、GitHub 写入或真实模型验证。
