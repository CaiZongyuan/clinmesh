# 门诊与住院共享收款生命周期

Status: approved

执行追踪：[Issue #342](https://github.com/CaiZongyuan/clinmesh/issues/342)。本规格承接 [#225](https://github.com/CaiZongyuan/clinmesh/issues/225) 转出的共享收款范围（原 A01）；按已确认安排后续排期，本次仅登记需求。

## 问题与目标

门诊和住院现有收款流程均可用，已经共享渠道计划及 `RefundLedger` 退款生命周期；收款尝试、确认、资金分配和结果恢复仍分别由 `WorkflowService` 与 `InpatientPayments` 维护。目标是让两端使用同一收款 owner，保持现有收费、医保、首次结算及归档后调整的业务含义。

## 范围

- 统一门诊账单、住院预交金与补缴的收款尝试、确认、资金分配及查询恢复，保留部分和组合支付。
- 保留 Workspace、Epoch、患者、就诊、账单、费用、渠道尝试、原交易与 Command 回执之间的关联。
- 门诊和住院保留各自的业务门禁及预览入口，通过共享收款结果表达成功、拒付和结果未知；原交易退款继续使用既有退款 owner。
- 现有业务库、成功交易、未决尝试及回执在统一后仍可读取和恢复。若需要迁移，必须提供非空旧库和重启验证。

## 用户故事

1. 作为收费员，我希望两类就诊采用一致的收款结果和恢复规则，避免重复收款或把未知结果当成完成。
2. 作为收费员，我希望资金分配、预交金抵扣和剩余应收能够回查原就诊、账单及交易，后续退款仍引用原款。
3. 作为护士，我希望首次住院结算只根据确定资金结果完成，查询恢复后可继续清床。

## 验收条件

- [ ] C01：门诊和住院实际通过同一收款 owner 创建尝试、确认结果、分配资金和查询恢复，不各自维护同一生命周期的状态机。
- [ ] C02：两端分别完成部分及组合支付；住院预交金抵扣、补缴、未分配余额与已使用金额可从公开接口核对，关联就诊、账单、费用和原交易。
- [ ] C03：成功、拒付和结果未知分别可见；未知时查询原尝试取得确定结果，重试或重复结果不新增收款或分配。确定失败后按当前预览恢复，不复用过期余额。
- [ ] C04：相同幂等键并发或重放返回同一结果，不同载荷被拒绝；不同键竞争不能超收或重复分配，冲突有明确恢复路径。
- [ ] C05：所需住院资金未知时，首次财务完成与清床继续被阻断；查询原尝试成功后可继续。后续财务调整不倒退已发生的首次结算、出区、清床或归档事实。
- [ ] C06：原交易引用、可退余额及未知退款预占仍由既有退款 owner 核对；统一收款不重复记录退款或待遇分摊。
- [ ] C07：现有交易、未决尝试和回执跨重启可读、可恢复，原交易与分配关系不被覆盖；必要迁移通过非空旧库验证。
- [ ] C08：岗位、病区、Workspace 和 Epoch 隔离继续有效，越权被拒绝，正式动作及其恢复保留审计。

## 设计决定

收费、临床与住院门禁仍归原 owner；共享收款模块拥有资金尝试、确认、分配和结果恢复，业务适配层消费正式结果。接口按门诊和住院实际所需表达来源与引用，不新增任意交易写入口。职责及真实取舍见[支付与住院职责边界提案](../decisions/proposed/architecture/2026-10-21-payment-inpatient-drg-boundaries.md)，在本规格实现并验收前，该提案继续保持 `proposed`。

## 测试策略

主矩阵通过公开 HIS Query/Command、真实临时文件 SQLite 和确定性合成支付渠道验证。沿用 `outpatient-workflow-http.test.ts`、`inpatient-payments-http.test.ts` 及 PCI 联合账本的现有证据，并为统一 owner 补两类业务的分配、三种结果、原尝试恢复、幂等、独立数据库连接竞争和重启断言；从公开交易、账单和回执核对唯一性，不用各端旧成功路径代替共享实现验收。

Web 仅补两端实际收款入口及恢复接线；CLI/Catalog 或运行时 Skill 合同若变化，在同一 diff 同步 owner、示例漂移和恢复合同。全部使用合成 Provider 和临时业务库，真实模型及压测另行取得当次运行授权。

## 范围外

- 改动患者医保待遇算法、DRG 分组、临床状态机或病案归档规则。
- 新增成本数据 owner、完整医院成本核算、财政票据或真实支付/医保渠道。
- 重写既有退款 owner，或以恢复床位、解档、覆盖历史账目处理资金差异。

## 依赖与风险

既有门诊、住院、退款、医保和归档后更正实现均可作为接入前置；当前没有外部实施阻塞，后续排期由维护者安排。统一期间必须保持首次财务门禁与后续调整分别表达，保留未知尝试及原回执；持久化或合同如有变化，迁移及兼容证据属于本规格的验收范围。
