# 诊疗建议信封预算与分批瘦身

Status: implemented

## 问题与目标

大体量病例（多手术史、多既往诊断、大检验目录）触发诊疗建议与病历质控的预算类失败：提示"当前完整资料或候选结果超过自动资料读取请求预算""检验目录超过本轮自动读取总预算"，医生拿不到任何建议。2026-10-19 的真实病例（`01a13394…8b`）实测：必读证据 38 条占请求信封 243.8 KB / 256 KB，余量 12.2 KB；诊断参考目录全量 143 条占 42.4 KB；检验目录 100 项全量定义占 268.7 KB，使目录筛选每批只容纳 2-3 项、远超 8 批上限。

目标：在保持"不裁剪进入生成与核验的完整资料、不静默丢弃来源、失败明确保留草稿"安全边界的前提下，通过请求构成瘦身让预算类失败在此类合法大病例上不再出现。

## 范围

- `apps/server` 诊疗建议服务（`doctor-recommendations-service.ts`）的历史筛选、目录筛选与生成请求构成。
- 历史证据打包单元（`doctor-recommendation-evidence.ts`）的容量计量。
- 适用全部建议类型（diagnosis、laboratory、imaging、pathology、prescription）与门诊医生建议入口。

## 用户故事

1. 作为接诊多年可见历史较多患者的门诊医生，我希望系统自动读完并筛选历史后仍能给出建议，以便不必因资料量大而放弃辅助推荐。
2. 作为医生，当资料确实超出任何请求预算时，我希望得到明确说明且草稿不被改动，以便知道系统没有静默截断病历。

## 验收条件

- [x] 对 2026-10-19 失败病例同规模的合成病例（必读证据 ≥180 KB、可选历史 ≥19 条、参考目录 ≥140 条），诊断建议在固定模型 stub 下完成历史筛选并进入生成，不再出现 `AI_REQUEST_TOO_LARGE` 的 `missing-evidence` 终态。
- [x] 同规模病例的检验建议：目录筛选批次数在 8 批以内完成全部条目覆盖，`complete` 后进入生成；不再出现"检验目录超过本轮自动读取总预算"。
- [x] 历史筛选与目录筛选请求不再携带必读证据与已选证据的全文，改携带紧凑索引（id、kind、label 与有界文本摘要）；生成与独立核验请求仍携带完整必读与已选原文。
- [x] 单条历史记录按 UTF-8 字节预算打包：任何单包不超过字节上限，中文长记录按完整字段拆分为多个必读包，不产生超过信封余量的单包。
- [x] 筛选返回的编号必须能对应原始证据或目录条目；虚构、重复编号仍被拒绝。
- [x] 超出全部瘦身手段后的极端情况（必读资料自身超过信封）仍明确失败并保留草稿，提示语义不变。

## 设计决定

1. 筛选阶段（历史筛选、目录筛选）的请求载荷以"判断相关性所需的最小视图"为准：必读证据与已选证据降为紧凑索引；目录条目在筛选阶段使用不含 `reportDefinition` 等重定义字段的筛选视图。选中条目的完整真实定义只在生成、核验、归一化与保存阶段使用，归属与既有决策一致。
2. 目录筛选对存在检验目录项的检验建议始终执行，不再以"全量目录能否装进生成请求"为门控：瘦身后全量目录虽能装下，但 reviewed/selected 筛选审计与"生成只能使用已筛选目录项"的响应校验仍由筛选阶段提供。瘦身的收益是批次数受控（小目录通常单批完成），而非跳过筛选。
3. 历史筛选完成后，若必读与已选证据合入生成请求超限，服务端发起一轮收敛请求（新的桥接 schemaName `doctor_recommendation_history_consolidation`）：向模型提供全部已选完整记录与容量上限，让模型保留最相关的至多容量条；收敛请求自身超限时跳过，收敛后仍超限则维持既有明确失败路径。容量为 0（连最大一条已选记录也无法与必读资料同装）时不调用收敛模型：保留必读资料继续生成，并以处理通知向医生说明已选记录未纳入本次建议。历史筛选复用缓存保存收敛前的选择。收敛请求纳入建议执行账本的 `history-consolidation` 阶段（依赖全部 history-selection 批次）：同输入重试与恢复时随账本复用或重置，不独立重跑。该 schemaName 已加入 `packages/contracts` 的 `modelBridgeRequestSchema` 枚举。
4. 历史打包与目录批划分的容量判断统一按 UTF-8 字节计量，消除字符计数与字节信封在中文内容上的错位；字符上限保留为证据文本合同的硬上限。
5. 进入生成与核验的证据内容不变；本需求不改变快照指纹、复用键与失效条件对完整资料的覆盖。
6. 机制理由与被取代的打包规则由 Agent Note 记录，见 [建议信封预算瘦身决策](../decisions/implemented/architecture/2026-10-20-recommendation-envelope-slimming.md)；上一步机制见[分批证据读取决策](../decisions/implemented/architecture/2026-10-15-recommendation-context-budget.md)。

## 测试策略

- 单元与合同测试：`apps/server` 现有 vitest 入口。关键断言：筛选请求载荷不含必读/已选证据全文；字节打包上限成立；批次数受控；编号校验拒绝虚构；生成请求仍含完整必读与已选原文。
- 回归锚点：以真实失败病例的快照规模构造合成用例（合成数据），断言终态为 `ready` 路径而非 `missing-evidence` 预算失败。
- 运行 `pnpm test`（覆盖 `apps/server` 相关套件）与 `pnpm typecheck`；跨包合同变化时运行 `pnpm check`。

## 范围外

- 模型返回空建议（"模型本轮未形成可发布的建议"）的提示质量优化。
- `MODEL_UNAVAILABLE` 等环境性失败的自愈或告警。
- 病历质控（`clinical-document-quality.ts`）的输入预算与失败语义。
- 提高模型宿主的 256 KB 传输上限或更换模型。
- 生成阶段按批拆分（保持全病例视野的单次生成）。

## 依赖与风险

- 筛选阶段只看索引，对相关性判断的输入变少；候选记录与目录仍为完整筛选视图，生成阶段必读全文完整在场，独立核验与医生确认兜底。
- 目录筛选视图缺少 `reportDefinition` 后，模型按名称、编码、标本与适应证选择，选中条目的参考范围在独立核验经 `selectedCatalogItems` 完整提供；不存在按缺失字段虚构的通道（编号校验限制只能选已提供条目）。
- 收敛 schemaName `doctor_recommendation_history_consolidation` 是模型宿主桥接合同的新增项：`packages/contracts` 已同步，实际部署需要 DSH 宿主桥接接受该 schemaName 后收敛轮才可用；宿主未升级时收敛请求按既有模型失败路径处理（明确失败、保留草稿），不产生静默截断。
