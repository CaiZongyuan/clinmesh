# 住院病案首页、编码目录与召回边界研究

核验日期：2026-10-20。本文为[住院闭环规格](../spec/2026-10-20-inpatient-closed-loop.md)提供实施设计依据，区分已经核实的来源事实与候选方案，不定义当前产品能力，也不代替正式需求与决策记录。当前业务合同从[临床业务流程](../architecture/clinical-workflows.md#82-住院闭环后续)进入；医保清单与 DRG 的不同职责见[既有官方研究](2026-10-15-drg-official-evidence.md#医保清单诊断与手术操作)。

## 可直接采用的事实

1. 国家卫生计生委《住院病案首页数据填写质量规范（暂行）》将首页分成患者基本信息、住院过程信息、诊疗信息、费用信息四组；要求诊断依据能在病历中追溯。诊断使用 ICD-10，手术操作使用 ICD-9-CM-3；使用 DRGs 开展医院绩效评价的地区使用相应临床版。[S1，第 1—2 页]
2. 规范把诊疗事实填写责任交给临床医师，把分类编码责任交给编码员。主要诊断、其他诊断和主要手术操作的选择有业务原则，不能由费用最大、记录最早或数组第一项单独决定。[S1，第 2—6 页]
3. 仓库已经固定 `nhc-icd10-clinical@2022.r4`，没有固定手术操作目录。其 `2022` 是来源版本，`r4` 是 cn-health 数据构建修订，不能称为官方第四版。来源 Manifest 明示 `authorityVerified: false`，也没有证明它与医保诊断目录逐码等价。[S2][S3]
4. 海南省卫生健康委员会有可以直接取得的手术操作 XLSX，包含 `3.0` 工作表及修订说明，可提供有来源定位的固定演示子集。公开获取不代表已经取得完整码表的再分发许可，也不能证明该工作簿是全国截至核验日的最新适用版本。[S4]
5. 本次取得的首页规范没有规定 HIS 出院召回窗口。项目要求的是有明确状态门禁及审计的召回；具体开放至结算前还是结算后，属于产品取舍，不能写成全国统一规则。

## 病案首页的核心字段建议

建议首页显式声明为“住院病案首页核心字段集”，保留以下四组业务字段和独立审核信息。这是规格允许的有界字段集，不是完整国家上报表，不包含医保结算清单，也不承诺可直接上报。

| 信息组 | 建议字段 | 事实来源与编辑边界 |
| --- | --- | --- |
| 患者基本信息 | 合成患者标识、姓名、性别、出生日期；本次住院号、病案号、住院次数 | 来自患者及本次住院事实，首页只读展示其固定引用或快照。住院次数按该患者实际住院记录计算，不由医生随手填写 |
| 住院过程信息 | 入院途径、入院接诊虚拟时间、入院科室及病区、转科记录、出院科室、出区虚拟时间、离院方式 | 来自登记、护士入科、转科及出院事实；入院和出院时间按规范精确到分钟。登记受理时间不自动替代实际入病房接诊时间；收费结算时间不替代离开病房时间 |
| 诊疗信息：诊断 | 主要出院诊断一项、其他出院诊断有序列表；每项名称、分类代码、编码体系、来源版本、固定目录发布标识、入院病情、病历依据引用 | 由主管医生确认诊断事实及主次关系，病案人员核验分类编码。入院病情保留“1 有、2 临床未确定、3 情况不明、4 无”四类；本次没有其他诊断时明确为空，不从全部既往病史自动补齐 |
| 诊疗信息：手术操作 | 本次已实施操作列表、主要操作标记、实施时间、实施记录引用、术者；每项规范名称、分类代码、类别、编码体系和固定版本 | 从本次成功执行记录派生候选，医生与编码员确认主次及编码。申请、计划、已取消操作、既往史不得进入已实施列表。无操作应明确表示“本次无已实施操作” |
| 费用信息 | 按已声明类别汇总的逐项费用、冲正及费用净额、住院费用合计、结算事实引用 | 来自本次住院费用账及其不可删除的逆向记录。预交金是资金收付，不是医疗费用；不能把预交金与费用相加，也不能手填一个与费用账无关的总额 |
| 审核信息 | 主管医生、首页修订号、提交人和提交时间、编码审核人和审核时间、审核结论与退回原因、归档人和归档时间 | 各岗位 Command 形成独立事实。审核绑定明确的首页及依赖修订；审核后若允许修改，原审核不能继续用于归档 |

入院和出院时间定义直接来自规范第八条；四组信息及人员职责来自第二、二十三至二十七条。[S1] 四类入院病情及其解释沿用[既有官方研究](2026-10-15-drg-official-evidence.md#入院病情与-ccmcc)核验的清单规范，但该字段的复用不使本次首页成为医保清单。出生及入院信息特殊字段、全部人口学项目、麻醉与切口愈合项目、完整国家费用分类上报等未在此核心字段集中声明；需要扩大时应先补来源、字段合同和适用场景，不能自动用空字符串或“正常”伪造完整性。

归档最低门禁建议为：清床完成、核心字段完整、主要诊断唯一、所有编码属于声明的固定目录、操作均引用本次实施事实、账目与已结算事实一致、编码审核针对当前修订通过。归档只读需要由共享业务命令守住相关病案事实；只禁用首页按钮不能满足跨 HTTP、CLI 及已有写入口的约束。异步检查报告或费用仍能改变归档输入时，应在归档前收口相应在途任务，或明确定义另一个更正流程，不能让它们悄悄使已审核快照失效。这些是实施建议，具体门禁由正式合同拥有。

## 出院召回窗口建议

现有规格明确四个独立动作依次为护士出院处理、财务结算、清床、病案归档，要求召回受状态窗口限制，但没有给出时长或具体状态集合。参考项目虽然有结算后召回路径，其逆向规则不能直接成为 ClinMesh 已批准合同；[已有源码研究](openhis-itai-pro-architecture.md#住院业务流程)也明确相关并发测试证据不足。

建议首期召回窗口为：护士已完成出院处理、尚未结算、未清床、未归档，且本次住院的原床位仍由原占用事实保留。窗口采用业务状态，不任意发明“24 小时”等全国规则。这一方案仍为待决定的产品建议。

| 状态 | 候选召回行为及依据 |
| --- | --- |
| 已开出院医嘱，护士尚未出院处理 | 走受限撤销出院医嘱或出院任务；患者尚未出区，不冒充出院召回 |
| 护士已出院处理，未结算，原床仍保留 | 可召回；同一事务恢复本次住院的在院责任与行政状态，保留原出院及召回事件、原因、执行人和虚拟业务时间 |
| 已结算 | 首期建议拒绝；若开放，需要一并定义结算冲正、补缴与退预交金逆向记录及归属，不能仅把 Encounter 改回在院 |
| 已清床 | 首期建议拒绝；原床可能已有新患者，不能抢占，也不能默默创建新的床位关系。开放需要独立的恢复床位与冲突方案 |
| 已归档 | 拒绝普通召回；撤销归档、病历更正或真正再次入院是不同流程，不能绕过病案只读 |

召回必须绑定当前 Workspace/Epoch、本次住院、预期版本和幂等键，并在同一原子命令中重新检查床位占用及结算状态。召回与结算并发时只有一个前置状态合法的命令能成功；不能先成功结算再接受旧版本召回。既往已执行的给药、手术和已入账费用保留，已经停止或取消的医嘱不因召回自动恢复。真正开始另一次住院时仍创建独立住院事实，不能使用召回来合并两次就诊。这些是候选窗口的实施约束，最终选择应写入正式需求或相应决策及当前 owner。

## 采纳状态与验证边界

召回窗口、首页核心字段集和固定操作子集已由 [住院闭环规格](../spec/2026-10-20-inpatient-closed-loop.md)采纳。本文保留来源与核验范围，实际范围和验收以该正式规格及其引用的合同为准；属性名、模块文件拆分和存储表名由实现决定。

建议用现有测试验证：实际入病房时间与登记时间有区别；首页不能把申请显示为已实施；未知或其他版本编码被拒绝；主要诊断唯一；审核通过后修改使审核失效；无实施记录能以明确空操作集归档；归档后各真实写入口拒绝病案变更；允许窗口内召回成功，结算、清床或归档后失败；召回与结算竞争不会同时成功。涉及真实账目和执行事实的断言应通过共享业务入口，不能只对 UI 按钮是否禁用作断言。

本次未验证完整国家首页上报数据集、全国最新手术版本、医保版诊断与操作完整目录及映射、各地召回管理制度或正式医疗计费标准。未运行临床编码金标准审查，未将八个示例当作任何具体患者的治疗建议。
