# DRG 运营分析前置条件与建设路径

编写日期：2026-10-20。本文整理 DRG 运营分析所需的数据、规则、业务依赖和分阶段建设条件，供 ClinMesh 功能规划使用；不是已批准规格，也不表示相关功能已经实现。政策依据复用 2026-10-15 的[官方规则研究](2026-10-15-drg-official-evidence.md)，本次未重新外部核验。当前产品行为以[系统架构](../architecture.md)及其详细合同为准。

## 一、结论与适用范围

DRG 运营分析需要将同一次住院的病案、诊断与实际操作、费用、分组及支付结果关联起来。建设深度决定前置条件：病例结构分析需要可靠分组，费用效率分析还需要逐项费用和时间数据，支付分析需要地方政策和结算结果，真实盈亏分析进一步依赖医院成本核算。

| 分析层次 | 要回答的问题 | 必需条件 | 资料不足时的输出边界 |
| --- | --- | --- | --- |
| 病例结构 | 收治哪些病组、病例复杂程度如何 | 结构化病案、适用编码、可靠分组；CMI 等指标另需对应权重 | 无法分组的病例单列原因；无权重时不计算 CMI |
| 费用与效率 | 同组费用、药耗占比、住院日有哪些差异 | 上述基础，加逐项费用、住院时间和可比较样本 | 可以描述样本差异；缺少可比基准时不下达效率优劣结论 |
| 支付差异 | 预计支付与结算反馈为什么不同 | 适用地区、年度和机构的支付办法、参数、结算反馈 | 参数为合成或尚未取得地方依据时，只展示明确标记的模拟结果 |
| 成本与盈亏 | 病例或病组形成多少结余或亏损 | 财务确认收入、病例成本、成本分摊规则和期间口径 | 只有收费或支付标准时，不显示真实盈亏 |

分析功能不必等待全院住院、手术、药房、医保和财务系统全部建成。已有可信数据时，可以先通过冻结的分析快照验证；需要在院预警和岗位整改闭环时，再打通相应业务来源。ClinMesh 的病例、历史样本、价格、支付和成本演示均使用明确标记的合成数据。

本文聚焦 DRG。DIP 的分值、点值和地方支付规则需另行确认，不能直接套用 DRG 的指标和计算模型。

## 二、五类核心前置条件

### 2.1 结构化且可追溯的住院病案

每个病例需要有稳定的本次住院标识，关联患者、住院就诊、病案、费用账和结算记录。患者身份、住院号和病案号的归属遵循[领域词汇](../../CONTEXT.md)，不能只靠姓名匹配或把多次住院合成一条病例。

| 数据范围 | 至少需要确认的内容 | 主要责任方 |
| --- | --- | --- |
| 住院基本信息 | 患者基本特征、入出院日期、入院途径、离院方式；所选规则需要的新生儿等特殊字段 | 登记岗位、住院医生、病案岗位 |
| 诊断 | 主要及其他出院诊断、编码及版本、入院病情、正式确认与修订记录 | 医生确认临床诊断，病案编码岗位审核编码 |
| 手术与操作 | 本次实际实施的主要及其他操作、编码及版本、实施时间、来源记录 | 实施医生、相关执行岗位、病案编码岗位 |
| 文书与清单 | 病案首页、医保结算清单的来源、审核状态、修订版本 | 病案岗位、医保岗位及相应事实 owner |

诊断、操作和必要字段以选定规则的实际要求为准。申请、计划、取消操作和既往手术史不能替代本次实际实施事实。病案首页与医保结算清单是不同输出，共同字段来自一致事实；限定字段草稿不能宣称为可正式上传的完整清单。编码规范、入院病情及主要诊断选择的官方依据见[既有研究](2026-10-15-drg-official-evidence.md#医保清单诊断与手术操作)。

### 2.2 明确版本并经过验证的分组能力

首先确定分析使用的地区、年度、规则版本和适用范围，再准备相容的诊断及手术操作编码。现有临床版 ICD-10 不能仅靠名称相似或裸 code 相同就视为医保编码；不同编码体系之间的映射需要可核验依据。

分组能力至少需要覆盖所声明范围内的判定顺序、主要诊断与操作条件、适用的 CC/MCC 及排除规则、异常输入和未覆盖情形。只有病组名称表、手填组码或下载配置文件，均不足以证明已经实现正确分组。已有可信分组结果可作为分析输入，但须保留其来源、版本和校验状态。

每次分组保存输入快照、输入版本、分组器及规则版本、输出组别、命中依据和失败原因。诊断、操作或其他影响分组的字段修订后，旧结果应标记为过期；重算保留前后记录。费用和支付数据变化同样需要使依赖它们的分析结果失效，但不应无依据地改变临床分组。

基准样例需覆盖正确分组、缺字段、排除条件、边界和不支持路径，并有可核验的预期结果。大模型可以辅助解释、定位文书证据和提出待核实问题，组码、权重和规则判定由经验证的规则能力或可信来源提供。

国家规则与地方落地、版本切换及配置可得性的详细依据由[官方规则研究](2026-10-15-drg-official-evidence.md#版本地方落地与支付边界)维护；本文不另行维护当前全国或地方在用版本清单。

### 2.3 完整的逐项费用账

病例需要关联药品、耗材、检查、检验、治疗、手术、床位、护理等实际发生的费用。每条费用至少包含项目及版本、数量、计价单位、单价、金额、发生时间、执行科室和对应业务来源。

费用账需要能够解释计费触发点、重复执行防重、取消、退药、退记与冲正，并保留原始记录和反向记录的关联。明细、费用类别汇总和清单总额应可核对；收费项目、手术操作码、药品及耗材编码分别维护关联，不能混作一套代码。

缺失价格、数量不明或费用来源冲突需要显式暴露。未计价不能当作免费，药房发药不能直接等同实际给药，报告修订也不能重复生成同一检查费用。限定病例的计费与质控建议见[单病例方案](2026-10-15-coronary-drg-quality-control-plan.md#3-逐项计费与住院费用账)。

### 2.4 地方支付办法与结算反馈

如果目标包含支付预测或结算偏差，需要取得目标统筹地区及生效年度的适用办法，并明确医院级别或其他机构适用条件。按实际地方办法准备权重、费率、调整因素，以及高低费用病例、除外支付、特例单议等有关规则；并非每个地区都使用相同参数或同一公式。

支付分析分别保存国家版模拟、地方规则预测、申报结果、医保审核结算及后续调整。结算反馈需要关联病例、申报和规则版本，并保留扣减、拒付、撤销或冲正的原因。预计金额不能混作实际收入，国家分组结果也不能独立推导地方实际支付。

未取得地方材料时，费用分析与规则研究仍可推进。若使用合成权重、费率或支付办法，参数和所有衍生结果均标记为模拟，不能仅在说明页标注后把报表展示为真实结算。

### 2.5 独立的成本与财务收入数据

真实盈亏需要财务口径下可归属本次住院的收入，以及直接成本和按明确规则分摊的间接成本。成本可涉及药耗采购、人员、设备折旧和其他费用；需要声明直接成本、可变成本或全成本等具体口径，保存归集期间和分摊规则版本。

以下金额分别表达：

| 金额 | 含义及分析边界 |
| --- | --- |
| 收费总额 | 按项目形成并经过有效冲正调整的费用；不等于医院成本 |
| DRG 支付标准或预测值 | 适用规则下的支付参考；不等于最终到账或财务确认收入 |
| 实际结算与患者负担 | 按实际结算反馈分别记录；汇总时确认是否已包含在总额内，避免重复相加 |
| 财务确认收入 | 按明确收入确认及调整口径归属病例的收入；预交金和收款流水不能直接当作收入 |
| 病例成本 | 按声明的成本范围归集；不能以收费价格替代采购或资源消耗成本 |

在期间和归集范围一致的前提下，病例财务结余按“归属病例的确认收入减去同口径成本”计算。支付标准与收费金额之间的差额可以作为支付费用差异观察，但不能直接命名为真实利润。仅有药耗成本时，可以明确计算相应贡献差额，不能宣称已覆盖全成本盈亏。

## 三、跨数据集的治理与统计条件

### 3.1 一致关联、版本与时间

病例、费用、分组、支付和成本在同一住院标识下关联；ClinMesh 还需保留 Workspace、Epoch、Scenario Run 等隔离边界。分析使用的是生成时的固定快照，并能回溯原始事实和规则。修订、退款或结算调整后，明确标记尚未重算的结果，防止新旧数据拼接。

在院预分组、出院审核分组和医保结算反馈分别呈现。报表明确采用入院、出院、结算还是财务期间筛选，以及转科病例如何归属科室；同一病例跨科室分摊时，汇总不得重复计数。虚拟住院日按受控业务时间线计算，不以真实等待天数替代。

### 3.2 可比较的样本与指标口径

单病例可以验证分组、费用和质控；运营趋势需要覆盖目标病组、复杂程度和时间范围的一批病例。样本规模依目标指标和用途确定，不设一个适用于所有场景的固定数量。合成病例的分布和费用差异只能解释设定场景，不代表真实医院效率。

| 指标 | 必须声明的计算条件 |
| --- | --- |
| 病例量、病组构成 | 纳入及排除条件、统计时间、病例去重和科室归属 |
| 分组覆盖率 | 成功分组数与明确纳入范围的病例数；无法分组、缺数据和不支持原因单列 |
| CMI | 同一可比较规则及权重口径下，纳入病例权重的平均值；缺权重不能填零，展示实际覆盖样本 |
| 次均费用、药耗占比 | 有效冲正后的费用、相同类别映射、分母范围及费用完整性 |
| 平均住院日 | 同日入出院等边界的计算规则、纳入病例与时间范围 |
| 同组比较 | 分组及权重版本、支付环境、病例结构和基准样本的可比性 |
| 支付或盈亏指标 | 预测或实际状态、收入及成本口径、期间和结算调整的处理方式 |

医保分组、权重或费用分类变更后，需要使用可核验的可比口径重算历史，或明确分开展示。不能直接混合不同年度和规则的指标来解释绩效变化。

### 3.3 责任与整改

医生拥有临床诊断和实际诊疗事实；病案岗位审核编码；医保岗位核对支付规则与结算；财务和成本岗位确认收入、成本及分摊；运营岗位消费分析结果。分析发现问题后，应定位到事实 owner，由有权限的岗位修订、复核和重算，分析页面不直接改写临床事实或账务历史。

规则分组与费用提醒需要保持临床和财务边界。不能为提高组别新增无证据诊断，不能因超过模拟支付标准自动减少必要治疗或阻止临床出院。相关官方要求及使用限制见[官方规则研究](2026-10-15-drg-official-evidence.md#版本地方落地与支付边界)。

## 四、ClinMesh 的依赖与建设顺序

当前[系统范围](../architecture/system.md)交付以普通门诊闭环为主，[住院闭环](../architecture/clinical-workflows.md#82-住院闭环后续)仍标为后续。单病例的可复用能力和代码缺口由[2026-10-15 的固定基线研究](2026-10-15-coronary-drg-quality-control-plan.md#当前项目的可复用能力与缺口)记录，不能把该静态研究当作后续版本的实现证明。

建议按可验证的分析层次逐步建设：

| 阶段 | 建设内容 | 进入下一阶段前需要取得的证据 |
| --- | --- | --- |
| 1. 固定分析边界 | 选择病种路径、地区或国家版模拟、规则及编码版本，冻结合成病例底稿 | 资料来源与适用范围明确；已知缺口和不支持情形可列出 |
| 2. 建立病例事实与费用 | 支持选定病例所需的住院、诊断、实际操作、用药耗材、逐项费用与出院数据 | 同一次住院可贯通；来源、数量、时间与费用可核对；退记和重复执行边界有效 |
| 3. 病案质控与预分组 | 生成首页及清单草稿、检查矛盾、整改复核，并在声明范围内分组 | 基准样例结果可复算；缺信息、不支持、输入修订和结果过期均正确呈现 |
| 4. 基础运营分析 | 建立一批冻结合成样本，分析病例构成、费用、住院日与药耗结构 | 汇总能下钻到病例和原始来源；分母、未覆盖样本、版本和科室归属一致 |
| 5. 模拟支付分析 | 取得适用地方材料，或建立明确标记的合成支付参数与反馈 | 预测、结算和调整分开；参数及结果的模拟状态可见 |
| 6. 模拟成本与盈亏 | 建立合成成本及收入模型，验证归集、分摊和调整 | 同口径结果可复算，无重复收入和成本；对外不宣称真实医院盈亏 |

如果仅验证离线分析，可以先用满足阶段 2 数据条件的冻结合成快照，再逐步接入业务来源。首期不必建设完整手术室调度、硬件采集、全院供应链、真实医保上传或真实支付；所选路径所需的实际操作、耗材、费用和病案事实仍需完整。单病例临床路径及验收细节沿用[既有候选方案](2026-10-15-coronary-drg-quality-control-plan.md)，不在本文另建一套实施规格。

## 五、启动前需要明确的事项

| 待明确事项 | 对实施的影响 |
| --- | --- |
| 首期分析目标及病种范围 | 决定仅做结构和费用分析，还是进一步建设支付与成本模型 |
| 目标地区、年度及规则版本 | 决定编码、分组、支付参数和历史可比性；未明确时只能选择有界模拟 |
| 输入来自业务闭环还是冻结合成快照 | 决定在院刷新、来源导航和整改能力的依赖 |
| 可用的地方规则、预期分组与基准样例 | 决定哪些分组和支付结果能够被验证 |
| 收入、成本和科室归属口径 | 决定是否具备盈亏分析条件，以及跨科室如何汇总 |

尚未取得的地方支付、完整编码映射及分组金标准资料，详见[既有研究的限制](2026-10-15-drg-official-evidence.md#未取得资料与限制)。本文没有新增业务接口、分组器、统计看板、正式规格或实施授权，也不据此给出新的开发工期承诺。

3. [系统范围](../architecture/system.md)、[临床业务流程](../architecture/clinical-workflows.md)与[领域词汇](../../CONTEXT.md)：拥有当前产品边界、共享业务流程及核心概念。本文的阶段、指标和职责安排是待确认的规划建议，不替代这些 owner。
