# 独立 Web 工作台 UI 评审观察

## 评审范围与结论

本文记录 2026-10-19 对独立 Web（`127.0.0.1:51888`，本地持久化演示数据）六岗位工作台、组件目录、设置页与窄屏视口的实机评审观察。评审只读操作，未产生业务写入；证据来自真实入口截图与 DOM 计算样式探测，截图为临时产物未入库。本文是评审证据，不是行为变更授权；采纳任何改进前仍按[需求规格](../spec/README.md)确认。当前 UI 合同见 [ClinMesh UI 设计合同](../ui/design.md)。

总体判断：整体界面符合"安静、高密度、可快速扫读"的设计合同——语义色克制、无常驻阴影、空态统一、动作就近、窄屏切换正确。主要问题集中在三类：一类是真实缺陷（深色主题不生效、枚举与内部数据直接暴露），一类是目录默认状态对临床工作流无价值，一类是密度合同在横幅、聊天区和表格上未落实。

## 缺陷类发现

### 1. 独立 Web 深色主题不生效

设置页与登录页提供"深色"选项，选择后应用保持浅色。DOM 探测（`theme: dark` 写入 `clinmesh.preferences:v1` 后登录）显示：`<html>` 获得 `.dark` 类且 `--background` 解析为深色 `oklch(0.1757 …)`、`body` 背景为深色，但应用壳层的 `aside`、`header`、`main` 计算背景均为 `rgb(255,255,255)`，整屏视觉与浅色完全一致。

机制：`.dark` 由 [index.html](../../apps/web/index.html) 启动脚本与 [preferences.ts](../../apps/web/src/app/preferences.ts) 挂在 `<html>`；浅色 token 在 [styles.css](../../packages/ui/src/styles.css) 第 144 行起的 `[data-clinmesh-app="web"]` 块对应用根 `div`（[web-app.tsx](../../apps/web/src/app/web-app.tsx) 第 477 行，携带该属性但不携带 `.dark`）重新声明；深色覆盖 `[data-clinmesh-app="web"].dark`（第 216 行起）要求同一元素同时具备两个条件，实际只有 `<html>` 满足。应用子树继承根 `div` 的浅色值，深色 token 永不作用于界面。

修复方向（任选其一，需同时验证 DSH Surface 作用域不受影响）：把 `.dark`/`data-theme` 同步切换到应用根 `div`；或将深色覆盖改为后代组合选择器（如 `:root.dark [data-clinmesh-app="web"]`）。修复后需按设计合同验证暗色语义色映射与三档字号组合。

### 2. 内部系统数据直接暴露给临床用户

诊断目录每张候选卡片显示来源 URI `urn:clinmesh:reference:nhsa-diagnosis`，对医生无信息量且每项重复。管理员合成患者档案显示英文 `Revision 1`、`Active` 与完整模型路由 JSON `dsh:{"provider":"deepseek-official","model":"deepseek-flash","reasoningEffort":"high"}`。[UI 设计合同](../ui/design.md)已规定界面不显示草稿版本、FHIR 版本或乐观锁版本；同一原则应覆盖来源 URI 与模型路由。开放模型选择属于管理员设置域，患者档案页不需要承载。

### 3. 状态与性别枚举未映射

挂号记录表格中仅 `awaiting-triage` 映射为中文（[registrar-workspace.tsx](../../apps/web/src/app/registrar-workspace.tsx) 第 727 行），其余状态如 `first-visit` 直接渲染英文枚举，与同页中文 `待分诊` 徽章并列。管理员患者头显示英文 `male`，而医生队列同一字段为中文 `女 · 24 岁`。日期输入 placeholder 为美式 `mm/dd/yyyy`。医生端已有 [doctor-case-status.ts](../../apps/web/src/app/doctor/doctor-case-status.ts) 的状态文案映射，挂号工作台未复用同层级的映射。

## 体验类发现

### 4. 目录默认状态对临床工作流无价值

诊断与药品目录在未输入搜索词时按编码序平铺候选（诊断如"(足母)囊炎、趾瘢痕、11-羟化酶缺乏"，药品如脂肪乳注射液排在前列）。医生的实际工作流是"按目标搜索"；默认长列表既无决策价值，也让人误以为可以滚动浏览全目录。建议默认态改为常用或本科室最近开具的短列表加搜索引导，或直接空态加搜索提示。

### 5. 药品包装选择文案噪声

包装徽章直接输出完整工艺描述，如"本品采用五层共挤输液用三室袋、胶囊剂、氧指示剂和高阻隔外包装袋。；1袋/袋"，选择所需的最小事实（规格、单位、包装量）被淹没。建议包装选择主行只保留规格与包装量，工艺细节进入次要行或悬停提示。

### 6. 患者横幅占首屏比例偏高

横幅由身份行、完诊清单七枚徽章与生命体征行组成，1440px 视口约占首屏 35–40%；390px 窄屏下徽章折行占近三分之一视口，且 `5/7` 计数与"完诊清单"标题的空间关系断裂。清单已有完诊 Dialog 承载完整视图，横幅可只保留未完成项徽章或未完成计数加最紧迫一两项，压缩后把垂直空间还给业务页签。

### 7. 问诊记录聊天区密度偏低

消息名字、时间戳、气泡各自独立成行且间距较大，一屏仅容纳两到三轮对话；医生回看患者长主诉时滚动成本高。建议将姓名与时间合并为单行 11px 辅助行，气泡间距减半；患者消息就近展示"已整理进病历"状态，替代独立时间行。

### 8. 表格与列表密度未达合同

挂号记录表行高偏大、门诊号列占比失衡；设计合同正文 13px 与行内动作就近的约定在表格中尚未体现。候诊侧栏患者卡中"不舒服/身体不适/不适"主诉普遍重复占行，可压缩为次行 muted 文本或悬停展示。

## 讨论类观察

岗位工作台共享"左列表 + 右表单"骨架，符合合同且学习成本低，但六个岗位视觉无标识差异，可在合同允许的克制范围内给页头或侧栏项一个岗位语义标识（如图标着色），帮助快速确认当前岗位。患者头像为卡通插画风格，与安静的临床界面气质存在张力，姓氏首字圆标更贴近国内 HIS 惯例；若插画为演示体验的有意设计，可保留但统一风格。

## 积极面

语义色克制（绿/琥珀仅用于状态）、无常驻阴影、空态统一且带引导文案、动作就近（选择诊断、开具等按钮贴近对象）、窄屏正确回落为"候诊患者/病例详情"切换、设置页三档字号与主题入口齐备。评审发现的缺陷集中在接线与文案层，不涉及设计合同方向调整。
