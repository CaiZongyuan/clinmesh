# 冠心病单病例 DRG 质控功能方案

核验日期：2026-10-15。代码基线：`8e8b93953eca382b13ad424d1895fb7fc52501f9`。本文是调研与候选方案，不是已批准规格，也不表示功能已经实现。官方规则及可得性见[官方依据](2026-10-15-drg-official-evidence.md)；当前产品行为以[系统架构](../architecture.md)、[领域词汇](../../CONTEXT.md)和下列源码为准。

已确认的目标是“出院前病案与费用质控，住院中预警”，范围限一个冠心病合成病例。建议以一条冠脉造影后择期 PCI 路径覆盖住院、介入、支架耗材、费用和编码；具体诊疗路径尚待选择，不能从“冠心病”推定心肌梗死、PCI 指征或已经植入支架。

## 结论与完整业务链

当前需要补齐五组能力：住院与诊疗记录、冠脉介入与耗材、逐项计费、病案首页与结算清单及预分组、质控与整改。计费已有门诊基础；住院、手术和 DRG 主要仍是待实现能力。只增加三个菜单，或把既往手术、处方汇总金额交给模型，不能形成可核验的 DRG 质控。

建议的一条可验收链为：

```text
固定冠心病合成病例及规则版本
  → 收治入院、入科占床、建立住院账户
  → 入院记录、住院医嘱、检查结果、执行记录
  → 冠脉造影、实际 PCI、支架与耗材使用
  → 汇集逐项费用、退记与冲正
  → 出院诊断、出院小结、病案首页及结算清单草稿
  → 病案、编码、操作、耗材与费用交叉质控
  → 定位整改、人工复核、重新预分组
  → 冻结通过审核的清单及质控快照
```

住院期间按在院阶段运行适用预检查；正式诊断、医嘱执行、手术耗材或费用发生变化后，自动刷新受影响预警，尚未到期的出院日期等字段不报缺陷。出院前对待确认的完整清单强制复核。临床出院、费用冻结或模拟结算、清床和病案归档保留独立状态。病案或费用质控缺陷优先阻断相应清单确认、费用冻结或归档，不因纯行政缺项一概阻断患者临床出院。

## 五组需要实现的功能

### 1. 住院与诊疗记录

- 一所合成医院、一个心内科病区、一张床的入院登记、入科占床、在院及出院流程；床位占用互斥，住院关联原门诊或急诊来源，保留两个 Encounter 的边界。
- 住院号、入院和出院日期、科室、入院途径、出院方式等最小字段；床位占用、临床出院、财务状态和归档分别记录。
- 本病例必要的临时/长期医嘱、核对、执行、停止和作废；药物实际给药或发退药事实与开立意图分开，数量和时间可追溯。
- 入院记录、必要病程及围术期记录、手术记录、出院小结的草稿、签署和修订。复用既有文书机制，增加真正适用的住院类型与字段。
- 固定病例需要的心电图、超声心动图、实验室检查和冠脉造影报告结构；按所选病例保留支持或排除诊断的关键结果。现有胸片/胸部 CT 能力不能替代这些检查；先支持可追溯的合成结构化结果，不要求引入心电设备或冠脉影像素材。
- 一条统一的住院业务时间线，允许病例跨天推进，并校验执行、手术、出院的先后顺序。业务日期与审计接收时间分开，不能依赖真实等待天数或只修改前端日期。

### 2. 冠脉介入与耗材

- 本院冠脉造影及 PCI 项目、申请、指征、实施、取消和结果；造影与支架植入分别记录，取消或未实施不能产生已完成手术事实。
- 操作名称、标准编码及版本、主要操作与其他操作、实际开始/结束时间、术者、必要麻醉方式、目标血管和病变、植入支架类型及数量、结局与并发症记录。
- 本次实际使用的支架、球囊等必要耗材明细，与具体操作、使用数量、收费项、价格版本关联；区分植入、使用、未使用退回及报损。支架植入数不能机械等同全部领用数或全部耗材收费数。
- 手术记录、结构化操作记录和首页操作编码的一致性检查；本次实际执行用 Procedure 表达，目录、申请和历史来源不冒充 Procedure。

首期不需要完整手术排程、手术室调度、麻醉机、体外循环、ICU 或全院耗材供应链。CABG 属于另一条临床路径；只有选定该病例时才替换为相应手术与耗材事实，不和首例 PCI 一起铺开。

### 3. 逐项计费与住院费用账

- 为本病例实际用到的检查、操作、药品、支架耗材、床位和护理服务建立有版本的本院价格；全部为明确标记的合成价格，或合法取得且固定地区、机构级别和生效日的参考价格。
- 医疗服务项目、手术操作码、耗材产品码、收费项和医保费用类别分别建关联，不把它们当同一套编码。
- 每条费用保存住院账户、原始医嘱/执行/发退药/耗材引用、项目、数量、计价单位、单价、金额、发生时间、执行科室及费用类别。金额继续用整数分计算。
- 为每类项目固定计费触发点、数量来源、取消与退费规则；例如介入与耗材以实际实施/使用事实触发，床护费按明确的计费日规则累计，药费按确定的发退药规则处理。报告更正不应重复产生原检查费用。
- 支持重复执行防重、未执行取消、退记/冲正、费用类别汇总、明细追溯和清单总额核对；原记录与反向记录保留，不能改历史单价或删账制造一致。
- 出院费用预览、冻结及修订后重新确认。旧预览、旧质控结果不能覆盖后续新增费用；不明价格、数量冲突或漏关联必须暴露。

DRG 质控首期可止于费用账、清单和模拟预分组；真实收款、医保上传、基金分配、财政电子票据不是完成这一目标的前置条件。收费总额、医院成本、DRG 支付标准和患者自付是不同金额；没有真实成本口径和地方支付政策时，不显示“真实盈亏”。

### 4. 病案首页、医保结算清单与预分组

- 保留临床诊断确认，增加出院诊断排序、入院病情、编码审核、证据引用和修订记录；编码人员提出编码问题，临床诊断由有权医生确认。入院病情保留中国清单规范中的“有、临床未确定、情况不明、无”四类语义，不压缩成美国 POA 布尔值。
- 固定当前病例、目标版本真正需要的首页及结算清单字段，至少覆盖患者基本特征、住院及离院信息、主次诊断、操作及日期、入院病情、费用类别汇总。病案首页与结算清单是不同输出，详细字段各有 owner；共同字段来自同一正式事实。
- 固定诊断编码、手术操作编码、分组规则包、适用地区、适用日期与版本；本院现有临床版 ICD-10 目录需核对医保版本兼容性，不能靠病名相似或裸 code 自动对码。
- 保存分组输入快照、输入版本/哈希、分组器版本、输出、命中依据和缺失字段。任何诊断、操作、费用或清单修订都应使受影响的旧结果过期，重新运行后保留前后记录。
- 区分“数据不足不能判断”“不在已实现范围”“国家版模拟预分组”“已匹配指定地方规则的预分组”；不能把全部冠心病硬编码成一个组，也不能用大模型自由生成组码、CC/MCC 或权重。

截至核验日，国家已发布 3.0 方案，地方仍有切换安排；官方还提供可下载的国家分组规则配置。具体日期、下载来源和使用边界见[官方依据](2026-10-15-drg-official-evidence.md)。首期应选择一个明确版本，覆盖该版本中本病例实际命中的完整判断链，并验证相关排除、优先级和边界；只下载一张分组名称表不等于获得可正确执行的分组器。官方 3.0 更新版配置中，抽查的冠状动脉支架置入 DRG 行没有 CC/MCC 细分条件；因此其他诊断需要如实记录，但不能承诺补充共病就会提高该病例的组别或支付。目标地方权重、费率、结算办法未取得时，可以交付清单质控及明确标记的国家版预分组，不能声称算出实际医保支付。

### 5. 质控结果、定位整改与复核

质控输出至少包括规则标识和版本、严重程度、触发事实及版本、证据入口、原因、需要谁处理、当前处理状态和复核记录。明确的结构及账务规则可作为对应业务门禁；诊断合理性和语义矛盾由模型辅助提示，必须附证据并交人工核实。信息缺失保持“待核实”，不能自动补成“无”或新增并发症以获得更高分组。

| 质控项 | 单病例可构造的缺陷 | 建议处理 |
| --- | --- | --- |
| 输入完整性 | 缺出院日期、离院方式、主诊断或必需操作码 | 阻断相关清单确认/正式预分组，定位到 owner |
| 主诊断与临床证据 | 仅有冠心病记录，却提交急性心肌梗死编码 | 提示临床与编码复核；不能仅凭单个检查结果自动改诊断 |
| 其他诊断与入院病情 | 病史中的疾病未证实影响本次住院，或入院前后状态不清 | 提示核实证据和入院病情，按选定规则判断 CC/MCC；不把所有高血压/糖尿病自动计入 |
| 手术漏记或错记 | 手术记录有 PCI，首页缺操作；只有造影却记录支架植入 | 明确事实矛盾阻断相应清单确认，回到操作/编码页修正 |
| 支架与耗材 | 植入记录一枚，但收费两枚且没有额外使用、报损或退回依据 | 按适用收费规则核对使用去向、数量及账务，不机械一比一 |
| 诊疗与费用 | 已执行项目缺费用或明确免收原因；取消项目仍有未冲正费用 | 定位原始执行及费用，补记或冲正，保留历史 |
| 重复计费 | 同一执行回执重试导致两条有效费用 | 由幂等和唯一来源约束防止；历史缺陷触发账务复核 |
| 费用守恒 | 明细金额、类别汇总、清单总额不一致 | 阻断费用冻结/清单确认；不能靠改汇总金额掩盖明细 |
| 时间一致性 | 手术日期在出院后、住院天数或床位费与时间线冲突 | 核对日期及计费口径，阻断相应无效输入 |
| 版本与结果过期 | 质控通过后又新增支架费用、修订诊断，仍沿用旧结果 | 标记结果过期，重新质控和预分组 |
| 规则与支付口径 | 缺地方版本却显示确定组码、支付金额或盈亏 | 拒绝给出超出依据范围的确定结果，并展示所缺资料 |

建议在同一病例工作台提供“住院概览、医嘱执行、介入耗材、费用、出院病案/DRG”入口，质控摘要可从住院期间打开，详细问题按需展开；不是新增全院经营看板。问题可导航到原始诊断、文书、操作或费用记录，经历待处理、已整改待复核、复核通过或人工说明，不能点“忽略”就让真实账务矛盾变成通过。

DSH Agent 和 CLI 复用同一 Query/Command：读取质控、定位证据、准备修正草稿、请求复核。DSH proposal 继续由相应人类岗位审阅并提交正式动作；CLI 任务 Agent 仅能在其单岗位 Grant allowlist 和各操作既定授权边界内提交 Command，不增加新的通用自动写入权限。需要同步 Operation Catalog、运行时 skill 与示例漂移测试，不另造 Agent 专用状态机。

## 建设顺序与每阶段验收

| 顺序 | 可独立观察的交付 | 验收证据 |
| --- | --- | --- |
| 1 | 固定一个合成病例、诊疗路径、必要目录及规则版本，跑通入院到出院；先可录入可追溯的操作和结构化检查结果 | 实际住院 Encounter、床位占用、跨日时间线、入院/出院记录；原门诊闭环可继续使用 |
| 2 | 该病例冠脉造影/PCI 与耗材执行、逐项费用归集、取消和冲正 | 原始执行到费用可双向追溯，重试不重复记费，未计价不被当免费，冻结后修改受控 |
| 3 | 从正式事实生成出院首页/结算清单草稿，具备基础交叉质控与整改复核 | 发现漏手术、错数量、重复费用、总额不一致；可定位修复并重新审核 |
| 4 | 按选定国家或地方版本完成限定范围预分组，展示命中依据和前后版本变化 | 完整基准样例有可核验结果；缺信息、规则不支持或结果过期时不会报确定结论 |

阶段一已应保留质控所需的结构化来源，阶段三开始交付完整质控体验。不要等建设全院住院、手术和财务系统后才验证首例；也不要先用假费用和手填组码做出“质控通过”界面。地方规则未确定时，阶段一至三仍可推进，阶段四的输出边界必须明确。

## 测试与最终验收建议

采用一个冻结的正确病例，构造少量明确缺陷修订，而非另建多病种病例库。隐藏验收底稿用于测试，业务质控仍只看正式可见事实。

1. **正确闭环**：住院、检查、实际操作、耗材、费用、首页/清单互相一致；在支持的版本和路径中产生可复算预分组，或明确显示尚无分组依据。
2. **可检出的缺陷**：分别移除必要操作码、制造耗材数量冲突、重复记费、缺价格、清单金额不一致，断言命中正确规则、证据位置及相应门禁。
3. **失败及边界**：取消未实施 PCI、执行重试、退记、同日/跨日住院、入院病情未知、无依据并发症、越权修订、旧版本并发提交与旧预览失效；正常在院不报缺出院日期，正式事实变化形成矛盾后自动出现适用预警。
4. **修复与重算**：修复 owner 记录后复核通过；诊断、操作、费用变化使旧质控/分组过期；原始事实、反向记录及前次分组可追溯。
5. **真实入口**：通过 standalone Web 或 DSH 的同一病例完成住院到出院前质控；新命令同时验证 CLI/Agent 权限、幂等、版本和审计，覆盖相关 React 18/19 合同。这里列的是实施后的验收要求，本轮未运行这些业务测试。

## 本轮边界与待定项

本轮交付研究和候选方案，没有修改业务代码、数据库状态、正式规格、Issue 或 PR。源码证据为静态核对，测试文件存在不代表本轮已运行通过；本地 SQLite 仅以只读方式核对合成病例的数据形状和当前路径，不保存患者身份、完整真值或影像素材。

实施前需要固定首例临床路径及冻结底稿，并选择国家版模拟还是指定统筹区的版本；如果暂不指定地方，建议先做明确标记的国家版规则与清单质控。是否展示实际支付预测取决于合法取得且可核验的地方支付资料，是否展示盈亏还取决于独立成本口径。
