# LLM-Wiki 主题知识层用于住院指南的评估

核验日期：2026-11-02。本文评估用户提供的《LLM-Wiki》文章所述持久主题知识层，是否适合当前住院指南接入问题。它是候选方案研究，不是新的临床指南、正式需求或实施授权。现有指南内容及实际检索证据由[住院指南适用性研究](2026-11-02-inpatient-guideline-applicability.md)拥有，本文只记录文章方法的增量价值及限制。

## 来源与证据范围

文章原链接为[飞书《LLM-Wiki》](https://scnwctaxwdzt.feishu.cn/wiki/AqKHwQpSJiBSWJkaEsycSrrnnRe)。网页访问转入登录页，本轮改为读取用户提供的 Markdown 导出正文，文件 SHA-256 为 `622c313487d9992b56811ced34e34a8312583b8b4485b25dd41fb7d86c40be2e`。本机原始资料保存在 WSL 项目的 `.data/research/LLM-Wiki/`，包含 `LLM-Wiki.md` 与全部图片附件；原始压缩包为 `.data/research/LLM-Wiki .zip`，均不进入 Git。完整阅读正文，附图未逐张核验；正文描述的配套 raw、page-specs、编译器和可见轨迹原件不在此次提供的目录中，未独立运行课程实验。

对 Karpathy idea file、研究论文、GraphRAG 和 FF-LLM Wiki 能力的介绍属于文章转述，本轮没有独立核验这些外部主张，也不以课程中的 DSH 版本声明推断 ClinMesh 当前宿主能力。适配判断主要依赖文章自身定义、形成过程及维护边界，以及已经实查的项目检索行为。

## 文章提出的方法

文章 §1.2 将 LLM-Wiki 定义为：从保留版本的原始资料形成可持久读取、互链、回溯和维护的主题知识。§2.5 强调主题页围绕一个问题综合多个来源，而不是每份原文生成一篇摘要。`sources` 记录结论依据，`links` 提供后续阅读路径，二者不能互相替代。

§2.6 明确说明，示例的八页内容先在公开规格中确定，再由确定性脚本落盘；该演示不能证明模型已经能自动、正确地编译医学知识。§3.3 和 §4.3 通过可见读取轨迹说明查询实际访问哪些页面及来源；一次正确回答不是通用准确率证明。§4.1–4.4 用新增一份来源、更新三页并保留其他页面的受控例子展示增量维护，没有证明长期自动更新或自动解决冲突。

## 对 ClinMesh 的适用判断

这种方法适合在现有指南原文库上增加按住院问题组织的证据导航和主题解释。它有机会减少每次从整份指南重组相同主题的工作，也为当前泛搜遗漏关键条款提供一个可评估的补充入口。它与现有检索可以组合，不能仅凭新增主题页推断检索、临床正确性、时延或用量已经改善。

| 已确认的问题 | 主题知识层可能提供的帮助 | 仍需保留或补齐的能力 |
| --- | --- | --- |
| 泛搜前八段没有覆盖人工已定位的关键页 | 预先把相关主题与关键来源段落关联，查询先定位主题，再打开对应原文 | 用固定问题比较来源召回、限定条件完整性及最终回答；主题本身也可能定位错误 |
| 同一患者问题涉及多篇指南 | 在同一专题中列出各来源的适用人群、条件、例外、版本差异和缺项 | 不把不同人群、推荐等级或年份的意见合并成无条件结论 |
| 新来源影响既有建议 | 通过来源与主题的关系定位需要复核的内容 | 原来源撤回、不可用或损坏时，所有派生主题和下游建议同步失效 |
| 住院预计被固定合成参数及 exact quantity 限制 | 帮助解释哪些是真正指南条件、哪些只是合成演示范围 | 产品行为仍由 owning 规格及业务代码决定，主题页不能自行放宽或增加门禁 |
| 缺具体产品、规格、数量或兼容依据 | 明确列出知识覆盖边界和待补资料 | 患者测量、本次计划、产品说明书、目录版本和组合兼容证据不能由主题归纳补造 |

## 最小候选范围

先围绕两类已知问题评估主题层即可：一类是“PCI 支架类别与尺寸核对”，关联血运重建指南、IVUS 共识及相关 PCI 原文；另一类是“对比剂与肾功能风险”，关联对比剂共识及其心功能、过敏等限制。双抗和出院可以沿相同原则扩展，但不必为证明模式一次编译整个语料库。

以“PCI 支架类别与尺寸核对”为例，主题应分别写明：在何种情境讨论某类支架；需要哪些可追溯测量；哪些结论还不能确定；对应原件的具体来源、版本、哈希和物理页；下一步可阅读的相关主题。项目自己的操作性归纳必须单独标识，不能写成指南原句，也不能从正文中的“可以考虑”生成系统的强制前置条件。

现有 SQLite 指南原文继续作为来源 owner，不把它复制成另一套可任意编辑的原件。派生主题可以重建，其事实依据应能落到现有 `sourceHash`、原文定位和具体结论。文章示例的整篇来源路径粒度，对医疗应用通常还不够，需要核对具体条款及上下文；内部链接只负责扩展，不能作为临床依据。

主题保存可复用的通用医学内容，不保存某次住院的诊断、测量、费用或临床决定。运行时先按当前岗位装配有权读取的本次住院事实，再结合可用主题回查指南原文，形成建议和缺项说明。院内材料、计价和 DRG 继续使用各自 owner 的最新版本，不从主题页复制一套动态目录或支付答案。

## 需要验证的关键合同

1. 结论回溯：每条医学结论有真实原文支持，能读到其人群、条件、例外和版本；不能只检查链接存在。
2. 不完整资料：主题可以帮助明确“能判断什么、还缺什么”，不能为了得到完整清单而猜测患者事实或把缺项都升级成治疗门禁。
3. 来源变化：来源撤回、权限或用途不允许、正文不完整、版本替代时，派生主题不能绕过原检索策略继续提供旧结论。
4. 独立对照：使用上一轮已人工定位的条款与实际查询作为基线，分别检查主题定位、原文召回、引用和条件完整性；加入无依据问题、CCS/ACS 混淆、过期来源及超出具体器械依据的反例。
5. 更新范围：新证据只影响有关主题和建议；保留原版本及依据关系，不以自动重写全部页面代表维护成功。

上述内容是进入产品前的评估条件。下面的人工专题实验只验证证据读取与边界，不等于完成主题自动编译、模型问答或临床质量验收。当前所需能力并不要求先引入图数据库、Embedding、新知识平台或一套独立 Wiki UI。

## 两专题的实际取证对照

本轮在用户确认的范围内整理[PCI 支架类别与尺寸核对](topics/pci-stent.md)和[对比剂与肾功能风险](topics/contrast-kidney.md)两个实验专题。专题由人工明确选择，不测试自然语言意图识别；引用在原文核对后人工整理，不测试 LLM 自动编译。问题和六处预期证据在专题形成前冻结；其中前三条直接沿用上一轮实际查询，第四条专门检查零对比剂策略的限定条件。它们是已知问题的针对性样本，不是盲测或临床准确率样本。

### 相同输入与证据策略

[可复现脚本](../../apps/server/research/guideline-topic-evaluation.ts)先调用实际 `GuidelineCorpus.search`，再按人工选定专题回读同一库的来源与完整原文页。两组都采用 `default + allowLocalEvaluation=true`，来源身份、版本、原件哈希、完整性、用途和正文质量条件一致。实验前后检查来源快照未变化；只读指南库，不访问患者业务库，不修改原文或产品接口。

每组上下文都限制为最多八段、48 KiB，专题 Markdown 本身占一段并计入字节。字节按相同原文字段与专题字段的 JSON UTF-8 序列化计算，不是服务商实际 Token 或计费量。证据命中同时核对原件哈希、2021 版本、物理页及预先指定的关键文字；不会把同文献的目录或参考文献页计为核心条款命中。

### 结果

| 问题 | 现有检索：关键证据 | 专题辅助：关键证据 | 现有／专题上下文段数 | 现有／专题字节 |
| --- | --- | --- | --- | --- |
| Q1：`PCI stent type drug-eluting DES BMS` | 0/1 | 1/1 | 8／4 | 46018／21396 |
| Q2：`IVUS reference segment lesion length lumen diameter stent sizing` | 0/2 | 2/2 | 7／4 | 46900／21396 |
| Q3：`PCI 含碘对比剂 肾功能 eGFR 水化` | 1/2 | 2/2 | 8／4 | 47166／21226 |
| Q4：`PCI 零对比剂 超低剂量 肾功能不全 IVUS` | 1/1 | 1/1 | 8／4 | 47028／21226 |

这四个固定问题的六处可用关键证据，现有检索命中两处，人工专题辅助取得六处。Q2 的来源中保留了 IVUS 的适用表述、OCT 的左主干开口例外及测长方法条件；Q4 保留了术前影像、IVUS、适应证与术者经验限制。这里的“保留”只表示原文条件进入了实验上下文，不证明模型将正确使用它们。每个专题辅助上下文为一份专题和三处完整原文，没有截断原文以制造字节改善。

对比剂物理第 4 页是一个独立缺口：固定包正文含不可解释控制字符，当前可用本地别名未纳入该页。专题保留待核对引用，但没有拎出该页的干净半段使用。它不计入六处可用证据的分母；对比剂专题的结果继续标为 `incomplete`，不能据此声称已经具备完整水化依据。已找到其他风险或零对比剂条款，不会自动补齐这个缺口。

### 边界检查

| 边界 | 实际检查的内容 | 能证明的范围 |
| --- | --- | --- |
| Q5：要求具体品牌、型号、规格和四类各一件 | 专题明确声明不支持具体产品选定和材料数量 | 证明机器可读边界存在，不是模型已正确理解任意临床问题 |
| Q6：择期 PCI／CCS 双抗疗程问题 | 人工指定的双抗主题不在这两个专题中，返回 `out-of-scope` 且不提供专题上下文 | 证明专题范围未被扩充；未测试自动识别 CCS／ACS 或最终用药回答 |
| Q7：要求固定水化速度 | 核对第 4 页质量隔离，最终上下文排除该页并保留缺口与固定速度能力限制 | 证明没有经人工摘要绕过不可用原文，不证明个体化补液决策正确 |
| Q8：核心来源不可用 | 两组同用 `default + allowLocalEvaluation=false`；核实基线核心来源不可用，专题文字和原文也全部停用 | 证明所选用途策略下派生内容未绕过原来源限制，不等于医学上没有指南支持 |

### 运行与复现

在 Linux／WSL 项目根目录运行：

```sh
node node_modules/tsx/dist/cli.mjs apps/server/research/guideline-topic-evaluation.ts
```

结果写入本地 `.data/research/inpatient-guideline-topic-evaluation.json`，只包含问题、覆盖、版本指纹、字节及边界状态，不复制指南全文。脚本使用已安装指南库及两个专题，不新增依赖、模型账本或通用检索服务。

基线模式保留了专题形成前的失败条件，便于独立复现漏召回：

```sh
node node_modules/tsx/dist/cli.mjs apps/server/research/guideline-topic-evaluation.ts --baseline-only
```

它不读取专题文件，在未找全预设证据时以非零状态退出；专题文件缺失时的回归检查也确认它仍能完成原检索并报告漏召回。首次基线运行约 3.89 秒，正常对照约 3.87 秒，包含 Node 启动、来源核验、全部查询和边界检查，不是单次检索性能指标。实验没有运行真实模型，也没有产生 Token／金额节省或最终回答准确率的证据。

## 当前结论

两个手工专题已在这组固定问题中改善关键原文的取得，并保留了正文质量和来源用途限制；它们适合作为进一步验证住院证据导航的候选。当前产品尚未接入专题，业务门禁没有改变。自动专题选择、模型编译、最终回答质量、未见问题泛化及临床效果仍未验证；具体产品依据与水化正文缺口也没有被补齐。
