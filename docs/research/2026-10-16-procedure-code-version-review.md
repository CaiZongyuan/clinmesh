# DRG 3.0 手术操作编码版本复核

核验日期：2026-10-16。范围是国家 DRG 3.0 更新附件引用、但本批 ICD-9-CM3 医保 2.0 静态 PDF 没有收录的 80 个完整操作编码。本文记录公开来源、编码身份及版本边界；产品行为仍由[DRG 设计方案](../spec/2026-10-15-drg-prescription-budget.md)拥有，DRG 文件整体来源见[既有来源研究](2026-10-15-drg-data-sources.md#drg-30-规则来源与版本)。

## 结论

80 个完整编码均能在重新下载的国家医保局 DRG 3.0 更新 PDF 中定位，均不在本批 ICD-9-CM3 医保 2.0 静态 PDF 中。国家医保编码平台当前公开提供的 ICD-9-CM3 医保 2.0 PDF，与本批原 PDF 的 SHA-256 完全相同；平台历史列表将该数据库快照标为“2021年1月”。因此，当前差异不能归结为 MinerU 漏掉了这 80 行，也不能因 PDF 文件名仍为医保 2.0 就将它视为动态查询库的当前完整快照。[官方字典页](https://code.nhsa.gov.cn/search.html?sysflag=80) [历史快照索引第16页](https://code.nhsa.gov.cn/toMessageListNew.html?pageNow=16)

80 个编码中，53 个已在国家医保局公开动态查询详情中取得完整编码、原文名称和可见分类层级。其余 27 个的读取遇到 SSL 错误或 HTTP 405 安全阻断，没有取得可验收的详情快照；这些请求失败不能解释为动态字典缺码。53 条成功记录可形成单独的官方网页补充候选集，原医保 2.0 PDF 字典保持独立。[官方手术操作公开查询](https://code.nhsa.gov.cn/jbzd/public/dataOperationSearch.html)

公开动态查询详情没有提供这 53 条的独立发布批次、生效日期或 DRG 3.0 配套字典声明。实际读取全部 17 页公示公布索引和 17 页数据库快照索引后，未在这些索引中识别出明确对应这 80 码的较新 ICD-9-CM3 配套字典发布证据。这个检索范围不证明其他渠道没有发布材料；动态编码身份确认也不等于官方分组器版本适配验收。[公示公布索引](https://code.nhsa.gov.cn/toMessageList.html?flag=2&showClose=1) [数据库快照索引](https://code.nhsa.gov.cn/toMessageListNew.html) [DRG 实施通知](https://www.nhsa.gov.cn/art/2026/9/2/art_104_21975.html)

## 名称异常与启用边界

53 个官方动态条目中，52 个名称与 DRG 首次引用处字面一致；比对全部引用位置后，35 个编码的名称标签一致，17 个有来源字面差异，另 1 个有术式冲突。加上 27 个读取失败编码，80 个编码分别进入这四种复核状态；53 个编码身份确认不表示全部通过 DRG 名称审核。

`41.4200x005` 存在明确术式名称冲突。DRG 第 438 页等 7 个位置写“经皮脾病损微波消融术”，官方动态条目写“经皮脾病损射频消融术”。DRG 第 1264 页渲染原文写“经皮脾病损射频消触术”，同时包含术式差异和文字问题；不得自行选择“微波”或“射频”作为正确值。

比对所有 DRG 引用位置时，53 条中有 18 条出现至少一处名称字面变体，集中于 PDF 第 1217—1301 页的部分位置，例如 `01.5900x054` 第 1217 页实际显示“经皮脑病损激光消触术（映射）”。这些变体同时涉及来源排版或原文问题与 PDF 文字层映射问题，不能统一称为 MinerU 误识。第 1264 页文字层抽出“经皮胖病损射频消触术”，渲染字形却为“经皮脾病损射频消触术”；机器抽取值和视觉观察分别保存。

编码身份确认、原文名称复核和分组器适配分别验收。网页补充条目保留完整来源并置于候选层；`41.4200x005` 的名称冲突须待官方勘误或权威配套说明。其他字面变体不得覆盖原始记录；即使名称一致，也不能补造动态条目的生效日期、替代静态原件，或声明已经能用于正式结算。所有运行启用标记保持关闭。

成功详情中的 23 个编码位于返回 HTML 的折叠容器，已保存其节点属性及分类标题；这是网页展现属性，不能解释为停用、作废或当前有效状态。每个条目的实际有效状态仍为未知，不能只凭官方响应中含有代码就补填“当前启用”。

## 复验材料

本地证据根目录为 `.data/reference-preparation/review-r2/`。`procedure-code-review.json` 保存 `sources` 与 80 条 `records`，每项含完整编码、状态、历史字典精确存在性、动态字典精确存在性、DRG 引用页、全部名称变体、名称冲突标记，以及详情快照路径、SHA-256、读取时间、HTTP 方法和表单参数。未取得详情时，动态存在性为 `null`，不会将请求失败记为 `false`。

`official/` 保存官方 PDF、字典页、全部 34 页索引、成功的查询 JSON 与详情 HTML，以及一次 HTTP 405 安全阻断响应。三个渲染页证据单独保存并引用原 PDF 哈希。来源与快照均不进入 Git；它们用于离线复核，不形成运行时对未公开网页内部接口的依赖。后续形成参考数据发布包时，应保留静态字典与官方动态补充来源各自的版本和校验摘要。
