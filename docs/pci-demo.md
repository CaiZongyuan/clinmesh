# PCI 黄金病例从零岗位演示

本手册用于固定合成冠脉病例的一次完整住院：从管理员准备资料和患者档案开始，完成检查、用药、造影、单枚支架 PCI、患者待遇与资金、清床归档、医院侧模拟核定和归档后更正退款。需求及验收状态由[正式规格](spec/2026-10-27-pci-golden-demo-readiness.md)拥有；规则启用由[部署说明](../deployment/drg/README.md)拥有，测试证据边界见[测试策略](testing.md)。这里的诊疗与金额只用于合成仿真。

## 准备条件

维护者先按[部署指南](deployment.md)启动同一集成版本的普通 Web 和 Server，使用独立合成业务库、合成 Provider 与确定性资金模拟器。安装完整临床 Reference Release，并按[PCI 规则部署](../deployment/drg/README.md)启用被审核的完整 v2 包。目录安装属于环境准备；本次病例、入院、诊断、检查、用药、手术与收退款从下述页面产生。

首次演示使用空合成患者库和没有住院事实的当前 Epoch。记录集成提交、Workspace、Epoch、Scenario Run、规则身份和临床 Release；后续记录同一 Case、Profile／Persona 修订、患者及住院号。使用上海时区的固定虚拟时间 `2026-08-24 09:00`，本轮不跨午夜，也不展开长期医嘱，因此没有新增床日费。计划手术时间是计划字段，不会自行推进虚拟时间。

## 页面准备与入院

1. 管理员打开“模拟数据 → PCI 演示准备”，分别点击“准备 PCI 目录”和“准备固定 PCI 病例”。确认目录准备完成，并选中固定病例对应的合成患者。重复准备应返回已有资料，不新增病例、库存或费用。
2. 点击“手工创建患者档案”，填写首个 Persona：主诉“活动后胸闷三个月，加重一周，休息可缓解”；开场陈述“医生您好，最近一活动胸口就闷，休息后会好”；已知史“无已知药物过敏，静息无胸痛”；症状体验“步行数百米后胸口闷，停下休息几分钟会缓解，没有晕厥”；用药记忆“近期未自行加药”；性格“平和”、说话方式“简短清楚”、健康素养“普通”、就医态度“愿意配合检查”。点击“保存为新修订”，再“设为当前”，确认活动 Persona Revision 1。此步骤不使用“生成患者档案”等模型入口。
3. 登记员打开“住院登记”，在直接入院表单选择“患者来源：就绪合成病例”，选中同一病例和接收病区“住院病区”。核对 Case、Profile Revision 和 Persona Revision 后点击“办理住院”。此时是待入科，预交金和费用均为零，没有门诊挂号。
4. 护士打开该患者，选择目标“1床”，点击“接诊并分床”。确认住院病区、床位和在院状态。
5. 医生在“诊断医嘱”选择 `I25.103` 冠状动脉粥样硬化性心脏病，主诊断入院病情选“1 · 有”，确认住院诊断。进入“DRG 与费用推演”，正式事实应为 **FR59**；计划和实际费用分开显示。

病例来源的九项基线值尚不是本院检查报告；管理员真值也不交给普通临床或登记岗位。下列检查必须在本次住院另行开立、送检并签收。

## 造影、PCI 与术后用药

1. 医生在“手术”申请 `88.5500 · 单根导管的冠状动脉造影术`，填写计划时间和固定合成理由。护士核对术前检查，医生确认知情同意已签署，再选择实际术式并“记录实际手术”。本次造影不使用下列 PCI 材料预留。
2. 医生在“病案”选择造影为本次主操作并提交首页修订；“DRG 与费用推演”的正式事实应为 **FM59**，显示缺少支付参数，成本也继续缺失。实际造影收费 **800.00 元**。
3. 医生申请 `36.0700 · 药物洗脱冠状动脉支架置入`。在“DRG 与费用推演 → 治疗耗材预留”分别选择下表四项、各数量 1，在“关联手术计划”选择该 PCI 申请；填写理由、审阅并确认预留。此时仅预留，不计费。
4. 护士核对该 PCI 的术前检查，医生确认知情同意。医生记录实际术式 `36.0700`，添加四项手术耗材，各数量 1；每项“替换治疗预留”选择原关联预留，再“记录实际手术”。确认四项均转实际使用，没有遗留预留或重复耗材收费。PCI 手术收费 **1,800.00 元**。
5. PCI 完成后，医生回“诊断医嘱”，在“术后关联手术”选择刚完成的 `36.0700`，新增一条阿司匹林肠溶片 **100 mg、1片、QD、临时**医嘱，用于合成病例的术后抗血小板维持演示。护士校对、药师发药、护士给药。确认它是关联本次 PCI 的独立术后医嘱，增加 **0.50 元**，累计六次药品执行均完成。

## 出院、待遇与未知组合补缴

1. 医生确认本次检查、医嘱和手术都已收口，在“出院结算”填写说明并“开出院医嘱”。护士选择“医嘱离院”并“办理出区”。此时已出区，尚未完成财务和清床。
2. 收费员在同一住院打开“患者医保待遇（合成）”，选“合成职工 v1”，预览待遇，审阅并提交医保结算。核对本节下方的独立账本。
3. 点击“预览结算”保留首次待结算预览；随后在“住院收退款”选择“出区补缴”，现金填写 `100`、银行卡填写 `1696.45`，合成渠道结果选择“未知后查明成功”。预览并确认已审阅收款，得到一笔 **1,796.45 元**的结果未知组合收款。
4. 观察“资金结果未知，请查询原尝试”。新收退款及首次“确认结算”均被阻断；护士查看同一住院，“清床”也不可提交。未知款项不能当作成功余额，也不能新开一笔款项替代。
5. 收费员点击这笔交易的“查询原收款”。成功后仍是原交易，现金／银行卡组成不变；累计成功预交金 **50.00 元**、成功补缴 **1,796.45 元**，未决笔数为零，尚应收为零。刷新或恢复不应新增第二笔入金。
6. 重新预览结算，核对费用净额 **4,036.18 元**和无补退，再“确认结算”。护士填写清床说明并“清床”，确认已清床。保存首次结算的费用、待遇、交易和回执身份，后续更正应保留这些旧事实。

## 归档后更正与原交易退款

1. 收费员打开“后续财务更正”，在“更正关联原费用”选择本次支架 **730.00 元**的原费用，冲减金额填写 `10`，说明合成核对原因，审阅并提交。它追加关联更正，不修改原费用和归档。
2. 在“后续医保更正”审阅并补偿原待遇，再预览和确认更正待遇。此次冲减的是目录外材料，基金 **2,169.73 元**、账户 **20.00 元**不变，当前医疗费用变为 **4,026.18 元**，患者责任变为 **1,836.45 元**，应退 **10.00 元**。
3. 选择有可退余额的原入金来源，本次收退金额填 `10`，预览后续退款并确认本次收退。成功后应收、应退均为零，更正完成。退款应引用原交易，不是无来源支出。
4. 回查首次结算、原待遇和交易快照、病案归档、冻结 FM39 与医保办核定记录，仍保持更正前内容；临床仍为已清床、病案已归档，不退回在院状态。当前账务显示 **4,026.18 元**，原冻结费用仍为 **4,036.18 元**。

## 恢复与重新开始

页面请求丢回执时先使用“恢复原准备操作”“恢复原档案选择”“恢复原住院操作”等原操作恢复入口，不改输入、不重新选病例或另建入院。确定的版本冲突应刷新当前事实后重新审阅；支付渠道结果未知使用“查询原收款／退款”。网络恢复、业务结果未知和版本冲突使用各自页面反馈，不把刷新当成已经成功。

要完整重演管理员准备至退款全部步骤，使用同一固定代码、规则和参考资料，另建独立临时业务库，从空患者库开始，按本手册重新执行。两次运行分别保留身份和证据，不将新库替换为原环境业务库，也不把重复“准备固定 PCI 病例”的幂等返回当成第二次住院。自动化可对真实 Web 旅程执行 `pnpm exec playwright test apps/web/e2e/inpatient-pci.spec.ts --project=web --workers=1 --repeat-each=2`；每例 fixture 创建独立临时库，每轮都应核对更正后的冻结历史。

需要在同一演示库复用固定病例时，管理员在“模拟数据”使用“重置数据”，默认保留患者库。它创建新 Epoch、保留旧 Epoch 和审计，按原 Case／Profile／Persona 修订重放已有住院为“待入科、零费用、零预交”，从护士接诊继续；登记员不再为已重放住院重复登记。若确需重新演示全部准备和登记页面，优先使用上述独立新库。重置与资产保留的详细合同见[仿真架构](architecture/simulation.md#106-重置与-epoch-隔离)；普通页面查询只看活动 Epoch，没有从页面切回旧 Epoch 的功能。

自动化运行结果和集成提交以[本票正式规格](spec/2026-10-27-pci-golden-demo-readiness.md)关联的交付证据为准。普通 Web 从零旅程、完整规则 HTTP 账本与 React 18/19 共享合同分别报告；Surface 中已有 HTTP 前置不代表 Surface 从零全流程，原生 DSH Session 和 Agent Tool 验收仍在本手册范围外。父任务 #225 的最终公开修改和关闭由人类决定。
