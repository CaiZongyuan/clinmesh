# Agent Note: 医生工作台三页签目录与表单统一为弹窗一体合同

Status: implemented

## Problem

医生工作台第二步的页签整理最初把目录浏览与表单填写做成「目录+表单同卡」的内联结构：目录列表直接驻留左主列，点选后在同卡内展开表单。实施与双轴审查中发现该结构在诊断、处方、检验、放射、病理五个页签各自重复适配目录高度、滚动、空态与搜索交互，调整/编辑入口与「一次一条」确认语义分散，弹窗高度约束（`12.5rem` 五条封顶）在内联形态下无法统一；且诊断目录（远程搜索+本院常用回退）、药品目录（本院/参考目录分组包装选择）与检验/放射/病理目录（本地小数据集即滤）数据形态差异大，同卡结构的复用收益为负。

## Decision

五个页签统一为「弹窗目录表单一体」合同：弹窗顶部搜索、中部目录列表（弹窗可视高度内滚动，必要时封顶防止超长），点选目录项后弹窗内展开表单；一次弹窗确认一条——诊断/处方为「加入诊断/加入处方」，检验/放射/病理确认动作呈现为「保存草稿」，确认即保存服务端草稿并落单；未确认关闭即弃置弹窗内输入（页面草稿与自动保存不受影响，已保存的服务端草稿不被更新）；页签列表条目以同一弹窗重开编辑（`编辑诊断 ${display}` 等入口）。右辅助列恒为一块推荐/待开具面板（处方结论方式不再占右列）；无需用药结论在左主列内整块替换目录与表单卡。弹窗桌面居中、宽高有上限，窄容器回落近全屏；目录容器带 `data-agent-catalog` 供 Agent 合同定位。

弹窗重置采用 latest-ref 模式：`targetRef.current = target` 渲染期同步最新编辑目标，`openingRef` 记录上一次 open 状态，`useEffect([open])` 在打开瞬间读取当时目标重置弹窗内状态，避免把易变 target 写进副作用依赖。

药品/处方弹窗的表单字段值域不再手抄边界，复用 `prescriptionDraftItemSchema.shape.*`（`doseText`、`frequencyCode`、`courseDays`、`quantity`）逐字段 `safeParse`，本院药品另按目录 `allowed*` 值域收紧，防止弹窗校验与提交合同漂移。

## Alternatives considered

保留「目录+表单同卡」内联结构：目录与表单挤占左主列纵向空间，五个页签各自维护高度与空态，搜索交互（完整搜索表单与简单即滤输入）不一致，Agent 断言需按页签分别适配。未采用。

检验/放射/病理弹窗复用诊断目录的 `CatalogSearchForm` 搜索表单：这三个目录是本地静态小数据集，无分页、无远程搜索，复用会引入用不到的分页/重试/展开状态。保留轻量输入框即滤。未采用。

同步删除旧的仅选择式目录弹窗组件：`apps/dsh-web` 既有 browser fixtures（`responsive`、`catalog-dialogs`）仍引用旧弹窗并锁定其合同，删除属独立的简化任务，不在本次 diff 内强行清理。暂缓。

## Consequences

五个页签的组件测试与 `apps/dsh-web` browser 合同全部改为弹窗合同断言（弹窗标题、`data-agent-catalog`、一次一条、取消弃置并重开、列表条目重开编辑、右列单面板）；spec A11 与测试策略措辞已同步（检验检查分类切换为检验/放射/病理子页签、弹窗目录在弹窗内滚动、保存草稿语义按域区分）。旧的仅选择式目录弹窗由上述 fixtures 继续引用，其删除与 fixtures 迁移延后到独立简化任务。
