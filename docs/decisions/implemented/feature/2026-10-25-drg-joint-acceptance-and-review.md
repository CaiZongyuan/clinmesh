# Agent Note: DRG 联合入口、当前事实与审阅绑定

Status: implemented

## Problem

支付与 DRG 联合验收需要医生、病案及医保办从同一次 PCI 住院读取和确认各自的事实。仅有领域 HTTP 接口无法证明岗位入口可用；旧首页修订也不能代表当前在院事实。评估若未绑定住院身份和实际开具选择，界面审阅可能在病例切换或异步执行后失效，裸列表的 Catalog 输出还会使已提交的 Command 在客户端被误判为失败。

本决策部分替代[住院 DRG 仿真链](2026-10-23-drg-inpatient-simulation-chain.md)中后置 Web 入口、恒定支付缺项与不记录读取审计的决定；保留其双轨编码、归档冻结、确定性合成核定与不保存只读评估实体的取舍。当前详细合同由[临床流程](../../../architecture/clinical-workflows.md#drg-评估与医保办核定)和[部署指南](../../../deployment.md#运行时-drg-规则启用)拥有。

## Decision

- 在院评估读取当前正式事实，首页未提交时用修订 0 表达；归档后只读不可变冻结结果。页面按归档状态互斥展示冻结结果和在院推演，不能仅禁用查询后继续展示其缓存数据、错误或过期提示。主操作仍需医生显式确认，计划不当实际。
- 多计划推演显式选择假想主操作；唯一计划可默认，实际主操作继续属于首页。FM39 消费固定 PCI 参数 owner，避免病例数据与运行评估各自维护不同的支付参考；版本升级不改既有冻结记录。
- 医生与医保办通过独立岗位入口调用共享 Query 与 Command。医生的已审阅单项草稿绑定完整依赖指纹，正式开具时服务端按实际选择重算；医保办先审阅服务端核定预览，再以指纹确认。指纹必须包含住院身份及实际分组输入，不能只绑定可能相同的版本号。
- 活动可见页面定期通过 Query 核对依赖，发现变化后保持过期状态并锁定已经打开的确认，要求人工重算和重审。Query 拥有服务端结果，客户端只保留已接受指纹和失效状态；后台刷新不能自行重新认可医生原审阅。
- 归档时在同一冻结结果内保存医院支付预估及其参数身份，作为核定与原预估的固定对账基线；收费差额单列。旧归档没有基线时明确不可对账，禁止按当前参数回填历史。医保办只取得冻结病例的分组属性、诊断与实际操作编码来源摘要，无需开放完整病案。
- 正式收费从发药、服务执行和手术材料 owner 读取实际数量，已记费发药不重复算未记费承诺。首次排程的判定使用执行事实，不能以医嘱已校对推断执行单已生成，否则错过当日给药时点的长期医嘱会漏算。合成院内支架、球囊与导丝条目有独立身份和明确计价单位，不修补真实参考的未知单位。合成医院支付参数独立版本化，覆盖明确演示病组，未覆盖继续报告缺口。
- 公开 DRG 读取记录成功与拒绝审计，成功审计不能落盘时拒绝返回结果；内部领域查询复用同一逻辑而不产生重复读取记录。写入与恢复继续遵守标准 Command envelope 和原回执，不在客户端绕过 Catalog 校验。
- 规则物化与运行时启用分开。正常服务配置同时要求版本包和受信审核文件，审核绑定 Manifest 与临床目录版本，逐项记录用途、编码、适用范围和算法证据。四个固定病例对照只能证明该切片，不能自动签署完整来源包审核。

## Alternatives considered

- **让首页提交成为在院评估前提**：拒绝。它把离院病案流程变成医生实时只读评估的门槛，并会保留旧事实。
- **只由浏览器标记过期**：拒绝。异步执行、其他岗位写入、患者切换与直接 API 调用均可绕过最后一次客户端状态。
- **把评估存成可编辑实体**：拒绝。指纹与正式写入重验已提供绑定，不增加需要同步的第二份临床或费用状态。
- **核定时用当前参数重建医院原预估**：拒绝。它会把参数变化抹平，使预估与核定差额失去可追溯基线；固定在已有归档结果内保存预估即可，无需保存每次只读推演。
- **用真实参考的包装或中选价格补齐未知计量**：拒绝。来源单位未确认时不能推断院内计费单位，合成演示条目必须拥有独立身份。
- **下载和哈希校验成功即启用完整规则**：拒绝。完整性不能证明使用条件、规则正确性及编码适配。

## Consequences

Web、DSH Surface 与 CLI 可保持同一审阅、权限和回执语义；缺规则与缺成本有明确降级。医院侧参考差额与患者待遇、资金及归档后的财务更正各自独立，不自动互相触发。PCI 联合旅程分别使用 CI 自编规则切片及固定完整 v2 包；完整来源包的使用条件与部署审核仍须实际核验，不能据此宣称某地正式结算一致。

验证以公开 HTTP 和临时文件 SQLite 拥有业务不变量，真实浏览器拥有岗位接线、迟到隔离与人工审阅，CLI 示例漂移测试拥有 Catalog 和回执格式；完整来源条件覆盖及离线 oracle 的独立证据见[固定来源核验](../../../research/2026-10-25-drg-condition-verification.md)。PCI 阶段分别核对无操作 FR59、造影主操作 FM59、支架主操作 FM39；造影与支架同时存在时不能因成功入组而忽略主次错误。测试替身只在支付渠道、模型及来源文件等外部边界，不替代临床和账务 owner。

依赖变化验证使用实际事实变更、临时价目输入和有效合成规则包重启，避免直接替换指纹而跳过生产计算。审阅后的并发验证使用独立 SQLite 连接并从公开医嘱、收费和原回执核对唯一性；同进程有界请求的通过不扩大为多进程或负载结论。成本尚无输入 owner 时只验证缺项展示，真实成本变化保留为[后续接入条件](../../../spec/2026-10-15-drg-prescription-budget.md#后续事项与成本接入条件)，详细场景与入口由[测试策略](../../../testing.md)拥有。
