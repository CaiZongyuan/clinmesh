# Agent Note: 按就诊场景决定月经史与孕产史必填

Status: implemented

## Problem

[女性病史文本要求](2026-11-09-female-clinical-history.md)仅按 Patient 性别要求两个文本章节。普通门诊、低龄女童、专科初诊和住院入院记录的采集目的不同，统一门禁会增加无关录入，还可能诱发无来源的阴性默认值。本决策取代原决策的全女性必填范围，保留自由文本、来源和历史原件兼容的选择。

现有实现只有门诊 Clinical Document，挂号收费类型和接诊流程中的“复诊”都不等于临床初复诊。直接增加年龄判断或按页面名称分支，仍然无法可靠区分适用场景。

## Decision

保留两个自由文本框，将患者属性、业务日期、科室编码和明确文书分类交给服务端共享规则计算，向页面、质控与 Agent 返回一致的适用性及原因。草稿不阻断；仅适用女性专科初诊在签署和正式修订边界要求非空白正文。年龄阈值和科室映射是院内策略，不能写成法规原文；完整当前规则由[临床业务流程](../../../architecture/clinical-workflows.md)拥有。

临床初诊／随访由负责医生在首次签署前通过独立 Command 核实，保存到 Encounter.type，采用版本、幂等和审计并创建带核实依据的 Provenance。Agent 只读，不从正文、挂号收费类型或流程步骤推导分类。分类修改作废旧签署预览，Patient 版本和权威规则输入也进入预览指纹。禁止签署后重分类，避免修订校验和归档 Encounter 的分类分歧。

本期处理门诊动态必填。住院入院记录、急诊例外、妊娠／哺乳状态、结构化表单和药品／放射安全联动分别依赖尚未存在的领域合同，保留后续规划。孕产史也不直接扩展为包含婚姻与配偶信息的婚育史。

混合自由文本不跨次就诊自动复制；来源、历史签署原件和同次草稿恢复继续保留。年龄、婚姻和历史段落均不能自动证明当前未孕、已绝经或正在哺乳。

## Alternatives considered

- 所有女性统一必填：上下文不足，普通门诊也被迫补全，与本次范围调整不符。
- 仅增加年龄上下限：不能区分文书、科室和已知临床情况，也容易把高龄当作已绝经或安全依据。
- 前端独立判断并隐藏字段：会与共享 Command、质控及 Agent 产生规则漂移，还可能遮蔽既有记录。
- 本期同时建设完整生殖安全体系：需要住院文书、状态时效、药品知识与急诊审计等独立能力，不符合已确认的“文本框＋动态必填”范围。

## Consequences

上下文缺失保留可见入口并提示核实，不制造确定性。初诊核实需要医生承担分类责任；病历非空不证明采集真实或诊疗安全。普通门诊不再因女性身份被统一阻断，收起不删除正文。公共接口回归覆盖签署、修订、分类 CAS／幂等和预览失效；共享纯函数覆盖业务日期与年龄边界，Web 与 React 18/19 DSH 浏览器覆盖文本框、动态标识及核实对话框。正式验收范围见[Issue #430](https://github.com/CaiZongyuan/clinmesh/issues/430)。
