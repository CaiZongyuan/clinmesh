# Agent Note: 门诊月经史与孕产史自由文本兼容及按就诊场景动态必填

Status: implemented

## Problem

门诊结构化病历需要独立记录女性患者的月经史与孕产史。若将其拆为繁琐的妇产科结构化子表或在全局持久化 schema 中设为无条件必填，既会加重普通内科门诊负担，又会导致存量缺少这两节的已签 `Composition`／`Bundle` 无法反序列化；反之，若仅按 `Patient` 生理性别对所有女性一刀切强制必填，低龄女童、普通非专科随访也被迫补填无关隐私，甚至诱发无真实问诊依据的“默认阴性”造假。同时，挂号收费类别与系统接诊阶段中的“复诊”并不等同于临床文书规范中的初诊／随访分类。

## Decision

保留可空兼容的双自由文本字段，并由服务端共享规则结合受审计临床初复诊分类动态裁决签署必填边界，当前完整规则见[门诊业务流程](../../../architecture/outpatient-workflows.md)：

1. **向后兼容的自由文本章节与来源忠实约束**：`menstrualHistory` 与 `obstetricHistory` 采用与既有病史一致的多行自由文本（每项上限 4,000 字，持久化与传输 schema 保持可缺失以兼容全部历史草稿、已签原件与幂等回执，新签署文书使用稳定章节编码 `menstrual-history` 与 `obstetric-history`；不与含婚姻配偶信息的婚育史混同）。草稿保存始终允许留空；自动病历整理仅写入有明确问诊或医生补充依据的陈述，绝不自动补写“平素体健／无异常／未孕”默认文本。
2. **受审计临床初复诊核实与服务端统一动态必填门禁**：负责医生在首次签署前通过独立受审计 Command 核实临床初诊／随访分类并写入 `Encounter.type` 与 `Provenance`（Agent 仅只读，禁止从挂号费类别或正文猜测；修改分类立即作废旧签署预览，首次签署后禁止重分类）。服务端共享纯规则综合患者性别、按业务日期计算的年龄、科室编码与已核实文书分类计算适用性并同步交付页面、质控与 Agent：仅适用女性专科初诊在签署预览、正式签署与文书修订边界强制非空白正文（缺项稳定返回 `CLINICAL_HISTORY_REQUIRED`），其余场景保持选填且折叠不删已录正文。

## Alternatives considered

- **拆分为初潮、周期、孕产次等结构化必填表单，或在迁移中为历史文书回填“无”**：超出通用门诊文书粒度，回填“无”则会凭空捏造临床阴性事实并篡改历史原件。
- **对所有女性患者或仅按年龄区间一刀切必填**：忽略科室与初复诊语境，且高龄或既往记录不能自动等同于当前已绝经或无妊娠风险。
- **仅在前端按页面显隐控制必填**：CLI、Agent 提案或直接接口调用可轻易绕过，必须以共享签署／修订 Command 为唯一权威门禁。

## Consequences

普通非适用门诊不再被女性病史门禁无端阻断，适用女性专科初诊则在签署关口获得确定性完整性保护，存量历史病历零迁移破坏。自由文本非空仅代表章节已填，不自动充当放射检查或致畸药物的妊娠／哺乳安全豁免证明。
