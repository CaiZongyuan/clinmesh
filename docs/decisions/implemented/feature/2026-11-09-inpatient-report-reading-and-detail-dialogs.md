# Agent Note: 住院医生报告按阅读状态展示与低频详情弹窗

Status: implemented

## Problem

住院医生需要频繁阅读新签发报告，页面内折叠全文却让每份待阅报告增加一次展开。已阅报告、手术申请、术后耗材更正和执行记录与高频临床信息共用正文，增加页面长度。统一到患者头部的 AI 用量入口还需要保留归档后的只读访问，以及未决请求的可见提示。

## Decision

在[步骤化手术与 DRG 决策](2026-11-05-inpatient-ai-step-fusion-and-ui-shell-alignment.md)基础上，[检查检验](../../../../apps/web/src/app/inpatient-investigations.tsx)按阅读状态组织内容：待阅检验结果直接显示完整表格，待阅影像显示完整印象与结论；已阅条目只保留紧凑摘要，全文与既往修订进入标准弹窗。影像确认仍绑定当前报告修订实际显示的首帧与稳定审阅锚点，展示变化不授予额外已阅权限。

[手术](../../../../apps/web/src/app/inpatient-surgery.tsx)保留关键测量、行内指南、耗材确认与最终汇总，低频编辑和完整依据按需打开；[医生医嘱](../../../../apps/web/src/app/inpatient-clinical.tsx)按单条医嘱查看执行记录。模态写入期间保留关闭保护，失败在弹窗内说明并保留输入；护士执行与其他岗位职责继续由各自页面承担。

[患者头部](../../../../apps/web/src/app/inpatient-patient-workspace.tsx)保留唯一跟进和用量入口。头部用量按本次住院累计，任务详情入口仍可限定原任务；归档后只读可查，跟进停止和权限失效使用实际状态说明。[用量弹窗](../../../../apps/web/src/app/inpatient-drg-usage.tsx)显示累计调用、Token 和费用，未决结果与进行中请求独立于计量完整性判断，可直接进入原请求明细。页面关闭不清零，用量和明细轮询仅在相应弹窗或明细打开时启用。

既有用量接口只有指定任务才返回阶段分组，因此阶段明细按需读取当前跟进任务，并明确标注统计范围；住院累计和请求分页继续覆盖本次住院全部任务，阶段查询不覆盖总额。行内指南只展示真实任务结果及其状态，不用固定临床结论填补尚无意见的状态。

## Alternatives considered

- 保持所有报告全文默认折叠：待阅报告需要重复展开，摘要也不能证明医生已看到全部指标。
- 将关键测量、指南摘要和全部手术参数一并移入弹窗：会打断选型与耗材确认步骤，医生需要跨窗口比对当前决策所需信息。
- 归档后隐藏整个 AI 入口：临床分析应停止，但历史调用和未决计量仍需核查，二者应分别控制。

## Consequences

正文优先保留当前决策与未解决待办，历史和低频编辑保持可查。新增弹窗共用 UI Portal 容器，验收分别覆盖 React 18/19 ShadowRoot 的键盘、焦点和提交保护，以及真实 Web 入口的阅读、状态切换与错误恢复。服务端 Command、审计、并发版本、指纹和报告修订合同保持由原模块拥有；范围与验收见 [Issue #400](https://github.com/CaiZongyuan/clinmesh/issues/400)。
