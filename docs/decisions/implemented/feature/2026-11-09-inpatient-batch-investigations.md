# Agent Note: 住院检查按类别集中开立与原操作恢复

Status: implemented

## Problem

住院检查弹窗一次只能开立一项。连续开立需要反复打开目录，而将多条单项请求简单循环发送又会在响应丢失、刷新或切患者后重复办理已经成功的项目。

## Decision

住院检查在同一弹窗内按检验、检查分别维护待开清单，每次最多保留 20 项。目录和待开区分别滚动、分页，完整已选清单不随搜索或目录翻页改变；每项保留自己的指征、目录版本和冻结价格，提交前集中检查所选项。当前业务合同由[临床业务流程](../../../architecture/clinical-workflows.md)拥有。

每项仍通过现有 `inpatient.investigation.issue` Command 独立执行，内部的申请、价目冻结与审计继续原子生效。客户端按顺序执行明确选中的同类项目，成功项移出草稿并显示结果，确定失败项保留输入；结果不明时停止派发余项并保留原输入、预期版本和幂等键。恢复先查询原回执或交给[住院原意图恢复](../bug-fix/2026-10-20-inpatient-command-intent-recovery.md)，不为结果不明项创建新键。

未提交输入与每项已发意图在发送前同步保存到 sessionStorage，按账号、Workspace、Epoch、岗位、患者与住院隔离。存储必须通过 schema 和关联校验，不能把无法读取的数据当作空草稿继续发送。关闭、切页、切患者和刷新保留输入，退出登录清除草稿；显式清空需要确认且不能丢弃待恢复项目。服务端查询仍由 TanStack Query 拥有。

## Alternatives considered

- 新增整批原子 Command：会让一项冲突回滚其他独立申请，违反已批准的逐项结果与恢复边界，也重复现有申请内核。
- 只在组件 state 保存多选并循环 mutation：刷新后失去原意图，无法区分尚未发送与已经提交但未收到响应的项目。
- 跨检查类别一次总开立：隐去类别与指征差别，扩大了用户本次确认的范围。

## Consequences

批量入口减少重复操作，保留独立申请、护士送检和既有权限边界。浏览器回归通过生产 Web、临时 SQLite 和受控合成 Provider 核对两项独立申请与丢回执恢复；React 18/19 ShadowRoot 合同另核对连续添加、跨页选择、焦点和窄宽度，不代表原生宿主全流程验收。
