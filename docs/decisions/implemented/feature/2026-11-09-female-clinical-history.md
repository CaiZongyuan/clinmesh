# Agent Note: 女性病历的月经史与孕产史文本要求

Status: implemented

## Problem

医生需要独立记录月经史和妊娠、生育经历，并在女性病历签署前确保已询问记录。拆成结构化妇产科表单会增加普通门诊的填写负担；全局必填 schema 则会让缺少新章节的历史签署件无法读取。

## Decision

月经史 `menstrualHistory`、孕产史 `obstetricHistory` 使用与现有病史一致的多行文本框，每项最多 4,000 字。草稿可暂存缺项，女性患者签署预览、提交和正式修订由共享 Command 读取权威 Patient 性别并检查非空白正文；其他性别允许留空。前端和质控复用相同的适用字段规则，不按年龄、婚姻状态或模型推断决定必填范围。

持久和传输 schema 保持新字段可缺失，以兼容旧草稿、Composition、Bundle 及回执；新签署件使用稳定章节编码 `menstrual-history`、`obstetric-history`。自动记录只把来源支持的事实写入对应字段，不自动生成正常、阴性病史或当前未孕。现有[家族史与过敏史决策](../architecture/2026-10-14-clinical-document-fields.md)继续适用，这两项仍可留空。

## Alternatives considered

- 拆分初潮、周期、孕次、产次等结构化字段：超出普通门诊本次需求，采用自由文本。
- 保存草稿即强制补齐：会阻止询问过程中的暂存，改为签署和正式修订时校验。
- schema 全局要求新字段，或迁移时补“无”：会破坏历史记录或制造阴性事实，保留缺失并只校验新的正式写入。
- 仅在页面设置必填：Agent 或其他接口可以绕过，因此以共享 Command 为业务边界。

## Consequences

现有女性草稿签署或历史结构化文书正式修订时需要补齐两项，缺项通过稳定原因 `CLINICAL_HISTORY_REQUIRED` 提示重新询问记录。已经签署的原件保持不可变且不补写。数据库扩展记录字段约束时保留来源、人工归属、锚点、顺序和逆操作数据，并在事务外关闭外键、重建后检查引用再恢复外键。接口回归覆盖草稿、缺项、非女性、修订、自动记录与有数据升级；真实 Web 和 React 18/19 DSH 浏览器合同覆盖文本框、必填及保存恢复。当前合同由[临床业务流程](../../../architecture/clinical-workflows.md)拥有，验收范围见[需求规格](../../../spec/2026-11-09-female-clinical-history.md)。
