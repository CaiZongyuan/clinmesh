# Agent Note: PathJX 提供门诊病理阅片与模型提示

Status: implemented

## Problem

医生需要在当前患者的病理会诊中使用 PathJX 的阅片、模型提示及人工复核，同时保留原申请、收费、正式报告和已阅责任。直接打开普通工作列表会扩大对象与身份范围，直接导入组件又会绑定独立前端运行时与发布周期。规格由 [ClinMesh #538](https://github.com/CaiZongyuan/clinmesh/issues/538) 和 [PathJX #327](https://github.com/JinhaoFang/PathJX-01/issues/327) 拥有。

## Decision

使用独立 origin 的专用 iframe 与版本化阅片服务协议。ClinMesh 只拥有临床事实、受限会话、外部引用和确认检查点；PathJX 拥有切片、模型、分析与人工复核。短效凭据经消息交换，只驻留浏览器内存，每次外部操作重新核对当前医院授权。共享服务凭据不能冒充医生，原生 API 不能访问接入对象。当前合同见[可插拔病理阅片](../../../architecture/pathology-reading.md)。

一次会诊固定一个既往标本、一张 H&E 切片和当前报告；共享原片不共享患者复核上下文。首次只扩展结直肠内镜标本和甲状腺手术标本，不把模型能力写成页面器官分支。新器官仍需相容服务、病例、价格及许可素材，新输出或交互须升级协议。

病理病例复用通用作者病例包的确定性身份与准备服务。幂等请求内部绑定包标识和版本，跨包复用同一操作键会拒绝；旧回执仍可通过原查询入口恢复，避免将另一个病例包的成功误认为病理准备成功。

模型提示、人工复核、正式报告和报告已阅分别保存。关联、打开或启用模型不自动推理；明确分析绑定固定模型与原意图。已有成功整片结果可以保留来源后复用，不自动重算历史会诊。显示事件只能提供本轮资格，服务器仍核对原片可读性、授权与报告版本，再由医生明确确认。

外部动作可能已经成功而响应丢失，因此以稳定编号查询原回执，并在业务事实与回执同事务后交换前后修订检查点。已确认动作缺失或回退时停止，不因原片仍可读就补建业务对象。两侧恢复必须对齐实例、内容、临床事实和原回执；失联不转换为重新执行。

## Alternatives considered

**抽取 PathJX React 组件或复制实现。** 页面容易融合，但耦合 React、路由、样式和发布，复核状态出现重复 owner；iframe 保留运行时与部署隔离。

**保留 ClinMesh 阅片器，只调分析 API。** 能提供少量提示，却要重建候选、定位、测量与复核编辑器，无法复用当前需求的完整阅片能力。

**跳转普通工作列表或同源代理整站。** 前者不能保证当前患者、报告与返回资格，后者让脚本共享父页认证上下文；路径前缀不能提供 origin 隔离。

**沿用导入、模型启用自动分析与超时后新键重试。** 接入改动较少，但会隐式耗用计算、改变历史上下文或重复临床动作。明确触发和持久回执增加协议复杂度，换取可解释的计算与恢复边界。

## Consequences

PathJX 可独立启停和替换，旧绑定仍指向原实例。故障与不兼容时文字报告保留，依赖阅片的已阅及完诊门禁继续生效。模型输出不获得正式诊断地位，协议接线通过也不代表医学质量验证。

部署需要登记许可、完整内容身份、已复核报告、实际模型与人类账号映射，并协调两侧备份。合成 HTTP、跨版本外壳和实际服务联调分别提供证据；真实原片与真实模型仍受独立授权及准备边界约束。首期不承诺多切片、通用插件市场、旧实例迁移或不兼容协议下的外部历史回看。
