# Agent Note: 默认检验服务与统一模拟数据管理

Status: implemented

## Problem

laboratory-cn 已提供完整报告、单位和成人规则，却仍要求管理员逐项发布才能开立。独立 LOINC 目录扩大默认下载和人工配置范围。管理员总览的标准/密集数据载入入口与已初始化的数据重复，重置又没有清楚区分保留患者与清空患者库。

## Decision

默认 lock 只同步疾病、药品和 laboratory-cn。启动时使用受信内部上下文与共享 Command，在每个当前 Workspace/Epoch 中自动启用 laboratory-cn 全部活动单项和组合。复用 Laboratory Service publisher 的解析、固定标识和快照构造；匹配当前 Release/policy 的服务不会重复更新，重置沿用已启用服务。显式配置其他 Reference Release 和来源的 CLI 发布能力保留，Web 不承担人工发布工作流。默认 Release 没有 LOINC 时停用其旧服务，历史申请快照保持冻结。

单项服务与组合成员服务具有不同标识，成员只能随组合执行。普通组合的有效标本是来源声明与所有成员声明的交集；声明“混合标本”的组合保留成员各自的标本。报告规则和原始来源定义仍由 Reference Release 拥有。

管理员唯一岗位首页是模拟数据。重置按钮在悬浮和键盘聚焦时说明影响，点击后进入二次确认，默认仅重置诊疗进度，可选择同时清空患者库。清空是逻辑归档：Profile 增加 archived_at，关联 Case 退役并停止出现在当前读取与挂号路径；旧临床和审计记录、来源病史、Brief、真值及检查快照继续保留供追溯。正在运行的患者或 Brief 生成阻止清空，排队中的相关任务被取消。账号、标准目录和已启用检验在两种重置模式下均保留。同源患者再次生成时恢复原档案，关联退役 Case 根据已有活动 Brief 恢复为待梗概或待就诊，保留不可变来源及历史关联。

[Laboratory Service 发布](2026-09-01-laboratory-service-publication.md)的人工默认流程由自动启用取代，显式发布的版本与原子性语义保留。[来源病例重放](2026-08-30-synthea-case-source-and-replay.md)仍定义默认重置，清空模式是其不重放病例的分支。接口和当前行为由[系统架构](../../../../docs/architecture.md)拥有。

## Alternatives considered

- 只预选所有候选：仍把初始化责任留给管理员，首次使用和重置后仍可能没有可开目录。
- 把全部参考概念直接当医嘱项目：绕过 Hospital Service 快照、组合依赖和报告规则，破坏既有临床合同。
- 清空时物理删除旧事实：会破坏已签发检验与来源快照、病例物化和审计之间的关联。
- 两个独立管理员页面：数据准备、患者生成和重置继续分散，增加没有业务价值的导航。

## Consequences

启动依赖可验证的 laboratory-cn 元数据，错误定义不会静默激活。开发 launcher 检查配置路径中的 lock Release，缺失时自动同步；Server 不在运行中下载目录。HTTP 测试覆盖默认启用、单项与组合、重复初始化、重置保留、显式发布、标本边界和清空读取隔离。页面测试覆盖唯一入口、影响提示、取消与确认、清空后刷新以及生成任务的导航恢复。开发进程监督测试等待数据源就绪标记后验证进程创建与停止，使目录初始化耗时与进程树生命周期独立。
