# Agent Note: 跨岗位共用卡片工作台、两栏开具器、阶段派生与原位审阅

Status: implemented

## Problem

门诊与窗口各岗位同时承载候诊／待办队列、患者头部、多业务页签、目录检索开具、正式记录审阅与 Agent 提案确认。若各页面各自拼装外壳、队列行、目录弹窗与查询失效，会导致 Web 与 DSH 分屏下断点错位、号码溢出卡片边界、在诊与完诊切换时 Tabs 指示器重建断帧，以及多栏并排挤压表单空间；若把“初次开具／记录管理”界面阶段存入数据库，或采用遮挡上下文的模态 Agent 提案弹窗并在点击批准时重新读取已变化的输入框，则会制造派生状态失步与“批准内容非所见内容”的审阅风险。

## Decision

以 `apps/web` 共用卡片工作台组合、控制器边界、正式事实阶段派生与两栏开具器统一跨岗位体验，详细规范见[临床 UI 设计](../../../ui/design.md)、[前端架构](../../../frontend-architecture.md)及[Agent 集成](../../../architecture/agent-integration.md)：

1. **共用卡片壳层、岗位模式绑定与原位冻结审阅**：`workspace-card-layout.tsx` 统一组织流程指示、可收起／窄屏浮层队列（`QueuePatientRow` 统一患者姓名、状态、补充信息与可复制完整单号排版）、患者头部、业务页签与底部主操作栏（DSH 宽度适配、800px 队列浮层与提交 `inert`/交接播报见[DSH 原生 Surface 与壳层协同](2026-08-30-dsh-native-clinmesh-surface.md)）。挂号、收费与药房通过 `WorkspaceModeProvider` 绑定门诊／住院模式与可见上下文。`.propose` 提案由单一 Agent review controller 投影至目标行或底部原位审阅条，严格锁定准备提案时的输入、预期版本、预览令牌与幂等键，绝不在批准时从变化后的表单重新组装命令；异步成功后的自动导航额外校验原病例控制器仍挂载。
2. **`DoctorCaseController` 集中协调与 `moveBefore` 连续导航**：门诊医生工作台保持在 `apps/web`，由 `DoctorCaseController` 统一收敛病例查询、预期版本、幂等键、精确缓存失效与按病例隔离的检查分类／申请选择；`DoctorWorkspaceScope` 持有跨“在诊工作台／完诊病例库”共享的唯一导航宿主，树切换时通过保持连接与布局的同作用域容器执行 DOM `moveBefore`（不支持时回退 `append`），在 React 18/19 StrictMode 下保留滑块 CSS 过渡与键盘焦点。患者头部内联汇总确定性的七项完诊进度、病历质控与诊疗建议状态，彻底移除独立业务右栏与抽屉。
3. **正式事实派生两阶段视图与确认版本门禁**：诊断、处方与四类检查的“开具态／管理态”纯由服务端正式事实（是否存在 `diagnosis_confirmation`、正式 `Prescription` 或已签发检查申请集合）在前端派生，不新增服务端阶段列，筛选为空、草稿保存或取消记录均不回退阶段；检查分类切换保持已访问表单挂载以保护未保存输入，放射／病理已阅资格继续绑定实际显示的 `DiagnosticReport` ID。药房操作以成功回执记录的确认版本约束后续查询投影，防止刷新暂败留下的旧待发缓存重新放开已执行动作。
4. **`OrderComposerLayout` 五类共用两栏开具窗口**：诊断、药品、检验、放射与病理开具弹窗共用 `OrderComposerLayout`（容器足够宽时 `5:6` 左目录右表单独立滚动，过窄时上下堆叠；住院证因字段极简保持单栏）。候选采用统一整行选择按钮并保留禁用原因，药品包装选择器作为独立表单控件置于行按钮之外，布局层不接管领域查询或临床草稿状态。

## Alternatives considered

- **过早将门诊工作台抽入 `packages/views` 或合并诊断／处方／检查为单一泛型大表单**：在无第二套独立 DOM 宿主时制造假共享层，泛型表单则会引入大量可选字段分支抹平各领域规则。
- **在服务端新增 UI 阶段字段，或切换检查分类／完诊页签时直接销毁重建导航与表单**：增加无业务含义的迁移与同步契约，且丢失未保存草稿与导航焦点过渡。
- **保留遮挡正文的模态 `.propose` 弹窗或在点击批准瞬间读取当前输入框**：阻碍医生对照病历核实，且可能把等待期间的并发改动误提交为人工批准事实。

## Consequences

全岗位在 standalone Web 与 DSH React 18/19 ShadowRoot 中保持一致的卡片层次、窄容器可达性与焦点连续性；TanStack Query 独占服务端事实，Zustand 与按身份病例隔离的会话私稿仅管理客户端视图与未发输入，不产生双份服务端状态缓存。
