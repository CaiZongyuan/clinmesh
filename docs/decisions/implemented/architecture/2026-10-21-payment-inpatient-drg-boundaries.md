# Agent Note: 共享支付、住院流程与 DRG 的职责边界

Status: implemented

## Problem

门诊收款与住院预交金若分别维护收退款状态机，会使资金未知、退款上限及费用分配产生不同语义。独立合成住院评估上下文与正式住院并存，也会让同次诊疗出现两套金额与状态；归档后退款若直接覆盖首次结算，还会破坏临床和病案的冻结含义。

## Decision

门诊与住院复用共享支付账务。住院 owner 继续拥有临床执行、计费来源、出院与清床门禁及病案首页；支付 owner 统一资金尝试、分配、关联原交易退款与恢复。业务门禁调用共享支付结果，不在住院适配层复制收退款状态机。正式需求与总体验收归[业务规格](../../../spec/2026-10-15-drg-prescription-budget.md)，当前行为归[临床流程](../../../architecture/clinical-workflows.md)。

患者医保待遇结算与医院 DRG 付费使用各自的规则和结果。DRG 读取已确认的临床与费用快照，不修改临床事实、不创建第二套可写收费账；费用、资金、收入与成本分别表达。

沿用住院端的财务结算后清床门禁。支付或退款未知时保持未结算，不封账、不清床；出院医嘱及出区按各自临床条件继续。这样保留同事现有流程语义，同时要求共享支付 owner 先查明资金结果，不能以重复收付或推定成功释放门禁。

结算与归档后的纠错使用共享账务 owner 中关联原费用、资金及结算的后续调整链。原病案及首次结算继续表达冻结时的事实，当前账务和差异由关联调整表达；不通过覆盖旧账、恢复床位或解除病案归档锁完成退款。首次结算门禁与后续调整状态分别管理，后续交易未知不倒退已发生的清床和归档。

医保办专岗承接医院侧 DRG、模拟核定反馈及差异复核。收费员继续拥有患者收付和待遇结算，病案人员继续拥有编码审核归档，临床事实由医生及相应执行 owner 确认。权限按所需投影划分，避免为了 DRG 复核而把完整病案读取或临床写入合并到收费岗位。读取与正式动作分别保留审计。

首次待遇冻结和后续补偿的独有取舍分别归[首次冻结决策](2026-10-22-inpatient-insurance-freeze.md)及[后续补偿决策](2026-10-22-inpatient-insurance-adjustments.md)；在院当前事实、审阅指纹及核定基线归[联合入口决策](../feature/2026-10-25-drg-joint-acceptance-and-review.md)。这些决策细化本职责边界，不改变各业务 owner。

## Alternatives considered

- 保留门诊与住院独立支付实现，再由报表拼接：短期改动较小，但退款、未知结果及资金分配会长期存在不同语义，难以验收跨场景一致性。
- 在 #225 重做住院临床及出院链路：可以自行安排流程，但重复同事已实现的住院范围，临床事实与费用容易产生多个 owner。
- DRG 继续只依赖独立模拟上下文：便于演示，但无法回答真实业务入口中同一次合成住院的费用、医保与分组如何对应。
- 资金未知时先清床、财务继续挂账：可更早释放床位，但会改变同事 #249 的门禁，首期采用结算后清床。
- 所有财务纠错必须先解档重开住院：可以继续沿用旧可写流程，但把资金问题扩大成病案和床位回退；首期保留归档边界，以关联调整表达财务变化。
- 收费员兼任医院 DRG 运营：减少一个岗位入口，但把患者资金操作与医院侧病例复核集中在同一权限集合；首期增加医保办专岗，分别验收职责和可见范围。

## Consequences

共享支付保留业务来源和原交易引用，首次结算及病案归档绑定冻结账，后续更正通过独立关联链表达当前费用与收退差异。已完成 Scenario Run 只扩大受控财务更正与恢复能力，临床写入及 Workspace／Epoch 隔离继续生效；不能把后续退款直接追加到旧冻结数组后继续假定原校验成立。

支付、患者待遇、医院 DRG、临床及归档仍有独立状态和金额口径，岗位页面需保留原事实、当前调整与恢复入口。资金未知阻断首次财务完成，后续未知只保持对应调整待处理；两者不能共用一个会倒退临床完成事实的状态开关。

公开 HTTP 的资金、医保补偿、归档后更正与医保办权限／审计矩阵验证这些职责边界；同一次 PCI 联合账本核对资金恢复和后续更正不改写冻结事实。测试入口与证据范围由[测试策略](../../../testing.md)和业务规格的逐项验收拥有。本 Note 的 `implemented` 表示职责划分已经落地，不表示总规格中所有依赖变化与并发场景均已验收。
