# Agent Note: 本地指南验证用途与来源范围独立控制

Status: implemented

## Problem

用户提供的冠心病资料需要先进入本地推荐流程验证，不能把商业许可研究作为该阶段前置，也不能将本地验证解释成开放许可。直接改原始 `license.usage` 会丢失实际权利事实；全局允许所有未知来源则会连带改变已有 WHO 和国内资料的用途边界。需求与本地验收由[规格](../../../spec/2026-10-26-reviewed-guideline-content.md)拥有，完整 Release 分发由 [#315](https://github.com/CaiZongyuan/clinmesh/issues/315)追踪。

## Decision

沿用独立指南 SQLite、FTS、来源 revision 和既有诊疗建议链。显式本地导入使用稳定的 `local-evaluation-` 来源身份，保留原文件 SHA-256、真实许可、版本、发布者和出版链接；本地验证模式默认关闭，只由可信部署配置开启，并仅作用于该来源空间。模式不覆盖撤回或替代状态，不开放其他原始来源。默认正式用途继续采用[免费全文用途决策](2026-10-16-free-guideline-corpus.md)。

本地同步清单是该来源空间的完整快照，包含明确物理页范围。新增或更新从本地内容寻址原件提取；不扩大官方下载 URL allowlist，不在业务请求中下载或读取任意文件。变更或移除先清空旧段落，再尝试新文件；缺失或错误字节不能恢复被收紧的旧范围。受控本地来源允许保留空段落记录，因此停用不必改写真实许可或伪装成出版物已撤回。真实许可标识和说明链接同时写入可见范围，供模型和医生查看。

段落依据身份包含规范化来源元数据摘要。适用条件、范围或来源说明变化后，旧依据 ID 失效；原文定位保持真实页码和字符位置，临床界面显示文献与范围而不显示内部摘要。原来源的稳定 ID 或原字节哈希被撤回／替代时，派生来源和可用统计同步停用；不以共享通知页面 URL 推定其他独立附件也被撤回。

本地文件允许没有已核下载端点，保留真实出版链接即可；官方下载入口仍在读取缓存前要求受信 HTTPS 下载地址。PDF 原文、数据库和缓存不进入 Git。本地元数据缺少下载端点时旧读端不兼容，回滚旧代码须配套恢复指南库一致快照，业务库不回滚。

## Alternatives considered

- 把本次所有资料标为开放许可：实现短，但改变来源事实并误导其他部署。
- 仅打开非商业用途开关：不能覆盖用户提供的未知许可资料，还会改变已有 WHO 来源用途，和当前明确的本地验证范围不一致。
- 全局跳过用途检查：会放开不属于本次导入的来源，关闭原型时也难以证明旧依据已停止提供。
- 建立另一套检索库或临床建议引擎：重复预算、引用、核验和正式确认逻辑，不能增加本次接线证据。

## Consequences

本地目的和原始许可分别可追溯；模式切换进入 revision，使旧自动建议失效，已经正式确认的诊疗事实保留。部分资料文字层异常，按可核对范围纳入，不猜测医学符号。合成 HTTP 与真实 Web 旅程证明原文进入生成和核验、医生确认及字段缺依据的处理，不证明临床准确性或完整商业权利。

本地导入依赖显式提供的原件目录；它是先行验证入口，不代表 #315 的固定 Release、自动安装或空目录验收已经完成。当前操作与回滚说明由[部署指南](../../../deployment.md#冠心病资料的本地流程验证)拥有。
