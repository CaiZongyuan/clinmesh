# Agent Note: 模型明细到期清理与长期统计分离

Status: implemented

## Problem

逐次模型账本随使用持续增长，但直接删除旧行会同时删除监控总量，并可能借外键清理释放未确认消费。只保留成功／失败状态不能证明已结算：取消、失联和重启后的请求可能仍在服务商计费。核对与补算的完整 Command 回执又保存了一份明细，若只删除账本，幂等重放会绕过保留期限。

## Decision

将明细、长期监控汇总和额度累计分开管理生命周期。保留策略归 Workspace，跨 Epoch 持久；真实 UTC 调用开始时间决定到期，上海日期只用于日汇总。清理在单 SQLite writer 内先将符合条件记录的当前有效计量合并到日汇总，再删除已结算预占关联和明细，全部在同一事务中完成。总览组合汇总与留存明细，列表只查询留存明细；各维度累计和独立起点继续由原控制模块拥有。

选择仅在清理时生成长期汇总，而不为每次用量帧、迟到结算和人工修订额外维护一份实时统计。留存期内的原始计量与修订仍是当前事实，归档时采用最终有效值；清理与删除原子提交，重跑自然不会重复计数。汇总保留已支持筛选的维度组合，已知人民币金额和未知计数同时保留，不能以已知部分代替完整账单。

清理资格由派发与消费证据、全部适用预占共同决定。在途、派发未知且未完成全部消费核对、实际 Token 或消费仍未知、任一层任一维度仍有预占的请求继续留存，不从结果状态或计时器推断零消费。派发未知的已结束请求经显式核对、有效 Token 与人民币均已知且全部预占已结算后，也可清理，原始派发及结果状态保存在必要审计，长期未知结果统计继续保留。实际消费已经明确、只缺单价或汇率且无未决预占的请求可以清理，未知金额统计永久保留；不为将来的潜在价表无限保留可补算明细。

核对或补算过的记录保留必要原始计量、调用时计价依据和修订审计，不保留完整任务、来源或临床上下文。相应 Command 回执改为过期标记并保留审计与幂等身份；修订在回放回执前检查明细仍存在。必要审计支持解释累计依据，不成为历史明细查询、恢复或再次补算入口。

## Alternatives considered

- 删除明细后从现存行重算统计或额度：实现简单，却使历史消费消失并恢复额度；三个生命周期必须独立。
- 每次 checkpoint、结算和修订都维护实时日汇总：可以直接读取汇总，但需对迟到证据与修订维护差额，新增重复计量风险；仅清理时归档满足长期查询需要。
- 按终态或预占期限释放并删除：能保证明细严格限期，却把请求结束误当成消费已知；未结算保护优先于天数。
- 仅按日或单模型聚合：数据更少，但无法保持功能、Provider、请求／实际模型、结果和病例组合筛选；保留已有维度，不扩展任意历史因果查询。
- 永久保存所有原始 JSON 或完整幂等响应：方便恢复与补算，却使保留设置失去作用；只保留长期统计和必要核对审计。
- 统一保留所有缺价记录直到补齐配置：能延长补算机会，但不区分消费未知与价格未知；无未决预占且消费明确的超期记录可清理，并明确下钻与补算边界。

## Consequences

长期总览的数量可以大于仍可下钻的明细数量；延长保留期或改为永久只影响仍存在的记录，不能恢复已清理请求。未结算请求可能超过设置期限，需要可信用量或带依据的人工核对；清理不会提供新额度、解除未知预占或授权重发。已经归档的缺价费用保持未知，不以当前价表补造精确账单。
