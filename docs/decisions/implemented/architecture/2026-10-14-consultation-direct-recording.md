# Agent Note: 问诊整理直接记录与人工正文保护

Status: implemented

同步语义核对、整轮自动重试和质量提示的当前边界由[增量记录决策](2026-10-15-low-latency-document-recording.md)补充或取代；本记录的其他来源与编辑保护理由继续适用。

## Problem

问诊病史整理经过来源校验和独立语义核对后仍等待逐条应用，增加重复操作。隐藏按钮不能消除后端待应用状态和签署核对门禁。需求由[病历字段规格](../../../../docs/spec/2026-10-14-clinical-document-fields.md)拥有。

## Decision

通过校验的病史直接经共享 Command 写入草稿、来源和任务完成事实，移除公开 review 操作、逐条应用、忽略、确认、撤销和签署问诊确认。正式病历签署继续使用负责身份、完整性、预览、版本和令牌校验；自动记录只改变可编辑草稿。具体边界由[系统架构](../../../../docs/architecture.md)拥有。

补充或明确更正只替换仍由自动记录拥有且锚点有效的片段。人工正文保持原样，相应患者更正另行追加；矛盾另行记录待核实措辞，保留原陈述。模型仍须保留全部有效事实和引用。写入重新校验所有相关字段的人工比较上下文，变化时有界重试；超出字段上限时整个事务回滚并显示整理失败。

失败 Command 回执保存错误码和整理、独立核对或写入阶段；来源错误区分引用、目标、字段上限、核对覆盖和语义拒绝，语义拒绝只保存候选索引及忠实性、完整性、关系判断。重试成功可清除任务的当前错误，但不修改失败回执，避免恢复后丢失原因；不保存被拒绝正文、Provider 消息或提示词。否定核对结果仍直接拒绝候选，不通过格式修复诱导核对者批准同一事实。

模型适配器的结构化修复耗尽时，通过进程内 `cause` 保留最后一次校验异常，每次尝试清除前次原因。记录服务只从受信的 `RecordingSourceError` 提取有界诊断，回执不序列化异常或 `cause`；错误码仍为 `AI_RESPONSE_INVALID`，沿用修复耗尽后停止自动重试的规则。

升级将旧有效 pending 标为被替代，并把对应及后续轮次推进代次重新排队。启动恢复通过 Command 调度，当前模型和来源重新校验；迁移和 Query 不写正文。暂停、失效身份、旧 Epoch 和签署准备继续限制写入。旧拒绝、撤销和逆操作列保留为历史，不伪造医生确认。

旧控制与签署预览回执重放时校验并投影到当前 DTO，移除核对字段，把旧 pending 记录映射为被替代历史；原始回执与审计保持原值。公开新请求不接受旧确认参数，历史回执查询仍提供原证据。

本决定取代[字段建议](2026-10-13-consultation-field-suggestions.md)的先确认再写入，以及[审阅与撤销](2026-10-10-consultation-history-review-undo.md)和[签署准备](2026-10-10-consultation-signing-preparation.md)中的病史人工核对；来源、片段归属和签署冻结仍有效。[独立病历字段](2026-10-14-clinical-document-fields.md)的分类和原件不可变约束继续适用。

## Alternatives considered

- 只隐藏按钮：后端仍留下 pending 与签署门禁，无法直接记录。
- 自动替换人工正文：会覆盖医生已保存内容；保留人工原文并追加患者更正。
- 遇到矛盾不记录或任选一方：丢失信息或制造确定结论；保留原陈述和待核实措辞。
- 只在可变任务行保存失败码：恢复会清除错误，无法追查失败阶段；不可变回执只保留有界诊断，不重复保存临床文本。
- 让通用 Provider 依赖病史诊断类型：混入业务规则；通用错误只保留进程内原因，由记录服务选择可持久化的诊断。
- 迁移直接应用旧建议：绕过当前校验、Command 和审计；重新调度持久任务。

## Consequences

后台完成即代表草稿更新，无逐条确认状态。页面展示由[移除来源界面决策](2026-10-14-consultation-recording-without-source-ui.md)拥有；后台来源关联仍有效。三方合并保护未保存输入和预填；重叠更新的完整语句保留由[未保存病史合并决策](../bug-fix/2026-10-14-consultation-unsaved-summary-merges.md)拥有。签署期间迟到结果失效，取消后恢复新代次；正式签署及 Agent 高风险提案批准仍沿用原授权。

公开 HTTP 和 file-backed SQLite 覆盖直接写入、五字段分类、多轮来源、人工保护、迁移恢复、去重、失败与签署竞态；核对拒绝后的显式恢复同时验证正文保护和失败回执保持。真实 DSH Provider 的网络替身覆盖引用、目标、字段上限及核对覆盖诊断，验证重启后重试成功仍保留失败回执；后一次 JSON 或形状失败不能沿用前一次校验原因。真实 Web 和原生 DSH 共用组合旅程；React 18/19 ShadowRoot 合同验证正文、无来源入口与无病史勾选框的签署。
