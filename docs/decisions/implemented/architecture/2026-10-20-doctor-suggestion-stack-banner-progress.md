# Agent Note: 医生工作台三栏布局与建议栈

Status: implemented

> 专属断点和窄屏抽屉由[共用卡片工作台](2026-10-30-workspace-card-composition.md)部分替代；七项完诊、质控与建议的数据归属和确定性摘要继续有效，当前布局见[UI 合同](../../../ui/design.md)。

## Problem

独立 Web 的医生工作台此前为"候诊栏 + 病例主区"两栏，Agent 参与没有稳定的位置表达；患者横幅内联的七项完诊状态块在中间列变窄后占用过多纵向空间。规格 [AI 原生医生工作台](../../../spec/2026-10-19-ai-native-doctor-workspace.md) 要求三栏骨架与建议栈，本 Note 记录第一步（独立 Web 面）落地的结构决定。

## Decision

医生工作台改为容器查询驱动的三栏骨架：`>=720px` 容器为 200px 候诊栏 + 病例主区，`>=1080px` 容器追加 280px 建议栈右栏；断点全部由容器查询声明，不使用 JS 测宽。建议栈（完诊未完项、质控开放疑点、医生推荐状态）是 `DoctorWorkspaceLayout` 的可选插槽，窄容器折叠为右下角浮动按钮与右侧抽屉，双挂载（右栏与抽屉同时存在）因此组件禁止声明 DOM id。

患者横幅压缩为两行：身份行保留姓名、性别年龄、过敏、分诊、门诊号、主诉、状态与完诊动作；生命体征与完诊进度合并为同一行，进度为"N / 7 + 未完 k 项"计数摘要。七项逐项状态与状态文字改由建议栈完诊分区承载，不再在横幅内逐项展示。

本决策部分取代[门诊医生完诊清单置于患者信息下方](2026-10-06-doctor-inline-completion-checklist.md)：内联七项状态块由建议栈完诊分区与横幅进度摘要共同承接，其余结论（横幅高度上限、独立滚动、无病例上下文栏）继续有效。建议栈数据全部来自确定性服务查询（Encounter completion、document-quality-control、doctor-recommendations），质控疑点与推荐详情沿用既有浮层入口。

## Alternatives considered

- 保留横幅内七项状态块并压缩尺寸：中间列在 1080px 容器下仅剩约 600px，状态块换行为两行以上，压缩收益有限。
- 建议栈仅窄容器提供抽屉：宽容器下 Agent 参与不可见，违背三栏目标。

## Consequences

建议栈在窄容器下双挂载，TanStack Query 按 key 去重共享网络请求；组件以 aria-label 代替 id 关联。队列列宽合同从 JS 内联样式改为容器查询类，既有断言同步更新。完诊逐项明细从病例区常驻内容变为建议栈内容，窄容器需打开抽屉查看。浏览器合同与 e2e 按新合同重写，横幅头部高度与队列列宽上限继续约束。
