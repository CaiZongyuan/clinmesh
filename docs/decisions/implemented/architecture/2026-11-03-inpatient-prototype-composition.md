# Agent Note: 住院岗位按原型复用结构并保留真实能力边界

Status: implemented

## Problem

住院岗位已有共享 Command 与岗位门禁，但患者头部、阶段卡和药房队列各自组合，行为一致仍可能让结构偏离已确认原型。原型包含床位、药师校对人、厂家批号与部分发药，而当前药房许可投影及单次执行 Command 不提供这些能力；照抄原型会产生虚构事实或必然失败的操作。

## Decision

`inpatient-layout.tsx` 拥有七岗位共用的两行患者上下文、平铺页签适配、办理首行、条目行和队列分组，底层继续复用工作台布局的队列、焦点、操作栏、审阅与滚动机制。住院样式由独立样式表限制在住院容器内；Web 和 DSH Surface 使用同一源码，React 18/19 浏览器合同验证 ShadowRoot 中的结构与交互。当前显示合同见[住院工作台](../../../ui/design.md#住院工作台)。

药房通过现有患者索引和各患者许可的窄查询派生药品执行队列，TanStack Query 继续独占服务端状态。执行单尚未展开的已校对长期药嘱保留只读入口；只有真实执行单允许发药。没有厂家批号时使用本页库存批次序号，并显示真实库存、有效期；不扩宽岗位读取权限，不捏造床位、校对人或部分发药能力。

收费头部与结算使用原资金账本判断方向。无需补交时跳过默认收款表单与未发生的步骤，但原补充预交金通过显式入口保留；原款退款和未知结果恢复保持独立可达，不能因页面简化降低原财务能力。

## Alternatives considered

- 各岗位分别复刻原型：容易再次出现两行头部、条目操作位置及窄宽度行为不一致，也会复制焦点与审阅处理。
- 扩大药房 DTO 并修改单次发药状态机：超出本次界面重排范围，也改变读取权限与业务合同。
- 隐藏没有待收余额的全部资金入口：会失去原预交金与退款恢复能力；默认精简与按需操作应同时保留。

## Consequences

原型决定页面结构，实际查询与 Command 决定事实和可执行动作。药房队列需要按既有许可查询读取药嘱，读取失败须显示重试，不能误报空队列。床位、校对人、厂家批号和部分发药若将来成为正式需求，须由独立合同变更提供，不从当前视觉规格反向推导授权。验收同时覆盖真实岗位入口、资金未知与回执恢复，以及共享结构的 React 18/19 合同。
