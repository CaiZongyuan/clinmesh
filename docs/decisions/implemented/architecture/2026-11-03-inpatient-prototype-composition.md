# Agent Note: 住院七岗位单行头部、步骤化 AI 融合、按状态阅片与有界分页结构

Status: implemented

## Problem

住院流程涉及登记员、病区护士、住院医生、药师、收费员、病案人员与医保办七个岗位。若各岗位纵向堆叠多阶段表单或让住院医生患者头部铺满六行编号、整行进度条与异常明细，会在 1280px 宿主下挤占三分之一正文视口并使患者身份滚出屏幕；若在「手术」与「DRG」双页签重复摆放耗材建议表与脱离步骤的 AI 卡片、把待阅检验／影像全文默认折叠，或为展示队列摘要而对全量历史患者逐行发起详情与核定查询，既增加医生重复点击，又会引发 N+1 查询放大或照抄原型捏造后端未授权字段（如厂家批号、药师部分发药）。

## Decision

以 `inpatient-layout.tsx` 统一七岗位壳层、单行头部、步骤内嵌 AI、按阅读状态展开报告及有界惰性分页，同时严守后端真实权限与 Command 边界，界面与业务合同分别见[临床 UI 设计](../../../ui/design.md)及[住院与手术流程](../../../architecture/inpatient-workflows.md)：

1. **七岗位共用单行患者头部与按需挂载阶段页签**：姓名行统一按“身份 + 状态 + 床位与住院日 + 本岗位主业字段 + 右侧本岗位最要紧项（如医生的紧凑 DRG 余额小条与跟进／AI 用量合一菜单、收费员的补退差额）”排列，病区名与可点击复制的业务编号收进“住院信息”下拉菜单；第二行仅在存在临床提醒、助手待确认项或检验异常计数标签时出现（药师药物过敏安全提示保持常驻，已读空列表明确显示“未记录有效药物过敏”）。业务内容区在固定视口高度内独立滚动；未访问阶段不挂载详情查询，访问后由 Tabs 隐藏保留未提交输入，同页多实例资金表单使用 React `useId` 隔离控件绑定，「更多」菜单中的低频页签（`入科`、`费用`）激活时渲染单个带 `×` 的可关闭临时页签。队列与住院主模型通过受控窄投影补充 `triage`、`referralReason`、`lastBedId`、`departedAt`、`recordNumber` 与 `archivedDrgCode`，消除列表 N+1 详情请求。
2. **手术五步内联 AI 融合与 DRG 页签去重收口**：住院「手术」页签固定按 `① 选型参数 — ② 手术耗材（合并指南参考条与目录预计预留） — ③ 术前核对 — ④ 术中执行 — ⑤ 术后完成` 递进；第 ② 步锁定预留后若返回第 ① 步微调测量参数，保留既有 `inpatient_material_reservation` 记录并仅标黄失配规格行供替换，仅在第 ③ 步显式执行手术 `cancel` 时同事务将关联 `reserved` 预留统一置为 `released`。「DRG」页签移除重复耗材建议表，专注当前已入账与计划推演对比及 4 项分组核对内联解释（无已完成手术时主操作显示 `○ 等手术完成` 中性态，术后在院主操作保存入口见[在院主操作确认](../bug-fix/2026-11-13-inpatient-primary-procedure.md)）。患者头部 AI 用量弹窗支持归档后只读核查本次住院累计调用、Token、费用与未决请求明细。
3. **按阅读状态组织报告与共享开具组件**：住院检查检验复用门诊 `OrderComposerLayout`、`LaboratoryResultTable` 与 `ReportText`（底层仍调住院专属 Command）；待阅检验直接平铺完整结果表、待阅影像直接展示完整印象与结论（放射确认已阅继续绑定当前修订首帧真实显示），已阅报告与单条医嘱执行历史、术后耗材更正等低频内容收敛为紧凑摘要加标准详情弹窗。
4. **药房与医保办每页 10 人有界惰性分页**：住院药房（待发在院页／已发历史页独立页码）与医保办归档核定队列均按每页最多 10 名患者惰性读取本页窄投影与核定状态，不后台预扫全库，计数与空态如实表述“本页”并提供显式翻页与回执跨页定位；药房用本页批次序号加真实效期表达批次，绝不捏造床位、校对人、厂家批号或单次部分发药动作。

## Alternatives considered

- **保留多行常驻头部、默认折叠全部待阅报告或在手术／DRG 双页签双份维护耗材表**：压缩正文首屏高度、迫使医生逐份点开新报告，并造成耗材预留入口混淆。
- **修改第 ① 步参数即自动释放整批预留，或照搬原型在开出院医嘱时自动取消手术／新增服务端“结算后才准交首页”门禁**：前者无故丢失未变器械预留，后者越权改变既有临床 Command 与 Agent 工具合同（首页提交仅在界面层等出院结算后开放即可避免无效退回）。
- **前端分批拉全院所有住院患者详情求全局待发药总数**：读取开销随历史线性增长且无端触发大量非当前查阅患者的临床与审计读取。

## Consequences

住院七岗位在保持窄 DTO 最小权限与既有单条 Command 语义的前提下，实现高密度单行头部、步骤内嵌 AI 与零 N+1 分页浏览；未来若需全局跨页待发计数、厂家批号或部分发药，须先立项扩展后端窄读模型与领域合同，禁止在视图层拼凑假状态。
