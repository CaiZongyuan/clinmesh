# Agent Note: 住院岗位按原型复用结构并保留真实能力边界

Status: implemented

## Problem

住院岗位已有共享 Command 与岗位门禁，但患者头部、阶段卡和药房队列各自组合，行为一致仍可能让结构偏离已确认原型。原型包含床位、药师校对人、厂家批号与部分发药，而当前药房许可投影及单次执行 Command 不提供这些能力；照抄原型会产生虚构事实或必然失败的操作。

## Decision

`inpatient-layout.tsx` 拥有七岗位共用的两行患者上下文、平铺页签适配、办理首行、条目行和队列分组，底层继续复用工作台布局的队列、焦点、操作栏、审阅与滚动机制。住院样式由独立样式表限制在住院容器内；Web 和 DSH Surface 使用同一源码，React 18/19 浏览器合同验证 ShadowRoot 中的结构与交互。当前显示合同见[住院工作台](../../../ui/design.md#住院工作台)。

药房待发页先按现有发药门禁筛选 `admitted` 在院患者，已发页保留完整索引；两个页签各自保存页码，再按各自的同一候选集合分页，每页最多 10 位，只在用户进入该页时读取这些患者许可的药嘱、库存和过敏窄投影；不预取未访问页，也不在后台分批扫描历史详情。药品仍按执行条目排列，待发、已发计数仅覆盖本页，页空不等于全队列清空。发完本页可显式继续下一页并选中下一页首条；全局回执恢复按原患者当前状态选择待发或已发页签，再从该页签同一候选集合定位原患者页；已离院患者进入已发历史，不把全索引页号套入在院候选，也不扫描中间页。TanStack Query 继续独占服务端状态，分页只保存客户端视图状态。执行单尚未展开的已校对长期药嘱保留只读入口；只有真实执行单允许发药。没有厂家批号时使用本页库存批次序号，并显示真实库存、有效期；不扩宽岗位读取权限，不捏造床位、校对人或部分发药能力。

药房选中详情成功后明确展示已知过敏状态：有记录时显示风险标签，已读空列表显示“未记录有效药物过敏”。正在更新或读取失败时显示相应状态，不把未知显示为无过敏；已知风险标签在更新期间保留。

收费头部在未结算时读取当前收退款账，已结算后与财务更正面板共用当前更正账查询；首次结算预览继续保持冻结，不用冻结余额代替后续补退款责任。无需补交时跳过默认收款表单与未发生的步骤，但原补充预交金通过显式入口保留；原款退款、未知结果恢复与按需展开的费用差异核对保持独立可达，不能因页面简化降低原财务能力。

同一资金表单可同时保留在费用与出院两个已访问分区中，各实例用 React `useId` 绑定自己的标签与控件，避免隐藏分区夺走可见表单的标签和焦点。Agent 的字段定位使用稳定语义属性，不依赖实例 ID；两个 React 版本共享同一绑定方式。

住院医生六个页签各自按原型的任务顺序组合正文，不能仅用共用头部、平铺页签和条目样式代替。诊断与报告先提供紧凑事实，编辑诊断、完整报告和新检查申请通过明确入口展开；诊断草稿在收起及页签切换后保留，收起的编辑器不占用当前主操作栏。手术优先展示当前计划和开始所需条件，申请、PCI 选型、耗材预计及整台补录仍有可达入口；每个手术动作的必填说明在该动作的位置填写，不共用一个输入框，术后核查随已完成的手术展示。DRG 以当前病组的支付参考为基准展示已发生收费、未记费医嘱和剩余额度，计划手术作为同一块内的预计行，收费构成由已有正式收费条目按类别归集，不新增服务端字段；核对、材料及跟进操作随后提供，归档冻结、重新审阅、未知结果和重试保持原合同。

原型的静态业务状态不创建新门禁或新写入语义。现有出院 Command 阻止未收口的手术、检查和转科，医生须回到相应环节处理，不会在开出院医嘱时自动取消手术；离院方式由护士办理实际离院时填写。医生病案提交在界面上等出院结算后开放：服务端入科后即接受提交，但病案人员审核要求离院事实，结算前的费用变化也会让已提交修订过期，提前提交只会产生必然退回或过期的修订。这是界面收窄，Command 仍按原条件接受提交；结算后核心字段直接展示，保留主操作选择与原提交能力。PRN 继续是医嘱频次，不能为了复制原型分段控件将其改成第三种时效。

住院检查检验复用门诊开具窗口（`OrderComposerLayout`）与报告显示组件（`LaboratoryResultTable`、`ReportText`），住院列表、开立、已阅、取消和重试仍由住院页面调用住院 Command；共用的是展示和目录选择，不共用门诊准备清单、缴费或病历插入。住院诊断入口只提供国家临床版检索，院内编码仍可由服务端接受并由病案审核拦截，避免界面与审核口径不一。

病案岗位的首屏分组摘要直接读取已有许可的 `drg/pregroup` 投影，未归档读取当前正式诊疗，归档读取冻结结果；不把术后核查的空态当作 DRG 复核，也不在界面重算病组。只有已归档且原接口明确返回缺少冻结结果时，以历史能力缺失状态保留可见说明；未归档异常、权限、资源及网络错误继续按读取失败展示，不把原病案的有效回查与缺少可选分组混为一谈。内部编码系统、版本和来源定位保留在其合同与来源详情，正文以临床代码、名称和已本地化的病情及离院方式表达。已知未收口申请的出院提示与禁用状态只映射现有 Command 的失败边界，服务端仍是最终权威。

状态交接必须跟随已有投影与当前住院身份。已取消申请不阻止报告全部已阅，但读取失败不能沿用缓存宣布完成；医生出院意图与护士实际离院的缺项各按原阶段表达。医保核定将自动初选与显式完成分开，避免“下一份”回到已核定首项；回执只驱动其原住院的下一步。医保头部与主区共享同一窄预览查询，复用已获许可的性别、年龄与住院天数，不额外拓宽患者或病区读取。

医保队列沿既有归档索引按每页最多 10 份读取核定记录，不为分组扫描全部历史或后台预取其他页。核定状态读取有审计成本；未知与失败不能按空记录归为未核定，因此分组只使用本页成功读取的事实，失败保留重试，计数与完成态说明本页。用户显式继续下一页后，待本页读取就绪才一次性固化首份未核定病例，后续刷新不重新推导选择；已全核定的页保留空待办和显式翻页入口。当前已选病例从原索引按身份保留，即使新增归档改变可见页边界也不替换；其主区详情继续按原许可独立读取。初选、下一份与页码均随完整会话身份重置，服务端状态仍只由 TanStack Query 拥有。

同一数值的默认主区只保留一个阅读位置。病案与医保将已有分组、费用和预估组合为四项事实，来源和完整病例按需打开；未知名称和费用保持空值，不用其他投影代替。头部承担身份与摘要，长助手说明与完整检验结果在原入口查阅，避免所有结果和值都占用固定头部；异常与失败仍有明确提示。逐项术前准备将状态、岗位与真实完成时间并排，避免以两句说明代替可核对的条件。

集中发药在上述分页、岗位窄投影及真实能力边界内扩展；共享批次的逐单推进和恢复取舍由[集中发药库存推进决策](2026-11-10-inpatient-dispense-stock-progress.md)拥有。

## Alternatives considered

- 各岗位分别复刻原型：容易再次出现两行头部、条目操作位置及窄宽度行为不一致，也会复制焦点与审阅处理。
- 将所有患者详情分批读完：总读取量仍随全部历史增长，也读取了当前没有查看意图的库存与过敏；不能作为按需读取的替代。
- 扩大药房 DTO 并修改单次发药状态机：超出本次界面重排范围，也改变读取权限与业务合同。
- 隐藏没有待收余额的全部资金入口：会失去原预交金与退款恢复能力；默认精简与按需操作应同时保留。
- 只换统一外框并保留旧页面内的全部常驻表单：仍会把报告、当前手术与分组比较推离首屏，无法满足原型的阅读与操作顺序。
- 照抄原型中的离院方式和自动取消手术：会跨越岗位动作归属，并改变本次明确保留的 Command 合同。
- 在服务端增加"结算后才可提交病案"门禁：能消除无效提交，但改变已有 Command 合同和 Agent 工具行为；界面收窄已满足用户需求。
- 住院另写一套检查开具窗口和报告显示：与门诊同一检验、影像合同下出现两套操作和展示，后续变更需改两处。

## Consequences

原型决定页面结构，实际查询与 Command 决定事实和可执行动作。药房索引没有药品摘要，因此本页之外的待发与已发数量保持未知；需要全局药品计数或全局条件筛选时，应先有对应的窄读合同。当前页读取失败须显示重试，不能误报空队列。床位、校对人、厂家批号和部分发药若将来成为正式需求，须由独立合同变更提供，不从当前视觉规格反向推导授权。验收同时覆盖真实岗位入口、资金未知与回执恢复，以及共享结构的 React 18/19 合同；医生六个页签分别验证正文顺序、次级操作可达和真实门禁，七岗位默认页的外框矩阵不能替代页内覆盖。
