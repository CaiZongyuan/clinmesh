# Agent Note: 受审计专病风险结构化记录与确定性临床算子内核

Status: implemented

## Problem

心内与慢病专病决策（肾功能剂量调整、造影剂水化评估、ACS 危险分层、双抗出血风险评估与血脂目标分层）依赖可复现的量化生理与风险指标（eGFR、CrCl、GRACE、TIMI、PRECISE-DAPT、ASCVD/LDL-C 目标值）。若由大语言模型心算公式、允许只读请求由调用方手填未入库指标，或在缺少血肌酐、体重、肌钙蛋白、心电图及床旁风险史时以“默认正常/默认阴性”兜底凑分，会产生不可追溯的数值偏差并掩盖真实临床缺项。同时，院内同时存在 WS/T 886-2026 国内单位（如肌酐 `umol/L`、血红蛋白 `g/L`、血脂 `mmol/L`）与 Synthea/PCI 参考数据美制单位（`mg/dL`、`g/dL`），算子必须显式校验单位而非裸读数值。

## Decision

1. **床旁专病风险与住院体征独立受审计记录，严守“未记录不等于阴性”**：将床旁危险因素与住院护理生命体征建模为显式受审计修订命令，未填写项保持 `null`（“未记录”）；ST 段偏移按时间升序严格锁定本次接诊或入院首份有效 12 导联心电图报告（不再向后续动态复查心电图顺延，避免住院期间继发心电改变污染首诊 GRACE／TIMI 基线分层），首份报告未给出明确 ST 段结论或尚未出报告时回退至床旁确认，均无记录则保持 `null`。当前数据结构与操作合同归属[临床业务流程](../../../architecture/clinical-workflows.md)。
2. **零平台依赖纯函数算子与严格客观取数门禁**：六项临床算子作为无 I/O 纯函数放在 `@clinmesh/core/clinical-scores`，强制执行双轨单位换算与生理极值拒绝；服务端只读查询拒绝外部覆盖参数，仅从当前就诊或住院已确认客观记录抽取输入，缺项一律返回 `status: 'incomplete'` 与精确 `missingInputs`。

## Alternatives considered

- **允许在评分 GET/POST 查询中传入临时指标试算**：调用方或 Agent 极易把未落库的猜测值当作正式患者评分写进病历或医嘱依据，破坏临床审计链，因此拒绝在患者评分接口开放任意参数覆盖。
- **缺项时按正常参考值或阴性病史默认补齐**：例如未查肌钙蛋白按阴性、未问吸烟或出血史按无处理，会系统性低估 GRACE、TIMI、PRECISE-DAPT 与一级预防风险，违反医疗安全边界。
- **新增非标准 FHIR `RiskAssessment` 资源类型**：当前 ClinMesh FHIR R5 能力集仅声明实际实现的资源与检索参数，复用已支持的 `Observation`、`DiagnosticReport` 与不可变 `Provenance` 即可完整表达测量、评估修订链与审计溯源，无需扩大未实现全量检索承诺的 FHIR 资源面。

## Consequences

- 门诊诊断页与住院诊疗页通过按需展开的折叠披露块（`<details>`）呈现专病风险评估表单与六项临床算子徽标摘要，不改变默认主屏布局，也不会在未展开时触发额外请求。
- 体征、风险评估、检验更正或首份心电图报告落库后，重新读取临床算子即时反映受审计客观记录及其资源版本号（GRACE／TIMI／PRECISE-DAPT 锚定首诊或基线客观事实，肾功能与血脂达标评估反映当前有效记录），可供后续通用指南专题与专科医嘱预筛直接复用同一客观快照。
