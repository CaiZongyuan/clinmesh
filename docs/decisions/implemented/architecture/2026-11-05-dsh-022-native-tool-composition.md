# Agent Note: DSH 0.2.2 的原生工具装配与问答状态读取

Status: implemented

## Problem

DSH 0.2.2 将工具目录与执行器分开装配，并收窄跨领域读取 Session Projection 内部状态的接口。仅替换版本号会让手工构建的宿主缺少原生工具执行器；继续读取问答领域的内部 `questions` 状态则无法保持类型与生命周期合同。ClinMesh 的连续页面工具交接、真实医生委托和迟到补答必须继续保留原任务身份，不能通过放宽授权或跳过原生执行回归完成升级。

## Decision

ClinMesh 使用上游公开的 `sessionProjections.snapshot(session, ['userQuestions'])` 读取用户问答的客户端视图，只在原问题仍为 `continued` 且任务和调用标识都匹配时接续已有委托。问答领域继续拥有投影注册、持久化与恢复，ClinMesh 不注册或维护第二份问答状态。

原生宿主沿用官方组合包中的工具执行器。独立装配 Cordis 的合同测试显式安装并启用 `@deepseek-ai/dsh-tool-executor-native`，使测试实际执行页面工具，而不是仅声明工具 schema。当前页面目录读取继续使用公开的 `tools.get` 与 `tools.schemas`；每步条件工具的执行准入和释放由上游执行器及桥接组件持有，不能把旧步骤的准入快照当成新页面的目录。

DSH、React Surface、AG-UI 与 ClinMesh adapter 的宿主依赖按同一精确候选版本验证。Node.js 最低要求随宿主提高到 24.9，仓库安装入口与容器基础镜像保持一致。具体版本、来源和支持提交由根上游锁拥有，安装与隔离运行步骤由[部署指南](../../../deployment.md#dsh-web-原生入口)拥有。

## Alternatives considered

- 只升级 DSH CLI，保留旧桥接 peer：无法证明工具调度、投影读取和配置热重载兼容，且会被候选验证明确拒绝。
- 对弃用的 `stateOf` 结果添加类型断言：继续耦合其他领域的内部状态，并掩盖公开视图与内部状态的结构差异。
- 在 ClinMesh 维护一份问答状态或读取原始日志：重复上游的折叠、恢复和清理职责；公开快照已提供所需状态。
- 删除原生工具执行断言或放宽授权检查：会让工具缺失表现为测试通过，无法保证病例隔离、人工确认和至多一次业务执行。

## Consequences

手工构建宿主的测试需要显式声明执行器依赖；日常 Profile 继续由官方组合包提供默认装配。桥接组件必须跟随宿主接口升级，验证不修改官方宿主源码，也不依赖全局 Profile。合成模型和临时数据库的原生旅程验证连续工具交接、草稿保存、人工确认、业务回执与审计，真实模型质量不由这些合同测试推断。
