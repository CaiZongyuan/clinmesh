# Agent Note: 病案首页绑定实际来源与不可变归档

Status: implemented

## Problem

患者身份可被后续就诊复用，报告更正和同净额冲正不一定改变Encounter版本；仅保存一个“审核通过”状态会让旧审核批准变化后的事实。首页若从当前Patient、申请或活动目录即时拼装，则不能证明归档时采用的身份、实际操作与编码来源。

## Decision

首页通过一次来源采集同时计算四组快照与canonical JSON指纹，独立修订冻结医生的显式主操作选择；编码审核绑定当前修订与指纹，归档重查完整来源后保存最终不可变快照。来源包含资源版本、实际操作材料、完整报告修订链与费用正反明细；首页工作流、当前查询时间和当前启用目录不进入指纹，避免审核自身使来源失效。当前合同由[病案首页与归档](../../../architecture/clinical-workflows.md#病案首页与归档)拥有。

医生纠正出区后遗漏或备用诊断继续使用正式诊断owner，窄开放到清床后未归档窗口；编码人员不另造诊断或覆盖临床判断。审核按原Release核验固定临床版完整身份，不用活动Release替换历史来源。患者级病案号独立持久生成，各次住院号和住院次数按本次事实固定。归档冻结本次快照，不全局冻结共享Patient。

只读保护放在真实写Command、执行计划及临床申请Kernel回调，包括无新增费用的报告更正。CommandExecutor先重放已完成receipt，再进行当前状态授权；新意图守归档锁，原意图无写重放。报告确认先核临床责任再检查归档，越权请求保持相同权限错误，系统执行回调仍使用内部归档锁。归档读取和页面必需的清单、详情、目录（包括护士常驻待接收转科与目标床位目录）使用当前Epoch只读授权，保留岗位科室责任；写入仍要求active Run。归档页面不挂载active临床组件，既有门诊后续结束Scenario也不阻断人类查询。

## Alternatives considered

- 只比较Encounter版本或费用合计：会漏掉报告更正、同额明细替换和零元冲正。
- 首页维护另一套诊断或允许编码员替换正式编码：拆散临床事实owner，出院诊断与Condition可能分叉。
- 归档后继续从当前Patient或目录拼接：后续就诊会改写旧病案的展示事实。
- 全局冻结Patient或放宽所有读取和Grant：跨越共享身份及既有Agent能力生命周期边界。
- 在通用读scope检查归档或在进入Command前拦截：使归档不可查询，或阻断已完成receipt的安全重放。

## Consequences

首页是已声明核心字段集，不是完整国家上报首页、医保清单或DRG输入认证；固定临床版来源与操作有界摘录保留原研究限制。未来解档或病案更正须另设审计流程，不能绕过普通只读门禁。真实HTTP覆盖来源失效、固定来源审核、显式实际主操作、归档与旧receipt；共享Patient升级、Scenario完成及遗留报告写点以明确标注的持久状态fixture验证，真实浏览器覆盖岗位提交、退回、修订、审核、归档和原意图恢复。
