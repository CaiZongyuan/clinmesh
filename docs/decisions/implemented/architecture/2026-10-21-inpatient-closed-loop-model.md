# Agent Note: 住院闭环的分层状态、床位互斥、共享检查手术与不可变病案归档

Status: implemented

## Problem

门诊就诊以单一 `Encounter.status` 表达一次完诊即结束的生命周期，而住院跨越数天并涉及入科分床、跨科转床、医嘱与检查送检、择期／介入手术、待出院、出区、财务结算、清床、召回及病案编码归档等多岗位协作。若将行政、财务与病案状态强压入标准 FHIR `Encounter.status` 或靠 `Encounter.location` 数组推断占床，会破坏 R5 状态枚举并丧失床位原子互斥保证；若为住院复制一套独立 LIS/RIS、用手术申请冒充已实施操作，或从当前可变患者／目录动态拼装归档病案首页，则会导致状态机分叉、未发生操作入账以及历史归档事实随时间漂移。

## Decision

建立分层状态、单写事务床位互斥、OP/IP 共享申请内核、手术双事实分离与四阶出院归档门禁模型，当前业务合同见[住院与手术流程](../../../architecture/inpatient-workflows.md)与[仿真、病例与素材](../../../architecture/simulation.md)，编码与前置依据见[住院病案编码与召回研究](../../../research/2026-10-20-inpatient-record-coding-and-recall.md)及[DRG 条件核验研究](../../../research/2026-10-25-drg-condition-verification.md)：

1. **分层生命周期、床位唯一互斥与场景虚拟时钟计费**：`Encounter.status` 仅维护 FHIR R5 标准取值，住院行政、财务与病案状态在 `InpatientService` 独立领域列与任务中受约束演进。活动床位占用与活动住院分床均由 SQLite 唯一约束保护，转床与双人换床在同一 `CommandExecutor` 事务内同时校验两侧 Encounter 版本并同步更新 `Encounter.location` 历史投影。过夜推进作为非医院岗位的场景控制能力（单步上限 366 天），按 `Asia/Shanghai` 午夜幂等展开床日费与长期医嘱执行计划。
2. **OP/IP 异或申请上下文、护士送检门禁与三方转科交接**：检查申请以门诊 `case_id` XOR 住院 `admission_id` 统一底层 `ClinicalRequestKernel` 与 LIS/RIS 适配器，住院申请开立时冻结本院住院价目，须经病区护士显式校对送检后才允许受理执行，首次报告签发事务记入住院账（报告修订不重复计费）。跨科转科按“原科医生申请 → 原科护士收口交接（停嘱核停、取消未执行计划、收口未送检检查与未实施手术） → 目标护士验空床原子接收”执行，读写权限随当前在院科室与病区动态转移，不锁死在历史开单人上。
3. **手术申请与实际实施分离**：`InpatientSurgery` 以 `ServiceRequest` 表达手术计划，要求护士术前核对与医生知情同意双确认后才允许开始或执行；唯一实际执行生成只读 FHIR R5 `Procedure` 并原子记入术式费与实际耗材费，术后医嘱与病案首页仅引用实际完成的 `Procedure`，绝不以计划或时间到达推定手术已实施。
4. **四阶出院门禁与绑定来源指纹的不可变归档**：严格按“医生出院医嘱 → 护士实际出区（结束 FHIR 床位时段但保留领域占床，结算前支持医生审计召回） → 收费员按逐项费用／冲正／资金指纹财务结算 → 护士清床释放床位 → 病案首页编码审核与归档”顺序推进。病案首页单次采集患者身份、诊断、实际手术耗材、报告修订链与正反费用明细生成规范 JSON 指纹，编码审核按原临床版 Release 核验并绑定当前修订与指纹，归档重验完整来源后写入最终不可变快照；归档锁置于真实写 Command 与内部回调入口（先放行已完成回执无写重放，再拦截新写入），不全局冻结跨就诊共享的 `Patient`。

## Alternatives considered

- **将住院行政状态塞入 `Encounter.status`、靠 `Encounter.location` 判断占床或用单一“出院”聚合命令包办结算清床**：破坏 FHIR 标准状态契约，无法用数据库唯一索引防御并发抢床，且将临床、护理、财务与病案四种岗位责任混为一谈。
- **为住院复制一套独立 LIS/RIS 或伪造影子门诊 `outpatient_case`**：前者使取消、重试与报告修订逻辑双份漂移，后者错误触发门诊收费与完诊规则。
- **依靠真实系统时钟定时器计床日费，或归档后继续动态联表拼接当前 Patient 与目录**：真实时钟无法确定性重放多日住院，动态拼接则会让后续复诊改写已归档病案首页。

## Consequences

住院登记、医嘱、检查、手术、转科、结算与归档共享统一的短事务、预期版本、幂等回执与审计基础设施，同时保持清晰的临床与财务岗位隔离。已归档病案在当前 Epoch 内对授权岗位保持完整只读可查（归档后的受控财务与医保更正通过独立追加链表达，见[住院共享资金与首次冻结账](2026-10-22-inpatient-funding-and-first-settlement.md)）。
