# Agent Note: 连续诊断清单与完整诊断组恢复

Status: implemented

## Problem

多诊断记录需要在一次目录选择中连续核对主次与备注。逐条关闭窗口和只保存有效服务端草稿会丢失未完成输入；丢响应后重新确认可能产生重复修订。[集中办理规格](https://github.com/CaiZongyuan/clinmesh/blob/spec/batch-clinical-actions/docs/spec/2026-11-09-batch-clinical-actions.md)同时要求连续添加、唯一主诊断和完整组原子性。

## Decision

页面拥有唯一诊断草稿，目录弹窗连续加入并回看同一清单。未加入的新行与各个稳定条目 key 的待保存编辑分槽持久保存，切换编辑目标不覆盖其他输入；移除或消费条目时清理对应编辑槽。新增后重置备注并按最新清单决定默认主次；显式改主让原主让位，删除主诊断晋升首条。已确认组继续通过显式入口整体回到编辑，不把正式事实自动复制为待办。

诊断组复用处方与独立检查的身份隔离私有存储及原意图恢复协议。尚未加入的输入、人工备注和选择在关闭、切页、切患者与刷新后保留；成功只消费原请求仍拥有的行，未知先查原回执，明确不存在才用原载荷原键重放。诊断在一个 Command 事务保存和确认整组；最终所选组必须恰有一个主诊断，不能沿用独立检查的逐项成功语义。当前合同见[临床流程](../../../architecture/clinical-workflows.md#81-门诊闭环)。

## Alternatives considered

- 每项加入后关闭：无法同窗核对整组主次，改为显式完成选择。
- 自动将所选次诊断晋升为主：会改变用户选择意图，改为提交前明确提示缺少主诊断。
- 逐诊断确认与恢复：可能形成半组或多个修订，保留整组事务与一个原回执。
- 普通 refetch 覆盖私稿：会抹掉人工输入；只有显式 Agent 回填成功才清理对应私稿并重挂载，结果未知时连旧动作句柄也禁止新写。

## Consequences

最多八项和唯一主诊断约束不变；待修输入可以保存，正式确认仍严格校验。有待保存的条目编辑时阻止确认旧组，并保持编辑入口可用；目录已明确不可用时在对应行标明原因。存储失败阻止新确认并提示显式清空；退出清理浏览器私稿，保留服务端共享临床事实。HTTP 验证非法诊断或双主整组回滚、原键重放与重启回执；页面及真实岗位旅程覆盖连续添加、备注与主次、刷新隔离和原结果恢复。
