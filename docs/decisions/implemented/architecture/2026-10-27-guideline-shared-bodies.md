# Agent Note: 指南多入口共享正文与独立来源记录

Status: implemented

## Problem

同一指南可经固定包和本地上传进入系统。把每个导入来源都保存为独立全文会重复占用数据库、全文索引、可检索数量及建议输入预算；仅在最终结果去重仍留下重复存储和错误覆盖量。按原件哈希直接合并也不充分：同一个 PDF 可以导入不同节选，版本、定位及实际提取正文仍需核对。来源的许可、范围、停用与导入出处不能因合并正文而丢失。

## Decision

在独立指南库中规范化来源与正文：每个来源 ID 保留元数据、来源摘要和维护限制，格式、原件哈希、版本及完整有序的定位与准确正文共同确定可共享正文。相同内容只存一份正文和索引，来源记录复用它；节选、修订及不同版本独立保存并保留来源关联。正文共享不表示许可互通，也不改变固定包资产及锁定规模。持久化与迁移合同由[存储合同](../../../architecture/storage.md#99-数据库迁移边界)拥有。

检索先逐来源验证用途、完整性与祖先限制，再在分轮、段数和字节预算前按共享正文合并候选；引用选择确定且实际可用的出处，保留原有元数据变化使旧依据失效的规则。撤回原来源停用下游，撤回上传记录只收紧该记录，不反向停用原指南。正文更新只改目标来源关联，其他来源仍引用的内容不回收。

旧 schema 升级在停服备份后的显式准备阶段完成，避免让旧读端在表结构变化中继续执行不兼容查询。只读检查在临时副本升级也不能把正式旧库判为就绪；迁移保留损坏来源的原摘要和不可信状态，正常已核验重导仍能修复，不以升级或共享另一来源的正文掩盖损坏。

## Alternatives considered

- 只删除本机重复库或关闭一个入口：不能处理其他安装、未来院内上传和再次导入，且会丢失来源记录。
- 只在返回结果去重：数据库与 FTS 仍重复保存，统计和检索预算仍可能被重复来源占用。
- 只按原件哈希去重：会合并不同节选、版本或修订正文，无法验证实际采用范围。
- 把整份来源元数据放入正文身份：导入编号、许可、范围说明和 URL 不同就无法复用完全相同的正文。
- 合并来源记录及其限制：会丢失上传出处，可能让另一入口重新启用已停用内容，或让派生记录反向停用原指南。

## Consequences

来源数与独立正文数分别报告，段落覆盖按正文去重；固定包统计保留快照口径，全库统计明确单列。旧数据库升级需要一致备份和短暂停服，旧代码回滚配套恢复旧库；业务和参考资料数据库不受影响。

公共导入、检索、准备及同步回归验证不同导入顺序和幂等、真实物理正文只存一份、节选及版本隔离、来源保留与共享正文回收、停用方向、损坏修复及只读升级边界；公共 HTTP 继续验证生成与核验采用相同去重依据并保护医生草稿。测试使用合成正文与临时数据库，不读取实际指南库或修改固定资产。
