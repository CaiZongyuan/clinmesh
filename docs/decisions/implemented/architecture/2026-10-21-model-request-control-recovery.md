# Agent Note: 双层模型请求准入控制、阶段检查点复用与未知派发恢复

Status: implemented

## Problem

一次逻辑临床模型任务往往跨越筛选、收敛、生成、格式修复、限流重发与独立语义核验多次实际请求；若仅在任务外层计数会漏掉内部重试消耗，若因病历同文保存推进版本号就作废建议、或在后段技术失败时丢弃已成功的前段结果，又会造成大量无谓重复调用。同时，当部署或 Workspace 停用模型、触及有限配额或遇到网络中断／SDK `finish:error` 包装异常时，把控制拒绝标为业务失败会耗尽重试机会丢失待办，而把派发结果未知的请求自动重发则会造成不可控的重复计费。

## Decision

在单 SQLite writer 内统一临床输入精确复用、持久阶段检查点、双层请求准入预占与受控待办恢复，当前合同见[存储与事务](../../../architecture/storage.md)与[安全与可靠性](../../../architecture/security-and-reliability.md)：

1. **内容指纹解耦保存版本与跨阶段持久恢复**：临床建议有效性按规范化结构正文与完整来源内容指纹判定，与纯草稿保存版本号分离，同文保存不触发重复推理；患者问诊回答按待答医生轮次共享唯一持久执行，合并并发 `ask`/`retry`。多阶段建议任务按稳定阶段、批次、内容哈希与依赖关系持久化成功步骤，每次实际派发前原子预占任务请求包络，后段技术失败或人工显式“继续”（通过一次性受信执行单元授权）仅接续未完成步骤而不重跑已成功阶段；显式“重新生成”才采用最新输入、当前模型与新包络。
2. **部署与 Workspace 双层原子准入及非阻塞队列扫描**：部署配置文件与受审计 Workspace 政策共同控制开关、自动重试与请求限额（首次设限建立独立持久累计起点，后续调额、切回无限或重置 Epoch 均不归零；公开状态对普通成员隐藏部署总上限与跨区用量，内部裁决使用完整政策）。每次尝试创建、双层配额预占与任务包络检查在同一 SQLite 短事务内完成，网络派发留在事务外。配额或开关拒绝归入独立控制等待分类，不消耗业务重试次数；Outbox 与 Persona／检验目录扫描器按固定轮次队尾与稳定控制快照越过受限队首，继续推进后续可执行任务与确定性目录发布。
3. **严格区分已知未派发与派发未知，禁止未知结果自动重发**：仅明确未派发的请求释放预占，已知派发转为累计消耗。由于锁定的 DSH SDK 会将底层网络异常包装为 `finish:error`，三类派发入口统一仅将明确鉴权拒绝、限流或非超时 Provider HTTP 错误结算为已知失败；超时、`408`/`504`、断流、缺少有效核算终态帧或结算写库失败一律保留未决派发与次数占用，停止自动重发，仅在人工明确核对或显式授权继续后处理。结构化校验耗尽时透传封闭领域安全码（如 `investigation_output`），绝不落盘原始异常文本或模型输出正文。

## Alternatives considered

- **同文保存不递增草稿版本，或仅在进程内存合并并发问答**：前者破坏签署预览与并发编辑 CAS 语义，后者在故障或重启后仍会重复触发外部推理。
- **从留存明细表实时汇总已用配额，或把控制拒绝当普通技术失败定时重试**：清理旧明细会意外“恢复”配额，定时重试则会烧光业务机会并阻塞同队列其他任务。
- **超时、取消或收到泛化 `finish:error` 后立即释放预占并自动重发**：在缺乏上游生成幂等与状态查询协议的前提下，无法证明远端未执行或未计费，保守挂起是唯一可审计边界。

## Consequences

所有模型生成均以账本可写与准入通过为硬前置，配额停用或耗尽时普通 HIS 读写与确定性业务不受影响，恢复配额后挂起待办自动按原权限与输入有效性续跑，而派发未知请求绝不静默双发。Token、人民币计价与明细保留生命周期由[统一模型调用账本与分维度额度控制](2026-10-21-model-usage-accounting-control.md)协同管理。
