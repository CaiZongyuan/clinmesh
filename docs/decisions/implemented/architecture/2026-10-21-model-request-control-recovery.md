# Agent Note: 双层模型请求准入与控制待办恢复

Status: implemented

## Problem

逐次用量账本覆盖了 Server 直接调用、DSH bridge 和 Host 独立识别，但只记录请求不能阻止后台消耗。一次逻辑任务可能包含格式修复、限流重发和独立核验；在外层计数会漏掉请求，在控制拒绝后标记技术失败又会丢失有效待办。停用、额度恢复与已派发结果未知必须有不同的恢复语义。

## Decision

部署与 Workspace 默认启用、请求额度无限、保留既有有界自动重试。部署政策来自受校验的配置文件，Workspace 管理员通过共享 Command 修改自身政策，以版本、幂等回执和审计保护并发编辑。任何一层停用均拒绝三类入口的新准入；关闭自动重试不阻止正常独立生成或核验阶段。

公开控制状态按当前岗位投影：普通成员只读自身工作区及有效控制状态，隐藏部署总上限和跨工作区累计量。准入使用完整内部政策，不能用公开投影参与配额裁决，避免授权脱敏改变执行约束。

请求尝试创建、双层请求预占、原任务请求包络检查在同一个 SQLite 短事务内完成，外部派发在事务后执行。每层首次设置有限请求额度建立独立累计起点，之后修改额度、切回无限、重启或重置 Epoch 均不重置。请求计数和预占独立于明细保留；明确未派发才释放请求预占，已知派发转为累计消耗，未知派发继续保留预占。监控保留起点以前的真实请求。

控制拒绝使用明确的安全分类。业务待办保存原身份、阶段与成功结果，控制恢复后沿用原并发限制重新核对 Epoch、权限与有效性；扫描按调用开始时的等待快照分页，持续停用的前页不能阻挡后续可恢复任务。技术重试继续受原包络及双层自动重试政策约束。已派发结果未知不因开关恢复、额度增加或账本恢复自动重做。成功的业务阶段由私有恢复记录或原有建议执行单元拥有，临床正文不进入用量账本。

Server 在途请求接入工作区取消信号。Host 独立识别通过原尝试回执查询取消状态，停用时尽力中断同一 stream；控制等待只重试明确未派发的准入，原许可与期限继续约束等待。短存活租约让 Server 显示仍在线的 Host 待办，而不创建虚假模型尝试或第二套派发队列。网络失联、未知准入或结果未知均不能推断为未消耗。

## Alternatives considered

- 只在逻辑任务开始时检查：无法覆盖任务内部重试与恢复，也无法在并发任务争用最后一个额度时原子裁决。
- 从当前明细实时计算累计额度：清理明细会恢复额度，历史请求与首次设限后的消费也难以分开；采用独立持久计数和每尝试预占。
- 把控制拒绝当作技术失败并定时重试：会消耗业务重试机会，最终丢失待办；控制等待独立于技术失败。
- 控制恢复时重建整个任务：可能重复已成功的生成、选择或核验步骤；复用有效成功阶段，只接续待办。
- 取消或超时后释放所有预占：无法证明服务商未派发或未收费；未知占用保留到可信结算。

## Consequences

模型生成依赖账本可写性；即使额度无限，记账失败仍暂停新派发。停用不影响普通 HIS 读写或确定性检查，取消也不保证服务商停止计费。部署仍为单 Server/SQLite writer，Host 不保存第二份余额。Token、人民币计价与人工核对由[计价控制决策](2026-10-21-model-usage-pricing-control.md)拥有；明细清理由[正式规格](../../../spec/2026-10-19-model-usage-control.md)的后续切片拥有。

验证使用公开 HTTP、临时 SQLite、少量带屏障的合成请求和三类实际派发边界，管理界面使用 Web 持久化旅程及 DSH React 18/19 合同；不运行真实模型或压测。当前接口与持久化事实分别由[安全合同](../../../architecture/security-and-reliability.md#模型用量查询)和[存储合同](../../../architecture/storage.md#910-模型调用账本)拥有。
