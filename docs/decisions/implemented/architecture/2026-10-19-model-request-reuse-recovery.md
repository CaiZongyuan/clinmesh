# Agent Note: 临床输入复用与模型任务持久恢复

Status: implemented

## Problem

病历保存版本同时被当作建议有效性依据，造成临床内容未变也重算。患者回答的写入幂等位于推理之后，重叠请求仍会各自生成。建议任务只有最终结果持久化，后段技术失败会重做成功前段；Provider 格式修复、限流重发和 outbox 重试各自拥有继续额度，无法表达同一任务的累计派发边界。[固定基线审计](../../../research/2026-10-19-agent-model-call-lifecycle.md#七三个风险的离线动态复现)保存风险证据，[正式规格](../../../spec/2026-10-19-model-request-reuse-recovery.md)拥有需求和验收。

## Decision

临床输入有效性与保存版本分离，同时规范化模型输入中的草稿证据标签。复用依据结构化正文和完整来源的精确内容；同文保存继续推进真实版本、审计和并发保护。旧成功快照只有原始归属与规范化内容均可验证时才复用，避免指纹升级既引发无谓重算，又错误接受不同输入。

患者回答以待回答医生轮次拥有执行，持久尝试和意图关联配合进程内共享，使重叠 ask/retry 等待同一生成。相同意图的失败或未知保持终态；新 retry 只有在原尝试终止后才采用当前模型，在途加入仍保留原模型与截止时间。已接受问题不随请求断开取消，runtime 关闭主动收束，重启遗留执行为未知。已保存回答优先恢复，各调用者的授权、输入冲突与回执仍各自完成。

建议按稳定阶段、批次、内容哈希和依赖持久保存私有成功步骤。每次实际模型派发前原子预占共享次数，覆盖 Provider 内部重发、修复、业务恢复和人工继续；outbox attempt 不拥有独立模型额度。正常分批各有首次请求，单元上限和 generation 额外请求上限共同限制继续，无法靠重建计划或改批次重新取得首次额度。成功候选只用于恢复，全部必要核验完成后才发布；合法核验否定正常结束。

请求派发后没有完整结果，以及预占后无法证明是否派发的崩溃窗口，都按未知保留次数。当前外部接口缺少结果查询和生成幂等协议，自动重发未知请求会掩盖重复消耗，因此只有人工明确继续才再次开放未完成单元。继续保留原模型、generation、成功步骤及剩余额度；重新生成才采用当前输入、当前模型和新额度。相同继续意图重放不重复开放，普通自动请求也不借失败新建代次。

完整筛选请求、受信作用域、模型与策略相同的成功步骤继续精确复用，可跨建议类型与人工新代次；生成及核验不跨任务共享。这保留既有记录级筛选收益，不引入语义相似缓存或截断完整临床证据。当前行为和存储分别由[临床业务流程](../../../architecture/clinical-workflows.md#81-门诊闭环)与[存储合同](../../../architecture/storage.md#模型执行恢复)拥有。

本决定部分取代[人工重试模型选择](../bug-fix/2026-10-07-generation-retry-current-model.md)中的问诊恢复边界，以及[建议记录级筛选与有限恢复](../bug-fix/2026-10-16-recommendation-record-selection.md)中的分层重试额度和整任务恢复方式。前者继续拥有检验新人工尝试采用当前模型的取舍；后者继续拥有记录句柄、输入完整性、DSH 安全限流协议与截止时间。原模型绑定和人工新意图采用当前模型的理由保持有效。

## Alternatives considered

- 同文保存不产生新版本：能减少版本驱动失效，却改变签署预览、并发编辑与保存追踪；在建议输入边界处理复用可保留保存语义。
- 只增加进程内共享：能合并同时运行的回答，无法阻止失败或重启后的同键重复推理。
- 只调低 outbox 尝试数：不覆盖 Provider 内部真实派发，也不能保留已经成功的生成和核验批次。
- 整个任务固定很小的总请求数：不同病例正常筛选和核验批次不同，会将正常分批误判为重试；稳定计划的首次与额外请求分别计数。
- 未知请求自动重发：恢复更主动，但无法确认远端是否执行；保守占用与人工继续让恢复意图可辨认。
- 失败后只允许重新生成：入口更少，却丢弃可用成功步骤；两种人工操作分别表达继续与重新开始。
- 对外承诺推理恰好一次：本地 claim 无法消除远端完成与本地保存之间的窗口，需要供应商幂等和结果查询协议才可重新评估。

## Consequences

同文保存和后段失败不再要求重做已有有效工作；故障时保留成功步骤与真实请求占用，恢复状态因此更细。未知不是远端未执行的证明，取消也不能证明零消耗。次数只约束 ClinMesh 可观察派发，不提供 Token、金额、宿主内部重试或原生会话用量账本；全局控制仍归[模型用量控制草案](../../../spec/2026-10-19-model-usage-control.md)。

稳定计划、依赖和策略版本是恢复身份的一部分。变更分组或指纹策略必须保留兼容校验；损坏或缺少执行证据的数据不能当成未派发。验证采用临时数据库、合成 Provider、受控传输和调度屏障，覆盖真实派发、关停、重启、回放及页面自动请求，不以真实模型压测替代恢复合同。
