# Agent Note: 出区、结算与清床分别拥有事实

Status: implemented

## Problem

实际离开病区、费用结清和床单位释放发生于不同岗位和时间。仅修改 Encounter.status 或在结算时释放床位，既不能表达召回窗口，也会把退款、床日费与床位重用混为同一动作。费用可在 Encounter版本不变时增加或冲正，单看版本或合计不足以证明收费员确认的是当前账目。

## Decision

InpatientDischarge 在既有 Command事务中拥有医生出院医嘱、护士出区、财务结算、清床和医生召回；医嘱、手术与其他在途事项仍由原 owner 提供门禁，不复制其状态机。实际出区结束 FHIR床位period，领域占床保留到清床。召回与结算竞争同一 Admission状态和财务 CAS，追加关联原出区的逆向事件及新的床位period，不删除历史或恢复医嘱。当前行为由[住院流程](../../../architecture/clinical-workflows.md#住院出院与结算)拥有。

预览在一致读事务计算排序后的逐项费用、冲正关系、原入金、补退交易、资源版本与金额指纹。提交在 Command的写事务重新计算并核对原指纹及预期金额；零元冲正也改变明细身份。Web通过显式查询固定已展示的预览，结果未知沿用原幂等键和完整输入恢复receipt，不自动替换为新金额。结算快照和补退交易append-only，退款外键关联原预交金，零差额不造零元资金。共享 InpatientBilling在新增费用前拒绝已结算账户。

## Alternatives considered

- 出院时自动结算与清床：跨越护士、收费员职责，无法保留原床或表达多退少补失败。
- 仅检查Encounter版本或净额：时钟计费不必改变Encounter，等额明细变化也会漏检。
- 退款直接覆盖原预交金：失去原入金及反向资金之间的追溯关系。
- 召回删除原出区：改写实际经过，病案过程和审计无法区分未出区与出区后返回。

## Consequences

待出院仍允许申请停嘱与核停收口；其他医嘱动作保持在院限制。出区事实的离院方式由病案读取，不由首页另行覆盖。收费员查询和回执仅包含财务字段。真实HTTP和SQLite覆盖补退、零差额、等净额明细冲正、状态竞争、失败整事务回滚；真实Web验证冻结预览与刷新后原receipt恢复。归档和支付平台对账不属于结算动作。
