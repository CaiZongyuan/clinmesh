# Agent Note: 门诊病历统一来源直接整理、句子编号溯源与草稿修订保护

Status: implemented

## Problem

门诊接诊期间，患者自由问诊回答、医生在助手聊天的查体／处置补充以及新签发的检查检验报告持续产生病历信息。若依赖右侧主会话手工调用填写工具或浏览器保持打开，无法保证每条已保存来源可靠入账；若整篇重写病历会覆盖医生手改内容；若让模型逐字抄写长句引文、每片段同步串行等待第二次语义核对模型或套用专用 6 秒短超时，会引发引文标点漂移、排队高延迟与正常请求被提前中断；若要求医生在表单内外逐条点击“应用／确认／撤销”建议或手动点击“保存草稿”，又会把系统持久化步骤变成高频操作负担。同时，已确认的门诊诊断在获得新检验结果后仍需支持不可覆盖的二次修订。

## Decision

建立统一持久来源、句子编号增量直接写入、签署准备冻结与临床草稿自动保存体系，当前完整合同见[门诊业务流程](../../../architecture/outpatient-workflows.md)：

1. **三类统一来源、十／十二字段边界与 `sentence-references-v1` 协议**：将患者问诊回答、经宿主原生 inbox 钩子签名核实的医生聊天补充（按 Session + RPC 防重，不混入患者对话）及固定版本正式报告统一为病例级持久整理来源。覆盖主诉、现病史、既往史、家族史、过敏史（可选文本，不冒充正式 `AllergyIntolerance`）、按场景动态必填的月经史／孕产史（见[按就诊场景决定病史必填](../feature/2026-11-09-contextual-clinical-history.md)）及仅接受明确医生来源的体格检查、初步评估、处置计划与随访要求。不可变批次快照（上限 `256 KiB`，序列化模型请求含提示词与格式修复上限 `128 KiB`）按共享完整句界生成带快照哈希前缀的短句子编号，模型仅输出总结事实与最多 12 个 `sourceIds`（未变事实以 `retainedFactIndexes` 保留），服务端确定性还原逐字引文（保留含自述的混合问句，拒绝纯提问充当事实）并按单候选隔离超长或越界错误，竞争同一替换目标的候选整组拒绝。
2. **直接写入草稿、人工片段保护与安静控制恢复**：通过确定性校验的增量经共享 Command 直接写入 `clinical_document_draft`，仅定向替换仍归 `automatic` 所有的有效 UTF-16 片段锚点；人工编辑过的片段永久归属 `manual`，后续患者更正或矛盾只追加带待核实措辞的说明，绝不覆盖人工正文或未保存输入，前端仅展示正文、变动提醒与按需展开的未完成说明，移除逐条应用、核对、撤销与前台来源弹窗（后台来源链与拒绝历史完整保留，写入后来源语义检查统一归入[病历质控](2026-10-19-recording-quality-consolidation.md)）。整理与补录沿用常规 `CLINMESH_AI_TIMEOUT_MS` 模型预算与独立后台槽位（移除专用 6 秒短截止），Command 提交后通过最长 10 秒的有界 revision 长轮询加速前端刷新；支持接诊后受审计 `pause`、`resume`、`backfill` 与 `retry`，推进任务代次并在上下文失效时主动取消在途模型请求。
3. **签署准备代次冻结与取消恢复**：结构化病历的 `preview-sign`、`sign` 与 `cancel-sign` 由共享 Command 执行。生成签署预览在同一事务固定文书正文与问诊来源计数快照，同时推进未完成整理任务代次以冻结后台写入；预览期间任何新来源或草稿变化均使快照失效，关闭弹窗或过期后调用受审计 `cancel-sign` 释放预览并按原暂停／待办状态恢复队列，正式签署生成不可变 FHIR R5 `Composition`、自包含 `Bundle` 与 `Provenance`（线性 `replaces` 修订链）。
4. **800 ms 临床草稿自动保存与诊断不可覆盖修订**：诊断、检查与处方编辑器在有效内容静止 800 ms 后经既有 CAS Command 自动保存（保存中或有未同步本地改动时锁定终结提交，`awaiting-doctor` 接诊前保持只读）；显式草稿保存由持久 Command Effect 标识，避免清空字段被分诊预填回写。门诊已确认诊断在完诊前允许重开草稿并再次确认，递增 `revision_number` 与 `supersedes_confirmation_id`，将旧 `Condition` 标为 `entered-in-error` 并保持 `Encounter.diagnosis` 仅指向最新确认版本。

## Alternatives considered

- **每次重写整篇病历或整字段锁定人工编辑**：前者无法保护医生局部手改，后者在修改一句现病史后阻断同字段后续问诊补充。
- **保留模型逐字复述原句、同步串行语义核对或专用 6 秒超时**：复述放大输出体积与标点错误，串行双模型调用倍增每轮等待，6 秒硬截断则把正常模型响应制造成批量漏记失败。
- **维持字段内待采纳建议卡片、手动“保存草稿”按钮或直接覆盖／删除已确认诊断**：增加非临床点击负担，覆盖旧诊断则会抹除既往临床判断与 FHIR Provenance 责任链。
- **使用 SSE 推送整理进度**：DSH 同源代理会缓冲流式正文，10 秒有界 JSON revision 轮询可在双端代理下保持一致时效。

## Consequences

问诊与医生补充可在后台低干扰地直接汇入结构化病历草稿，正常批次仅需一次整理模型调用（在固定合成多轮病例中输出字节减少约 34.3%），人工编辑、未保存输入与已签不可变文书均受服务端代次与锚点严格保护。句子编号合法仅证明原文位置归属，语义忠实性仍由统一病历质控辅助提示并由接诊医生在签署前最终把关。
