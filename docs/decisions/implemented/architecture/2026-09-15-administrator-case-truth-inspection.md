# Agent Note: 管理员病例真值核对

Status: implemented

## Problem

管理员需要核对合成患者的开场表现、本次疾病和来源证据。Patient Brief 有意隐藏尚未发现的诊断，Visible Source History 只包含本次就诊前的可见历史，因此这两类临床材料无法承担病例真值核对。将真值混入其中会使普通临床读取路径泄露答案。

## Decision

在管理员模拟数据患者详情中增加独立的只读真值区域，位于患者梗概之后，默认折叠并按需加载。它复用不可变 Case Truth repository 和 R4 结构化展示，不创建第二份病例数据，也不把外部来源转换为本院诊疗事实。诊断、本次就诊和相关记录分区展示；只有明确关联 Index Encounter 或被该就诊 diagnosis 引用的 Condition 进入本次诊断，引用闭包中的其他诊断归入相关记录；来源没有诊断时明确说明，不从用药或检验推断疾病。

服务端在读取前检查受信管理员岗位，并按会话 Workspace 查询。真值响应使用独立 DTO 与禁止 HTTP 缓存的专用管理员路由，不扩展普通病例、历史、FHIR、CLI、Page Context 或 Agent Tools 的返回字段。患者切换重新折叠，正文收起后卸载；角色切换和退出沿用应用既有 Query cache 清理。

该决策在[来源病例与跨 Epoch 重放](2026-08-30-synthea-case-source-and-replay.md)的私有事实边界上增加管理员核对例外，普通临床参与者的可见性和真值持久化 owner 不变。接口与错误合同由[系统架构](../../../../docs/architecture.md)拥有。

## Alternatives considered

- 把真值合并进来源历史：减少一个读取入口，但破坏临床可见历史的含义和现有逐项授权边界。
- 只在前端隐藏管理员区域：界面不可见不能阻止非管理员直接调用接口。
- 默认读取或展示真值：打开患者即暴露答案，并增加无须核对时的查询和渲染开销。

## Consequences

管理员可直接核对冻结来源证据，临床工作台仍通过问诊和检查获取本次事实。R4 展示层处理原始字段与缺失值，原始 JSON 保留为折叠的核对入口。HTTP 测试覆盖管理员读取、非管理员拒绝、未登录拒绝、缺失病例及工作区隔离；页面测试覆盖按需加载、嵌套记录折叠和患者切换。管理员真值没有 Agent operation，因此新增入口不会扩大现有 CLI Grant 的能力。
