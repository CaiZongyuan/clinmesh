# Agent Note: 病历界面隐藏待补充提示与依据入口

Status: implemented

## Problem

病历字段持续显示“评估/处置/随访尚未记录”等待补充提示，即使不阻止保存，也会给正常问诊增加重复提醒。“查看依据”又在每条问题旁增加操作入口，与医生要求自动写入、发现错误后直接修改正文的使用方式不符。

本决策取代[仅提示与直接编辑决策](2026-10-18-advisory-quality-without-confirmation.md)中保留可选依据入口的取舍，并收窄[原质控决策](2026-10-15-doctor-document-quality-control.md)的界面展示范围。当前验收合同由[质控规格](../../../../docs/spec/2026-10-15-doctor-document-quality-control.md)拥有。

## Decision

Web 与 DSH 共享界面不展示任何 `needs-completion` 问题，覆盖全部十字段、旧处理记录和签署前汇总；缺少持续时间、模板空字段及已知事实遗漏只要属于此分类，都不生成用户提示。具体事实矛盾及 Agent 来源疑点仍作为辅助核实信息显示。

质控问题不提供“查看依据”按钮，也不渲染展开面板、规则链接或来源引文。医生通过现有问诊、报告与正文入口查看资料，直接编辑病历，无需逐条确认或核实保留。

此次调整属于界面展示边界：后台检查结果、来源证据、公开接口与审计仍保留。检查状态保持真实，隐藏提示不表示全部内容已经核实；保存和正式签署继续沿用既有合同。

## Alternatives considered

- 只隐藏“待补充”标签：正文仍重复显示尚未记录的提醒，不能解决干扰。
- 只删除字段提示：签署汇总和旧处理记录仍会重新暴露同类提醒，造成入口间不一致。
- 保留可选依据或折叠入口：仍给每条问题增加用户已明确要求删除的界面操作。
- 删除后台质量检查与来源数据：超出本次展示调整，并会破坏既有公开协议与审计兼容。

## Consequences

空字段不会因质控额外提醒医生补充；医生仍按本次就诊实际情况记录。无提示不能作为病历完整或临床质量通过的结论。

回归覆盖全部字段及旧记录中的待补充提示隐藏、签署汇总一致性、无依据入口，以及仍可直接编辑和签署。React 18/19 ShadowRoot 合同保留双语、窄分屏、字号、输入焦点和迟到响应验证。
