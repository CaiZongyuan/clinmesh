# Agent Note: 手术计划单次耗材预计与持久工作稿

Status: implemented

## Problem

医生保存冠脉造影／PCI 计划后需要一份可修改、可恢复的预计清单，并在审阅后一次确认预留。既有耗材分析依赖主动开启的持续住院跟进；直接复用该开关会扩大授权生命周期。页面触发生成会因刷新或重挂载重复派发，本地表单也无法保留跨会话手改内容。逐项预留请求在中途失败时留下半份清单，难以证明医生实际确认了哪次修订。

本决策实现[住院 AI 辅助规格](../../../spec/2026-10-28-inpatient-ai-assistance.md)中的 P2；固定患者准备、最终实际用量统一处理与三类分组核对继续由[原提案](../../proposed/architecture/2026-10-28-inpatient-ai-preparation.md)各自范围负责。当前合同归[临床流程](../../../architecture/clinical-workflows.md#手术计划的单次耗材预计)。

## Decision

保存受支持手术计划的 Command 原子写入一次预计意图。意图保存原受信 context、原授权操作、计划身份、版本和正式依据快照；自动意图绑定手术申请，显式补建／重新预计绑定预计请求，后台按该原始操作核验授权；保存、取消与确认分别校验本次窄操作。完整后复用既有持久分析队列、生成／独立核验、Accounting Guard、实际请求用量账及未知恢复。缺项保留自动待办，查询只读取。历史计划由医生显式补建；单次预计与主动持续跟进拥有独立生命周期，派发和发布都重新核对原授权及当前正式依据。

模型分析与医生工作稿分别持久保存。首次有效结果只初始化尚不存在的稿；之后重新预计产生候选差异，显式保存才采用。工作稿以预计版本、稿件修订和依据指纹校验并发，允许医生使用已核验候选人工准备。本地已有未保存编辑时，服务端新修订不能自动替换输入或静默推进其预期修订；页面展示最新保存内容，由医生明确核对后继续保存。新分析也不能让旧生成关联阻断后续编辑；明确核对后保留材料和说明为人工稿，移除过期生成关联。查询始终使用当前受信读者的权限，非医生读取持久快照，原意图身份仅用于续跑和失效判定，避免转科后仍依赖原医生的患者权限。当前依据、目录身份、单位、价格与独立数量范围由确定性规则核验；模型结论不能替代缺失的临床资料或扩大有限合成证据。

确认以同一 Command 事务调用共享的整批预留替代模块，明确核对同计划全部未消耗原预留、计划及 Encounter 版本，原子释放旧项、创建新项、冻结目录快照并记录所确认稿件修订。独立手工整批入口复用该模块。确认关系与预留共提交或共回滚，既有 Command receipt 继续恢复原意图；实际用料和正式收费仍沿原手术 Command。

## Alternatives considered

| 方案 | 未采用的原因 |
| --- | --- |
| 保存计划时隐式开启持续跟进 | 一次准备会获得长期后台生命周期，混淆用户动作和授权边界。 |
| 页面挂载时生成，工作稿仅留浏览器 | 刷新与多端无法可靠区分重试和新意图，也无法避免晚到结果覆盖手改。 |
| 将最新模型结果直接作为可变工作稿 | 重新生成会静默改写医生已审阅内容，确认难以绑定明确修订。 |
| 本地编辑自动跟随最新稿件修订保存 | 首次生成或其他会话保存后，会绕过医生对新内容的核对，可能覆盖尚未审阅的修改。 |
| 循环调用单项预留 Command | 请求之间没有整体事务，无法在中途失败后恢复完整原清单。 |
| 为单次预计另建模型派发与计量账 | 重复未知恢复和用量控制，容易绕过既有记账门禁或重复计量。 |

## Consequences

自动预计无需持续跟进，服务端恢复也不依赖页面生命周期。并发编辑或依据变化会显式冲突，医生需重新审阅；旧模型结果与人工稿继续可追溯。未知请求必须核查原尝试，模型缺失或失败仍允许正常手术及符合当前依据的人工准备。

整批确认能够保证全有或全无，并冻结历史目录依据；同稿修订重复确认明确拒绝。该事务要求显式完整旧集合，已有部分实际消耗转入原用量工作流，避免把预留替代解释为实际使用更正。预留仍只进入推演，不锁库存或提前产生费用。

造影新增独立有限合成依据，PCI 保留原有限证据范围。受控 Provider 与临时数据库回归分别覆盖自动单次派发、无跟进、工作稿恢复与晚到保护、整批故障回滚、版本／授权／目录失效及未知恢复；这些证据证明产品接线与事务语义，不扩大为真实模型质量或真实临床适用性结论。
