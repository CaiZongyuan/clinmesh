# Agent Note: 术后核查的事实复查与责任交接

Status: implemented

## Problem

术后计划与实际差异、临床记录和费用疑点需要对应岗位处理。模型解释或关闭提示不能证明正式业务已更正；同一次住院又可能完成多次手术，切换当前计划不能使此前问题消失。后台权限结束后仍需保留结果与未解决责任，而不能为了交接延长旧权限。

## Decision

核查以每个已完成手术为边界，按人工术前计划引用的选型确认身份和版本定位原申请。计划、实际使用、更正历史、正式收费净额及阶段分组继续来自原 owner；核查只保存不可编辑的依据快照、问题和岗位处置。问题 key 包含实际手术身份，相同依据不重复；只有对原问题的最新业务事实复查证明消除，才能标为已解决，来源再次成立则重新打开。人工无需处理必须保留岗位和理由。

模型解释消费确定性核查的问题及引用，沿既有任务、生成与独立核验步骤和用量 owner 执行。处置状态不进入模型依据，避免点待办就重新分析；额度不足、未知或核验未通过时仍保留规则结果和最后已发布的历史，并明确其当前有效性。原请求在途时保留其授权版本直到结局明确，避免新绑定吞掉未知终态；成功步骤只经现有 checkpoint 安全接续。

归档、停止或失权后只保留与收拢既有结果。交接使用当时有效的人类病例权限，保存未解决问题的负责岗位，不自动解决问题或新增出院条件。归档后财务及医保核定不恢复临床分析；同任务重新开启时旧轮交接不代表新一轮已结束。收费员只读财务疑点，不获得临床计划、参数或模型临床解释。

当前行为见[术后核查与责任交接](../../../architecture/clinical-workflows.md#术后核查与责任交接)，正式验收由[PCI 住院 Agent 规格](../../../spec/2026-10-27-inpatient-drg-agent.md)拥有。

## Alternatives considered

- 以当前最新计划替代全部术前依据：会让第二台手术覆盖第一台未解决责任，采用按申请及实际手术分别匹配的冻结来源。
- 模型或人工按钮直接设置已解决：缺少正式更正证据，采用业务事实复查和显式人工无需处理两种不同结果。
- 每次待办操作重新调用模型：处置不改变临床事实，保留依据复用并独立记录人工历史。
- 为交接继续使用失效后台授权：会扩大旧任务权限，改由当前有效岗位接手只读结果和责任。

## Consequences

临床与财务更正仍需经过各自原 Command，核查不能改写原记录或费用。归档冻结与交接保留未完成模型状态及未解决岗位责任；历史结果可供回查，不能成为当前未经核验建议。病例用量只按实际请求计量，不以待办、业务事件或规则检查数量推算消耗。
