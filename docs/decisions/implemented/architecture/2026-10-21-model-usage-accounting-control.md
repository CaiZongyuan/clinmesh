# Agent Note: 统一模型调用账本、三入口计量、调用时计价与分层保留

Status: implemented

## Problem

ClinMesh 同时存在 Server 直接 OpenAI-compatible 调用、Server 经 DSH bridge 调用以及 DSH Host 自发执行的医生代问意图识别三条实际模型派发路径。若仅在逻辑任务外层记账会遗漏格式修复与限流重发，Host 自发识别也会游离在账本之外；若以当前最新价表回算历史记录、直接累加含义重叠的缓存／推理 Token，或把未经协议证实的 SDK `contextWindow`/`maxTokens` 当作计费硬上限，会产生失真账单与虚假的有限预算承诺；若删除过期明细时连带清掉监控统计或释放未决预占，更会破坏长期可观测性与配额门禁。

## Decision

在 Server 应用层与单 SQLite writer 上建立覆盖全部派发入口的 `ModelUsageService`，详细权限、存储与配置合同见[安全与可靠性](../../../architecture/security-and-reliability.md)、[存储与事务](../../../architecture/storage.md)及[部署指南](../../../deployment.md)：

1. **三类派发边界统一准入与逐帧持久化**：Server 直接调用与 DSH Provider 在每次实际网络派发前与请求包络同事务创建受信尝试身份（Server 经 bridge 转发至 Host 时复用同一尝试 ID，绝不双计）；DSH Host 自发代问识别在锁定 SDK 准备句柄后向 Server 申请窄准入（核对最新同客户端 `PageContext`、岗位、Epoch 与任务连续性，输入来源证明不可替代准入）。流式执行期间按帧短事务落盘已观察用量与实际模型配置，超期在途记录在读取或控制交互时自动收敛为派发未知且继续接纳迟到可信终态帧；账本不保存提示词、消息正文、凭据或原始错误文本。
2. **调用时冻结计价、生产上界诚实门禁与双权限人工修订**：价表与汇率由部署维护者统一配置（百万分之一货币单位安全整数运算，输入与输出分项无重叠计价，预占向上取整、结算按实用舍入），准入时按 `requestedModel` 冻结单价与汇率版本。由于当前直接 OpenAI 入口无硬输出 Token 上限、锁定的 DSH SDK 亦未提供底层 wire 协议级可信计费上界，生产入口在启用有限 Token 或非全零有限人民币额度时显式拒绝派发（默认全无限模式正常监控记录，全零价表仍可建立零金额上界），绝不用字符估算或目录回退值伪造预算担保。未知 Token／金额或历史缺价仅由管理员经受审计修订补充（关联特定住院病例的 DRG 用量修订同时要求管理员资格与当前病例读取权限），原始服务商证据保持不可覆盖。
3. **明细、日汇总与配额累计三层分离保留**：保留期按 Workspace 跨 Epoch 配置并以真实 UTC 开始时间判定到期。仍在途、派发未知且未完成全部消费核对、有效 Token 未知或任一维度仍持预占的记录强制留存；满足清理条件的记录在单事务内先将最终有效计量（含分别统计已知值与缺失请求数的输入／输出分项，不按比例拆分旧总量）归档至 `Asia/Shanghai` 日汇总表，再删除明细并将关联修订回执标为过期，保留必要核对审计与永久配额累计，清理绝不释放未决预占或恢复已消耗配额。
4. **下推式权限查询**：Workspace 成员可查阅本区跨 Epoch 汇总；普通成员明细按活动 Epoch 与实际门诊病例责任或住院科室／病区范围在 SQL 层过滤，行政调用仅管理员可见。

## Alternatives considered

- **在 Host 维护第二份本地账本，或每次用量帧实时更新日汇总差额**：多进程余额在并发与重启时必然分叉；实时维护日汇总差额在迟到帧与人工修订叠加时易引入重复计量，仅在到期归档时聚合最终有效值最稳健。
- **根据输入字节估算预占，或剩余配额不足时自动压低 `maxTokens`**：估算无法覆盖隐藏推理 Token，压低输出上限则会截断临床病历与核验结构。
- **到期按计时器无条件删行并从剩余明细重算总额**：抹除历史消费并让未决未知请求逃逸配额控制。

## Consequences

记账可写性成为全系统模型调用的统一前置门禁（无限额度下同样先落账再派发），请求级控制待办恢复见[双层模型请求准入与控制待办恢复](2026-10-21-model-request-control-recovery.md)。长期总览的累计调用与费用可大于当前留存可下钻明细数；配置价表仅提供治理估算口径，不替代上游云厂商实际账单。
