# Agent Note: PCI 住院持续跟进与模型用量归属

Status: implemented

## Problem

页面 Agent 的短期上下文不能承担关闭页面后的持续病例授权；后台 outbox 也不会自动授予临床读取权限。术中实际使用、手术完成、正式收费及待办处置又是不同事实，不能以逐件调用完成手术、关闭提示或模型声明相互代替。

业务变化、一次分析和一次实际模型请求分别有自己的身份。恢复必须保留未知结果和原尝试预算，不能通过停止重开任务重置；临床依据变化后，也不能继续把旧建议显示为当前有效。产品范围及验收由[正式规格](../../../spec/2026-10-27-inpatient-drg-agent.md)拥有。

## Decision

`InpatientDrgFollowup` 持有本次住院的稳定任务身份、启动岗位绑定及授权版本，复用 `IdentityService.modelTaskContextStatus` 与住院责任校验。每次后台读取、派发和结果发布重新核对有效性；切换页面不改任务病例，撤权、责任变化及归档会停止新分析。人工确认仍使用当时的人类会话、病例权限及预期版本。

`InpatientDrgAgent` 将医生确认的参数和来源版本、已确认计划、实际使用及规则依据绑定为输入指纹。术前、术中和术后沿同一 runtime 的模型绑定、受控 Provider 与 `ModelTaskRecovery` 生成并独立核验结果；成功步骤可以复用，结构正确但被核验否决的结果属于已知失败。原请求尚在途时保留其执行包络，结局明确后再续接；未知请求保持待核查，不自动重发。历史建议、参数和合成适用／兼容说明保留独立快照。

临床参数归 `InpatientPciSelection`，首期只核验明示的有限合成协议；真实来源与合成声明分别保留，见[选型依据决策](2026-10-27-pci-selection-evidence.md)。逐笔实际使用、部分预留、追加更正及独立完成手术由[手术 owner](2026-10-27-inpatient-surgery-material-events.md)维护，收费仍写共享账。阶段性分组由正式诊断和实际操作决定，材料数量不提升病组。

医生认可集合界定本轮建议范围，完整候选快照保留组合依据：已认可产品的合成兼容条件仍可能引用其他器械版本。候选目录中的每项状态与本次任务是否完整分别判断，具体派发及缺项合同见[PCI 参数与候选依据](../../../architecture/clinical-workflows.md#pci-参数与候选依据)。

`InpatientDrgReview` 保留不可覆盖的核查修订和按原手术依据识别的岗位待办。人工处置不修改临床或费用事实；解决依赖最新正式事实复查，人工无需处理保留理由，依据变化后的问题重新核对。归档、停止或失权后保留结果及未解决责任，由当前有效病例角色交接；后续财务及核定不恢复本轮临床分析，AI 待办不增加出院门禁。

模型用量仍由 `ModelUsageService` 逐次记录。稳定任务、当前住院、实际阶段和真实触发来源共同归属请求；Server 到 bridge 转发沿用同一尝试身份。原日汇总保留任务与阶段维度，明细到期不清零累计，也不补造旧汇总的任务归属。病例摘要和明细共用病例读取权限；核对与补算同时要求管理员资格和当前病例权限，见[双权限决策](../bug-fix/2026-10-27-drg-usage-correction-authorization.md)。规则检查与有效结果复用不制造请求、token 或节省量。

### 复用现有模块

| Owner | 本需求使用的边界 |
| --- | --- |
| 住院、手术、计费与 DRG | 诊断、实际操作、费用、预留、确定性推演及冻结仍归原模块；新模块只引用版本和事实 |
| `OutboxDispatcher`、`GenerationModelBinding`、`ModelTaskRecovery` | 使用 runtime 已装配实例、既有 handler 和安全恢复，不另建调度或通用恢复框架 |
| 门诊建议与病历质控的模式 | 沿用输入指纹、独立核验及失效保护；住院事实与权限独立读取，不调用门诊病例入口 |
| `ModelUsageService` | 复用计量、计价、控制、留存和人工核对；不建立病例预算或第二套用量账 |

## Alternatives considered

- 只依赖当前页面的聊天 Agent：无法满足离开页面后的持续跟进及责任交接。
- 每条业务事件直接运行完整模型分析：重复发送未变化资料，且事件数不能代表实际请求与用量。
- 只按费用差额或材料名称复用结果：遗漏临床参数、用途和兼容依据变化，无法保证建议仍适用。
- 重建任务或刷新授权时重置原请求：可能重发未知请求、遗失在途状态或绕过原尝试预算。
- 用业务事件估算 token 或把病例用量当整个宿主账单：无法证明实际计量、独立核验及覆盖范围。

## Consequences

离开页面仍可能产生已授权的模型消费，因此调用及未完成原因必须在病例内可见；停止重开保留原消费与尝试预算。用量核对或补算只修订计量，不会将未知的临床模型结果变成有效建议。

问题的处理归属与任务是否运行分别保存。切换手术、停止分析或完成交接都不能代替原问题的事实更正，尚未解决的责任会继续存在。

## Verification

[公开联合旅程](../../../../apps/server/tests/inpatient-drg-agent-http.test.ts)贯通本次住院的参数、三阶段实际派发、逐笔使用、更正、差异处理、归档交接及病例用量。新行为另由各 owner 的公开 HTTP、真实 SQLite 和 Web／React 18／19 界面验证；详细验收仍以[正式规格](../../../spec/2026-10-27-inpatient-drg-agent.md#验收条件)为准。

## Risks

有限合成协议不是真实器械 IFU 或临床推荐金标准。生产适配器缺少可信计量上界时，有限 token／金额控制会拒绝派发；不承诺配置额度即可获得可运行的费用保证，也不以未知或缺价作为零费用。证据边界见[选型研究](../../../research/2026-10-27-pci-material-recommendation-evidence.md)和[用量查询合同](../../../architecture/security-and-reliability.md#模型用量查询)。
