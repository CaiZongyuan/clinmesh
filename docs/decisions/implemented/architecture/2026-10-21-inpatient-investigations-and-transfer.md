# Agent Note: 住院检查复用申请内核，转科按当前临床责任交接

Status: implemented

## Problem

既有检查申请与报告关联门诊 case。直接给住院岗位放行会使报告归错 Encounter，复制 LIS/RIS 则会分裂取消、重试和报告修订合同。住院还有护士送检和跨科责任切换：开立不等于已经送检，原开具人也不等于转科后的责任医生。默认检验目录中的零价表示未计价，不能据此自动收零元。

## Decision

临床申请以真实 OP/IP XOR context 统一持久 owner。门诊保留原 case ID 与 wire 合同，住院 context 指向本次 admission；来源只用于结果解析，正式资源归本次 IMP Encounter。新 context 随原登记 Command 创建，查询不补写。迁移保留全部 Epoch 的旧行、引用、报告、确认、快照、回执和 outbox，并在提交前完整检查外键。

InpatientService 下的 InpatientInvestigations 负责住院开立、护士送检和责任校验，执行与报告仍交给既有申请内核和 LIS/RIS 适配器。护士送检事实是 accept 的事务前置条件；住院报告不进入门诊对话和自动记录。当前科室与病区在每次读取和写入时重新核验，转科后当前责任医生可以处理原科在途报告，不按历史 authored_by 锁死。

本院只对确知基础项目声明额外的有界合成价格，不推断全目录单项或组合价。未计价服务保持不可开展，申请冻结医院声明的价格、版本、来源和执行完成触发点。首次报告完成事务写同一本住院账，修订不重复收费；回调重读当前住院与财务状态，防止结算后追加应付。具体项目及金额由[当前临床合同](../../../architecture/clinical-workflows.md#82-住院闭环后续)拥有，不代表国家价格。

转科是医生申请、原护士交接、目标护士接收的独立任务。目标 incoming 清单只给接收必要事实，不提前扩大普通详情权限。原科停嘱核停、取消未执行计划、送检或取消未送检申请后才能交接；接收事务再次校验全部条件与空床，并原子切换床位、组织、病区和 FHIR 历史。已发未给取消保留实际发药、库存及费用；已送检申请继续完成并由新科接管，既往账目不迁改。

## Alternatives considered

- 给原 outpatient_case 造一个住院影子：制造不存在的门诊事实，还会把完诊、收费与 Scenario 生命周期错误地耦合到住院。
- 独立实现一套住院 LIS/RIS：重复状态机、重试、报告修订和素材来源校验，容易产生无法追溯的占位报告。
- 开立时直接排执行：跳过病区护士校对送检，无法区分待办意图和实际送检。
- 转科后只认原开具医生：旧科保留不应有的读写权，新科不能接管在途报告。
- 将未计价视作免费或给全部单项/组合套统一价格：把未知医院价变成已确认财务事实。

## Consequences

申请生命周期和报告格式只有一个 owner，业务上下文与来源各有明确身份。转科以短事务维护当前责任，不能作为绕过旧科收口或读取未接收患者完整病历的入口。HTTP 合同、真实 SQLite 旧库迁移、门诊回归与 SQL 预算、真实 Web 岗位旅程分别覆盖业务、数据保真、既有合同和临床入口；影像验证遵循合成 fixture 与真实像素隔离规则。
