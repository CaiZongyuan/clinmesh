# Agent Note: 完成手术时核实最终耗材净差额

Status: implemented

## Problem

逐笔耗材与追加更正已保存实际使用及正式收费，但完成动作不能接收真实最终总量。再次登记总量会重复收费，逐笔更正后另页释放预留又不能保证与完成状态一起提交。自动释放本计划全部余量还会误删医生希望保留的后续安排。

## Decision

完成前以当前全部有效使用来源、冻结材料依据和明确预留身份核实最终总量。预览只读，指纹绑定输入、实际手术、材料目录、原预留及原费用／冲正事实；提交在原 Command 事务重新规划并核验指纹。增加只追加差额；减少复用原材料更正与精确冲正，必要的正数替代继续保存历史冻结依据；最终零不追加零使用。预览金额反映已有财务冲正，避免再次承诺退款。

预留继续使用共享读取合同。历史单位和规格只从原冻结快照或唯一已有使用依据读取，缺失保持未知。多预留及不同冻结依据按身份分别审阅，不按材料名称自动匹配。目录显示或来源变化也可使同一预留的逐笔使用保存不同快照，因此不能以预留身份强迫它们合并。余量按预留汇总净差额，事务先退回减少量再登记增加量，避免单行均未超限却合计超用，也允许耗尽预留在总量不变时调整各冻结依据的用量。新增额外使用按当前有效目录审阅，旧事实不回写；页面预览展示服务端实际采用的产品、版本、单价与单位，变化时明确提示重新核实数量。

只有明确选择的本手术预留在完成事务关闭，`releaseReason` 同时保留完全消耗项的显式关闭选择，使后续更正退回量仍按该选择处理。未选预留默认保留并在回执说明。0102 迁移对旧已完成且全耗尽的绑定预留补记原关闭策略并推进版本，不改原使用、价格、费用或回执。旧完成输入仍接受，新增可选字段不注入默认值，保留旧请求哈希和历史 receipt 的恢复能力。指纹另绑定受信 Workspace/Epoch、Actor 与岗位，不能跨会话套用。

本决策部分替代[逐笔耗材决策](2026-10-27-inpatient-surgery-material-events.md)中完成时自动关闭余量的策略；原逐笔、追加更正及单一收费 owner 继续适用。当前接口与流程由[住院手术](../../../architecture/clinical-workflows.md#住院手术最小闭环)拥有。

## Alternatives considered

- 重记最终总量：会重复形成原有材料收费，选择只追加净差额。
- 循环调用逐笔 Command 后再完成：中途失败会留下部分事实，选择在一个完成事务复用内部写点。
- 自动选择同名预留或关闭全部本计划余量：无法表达多候选和保留意图，选择明确身份与版本。
- 新增材料事件表或独立账本：会分裂现有事实和收费 owner，继续使用原事件、更正及回执。

## Consequences

核实列表必须覆盖全部当前有效使用。目录、价格、费用或预留变化须重新审阅；历史依据不足时不能从当前目录补猜。HTTP 测试覆盖净量增减／归零、冻结依据、已有冲正、跨手术隔离、故障回滚与原回执；同一页面旅程覆盖 Web、React 18/19 Surface 及未知结果恢复。
