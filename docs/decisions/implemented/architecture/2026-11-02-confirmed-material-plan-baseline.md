# Agent Note: 已确认耗材清单作为不可变术后核查依据

Status: implemented

## Problem

单次耗材清单确认已表达医生对本手术整份预计材料的审阅，但原术后核查只接受持续跟进入口的冻结人工计划。医生需要重复确认另一份计划，且预留余额会随使用和释放变化，不能证明术前实际确认的原数量。当前工作稿也可能已被编辑，旧确认标记不足以恢复原材料快照。

本决策补充[单次耗材预计](2026-10-28-single-material-estimate.md)的确认结果，并扩展[事实复查与交接](2026-10-27-inpatient-drg-review-handoff.md)的依据来源；单次预计和主动持续跟进的授权生命周期、原比较规则及岗位处置边界继续适用。需求见 [住院 AI 辅助需求的 清单衔接切片（Issue #344）](https://github.com/CaiZongyuan/clinmesh/issues/344)，当前行为由[临床流程](../../../architecture/clinical-workflows.md#术后核查与责任交接)拥有。

## Decision

单次清单确认沿原共享 Command，在整批预留、工作稿确认关系、Effect、审计和幂等回执的同一事务中追加不可变术前快照。`inpatient_material_plan_confirmation` 固定本次 Workspace/Epoch、住院、申请、预计身份与工作稿修订；保留确认人和时间、依据指纹、原确认材料及目录版本、规格、单位、数量、冻结价和证据来源。预留引用用于追溯确认结果，余额不参与恢复原确认数量。术前重新确认追加版本和同来源取代关系，手术开始后只能沿实际使用及更正流程记录新事实。

既有持续跟进计划保留在原 owner，不将旧表记录改写成单次来源。共享解析按原选型确认身份与版本核验其申请绑定，并为两种来源提供同一公开依据结构。每种来源独立保留取代历史；跨来源没有明确取代关系时保留双方并报告冲突，不以最近时间或内容相似推定医生已审阅替代。缺少可核验快照的历史确认保持待核实，不将当前草稿、预算预留或实际使用提升为术前临床依据。

原术后核查消费解析后的有效依据，继续拥有材料数量、非计划产品、替换和正式收费净额疑点的比较及岗位待办。单次确认只留存本次依据，不创建、扩大或延长持续跟进授权，也不新增模型派发；后台核查、模型解释和交接仍沿原生命周期。收费员仅接收财务内容，冻结核查保留当时的来源快照。

## Alternatives considered

| 方案 | 未采用的原因 |
| --- | --- |
| 从剩余预留恢复术前清单 | 消耗、释放和更正改变余额，原确认数量及被取代材料无法可靠重建。 |
| 将当前工作稿或旧确认标记回填为历史快照 | 标记未证明当前稿就是确认时的内容，会伪造临床依据。 |
| 确认清单时同步创建持续跟进计划或后台任务 | 一次确认会扩大为长期授权，混淆原来源及用户动作。 |
| 将两类来源迁入同一旧表并按最新时间选用 | 改写既有归属，且不能证明跨来源的取代已经被审阅。 |
| 为单次清单另建术后比较与待办 | 相同实际材料和费用会由两套规则判定，容易出现不一致。 |

## Consequences

医生只需在术前确认一次清单，原数量在预留用尽后仍可核查；同来源重新确认、实际用量更正及回执恢复各自保留可追溯身份。历史无法证明的依据继续明确未知，两来源冲突需要核实原记录；系统不会为消除提示自动改变临床、费用、分组、支付或出院条件。

验证沿公开耗材预计与术后核查 HTTP Query／Command、角色会话和临时 SQLite，覆盖确认、实际使用、完成手术、原授权下核查的连续旅程，以及预留消耗／释放、版本取代、来源冲突、跨手术隔离、历史缺证据、事务回滚和原回执重启恢复。Web 与 React 18／19 Surface 验证一次确认及后续来源和差异展示，既有持续跟进计划保留独立回归；这些证据只证明合成接线与业务合同。
