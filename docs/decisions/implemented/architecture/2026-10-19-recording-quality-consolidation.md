# Agent Note: 门诊病历质控与自动记录来源语义核对合一及安静提示边界

Status: implemented

## Problem

门诊自动病历整理若在每片段落库后单独调用模型做忠实性核对，同时整份病历质控又再次检查来源支持度、遗漏与矛盾，会造成重复模型请求并在界面并列两套核对状态；若实时质控每次都自动拉取患者跨年全量既往史与完诊病历，寥寥数句本次问诊就会携带数百条历史记录击穿上下文预算；若在表单顶部常驻提示“评估／处置尚未填写”等问诊期正常空字段，或在每条提示旁放置“已核实保留／查看依据”确认按钮，又会打断医生连续问诊并违背“自动直接记录、有误直接改正文”的交互准则。

## Decision

将自动记录来源语义检查并入限定本次就诊范围的统一病历质控，并采用非阻断、分层安静展示设计，当前合同见[临床决策支持与质控](../../../architecture/clinical-decision-support.md)与[门诊业务流程](../../../architecture/outpatient-workflows.md)，官方书写规范边界见[门诊病历质控规则研究](../../../research/2026-10-15-outpatient-record-quality-rules.md)：

1. **取消逐片段事后核对，统一归入整份病历质控**：移除自动记录保存后的逐片段语义核对通道、模型绑定与专用重试（旧 `consultation.verify-history` outbox 事件仅兼容退役消费，兼容 `verification` 计数恒置零）。自动片段通过复合外键关联不可变批次快照，由 `doctor_document_quality_state` 在整份病历质控生成与独立复核中一并检查旧事实保留、更正／冲突关系、已拒绝事实无新依据重现及 Agent 直接写入归属；人工接管的片段退出自动来源归属检查，仍参与整篇文书逻辑一致性检查。
2. **严格限定本次就诊输入与按完整指纹复用**：实时质控仅读取当前候选正文、本次问诊回答、医生明确补充、本次已发布报告以及当前过敏、分诊和已确认诊断摘要，不自动枚举外部来源历史或既往完诊全文（超限直接标为不完整，绝不静默截断伪造通过）。服务端在 `input:` 保留命名空间按完整临床输入指纹复用规范任务（排除纯草稿版本号与客户端指针，保存同文不重复调用模型）；客户端隔离编辑正文与冻结签署预览两套请求身份，防止预览打开期间新来源到达引发双视图互相抢占重查。
3. **具体说明结构与分层安静展示边界**：质控问题必须包含具体摘要、临床影响、最小处理动作与唯一原句字段定位（否定复核保持合法结果，不触发格式修复改口）。界面不提供逐条“已核实保留”或确认按钮（历史核实回执仅只读兼容保留），医生直接编辑正文即可触发重检；页面顶部紧凑提示条仅展示开放的事实矛盾与来源疑点，问诊过程中的空字段与待补充项（`needs-completion`）仅在按需展开的“依据与说明”及签署汇总详情中展示，自动记录后台部分失败亦收敛为按需展开的重试说明而不常驻报错横幅。软性质控提示不阻塞草稿保存或正式文书签署（关键临床关口的确定性红线与受控越权门禁由[双层事中临床质控](2026-11-18-two-tier-clinical-quality-gates.md)独立承担）。

## Alternatives considered

- **保留逐片段核对与整份病历质控双调用链，或将核对移回草稿落库前**：前者无对比收益却倍增模型开销与状态噪音，后者重新引入每轮问诊的串行模型等待。
- **继续将全量纵向病史送入实时质控，或完全隐藏所有 `needs-completion` 详情**：全量病史使每次按键保存后的质控开销随历史线性膨胀；完全隐藏待补充详情则会让医生看到“检查已更新”却找不到已识别的已知遗漏。
- **保留逐条“确认保留”按钮或把模型语义质控设为硬性签署门禁**：增加无谓点击负担，且概率性模型误报会导致合法病历无法签署。

## Consequences

自动记录正常批次收敛为单次模型调用，病历编辑区在问诊初段保持安静无打扰，同时医生仍可在签署前按需展开完整待核实与待补充清单并一键定位对应字段。空提示列表仅代表本次就诊已知输入内未检出明显矛盾，不构成全病史无遗漏或医疗监管合规认证。
