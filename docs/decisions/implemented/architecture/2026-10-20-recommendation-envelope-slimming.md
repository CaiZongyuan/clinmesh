# Agent Note: 诊疗建议的信封瘦身与已选记录收敛

Status: implemented

## Problem

[分批证据读取决策](2026-10-15-recommendation-context-budget.md)解决的是"合法大病例无法进入生成"：历史按完整原文分批读取，目录按完整定义分批筛选。真实病例（2026-10-19）暴露了剩余的结构性缺口：必读安全资料自身可达 244 KB / 256 KB 信封，而历史筛选、目录筛选的每个批次请求都重复携带必读证据与已选证据全文及全量目录定义。结果是筛选批次容量随必读体量塌缩（检验目录每批仅容纳 2-3 项，触发 8 批总预算失败），已选历史合入后生成请求也可能无空间，病例再次无法获得建议。另外历史打包的单包上限按字符（12,000）计量，中文内容按 UTF-8 字节可达 3 倍体积，字符预算与字节信封错位。

## Decision

筛选阶段请求以"判断相关性所需的最小视图"为准：

- 历史筛选与目录筛选请求中的必读证据、已选证据降为紧凑索引（id、kind、label 与有界原文摘要），不再是全文。候选记录与目录条目仍以完整内容参与筛选，模型只返回编号，不生成替代原文。
- 目录筛选与生成请求中的检验项目使用筛选视图：保留项目身份、真实编码、标本、组合成员、允许适应证与适用条件，不含 `reportDefinition` 及参考范围规则。选中项目的完整真实定义继续只在归一化、独立核验、保存与失效判断中使用（与[分批证据读取决策](2026-10-15-recommendation-context-budget.md)的生成目录保留清单一致，报告定义本就不在其保留列表内）。参考诊断目录只保留编码身份字段（id、system、version、code、display）。
- 目录筛选对存在检验目录项的检验建议始终执行：瘦身后全量目录虽能装进生成请求，但 reviewed/selected 筛选审计与"生成只能使用已筛选目录项"的响应校验仍由筛选阶段提供；瘦身的收益是批次数受控，而不是跳过筛选。
- 历史打包与目录批划分的容量判断统一按 UTF-8 字节计量：单条记录或完整字段超过 12 KiB 字节即按完整字段拆分，聚合包上限维持 16 KiB 字节；12,000 字符上限保留为证据文本合同的硬上限。12 KiB 字节对纯 ASCII 内容与原 12,000 字符上限基本等价，对中文内容收紧约 3 倍。
- 历史筛选完成后，若必读与已选证据合入生成请求超限，服务端发起一轮收敛请求（桥接 schemaName `doctor_recommendation_history_consolidation`，已加入 `modelBridgeRequestSchema` 枚举，宿主桥接需同步接受）：向模型提供全部已选完整记录与容量上限，让模型保留最相关的至多容量条。收敛请求自身超限时跳过；收敛后仍超限则维持既有明确失败路径，不静默截断必读资料。容量为 0（连最大一条已选记录也无法与必读资料同装）时不调用收敛模型，保留必读资料继续生成，并以处理通知说明放弃的已选记录数。收敛结果进入既有选择审计（selectedRecordIds 等）；筛选复用缓存保存收敛前的选择，收敛随每次生成独立执行。
- 进入生成与独立核验的证据内容与快照指纹、复用键、失效条件不变；正式要求见[信封预算规格](../../../spec/2026-10-20-recommendation-envelope-budget.md)。

## Alternatives considered

- 提高批次上限或传输上限：宿主桥接强制 256 KiB，提高批次只增加调用且生成请求余量为负的根因不变。
- 生成阶段按批拆分：生成需要全病例视野，拆批会系统性降低建议质量。
- 摘要或截断必读安全资料：违背"不裁剪进入生成与核验的完整资料"边界，改为筛选阶段不携带全文。
- 预先按关键词淘汰候选历史或目录：与既有决策一致地被拒绝，筛选仍覆盖全部候选。

## Consequences

筛选请求体量与必读资料规模解耦，批次数量恢复受控；2026-10-19 规模的病例可完成读取、筛选并进入生成。筛选模型只依据索引判断必读资料关联，相关性判断的输入变少；候选与目录仍为完整内容，生成阶段必读全文完整在场，独立核验与医生最终确认共同兜底。收敛轮在极端已选集上增加一次模型调用，仅在超限时发生。验证范围见[测试策略](../../../../docs/testing.md#end-to-end)。
