# Agent Note: 分组记录核对独立读取与单次解释

Status: implemented

## Problem

医生需要在住院页面核对实际 PCI、首页主操作和计划分组依据。既有术后复查由活动跟进任务驱动，并同时承担耗材差异待办及责任交接；直接沿用其启动条件会迫使医生为一次只读核对开启长期分析。每次页面读取调用模型又会使规则提示依赖模型成功，并重复产生请求。

## Decision

分组记录核对作为既有复查 owner 的确定性查询，不依赖活动任务。查询读取已确认诊断、实际操作、首页已提交的主操作选择和待实施计划，调用原正式分组与计划推演；后台复查消费相同问题结果。实际 PCI 与另一主操作同时成立时展示两份原记录，不判断谁必然错误，也不代改主操作。分组缺项或编码不兼容与支付参数缺失分开展示，医院支付参考与患者医保及正式收费继续分离。

页面展开是一次解释的明确意图。独立意图保留当前医生权限及依据版本，复用已有分析持久化、Outbox handler、模型绑定、计量和未知步骤恢复，不伪造活动跟进任务或新建模型账本。模型仅接收核对问题和当前岗位可见来源，生成与独立核验均约束问题和来源；在派发与发布前重验原授权和依据，迟到结果不能用于其他病例或旧版本。有效结果复用，失败仍显示确定性核对，未知结果沿原尝试恢复。

既有后台自动复查、材料差异待办及归档交接继续保留；本决策补充[事实复查与责任交接](2026-10-27-inpatient-drg-review-handoff.md)的页面读取路径，落实[准备与预计提案](../../proposed/architecture/2026-10-28-inpatient-ai-preparation.md)中的直接核对部分。当前合同见[直接分组记录核对](../../../architecture/clinical-workflows.md#直接分组记录核对)，验收归[PCI 住院 AI 辅助规格](../../../spec/2026-10-28-inpatient-ai-assistance.md)。

## Alternatives considered

- 为页面自动开启长期跟进：可复用任务身份，但扩大一次解释的授权范围，且只读页面会改变用户未选择的后台行为。
- 页面自行比较病组或让模型判定：形成第二套判定，缺少共享业务依据，模型失败也会遮蔽确定性问题。
- 每次展开重新生成：容易重复计量，断流或失回执后还可能重复外部请求；使用持久意图、指纹复用和既有步骤恢复。
- 独立建立解释队列与计量表：增加授权和未知结果的第二套生命周期；沿用现有分析执行边界，单次意图只拥有何时请求及当前依据。

## Consequences

核对与解释都是辅助审阅，正式更正仍经原 Command；包含 PCI 的病例仍可因主操作及其他正式事实不同形成不同病组。公开 HTTP 和临时 SQLite 验证未开启跟进、三类问题、支付缺参、权限、失效与正式事实不变；受控 Provider 验证首次派发计量、结果复用和恢复，Playwright 补真实页面的提醒、展开及返回原记录。合成验证只证明接线和有限规则范围，不代表真实模型的临床质量。
