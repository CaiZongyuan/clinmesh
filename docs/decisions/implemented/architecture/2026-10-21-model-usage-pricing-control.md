# Agent Note: 模型调用时计价与分维度额度结算

Status: implemented

## Problem

请求次数不能约束单次模型的 Token 或金额，未知结果也不能解释为零消费。以当前价表重算旧请求会改变历史依据，缓存与推理若重复累加又会高估消费。DSH 的准备句柄能固定模型配置，却不自动提供底层协议的可信计量上界；若把目录回退或启发式估算当作保证，有限额度会产生错误承诺。

## Decision

延续[双层请求准入](2026-10-21-model-request-control-recovery.md)的单 Server／SQLite writer，将 Token 与人民币分别作为部署及 Workspace 的独立额度维度。每层每维度首次设为有限时建立持久起点，之后无限只是停止拦截，不重置起点或累计。所有适用限制与旧任务请求包络在一个短事务中检查并预占；网络等待在事务外。有限模式需要对应维度的可信上界，不足或不可核算时拒绝，不改变输出、输入或推理策略。

价表由部署维护者统一配置，Workspace 只有只读能力。准入按受信 Provider 与 `requestedModel` 精确冻结单价、币种、汇率和版本，DSH 保留完整固定路由；响应观察到的实际模型不能覆盖调用时依据。输入与输出分别包含缓存、推理子集，按互不重复分项计价，预占按可能最高分项单价计算。金额采用百万分之一货币单位的安全整数，中间乘除使用整数运算，预占向上取整，结算按实际用量舍入，避免浮点相乘低估上界。

三个当前生产入口都明确记录不可核算原因。直接调用没有硬输出 Token 上限；锁定的 DSH SDK 未公开绑定实际 wire adapter 的计量保证，`contextWindow` 可能是回退值，`maxTokens` 也不能证明底层总输出计费上限。当前有限 Token 和非零金额保护因此拒绝这些入口；全部无限时继续监控，明确全零人民币价表仍可建立零金额上界。合成有界适配器只验证通用内核，不扩大生产能力声明。可信边界未来只有在同一派发代次能提供可验证协议保证时才能开放。

未知派发或消费跨取消、超时、断流、重启与期限到期保留占用，可信用量只结算已知维度。业务结果未知与消费未知分别处理：启动恢复和 Host 超期复用同一结算路径，按已经持久保存的用量结算，而不等待可能永远无法送达的终态；状态与额度原子提交，重复恢复不重复累计。此前已标为未知的未决记录也参与启动结算，未知维度继续保留。恢复结算不能冻结仍未知结果的后续用量证据：迟到进度与终态按有效计量差额调整，防止少记消费，重新不可核算的维度恢复未知占用以保持有限准入保守；已完成终态保留原不可覆盖约束。管理员核对以独立修订补充未知 Token 总量或人民币金额，允许部分处理；缺价或缺汇率补算单独保存采用的依据，缺汇率时保留原单价。两种操作通过当前管理员身份、修订版本、幂等键、同事务审计与回执约束，原始用量、调用时快照与原估算保持。修订更新有效计量与累计，不授权模型重发。

派发未知但已结束的请求完成显式消费核对后，将一次请求预占转为已用，Token 与人民币有效值均已知才算完成，包括零值。这样保留一次请求的保守占用，同时结束人工已确认的未决状态；部分核对仍不结算请求次数。消费核对不证明业务结果成功，也不把原始派发证据改成已派发。两项消费原本均已知时允许仅依据核对，避免“禁止覆盖已知数值”与“必须补数值”共同封死请求预占的人工收束；具体准入条件由[存储合同](../../../architecture/storage.md#910-模型调用账本)拥有。

## Alternatives considered

- 用字节数、字符密度或历史平均预占：容易实现，但既不覆盖隐藏推理，也不能证明上界；保存未知并拒绝对应有限维度。
- 从 SDK 的上下文与输出配置直接推导保证：能得到数字，却可能依赖未知模型回退和会省略限制的底层协议；等待同代次的可信适配器合同。
- 配额不足时降低输出或输入：可能改变临床生成与核验结果；保留调用策略并显示拒绝原因。
- 改价时重算所有旧请求：能统一当前报表，却抹去实际调用时依据；新请求使用新版本，缺失依据仅显式补算。
- 在原用量上覆盖人工核对：字段更少，但无法区分服务商证据与人工判断；有效计量由独立审计修订投影。
- 取消或定时器到期释放余额：可快速恢复可用额度，却无法证明服务商未消费；保留未知直到可信结算或显式核对。
- 恢复时只改结果状态、等待管理员结算全部维度：实现简单，但已经完整的用量不符合补充未知维度的核对条件，可能留下无法处理的预占；直接幂等结算已有可信证据。

## Consequences

有限额度可能因能力不足或未决消费阻止新请求，这比未经证实的预算保证更符合调用合同。全部无限仍要求账本可写，缺价或缺汇率本身不阻止调用；费用只代表部署配置口径下的估算。管理员需要依据处理未知维度，部分核对不会替另一维度释放余额。

当前接口与权限由[模型用量查询](../../../architecture/security-and-reliability.md#模型用量查询)拥有，持久原始证据、快照和修订由[模型账本](../../../architecture/storage.md#910-模型调用账本)拥有，价表字段与有限能力由[部署说明](../../../deployment.md#模型用量)拥有。验证通过合成价表、受控派发与临时 SQLite，使用公开 HTTP 检查权限、累计、核对和补算；浏览器检查 Web／DSH 接线与 React 18/19 对话框，详见[测试策略](../../../testing.md#14-测试策略)。明细保留及整个用量监控规格的后续范围仍由[正式规格](../../../spec/2026-10-19-model-usage-control.md)拥有。

住院 DRG 明细要求病例读取范围时，管理员资格与当前临床岗位共同授权纠错，取舍见[双权限纠错决策](../bug-fix/2026-10-27-drg-usage-correction-authorization.md)。
