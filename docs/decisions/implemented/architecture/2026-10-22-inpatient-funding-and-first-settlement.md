# Agent Note: 住院共享收款接入、原款退款账本与结算后财务更正链

Status: implemented

## Problem

住院资金流贯穿入院现金预交金、在院追加预交金、首次出院结算多退少补以及清床／病案归档后的错漏计费更正。若住院独立维护一套异于门诊的收款尝试表，或让首次 `settle` 命令无条件直接生成成功补退，既会产生双套交易恢复逻辑，又无法表达支付渠道结果未知时的封账与清床阻断；若把费用冲减直接覆盖原账项、把退款直接改写原预交金，或在归档后为退补差额而解档重开住院与床位，则会抹除原始收付依据并破坏首次结算与不可变病案的冻结语义。

## Decision

在[共享支付与住院边界](2026-10-21-payment-inpatient-drg-boundaries.md)下，以 `PaymentCollection`、`RefundLedger`、`InpatientPayments` 与 `InpatientFinancialAdjustments` 组合完整住院资金与更正闭环，当前业务与存储合同见[收费、结算与医保](../../../architecture/billing-and-insurance.md)及[存储与事务](../../../architecture/storage.md)：

1. **全用途接入共享 `PaymentCollection` 与原款 `RefundLedger`**：入院登记现金预交金、追加预交金、首次结算补缴与结算后补收统一经 `PaymentCollection` 创建原款、冻结付款方式并按原尝试查询恢复（入院登记款通过无独立预览的分配接入，不计入公开独立收款尝试，从而保留“从未发起独立收退款尝试时允许人工审阅后默认现金结清”的兼容路径，超单笔限额差额要求显式分笔办理）。费用冲减、原款退款与渠道结果分别追加事实：共享 `RefundLedger` 按原款类型与 ID 追踪累计成功退款与未知预占，组合支付按原冻结方式逆序分配退回金额，绝不覆盖原费用或原收款记录。
2. **首次冻结结算、清床门禁与无死锁未知恢复**：首次封账预览绑定排序后的逐项费用、冲正、医保分摊与资金指纹；必须全部在途收退款结果确定且患者净应付结清后才能完成首次封账，进而解锁护士清床。原资金记录读取与未知尝试查询不要求当前医保费用来源仍有效，确保费用冲正后仍能先查明在途未知资金、再执行医保待遇撤销，消除恢复死锁。
3. **归档后 `adjustment_id` 独立财务更正链**：首次结算、清床或病案归档后的补计费用、费用冲减与关联补收／原款退款由 `InpatientFinancialAdjustments` 独立承接，以非空 `adjustment_id` 与首次冻结账严格隔离（首次结算快照与病案归档校验始终排除后续调整资金，同一成功原款共享唯一可退余额上限，正反未结更正先行抵消，存在任何未知收退款时阻断新预览与确认）。后续财务 Command 仅对当前 Epoch 下 `active` 或 `completed` Scenario Run 的人类收费员开放（`closed` Run 与失效 Agent Grant 继续拒绝），绝不回退已完成的出区、清床或病案归档锁。

## Alternatives considered

- **保留住院私有收款尝试表或向新旧两套表双写以迁就退款外键**：延续双套状态机与双权威账源，改为统一接入 `PaymentCollection` 并通过[一次性开发切换](2026-11-10-outpatient-multi-charge-collection.md)收口旧合成运行链。
- **退款一发起即扣减实收，或将归档后未知退款映射回“未结算”并解档重开床位**：前者把渠道拒付或未知误算为已退资金，后者因纯账务纠偏破坏已完成的临床出院与病案冻结事实。
- **读取未知资金尝试时强制校验医保来源未失效**：在发生费用冲正后锁死未知尝试恢复入口，使收费员既不能结清未知交易也无法撤销旧待遇。

## Consequences

住院页面清晰并列首次冻结账（费用、医保、净实收）与结算后当前调整差异及待办收退，所有写操作均绑定会话级原意图与幂等回执恢复（见[住院写入绑定原意图恢复](../bug-fix/2026-10-20-inpatient-command-intent-recovery.md)）。本地 SQLite 事务回滚仅保证院内账表与回执原子性，外部渠道未知结果始终通过查询原尝试收敛。
