# Agent Note: 门诊申请应收与执行门禁

Status: implemented

## Problem

同次门诊可以有多项独立检验、放射和病理会诊，原病例级单个申请引用及病例加类别的收费选择不能表达各自应收与放行。只在开立时补建费用，仍会让既有受理事件提前执行，也可能让预览、确认和恢复指向不同申请。临床取消、应收冲减与原款退款还必须分别保留事实，避免取消后未知资金或未退余额失去处理入口。

## Decision

以原申请拥有唯一应收与首次财务放行事实。正式开立在共享 Command 事务冻结门诊价目；资金、医保和恢复始终绑定原 ChargeItem。受理重验当前确定全额覆盖并原子冻结许可，开始及重试校验该许可。这个边界既能阻止过早或直接调用，也能让已受理申请在后续待遇撤销时继续执行，把新欠款留给独立财务待办。完整行为由[临床工作流](../../../architecture/clinical-workflows.md#门诊独立检查的应收与执行门禁)拥有，价格参数只在[合成价表](../../../spec/2026-10-26-outpatient-investigation-billing.md#价目与计费时点)维护。

当前医生清单的每项检查同时绑定加入或明确重审时的服务及价目快照，确认事务先核对再保存和开立。单独校验建议输入指纹不足以保护人工清单：后台可取得新指纹，而医生仍只审阅过旧价；逐项快照让这个差异产生冲突，并由真实确认入口回归覆盖。

检验建议的读取投影附带至多八个精确服务的当前版本、允许目的与门诊价目，来源为当前病例医院目录，不来自模型输出或手动搜索页。选择这个窄投影可让医生直接审阅自动建议，避免先打开添加弹窗或翻页才偶然取得价目；已审阅快照仍独立冻结，后台新价不自动覆盖。

账单、支付、退款与医保分配继续聚合原账，不新增可编辑影子账或病例级第二套余额。以持久化策略区分新门诊、未计费历史及住院，避免通过碰巧找到费用来猜测适用规则；存储归属与旧预览的无歧义恢复见[持久化合同](../../../architecture/storage.md#门诊独立检查计费策略)。

临床取消只派生原费用的冲减依据，资金仍由收费员按原成功交易退款。取消与受理竞争同一事务；首次放行前禁止普通冲减绕过门禁。取消退款责任参与统一 Run 完成检查，使完诊或发药可以继续，而退款入口在责任结清前保持可用。

## Alternatives considered

- 仅在三类开立代码补建费用：不能阻止已有 outbox 立即执行，且病例加类别无法区分多个原申请。
- 只在收款成功时排受理：不能防御旧事件、重复派发或直接执行 Command；资金守卫应在共享生命周期内重验。
- 把独立申请转换为兼容检验病例状态：会占用单个原申请引用，关闭当前医生任务，无法表达同次多个并行申请，也破坏放射和病理身份。
- 完成执行后按住院方式记账：无法满足门诊收齐后才执行的目标，且将预交金住院模式引入门诊。
- 取消时自动退款或删除费用：混淆临床状态、应收调整与资金三条链，无法保留未知退款及原交易余额控制。
- 全量历史申请补费：旧在途、已完成申请没有审阅过门诊价格，补费会改变历史语义并可能阻断原执行。

## Consequences

门诊演示价格与住院计价、真实医院报价分别维护，零占位不能成为免费执行。服务和价目变化使旧草稿失效，正式费用保留原快照；这增加了重新审阅的必要步骤，但避免静默采用医生未见过的新价。历史申请不追收，也不能用缺失策略绕过新门禁。

首次放行形成不可回退的临床许可；受理后的待遇撤销和财务更正需要收费员处理差额，不能以重新阻断执行替代财务处置。临床取消也不等同退款，未结清责任延后 Run 完成，原费用、原交易、报告和执行链始终保留。

新增类别必须同时穿过存储约束、contracts、医保映射及支付 adapter。验证分别观察受理资金守卫、开始快照守卫、精确原费用、非空旧库与完成时序，避免只证明没有入队。完整业务矩阵由公开 HTTP、临时 SQLite 与受控外部边界拥有，Web、DSH 和 CLI 只补各自真实接线；分层归属见[测试策略](../../../testing.md#end-to-end)。
