# Agent Note: 诊疗建议的分批证据读取与请求预算

Status: implemented

## Problem

多年可见历史与院内完整检验定义可以分别超过一次模型请求的预算。把每条历史都占用一个证据槽、把执行及模拟元数据原样发送，会使合法大病例无法生成建议。反复逐条授权读取还会使建议轮询在模型调用之外消耗明显时间。详细需求由[诊疗建议规格](../../../../docs/spec/2026-10-13-doctor-guideline-recommendations.md)拥有；本文取代[来源与草稿边界决策](2026-10-13-doctor-guideline-recommendations.md)中整份历史必须在单次输入容纳的限制，临床确认、来源与草稿保护继续由原决策拥有。

记录级筛选与有限限流恢复由[后续决策](../bug-fix/2026-10-16-recommendation-record-selection.md)拥有；本文按整包选择历史的规则由其取代，来源、必读资料与目录边界继续有效。目录筛选的触发条件与筛选载荷已由[信封瘦身决策](2026-10-20-recommendation-envelope-slimming.md)取代：存在检验目录项即始终筛选，不再以“完整目录仍超限”为前提，筛选请求携带紧凑索引而非全部已选原文；本文的生成目录保留清单与选中项目完整定义的归属继续有效。

## Decision

完整授权输入保存在建议 snapshot，所有本次资料、可见来源和完整目录继续参与指纹。历史使用与医生详情相同的白名单，通过当前病例、患者及负责医生边界批量读取；本院完诊资料沿用原有责任和完诊规则。既往诊断读取继续遍历 FHIR 搜索游标，不能把一页当作完整安全资料。

本次资料始终保留。历史按来源、资源类型和是否必读无损打包，每包至多 12,000 字符，多条聚合目标为 16 KiB UTF-8；不裁剪完整记录，单条可以独占一包。诊断、过敏、用药、设备、手术、本院完诊记录及带明确异常或未知解释的 Observation 必读。没有解释标记的 Observation 仍须读取，不能推定正常。必读长记录只允许按完整字段拆分且所有片段均必读；无法保持完整字段时明确缺证。

精简后能容纳全部资料时直接生成，不增加历史筛选。溢出时，服务端先完整划分其余历史的全部批次，再让模型返回本批需要保留的原证据包编号与是否完整读取。模型不生成替代原文的摘要，虚构、重复及其他批次编号不通过验证。每批都包含本次及安全资料，筛选针对本次诊断、检查和用药共同的支持、反对、适用性及未解释信息。全部批次完成后才进入生成；持久输入登记已读取与选中编号，可从完整 snapshot 定位未选中的来源。病例证据引用指向实际提供给生成与核验的原文包，包内保留条目身份、临床时间、标题、状态和临床字段。

历史筛选最多八批、两批并发，全部阶段共享既有任务截止时间。仅复用已完整完成的筛选，内存最多保存八个结果；键包含授权 context、固定模型、完整证据与指南，值仅保存原证据编号。当前 outbox 入口串行派发各类建议，同一病例不同页面可复用已完成结果；不引入跨任务取消、并发 Promise 所有权或持久摘要缓存。输入、权限或模型改变时重新读取，进程重启可以重新筛选。

生成目录保留项目身份、真实编码、标本、组合成员、允许适应证与临床适用条件，排除价格、执行科室、周转时间和结果模拟配置。`laboratory-cn` 的成年限制与性别参考规则保留，模拟范围不冒充临床参考范围。完整检验目录仍超限时，先按最大的至多八项预留历史装配空间，必要时退到最大单项；目录筛选使用全部已选原文和指南，按完整项目覆盖所有批次，每批至多选择八个原始编号，最多八批、两并发。全部完成后只向生成提供选中目录，未选编号不能生成建议，持久输入登记全部已读与所选编号。已完成的目录选择按授权、模型、完整病例、选中证据及完整目录复用，内存最多八个结果；目录细节变化也使复用失效。所选项目的完整真实定义继续用于归一化、独立核验、保存与失效判断。

所有模型阶段按实际 payload 的 240 KiB 和完整传输封装的 256 KiB 检查，包含 schema、提示词及 DSH 4 KiB 格式修复预留。筛选每波读取前后检查任务代次，旧轮不继续消耗后续请求；生成前再次核对完整输入指纹。生成仍最多八条候选；核验可容纳时只请求一次，超限时按完整候选分批、最多两并发。每批保留全部已选原始病例证据及指南，目录和药品规格限定为该批候选；每批核验必须恰好覆盖候选及处方字段，全部批次结束后才发布。合法否定结果保持否定，不通过格式修复改为通过。

## Alternatives considered

- 提高条数或单次字节上限，无法处理继续增长的病史，也不能改变宿主与模型传输边界。
- 只取近期、第一页或关键词命中的历史，会遗漏旧安全信息；没有异常标记也不能证明结果正常。
- 用模型摘要代替所有原文，会增加事实改写与限定语丢失风险；当前只允许选择实际提供的完整证据包。
- 全部病例都先多轮整理，会增加小病例耗时；当前保留直接生成的快速路径，仅溢出时筛选。
- 用模拟器的资源闭包批量读取，超出医生历史索引边界；批量查询必须从当前授权历史索引出发。
- 新建向量库、通用 Agent 工具循环或全局缓存平台，增加依赖与所有权，现有 SQLite、模型桥、Command 与 outbox 已能完成本需求。

## Consequences

必要资料或所选相关资料自身仍超限、历史超过总批次预算、读取未完成及模型失败都会明确停止，不静默丢来源，也不改写草稿。选择编号可阻止虚构事实来源，但不能证明模型的临床相关性判断完全正确；固定必读安全资料、完整来源清单、独立核验与医生最终确认共同限制风险。

本决策保留有效：批次结构、编号审计与明确失败路径仍是当前机制；筛选阶段载荷与打包计量由[信封瘦身决策](2026-10-20-recommendation-envelope-slimming.md)细化，正式要求见[信封预算规格](../../../../docs/spec/2026-10-20-recommendation-envelope-budget.md)。

筛选和拆分核验可能增加模型请求，输入精简、有限并发与同输入复用减少重复等待，不能据此承诺真实模型的固定响应时间。性能证据使用同一合成规模的公开 HTTP 测量及 SQL、调用数量；只测裸 SQL 会漏掉逐条授权、prepare、解析和装配成本。验证范围见[测试策略](../../../../docs/testing.md#end-to-end)。

实模验收的隔离环境保留显式 `NODE_USE_ENV_PROXY=1` 和已校验的无凭据代理 URL，使 Node 网络行为与调用方配置一致；任意 `NODE_OPTIONS` 及业务凭据继续隔离。操作方式由[部署文档](../../../../docs/deployment.md#问诊自动记录原生验收)拥有，避免将验收进程的连接超时误判为病例预算或模型推理耗时。
