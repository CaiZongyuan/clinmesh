# Agent Note: 门诊与住院共享声明式药事规则

Status: implemented

## Problem

固定三药的两两联用白名单、总片数枚举与完整诊断身份匹配无法表达心血管多药治疗和慢病共病。同一 ICD-10 疾病在院内与不同参考版本有不同身份，完全匹配会拒绝具有相同适应证的诊断；分别扩展门诊、住院和前端的判断会使三个入口产生不同拒方结果。

## Decision

院内药品可声明 `safety`：药理类别、ICD-10 前缀与单次／单日极量。共享 contracts 保存边界 schema，core 纯函数拥有互斥、前缀匹配、剂量换算后的区间检查和频次时点。适应证以正式确认的 Condition 冻结编码为依据，避免 Reference Data 诊断在院内目录缺项或目录更新时被误拒。门诊及住院 Command 仍重读本次诊断、有效过敏与权威目录，在原事务边界返回细分原因；页面复用纯函数做输入检查并保留服务端最终审方权。

跨类联合采用默认允许、显式互斥的规则。数量极量与用法剂量分别校验，避免用固定总片数假定疗程。PRN 按最多每日四次审方，实际任务另受业务日次数与数量上限约束；计划本身不形成给药事实。ONCE 只用于临时医嘱。未声明新规则的旧配置继续按原合同执行，不静默覆盖自定义院内规则。

Hospital Baseline 持有默认常备目录及初始批次，PCI 准备按具体产品身份复用并只补缺，继续保留原库存与价格。当前药品目录、频次、执行和拒绝原因由[临床流程合同](../../../architecture/clinical-workflows.md#声明式药事规则)拥有。

## Alternatives considered

- 继续枚举每对允许联用药与每种合法总片数：新增一种药或疗程会放大配置数量，难以审查遗漏的临床组合。
- 全部药品直接接受任意诊断与正数剂量：无法稳定拒绝错误适应证、药理互斥与超过每日极量的用法。
- 在每个入口分别增加分支：容易出现页面可选但后端拒绝，或 HTTP 与 Agent Command 审方不同的结果。
- 覆盖旧自定义配置以统一行为：会改变已有药品限制、价格和库存语义，破坏 PCI 只补缺与幂等合同。

## Consequences

规则规模随药理类别和药品增长，门诊与住院的适应证保持一致，旧配置可渐进声明新规则。ICD 前缀与极量均为有界合成仿真规则，不能代替真实药品说明书或临床审方。整数制剂库存合同继续生效，安全区间内的分片剂量仍可能因缺少库存换算依据被拒绝。纯函数、临时 SQLite HTTP、非空迁移及 React 18/19 真实浏览器合同共同验证共享规则、拒方呈现和时点排程。
