# Agent Note: DRG 离线资料分发、无损精简物理储存与完整有序条件分组程序

Status: implemented

## Problem

CHS-DRG 3.0 参考资料既包含数百 MB 的多地区同内容副本、派生导出与逐行重复说明，又包含涉及联合手术、MDC 优先级、年龄／新生儿出生体重边界、创伤外层约束及特殊终端判定的复杂分组逻辑。若把离线资料直接混入临床 Reference Release 会让文件完整性核验被误认为业务已启用；若把原始数百 MB 目录提交 Git 或原样铺盘会造成仓库与常驻磁盘膨胀；若运行时直接执行外部 JavaScript 源码或仅靠成员编码表加病组名称启发式推断，则会引入不受控运行时代码或在组合操作与优先级边界上静默分错病组。

## Decision

将 DRG 参考资料的固定分发、无损精简储存与声明式条件分组程序分层解耦，当前合同分别见[DRG 条件分组](../../../architecture/drg-grouping.md)、[DRG 离线精简储存](../../../drg-reference-storage.md)、[FHIR 与参考数据策略](../../../architecture/fhir-and-commands.md)及[部署指南](../../../deployment.md)，完整原程序对照见[DRG 条件核验研究](../../../research/2026-10-25-drg-condition-verification.md)：

1. **独立离线资料清单与固定 Release 自动获取**：DRG 参考资料在 Reference SQLite 中拥有独立于临床目录的清单表与维护审计，默认保持离线核对用途而不自动启用分组业务。完整快照通过 GitHub Release 固定归档分发（Git 仅锁定 URL、规模与解析后规范 JSON 哈希以消除跨平台换行差异），开发与容器构建准备阶段先校验归档、拦截路径穿越与链接，再经单轮完整核验后原子安装目录并登记清单，失败保留旧版本不变。
2. **`clinmesh.drg-compact.v1` 逻辑与物理储存分离**：保留原始 manifest/checksums 对每个完整逻辑文件的逐字节权威 SHA-256（含 JSON 数字词法、字段顺序、BOM 与换行语义），通过锁定的物理储存索引表达多地区文件别名、内建派生配方、状态模板与原文页行引用（只维护当前精简格式见[DRG 只维护当前精简格式](../simplification/2026-10-25-drg-current-format-only.md)）。制包、安装核验（对缓冲文本惰性逐行解析以避免 Node.js 24 `readline` 迭代器重开异常）与按需显式导出共用同一无损只读读取器，常驻磁盘不物化重复派生副本。
3. **`clinmesh.drg-rules.v2` 完整有序条件编译器与封闭解释器**：维护期离线编译器使用 TypeScript AST 将来源分组程序的完整有序控制流、创伤外围函数结构身份及显式支持条件编译为受限声明式程序（拒绝变量遮蔽与未知语法，编译及装载期严格核验局部变量声明顺序、词法作用域与成员覆盖）；服务端启动仅装载经校验的 v2 规则包与受信审核文件，运行时不引入编译器也不执行外部脚本。分组解释器按 `Asia/Shanghai` 当地业务日期计算年龄与日龄，从正式 FHIR `Observation` 只读投影精确出生体重（范围比较符保持未知，不伪造精确克数），缺必要输入或主次编码不兼容时显式返回无法入组或无效输入，绝不用部分成员表兜底。

## Alternatives considered

- **直接将五目录与 OpenDRG 数据导入临床 Reference Release，或把数百 MB 资料提交主分支**：混淆离线核验与临床启用状态，污染源码仓库历史。
- **仅做相同哈希文件去重或按当前演示病组裁剪参考库**：前者无法消除派生文件与行内重复说明的高占用，后者破坏完整参考资料的无损字节可重现性。
- **运行时直接运行上游 JavaScript 或继续手工按病组名打补丁**：暴露宿主执行面，且手工特例无法在来源升级时逐条件捕获控制流与优先级漂移。

## Consequences

开发环境与生产构建可离线复用约百 MB 级无损精简资料并逐字节还原任意原始逻辑文件，分组内核在零 I/O 纯函数边界内完整复现原程序控制流（离线对照在隔离无 I/O VM 中独立验证全条件分类与终端命中）。来源程序升级或新增未编译语法时会在准备阶段确定性报错，须经维护者补充编译支持与离线对照后发布新不可变规则包。
