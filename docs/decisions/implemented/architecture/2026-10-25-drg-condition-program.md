# Agent Note: DRG 从成员表推断改为完整有序条件程序

Status: implemented

## Problem

CHS-DRG 3.0 的成员编码不足以表达联合操作、MDC 优先级、人口边界、创伤分区及特殊终端条件。按病组名称推断谓词会产生有病组编号却跳过必要条件的结果。锁定完整来源和文件哈希只能证明资料身份，不能证明计算正确。

## Decision

离线编译器把原程序的有序控制流及明确支持的条件编译成受限声明式程序；服务启动只装载经 schema、引用、覆盖和层级核验的 v2 规则包。未知语法和发生变化的未编译来源适配逻辑使准备失败，缺输入或不兼容主次编码使当前病例显式失败，不沿用部分成员兜底。实际合同由[DRG 条件分组](../../../architecture/drg-grouping.md)拥有。

来源程序只在显式离线对照时进入无 I/O VM，独立于生产解释器。固定合成输入及人工解释预期、完整条件分类和全部终端命中共同提供可复核证据；不宣称地方正式医保一致性或穷尽所有输入。

本决定替代[住院 DRG 仿真链决策](../feature/2026-10-23-drg-inpatient-simulation-chain.md)中的简化分组内核、MDC 回填与未消费新生儿参数的取舍。其双轨编码、归档冻结和受控核定仍有效。出生体重复用正式 Observation 的只读投影并冻结来源版本，不另建临床写入口；历史结果及回执保持原合同。

## Alternatives considered

- 继续扩展成员表并按病组名称加特例：不能维护主次顺序、组合条件和判定优先级的完整关系，容易在源升级后静默遗漏。
- 直接在服务执行上游 JavaScript：会把来源代码、宿主能力和来源适配行为带入运行时，无法形成封闭可验证的规则合同。
- 手工逐组重写全部规则：与来源形成第二套长期维护逻辑，难以逐条件检测漂移；人工解释更适合独立预期及关键边界验证。
- 只比较固定成人病例：无法证明新生儿、创伤、机器人、产科和联合条件支持，未采用。

## Consequences

规则包升级到 `clinmesh.drg-rules.v2`，旧不完整规则必须重新准备；历史持久结果不需要迁移。编译器使用维护环境已有 TypeScript AST，运行时装载路径不引入编译器。来源升级会显式触发新增语法或适配身份核验，维护者必须补实现和独立对照后生成新不可变规则身份。

原程序一致性、临床编码适用性、来源使用许可和本院支付参数是独立证据。本次保留既有来源隔离，不新增启动装载入口，也不替代 #279 的最终临床和资金联合验收。

## Verification

通过分组纯函数、规则包文件边界和临时 SQLite 上的住院 HTTP 验证正常、歧义、无法入组、缺参、来源失配、规则遗漏、编码不兼容及归档后规则变更。完整原程序对照及来源身份见[核验记录](../../../research/2026-10-25-drg-condition-verification.md)。
