# Agent Note: 护士实际执行事实与集中办理的分段结算

Status: implemented

## Problem

护士逐项记录给药、健康教育或发起 PRN 时需要重复进入和确认。直接汇总待办并全选会把尚未发生的动作写成完成；把 PRN 发起与给药混用又会跳过实际发药和给药核实。响应丢失及刷新还可能让已经发生的事实重复写入，或让迟到成功误删后来编辑的输入。

## Decision

三类动作分别使用独立清单、预览和确认，复用各自原 Command，不新增批量业务 API。给药与教育先逐项明确核实实际发生的事实，再允许选择；PRN 单独核对每项最终理由，只创建待执行任务。当前业务条件、数量上限与费用归属由[临床业务流程](../../../architecture/clinical-workflows.md#护士实际执行与-prn-集中办理)拥有，原计划与实际事实分离的决策继续有效，见[住院医嘱与给药](2026-10-21-inpatient-orders-and-administration.md)。

私稿只拥有人工输入、选择、核实与原尝试，不缓存一份平行临床状态。范围包含账号、完整 Actor、患者、住院和动作。冻结清单中的每项在发送前保存原 Operation、参数、预期版本、独立幂等键和原行修订；存储失败阻写。原 writer 继续拥有单个在途写意图及原回执查询，集中办理只负责有界编排与持久结算。

响应须证明本次原动作：给药核对原执行完成及本次 MedicationAdministration，教育核对原执行完成与对应服务费用；PRN 按本次创建的 Task 定位 pending 执行并核对医嘱及理由，不能以未递增的医嘱版本或历史同医嘱任务代替。成功先结算原修订，再清原写意图；清理失败仍恢复原尝试，不因成功行已移出私稿而生成新请求。确定拒绝保留输入和原因；未知停止后续项目，只有原回执明确不存在才原键重放，余项须重新核对。

服务端退出成功后，各私稿 owner 独立尝试清理；本地存储异常不改变服务端退出结果。清理未完成时，当前运行时隐藏原私稿并阻止写入，再次读取前先尝试完成清理，不能删除共享 writer 的原意图来伪装成功。补偿标记仅存于当前运行时，不作为跨页面重载的持久清理保证。

## Alternatives considered

- 对待执行任务直接全选完成：待办只证明存在执行计划，不能证明给药或教育已实际发生。
- 将 PRN 发起并入给药：发起仅产生 pending 任务，尚未完成发药与实际给药核实。
- 以医嘱版本递增或任意同医嘱任务证明 PRN 成功：原发起不递增医嘱版本，历史任务也不能证明本次写入。
- 先清写意图，再处理本地结果：清理之后若持久结算失败，刷新将失去已发生动作与原尝试的关联。
- 扩展新的通用批处理框架或后端批量状态机：当前原 Command 已拥有权限、版本、时点、幂等和完整事务；新抽象会重复业务 owner。

## Consequences

重复确认减少，逐项实际事实与 PRN 理由仍可核对。独立项目部分成功不回滚已发生的事实，未知结果阻断后项并恢复同一次尝试。公开 HTTP 验证唯一 Task、MedicationAdministration、费用和原键恢复，真实 Web 与 React18/19 ShadowRoot 验证三动作入口、逐项核实、原回执及对话框可达性；媒体绑定最终代码提交且只使用合成数据。
