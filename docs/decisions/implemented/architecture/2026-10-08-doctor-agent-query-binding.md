# Agent Note: 医生 Agent 纯查询免抄写绑定与聊天委托代问

Status: implemented

## Problem

门诊问诊与自动病历整理过程中，页面语义版本随每轮问答和草稿保存持续推进；若要求医生当前病例的纯只读查询工具也由模型手工抄写最新绑定参数，模型常沿用上一轮历史值导致连续只读查阅反复被拒。同时，医生希望直接在右侧「ClinMesh 医院助手」聊天框交代追问范围（将左侧输入框纯粹留给医患对话），但宿主消息的 `kind:user/rpcId` 可被注入构造，主会话模型的自述也不能作为已获医生代问授权的可信证据。

## Decision

针对医生当前接诊病例建立免抄写纯查询原点核对与聊天委托双阶段验证，完整协议见[Agent 集成](../../../architecture/agent-integration.md)：

1. **医生纯查询原请求核对与执行时绑定**：仅对当前接诊病例的一组白名单纯查询工具免除模型参数中的绑定抄写（内层剥离历史残留绑定字段后严格校验业务参数，问诊发送、草稿保存、栏目选择与 `.propose` 提案仍强制保留精确语义绑定）。Host 结合公开 Session header 与原生 `tool/call` 事件核对调用来源，签发同时携带原任务锚点（`taskEpoch`）与当前执行 `PageContext` 的读取 proof；Server 核对同一病例、当前责任医生与实时权限，病例快速切走再切回也会推进 `taskEpoch` 使旧任务失效，对象不明或目录损坏时立即失败关闭并提供基于当前可见只读定义的失配恢复诊断。
2. **右侧聊天原文签名凭证与独立无工具意图识别**：左侧问诊输入框仅向患者发送问题；医生在右侧医院助手聊天提交消息时，Client 观察公开 `SessionSnapshot.pendingSubmissions`，经当前有效 frame 取得原文签名凭证（v2）并向 Host 登记，Host 在首次执行医院工具前等待并核对 RPC、Session、正文哈希与病例目录绑定。随后 Host 使用原请求模型发起一次无工具、无病史与无会话上下文的独立结构化意图识别，仅在识别出明确当前代问委托及具体追问范围且逐字引用医生原文时才签发代问许可（本次委托识别调用纳入[统一模型调用账本](2026-10-21-model-usage-accounting-control.md)准入计量）。未知执行结果通过暂停请求立即终止原代问任务，绝不自动重放。

## Alternatives considered

- **继续提示模型抄写最新绑定或一律放宽为执行时最新病例**：提示词无法阻止模型复述旧参数，而无原点锚定的执行时绑定会把生成期间切换患者前的旧查询串入新病例。
- **在左侧问诊区并排保留“发给患者／交代助手”双按钮**：同一输入框承担两个对话对象，极易误发。
- **直接信任 `kind:user/rpcId`、关键词匹配或主会话模型自称已获委托**：公开注入通道可伪造相同消息结构，关键词无法区分否定与假设讨论，模型自填授权字段则会让历史或工具输出自我提权。

## Consequences

医生可在右侧自然交代追问或连续查阅病史、评分与指南，不再因草稿自动保存导致只读工具反复报绑定冲突。每次选定病例的新医院工具回合会增加一次轻量无工具意图识别开销；跨包升级须保持 Host、Surface 与 Server 的输入凭证及 `taskEpoch` 协议同步。
