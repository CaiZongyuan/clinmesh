# Agent Note: 门诊号发行高水位与恢复完整性

Status: implemented

## Problem

现存挂号数和最大号码不能证明历史上发行过的最高号码；删除最高号、清空业务行或重置 Epoch 后重建计数会复用旧号。把计数器放进一致备份仍不足以解决旧备份回退和克隆并行写入。历史迁移也不能因为当前业务行与历史投影数量相等，就假定未发生过删除。

## Decision

使用按业务日期、跨 Workspace/Epoch 的独立持久高水位，以及含发行权威身份、active/retired 状态和完整日期计数器摘要的单例。共享挂号 Command 在原写事务内验证完整状态、分配、投影 Encounter 并保存 Registration、业务关联和回执；失败一起回滚。摘要以日期排序的规范化计数器计算，既检测数值损坏，也使已建立日期的缺行与新日期首次使用可区分。业务删除、产品内 reset 和虚拟日期变化不清理发行事实。

存量初始化通过[专用迁移边界](../../../../apps/server/src/infrastructure/sqlite/registration-number-migration.ts)验证全部 Epoch 的审计序列、哈希链及持久头，并核对每条初始 AuditEvent 的内容哈希、操作和结果。审计链原格式未把 outcome 纳入链哈希，因此单独核对投影结果，防止把原成功发行误分类为失败。正常挂号与合成病例开始必须由审计中的 created Encounter 关联到初始 FHIR 历史及完整号码；全部现存 Registration 和有号 Encounter 历史反向匹配这些证据。已删除当前业务行但初始历史和审计仍完整时，可以恢复已证实的发行上界；任一必要证据缺失、损坏或来自未知发行路径都拒绝迁移。

旧版 reset 的重放调用共享挂号函数，但没有将重放产生的 Encounter effects 保存在 reset 回执和审计清单中。现存重放业务行只能提供下界，无法证明已删除重放号的上界，因此任何旧版成功 reset 均拒绝自动初始化。失败回滚当前迁移，保留旧号、内部 ID、原库和既有升级前备份；不将局部扫描结果标成可信历史。跨作用域既有重复号保持原值，新发行从跨作用域已确认的按日上界继续。

[受控恢复](../../../../apps/server/src/infrastructure/sqlite/database.ts)显式要求同一身份的可信最新发行权威库。候选先从备份通过 SQLite backup API 创建并验证，随后在最新源的写锁内读取高水位、提交退休，再把备份与最新源的逐日高水位取大值并激活候选。运行中的旧连接也必须在每次发行时读取退休状态，不能继续写号；同一退休源不能再次转移到第二个目标。退休后失败保持停止发号，保全旧源而不自动重新激活；当前没有自动修复此状态的入口。

当前合同及操作步骤分别由[存储与事务](../../../architecture/storage.md#门诊号发行状态)和[数据库运维](../../../demo-architecture.md#database-operations)拥有。完整性摘要和审计链用于识别证据缺失及意外损坏，不抵抗有权同时改写数据与校验值的管理员；无法证明当前唯一权威时拒绝受控恢复。任意文件复制、对旧快照直接改启动路径，以及独立克隆并行写入不属于自动识别与全历史唯一保证。

## Alternatives considered

- **按现存最大号初始化或运行时补表**：无法覆盖删除最高号和全删业务行，会将缺失发行事实误当成首次使用。
- **只读取 FHIR 历史或 Command 回执**：这些表没有发行总量的完整性头；必须先用完整审计证明每次发行，再反向核对资源，不能把扫描得到的最大值当作证据完备。
- **接受所有旧 reset 并扫描剩余重放资源**：旧流程没有完整发行清单，无法排除最高重放号连同相关业务事实已删除，拒绝推测上界。
- **只备份计数器并恢复旧文件**：备份之后已发行的范围会丢失。必须同时保留可信最新权威，并在新目标激活前停用旧权威。
- **外部集中发号服务或全历史发行日志**：可支撑更大的多写权威和灾难恢复范围；当前单 SQLite 写权威使用持久高水位、完整性清单和受控移交即可满足已批准范围。

## Consequences

迁移和恢复宁可拒绝发行，也不把证据不足解释为安全重置；已有数据可保留用于后续核验。原业务查询权限仍以 Workspace/Epoch 隔离，共用发号器不扩大读取范围。旧备份恢复需要保留最新发行权威，完全丢失最新证据时无法自动恢复发号。

[历史迁移测试](../../../../apps/server/tests/registration-number-migration.test.ts)覆盖多作用域、日期、历史重复号、保留初始历史与必要证据缺失；[恢复测试](../../../../apps/server/tests/registration-number-recovery.test.ts)覆盖旧备份与最新高水位合并、原写者停用、身份不符、丢失计数器及退休后的持久化失败。[数据库生命周期测试](../../../../apps/server/tests/database-lifecycle.test.ts)继续验证显式迁移、备份一致性、损坏候选、CLI 和真实 file-backed SQLite 合同。
