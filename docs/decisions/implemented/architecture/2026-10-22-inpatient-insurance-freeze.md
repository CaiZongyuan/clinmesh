# Agent Note: 住院首次结算冻结患者医保分摊

Status: implemented

## Problem

住院原账以现金与预交金结清总费用，归档也以现金合计核对费用。患者医保加入后，基金和个人账户承担部分费用；继续按总费用收款会多收，继续只按现金归档会拒绝正确的组合结算。结算后待遇补偿还可能改变当前医保账，不能因此改写已经审核的首次结算与病案来源。

## Decision

正式住院费用是医保来源的唯一 owner。首次结算使用有效待遇的患者负担计算资金差额，预览绑定逐项费用、待遇及资金指纹；未知收退款阻止本次待遇变化和首次财务完成。结算快照保存完整原待遇及来源，病案归档核对冻结患者现金、基金和账户之和与冻结费用一致，后续待遇变化不参与首次冻结来源。

当前合同由[住院医保与首次冻结账](../../../architecture/clinical-workflows.md#住院医保与首次冻结账)拥有。公开 HTTP 验证两套合成方案、未知组合补缴及原尝试恢复、撤销后重审和医保组合账归档。

## Alternatives considered

- 以总费用继续收款，再由医保处理独立退款：会在首次结算重复收取患者已经由基金和账户承担的费用，且难以解释当前资金门禁。
- 病案始终读取当前有效医保待遇：撤销补偿会改变已审核来源，使后续财务更正反向影响原归档事实。
- 只冻结待遇总额：无法核对原费用、逐项分配及来源版本，不能识别合计相同的明细漂移。

## Consequences

患者医保与资金分别落账，原住院的行政及临床完成状态保持自己的含义。首次结算及归档保存的医保引用需要随持久化 schema 保真读取；后续更正必须在独立调整链展示当前待遇和患者收退，不能更新原冻结快照。
