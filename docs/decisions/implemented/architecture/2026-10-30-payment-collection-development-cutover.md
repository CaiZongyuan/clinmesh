# Agent Note: 共享收款开发切换保留来源资产并重建完整运行链

Status: implemented

## Problem

门诊与住院已经通过共同内核记录新收款，旧合成交易仍存在于停用结构。仅删除旧资金会使已经放行的临床进度、首次结算和病案冻结失去依据；删除整个 operational SQLite 又会丢失患者来源、账号配置、发行权威及模型用量。普通 Epoch reset 保留旧世代，无法完成旧结构收口。

## Decision

提供明确的一次性 `db payment-cutover` 维护入口，在经验证的备份之后，以一个 SQLite 写事务完成旧关联运行链舍弃、新活动 Epoch、配置复制、库存耗用回补和旧交易结构移除。保留来源资产及独立审计，原运行 Epoch 关闭为保留身份的壳，病例恢复可从岗位重新开始的生命周期；保留与舍弃清单及报告校验由[存储合同](../../../architecture/storage.md#共享收款的一次性开发切换)拥有，具体操作及失败恢复由[部署指南](../../../deployment.md#共享收款的一次性开发切换)拥有。

普通升级遇到旧资金时拒绝而不清理。已完成切换或已经产生新模型交易的库拒绝再次执行舍弃；已有新资金且没有旧资金的库使用普通迁移保留原事实。发行权威、高水位、模型用量及额度不因开发例外回退，独立 Reference 和 Guideline 库不参与本次写入。

保留校验按稳定行序比较身份、数量和内容摘要，Case 仅允许生命周期状态、revision 和更新时间变化；配置在确认原内容完整后复制至新世代。未知表、排队或运行中的来源任务、源状态在备份后变化或完整性校验失败都拒绝提交。报告只输出数量、摘要及世代身份，不输出来源正文或凭证。

## Alternatives considered

- 迁移旧合成交易或保留两种格式的读取适配：可以保真访问历史资金，但需要持续维护旧状态和引用。当前阶段允许重跑合成就诊，选择一个交易权威并删除停用结构。
- 仅清除资金记录：重建范围较小，但旧放行、结算及归档仍依赖已经舍弃的资金，无法解释其完成依据。
- 删除整个业务库：操作简单，却同时丢失与运行事实共库的来源资产和跨 Epoch 状态，不符合保留边界。
- 仅调用现有 Epoch reset：能够拒绝旧意图，但继续保留旧运行事实及 schema，不能替代本次显式结构切换。
- 在启动时自动清理：减少维护步骤，但普通启动可能意外丢弃新资金或来源资产。保留显式确认和备份，使舍弃范围可核对。

## Consequences

旧合成运行事实需要从原岗位重新建立，不能读取或恢复为新格式资金。新模型成功交易、未决尝试、退款引用及回执仍须持久恢复，开发切换例外不授权后续升级丢弃数据。

失败保持原文件及诊断备份，数据库事务整体回滚；旧 schema 备份供匹配历史 release 的诊断和受控恢复使用，不能直接交给要求当前 schema 的恢复入口或据此退休最新发行权威。维护窗口必须停止全部写入，备份与原库不能作为两个独立 writer 启动。本地原子性不表示真实外部渠道能够随数据库回滚。

验收使用包含旧交易、关联运行事实和保留资产的非空合成临时库，核对清单、保留摘要、新世代隔离、故障回滚以及岗位重建；最终新模型继续复用两端共享资金合同和 PCI 联合账本验证重启恢复、资金隔离及冻结门禁。历史资金 schema 的保真测试固定到本次切换前，不能被误读为新模型兼容旧交易的承诺。
