# Agent Note: DRG 完整逻辑资料与常驻物理储存分离

Status: implemented

## Problem

完整离线快照包含相同内容的多地区副本、可重建导出及逐行重复说明。直接删除旧清单内的文件会破坏完整性与来源保证；安装后重新展开全部旧路径也不能减少常驻磁盘占用。正式目标见[规格](../../../spec/2026-10-25-drg-compact-storage.md)。

## Decision

原 manifest/checksums 保持完整逻辑文件的权威哈希，新增锁定的物理索引表达别名、内建派生配方及状态模板、原文页行引用。每个原文件仍必须重建为相同字节；JSON 数字词法、字段顺序、BOM 和换行属于兼容合同。保留完整 records、原文页和所有成员，不按编码、地区或当前运行消费范围删减数据。

制包、安装核验和显式导出使用同一只读读取器。安装不物化派生副本，不使用链接，也不缓存跨运行的核验成功。每次准备重新校验物理对象、完整逻辑文件集合和既有语义清单，只有全部通过后才原子安装和登记。当前格式、命令及路径合同由[储存合同](../../../drg-reference-storage.md)拥有。

新格式使用新 inventory、归档及分发锁，旧发行快照保持原身份。安装格式的支持范围由[当前格式决策](../simplification/2026-10-25-drg-current-format-only.md)取代。此决策扩展[自动分发决策](2026-10-22-drg-reference-distribution.md)的物理表达；该决策的自动准备、失败保旧、check-only 和运行用途隔离继续有效。

## Alternatives considered

- 只保留哈希完全相同的一个副本：无法消除派生导出和重复来源字段，占用仍明显高于目标。
- 只做约 414 MB 的别名及派生文件精简：实现较简单，但 readiness 状态和成员来源的全量可逆性已能校验，因此本次同时完成模板及页行引用。
- 每次安装恢复所有旧文件，或用硬链接、符号链接兼容旧路径：恢复副本会失去常驻节省；链接增加归档、跨平台及安全边界复杂度。
- 只验证 JSON/CSV 语义相等并更换原文件哈希：会放弃旧快照逐文件字节追溯，使格式差异与事实差异难以区分。
- 按当前读取子集拆分默认资料：改变完整资料覆盖和产品用途，不能计作本需求的无损精简。

## Consequences

读取少量文件会承担重建成本，维护者需要通过显式导出取得旧文件。共享规则汇总及原文页在单次核验内复用，避免反复解析同一依赖；原逻辑结果不永久写入安装目录。新增索引和模板计入实际常驻体积，下载节省独立测量，不从解包规模推算。

使用合成 fixture、临时 SQLite 和受控 HTTP 验证读取、导出、首次及重复安装、损坏恢复和失败保旧；真实资料逐文件核对旧 SHA-256，并另行测量归档及安装结果。全部使用限制和缺参保持不变，格式精简不构成临床或支付运行授权。
