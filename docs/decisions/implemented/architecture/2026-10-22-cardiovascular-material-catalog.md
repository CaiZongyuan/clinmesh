# Agent Note: 心血管耗材来源价格与可收费项分开表达

Status: implemented

## Problem

现有耗材 schema 要求每项都有收费定义及单位，而固定来源的 231 条心血管记录有 179 条未提供单位、全部缺规格。用假单位或零元收费填满合同会使缺少计价依据的记录进入实际手术账；另建通用参考数据发布系统超出本次固定目录需求。

## Decision

归一化公开来源快照由仓库拥有并校验，和原两项合成耗材共用 `inpatient_surgery_catalog` 的 material 行。Scenario 的既有补缺 seed 在当前及新 Epoch 安装，稳定 ID 以固定工作簿行定位，不按产品名称合并，也不覆盖已有 ID 的配置。原工作簿、来源附件与本地路径不进入仓库。

目录合同允许已配置合成本院收费的条目，以及因单位未确认而不可收费的条目。原可收费 schema 保留原字段及可选 reference，实际实施和旧 receipt 继续使用可收费 schema；缺单位项只有完整参考价格与来源，没有 ChargeDefinition。执行事务显式拒绝后者，不将参考价格或零值当成收费依据。

表内中选价与拟供应价、地区、日期和原字段分别保存。明确单位的 52 条按中选价制定合成演示收费，来源中的历史及未核实限制继续保留；它不成为真实医院现价声明。当前业务合同见[临床流程](../../../architecture/clinical-workflows.md#82-住院闭环)，独有验收见[规格](../../../spec/2026-10-22-cardiovascular-surgical-materials.md)。

持久目录采用固定 `cardiovascular-columns-v1` 列顺序保存本行全部17个原字段、对应来源组全部12个原字段、价格分值、规范日期及文件定位，减少重复键和可推导字段带来的SQLite页增长。读取只从本条已持久值展开完整DTO，实际实施仍冻结完整对象；历史完整JSON继续可读，不依赖当前静态资料补旧来源。性能基线仅为新增231行同步确定性行数与写语句上限，原数据库增长门槛保持不变。

Web 从可收费项选择，只为已选材料生成用量输入；CLI 目录返回全部记录并暴露不可用原因，不增加全量管理页。目录查询 operation 升为 v2，实际实施输入和旧响应快照保持兼容。

## Alternatives considered

- 只收录有单位的记录：丢失已确认要保留的 179 条来源和价格。
- 为未知单位填“个”或将价格置零：制造可执行但没有依据的收费定义。
- 直接替换原两项材料或覆盖目录价格：会改变既有院内配置；实施历史应继续使用冻结快照。
- 扩展 Reference Release、动态 Excel 导入与管理界面：固定快照和既有 seed 已满足此次可重复安装需求。

## Consequences

新数据增加每个 Epoch 的目录行数与存储，性能写入基线须与实际 seed 核对。已实施记录仍冻结耗材、用量、单价和来源，重启补齐不会改写既有事实。单位补齐、参考表更新及调价须另行明确，不能借启动自动覆盖历史目录。
