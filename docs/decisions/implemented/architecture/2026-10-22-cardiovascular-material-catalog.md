# Agent Note: 心血管耗材目录分层计价与住院共享目录前置准备

Status: implemented

## Problem

公开采集的 231 条心血管介入耗材来源记录中有 179 条缺少计价单位且全部不含临床规格，若强行填入假单位或零元单价会让无依据条目混入正式手术账单，若直接丢弃又会损失已核实的来源价格对照。同时，住院药品、检验与诊断若复制全量参考库或继续使用固定剂量枚举筛选，会导致跨库分页失真、缺配置项目无原因提示或剂量与整数库存制剂单位脱节；而将 PCI 目录准备直接绑死病例物化又会在准备阶段产生非预期的挂号与收费副作用。

## Decision

在同一套主数据与手术目录表内严格区分参考来源与可执行院内配置，并将 PCI 基础资料准备设计为无临床副作用的幂等前置命令，当前业务合同见[住院与手术流程](../../../architecture/inpatient-workflows.md)与[处方、医嘱与药事](../../../architecture/orders-and-pharmacy.md)：

1. **耗材参考来源与可收费项显式分层及紧凑存储**：归一化公开来源快照与合成耗材共用 `inpatient_surgery_catalog` 的 `material` 行，按固定工作簿行生成稳定 ID 补缺安装而不覆盖既有配置，以固定列序 `cardiovascular-columns-v1` 紧凑持久化全部原始字段、中选价／拟供应价与文件定位以控制 SQLite 页增长。目录 schema 显式区分两类状态：明确单位的 52 条配置合成本院收费定义（`ChargeDefinition`），供 Web 选择与手术实际计费冻结；缺单位的 179 条仅保留完整参考报价与出处，无 `ChargeDefinition`，CLI 查询公开其不可用原因，手术执行事务严禁将其按参考价或零元入账。
2. **院内与参考目录分库分页及纯函数剂量换算**：药品、检验与诊断在院内目录与独立 Reference SQLite 各自有界分页，候选明确标注未启用或缺项原因，正式开立仅接受完整院内配置身份（住院检查计费沿用 `inpatientInvestigationBilling` 服务与版本快照兼容结构）。住院给药由医生输入本次剂量，前后端共用纯换算函数按明确制剂含量、每次上限与整数库存制剂单位校验（跨门诊／住院的药理类别互斥、适应证前缀与单日极量扩展见[共享声明式药事规则](2026-11-13-shared-medication-safety.md)）。
3. **无临床副作用的幂等 PCI 目录准备**：管理员通过当前 Epoch 的共享 Command 原子补齐固定版本与内容哈希的 PCI 院内目录、合成单价与初始库存批次；重复执行保留已发生的库存消耗与既有业务事实，且不自动触发患者物化、挂号、发药或计费（多病例底稿与模板 Persona 准备由[通用 Authored Case Pack 编译器](2026-11-19-authored-case-pack-compiler.md)独立承接）。

## Alternatives considered

- **只保留 52 条有单位耗材，或为其余 179 条填默认单位“个”／零元价格**：前者丢弃已核对的集采价格参考，后者制造无真实计价依据的可收费假象。
- **合并院内库与 26 万条参考库全量内存排序分页**：查询成本随参考库膨胀且分页总数语义失真。
- **在服务启动或目录准备时自动物化演示住院病例并预扣库存**：混淆基础目录配置与岗位实际医疗行为，破坏从零岗位交接验收边界。

## Consequences

每个 Epoch 幂等持有完整心血管耗材参考与可计费子集，已实施手术永久冻结当时的耗材、单价与来源快照，后续目录补缺或调价不回写历史账目。合成演示单价与固定规格依据（见[单次耗材预计决策](2026-10-28-single-material-estimate.md)）仅服务仿真闭环，不代表真实医院现行采购目录或器械说明书。
