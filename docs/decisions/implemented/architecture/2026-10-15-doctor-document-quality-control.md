# Agent Note: 病历质控的输入归属与人工处理

Status: implemented

## Problem

自动整理的写入前来源校验只覆盖本次整理增量，不能代表整份病历没有缺项、遗漏或矛盾。整理控制版本只随控制动作变化，不能识别正文保存、未保存编辑或来源新增。Agent 直接设置病历草稿又与人工保存共用入口，单靠自动整理片段无法判断所有 Agent 新增事实的来源。

## Decision

自动记录的来源语义、旧事实保留、关系及拒绝事实重现检查由[统一质控决策](2026-10-19-recording-quality-consolidation.md)补充；沿用本决策的生成、独立复核、同输入复用和签署汇总。

字段与签署汇总的待补充提示、依据入口展示范围由[安静质控提示决策](2026-10-18-quiet-document-quality-hints.md)取代。

实时质控读取全量既往资料的范围由[本次就诊输入与安静记录决策](2026-10-18-current-encounter-quality-and-quiet-recording.md)取代；历史批量读取仍用于诊疗建议。界面的人工核实入口由[仅提示与直接编辑决策](2026-10-18-advisory-quality-without-confirmation.md)取代；本文继续拥有质控输入、授权、已有处理数据与公开协议的兼容边界。

按[批准规格](../../../../docs/spec/2026-10-15-doctor-document-quality-control.md)建立独立的病例质控状态，复用现有 Command、outbox、模型绑定、输入哈希与授权校验。检查输入绑定实际候选正文、已保存草稿版本和可见来源；未保存候选只用于检查，不隐式写入临床草稿。持久任务完成前重新核对输入和授权，旧代次、旧来源或旧 Epoch 的结果不成为当前结果。

模型任务按完整临床输入指纹持久化在同一质控表的内部 `input:` 保留命名空间。指纹包含病例、完整授权上下文、Workspace/Epoch、正文、来源、Agent 内容归属和策略版本；排除只用于版本绑定的草稿版本与内部任务指针。已保存入口和未保存客户端分别保存自己的版本绑定，解析同一规范任务的成功、在途或失败结果；保存同正文不会再付出模型检查，迟到结果只更新自己仍有效的规范代次。旧的无指针状态继续可读，指针不由 HTTP 调用者提供，也不成为临床事实。

客户端只在 QueryClient 生命周期内保存请求身份元数据，服务端结果仍由 TanStack Query 管理；正文与相关来源决定请求身份，病例工作流计数、记录进度和导航不参与。未保存正文恰好等于持久草稿时使用已保存检查；真正的候选继续保留独立版本。页面卸载不取消已经发出的检查，缓存网络失败也不在重挂时自动重试。最终失败只由医生明确重试推进规范任务代次，其他绑定不会借导航或保存重新启动它。

失败状态保留生成或独立核验阶段及有限安全原因，格式、结构、来源、检查范围和覆盖错误分别进入具体纠正反馈；不持久化或展示模型原文与异常正文。DSH SDK 的当前文本流能力不被包装为原生结构化输出；项目沿用单个 JSON 数据对象、严格验证和既有有限纠正 deadline，合法语义否定保持正常结果。完整输入超限直接标记不完整，不以分批截断制造通过结论。

格式指令与 schema 使用相同条件：空字段不存在可引用原文，缺项条目省略可选 documentQuote，不返回空串、null 或虚构引文；独立核验对否定候选也返回相同 index 和 supported:false，只有输入候选为空才能返回空数组。策略版本随这些条件推进，旧任务不复用不同指令下的结果。当前宿主公开 seam 可声明 Tool 参数但不能强制选择或严格约束，增加数据 Tool 也不能宣称获得原生 JSON 保证，因此保留不执行 Tools 的辅助调用边界。

生成请求按当前正文收窄缺项 schema：只允许核心模板的实际空字段，非空主诉的内容建议必须带正文引文；可选字段和其他非空正文不能作为通用缺项。遗漏和矛盾仍可覆盖全部字段，并继续接受相同的独立来源与语义校验。范围或引用错误的纠正反馈带具体候选及引文索引，指令明确患者、医生和报告来源必须逐字引用完整原句；仅有错误代号与集合路径不足以说明哪条引用或范围需要纠正。服务端仍以既有完整校验决定结果，不静默过滤无效候选，不增加纠正次数或 deadline，策略变更使旧失败缓存失效。

确定性规则校验适用模板和引用归属，语义问题必须带可复核的正文位置、原文和时间。Agent 直接设置的新增内容保留其归属；客户端声明的来源不是可信事实，仍需服务端核对引用及语义。人工文本不因没有引用被归为 Agent 无来源内容。

医生核实保留的决定绑定该问题的相关正文和证据，记录处理人、时间及选填原因。重算复用仍然适用的决定；相关事实变化后重新核对。该决定不成为患者事实，不自动修改病历或解除原有签署门禁。

签署预览显示其实际正文的质控摘要以及尚未完成、过期或失败状态。质控任务完成不改变预览正文，也不单独让预览失效；新的提示不要求额外勾选或阻断正式签署。

正文只为当前具体待处理问题显示一条医生可理解的短提示，多处问题按需展开；影响、处理建议、依据、已核实历史和检查状态统一放入说明。没有具体问题时隐藏质控块，检查未完成、过期或失败仍在说明内保留真实状态；隐藏不是检查通过，签署预览也沿用此展示边界。

问题定位只响应医生点击，限定当前病历的对应字段，滚动并聚焦输入框。只有该字段内唯一、精确匹配的病历证据原句才建立选区；空字段、已编辑原文、重复引文或异字段证据仅定位当前字段，不猜测文字位置。定位不保存、修改正文或采纳自动整理，说明关闭后的延迟定位还绑定原病例与授权范围。

十字段直接记录与变动提醒继续拥有病历录入体验，质控的依据与核实保留仅属于独立问题，不恢复自动整理的逐条确认、来源或撤销界面。质控后台任务使用独立的医生任务授权校验，与自动记录共享身份、Workspace/Epoch 和 Grant 有效性验证，分别保留窄操作白名单。

只读病例思路、分类限制与具体质控说明的增量取舍见[临床说明决策](2026-10-16-clinical-explanations.md)；可采纳建议、编辑与签署合同保持各自归属。

## Alternatives considered

- 直接把质控加入诊疗建议的 kind：该输入强依赖目录和指南，且不包含尚未整理的医生补充，无法准确表示纯文书质控。
- 复用整理控制版本作为检查版本：控制版本不涵盖完整输入，会接受旧正文或旧来源的结果。
- 为实时质控自动保存编辑：改变现有显式保存语义，可能提交或覆盖医生尚未决定的内容。
- 永久忽略某类问题：相关事实更新后仍可能压制有效提示，不能代替对具体证据的人工核实。
- 让模型检查结果成为签署门禁：超出本期范围，也无法保证医学判断正确。
- 用系统检查状态常驻提醒医生病历有问题：检查能力和具体文书问题含义不同，因此状态按需查看，正文只显示可处理的问题。
- 按旧字符偏移选中问题：未保存编辑会使偏移指向无关内容，因此定位时重新核对当前字段的唯一原句。
- 让组件挂载身份直接创建候选任务：导航会改变 clientId，且无关详情变化会推进版本，因此请求身份独立于挂载，临床任务按完整输入复用。
- 把共享在途状态复制到多个独立队列行：原任务被刷新或失效后，副本可能永久停在处理中，因此入口保存规范任务绑定而不复制执行所有权。
- 把所有校验异常归为 JSON 解析失败：会向医生和纠正请求提供错误原因，因此保留安全类别；不通过放宽来源验证让格式恢复看似成功。
- 每次质控按分页列表逐条读取历史：即使不等待模型，也会在患者切换和轮询时重复数千次 SQL；复用当前授权索引的批量读取可保留相同资料与权限。

## Consequences

语义核对仍会误报和漏报，不能把空提示列表标为全面临床或监管合规通过。不同时间的事实变化、来源中的否定与不确定性必须保留；输入超出单次检查能力时说明不完整，不以静默截断给出通过结论。官方条款的门诊适用边界由[研究记录](../../../../docs/research/2026-10-15-outpatient-record-quality-rules.md)拥有。

公开 HTTP、真实 SQLite 与外部模型网络边界拥有语义、来源、版本、幂等、权限和恢复矩阵。真实 Web、React 18/19 ShadowRoot 与原生 DSH 拥有输入保留、键盘依据、核实与签署集成；测试入口由[测试策略](../../../../docs/testing.md)维护。

596 条历史的当前 HTTP 回归验证实时输入范围及读取开销，具体合同由[本次就诊输入决策](2026-10-18-current-encounter-quality-and-quiet-recording.md)拥有。SQL 数量提供不依赖机器速度的回归门禁。
