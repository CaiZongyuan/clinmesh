# Agent Note: Agent 页面操作柔光反馈与人工编辑控制边界

Status: implemented

## Problem

DSH 原生会话在操作 ClinMesh 表单并发起原位人工审阅时，仅凭连接在线状态无法向用户表明当前正在执行哪项页面动作；若逐个输入框绘制流动边框会产生视觉杂乱，若人工审批与提交阶段也维持相同动效则会混淆 Agent 操作与人类最终责任；同时，仅读取服务端已保存草稿无法反映用户正在输入框中编写但尚未保存的内容。

## Decision

将真实工具生命周期事件、工作区边缘柔光与挂载表单结构化读取组合在同一客户端边界内，操作与时序合同见[产品内 Agent 能力指南](../../../agent-capabilities.md)：

1. **真实调用级事件与单画布环绕柔光**：页面 Tool 包装器直接从真实授权、动作返回与审阅状态发出调用级事件，Web 适配器通过固定版本 `ai-motion@0.4.8` 在当前可见工作区（或打开中的目录弹窗 Portal 内）维护单个透明中心 WebGL2 边缘柔光 Canvas，并以静态淡边框和菱形标记指示可见目标。仅非 `.propose` 的真实 `executing` 动作驱动柔光流动；提案准备、等待人工审阅、人类批准提交、拒绝及完成停留均为静态状态，执行结束立即停止持续绘制并在淡出后释放 GPU 资源（快速合并帧至少保留一帧静态完成态，减少动效偏好或无 WebGL2 环境自动降级为静态边缘）。
2. **精确落点计算与页头分类计数**：病历填写在动作入口按当前病例与字段 ID 对比输入与现值，仅记录变化字段选择器而不复制病历文本；问诊动作记录执行前已挂载消息 ID 基线，只高亮本次新增气泡。页头状态摘要分别统计正在执行（含提案准备）、待确认、人工提交中与需查看数量，按需展开详情，不常驻铺开操作流水。同会话内工具重注册产生的瞬时 `connecting` 或病例详情加载中的空档不提前清空有效反馈，切换会话、岗位、患者或卸载则立即清理视觉状态（不冒充取消已发出的服务端请求）。
3. **无独占锁的挂载表单结构化读取**：表单组件显式注册结构化当前值，页面只读工具仅合并同页、同病例且仍挂载的未保存输入，既不开放任意 DOM 选择器抓取，也不引入输入遮罩、模拟逐字打字延迟或服务端并发编辑锁。

## Alternatives considered

- **从连接状态或对话流文本推断动画，或让人类批准提交继续维持流光**：前者在空闲时误报动作、复制宿主职责，后者把人类医疗确认误导为 Agent 自动执行。
- **延续逐字段流动渐变或仿照外部工具加全屏输入遮罩与模拟点击延迟**：多字段流光干扰临床阅读，遮罩与人为延迟则阻碍医生随时接管编辑并扭曲真实业务时序。
- **开放任意 DOM 快照工具读取未保存内容**：失去可靠的岗位与病例隔离边界，改由业务表单显式声明结构化状态。

## Consequences

视觉层清晰区分“Agent 正在操作页面”与“等待或执行人类审阅决定”，且不复制业务状态机、不阻塞键盘指针输入、不新增持久化数据；执行动画结束不代表未知回执已落库。用户可在 Agent 操作期间随时编辑，但系统不承诺多写者自动合并或防覆盖锁，正式医院事实仍由共享 Command 版本校验与人工审阅门禁保护。
