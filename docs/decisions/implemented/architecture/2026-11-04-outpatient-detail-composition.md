# Agent Note: 门诊细节组合保持真实数据与交互生命周期

Status: implemented

## Problem

门诊队列、开具窗口和窗口岗位已有真实业务状态，但相似信息各自组合，导致号码位于卡片边界外、重复金额与审核信息占据主流程。医生队列虽然使用共享 Tabs，完诊病例库与在诊工作台的树切换仍会重建滑块，声明过渡样式不能保证实际滑动。需求由[门诊细节规格](../../../spec/2026-11-03-outpatient-detail-polish.md#门诊细节对比方案)拥有。

## Decision

医生、分诊和药房通过 `QueuePatientRow` 复用患者行的展示边界。姓名与状态、补充信息和完整业务号码按相同顺序组合，复制操作与选择操作分别保留原可访问名称及可信对象绑定；组件只拥有外观，不读取业务接口或复制服务端状态。

`DoctorWorkspaceScope` 持有唯一的导航宿主和共享 Tabs Portal。在诊工作台与完诊病例库保留各自卸载行为，导航插槽只接入同一宿主。宿主接入 DOM 后才首次挂载导航，避免 Base UI 在断连状态测量并隐藏指示器。插槽交替时，经同作用域内保持连接和布局的屏外容器使用 `moveBefore` 搬移，保留 CSS 过渡与焦点；普通 detach/append 或隐藏容器都会取消过渡。

宿主的插槽和暂存容器都属于同一行动身份作用域，由其 DOM 生命周期统一清理。额外的仅清理 Effect 会在 React 18 开发 StrictMode 重放时移走仍需使用的宿主；React 19 的 ref 重放可能掩盖该问题，因此同时验证两个版本的开发模式。浏览器缺少 `moveBefore` 时回退为 append，保留选择功能，动效连续性以支持该 API 的浏览器为界。

住院证保持单栏真实病区与原因，病例上下文来自当前正式信息，底栏与开具窗口一致。检查详情复用标题、编码和事实表，价格继续来自已有门诊价目投影；短目录按内容收缩，长目录仍受最大高度与独立滚动约束。收费与药房压缩重复展示，金额、人审快照、批次身份及未知回执继续由原合同拥有，当前行为见[临床 UI](../../../ui/design.md)。

## Alternatives considered

- 只加长指示器过渡：指示器已被重建，没有可供过渡的上一位置。
- 新建医生队列滑块：复制已有共享组件，增加两套行为与键盘合同。
- 为保留导航而常驻两个业务工作台：连带保留查询、草稿与主操作，超出导航的职责。
- 提升整个业务布局到共同父级：能够稳定导航，但牵动病例控制器和病例库的完整组合。
- 只保留 Portal 或 DOM 实例后重新 append：React 身份可保留，浏览器 CSS 状态与焦点仍会重置。

## Consequences

导航的生命周期与业务页面的生命周期分别由各自所有者管理，行动身份、Workspace、Epoch 或岗位变化会建立新宿主。React 18/19 合同测量真实渲染帧中的中间位置、DOM 连续性、焦点与减少动效，开发模式另验证 StrictMode 重放；定时器到达 60ms 不代表浏览器已推进动画时间线，应通过渲染帧取样。

表单、查询、Command、版本、幂等和人工确认保持原归属。组件测试验证名称点击、可访问描述和实际操作，浏览器验证长号码边界、输入空间、表格溢出和次级入口；源码中的类名或截图数量不替代结构验收。
