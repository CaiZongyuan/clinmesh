# Agent Note: 住院工作台按患者与阶段组织

Status: implemented

## Problem

住院登记、医嘱、检查、手术、出院和病案分属不同岗位。把这些表单纵向堆叠会使患者上下文离开视口，也不能说明当前任务和后续交接；直接照搬内存原型的线性状态机会与真实权限、并行医嘱和独立财务状态冲突。

## Decision

工作台选择患者后持续显示真实住院号、床位、行政与财务状态，以及当前岗位可读取的费用。阶段导航将入科、诊断医嘱、检查、手术、费用、出院和病案分开，按入院、在院、出院、病案分组；阶段主线状态由住院登记的服务端字段推导，以装饰标记区分已完成、进行中、待办与已关闭——检查、手术、转科在出院后未发生时标为已关闭而非已完成，费用按实际结算收口，归档后全部收口；住院日由场景虚拟时间与实际入科时间计算，场景时间不可读时隐藏。默认阶段由住院状态与当前岗位决定，每阶段给出负责岗位、前置条件与下一办理位置。新住院证的登记交接提示在关闭弹框后仍保留。详细界面合同由[UI 设计合同](../../../ui/design.md#住院工作台)拥有，独有验收见[住院规格](../../../spec/2026-10-20-inpatient-closed-loop.md)。

未访问阶段不挂载患者业务详情；访问后保留组件并由 Tabs 隐藏非活动面板，使未提交输入、主操作选择基线和显式冻结的结算预览继续存在。服务端状态仍由 TanStack Query 持有，阶段及访问状态仅用于本地视图；正式操作继续复用共享 Command 与原写入意图恢复。

独立 Web 的住院、登记、收费和药房外层固定为视口高度，阶段内容自行滚动，患者横幅位于滚动面板外。DSH Surface 使用宿主提供的高度和 portal，不新增助手或改变宿主布局。药房、收费与登记仅展示各自窄 DTO 中已知的事实；已有床位 ID 但目录尚未取得时显示未知标记，不宣示未分床。

## Alternatives considered

- 保留长页面并增加目录锚点：跳转后仍会丢失患者上下文，也不能清楚表达岗位交接。
- 每次换阶段都卸载表单：未提交输入和冻结预览会被重建，改变原意图与确认基线。
- 首屏挂载全部隐藏表单：触发尚未访问阶段的业务查询，增加故障面和无关等待。
- 复制原型状态机并自动推进岗位：不能替代真实受信身份、当前责任范围和事务门禁。

## Consequences

阶段提示不授权业务，也不自动登录其他账户。历史岗位的工作病区选择保持原职责和回执绑定，默认单科环境无额外选择；兼容理由见[单科默认决策](../simplification/2026-10-21-single-inpatient-default.md)。阶段可见性采用真实目录和服务端事实，不从受当前病区收窄的普通目录推测是否存在其他转科目标。

验证同时覆盖未访问阶段不查询、切回保留输入、原回执恢复和归档只读。长内容以 DOM 检查面板确实可滚动，滚动后横幅坐标不变且仍在视口；桌面与窄宽度使用同一真实业务入口。
