# Agent Note: 门诊独立检查的逐项确认与原回执恢复

Status: implemented

## Problem

同类独立检查可以分别形成临床申请及费用，整批回滚会丢弃已经合法完成的项目。连续准备多项手动检查后，单草稿字段也无法保存各行输入；响应丢失时把剩余清单当成新开立，会重复产生申请与费用。[批量办理规格](https://github.com/CaiZongyuan/clinmesh/blob/spec/batch-clinical-actions/docs/spec/2026-11-09-batch-clinical-actions.md)明确要求独立检查逐项报告结果，诊断组与整张处方继续保持整体边界。

## Decision

三类门诊独立检查继续使用 `doctor.recommendations.confirm` 和现有事务内单项领域内核。最外层 Command 先核对负责身份、Encounter、草稿版本及全部 Agent 项目的建议身份、代次和完整资料指纹；每个检查再以 SQLite savepoint 独立核对审阅价目、保存草稿及开具，失败只回滚该项的资源、费用和 outbox。非预期错误及权限失败使整个 Command 回滚。只有外层写一份审计、Action Trace 和幂等回执，响应按原请求下标报告每项成功记录或确定失败。

已有单草稿的替换仍要求显式处理与正确版本。删除原草稿放在首个成功项目的 savepoint 内；全部失败时保留原草稿。成功记录不因其他项目失败撤销。该决定仅接替[准备确认决策](2026-10-18-prepared-clinical-confirmation.md)对独立检查的整批回滚保证，诊断组、整张处方及自动项目防过期边界继续有效。

门诊检验使用账号、Workspace/Epoch、岗位、病例及 Encounter 绑定的浏览器草稿，与 Agent 项目共用待开清单；加入后保持目录弹窗打开，原数量上限 8 不变。三个检查类别共享草稿结构、编辑选择偏好和逐项响应协议，具体目录及必填字段由对应页面拥有。持久输入读取时验证结构，保存失败阻止新开立，退出登录只清理未提交草稿；存储策略拒绝访问或删除时，清理错误不阻断已经成功的服务端退出和已认证界面移除。已发送的原意图与草稿使用不同存储前缀，退出时保留原请求、幂等键及尚未消费的结果；重新登录仍须匹配原账号、Workspace/Epoch、岗位、病例和 Encounter，不能把退出登录当作确定失败。修改 Agent 项目的临床字段继续保留其来源和证明，不能因编辑暗中绕过建议时效校验。

发送前持久保存完整选择、审阅价目、Encounter 及草稿版本、证明和原幂等键。响应未知时阻止新开立，提供独立于模型准备的原操作恢复入口。限定医生 Session 的 `GET recommendations/:kind/confirmations/:idempotencyKey` 只返回同账号岗位、Workspace/Epoch、病例和类别的原回执；它显式排除在 Operation Catalog 外，不扩展 CLI 或 Agent Grant。发送和恢复查询前重新核对服务端 Session，查询查无回执后重发前再次核对身份与页面生命周期，只重放同一请求与原键；查询失败、非 JSON 错误及幂等冲突不能证明原写入失败。只有原 POST 明确返回的就诊预期版本、资料或目录冲突拒绝释放原意图；版本拒绝发生在回执创建之前，保留旧意图会让恢复永久重放过期版本，因此保留输入供医生刷新核对并创建新意图。收到结果后先保留结果，再消费仍属于原提交的成功输入；失败输入保留供重新核对，跨病例迟到响应不消费当前清单。

浏览器草稿的订阅投影供统一清单与 Surface Agent 共用，页面上下文及修订包含全部手动行。校验持久数据时保留内容未变对象的引用，勾选变化不改变临床输入的提交归属。服务端新草稿版本只定向导入对应行，提交清掉旧单草稿后不会把旧父级字段重新导入而覆盖其他人工修改。

退出登录后查到部分成功或全部失败的回执，或重放原 POST 得到明确拒绝，缺失的失败行从冻结请求恢复到原作用域的手动草稿或编辑偏好，保留原字段、价目及 Agent 来源证明；已有的新输入或移除决定优先。失败输入保存完成后才能释放原意图，保存失败保留原意图、已有结果及恢复入口，避免再次退出或刷新丢失唯一输入。

## Alternatives considered

- 延续同类独立检查整批回滚：与独立项目成功保留的业务边界冲突；仍适用于诊断组和整张处方。
- 浏览器逐次覆盖单草稿并调用多个完整 Command：容易覆盖其他人工输入，且不能形成一份稳定、可恢复的逐项回执。
- 给通用 CLI receipt 放开页面组合操作：扩大 Agent 能力面。采用病例和检查类别限定的 Session 查询，复用既有回执存储与身份隔离。
- 只在内存保存幂等键，或查询失败后重新构造请求：刷新及目录变化后无法证明恢复的是原操作。

## Consequences

整次提交有一个受信意图和回执，每个独立检查内部仍完整生效或回滚。失败项修正后使用新意图；未知结果必须先恢复原意图。公开 HTTP 验证部分成功、原草稿保留、费用与幂等重放，组件及真实入口验证连续添加、输入隔离、刷新恢复与失败保留。当前合同由[临床流程](../../../architecture/clinical-workflows.md#门诊独立检查的应收与执行门禁)拥有。
