# Agent Note: 患者医保待遇共享核算、首次结算冻结与跨年追加补偿账

Status: implemented

## Problem

门诊分批缴费与住院跨日结算都需要区分医保统筹基金、个人账户与患者现金自付。若把医保抵扣塞进现金支付方式（Payment Tender），账单将混淆待遇核定与实收资金；若每次就诊只允许单条可变医保记录或在撤销待遇时将患者年度账户直接重置回历史快照，既无法支持门诊检验缴费后新开处方继续享受待遇，又会抹去同一患者在原结算之后其他就诊产生的真实年度起付线、封顶线与个人账户变动；而在住院结算归档后若因费用更正直接改写原医保记录，则会破坏首次结算与病案归档的三方平衡依据。

## Decision

由共享 `InsuranceService` 统一管理患者年度医保账户、门诊分批分配、住院首次冻结与结算后原年度追加补偿，详细合同见[收费、结算与医保](../../../architecture/billing-and-insurance.md)、[存储与事务](../../../architecture/storage.md)及[FHIR 与共享 Command](../../../architecture/fhir-and-commands.md)：

1. **共享年度账户、品规分摊与门诊分批门禁**：门诊与住院共享患者年度个人账户版本，分别累计各自年度起付线与统筹基金封顶（年度首次确认即锁定职工／居民合成参保方案，品规级甲乙丙先行自付与混合处方整数分拆分见[品规级甲乙丙医保属性决策](2026-11-19-item-insurance-coverage-and-mixed-prescriptions.md)）。预览冻结费用及目录指纹、岗位、虚拟日历年与账户版本，确认事务重验全部依赖。门诊按尚未有效分配的账项分批结算（药品待遇预览与确认均要求已完诊，避免个人账户全额覆盖提前触发药房放行；处方存在任何有效医保分配——含仅累计起付线的零基金分配——即阻断临床撤方，须先由收费员追加待遇撤销补偿）。
2. **住院首次结算冻结与归档三方核验**：正式住院费用为住院医保唯一来源，首次结算以当前有效待遇的患者现金自付额计算预交金多退少补，任何在途未知收退款均阻断待遇变更与封账。首次封账完整冻结原待遇快照，病案归档严格核对“冻结患者现金净额 + 统筹基金 + 个人账户 == 冻结总费用”。
3. **追加逆向补偿与结算后原年度替代重算**：待遇撤销通过唯一引用原结算的逆向事件追加补偿，绝不覆盖历史记录或回退已放行的检验／发药进度（已放行项目转为患者补收责任）。住院首次封账后的费用更正通过独立的 `inpatient_insurance_adjustment` 串行管理“原待遇精确补偿 → 替代待遇预览确认 → 患者现金差额收退”：始终固定原结算虚拟日历年与参保方案读取该年度实时累计（跨年虚拟时钟不改变账户归属，其他就诊并发结算推进该年度版本即令旧预览失效），新患者现金差额按“替代待遇患者自付 − 全部成功现金净额”计算（因个人账户已被其他就诊消耗，费用冲减亦可能产生现金补收），全程保留首次冻结账与病案归档不变。

## Alternatives considered

- **将医保作为支付渠道方式，或门诊与住院各建一套待遇账户**：前者混淆待遇减免与可退现金流，后者使同一患者个人账户余额并发分叉。
- **撤销或重算时把年度账户回滚至原结算前快照，或限定结算后收退方向必须与费用增减同向**：回滚快照会擦除其后发生的其他门诊／住院累计，限定方向则无法在个人账户已被他次就诊用尽时结清真实患者负担差额。
- **让病案归档动态读取最新有效医保待遇**：使归档后的账务调整反向破坏已审核归档快照的一致性。

## Consequences

患者待遇、实收现金、年度累计与归档冻结账保持各自可审计的追加历史；目录或参保映射缺失时显式拒绝计算而不猜测地方政策。当前两套固定合成参数仅用于院内仿真对账，不代表特定统筹区真实联网申报接口。
