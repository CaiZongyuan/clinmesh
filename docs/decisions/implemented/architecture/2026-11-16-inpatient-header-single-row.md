# Agent Note: 住院患者头部单行

Status: implemented

## Problem

住院医生的患者头部由编号行、跟进开关、AI 用量入口、整行 DRG 费用进度、“助手已准备”行以及提醒与检验值行组成，最多六行，在 1280 宽宿主下占去页签正文近三分之一高度。其他岗位固定两到三行，其中编号行对多数岗位不是当前任务所需。正式范围见[住院患者头部规格](https://github.com/CaiZongyuan/clinmesh/issues/506)。

## Decision

七个岗位共用一条规则：姓名行依次是身份、状态、床位与住院日，后接本岗位主业字段，右侧放本岗位最要紧的一项；病区名和其余字段收进“住院信息”菜单；第二行只在有提醒时出现。各岗位把字段清单交给同一个头部组件，由岗位决定哪些留在姓名行。

本决策部分演进[手术流程减负](2026-11-13-surgery-flow-assistance.md)中“任意页签保持一行费用进度”的呈现：费用进度缩为姓名行右侧小条，只常驻状态、病组、进度与余额，完整金额移到悬停说明和无障碍描述。数据来源、比较口径、阈值和仅住院医生可见不变。

跟进开关、跟进状态与 AI 用量入口合为一个菜单，按钮文字承载当前状态；助手已准备的可跳转事项合为一个计数菜单；检验值改为数量标签。三处弹层与“住院信息”都复用共享 UI 包已有的下拉菜单。药师的药物过敏提示属于用药安全信息，保持常驻。界面详细合同归[住院工作台](../../../ui/design.md)。

## Alternatives considered

- 只去重复、保留整行进度条和异常检验值：信息损失最小，但提醒较多时在窄宿主下仍超过 200px，没有解决正文被压缩的问题。
- 只压缩住院医生、其他岗位保持两行：改动面小，但同一工作台的头部结构因岗位而异，编号时而在第二行时而在菜单里。
- 整个头部折叠为可展开摘要：最省高度，但金额、状态等每次办理都要看的事实需要额外一次点击。
- 为收起字段新增气泡弹层组件：可以承载任意内容，但共享 UI 包已有下拉菜单能满足只读字段与点击复制，不值得多维护一个 primitive。
- 用仅悬停可见的提示承载编号：键盘与触屏不可达，也无法复制。

## Consequences

头部常态一行、有提醒时两行，页签正文获得相应高度。医生查看已用与支付参考金额、具体异常检验值和助手各项状态需要悬停或多一次点击；编号复制从常驻按钮变为菜单项。新增岗位或字段时在字段清单中声明其归属，不再向头部追加行。React 18/19 浏览器合同覆盖菜单在 ShadowRoot 中的打开、复制入口与单行高度；组件与旅程测试经菜单入口操作跟进和用量。
