# Agent Note: 胸片与胸部 CT 阅片闭环及定向病例生成

Status: implemented

## Problem

门诊与住院临床闭环需要“开立放射检查、等待报告、实际阅片、确认已阅”的真实业务路径，但程序合成图像没有可信病灶与可核对的报告依据，而接入真实医学影像又必须严守合成数据红线、报告与标注一致性、病例病史相容性及隐藏真值隔离。同时，首批公开胸部素材仅覆盖特定疾病（如存活肺癌与急性支气管炎），默认全模块随机生成 Synthea 患者命中率极低，仅靠服务端换 seed 重启 JVM 往往耗尽重试上限。

## Decision

以公开去标识影像窄例外、通用素材存储、共享申请内核与 Provider 时间有界定向生成构成完整放射闭环，详细合同见[检验、检查与报告](../../../architecture/examinations-and-reports.md)、[仿真、病例与素材](../../../architecture/simulation.md)、[前端架构](../../../frontend-architecture.md)、[放射使用指南](../../../imaging.md)与[影像素材清单](../../../../imaging-assets/README.md)：

1. **真实像素窄例外与独立素材包**：仅允许清单登记的公开授权、已去标识影像像素作为合成数据规则的显式例外；患者身份与病史仍全部合成，像素与来源 DICOM 保存在本地素材目录，绝不进入 Git、SQLite、日志或任何模型／开发验证 Agent 输入。通用素材存储负责分段下载、流式哈希校验、原子安装与修复，放射适配器负责 DICOM HU 换算、方向／层序与 MONOCHROME1 规范化并输出 `series.json`/`frames.bin`。
2. **结构化标注核对、签署哈希绑定与病例相容匹配**：报告基于来源数据集的结构化读片标注生成、经确定性规则核对并由人工对照影像复核签署，签署哈希 `imagingReportContentSha256` 同时锁定输出像素、来源实例、许可、整理规则、适配条目、标注与报告正文，并纳入未开始病例的准备身份（已开始病例保持原绑定冻结）。`matchCaseImaging` 仅将素材作为既往与本次来源编码相容病例的补充影像表现，存在胸骨切开、肺移植、起搏器等冲突手术或既往肺癌史的阴性匹配一律拒绝配片，绝不改写疾病或将未覆盖当作正常。
3. **共享申请内核、可替换阅片外壳与人类显示证明**：放射与检验、病理、功能检查共用 `ClinicalRequestKernel` 的状态机、版本、幂等与审计；阅片外壳按序列 `kind` 装载 canvas 灰度堆叠引擎，窗宽窗位与反相计算沉淀在 `@clinmesh/core` 纯函数中。Agent 仅参与申请与文字报告读取，DSH/Web 确认放射报告已阅要求人类会话内实际完成影像帧解码显示证明。
4. **Provider 内部按时限 `-k` 定向生成与服务端权威复核**：管理员按适配条目发起定向生成时，Server 从适配规则自动推导窄保留条件（须存在／须不存在的 SNOMED 编码有界列表及可选最新 Observation 编码值条件，不接受任意 JSON 或命令行参数）传给声明 `targetedGeneration` 的 Synthea Provider；Provider 在单次 JVM 运行内以 `-k` keep module 限时 4 分钟持续筛选存活患者，返回后仍由 Server 的 `matchCaseImaging` 做唯一权威复核（不满足则沿既有确定性换 seed 重试），成功后立即执行影像准备，若仅准备步骤失败则保留患者并附加 `IMAGING_PREPARATION_FAILED` 警告。

## Alternatives considered

- **程序化生成伪造胸片／CT，或把像素存入 SQLite／交给模型看图写报告**：伪造图像无临床阅片价值，大体积像素入库拖垮备份与性能门禁，模型直接读图既违反像素隔离又无法用结构化标注核验。
- **引入重型 WebGL/WASM 医学影像库（如 Cornerstone）**：体积庞大且 Worker/WASM 加载与 DSH 单文件 lazy-CJS 宿主相容风险高；轻量外壳加灰度堆叠引擎已满足需求并为病理 OpenSeadragon 引擎预留扩展位。
- **在素材清单手写第二份保留条件或自动启用 Synthea 模块过滤**：前者与匹配规则形成双事实源，后者裁剪掉合并症模块导致患者纵向病史失真。

## Consequences

录屏、截图与演示须保留清单要求的公开数据集署名；Docker 基础镜像不含离线影像素材包，未同步素材时放射服务如实显示未开展，未匹配病例的申请以明确未取得结果结束。升级 Synthea 或新增疾病模块时须重新核对未覆盖编码清单，未升级至支持 `targetedGeneration` 的旧 Provider 镜像会显式拒绝定向请求而不静默退化为随机生成。
