# Agent Note: 安装阶段自动取得固定 DRG 资料

Status: implemented

## Problem

离线清单能够证明本地资料身份，但代码克隆和临床目录同步不能取得本地整理包。五目录依赖已经完成的整理与复核结果，OpenDRG 网页及采集元数据也会改变，因此让安装者重新采集无法重现现有锁定快照。需求见[新安装自动准备完整 DRG 参考资料](../../../spec/2026-10-22-drg-reference-installation.md)。

## Decision

通过独立 GitHub Release 资产分发既定快照，Git 只保存固定下载地址、压缩及解包规模和 SHA-256。维护工具先沿用离线清单逐文件核验，再按明确文件列表、固定时间与排序制作可复现 tar.gz，不收录其他本地目录。快照保留原来源及隔离条件，分发不等于业务启用。

安装准备复用完整的现成本地资料或已安装版本；缺失或损坏时下载到临时目录，先校验压缩包身份，再拒绝路径穿越、重复路径、链接及超额条目，沿用原有内容检查后才原子安装版本目录并登记清单。锁身份采用 schema 解析后 JSON 的摘要，避免 Windows CRLF 与 Linux LF 产生不同版本。check-only 使用临时目录与数据库。当前操作与失败恢复由[部署指南](../../../deployment.md#离线-drg-资料核对)拥有，运行时隔离继续遵循[原清单决策](2026-10-21-offline-drg-reference-inventory.md)。

同一轮准备只读取和解析一遍完整资料，登记阶段接收本轮已核验的清单，继续在事务中保证不可变身份和审计；下载后的目录原子移动不改变该清单。下一次独立准备重新核验文件，不缓存跨启动的核验结论。

独立 Server、DSH 和局域网启动准备均覆盖 DRG，不以临床参考目录已存在作为跳过依据。完整参考同步已经准备 DRG 时，启动器不再追加独立 DRG 准备；LAN 和 DSH 启动器准备成功后使用 Server 的内部 `dev:prepared` 入口，经 `db:prepare --migrations-only` 保留数据库迁移而不重复获取或核验资料。独立 Server 的 `dev` 入口仍拥有完整准备责任。生产镜像在构建时取得完整资料，冷启动只核对和复用。Server 业务运行期间仍只读参考库，不联网获取资料或执行包内第三方程序。

## Alternatives considered

- 要求部署者复制开发机器资料：无法满足新安装自足，且会使个人目录成为未声明依赖。
- 在每次安装时从上游重建：缺少全部原始整理输入与固定远端身份，不能保证得到已经核验的同一快照。
- 将生成资料提交主分支：会把数百 MB 数据混入源码历史；独立版本资产能够固定身份并复用现有完整性合同。
- 把 DRG 纳入临床目录就绪判断：会让已有临床库的升级和单独 DRG 修复耦合到全部临床数据下载，保留独立准备入口更直接。
- 在核验、登记和后续 Server 启动阶段分别扫描全部文件：每次都会重复哈希和解析数百 MB 内容；复用本轮核验结果与明确启动准备责任可以保留下一次启动的损坏检查。

## Consequences

首次准备需要访问固定分发地址，已有完整资料可以离线复用。下载、解包或内容校验失败不会替换已有版本或清单，也不会报告准备完成。镜像构建失败必须保留错误，不生成缺资料的成功镜像。完整性、使用条件、编码兼容和算法正确性仍分别表达，不自动补齐七个病组的缺失支付参数。

验证从公共准备入口和真实构建后的 CLI 观察结果，使用合成归档及临时 SQLite 覆盖首次下载、重复准备、失败保旧、危险归档和 check-only；真实资料另外在空目录取得、回读并重复准备。不以开发者已有资料目录证明新环境可安装。
