# Agent Note: 结算后医保按原年度追加补偿与替代待遇

Status: implemented

## Problem

首次住院待遇已进入冻结结算和病案依据，后续费用纠错仍需核对患者实际现金及医保年度累计。患者可能在原待遇确认或补偿后另行就诊，直接把年度账户恢复到初始值会抹掉其他就诊的影响；按费用减少额退款也会忽略个人账户被其他就诊占用后产生的补收。

## Decision

首次冻结继续遵循[原医保冻结决策](2026-10-22-inpatient-insurance-freeze.md)。后续财务调整独立关联当前有效医保、精确补偿和替代待遇；`inpatient_insurance_adjustment` 保存原待遇／补偿／替代引用，预览关联表绑定本次调整。原费用和首次保险来源不改写，追加费用差异形成当前来源。共享 InsuranceService 提供事务内预览、审阅及追加原语，公开更正 Command 独立执行收费员、当前 Run 和资金确定性授权，普通首次医保门禁继续有效。

更正固定沿用原待遇年度与方案，即使虚拟时钟跨年也读取原年度事件累计；补偿只追加原事件的精确反向影响。预览确认使用患者该年度版本，其他就诊竞争成功即使本次费用未变也使旧预览失效。新待遇确认后的现金差额取新患者负担减全部成功现金净额，费用冲减可以产生补收，退款亦可超过本次费用冲减。投保住院串行处理更正，待遇和现金均确定后才开放下一次；未知资金保留当前调整待查，不撤销原清床或归档。

## Alternatives considered

- 覆盖首次结算或重开原账：破坏病案与临床完成事实的稳定依据。
- 重置年度累计后重算：会抹掉后来其他就诊的账户、起付线和基金影响。
- 按费用更正方向和金额限定收退：个人账户跨就诊变化时无法结清真实患者差额。
- 一个新 Command 内嵌调用现有公开医保 Command：嵌套事务及授权语义混淆；采用受信事务原语，外部仍为窄更正命令。

## Consequences

患者医保历史、当前调整、首次账和资金尝试均可独立追查。收费员需显式补偿、审阅替代待遇和办理现金差额。费用或原年度余额变化后必须重新预览，响应丢失继续原意图并查回执。公开 HTTP 验证同患者门诊竞争、跨年、拒绝及未知收退重启恢复；真实收费入口验证追加、更正审阅和原回执恢复。完整操作合同归[住院医保](../../../architecture/clinical-workflows.md#住院医保与首次冻结账)。
