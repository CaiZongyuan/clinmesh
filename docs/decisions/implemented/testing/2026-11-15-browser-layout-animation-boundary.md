# Agent Note: 浏览器布局采样等待有限动画的最终状态

Status: implemented

## Problem

主题、字号和宿主尺寸变化可能触发有限动画。两次浏览器帧并不保证动画已经结束，滚动前后的严格矩形比较可能混入尺寸插值；直接等待 `Animation.finished` 的 `Promise.all` 又会将正常取消视为验收错误。主分支失败与受控回归见 [Issue #504](https://github.com/CaiZongyuan/clinmesh/issues/504)。

## Decision

需要比较最终布局的手术和护士集中办理旅程共用有限动画等待入口。每次采样前经过真实浏览器帧，读取目标子树尚未结束的有限动画并等待其完成或取消，再重新读取；取消后产生的替代动画也须结束。无限状态动画不阻塞采样。等待继续受原 Playwright 整例预算约束，不加入固定延迟或重试。

最终位置、完整尺寸、滚动、同排操作、焦点及业务回读断言保留。该等待只确定布局采样时机，不改产品动画、页面或数据，也不把实际布局差异解释为允许误差。当前验收入口见[用户界面验证](../../../testing.md#用户界面验证)。

## Alternatives considered

- 将严格矩形比较改成更大容差：会丢失原布局合同，且不能解释正常取消。
- 用固定延迟或提高超时等待：无法保证有限动画结束，也不能覆盖取消后生成的替代动画。
- 关闭产品动画：改变被测界面，无法验证实际宿主的过渡行为。
- 对旧动画只用一次 `Promise.allSettled`：可以处理取消，但新动画仍可能处于中间态，因此必须重新读取当前动画。

## Consequences

布局验收等待当前有限过渡的真实结束，持续状态指示仍可运行。若有限动画停滞或真实布局不符合原合同，测试仍在既有预算内失败。受控 ShadowRoot 浏览器合同分别覆盖尺寸动画、正常取消与替代动画，并与实际 Web、React 18／19 的旅程一起验证。
