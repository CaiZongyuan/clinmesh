# Agent Note: 将手术全程旅程与同 runner 其他浏览器文件分阶段执行

Status: implemented

## Problem

手术全程旅程同时覆盖真实临床写入、助手核对、宽度与主题矩阵、滚动及术后责任处置。独立运行能够在原时限内通过；与其他浏览器文件在同一 runner 并行时，会在不同调用处耗尽整例时限。几何诊断已记录可见底栏、同排操作与正确分区，单凭最后的定位等待不能认定底栏被移除。全局串行或放宽时限会影响其他合同，也不能提高此类失败的诊断价值。

## Decision

为三个手术全程用例标记 `@surgery-flow`。完整和前端 CI 的浏览器与 E2E 执行组先排除该标签运行普通集合，成功后再单独运行该标签。浏览器普通集合仍使用原生两分片，隔离阶段只由第一个 runner 无分片执行；Web 隔离阶段同样无分片。两个阶段的集合互斥，并集等于原集合。

无分片的隔离阶段保留运行器的零测试失败语义，防止漏配标签被空分片掩盖。Surface 两版本仍在同一个文件内顺序执行，失败后后者继续，数据与 context 各自隔离。全局两个 worker、零重试、动作及整例时限、全部临床和几何断言保持。定向测试计划本来逐文件执行，不增加标签筛选。

CI 真实 CLI 合同验证参数、执行顺序及任一阶段失败即失败关闭；Playwright 实际列举核对完整集合与两阶段分片的覆盖。成功缓存继续绑定实际命令与完整检查输入，调度变化不能复用旧命令的成功记录。当前命令与覆盖由[测试策略](../../../testing.md#github-ci-的检查选择与并行)拥有，范围见 [Issue #503](https://github.com/CaiZongyuan/clinmesh/issues/503)。

## Alternatives considered

- 只将同文件两版本改为顺序执行：保留独立数据，但仍会与其他文件共享 runner 资源，不能完整隔离这条长旅程。
- 所有浏览器用例改为一个 worker：扩大影响范围并拖慢普通集合；当前只隔离已观察到争用的三例。
- 增加整例或动作时限、自动重试：会改变原合同并推迟稳定失败的反馈，不能替代调度隔离。
- 隔离阶段继续传入两分片：当前两版本同组只落入一片，另一片为空；漏配标签时两个空分片也可能通过。因此由首个 runner 无分片执行，并保留找不到测试时失败。
- 为三个用例新增独立工作流 job：增加 runner 准备与调度入口，现有执行组内顺序阶段已经能提供所需资源隔离。

## Consequences

普通集合仍并行，长旅程与同 runner 上其他文件顺序执行；总耗时受分片均衡和独立 runner 性能影响，不承诺固定墙钟收益。失败阶段阻止执行组保存成功记录；普通集合失败时不再启动隔离阶段，修复后仍须完成两阶段验证。

该决定针对测试调度，不声明具体浏览器或业务代码的性能根因，也不放宽已有业务与性能门禁。新增其他长旅程前需另行确认资源隔离需求，不自动将所有端到端测试加入该标签。
