# Agent Note: 已替代 DRG 旧登记采用显式局部恢复

Status: implemented

## Problem

完整资料与精简资料可保留相同的全部逻辑文件，但登记的物理储存索引不同。旧格式登记留在参考库时，当前 schema 拒绝读取；准备入口吞掉该错误后只登记当前身份，产生准备成功与 Server 全库核验失败的不一致。为处理一条旧登记而重建整个参考库，还会牵动独立的临床 Reference Release 和诊断、药品、检验目录。正式要求见[修复规格](../../../spec/2026-10-26-drg-inventory-recovery.md)。

## Decision

允许维护者在一致备份、原始登记与审计归档、完整核验当前资料并证明新旧逻辑覆盖一致后，以明确身份和原值校验的事务清理已被替代的旧登记。恢复保留临床目录、其他登记、既有审计及业务数据库；不改写旧清单，不给旧数据补默认 `storage`，不增加旧格式读取或自动清理能力。

准备入口只有在全部已有登记通过当前格式和内容哈希校验后，才能报告当前资料可用；当前身份已在前页出现也不能跳过后续页。数据库或登记表尚未建立可由既有初始化路径准备，其他读取或完整性错误直接失败。当前恢复顺序与边界由[部署指南](../../../deployment.md#旧格式-drg-登记的局部恢复)拥有。

本决策取代[只维护当前格式决策](../simplification/2026-10-25-drg-current-format-only.md)中以新建参考库处理旧登记的要求；当前格式拒绝、无自动迁移、不可变身份、失败保旧、来源隔离和用途限制继续有效。

## Alternatives considered

- 重建整个参考库：范围超过旧登记问题，可能丢失仍被本机配置引用的临床 Release，并需要重新导入独立临床目录。
- 放宽 schema、忽略旧记录或自动删掉所有缺少 `storage` 的记录：掩盖来源或内容损坏，不能证明任意记录已被当前资料完整替代。
- 为旧登记补写 `storage` 或改成新身份：改变不可变内容及哈希，失去原登记和审计的可追溯性。
- 在正常准备中自动发现并迁移历史格式：增加安装器分支和隐式删除行为；已知替代关系只由显式维护处理。

## Consequences

升级环境的局部恢复需要实际备份、归档和替代证据，不能仅凭记录日期执行。未知旧登记或其他损坏仍会阻止准备成功；协作者可从失败指引进入同一恢复合同。正常安装仍只支持当前精简格式，未增加历史 schema 或新的维护命令。

回归使用合成固定资料与临时 SQLite，从公开准备入口覆盖当前身份缺失与已存在、跨页坏记录、失败保旧和合法重复复用；本机维护另核对完整资料、备份、归档及非目标数据的一致性。二者均不要求真实模型或压测。
