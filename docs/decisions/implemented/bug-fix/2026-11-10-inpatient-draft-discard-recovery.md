# Agent Note: 住院私稿退出清理失败后的恢复边界

Status: implemented

## Problem

浏览器可能允许读取和保存 sessionStorage，却拒绝删除已有内容。服务端退出登录已成功时，前端必须移除已认证页面；仅捕获本地删除错误，会使重新登录后的住院医嘱、手术耗材、预留或更正私稿恢复旧输入。

## Decision

四类私稿复用 app 私有的命名空间清理 guard。退出时先在内存标记整个命名空间待清理，并尽力保存不含临床内容的清理标记，再尝试删除。删除全部私稿及最后的标记后才解除待清理状态；读取、保存及原回执消费或结算扫描前先完成补清理，失败则阻止返回旧内容。存储允许写入标记时，重新加载模块后仍可完成补清理；存储完全不可用时以内存标记保护当前运行会话。

私稿清理只覆盖各自既有前缀。已发送的岗位级写入意图、冻结命令、幂等键和服务端回执继续归原恢复协议，不因退出清理改变。当前存储合同见[浏览器未提交私稿](../../../architecture/storage.md#浏览器未提交私稿)。

## Alternatives considered

- 忽略退出清理错误：保留了已经被退出操作作废的输入，重新登录会将其误认为仍可办理。
- 仅逐条记录删除失败的键：枚举或访问存储本身也可能被拒绝，无法确定完整的待删除集合。
- 删除 sessionStorage 全部内容：会丢失已发送但结果未知的原意图，破坏幂等恢复边界。

## Consequences

存储恢复后，首次 owner 读取先清除退出前私稿，再允许正常新建与恢复新输入。未能补清理时，owner 显示空输入和存储失败状态，不以容错原文展示绕过清理。真实 signOut fetch、Storage 故障和四个实际 owner 的回归覆盖删除被拒、重新载入及新输入保存；原回执恢复仍由共享写入层验证。
