# Agent Note: 集中办理私稿退出清理失败后的恢复边界

Status: implemented

## Problem

浏览器可能允许读取和保存 sessionStorage，却拒绝删除已有内容。服务端退出登录已成功时，前端必须移除已认证页面；仅捕获本地清理错误，会使重新登录后恢复已经作废的未发送输入。集中办理记录还可能同时保存未知原尝试，整条删除会丢失幂等键或回执结算证明。

## Decision

各私稿 owner 复用 app 私有的命名空间清理 guard。退出时先在内存标记整个命名空间待清理，并尽力保存不含临床内容的清理标记；owner 可按原 schema 验证记录并保留最小恢复信息，默认删除未提交私稿。全部裁剪或删除及移除标记后才解除待清理状态；读取、保存及原回执消费或结算扫描前先完成补清理，失败则阻止返回旧内容。存储允许写入标记时，重新加载模块后仍可完成补清理；存储完全不可用时以内存标记保护当前运行会话。

私稿清理只覆盖各自既有前缀。门诊 confirmation 原请求保持独立；取消、重试和已阅的未结算 intent 留在原键并只保留原行。住院批量记录保留未知原尝试，药房还保留同批先前成功项，因为原库存版本证明依赖这些增量。裁剪是幂等转换，不调用公开保存或通知接口；只有退出清理的 finally 通知挂载 owner，补清理本身不通知。岗位级写入意图、冻结命令、幂等键和服务端回执继续归原恢复协议。当前存储合同见[浏览器未提交私稿](../../../architecture/storage.md#浏览器未提交私稿)。

## Alternatives considered

- 忽略退出清理错误：保留了已经被退出操作作废的输入，重新登录会将其误认为仍可办理。
- 仅逐条记录删除失败的键：枚举或访问存储本身也可能被拒绝，无法确定完整的待删除集合。
- 删除 sessionStorage 全部内容：会丢失已发送但结果未知的原意图，破坏幂等恢复边界。

## Consequences

存储恢复后，首次 owner 读取先删除或裁剪退出前记录，再允许正常新建与恢复新输入。未能补清理时，owner 显示空输入和存储失败状态，不以容错原文展示绕过清理。回归覆盖真实 signOut、Storage 故障、重新载入后的补清理、新输入保存，以及取消、已阅和同库存批次发药沿原键恢复且不继续发送余项。
