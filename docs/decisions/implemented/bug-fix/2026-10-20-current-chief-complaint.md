# Agent Note: 当前病历主诉与分诊来源关系

Status: implemented

## Problem

医生页头只读取分诊投影，病历中的手改、清空和后续签署修订不能反映到主诉展示。质控同时收到分诊原文与同源派生摘要，却没有底层记录身份及时间；输入结构不足以区分重复佐证、后续整理和实质冲突。真实模型偶发误报的完整触发输入未被复现，不能将这项结构缺口解释为全部根因。

## Decision

页头从病历编辑器已有的当前病例工作稿投影主诉，使用空值是否存在区分清空与没有文书；签署后按最高业务修订号读取不可变签署件。主诉相对保存稿的差异呈现既有未保存提示，刷新恢复服务端保存稿，不新增可写状态或隐式保存。当前合同见[临床业务流程](../../../architecture/clinical-workflows.md)。

质控只保留一份完整分诊证据，以持久分诊标识、版本和业务记录时间绑定初记，并显式标明 `clinical:presentation` 的派生关系。患者、医生补充及报告继续保留独立来源和业务时间，实际来源保存时间存在时才提供可用时间；旧数据缺失不补造。文书保存者、版本、保存时间及候选改动字段独立放在 `documentContext`，只解释待检查版本，不能作为正文正确的证明。

生成与独立复核共享来源解释规则。合理概括、同义改写、实际来源支持的补充、合理时间变化与有原文依据的明确更正不要求与初记逐字一致；同时同语境且未解释的互斥仍提示具体事实。更正依据仍由实际问诊、医生补充及已有自动记录关系提供，不从人工编辑或较晚保存推断“已核实”。

来源身份、业务时间、已知可用时间和策略版本参与临床输入指纹；仅表示版本归属的 `documentContext` 与草稿版本、任务指针一起排除，保留同文再次保存以及候选保存后的规范任务复用。旧策略与来源变化继续使旧结果失效，迟到结果沿用既有授权及版本保护。

## Alternatives considered

- 覆盖分诊原记录或排除全部分诊证据：丢失原始来源、生命体征及真实冲突依据。
- 把手改病历复制为可信医生来源，或认为最新保存自动更正旧事实：会用待检查正文证明自己，压制仍需核对的矛盾。
- 只按提醒文字过滤主诉问题：无法保留正常整理与实质冲突之间的语义边界。
- 把文书保存元数据全部纳入指纹：同一正文每次保存都会再次调用模型，破坏已保存与候选输入的复用合同。

## Consequences

不新增逐条确认、核实保留或签署门禁。来源关系由服务器在病例授权后按 Workspace、Epoch 和病例读取，模型仍只给辅助提示，不修改病历。公开 HTTP 与真实 SQLite 回归覆盖来源去重、时间缺失、正常整理、真实冲突及同文复用；组件和 Playwright 覆盖页头、保存冲突与双 React 版本。合成模型替身证明输入、输出和独立复核接线，不能证明实模的临床准确率。验收范围见[规格](../../../spec/2026-10-20-current-chief-complaint.md)，测试归属见[测试策略](../../../testing.md)。
