# Agent Note: 住院模型用量纠错的管理资格与病例权限

Status: implemented

## Problem

DRG 模型明细沿用当前住院读取岗位与病例范围，人工核对及补算又要求管理员资格。若把管理员资格等同于当前选中的 `roleCode`，纯管理员无法读取病例，切到临床岗位后又无法核对，便会使[既有计价控制](../architecture/2026-10-21-model-usage-pricing-control.md)要求的未知消费核对和缺价补算失去可用入口。

## Decision

HTTP adapter 复用 `IdentityService.resolveAdministratorActor`，确认同一成员具有当前工作区的有效管理员资格，同时保留其所选 Actor 与临床岗位。服务只接收该受信 adapter 的管理资格结果，仍按原 Actor 检查目标病例的读取范围；请求正文不能声明管理资格。两项检查先于共享 Command 的旧回执回放，撤销任一资格或切换到错误病区后不能借原幂等键取得旧明细。

病例用量明细复用现有核对／补算对话框，使双权限成员在原住院和任务范围内操作；设置页的纠错入口采用同一管理员资格提示。工作区额度与留存设置继续要求当前选中的管理员岗位。当前接口、拒绝结果及计量保留合同由[模型用量查询](../../../architecture/security-and-reliability.md#模型用量查询)拥有。

## Alternatives considered

- 只检查当前选中的管理员岗位：不能同时满足 DRG 病例读取范围，使正式需求中的核对和补算不可达。
- 将临床 Actor 改写为管理员后调用服务：丢失当前病例范围，可能把管理权限当成临床读取授权。
- 新建临床管理授权、令牌或病例专用纠错账本：已有多岗位成员和身份入口能够表达双权限，没有新增协议或账本的需求。
- 在设置页丢弃任务筛选后纠错：难以保持本次住院与当前任务定位；病例内复用现有对话框即可完成。

## Consequences

纯临床成员只能读取，纯管理员汇总岗位不能下钻 DRG 病例；同时具有两项有效权限的成员可以核对仍留存的未知消费并显式补算缺价。资格与范围变化会拒绝旧回执，历史原始用量和调用时计价依据保持原合同，核对不触发模型重发。公开 HTTP 回归覆盖两类修订、岗位切换、资格撤销和重复回执，Web 与 React 18／19 Surface 旅程覆盖病例内的实际补算及焦点。
