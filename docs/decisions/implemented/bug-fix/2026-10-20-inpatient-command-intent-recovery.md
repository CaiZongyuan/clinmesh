# Agent Note: 会话级原写意图恢复、门诊完诊后原退款收敛、预留集合指纹与退出补清理

Status: implemented

## Problem

临床与财务写操作在响应丢失、跨 Epoch 重放、耗材整批替换及退出登录时面临四类边界漏洞：第一，住院登记不递增 `Patient` 版本且允许同患者多次住院，超时丢响应后若换新幂等键重发会重复建档收预交金，互换床位刷新版本重做会把床位换回，且人类 Cookie 在 Epoch 重置后自动绑定新世代，单靠 `Patient` 版本拦不住跨世代旧登记；第二，门诊未知退款若未计入共享未决资金门禁会误放行临床执行，而药房发药使 `Scenario Run` 进入 `completed` 后又会锁死在途未知退款的查询恢复入口；第三，术前耗材整批替换若要求客户端回传有上限的旧预留数组，会在单项累积超阈值时失败或漏审并发新预留；第四，部分受限环境允许读写 `sessionStorage` 却拒绝删除，退出登录若忽略清理报错会让后续重登恢复已作废草稿，而一刀切清空又会毁掉在途未知写意图与同批次发药库存增量证明。

## Decision

在共享幂等回执与会话存储层补齐四项恢复与并发守卫，当前协议见[FHIR 与共享 Command](../../../architecture/fhir-and-commands.md)、[收费、结算与医保](../../../architecture/billing-and-insurance.md)、[住院与手术流程](../../../architecture/inpatient-workflows.md)及[存储与事务](../../../architecture/storage.md)：

1. **会话绑定原写意图持久化与 `expectedEpoch` 乐观断言**：住院登记、床位互换、住院证、场景时钟及门诊／住院资金写操作在发送前将完整命令输入、原预期版本与幂等键写入 `sessionStorage`，严格绑定账号、Actor、Workspace、Epoch、Scenario Run 与岗位（存储不可用即拒绝发请求）。原意图未确认前锁定表单；恢复时先按原 `operationId + idempotencyKey` 查 `command-receipts`，无回执才以完全相同的原输入与原键重放，仅成功或可信 JSON 业务拒绝才释放意图（超时、5xx 及非 JSON 4xx 均保持未决）。住院登记额外携带 `expectedEpoch` 前置断言，与当前活动世代不符时稳定返回 `INPATIENT_EPOCH_CONFLICT`。
2. **门诊未决退款共享门禁与 `completed` Run 原退款恢复例外**：共享资金投影同时纳入未知收款与未知退款，阻断同一账项的新收退预览、确认及收款放行；处方撤回按冲减后净应收判定结清。仅对 `refund.recover` 开放当前 Workspace/Epoch 下人类收费员在 `completed` Scenario Run 的窄例外以查明并落盘既有未知退款终态（新冲减、新退款、`closed` Run 与 Agent Grant 继续严格要求 `active` Run）。
3. **服务端耗材预留集合指纹（`reservationSetFingerprint`）**：预留读取同步计算并返回同住院、同手术计划全部活动预留身份与版本排序后的规范化指纹（含空集合）；单次预计确认与手工整批替换仅提交医生审阅过的集合指纹并在写事务内重算比对（回执重放优先直接返回原结果），彻底解除旧预留条数数组上限并拦截未审阅并发变更。
4. **退出登录命名空间延迟补清理与未知意图裁剪保留**：退出登录时各私稿 owner 统一经命名空间清理守卫先写入内存与不含临床正文的持久待清理标记，对已完成或未发出的草稿执行删除，但显式裁剪保留尚未结清的未知原写意图及住院药房同批先前成功项（用于证明[集中发药库存版本增量](../architecture/2026-10-21-inpatient-orders-and-administration.md)）；若退出瞬间浏览器拒绝删除存储，后续模块重载或首次读取／保存前必先完成幂等补清理，补清理失败则只返回空态与存储错误，绝不泄露退出前作废草稿。

## Alternatives considered

- **每次重试生成新幂等键并刷新最新资源版本，或仅在组件 `ref` 保存幂等键**：无法排除首次请求已提交，导致重复收款建档或床位反向互换；组件卸载刷新即丢失原输入与预期版本。
- **因存在未知退款推迟门诊临床完诊，或在 `completed` 场景放开全部新退费更正**：耦合外部支付渠道与医生完诊责任，或越界放大已完成场景的写权限。
- **调高旧预留回传数组上限，或退出时无条件调用 `sessionStorage.clear()`**：调高上限仍会在下一阈值失效且放大请求体；全清存储则会抹掉已发出但结果未知的原幂等键，破坏不重复执行保证。

## Consequences

跨刷新、跨世代重置、发药结案后退款收敛、30+ 笔累积预留整批替换及受限存储退出重登均具备确定性的防重与防串稿保护；持久意图或清理标记损坏时宁可显式阻塞提示核查，也不静默放行潜在重复写入。
