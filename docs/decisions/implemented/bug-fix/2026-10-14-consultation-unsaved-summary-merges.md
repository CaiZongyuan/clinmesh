# Agent Note: 未保存病史与自动总结的完整语句合并

Status: implemented

## Problem

直接记录允许后台替换尚归 automatic 的病史片段，浏览器可能同时存在未保存的医生改写。字符三方合并会丢弃重叠的新患者事实，或把另一部分改写拼进人工句子；随后保存会把已完成任务的事实永久删掉。当前保护要求由[病历字段规格](../../../../docs/spec/2026-10-14-clinical-document-fields.md)拥有。

## Decision

浏览器以当前显示基线中已见过的增量标识识别新自动记录，只对新 applied、automatic 病史增量涉及的字段启用完整语句三方合并。句界包括中文句号、问号、感叹号、分号和换行，不按逗号或小数点拆分；换行独立匹配，后台另起一行追加时不会把原句误判为改写。互不重叠的语句继续更新；重叠时保留未保存正文，把后台完整变化另行追加在“待核实补充：”标签之后，不丢弃事实、不拼接半句、不推断哪一方正确。标签独占一行，使下一轮仍能定位完整后台语句并更新它。双方相同的变化只保留一次，双方同时追加的内容都保留；不截断超限字段，保存继续受现有长度合同约束。

共享纯函数保留原字符范围跟踪用于持久化片段归属，调用者显式提供冲突标签才启用完整语句合并；其他工作站的人工保存与非自动记录字段沿用本地输入优先的原合同。合并只改变浏览器工作稿，已见增量标识属于显示基线；Query、来源、共享 Command、草稿版本、正式签署和人工审批的所有权保持不变。首次自动草稿的预填合并继续沿用原规则，不增加医生逐条应用或确认。

本决定取代[片段归属决策](../architecture/2026-10-08-consultation-history-ownership.md)中的字符级浏览器合并取舍，补充[直接记录决策](../architecture/2026-10-14-consultation-direct-recording.md)的未保存输入保护；服务端锚点与人工归属仍由原决策拥有。

签署冻结旅程等待真实签署弹窗，并核对服务端签署准备已生效，再读取冻结快照和释放在途模型结果。点击完成只代表浏览器动作完成，不能作为异步预览 Command 的完成屏障。

## Alternatives considered

- 丢弃重叠后台变化：保住人工输入，却在下次保存时删除已完成任务的新事实。
- 继续拼接不重叠字符：字符相同不代表语义可以组合，会制造双方都未写过的句子。
- 有人工编辑就锁定整字段：阻止同字段其他完整语句的安全更新。
- 自动选择一方或重新生成整个字段：缺少当前人工内容的独立语义依据，扩大覆盖范围。
- 用固定等待或放宽超时代替签署准备检查：依赖机器速度，仍不能证明冻结点已经建立。

## Consequences

冲突文本保留双方完整陈述供医生正常编辑，后台的新事实可随工作稿保存并在刷新后恢复。后续自动更新仍可更新单独保留的后台语句，不能改坏医生原文。Core 回归覆盖重叠改写、不同语句、连续更新、同时追加、删除、换行和 Unicode；真实 Web 从问诊入口验证三轮整理、未保存编辑、保存和刷新。共享签署旅程验证准备、冻结、取消恢复及签署，适用于 Web 与原生 DSH。
