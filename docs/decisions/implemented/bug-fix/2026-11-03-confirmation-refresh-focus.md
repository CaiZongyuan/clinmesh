# Agent Note: 后台核对保留确认条外的用户焦点

Status: implemented

## Problem

原位确认按钮的 ref 随可用状态变化重新绑定。后台核对会反复切换可用状态，重新绑定时无条件聚焦按钮或取消入口，会把焦点从已打开的菜单或正在编辑的字段拉回确认条。此时 Escape 可能取消确认而未关闭用户正在操作的菜单。

## Decision

共享确认 hook 记住最近一个非空按钮节点，并沿用原确认作用域。首次挂载或新作用域仍执行原聚焦；同一按钮的后台状态更新只在焦点仍属于操作栏或已回到页面主体时执行聚焦。判断使用按钮所在 Document 或 ShadowRoot 的实际焦点。React 因 ref 回调变化传入的空值不清除上一次按钮身份，避免把同一节点重新绑定误认成初次出现。

当前交互合同由[可访问性与验证](../../../ui/design.md#可访问性与验证)维护。组件回归覆盖菜单、其他输入和延迟出现的操作栏；真实 Web 与 React 18／19 ShadowRoot 合同通过受控读取响应验证浏览器焦点归属。

## Alternatives considered

- 移除确认聚焦：会破坏初次审阅及操作栏延迟出现时的键盘入口。
- 只检查菜单是否打开：遗漏其他输入，也把确认 hook 耦合到全局浮层选择器。
- 增加 Escape、延迟或重试：不能保证焦点归属，也可能取消用户仍需保留的确认。

## Consequences

后台核对不打断用户当前操作，菜单的 Escape 与确认条的 Escape 各自作用于当前焦点。原确认门禁、提交、取消与作用域恢复不变，共享实现只使用 React 18／19 共有 API。
