# Agent Note: 完成通知只让显式按钮接收鼠标

Status: implemented

## Problem

完成通知固定在右下角。底部操作栏可以预留高度，但行内退款确认等操作位置随内容变化，仍会落到通知正文下方。正文接收鼠标时会阻断确认，悬停还会暂停自动消退；透明的堆叠通知也可能继续命中鼠标。

## Decision

共享 [Toast](../../../../packages/ui/src/components/toast.tsx) 的通知正文允许鼠标穿过，仅操作和关闭按钮接收鼠标。折叠堆叠中透明正文内的按钮不参与命中，展开后恢复。保留 Base UI 的通知管理、键盘焦点、操作和关闭机制；当前交互合同归[UI 设计](../../../ui/design.md#共用卡片工作台)。

## Alternatives considered

- 继续上移通知：只能保护已知的固定操作栏，不能保证避开任意行内确认。
- 在旅程中强制点击或先关闭通知：无法解决真实用户的遮挡与悬停暂停。
- 仅隐藏透明堆叠通知的命中：可见通知正文仍会挡住确认。

## Consequences

通知正文不再承担鼠标悬停暂停或滑动关闭，用户仍可点击关闭按钮或用键盘进入通知。鼠标停在通知正文上时，自动消退照常运行。[React 18/19 浏览器合同](../../../../apps/dsh-web/src/client/toast.browser.test.ts)覆盖真实鼠标重叠、透明堆叠、操作按钮、键盘操作、关闭与自动消退；PCI 全旅程继续核对原收退流程和业务写入次数。
