# Agent Note: 容器指南库与维护限制持久化

Status: implemented

## Problem

指南固定资料可以随镜像分发，但运行库还保存安装后的撤回、替代、正文和用途限制。将运行库留在镜像路径会使容器重建后恢复包内旧状态，即使业务库使用持久卷，已停用的依据仍可能重新可用。只保证普通准备不覆盖限制，不能保护容器层被替换的情况。

## Decision

容器将可维护指南库与业务库放在同一持久数据卷中的独立文件。镜像内的锁定原件、提取正文与核验记录作为可离线复用的准备输入；启动继续调用既有准备入口，验证固定快照并事务更新卷库，保留后续维护限制，不复制镜像数据库覆盖现有库。默认路径、旧容器迁移和自定义挂载由[部署指南](../../../deployment.md#docker-一键启动)拥有，来源限制和 schema 升级由[存储合同](../../../architecture/storage.md#99-数据库迁移边界)拥有。

## Alternatives considered

- 继续使用镜像路径，仅保留业务卷：容器升级丢失维护限制，重新启用已停用资料。
- 每次启动复制镜像内指南库：即使目标位于持久卷，仍会覆盖后续维护状态。
- 首次启动重新下载资料：增加网络依赖，丢失镜像已核验资料提供的离线启动能力。
- 仅要求运维手动修改环境变量：默认部署仍会丢失指南维护状态，不能作为完整交付。

## Consequences

重建容器与更新镜像保留来源限制；固定资料快照与可维护运行库分别拥有生命周期。旧容器层中的指南库需在移除前一致备份并迁入持久卷，代码无法从已删除的容器层恢复状态。回滚旧 schema 仍需要配套指南库备份，不回滚业务库。

生产入口回归使用合成资料和临时持久目录验证离线首次准备、跨进程复用、限制保留及新快照更新，替身只隔离与指南无关的启动服务，不读取真实指南库或调用真实模型。
