# Agent Note: 住院与门诊发号迁移身份兼容

Status: implemented

## Problem

门诊发号与建议预算版本已发布两份迁移，住院闭环也已有落库版本。两侧使用相同数字前缀但不同完整文件名；重编号或覆盖任一侧会让已有数据库的迁移记录失去对应内容，不能通过正常校验与升级。

## Decision

沿用按完整文件名及校验和识别迁移的现有机制，保留两侧原始 SQL 和迁移身份，只应用尚未安装的文件。住院来源物化、精确检验快照和门诊原申请计费的表重建均保留事务外切换外键和提交前完整校验，门诊发号迁移保留初始化时的审计与历史证明；各自的失败回滚和保护条件同时生效。版本及双路径合同由[存储与事务](../../../architecture/storage.md#99-数据库迁移边界)拥有。

## Alternatives considered

- 为消除重复数字前缀而重编号住院迁移：会改变已使用住院版本的迁移身份，即使 SQL 内容相同，也无法证明旧记录对应新的文件名。
- 覆盖已发布门诊迁移：损害门诊发行权威和按日高水位，可能在恢复后重复发号。
- 为旧住院库跳过发号历史证明：保留当前号码不能证明所有历史发行，旧 reset 或损坏审计仍必须拒绝升级。

## Consequences

迁移数字前缀表达排序，完整文件名表达身份。升级回归分别从两侧真实 schema 安排已审计发号与旧回执，验证原事实、历史、迁移记录和发行权威保真，并注入失败验证回滚与外键恢复。原版部分迁移测试显式限定其历史迁移集合，避免同前缀的另一份迁移意外改变测试基线。门诊计费的失败回滚从该迁移紧邻的前置 schema 验证，成功升级再核对其后全部待应用身份；批次中的前序迁移按各自事务提交，不声明跨文件整体回滚。
