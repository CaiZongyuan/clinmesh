# Agent Note: 在院主操作确认复用首页修订

Status: implemented

## Problem

实际手术存在时，DRG 必须由医生显式确认主操作。在院病案页将选择器与完整首页一起延迟到出院结算后，导致手术已完成却无法形成正式预分组；费用正确并不表示病组有效。需求见 [Issue #488](https://github.com/CaiZongyuan/clinmesh/issues/488)。

## Decision

在院页面（`admitted` 或 `discharge-pending` 且未结算、未归档）提供独立的主操作保存入口，复用现有 `inpatient.record.submit` 追加当前来源快照与显式选择，并结束[术后待确认主操作的费用预计与核查清单](../architecture/2026-11-14-postoperative-reference-and-review.md)中的待确认过渡。该 Command 继续沿用预期修订、来源指纹、幂等、审计和私稿恢复，不新增主操作存储或写协议；来源或修订冲突时在同区禁用重复保存并要求显式放弃原选择后重审。在院保存形成的未离院、未结算修订不视作正式病案首页提交，服务端编码审核（通过与退回）均拒绝未离院病例，病案岗位界面与连续审核队列亦保持锁定，完整首页仍等待出院结算后核对提交。本决策部分取代[住院手术与 DRG 步骤化 AI 融合及全站壳层窄投影对齐](../feature/2026-11-05-inpatient-ai-step-fusion-and-ui-shell-alignment.md)中“在院期间一律等待出院后在病案首页选择主操作”的约定：仅尚无已完成手术时保留 `等手术完成` 中性态，手术完成后即提示前往病案页保存。当前行为由[临床流程](../../../architecture/clinical-workflows.md#drg-评估与医保办核定)拥有。

## Alternatives considered

- 根据最新手术或目标病组自动选主操作：会把系统推断当成医生确认，并可能把诊断性造影与 PCI 的主次顺序写错。
- 仅在结算后展示分组：无法满足住院期间按已实施事实预分组的既有能力。
- 新建主操作 Command 与独立持久状态：与首页修订中的主操作形成双重来源，需要额外同步与协议维护；现有修订机制已能完整承载该写入。

## Consequences

在院确认会增加一份带当前来源的首页修订，不能据此认定离院、结算、编码审核或归档已完成。页面将其显示为主操作依据保存；完整提交仍须在结算后重新审阅。真实浏览器回归覆盖未选不完整、显式保存、刷新保留、再次改选、正式病组及结算门禁；既有 PCI 黄金旅程覆盖后续结算和归档。
