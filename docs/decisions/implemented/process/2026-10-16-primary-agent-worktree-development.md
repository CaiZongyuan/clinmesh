# Agent Note: 主 Agent 统筹的按需 worktree 编排、最小可证实验证与工程追溯规范

Status: implemented

## Problem

在多模块仿真 HIS 的 Agent 协同开发中，若强制所有小修改都走“访谈 → 规格 → 拆票 → 独立分支 → 录屏 → 复盘”重型流水线，或要求用户每次手动点名显式编排技能、亲自分派并跟进各个子任务，会产生高昂的流程摩擦；反之，若私自改写上游通用 Matt skills 元数据使其自动触发、照搬其自动转 ready／reset 清理动作，或在提交前 `code-review` 时只检查三点提交 diff 而漏看未提交与未跟踪文件，则会制造上游技能分叉、越过项目授权边界并放过工作区缺陷。

## Decision

确立由主 Agent 按任务复杂度统筹开发拓扑、窄验证证据与简体中文可追溯交付的协作机制，详细操作约定见[Agent 工程开发](../../../agent-development.md)、[文档规则](../../../AGENTS.md)与[Issue 规则](../../../agents/issue-tracker.md)：

1. **主 Agent 自动统筹与按耦合度选择直做或 worktree 并行**：主 Agent 直接承接用户自然语言目标，负责需求澄清、范围界定与交付收口：单个或紧密依赖任务在当前工作分支直接完成；包含多个可独立验收切片的复杂需求围绕同一父规格（见[恢复 GitHub Issue 为正式需求规格](2026-11-11-github-issue-canonical-specs.md)）在仓库外隔离 git worktree 并行实施后统一集成。上游通用 Matt skills 保持原文与显式调用设置不变（本机开发 skills 与共享仓库资料的隔离见[共享工程资料与本机配置分离](2026-10-19-repository-sync-boundaries.md)），通用 ADR 产物统一映射为本目录的 Agent Note；代码简化使用 `reduce-complexity` 并严格保留共享 Command、FHIR R5、权限、幂等与持久化契约。
2. **完整快照双轴审查与最小覆盖验证纪律**：行为变更坚持测试先行，合入或交付前的双轴代码审查必须覆盖完整待交付快照（含已提交变更、暂存区与未跟踪新增文件），复盘仅形成有证据支撑的改进候选而不未经确认自动改规则。迭代期优先运行能捕获当前回归的最小检查，仅在触及跨包契约、构建配置、文档投影或发布路径时升级运行全量 `pnpm check`；报告中只陈述实际执行过的命令、耗时与真实结果，复用仍有效的成功证据，严禁未经当次明确许可触发压测或真实外部模型调用。
3. **简体中文结构化工程消息与授权边界**：Commit、GitHub Issue、Pull Request 标题与正文及评审回复统一使用简体中文并保留精确技术标识符，清晰记录交付行为、关联 Issue 与实际验证证据；所有远端推送、PR 状态变更与工作树清理严格沿用用户明确授权，发布前核查无真实患者信息、密钥或本机敏感路径。

## Alternatives considered

- **修改上游 Matt skills frontmatter 强制自动触发，或在根 `AGENTS.md` 平铺全部可选技能全文**：制造难以升级的上游分叉，并无谓消耗常规任务的根上下文窗口。
- **要求用户手动调用 `implement-spec` 逐票调度，或对所有微调一律强制拆票、建 worktree 与录屏**：将编排负担转嫁给用户，让简单修复背负无效行政开销。
- **每次推送前无差别强制跑满全仓所有测试套件（含与纯文档修改无关的代码测试）**：拖慢反馈周期且掩盖针对性回归信号。

## Consequences

用户只需面向主 Agent 表达业务意图与授权边界，主 Agent 自适应完成单分支直做或多 worktree 并行集成；git worktree 仅提供源码工作树隔离而不自动隔离端口或共享本地文件，主 Agent 仍对基线同步、可写路径隔离与最终集成验证负总责。
