# Agent Note: 单住院科默认环境与旧岗位上下文保留

Status: implemented

## Problem

默认内外科双病区让同一合成人员具有两个岗位上下文，增加新入院与岗位切换的选择成本。当前演示只需要一个住院科、一个病区，但旧库已有真实住院事实；岗位身份与科室、病区同时参与原 Command 请求指纹和回执授权，不能把显示去重解释为删除原身份。

## Decision

默认环境使用现有稳定标识创建一个中性住院科和病区。初始化补齐缺失的默认环境，并仅升级稳定默认 ID 上与原种子精确匹配的科室、病区、病房和床位显示名；FHIR Repository 维护当前资源、历史版本与索引，病区目录名称同步更新。自定义名称及其他旧病区名称保留，原资源引用、岗位和运行事实不迁移；数据库 schema 保持不变。病区目录保留旧条目，以 `acceptingAdmissions` 表达新入院目标。新直接入院、转院登记及新签发住院证只接收默认病区，已签发住院证与旧幂等键保持原合同。原医护上下文继续操作所属住院与在途转科，不扩大服务端作用域。

Workspace 级岗位绑定必须保留以便原回执恢复，但不能让未安装于新 Epoch 的职责再次生效；身份与显示元数据边界由[身份认证](../../../architecture/security-and-reliability.md#111-认证)拥有，住院入口与错误由[临床业务流程](../../../architecture/clinical-workflows.md#82-住院闭环)拥有。

## Alternatives considered

- 仅隐藏或停用旧岗位：即使旧科已无在院患者，原操作仍可能需要用旧 PractitionerRole 恢复回执，且旧患者会失去原负责上下文。
- 将历史 ward、bed、admission 统一改成默认标识：会改写历史床位归属与首页来源，损害转科约束、FHIR 历史和已归档事实。
- 自动通过转科 Command 搬迁既有患者：它会产生实际临床事件，要求在途任务先收口；界面与默认配置的简化不构成这种临床动作的依据。
- 将一个岗位放宽为读取所有病区：改变既有责任与权限边界，无法用显示需求支持这项授权变化。

## Consequences

新环境只有一个默认医护上下文；旧环境仍可包含需要明确选择的历史职责。显示名升级只增加环境资源的 FHIR 版本，保留旧名，不修改临床资源版本、首页来源指纹或业务回执；后续启动不再产生新版本。跨病区测试显式安装第二病区，不把额外演示配置带回生产默认种子。验证覆盖默认环境重启幂等、旧证转收、原 scope 与跨 scope 拦截、手术和检查费用、归档及原回执无写重放。降低新环境资源数量后，仅按实测更新场景安装的行数预算，不放宽其他性能门禁。
