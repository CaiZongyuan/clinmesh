# Agent Note: 固定病例就绪与 AI 耗材预计的事实边界

Status: proposed

## Problem

固定 PCI 演示资料有可重复的内容，仍要求操作者手填 Persona；已有耗材建议依赖主动跟进和人工参数，确认计划与预留分开。最终用量与预计不同，或已有术中逐笔记录时，操作者需要自行理解剩余预留、追加使用和更正之间的关系。把这些录入全交给模型会混淆固定病例、预测和实际事实。

PR #339 已提出持久化模型分析、参数及候选核对、逐笔用量／更正、后台复查和用量归属。本提案以该实现为复用基线，补充流程简化，不将它们重新设计为后续待建能力。

## Proposal

需求和验收由[PCI 住院 AI 辅助规格](../../../spec/2026-10-28-inpatient-ai-assistance.md)拥有。本提案解释固定准备、自动单次预计、整批预留、最终用量与直接核对的边界；持续任务、事件历史和用量账仍由[原规格](../../../spec/2026-10-27-inpatient-drg-agent.md)及对应 owner 拥有。

固定演示使用版本化合成档案，一次准备有效 Persona 并选用，停在待入院。它不依赖模型；模型只负责按当前正式资料及院内依据提出耗材预计，身份、单位、价格、费用与分组由确定性业务能力处理。Material Estimate、Treatment Material Reservation 与 Material Use 各自表达预测、已确认推演计划和实际使用，不能互相充当证明。

### 模块边界与复用

| 原有 owner | 本轮新增的调用合同 | 保持隐藏的职责 |
| --- | --- | --- |
| 固定病例来源准备 | 准备并读取有效档案及选用状态，保护人工修订及消费绑定 | 模板版本、不可变修订、首次选用、幂等与整体事务 |
| 耗材依据与模型建议 | 保存计划后的单次预计、读取／保存工作稿、显式重新预计及候选差异 | 受信资料带入、方案版本、来源指纹、模型派发、核验、计量与未知结果恢复 |
| 治疗耗材预留 | 统一确认整份工作稿及明确的旧预留调整 | 原预留身份、版本、冻结价、替换关系及原子回执 |
| 手术材料事件 | 提交真实最终总量、选定预留与完成意图，返回差额结果 | 净实际量、追加使用、更正冲正、部分消耗、释放与费用审计事务 |
| 分组与复查 | 无需活动任务的结构化核对，按需解释及原记录引用 | 分组／推演复用、依据版本、解释失效与恢复 |

表格表达职责，不要求逐行新建框架。复用 PR #339 的持久化模型建议、材料事件、更正和复查 owner，避免第二套状态机；无需独立预重构票，必要的局部整理随切片完成。服务端状态继续由 TanStack Query 管理。

### 自动单次预计与人工工作稿

计划保存成功留下持久化的单次预计意图，不能靠页面挂载或查询调用模型。单次意图复用已有模型执行及恢复模块，但不依赖医生先开启持续跟进，也不隐式开启长期病例任务。历史计划通过明确操作补建意图。

预计绑定住院、计划、有效临床依据、目录与院内方案版本；自动带入有权正式资料，只要求确认真实缺项。复用已有 PCI 有限合成证据，补充造影方案及独立正反样例。缺测量或数量依据时保留待核实，不从私有作者底稿、目录规格或目标费用反推患者事实。

生成快照与医生未确认工作稿分别持久化。刷新和同库重启恢复，工作稿保存检查版本；新建议作为候选差异，不能覆盖人工编辑。关键依据变化标记需更新，取消、失权、计划撤销或 Epoch 变化后禁止发布原意图的晚到结果。

待生成、生成中、就绪、缺项、依据变化、失败、取消及结果待核查分别可观察。模型未配置或被既有控制拒绝时说明原因，不派发 Provider；已派发结果未知时核查原尝试，不因超时或重启另发请求。预计及解释从首次派发沿用现有计量和授权，不另建账本，也不要求先做新用量看板。

### 整批预留与最终用量

一次确认通过共享 Command 校验整份清单并原子创建或调整预留。同计划再次确认明确列出被取代原预留及其版本，先重审再处理；没有选中的旧记录保留并展示。业务结果未知先查原回执，同键不换输入，不留下半份新预留或提前释放旧记录。

PR #339 的预留读取已有目录版本、冻结价、消费／剩余量及并发版本。本轮沿同一合同补足实际需要的单位和历史依据解析，不能另造 DTO 或继续假设这些字段不存在。历史价格从持久化事实解析；目录改变须展示差异、明确重审，不能静默换价。

完成手术时，医生输入真实最终总量并明确本次处理哪些原预留。系统读取已有逐笔事件和更正后的净实际量，只追加尚未发生的增量，减少或归零沿已有更正语义冲正。没有逐笔事件时可直接形成实际使用；实际记录只接受正数，最终零量不新增零使用或零收费。已有历史不删除、不回写。

最终用量核实、选定预留的消耗／释放、追加使用／更正、计费、完成事实及审计在同一事务中提交，失败全部回滚；不得在页面循环多次请求模拟成功。未选预留不自动释放，这需要显式调整既有完成动作“收拢全部剩余预留”的默认语义及其合同测试。旧入口沿兼容调用明确原意图，不能悄悄改变既有回执。

同材料多条原预留、跨计划候选及目录变化要显式核对，不按名称猜关联。新增材料按有效目录计价，原预计与实际差额保留，预留与正式费用不重复归集。既有逐笔登记和完成动作继续可用，不能用重复完成手术模拟逐笔使用。

### 直接核对与按需解释

三类结构化核对直接读取当前获授权的住院事实，无需有效跟进任务；复用原分组、推演及复查判定。后台待办仍可消费同一规则结果，但不成为页面读取门禁。加载、失败、明确差异、缺项和未发现本范围差异分别表达。

确定性读取不调用模型。医生展开具体问题时才生成解释，绑定该问题与依据版本，有效结果复用、依据变化失效；无模型仍显示规则结果与来源。它不自动更正首页、主操作、诊断或报告已阅，也不将耗材数量或目标病组当作正式分组依据。

固定首个 Persona 自动选用会部分改变[固定 PCI 作者来源与直接住院](../../implemented/architecture/2026-10-26-authored-pci-inpatient-source.md)中的人工首录取舍，来源身份、不可变修订、隐藏事实隔离及一次消费保持。实施时更新当前 owner 和双向引用；本提案不将尚未实现的目标写成当前合同。

## Alternatives considered

- 保留首个 Persona 手填：无需模型，但仍重复抄写固定演示资料。采用固定版本准备；动态病例继续原生成方式。
- 每次由模型重建固定档案：入口统一，但增加运行依赖、等待与漂移；固定准备使用合成模板。
- 直接把黄金账本四项各一件当作预计：便于复现费用，却无法根据当前术式和正式资料估算；模型及院内方案必须有适用与数量依据。
- 每次自动预计都先开启持续跟进：可直接沿用任务身份，但改变用户选择并扩大后台授权；单次生成适配已有执行模块，不隐式启动长期任务。
- 确认建议只保存计划，再逐项建预留：保留现状，但重复操作并可能部分成功；采用一次原子确认。
- 将真实最终总量直接再次计费：接口简单，却重复收取已有逐笔用量；采用净实际量差额及追加更正。
- 完成手术自动释放全部剩余预留：与旧默认一致，但可能清掉本次未选项；采用明确处理引用并展示未选项。
- 新建分组解释引擎或内部 mock seam：隔离容易，却产生重复判定，无法证明真实事务；复用现有 owner，主验证通过公开 HTTP 和临时 SQLite，页面补真实 Playwright 入口。

## Acceptance criteria

可观察要求由正式规格的 B1–B14 及测试策略拥有。固定准备无模型、自动预计有模型参与、确认整批原子、最终用量与逐笔事实不重复、三类核对按需解释，均需从公开入口证明。合成模型测试不替代真实临床质量证据。

## Risks

自动单次预计与活动跟进任务解耦会影响既有身份、授权和用量归属，必须沿用原执行模块及未知尝试恢复。最终用量核实会触及已收费事件和完成时预留清理语义，需同步公开合同、Operation Catalog、运行时 Skill 和漂移测试，保留历史读取及原回执。

本提案核对的 PR #339 尚未合入主线，原审查修复可能改变复用细节。实施采用实际集成版本；不重开旧票范围，不把本轮增量变成旧票的反向阻塞。
