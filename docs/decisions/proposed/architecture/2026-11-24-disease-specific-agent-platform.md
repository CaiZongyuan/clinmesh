# Agent Note: 标准化专病智能体平台目标架构

Status: proposed

## Problem

ClinMesh 已有的专病能力，包括确定性评分、指南专题、医嘱组套、事中质控和床旁风险评估，见[临床决策支持](../../../architecture/clinical-decision-support.md)。它们都按心血管写在 TypeScript 代码里：
- 指南专题靠病历文字匹配启用；
- 专题、组套和科室的 ID 写成合同里的枚举；
- 评分各自读取原始记录，不区分本院与外院，也不区分“没问到”与“没有”。

因此每加一个病种，都要同时改合同、界面、Agent 工具和测试。

[国内外专病智能体调研](../../../research/2026-11-17-disease-specific-agents-survey.md)提出了“一套通用底座加可插拔专病包”的架构，覆盖数据治理、语义、知识、运行时、Agent 执行和评测六个方面。ClinMesh 目前处在 demo 阶段，每期 demo 只实现并演示其中一部分。如果按某一期 demo 的范围来设计架构，demo 用不上的阶段会被直接跳过，以后补上时就要改格式、改合同。

本 Note 是目标架构的唯一 owner：
- 调研文档第四至六章的每一节，都要在本 Note 中有归属；
- 每一期 demo 的正式需求（GitHub Issue）只写本期的实现范围，并引用本 Note。一期做完整的专病包框架和冠心病 demo：凡是能用合成数据、模拟对等方或受控模型流做出来的规划，都放进一期；二期再考虑其他病种；
- 某个预留项进入实施时，另开 Issue 引用本 Note，并按实现结果把相应部分转成当前合同和 implemented Note。

## Proposal

### 状态标记

| 标记 | 含义 |
| --- | --- |
| 已有 | 当前 main 已实现，迁移时保持行为不变 |
| Demo 一期 | 一期实现，用冠心病演示 |
| Demo 一期（仿真） | 一期实现，但真实环境中的对等方（外部系统、第二家医院、审核人、真实模型）由合成数据、模拟对象或受控模型流代替。只证明工程上可行，不证明真实环境中的效果 |
| Demo 二期 | 二期病种 demo 实现并演示（病种待定，乳腺癌为候选） |
| 预留 | 架构已确定接入层、接口和数据，但缺少调研结论、许可或后续病种，暂不实现。实施时不得另起一套结构 |

### 分层

平台从下到上分九层。上层只能通过下层的受控接口读取数据，不能越层直接读原始表。

| 层 | 职责 | 对应调研 |
| --- | --- | --- |
| L0 数据接入 | 把外部系统的资料收拢、认人、去隐私，再转换成原始记录 | 4.3 第一、二步，4.6 |
| L1 原始记录 | FHIR R5 资源、外院病史、床旁问卷，是唯一正本；仿真环境另有隐藏的 Case Truth | 4.1、4.4 |
| L2 临床事实总账 | 把原始记录誊写为带出处、时间、标本和质检标记的事实，并按任务判断资料是否够用 | 4.3 第三、四步，4.4、4.5、4.7 |
| L3 语义 | 概念词表与编码映射 | 4.2，5.3 第 1 部分 |
| L4 知识 | 指南原件、专题页、知识主张，以及发布与撤回 | 5.3 第 2 部分，7.1 |
| L5 专病包 | 公共层、病种包、医院适配三层数据 | 5.2、5.4 |
| L6 包运行时 | 启用、阶段、就绪、排雷与退出、时机与提示卡、展示前安全检查、多包并排 | 5.1、5.2、5.7 |
| L7 Agent 执行 | 固定节点流程、通用工具网关、两道闸、弃答和全程追溯 | 5.5、5.6 |
| L8 评测与治理 | 黄金病例与考卷、启用关卡、标准化报告、消融、静默试运行、受控学习 | 第六章 |

### L0 数据接入

- **接入适配器【Demo 一期（仿真）】**
  - 每种外部来源（HIS、LIS、报告系统、外院资料、基因报告）各有一个适配器。适配器负责把资料转换成 L1 的 FHIR R5 资源，并附 Provenance，Provenance 中写明来源系统、批次和收到时间。
  - 适配器之间只共享“接入契约”，契约包括资源类型、来源系统标识和批次完整性。上层不感知来源系统。
  - 一期提供两个适配器：现有的合成数据来源（Authored Case Pack 和 Visible Source History），以及本院内一个字段结构不同的第二个模拟来源系统（例如独立的检验系统）。后者用来证明总账不依赖来源系统。真实 HIS 接入需要真实医院，不在 demo 范围内。
- **跨系统认人【Demo 一期（仿真）】**
  - 患者匹配有置信门槛，拿不准的进入隔离区等人工确认，绝不凭姓名合并。
  - 用合成数据构造跨系统 ID 不同的同一患者和同名不同人，演示“置信门槛 → 隔离 → 人工确认”。公共陷阱题“同名不同人”同时验证上层不会误合并。
- **去隐私【预留：一期不做】**
  - 出院后的数据进入研究或跨院用途前，要去掉身份信息，并对同一患者的全部日期统一平移相同天数。
  - 这一步只用于研究导出和跨院回传，临床运行不经过它。一期不考虑其他医院，也不做研究导出，所以不做。
- **批次完整性【Demo 一期（仿真）】**：未同步完的批次标为“未完成”，总账不收录，Agent 也读不到。
- **跨院协作【预留：一期不做，调研 4.6】**
  - 采用“数据不出院”：包、考卷和评测运行器进入医院本地运行，只回传指标和考卷结果，不回传病历。
  - 追溯记录和标准化报告都带医院（tenant）标识，这个字段一期就定下（见格式预留）。一期只有合成医院 ClinMesh，不建第二家医院，也不演示跨院回传。

### L1 原始记录

- 本院 FHIR R5 资源、Visible Source History（外院病史）和 Clinical Risk Assessment（床旁问卷）都已有，是唯一正本，总账不覆盖它们。
- Case Truth 只供仿真器和考卷阅卷使用，临床接口与 Agent 都读不到。这一条已有。
- 检查检验结果：
  - 黄金病例的结果只取 Case Truth 中预置的值，没有预置的检查显示“本病例未预置”。【Demo 一期】
  - 一般动态病例沿用现有的参考值和受限生成器。
- 无图像的预置已签发病理、影像报告，以及 Authored Case Pack 去掉心血管专用的必填项。【Demo 二期】
- 多模态（调研 7.1 第 7 问）
  - 架构上以报告文字、结构化结果和元数据为事实来源。
  - DICOM 原图与病理全切片只通过现有素材流程展示，不进入总账，也不进入模型输入。这是长期约束，不是待实现项。

### L2 临床事实总账

- **基本形态**：只读、按需生成，不另外存储。誊写规则按资料来源写，共三套；收录 8 类资料。【Demo 一期】
- **每条事实 14 个字段**【Demo 一期】：
  1. 项目代码；
  2. 原话和归一值；
  3. 方法；
  4. 标本或部位；
  5. 检查时间；
  6. 报告时间；
  7. 出处记录、版本和来源系统；
  8. 本院／外院；
  9. 签发、更正或作废状态；
  10. 有／没有／没问到；
  11. 替代关系；
  12. 确定程度（疑似／确诊）；
  13. 入库时间；
  14. 映射版本。
- **质检标记**【Demo 一期】
  - 可疑：单位不在白名单、超出合理范围、时间颠倒、违反性别常识。
  - 冲突：同一标本同一项目出现矛盾结果。
  - 方法不同的同类项目不合并成一个值。
  - 被标记的事实不参与算分和红线，医生核实后才参与。
- **多处对账【预留：一期不做】**：跨文书核对同一事实，比如手术记录写的支架数与收费耗材数不一致，就标为冲突。对账规则由包声明，平台执行。核实由收费或病案岗位完成，不在医生接诊主线上；以后作为总账的一种冲突规则加入，格式不变。同一报告内的冲突检测仍在一期。
- **大模型抽取【预留：一期不做】**
  - 从自由文本中抽出的事实，必须带原文定位，并标“需复核”。
  - 抽取质量用逐字段对照专家摘录和复现分析来验收（调研 4.3 的 VALID 三支柱）。
  - 以后用合成的自由文本报告和受控模型流演示抽取，用合成的“专家摘录”做逐字段对照，并做复现分析。真实模型运行需要用户针对该次运行的许可。
- **其他规则**【Demo 一期】
  - 外院规则：外院资料标“待核实”，核实后才参与计算。
  - 有效期：平台设默认值，包只能收紧。
  - 按时间回看：只返回某时间点之前已出、当时有效的那一版。
- **就绪三档**【Demo 一期】
  - 包按任务声明关键项和次要项，结果分为齐全、缺次要、缺关键；缺关键时不准起草。
  - 可疑或冲突的事实按缺失处理。
- **任务视图【Demo 一期】**：按任务只给最少字段。比如 MDT 会前、随访、临床试验筛选，各自只取声明过的字段。字段清单复用就绪三档中该任务声明的关键项和次要项，包作者不另写；Agent 通过查事实总账的工具读取时，只返回当前任务声明过的字段。
- **研究库支线【预留：一期不做】**：导出前必须去隐私，而去隐私一期不做。
  - OMOP CDM 只是研究分析的一条支线，从总账单向导出，不是 Agent 的数据来源。
  - 导出前必须完成去隐私。

### L3 语义

- **概念词表**【Demo 一期】
  - 轻量的上下级树，分三层：公共层一棵树，病种包向下扩展，医院层只挂本地叶子。
  - 现有药品分类 `pharmacologyClasses` 迁入词表。
  - 不引入图数据库。
- **编码映射**【Demo 一期】
  - 按 SKOS 分为相等、相近、更宽、更窄四种。
  - 每条映射有审核状态（提议、已审、已批准、已废弃）、审核人和生效日期。
  - 只有已批准的“相等”映射参与算分和红线。
- **映射变更影响报告【Demo 一期】**：映射变更后，能查出受影响的历史事实、规则和考题。
- **标准术语库【预留：按许可决定】（调研 7.1 第 1 问）**
  - SNOMED CT、NCIt、ATC、HPO 只作为映射目标接入，不替换词表本身。是否接入以及接入多细，按病种需要和许可分别决定。
  - mCODE 4.0.0 与 CardX HTN 1.0.0 基于 FHIR R4，CardX CIED 为 R5 ballot 版。只参考其中的数据元素清单，不引入 Profile。
  - 冠心病包可以参考 CardX 的血压表达：诊室与自测分开，自测均值写明方案和时间窗，并标明患者自报还是机构测量。LDL 和心血管风险评分 CardX 没有覆盖，需要自定。
  - mCODE 没有专门的 ER、PR、HER2 Profile，二期如选乳腺癌，需要自定这些项目。
- **临床编码与医保编码对照【预留：一期不做】**：卫健委临床编码与医保贯标编码的对照表放在医院适配层，由 L3 统一查询。现有药品和医技目录的医保属性保持不变。
- **必填与取值约束**：用 schema 和总账质检表达，不依赖本体推理；查不到不等于不存在。

### L4 知识

- **原件库**（已有）：指南原件有 SHA-256、页码和原话片段；任一引用失效，整题停用。
- **两层知识卡**【Demo 一期】
  - 专题页：作用是导航，不替代原文。
  - 知识主张：每条写明适用条件、原文锚点、来源版本、关联概念和审核状态。主张逐条停用。
- **发布状态机**
  - 状态依次为：导入 → 草稿 → 已映射概念 → 自动校验通过 → 医生已审 → 已发布；已发布之后可以被替代或撤回，审核中也可以驳回。
  - Demo 中示范卡最高到“自动校验通过”，界面称“试用版”，每次被引用都标“未经医生检查，仅用于仿真”。“医生已审”和“已发布”只能由登记的临床审核人推进。【Demo 一期】
- **知识快照与就诊时间**【Demo 一期】
  - 运行时只读某个已发布的快照。
  - 提示卡和起草内容都记录包版本与知识版本。
  - 回看旧病例时默认用当时的版本，也可以用新版重看，并标出差异。
- **离线制卡流水线【Demo 一期（仿真）】**
  - 流程：原件导入 → 模型起草主张 → 结构体检 → 医生审签 → 发布快照。
  - 模型只能归纳原件里明文写出的内容，原件未覆盖的留空。
  - 线上运行时不挂任何写知识的工具。
  - 一期用受控模型流起草，并走完体检和审签流程。审签状态遵守 L4 发布状态机：没有登记的临床审核人时，最高只能到“自动校验通过”。
- **新指南差异报告【Demo 一期】**：新原件进入时，列出受影响的专题、主张和规则；冲突交给专家裁决，不静默覆盖。
- **中文检索【Demo 一期】**：知识检索采用中文分词，并用概念词表的同义词扩展。
- **版权【Demo 一期】**：没有分发权的指南全文不随包跨院分发，只分发出处与锚点。一期没有跨院分发。
- **院内疑难病例库【预留：一期不做】（调研 6.5、7.1 第 5 问）**
  - 存的是经过脱敏、经高年资医生审定的“疑难案例卡”，与公共知识分开存放和授权。
  - 只在“超出包范围”时作为参考出现。
  - 以后用合成的疑难案例卡，演示“候选卡生成 → 审定 → 入库 → 超范围时参考”的流程。一期“超出本包范围”卡不附参考病例。

### L5 专病包

- **形式**【Demo 一期】
  - 包是一个数据文件夹，里面不含代码，加载时做 schema 校验并记录指纹。
  - 包的内容包括：说明书（含支持的任务）、触发条件、诊疗阶段、核心指标、不适用人群、知识卡、组套、问卷题、打钩量表、排雷清单、退出条件、易混淆的病、质控收紧项、风险标签、工具白名单与禁止动作、考卷。
- **三层叠加**【Demo 一期】
  - 叠加顺序：公共层 → 病种包 → 医院适配。
  - 本地化内容可以替换；安全类内容只能收紧。
- **公式**【Demo 一期】
  - 复杂公式放在平台公式库，带版本号，包按名字和版本引用。
  - 打钩加分量表写在包的数据里。
- **包的两种类型**【Demo 一期】
  - **完整专病包**：管理诊断明确或疑似的病种，包含阶段、组套、质控、考卷等全部内容。
  - **识别包**：针对容易漏诊的疑难病和罕见病，只包含触发条件、不适用人群、一张提示卡（建议考虑某病，以及可做的确诊检查、转诊或 MDT）和考卷，不包含阶段和组套等管理内容。识别包与完整包共用同一种格式，只是用到的部分不同。
  - 一期示例：在冠心病相关场景中加一个“家族性高胆固醇血症”识别包，触发线索包括早发冠心病、LDL 显著升高、家族早发冠心病史；现有评分的输入里已经包含发病年龄和家族史。为此新增一例合成黄金病例。
- **按病种分阶段推进**
  - 冠心病包与 2 型糖尿病肾功能用药包【Demo 一期】。
  - 其余病种中的一个或多个【Demo 二期】，具体病种待定，乳腺癌为候选。
  - 再往后的病种【预留】。
- **单病种质控必查项【预留：一期不做】**
  - 包声明国家单病种质控的必查项，规则基于总账结构化事实。平台在医嘱签发、出院等现有质控时机执行，未完成的项在医生办理当时提醒，不等出院后人工回填。
  - 必查项只对国家规定的适用人群生效。依据《单病种质量监测信息项（2020 年版）》（国卫办医函〔2020〕624 号附件 2），心肌梗死只覆盖 ST 段抬高型首次住院（主要诊断 I21.0–I21.3、I21.9），非 ST 段抬高型不在范围内；接入前需核对官网原件。
- **DRG 编码核对【预留：一期不做】**
  - 包声明诊断、手术编码与实际诊疗的核对规则，由病案编码岗位使用，复用现有 DRG 分组能力。它不在医生接诊主线上，一期不做；现有 DRG 行为保持不变。
- **CPG-on-FHIR 对齐【预留：一期不做导出】**
  - 证据见 [CPG-on-FHIR、CDS Hooks、CardX、mCODE 与专病包的对齐调研](../../../research/2026-11-24-cpg-cdshooks-cardx-mcode-pack-alignment.md)。CPG 当前发布版为 2.0.0，基于 FHIR R4，没有 R5 版。它用 CQL Library 表达逻辑，直接采用就要引入表达式引擎，与“包不含代码”冲突。
  - 因此包采用内部格式。触发条件、阶段、知识主张、组套、问卷和量表，可以导出为 PlanDefinition、Recommendation、Questionnaire 等结构。工具白名单、禁止动作、考卷、质控收紧、风险标签、易混淆的病和“只收紧”规则，在 CPG 中没有对应结构。
  - 一期不做导出器：导出物是 R4 文件，而平台 FHIR 固定为 R5，目前也没有交换对象。等 CPG 发布 R5 版，或者出现真实的交换对象时，再做导出器，只导出能对应上的部分。

### L6 包运行时

- **启用**【Demo 一期】
  - 按结构化条件自动启用，不看科室，也不匹配文字，并给出启用原因。
  - 触发条件可以跨时间、跨就诊组合总账事实，例如“近 5 年内先后出现 A 和 B”，用来捕捉分散在不同年份、不同科室的线索。条件会说明各个时间窗口取自总账中的哪些时间。
  - 医生可以关闭，关闭留审计。
  - 一位患者可以同时启用多个包。
- **诊疗阶段**【Demo 一期】：由总账事实判定当前阶段，只启用本阶段的内容；阶段切换留审计。
- **时机与提示卡**【Demo 一期】
  - 借用 CDS Hooks 的时机名称和卡片格式。
  - 同步时机包括：打开病历、勾选医嘱草稿，以及四个质控关口。同步时机不调用模型，要求 1 秒内返回。
  - 后台时机为“新报告到达”。
  - 提示卡带依据、来源包与版本、风险标签、草稿动作和否决理由，不允许系统自动写入。
  - 卡片合同的字段分两类：
    - 沿用 CDS Hooks 2.0 的字段：`summary`、`indicator`、`source`、`suggestions`、`overrideReasons`、`links`；
    - 平台自定的扩展：依据事实版本、包与知识版本、风险标签、投递模式。
  - 不使用 `systemActions`。
  - CDS Hooks 中 `patient-view`、`order-sign` 成熟度较高；`encounter-start`、`encounter-discharge` 成熟度仅为 1，只借用名称。
  - 门诊建议、住院意见和 Agent 起草，都改为按时机触发并输出提示卡。
- **提示卡投递模式**
  - 投递模式分为“展示”和“静默”。静默卡只记录、不展示，供静默试运行使用（见 L8）。字段在一期定下，一期只用“展示”。【Demo 一期】
- **依据失效连带失效**【Demo 一期】：卡片和草稿记录所依据的事实版本；依据被更正或作废时，卡片标为过期。现有住院指南意见的 `stale` 状态就是这样处理的。
- **展示前安全检查**【Demo 一期】
  - 检查项：红线、过敏、禁止动作、不适用人群、引用有效性。
  - 这道检查不调用模型，不通过的内容不展示。
  - 现有的独立核验和签发时的红线检查保留。
- **门诊未确诊阶段（调研 5.7）**
  - 排雷清单、打钩量表、退出条件、不适用人群（选择性弃答）。【Demo 一期】
  - 易混淆的病：两个症状相近的包同时启用时，两边都不出治疗建议，先合出一张鉴别单。【Demo 一期：用测试假病种包验证；用真实病种演示要等二期】
  - **包前识别【Demo 一期】**
    - 不在分诊台进行，分诊护士的流程不变。它在医生接诊后运行，位于“启用”之前。
    - 输入是已经结构化的事实：既往史、医嘱、诊断、体征与分级，以及医生手动启用。命中候选包后，追问题通过床旁问卷出现，排序采用“最大信息增益 + 红旗问题插队”，最后给出一张交接卡，写明阳性症状、前三位候选和已排除的阴性症状。
    - 结构化主诉类别和预问诊作为以后新增的触发来源预留，接入时不改触发条件格式。
    - **表型匹配**【Demo 一期（仿真）】：把病人跨时间的异常发现整理成标准症状词（HPO），与罕见病知识库匹配，排出候选病种，并以不打断操作的提示卡给出。一期使用合成的小型知识库；采用 HPO 和真实罕见病知识库之前，需要先核实许可。
  - **组套由医生按习惯选用**【Demo 一期】：包不主动推荐组套，组套只在医生自己选用时出现，选用时照旧按禁忌预筛并标缺项。医生个人组套、科室组套【预留】放在医院层，接入时复用同一组套格式和预筛。
  - **阶梯解锁【预留：一期不做】**：组套项可以带档位和解锁条件，前一档结果命中后下一档才进入候选。它要由平台按档位推出组套，与“组套由医生按习惯选用”冲突；以后作为组套格式的可选字段加入，不破坏现有格式。
  - **无指征检查提醒【Demo 一期】**
    - 质控规则增加“适应证”类别：包用总账结构化事实写适应证规则，不翻病历文字。医生保存医嘱时检查已开出的单子，没有适应证的高值检查出黄牌并写明缺哪条依据；资料不全时显示“缺项待补”，不判为无指征。
    - 黄牌只看临床适应证，不与 DRG 参考余量联合计算：临床警示与 DRG 支付参考分开，门诊与住院用同一规则；DRG 余量照旧单独显示。
    - 医生强行通过时填写的理由，进入 L8 的否决理由汇总。
  - **三车道分流【预留：一期不做】**：包声明快车道、直通和分步三类条件，平台在首个同步时机判定车道，快车道的检查一次性并行开出。它属于分流，并由平台决定开哪些检查，一期不做；以后加入时作为包的可选声明。
  - **先检后诊【预留：一期不做】**：新增“预就诊值班医生”岗位，对预问诊生成的基础检查草稿批量审签。审签必须由医生通过共享 Command 完成，检查范围限于低风险基础检查白名单。它发生在医生接诊之前，要改医院流程；等预问诊作为触发来源接入后再做，接入时不改触发条件和医嘱格式。
  - **诊室环境音书记员与预排单【预留：一期不做】**：基于现有问诊录音能力，把医生口述的检查和用药转成待确认草稿。每句病历都能回溯到原始录音时间点。
- **疑难与罕见病提示不打断**【Demo 一期】：识别包和表型匹配输出的提示卡只给信息，不拦截操作，以控制提示疲劳。
- **多包并排**【Demo 一期】
  - 公共层维护统一的风险标签词表，标签冲突时并排展示，平台不自动取舍。
  - 真实的跨包冲突演示放在【Demo 二期】。

### L7 Agent 执行

- **固定节点流程**【Demo 一期】
  - 流程依次为：鉴权 → 查数据 → 就绪判定 → 查证据 → 汇总事实 → 规则检查 → 写草稿 → 医生审核。
  - 先做单 Agent。
  - 多 Agent 作为消融实验的 E 组，随消融实验一起预留，不进入默认流程；只有消融实验证明有净收益，才切换为默认。【预留：一期不做】
- **通用工具网关**【Demo 一期】
  - 工具不随病种增加；调用时带包 ID，只能用白名单里的工具，包的禁止动作一律拒绝。
  - 已发布的 8 个专病工具保留原名和原路径，改由包驱动。
  - 新增查总账、查缺项、查看或关闭已启用的包。
  - 调研 5.5 的 7 个窄工具在本平台的对应关系：
    - 时间线和已核实事实 → 查总账；
    - 原文证据 → 现有的原文与出处读取；
    - 就绪判定 → 查缺项；
    - 已发布知识 → 知识卡工具；
    - 规则执行与草稿生成 → 由平台在各时机完成，不开放成 Agent 可以任意调用的工具。
- **两道闸**【Demo 一期】
  - 数据闸就是就绪三档。
  - 临床安全闸就是展示前安全检查加签发时的红线。
  - 证据不足时输出“弃答”或“需人工审核”，并说明缺什么。
- **全程追溯**【Demo 一期】：每次执行记录任务、病例、医院、包版本、知识快照版本、模型版本、输入与输出指纹、工具与规则结果、耗时。
- **不可信文本**【Demo 一期】：病历、指南和网页中的文字一律当作数据，不当作指令。
- **安全操作菜单**【Demo 一期，沿用现有设计】：包和 Agent 只能经由平台定义的少数几个草稿动作提交内容。正式写入走共享 Command 和人工确认。
- **实时性（调研 7.1 第 4 问）**：同步时机只做事件驱动的确定性工作；调用模型的工作在后台时机完成。隔天批处理只用于 L8 的评测与治理。

### L8 评测与治理

- **黄金病例与基准**【Demo 一期】
  - 迁移前冻结黄金病例。用现有代码跑出基准结果，迁移后逐项对照，差异必须为零。
  - 考题答案沿用 Case Truth 隔离。
- **考卷**【Demo 一期】
  - 每个包至少有六类考题，另有一套公共陷阱题。识别包的考卷除了要求“该提示时提示”，还要求“不该提示时不提示”。
  - 考卷固定在指定的知识版本上运行。
  - 不及格的包不能启用；新增包时，已有包的考卷不能退步。
- **四级评测（调研 6.1）**
  - L1 数据、L2 语义、L3 知识，以及 L4 中的安全部分（越权工具、禁止动作），由机器判分。【Demo 一期】
  - L4 中 Agent 输出质量的评测（采分清单、正负分双轨、关键事实覆盖、医生修改量）。评分器一期实现，用受控模型流测试；对真实模型输出评分需要用户针对该次运行的许可。没有评分结果时，界面标“Agent 输出未评测”。【Demo 一期（仿真）】
- **出错归层**【Demo 一期】：考题按数据整理、术语映射、知识、Agent 与安全、工作流归层，失败项按层汇总。
- **测试集规则（调研 6.2）**
  - 按患者切分、按时间截断、考卷冻结。【Demo 一期】
  - 按机构切分和外部测试，需要第二家医院。【预留：一期不做】
  - 合成数据只能证明工程上可行，不能证明临床效果。
- **标准化报告**
  - 包括：迁移前后差异、加入新包时的平台改动、复用比例、新增条目数、已有包是否退步、按层失败项。【Demo 一期，二期补乳腺】
  - “不挑来源系统”指在两种模拟来源结构下得到相同的总账视图，依赖 L0 的第二个适配器。【Demo 一期（仿真）】
  - “知识发布效率”依赖离线制卡流水线。【Demo 一期（仿真）】
- **消融实验【预留：一期不做】（调研 6.3）**
  - A 到 E 五组按同一病例、同一模型版本配对比较，严重安全错误单列。
  - 用受控模型流跑时，各组输出都是预先准备的，差异没有说服力，所以一期不做。等用户批准真实模型运行时再实现运行器，每次运行都必须有用户针对本次运行的明确许可。卡片记录依据版本（格式预留）保证以后能复现。
  - 只有消融实验显示有净收益，才加大本体和 LLM Wiki 的投入（调研 7.1 第 6 问）。
- **四层防御（调研 6.5）**
  - 第一层是医疗软件安全自查表，对应条目为：特殊人群、报告撤回连带失效、跨科用药冲突、断网降级、全链路追溯。前四项都已在 L6、L7 中有对应设计。“口述与购药账单不符”的对账放在 L2 多处对账（预留）。【Demo 一期】
  - 第二层是选择性弃答，加上独立于模型的药事红线。【Demo 一期】
  - 第三层是刁钻假病人回归，即公共陷阱题。【Demo 一期】
  - 第四层是静默试运行，使用提示卡的“静默”投递模式，统计 AI 拟开与医生实开的分歧名单。【预留：一期不做】它的价值来自真实医生长期使用后的差异，用黄金病例仿真会与考卷重复。
- **受控学习【预留：一期不做】**：否决理由一期已随 Clinical Override 进入审计，以后汇总直接使用。
  - 否决理由和静默分歧每月汇总、聚类，交医务、科主任和临床药师组成的审核委员会裁决。
  - 合理豁免更新进医院适配层或病种包，违规习惯加入质控重点。
  - 每次更新都要重跑已冻结的考卷并锁定版本。
  - 禁止线上自动改规则或改知识。
- **发布门槛**：
  - 【Demo 一期】核心事实可追溯率为 100%，测试中不出现越权读取成功的案例。
  - 【Demo 一期】有未关闭的严重问题时阻断发布。
  - 【需真实条件】关键字段的最低要求由专科团队逐项设定。一期先由包作者设定，并标为“待专科确认”。
- **医工分工【预留：一期不做，调研 7.1 第 8 问】**：知识与概念由审核委员会批准；数据质量异常由医院数据责任方负责；临床安全事件走院内上报，平台只提供审计记录。

### 现在就要在格式中预留的内容

预留项可以晚实现，但如果格式现在不留位置，以后加入就会破坏已有数据或合同。下面几项必须在 demo 一期的格式中就定下来；其他预留项以后可以作为可选字段追加，不影响兼容性。

| 预留内容 | 为什么现在就要定 |
| --- | --- |
| 总账出处中的来源系统标识，追溯记录中的医院标识 | 以后接第二个来源系统或第二家医院时，不必回填旧数据 |
| 编码映射的四种审核状态和生效日期 | 状态枚举以后扩展会变更合同 |
| 知识的完整发布状态机（demo 只用到“自动校验通过”） | 同上；同时避免“试用版”“正式版”这两个名字和标准状态脱节 |
| 提示卡的投递模式字段（默认“展示”） | 以后做静默试运行时，不需要改提示卡合同 |
| 卡片与草稿记录所依据的事实版本 | 依据失效连带失效、按时间回看、消融复现都依赖它 |
| 触发条件支持跨时间、跨就诊的组合，并标明时间窗口的取值依据 | 识别包和疑难病线索依赖这种语义，以后再加会改变触发条件的格式 |
| 包类型字段（完整包或识别包） | 加载校验和考卷要求按类型区分 |

## Alternatives considered

**只按当期 demo 的范围设计架构。** 这样文档最短，但 demo 用不上的阶段会被跳过，以后补上时要改总账、映射、知识状态或提示卡合同。本提案改为由架构覆盖全部阶段，demo 只取其中一部分实现，并在格式中预留必要的位置。

**包里可以带计算代码。** 调研 5.4 原本建议在包中放 `calculators/*.ts`。包带代码之后，加载时就无法只靠 schema 校验，医院适配层也无法判断某个改动是不是“只收紧”。因此复杂公式统一放在平台公式库，按版本引用。

**沿用病历文字匹配来启用专题。** 现有做法要靠否定句清洗来排除“否认胸痛”这类表述，而且无法表达“上腹痛 + 糖尿病”这样的组合条件。结构化条件可以用考题直接判对错，所以采用结构化条件。

**一开始就上重型本体或图数据库。** 调研的风险登记把“本体做得过重”和“过早上图数据库”都列为交付风险。因此先用关系表和带版本的词表文件，并且只在映射等级和审核状态上做到严格。

**从多 Agent 起步。** 多 Agent 增加的延迟、成本和归因难度，都要先由消融实验证明值得，所以先用单 Agent 固定流程。

**对外提供完整的 CDS Hooks 服务。** 包是平台内部数据，暂时没有外部 EHR 调用方；CPG 也不规定必须用 CDS Hooks 投递。因此只借用时机名称和卡片格式，对外服务作为跨机构交换的预留项，与 CPG-on-FHIR 对齐一起评估。

## Acceptance criteria

- 调研文档第四至六章的每一节，在本 Note 中都有归属和状态标记。每个“预留”项都写明了接入层、接口和所需数据。
- 每期 demo 的需求 Issue 都引用本 Note，并逐条说明本期实现了哪些“Demo”项。Demo 的格式包含“现在就要在格式中预留的内容”中的全部条目。
- 任一预留项进入实施时，都新开 Issue 引用本 Note；实施完成后，把对应部分写入当前合同，并新建 implemented Note。本 Note 只更新状态标记，不改写原提案。
- 预留项实施时不需要修改已有包的数据文件。如果需要修改，说明本 Note 的格式预留有遗漏，要先更新本 Note。

## Risks

- **范围被 demo 带偏**：每期 demo 都可能把“这期不做”误当成“架构不需要”。审查需求 Issue 时，要对照本 Note 的逐节归属表。
- **一期范围过大**：一期包含整个框架，子票数量会明显增加。每张子票都要能独立验收，按依赖顺序推进，演示可以分批进行。
- **仿真被当成真实效果**：凡是标“仿真”的能力，界面和报告都要注明“仿真演示，不代表真实环境效果”。
- **患者认错、标本或时间混淆**：影响极高。由 L0 置信门槛、L2 按标本与时间建模、公共陷阱题共同控制。
- **知识过期或错误扩散**：由主张级版本、快照发布、依据失效连带失效和差异报告控制。
- **Agent 越权**：由服务端工具网关、白名单、禁止动作和审计控制，不靠提示词。
- **模型或知识更新后效果倒退**：模型、提示词和知识版本都要锁定；任何一项更新，都重跑已冻结的考卷。
- **评测集质量不足**：合成黄金病例只能证明工程上可行；在任何场景中宣称临床效果，都需要经授权和伦理审查的真实评测。
- **医院异构程度超出预期**：用接入契约加医院适配层吸收差异，上层不感知来源系统。
