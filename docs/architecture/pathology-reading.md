# 可插拔病理阅片

ClinMesh 拥有患者、就诊、病理申请、原费用、正式报告、责任和报告已阅；外部阅片服务拥有切片、分析、模型、候选、测量与人工复核。两者通过 `clinmesh.pathology-reading.v1` 互通，首个适配器是独立部署的 PathJX。协议与 PathJX 原生 `/api/v1` 分开版本化，不建立通用插件市场。业务流程见[病理会诊](clinical-workflows.md#病理会诊)，部署与恢复见[部署教程](../deployment.md#pathjx-外部阅片服务)。

## 单片绑定与来源

一次会诊冻结一个既往标本、一张 H&E 切片、一份当前报告。`pathology_reading_binding` 按 Workspace、Epoch、申请持久保存外部实例、绑定标识、内容 SHA-256、初始输入和确认版本。更正报告沿用同一张切片；新增会诊不复用别人的人工复核上下文。临床 DTO 不暴露资产键、来源路径或外部内部对象。

外部清单通过 `externalPathologyCatalogSchema` 验证，登记器官、来源诊断、相容标本、许可、署名、去标识声明、真实或合成来源、实例及内容哈希。已发布报告须经人工批准，签名哈希覆盖切片输出、报告全文、修订、单片和染色；变更任何一项使复核失效。已开始病例的准备与报告绑定保持冻结，读取时另查外部可用性。许可字段与哈希是部署者的登记与核对记录，不代表系统自行取得第三方授权。

## 服务与会话

管理员配置使用版本检查、幂等键和共享 Command 审计，只能选择部署已批准的确切 HTTP(S) origin。服务凭据只留 Server，绑定和创建会话不向外部发送 ClinMesh Cookie。未配置、未启用或外部离线均不阻碍 HIS 启动。

服务接口前缀为 `/api/integrations/clinmesh/v1`：

| 入口 | 合同 |
| --- | --- |
| `GET /capabilities` | 协议、实例、器官、标本、染色、任务、模型版本和摘要；读取不触发推理 |
| `GET /assets/:assetKey` | 登记资产的内容身份与当前可读性 |
| `PUT /bindings/:bindingId` | 原意图幂等准备一张切片的隔离复核对象 |
| `GET /bindings/:bindingId` | 原对象身份、可读性与修订检查点 |
| `POST /sessions` | 按当前医生和固定上下文创建最长五分钟受限会话 |
| `GET /operations/:intentId?bindingId=…` | 查询原绑定或会话意图；未知时保持未知 |
| `DELETE /sessions/:sessionId` | 撤销外部会话；本地先撤权，外部故障不恢复本地权限 |

浏览器加载独立 origin 的 `/clinmesh/reading`。无凭据 `GET /bootstrap` 声明协议；iframe 发出 `ready`，父页严格核对 origin 与发送窗口后通过消息发送一次性 `launchToken` 和代次。iframe 使用 `POST /sessions/exchange` 的 `{ launchToken }` 换取内存短效 token；只可调用返回的 `/api/integrations/clinmesh/v1/session/:sessionId`。token 不写 URL、日志或浏览器持久存储，也不使用 ClinMesh Cookie 或 PathJX 原生账号 token。

交换结果只向浏览器暴露申请、报告及报告版本；Workspace、Epoch、病例关系与外部绑定由两侧服务持有。每次服务读取或写入均重新核对 ClinMesh 的单会话授权回调、登录、当前岗位、责任、配置版本与当前报告头。报告更正使旧会话失效；之后可明确重新打开历史报告，只获得读取权限。Agent Grant 和共享服务主体不能冒充医生作人工决定。PathJX 原生 API 隐藏并拒绝接入绑定对象。

## 显示与已阅

`displayed` 必须在实际瓦片绘制后发送。父页验证协议、origin、发送源、会话、申请、报告版本与代次，Server 再核对当前授权、内容和修订检查点；描述或缓存命中不能自行取得资格。`failed`、`invalidated`、`closed` 和上下文变化撤销资格，迟到回执不重新授予资格。

病理已阅仍通过原业务 Command 明确确认，要求当前医生在有效会话内实际显示过该报告切片且原片仍可读。AI 候选、候选已看、人工复核和已阅分别保存，不互相替代。报告阅读私稿不保存启动 token 或像素；连续阅读切换报告可保留同一窗口内的显示资格，关闭、刷新、退出或确认流程结束即撤销会话。会话描述、分析与瓦片使用 `private, no-store`。

## 未知结果与恢复检查点

外部写意图使用稳定编号，同键同体复用、异体拒绝。绑定或会话响应丢失后查询原编号，只有明确查无才重发原请求。浏览器刷新后，同医生、登录与当前报告的未决会话也先恢复原编号，不另建对象。人工动作的原回执由 PathJX 持久化，刷新后先读未确认回执；当前读取授权允许查询，不能因此获得重发写权。

初次绑定修订必须为 `0`。PathJX 写前发送 `authorize`，携带绑定、当前修订和稳定意图；ClinMesh 保存该意图的前序检查点。业务事实与原回执在 PathJX 同事务提交，随后发送 `committed`，携带同一意图、前序与提交后修订；ClinMesh 在同一事务确认意图并推进检查点。提交后回调丢失只重发原确认，重复确认不会把后续检查点倒退。授权后尚未提交的意图不阻断只读查询；重试继续使用同一意图，只有其原确认能推进版本。

原对象缺失、内容变化、确认版本缺失或回退时，绑定进入 `repair-required`，拒绝新的显示资格和写入，不自动补建、换片、重跑或采纳未知远端版本。停用与切换实例保留旧映射，重新启用原实例可恢复；替换实例不能静默接管历史。协议不兼容拒绝嵌入阅片和写入，ClinMesh 文字报告与历史引用仍可读。

## 计算与验证边界

关联切片、打开页面、模型登记和启用均不自动触发接入推理。受控准备或医生明确区域分析固定原片、范围和模型版本；历史结果不随新模型启用自动替换。专用病理视觉执行器的像素处理与通用问诊模型隔离，真实模型运行仍须本次明确授权。

两侧合同样例、合成 HTTP 与浏览器旅程验证接线和拒绝边界，不证明真实医学质量。原片许可和完整哈希、已安装模型以及真实部署联调分别核验；没有这些证据时不得把合成服务测试称为真实模型接入成功。取舍见[Agent Note](../decisions/implemented/architecture/2026-11-20-pathjx-pathology-integration.md)。
