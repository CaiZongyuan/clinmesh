# 临床业务流程

本文定义 ClinMesh 跨岗位临床状态机的共享边界、领域合同导航与跨工作流连续办理不变量。系统总入口见[系统架构](../architecture.md)，业务验证要求见[测试策略](../testing.md)。

## 状态机与责任边界总览

ClinMesh 通过共享 `CommandExecutor` 驱动门诊与住院状态机；HTTP、FHIR R5 Operation、Web/Desktop 与受控 Agent 工具共用同一套领域校验、预期版本（CAS）、幂等回执、`AuditEvent` 与 `Action Trace`。临床意图、实际执行、财务账目与病案归档彼此分离：签发后的申请、处方、医嘱、手术、病历与报告禁止无约束覆盖，取消、撤回、停嘱、冲正与修订均通过显式状态转换、`Provenance` 与逆向事实留痕；临床取消不等同自动退款，财务冲减或退款也不回退临床执行；仅当当前 Epoch 内全部门诊完诊、无未归档住院或待转收住院证、且门诊检查取消退款责任归零时，`Scenario Run` 才完成一次。

## 连续办理私稿与逐项原回执恢复

门诊与住院多岗位集中办理窗口在不新增通用批量写 API 的前提下，通过客户端会话私稿与既有共享 Command 回执实现跨刷新连续办理：

- **分页、勾选与动作隔离**：多页候选列表保持每页 10 项、单次上限 20 项（门诊目录开具上限 8 项，手术完成核实上限 100 行）；跨搜索与翻页保留已明确勾选和编辑的项目并展示完整计数，“当前页全选”仅纳入本页当前符合可办理条件的项目。“清空选择”只取消勾选并保留草稿，单行移除与需二次确认的整份丢弃分开执行。阅片窗口中的影像与病理已阅显示资格证明仅在当前窗口内存有效，不写入或从 `sessionStorage` 私稿恢复。
- **三类提交与部分成功语义**：门诊诊断组、整张处方与多费用合并收款各自通过单笔共享 Command 原子提交；门诊独立检查开立在外层统一校验身份与建议指纹后按每项 SQLite savepoint 独立计价并返回单份按下标对齐的回执；其余连续办理动作（住院医嘱开立／校对／核停／执行、检验送检、报告已阅、检查取消／重试、手术耗材预留与更正）在确认前逐项冻结不可变 Command 载荷与原 `idempotencyKey`，队首顺序调用既有单项 Command，确定业务拒绝保留前序已完成事实并将失败项留回草稿重审。住院医嘱开立的费用预计绑定生成时的待开集合修订，草稿增删改后旧预计失效；术后耗材逐笔更正按前序成功回执顺序递进 `surgeryRequest` 预期版本，共享预留变化时立即停止后续项目。
- **未知结果原回执恢复与只读门禁**：成功项在持久写入层先推进前序临床／病例 revision 并消费对应私稿行，再清除写意图。遇到网络超时、`503` 或响应不可解析等未知结果时立即停止后续项目并冻结新提交，在同一身份作用域查询原回执（`GET /api/his/v1/command-receipts?operationId=...&idempotencyKey=...` 或限定医生 Session 的 `GET .../confirmations/:idempotencyKey`）；仅明确返回 `404 COMMAND_RECEIPT_NOT_FOUND` 且当前状态仍允许写入时才按原载荷、原幂等键重放，恢复查明后余项须重新核对确认，不自动续发旧队列。病例进入待出院、离院或归档只读后仍允许查询结清先前已发出的未知原回执。客户端 `sessionStorage` 键隔离、坏稿保留与退出登录补清理合同见[浏览器未提交私稿](storage.md#浏览器未提交私稿)，设计取舍见[临床连续办理私稿与逐项原回执恢复决策](../decisions/implemented/architecture/2026-11-10-clinical-batch-draft-and-receipt-recovery.md)。
