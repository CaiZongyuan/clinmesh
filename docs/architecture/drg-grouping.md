# CHS-DRG 条件分组合同

本合同定义固定 CHS-DRG 3.0 原程序的条件提取、计算、规则包与独立对照。住院流程继续由[临床业务流程](clinical-workflows.md)拥有；离线资料的获取、来源限制与完整逻辑文件读取见[DRG 储存合同](../drg-reference-storage.md)。本实现用于仿真和来源程序一致性核对，不构成地方正式医保分组或结算一致性证明。

## 来源与计算

计算入口为 `groupDrgCase`，接受单一主诊断、单一主操作标记及保持临床顺序的次诊断、次操作。主诊断和主操作移动到各自首位，其余相对顺序保留；多主诊断返回 `invalid-input`，多主操作返回 `ambiguous`，有操作却未选择主操作返回 `invalid-input`。规则只读临床事实，不更改诊断、操作、收费或支付记录。

编译器只解析 JavaScript AST，将完整有序路由、终端谓词和参数表转换为 `clinmesh.drg-program.v1`。运行时只解释封闭节点，不导入来源 JavaScript，也不使用 `eval` 或动态函数。未支持的 AST、发生变化的未编译预处理或结果映射、缺少引用、循环调用和覆盖失配均拒绝准备或装载。组名只用于展示，不能推导计算条件。

| 条件类别 | 计算语义 |
| --- | --- |
| MDC、ADRG 与终端优先级 | 保留原程序短路顺序，包括先期分组、新生儿、多部位创伤和各疾病系统；不从首个成员码回填 MDC |
| 联合操作与诊断条件 | 保留主操作、次操作切片、任一诊断、诊断和操作组合、匹配数量及有序兜底；不将联合条件展开成彼此独立的操作成员 |
| CC、MCC 与排除 | 按原预处理遍历完整诊断列表，以主诊断 CCE 组号排除同组并发症；每码先判 MCC 再判 CC，终端仍执行原诊断数量条件；解释返回排除组和实际参与码 |
| 年龄、性别、日龄与出生体重 | 执行原谓词，覆盖 6/70 岁、28/365 日和 1000/1500/2000/2500 克等边界；性别未知、婴儿日龄缺失或实际路径所需出生体重缺失时返回 `invalid-input` |
| 机器人与产科严重条件 | 机器人检查原指定的次操作；产科严重主诊断名单独立于普通 CC/MCC 条件 |
| 多部位创伤 | 按原来源分区计算不同受伤部位数，保留主诊断资格和操作条件 |
| 有效操作与歧义 | 使用完整 SS_VALID 参数及原 MDC 内判定；原程序 QY 结果映射为 `ambiguous`，失败码映射为 `ungroupable` |
| 编码适用性 | 诊断和操作分别核对从源条件及参数提取的精确码词表；任一主次编码未知时显式 `coding-incompatible`，不忽略次编码后报告成功 |

星号组合码保持来源字典的整码语义，例如 `B+G*` 不自动由两个独立诊断合成，也不做名称或模糊映射。临床版编码仍由病案 owner 管理；只有来源程序精确接受的编码才能直通。`dischargeMode`、`inpatientDays` 保留输入合同，但本锁定源没有使用它们，不宣称这两个字段参与计算。

## 住院输入与冻结

在院计算读取已确认诊断和已实施操作；主操作取病案首页选择，计划只进入单独的推演。年龄以离院时点、尚未离院时以入院时点计算日历整岁，未满周岁保留实际日龄。无效或未来出生日期产生无效输入，不替换为零岁。

出生体重读取同一患者已有、状态为 `final`、`amended` 或 `corrected` 的 LOINC `8339-4` Observation，只接受 UCUM `g` 或 `kg` 并换算为整数克。当前体重、其他患者、初步及已作废测量不参与；没有正式记录保持缺失，正式记录冲突或无法解释单位时保持未知。首页只保存克数及 Observation 的 id/version 投影，不创建第二份可编辑体重记录，也不增加新生儿诊疗入口。

人口属性与出生体重来源版本参与在院推演指纹。首页修订和归档保存其快照；归档分组及历史 Command 回执仍直接读取原持久结果，不依赖当前规则包、当前 Observation 或新编码词表。旧快照可以不含出生体重属性，其原序列化、来源哈希、原费用及回执不被补写。

## 规则产物与交接

`clinmesh.drg-rules.v2` 包含 `manifest.json`、`groups.jsonl` 和 `program.json`。manifest 保存 release/sourceVersion、原 JavaScript/参数表/层级文件 SHA-256、实际条件类别、MDC/ADRG/DRG 覆盖及产物哈希和行数。准备时交叉核对源内 CC/MCC/CCE/SS_VALID 与独立参数表，核对全部终端、ADRG、MDC 集合及父级。装载时再次验证程序结构、来源覆盖、文件身份和层级，文件哈希合法不能替代条件完整性核验。

旧 `clinmesh.drg-rules.v1` 只含成员表和按名称推断的谓词，不能表达完整条件，因此拒绝装载并要求重新准备。这个格式变化不影响历史 `DrgGroupingResult`，不迁移或重新计算归档数据。

维护者使用显式文件路径创建尚不存在的新目录，失败不替换已有产物，也不修改运行库或自动启用规则：

```sh
pnpm --filter @clinmesh/server drg:build-rules --source <原程序.js> --tables <chs_drg_30.json> --groups <r3/groups.jsonl> --output <新规则目录> --release <不可变规则身份> --source-version <来源版本> --expected-source-sha256 <已锁定原程序SHA256>
```

正常启动接线、规则包选用、病例物化和最终支付联合验收由 [#279](https://github.com/CaiZongyuan/clinmesh/issues/279) 负责；共享目录及首例 PCI 参数由 [#303](https://github.com/CaiZongyuan/clinmesh/issues/303) 负责。本包产物不更改现有离线资料的用途、许可待核验或适用性隔离状态；启用仍须消费对应来源核验结果，不能把本次程序一致性证据当成正式使用许可。

## 独立对照与覆盖

维护工具在没有网络、文件系统和进程能力的独立 VM 中执行已核对 SHA-256 的原程序，仅作为显式离线验证 oracle。运行时分组与规则准备不执行来源代码。合成输入由原源码路由成员、联合条件、人口边界和独立写明的人工案例生成，预期来自原程序及人工解释，不读取 ClinMesh 输出生成预期。

```sh
pnpm --filter @clinmesh/server drg:verify-rules --source <原程序.js> --tables <chs_drg_30.json> --rules <已物化规则包目录> --report <新报告.json> --program <新程序产物.json>
```

报告保存来源身份、条件清单、各例输入及来源位置、人工预期、oracle 预期、实际结果、差异和未命中终端。非零差异或遗漏不能被隐藏。完整源固定为 OpenDRG `2026-10-20` 的 CHS-DRG 3.0：原程序 SHA-256 `70c00d9ef9b02c1556b8a96ece350f6ce3d1fd2b6f9dd8ea80c2ec7d2ba0f0ff`，参数表 SHA-256 `75e10058ed0a30e2f679c68b34b8db8a580c5572b8667f2b9a1bf258de8db3b5`，r3 层级 SHA-256 `4dba56d298c8a6d07266978498c8e429e6bb4fc456cbf14c1bb45ea016e855cb`。实际固定核验结果与产物身份见[对照记录](../research/2026-10-25-drg-condition-verification.md)。

条件支持清单和有限合成输入分别证明语法覆盖与行为一致性；终端全部命中也不等于枚举所有可能病例。来源、编码或格式升级必须重新编译和对照，不能沿用旧哈希通过或仅跑成人样本。取舍见[完整条件程序决策](../decisions/implemented/architecture/2026-10-25-drg-condition-program.md)。
