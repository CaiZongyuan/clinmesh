# 收费、结算与医保

本文定义门诊与住院收费账单、共享收款交易、多费用合并原款收款与逐分配原路退款、住院预交金与实时欠费摘要、首次冻结结算、患者医保待遇共享计算与品规级甲乙丙混合处方明细结算、手术与住院 DRG 费用推演口径、以及结算后财务更正与原年度医保补偿重算合同。门诊独立检查预付费放行与取消门禁见[检验、检查与报告](examinations-and-reports.md#门诊独立检查的应收与执行门禁)，门诊处方分轨与药房交接见[处方、医嘱与药事](orders-and-pharmacy.md#门诊处方分轨无需用药结论与撤回)，住院出区、清床与病案归档锁见[住院与手术流程](inpatient-workflows.md#住院出院召回窗口与清床)。

## 收费账单、合并原款收款与逐分配原路退款

### 门诊只读账单与分次／多费用合并收款

门诊账单按单次就诊 `Account` 只读聚合既有 `Charge Record`，展示挂号、检验、放射、病理、功能检查与本院处方应收、累计成功收款、有效医保覆盖、当前未收余额及分页支付历史；账单不维护可手工覆盖的独立余额字段，正式财政票据暂未实现（院内收款统一由本地 `PaymentTransaction` 与关联分配表表达，不混同 `ChargeItem` 可计费活动或 `Invoice` 账单，不保存逗号拼接 ID 字符串，也不滥用 FHIR `PaymentNotice` / `PaymentReconciliation`）。挂号费保留为只读应收；未收款即已撤回的处方退出有效应收汇总，已全额收款后撤回的处方保留原实收历史等待财务处理。

收费员支持单项分次收款与同次就诊多费用合并收款，所有金额均以整数分计量，单笔尝试可组合现金、银行卡与移动支付（每种渠道至多出现一次，显式金额须为正整数，未指定方式时默认现金结清剩余应收）：

- **单项分次收款**：预览冻结目标 `ChargeItem`、本次金额、支付方式、费用版本、岗位上下文与真实时间五分钟有效期，凭 `commitToken` 确认；部分收款保持剩余应收可继续收取。
- **多费用合并收款（`payment.multi-charge.preview` / `confirm`）**：允许明确勾选同患者、同次就诊的 2–20 项可收款费用（可跨四类医技与已完诊未撤回本院处方，一项失格即整单拒绝而不静默剔除）；每项本次收款金额固定等于其当前剩余应收，组合支付方式总额必须精确等于所选余额总和（不支持多项不足额任意分摊）。确认在同一共享 Command 事务内重验全部冻结项与版本，仅创建一笔共享原款 `PaymentTransaction` 与多条逐项分配记录；成功、拒付或结果未知作用于整笔尝试，绝不产生部分费用资金成功。

当某项原费用的“成功收款减成功退款再加有效医保基金与个人账户分配”足额覆盖净应收（原费用减累计冲减）且无未决资金时，按费用策略触发一次临床放行（放行医技受理或移交完诊处方至药房；后续医保撤销产生的补收仅改变财务余额，不回退或重复触发临床执行）。任一关联收款或退款处于结果 `unknown` 未决状态时，严格阻断该费用的新收退款预览、确认与医保变更；收费员须通过支付历史调用 `payment.recover` 或 `payment.multi-charge.recover`（提交原支付版本与全部关联 `ChargeItem` 版本，不接受新金额或结果覆盖），按原收款时冻结的渠道结果追加唯一终态后方可继续办理。合并原款与恢复取舍见[门诊多费用合并收款决策](../decisions/implemented/architecture/2026-11-10-outpatient-multi-charge-collection.md)。

### 费用冲减与逐分配原路退款

收费员先针对具体 `ChargeItem` 版本登记带明确原因的费用冲减（`ChargeAdjustment`），降低净应收集上限而不直接发送资金、不撤销任何临床医嘱或发药执行；随后基于已成功原款经共享 `RefundLedger` 预览并确认部分或全额退款（合并原款必须通过 `refund.allocation.preview` 显式指定 `paymentId` 与 `chargeId`，严禁从整笔原款猜测目标费用）。

每笔退款同时受四重硬约束：原交易剩余未退总额、合并原款内该指定费用分配的未退余额、该费用跨原款共享的累计冲减依据剩余额度、以及单笔退款硬上限 `1,000,000,000` 分（1,000 万元，大额原款须分次预览审阅退回）。退款严格按原款冻结的支付方式逆序原路退回，每种方式不超过其未退余额，不允许操作员改选退款渠道。结果未知的退款尝试立即预占原款、渠道与冲减依据额度（拒付则释放预占），恢复查询仅追加原冻结渠道终态；客户端在发起冲减、预览、确认与恢复前将原幂等键与完整载荷写入经结构校验的会话 `sessionStorage`（见[浏览器未提交私稿](storage.md#浏览器未提交私稿)），刷新或断线后先查 Command 回执以杜绝重复退付。新冲减与新退款要求 `Scenario Run` 处于 `active`，仅既有未知退款查询收敛允许同 Epoch 人类收费员在 `completed` Run 执行。

## 住院预交金、欠费摘要与首次冻结结算

### 预交金、出区补缴退款与实时欠费摘要

`InpatientPayments` 复用门诊同一套 `PaymentCollection` 与 `RefundLedger` 承载入院预交金、首次封账前的追加预交金、出区补缴与原路退款（单笔退款上限同样为 `1,000,000,000` 分）。成功预交金与补缴按 `paymentId` 去重计入本次住院专属资金池（拒付或未知不入账，未封账资金严禁自动跨门诊或跨次住院结转）；退款只能引用本次住院已成功的预交金或补缴原款，不超过当前待退差额与原款可退余额。未知收退款不阻断医生开立出院医嘱或护士办理实际出区，但硬性阻断新增收退款、首次封账与护士清床。

已授权的住院列表与详情读模型在同一快照内提供窄字段 `outstandingFen`：当资金与医保状态确定时返回当前尚应收的非负整数分（首次结算前按患者现金负担减净入金计算，首次结算后切换为后续财务更正的待收净额），当存在未知收退款或医保来源失效待重审时返回 `null`（界面不推定结清、也不重复提示补缴）。临床医生仅读取该窄摘要，完整资金流水与逐项账单严格限收费员岗位访问。

### 逐项账目指纹预览与首次封账

患者由病区护士办理实际出区（`departed`）后，收费员通过窄结算预览接口（不含临床出区医嘱说明）一致读取逐项住院费用（发生时已冻结科室归属的正向账项及结算前全额冲正反向行）、预交金／补缴／退款流水及有效医保分摊，生成稳定的逐项结算指纹（覆盖每行费用 ID、版本、金额、来源、科室、业务日、冲正关系、入金记录与医保状态）。

`inpatient.discharge.settle` 在写事务内重读全部账务数据，严格校验原结算指纹、`expectedChargesFen`、`expectedBalanceFen`、无任何未知资金尝试且剩余待收退现金差额归零（仅在从未发生过任何独立收退款尝试且差额未超单笔上限时，兼容允许人工审阅 `settle` 在同事务完成默认现金结清；一旦存在独立拒付或未知尝试，必须显式补收退并重新预览）。结算成功后原子冻结首次结算快照与唯一资金用途投影，同时永久锁定 `InpatientBilling` 普通入账与结算前普通冲正入口。资金池与首次封账设计见[住院资金与首次冻结结算决策](../decisions/implemented/architecture/2026-10-22-inpatient-funding-and-first-settlement.md)。

## 患者医保待遇与品规级甲乙丙混合结算

普通门诊与住院共用 `InsuranceService` 患者医保待遇计算内核：所有金额均按整数分计算、比例乘法采用确定性整数截断，仅在医保统筹基金、个人账户与患者个人现金负担之间执行分配，不创建现金收款流水、不改写原费用金额，也完全独立于医院侧 DRG 支付参考额。待遇账户绑定 `Workspace/Epoch`、`Patient` 与上海时区虚拟日历年：患者在该年度首次确认医保结算即锁定年度参保方案（合成职工 v1 具备年度起付线、统筹比例、年度封顶与期初个人账户，合成居民 v1 具备不同起付线、比例、封顶且期初个人账户为零；具体合成参数由 `InsuranceService` 拥有，撤销原结算也不允许跨方案切换），门诊与住院的目录内累计、年度起付线与基金封顶线分别独立核算，个人账户余额跨门诊与住院共享。

药品与医技目录维护品规级甲／乙／丙合成医保属性（甲类 `included=true, priorSelfPayBps=0`；乙类 `included=true, priorSelfPayBps=1..9999`；丙类目录外 `included=false, priorSelfPayBps=0`），在门诊开立处方／检查及住院下达医嘱／计费时分别冻结写入 `prescription_item`、`charge_record`、`inpatient_order` 与 `inpatient_charge`（门诊挂号、放射与病理固定为目录外；仅历史未冻结存量行兼容回退旧类别默认比例；缺失医保映射一律以 `INSURANCE_COVERAGE_UNAVAILABLE` 拒绝预览，绝不以零报销静默放行，后续目录调整不溯及已开立账项）。包含甲乙丙多品规的混合处方先在明细级逐条截断算出目录外全自费 `outsideFen`、乙类先行自付 `priorSelfPayFen` 与纳入统筹合规费用 `eligibleFen` 并汇总至对应 `ChargeItem`（若收费员做过费用冲减，按最大余数确定性比例回填各明细净额），再统一扣减年度剩余起付线、按方案比例与年度封顶切分统筹基金、以个人账户余额抵扣目录内个人自付部分，剩余差额由患者现金承担，完整明细拆分保留在 `allocations[].items` 供展示与审计。

门诊药品待遇预览与确认要求 `Encounter` 已完诊（否则返回 `INSURANCE_FUNDS_CONFLICT`），已收取患者现金的费用须先完成财务更正方可重新结算医保；住院首次医保待遇仅允许在患者已出区（`departed`）、未首次封账、未归档且无未知收退款时确认或撤销，一旦完成首次封账即冻结为病案归档核账基线（归档强制核验“原患者现金 + 原统筹基金 + 原个人账户 === 原费用净额”）。医保撤销必须指定原结算记录及其所属原年度的 `expectedBalanceVersion`（通过 `annualBalances` 读取，禁止用新年度版本撤销跨年旧单），每份原结算至多追加一份负向年度补偿记录并完整保留历史链。患者待遇与混合处方明细规则见[患者医保待遇内核决策](../decisions/implemented/architecture/2026-10-22-patient-insurance-benefits.md)与[品规级甲乙丙医保属性与混合处方明细结算决策](../decisions/implemented/architecture/2026-11-19-item-insurance-coverage-and-mixed-prescriptions.md)。

## 手术与住院 DRG 费用推演口径

住院患者侧收费／个人医保待遇与医院侧 CHS-DRG 支付参考额严格分立（见[收费、住院与 DRG 边界决策](../decisions/implemented/architecture/2026-10-21-payment-inpatient-drg-boundaries.md)）。住院 DRG 页面、单次耗材预计与术中实时面板统一按四组不重叠口径去重汇总预计住院总收费：

1. **已发生正式收费净额**：实际已发药（含已发药尚未给药，不重复计入未记费承诺）、手术台内基数用药、首次完成报告的医技检查、已完成病区服务与手术完成自动联动的术中专科护理、已登记手术及耗材使用、实际在院午夜床日费减去冲正后的净额。
2. **未记费医嘱承诺**：已签发医嘱在首次排班前计下一剂或单次服务承诺（含已校对尚未排班的长期医嘱），生成排班后仅统计尚未发药／尚未执行的实际待办任务，不向未来住院天数外推疗程。
3. **材料预留未用余量**：活动耗材预留按冻结目录单价乘剩余未消耗数量（`remainingQuantity`）计算；已实际消耗部分归入正式收费净额。
4. **未预留草稿与计划增量**：待实施计划术式费（含已转同台 PCI 阶段术式费）、该计划术式绑定的术中专科护理联动费（同台转 PCI 若同申请造影阶段已计收相同术中专科护理则自动去重、不重复计入承诺与完术费用），以及尚未转化为正式预留的有效人工工作稿／选型增量（同一手术计划存在未确认人工工作稿时以整份人工稿覆盖选型预计；`projectionComplete` / `projectionMissing` 显式标记纳入草稿是否具备完整有效价格，缺价时严禁将残缺金额展示或解释为完整预计）。

住院患者页头进度条与 DRG 页共享确定性口径优先级（界面展示规范见[住院工作台](../ui/design.md#住院工作台)）：存在待实施或进行中手术计划且推演分组可用时，展示计划实施后的预计病组、预计总收费与参考差额并注明“按计划手术预计”；无待实施计划但存在新完成手术尚未被在院主操作确认覆盖时，仅在唯一候选或全部主操作候选得出相同病组与支付参考时展示重算后的 `postoperativeEstimate` 并注明“待确认主操作”（候选分歧或缺参考时保持待确认状态，绝不沿用旧正式参考误报超支）；其余情况展示当前正式分组与已发生收费净额。达到有效正参考额 `90%` 提示“接近”、严格超过 `100%` 提示“已超”（仅作临床进度参考，绝不充当医嘱／耗材开立硬上限或医院全成本盈亏结论；PCI 支架组 `FM39` 与纯造影组 `FM59` 分别消费 `pci-drg-payment-parameters.ts` 声明的独立合成支付参数）。AI 费用说明经生成与独立核验双重校验，仅允许引用确定性费用块内的真实金额与单位；术中 `drg-agent` 实时跟踪每类耗材的计划量、已用量、剩余量与超计划偏离，一旦收费、医嘱、预留或工作稿变动使费用指纹失效，立即将旧文字说明标为过期且不自动重发模型请求。手术流程费用与核查辅助见[手术流程费用与核查辅助决策](../decisions/implemented/architecture/2026-11-13-surgery-flow-assistance.md)。

## 结算后财务更正与原年度医保重算

住院首次结算封账后（含 `settled`、`cleared` 已清床与 `archived` 已归档阶段），人类收费员会话可在当前 Epoch 的 `active` 或 `completed` Run（`closed` Run 与失效 Agent Grant 关闭新写）对原正数住院费用追加带明确原因的后续冲减或补计。原费用、首次结算快照、行政出区／床位状态与不可变归档病案首页均保持冻结不倒退；当前财务账仅叠加有明确业务引用的后续更正，病案页以只读方式并列展示原冻结金额与结算后当前差异。

后续费用更正与资金收退分步确认：反向未结清更正先行抵消差额，退款同时受本更正剩余额度、全账待退净额及选定原成功交易（含首次入金与后续成功补收）可退余额限制，补收同时受本更正额度与全账待收净额约束；一旦存在任一结果未知的后续补收或退款，所有新预览与确认均以 `INPATIENT_FUNDS_PENDING` 阻断，直至查明原尝试终态后重新预览。

对已确认医保待遇的住院病例，结算后财务更正由 `InpatientInsuranceAdjustments`（每次住院同时仅允许存在一条未结清更正）在 `financial-adjustments/:adjustmentId/insurance/cancel|preview|confirm` 链路中按序串联：先精确逆转当前有效待遇在原结算日历年度的累计影响，再沿用首次参保方案、冻结品规覆盖属性与原结算年度实时累计余额，按“原费用 + 全部结算后费用调整”重建替代待遇预览并校验原年度余额版本。仅在新替代待遇确认生效后，才按“新患者个人现金负担 - 当前已收净现金”计算并开放后续补收或原路退款，不以账面费用增减方向机械限制医保重算后的实际现金差额。
