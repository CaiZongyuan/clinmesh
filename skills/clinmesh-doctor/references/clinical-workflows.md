# Doctor Clinical Workflows

## Consultation and diagnosis

A pending doctor turn owns one shared reply execution. Overlapping ask, retransmissions and retry requests join that execution; every request still checks its own authorization, input and receipt. Read `consultation.replyAttempt`: `executing` keeps the original `deadlineAt` and model even if a different retry key joins it. A new waiter never extends the 30-second deadline, and leaving the page does not cancel an accepted reply.

`MODEL_CONTROL_BLOCKED` (409) means model dispatch is waiting for controls or ledger availability; the saved doctor question remains. A `blocked` reply resumes only within its original deadline, with valid authorization and current case state. Poll the case and original receipt while it waits. Expiry terminates that attempt; only an explicit clinician retry can start another. Restoring controls never automatically resends an `unknown` request.

Submit free-text `message` with the current Encounter, doctor Task and Consultation versions. The doctor message is saved before patient generation; each text reply is frozen. Report cards carry formal report references and do not count as text replies. After a timeout or ambiguous outcome, query the original Command receipt and refresh the case. An `executing` receipt proves acceptance, not an answered turn. The same ask/retry key replays its original successful reply or terminal `failed`/`unknown` outcome without new inference; completed replies take precedence over an uncertain attempt state. `AI_TIMEOUT` and `CONSULTATION_REPLY_UNKNOWN` represent unknown outcomes, and restart does not automatically answer them. For `AI_AUTH_FAILED`, check the selected model's access; for `AI_REQUEST_FAILED`, check availability. Only after the original attempt terminates and the clinician explicitly requests another reply, use `encounter.consultation.reply.retry` with the refreshed Consultation version and a new retry intent key; that new attempt binds the current ClinMesh model. Repeat that intent with the same key and identical payload only. Never resend the doctor message as a new intent.

Completed Encounters and legacy question-topic personas are read-only. Case Truth is not a query surface; derive conclusions only from visible source history, triage, Consultation Records and signed results. Save diagnosis entries as a draft, then confirm only after exactly one entry is primary. A later draft and confirmation creates a new linear diagnosis revision and invalidates the superseded Conditions; re-read the case before using the diagnosis downstream.

## Recommendation recovery

The doctor workbench's recommendation `recovery` state reports durable stage progress, request counts and `canContinue`. Ordinary preparation requests reuse the same failed, unknown or exhausted generation. A clinician can continue the original task with its model, successful checkpoints and remaining requests, or explicitly regenerate from current input with the current model and a new generation. Unknown requests require explicit continuation; exhausted or invalid input cannot continue. These controls currently belong to the workbench API, with no published recommendation CLI command. Read the [current workflow contract](../../../docs/architecture/clinical-workflows.md#81-门诊闭环) for the API and limits; do not substitute a new consultation question or an unrelated Command to reopen a recommendation.

## Laboratory and services

Search the case-scoped laboratory catalog and select one active Hospital Laboratory Service. The global Reference catalog defines terminology and cannot be submitted as a Clinical Request. Save one laboratory request draft and issue it only from its current version; the server freezes the service and report definition. Payment and LIS processing belong to downstream actors. A failed Investigation generation may be retried through its explicit command: a new manual attempt binds the current ClinMesh model when generation starts, and its automatic retries and restart recovery keep that model. The responsible doctor acknowledges the latest final report; an administrator uses a separate Grant for the controlled correction command, which the server binds to `lis-system`.

Hospital Service order and completion are separate high-risk Commands and create normal ServiceRequest, Task, and ChargeItem facts.

## Outpatient investigation billing and cancellation

Read the case-scoped catalog and review `outpatientBilling` before issuing an independent laboratory, imaging, pathology or functional examination request. A missing or invalid outpatient price returns `CATALOG_CONFLICT` and preserves the draft; refresh the catalog and review again. Never submit an amount or infer a price from inpatient configuration. Issue freezes the selected service and price and creates one original charge atomically. Keep that request's `billing.chargeItemId` for the cashier handoff; partial, declined or unknown funds leave the request waiting. Read financial status separately from clinical status. Only full definite funding permits acceptance; later financial changes preserve an already accepted request's first release snapshot.

The doctor's workbench confirmation binds every manual or Agent investigation selection to its `reviewedService` snapshot. A service or price change returns `CATALOG_CONFLICT` before saving any selected draft; keep the selection, refresh the catalog and explicitly review again. This confirmation accepts a doctor Session only, with no CLI command or Agent Grant. CLI and Surface issue proposals continue to issue a saved, version-bound draft; do not substitute a recommendation confirmation or inject a new price. Snapshot details belong to the [current investigation billing contract](../../../docs/architecture/clinical-workflows.md#门诊独立检查的应收与执行门禁).

Cancel only `issued` or `generation-failed` requests with the current request, ServiceRequest and Task versions. `WORKFLOW_CONFLICT` blocks cancellation with unknown collections/refunds or active insurance: resolve the cashier's original unknown attempt, or have the cashier run the original `insurance.cancel` first. Refresh after these financial changes. The cancellation Command appends a full reduction of the original fee and preserves history; the cashier separately refunds each original successful payment. An unpaid cancellation creates no refund, and a partly paid cancellation refunds only collected funds. A version or workflow conflict requires a fresh read and decision. Ordinary cancellation rejects `accepted`, `in-progress`, `reported` and `acknowledged` requests.

Retry the original failed request using its latest version; its frozen service, price and charge remain unchanged, and no second charge is created. A cancelled request cannot retry or release. Historical `legacy-unbilled` independent requests keep their original behavior without retrospective charges; inpatient investigation execution and charging remain separate. The detailed state and funding rules belong to the [outpatient investigation billing contract](../../../docs/architecture/clinical-workflows.md#门诊独立检查的应收与执行门禁).

## Functional examinations

The case-scoped examination catalog owns the available ECG and TTE services. Their versioned drafts, issue, original-charge funding, cancellation and retry use the same lifecycle as the other investigations, with their own examination operations. Read the current case examinationRequests after each action; acknowledge only its latest signed report using that request version and DiagnosticReport version. A repeated acknowledgement with the original key reads its saved receipt. A query or opening a report never records acknowledgement.

Reports contain frozen text findings, impression and structured results. Normal adult baseline results are available only for ordinary adult Synthea cases without conflicting cardiovascular facts; missing or partial exact truth must not be filled with normal values. See the [functional examination contract](../../../docs/architecture/clinical-workflows.md#无像素功能检查) for supported measurements and snapshot rules. Inpatient doctors issue the same services through inpatient investigation Commands and ward nurses dispatch them; the outpatient payment gate does not apply to inpatient requests.

## Medication

A prescription draft is not a MedicationRequest. Keep all items in one draft or issuance from a single source: either active outpatient hospital pharmacy items (`catalog clinical get`, which create hospital `ChargeItem`s for cashier settlement and pharmacy dispensing) or national reference products (`reference medications search`, which issue an external electronic prescription with `Prescription` and `MedicationRequest`, satisfy `medication-conclusion`, and skip hospital billing and pharmacy queues). Mixing both sources returns `CATALOG_CONFLICT` (`reason: PRESCRIPTION_MIXED_CATALOG_SOURCES`); keep only one catalog source in the draft before saving or issuing.

Hospital medication frequencies are `QD | BID | TID | QN | PRN | ONCE`. When the catalog declares `safety`, use its ICD-10 indication prefixes, pharmacology exclusions, single/daily dose limits and course-based quantity ceiling; do not treat the legacy example dose or quantity arrays as exhaustive. Keep only combinations accepted by the shared rules.

Resolve prescription rejection by `error.reason`: replace mutually exclusive pharmacology classes (`PRESCRIPTION_COMBINATION_NOT_ALLOWED`); confirm a primary diagnosis first (`PRESCRIPTION_DIAGNOSIS_UNCONFIRMED`); align confirmed diagnosis or select an indicated drug (`PRESCRIPTION_DIAGNOSIS_NOT_ALLOWED`); replace drugs conflicting with active allergies (`PRESCRIPTION_ALLERGY_CONFLICT`); adjust `doseText`, `frequencyCode`, `courseDays`, or `quantity` to allowed values (`PRESCRIPTION_DOSAGE_NOT_ALLOWED`); reread draft and Encounter versions before saving/re-issuing (`PRESCRIPTION_DRAFT_STALE`, `PRESCRIPTION_ENCOUNTER_NOT_ACTIVE`); or reread the case when the Encounter already has a formal prescription—an Encounter allows only one prescription, and withdrawing an undispensed prescription unlocks `confirm-none` rather than a second prescription (`PRESCRIPTION_ALREADY_ISSUED`). Confirming no medication is an alternative formal conclusion (`PRESCRIPTION_NO_MEDICATION_RECORDED`). A signed prescription may be withdrawn only before dispensing begins.

## Clinical document and completion

Patient answers, proven doctor supplements and published report text are recorded directly across twelve document fields after deterministic source validation. Read the latest draft and per-source recording results; use existing document quality control for source meaning, previous facts, correction/conflict relations and rejected-fact context. Legacy verification states are inactive and cannot be retried. No doctor acknowledgement or suggestion application is required. Save explicit text edits with the current version, preserving other fields. Create a complete version-bound document preview and sign from it; correction of a signed document creates a new revision. Signing never completes the Encounter.

Preparation fixes the document and the Consultation or source snapshot, including doctor-only cases without a Consultation, and invalidates in-flight recording. A changed Consultation or source snapshot requires cancellation and a new preview. Cancel with the current Encounter version and previewId to return to editing. A recovered or expired preparation remains visible through consultationRecording.signingPreparation, even without automatic recording. Cancellation preserves explicit pauses and failures; use the recording control to resume or retry. On an ambiguous commit recover the original receipt and reread the case before cancelling an unsigned preparation. Formal signing and Agent high-risk proposal approval keep their existing authorization.

Review the preview's `qualityControl` separately: current field issues and pending, stale, failed or incomplete checks are advisory and do not add a signing gate. The [doctor Skill](../SKILL.md#document-and-completion) owns quality categories, source boundaries and the explicit clinician decision to retain text. Saved checks use `caseId`, `encounterId`, `encounterVersion` and `expectedDraftVersion`; unsaved checks additionally require the complete `document`, `clientId` and `clientRevision` together, without saving the clinical draft. Retention uses `issueId`, `expectedInputFingerprint` and the candidate's `clientId` where applicable, with optional `reason`. A changed input requires a fresh read and decision; recover an ambiguous write with its original idempotency key and receipt. These operations do not restore automatic recording's old acknowledgement or per-fragment controls.

Encounter Completion is independent of document signing, payment, dispensing, and Scenario Run completion. Read the completion preview and resolve every incomplete condition before submitting the completion Command.
