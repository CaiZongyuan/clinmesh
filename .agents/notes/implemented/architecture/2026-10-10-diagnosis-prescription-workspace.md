# Agent Note: 诊断与处方两阶段视图

Status: implemented

## Problem

诊断与处方的目录选择、整组表格编辑和正式记录阅读使用不同的显示结构，窄分栏里同时编辑多条记录使上下文和焦点不稳定。需要在首次填写时直接检索目录，并在正式确认后集中阅读选中记录，同时保留诊断修订、整张处方生命周期和 Agent 的真实表单。

本文拥有 [诊断与处方两阶段工作台](../../../../docs/spec/2026-10-10-diagnosis-prescription-workspace.md)的视图阶段与目录布局，部分取代 [医生临床目录选择与草稿确认](../feature/2026-08-31-doctor-clinical-catalog-dialogs.md)的诊断／药品必须先打开 Dialog 和整组表格编辑决定。原 Note 的明确选择、搜索、分页和不同领域模型边界继续有效。

## Decision

首次诊断编辑以是否存在正式 confirmation 为界，处方以是否存在正式 Prescription 为界。已保存草稿保留目录与编辑阶段；已有 confirmation 的新诊断草稿继续使用管理阶段；已撤回处方保留正式记录。筛选为空不改变阶段，不增加服务端阶段字段。

诊断和处方分别复用其现有目录 picker。首次目录使用紧凑卡片，选择立即加入当前草稿；处方先由医生明确选择具体产品和包装。更换 Dialog 保留暂选、取消与明确加入合同。已确认诊断的追加 Dialog 复用目录与选中条目编辑，关闭保留已发生的修改。目录与条目编辑只有一个活动实例，避免重复 Agent 表单或并行改写同一输入。

列表、搜索、筛选、所选条目及窄屏列表／详情切换属于页面视图状态，服务端事实由现有 Query 管理，当前草稿、自动保存和正式动作继续由原页面与 Command 拥有。列表操作不删除事实，已完诊诊断详情只读取正式 confirmation。窄屏返回后焦点回到列表搜索，追加 Dialog 关闭后回到触发器；共享 Input 沿用 Button 的 forwardRef 模式兼容 React 18／19。

更换弹窗打开时暂停后台目录搜索，关闭后恢复原查询和页码，避免两个显示实例共享远端结果却保留不同查询标签。处方草稿删除按病例和删除版本处理，已过期的回执不清空后续草稿；刷新重建的回执对象身份不触发重复删除效果。

确认作用于整组诊断，开具、删除草稿和撤回作用于整张处方。无需用药先展示当前草稿清除预览，提交继续调用原 Command。未保存或保存中时保持终结动作门禁；目录与保存失败保留输入并提供重试。状态进度只使用实际 Prescription 状态，未提供的缴费、调剂时间、给药途径和价格不推导为事实。

## Alternatives considered

**维持目录 Dialog 与整组表格。** 复用已有布局，但首次操作仍需先打开弹层，多条输入同时占用窄分栏，难以把当前条目与编辑对象对应。

**在服务端增加界面阶段。** 可直接返回初次／管理标识，但它能由正式事实派生，会增加缓存、迁移和一致性合同。草稿保存及筛选结果也容易被误当正式阶段变化。

**合并诊断与药品为泛型工作台。** 两页都具有目录、列表和详情，但主次角色、备注、药品产品、包装及用法属于不同模型。共享 primitives、搜索与分页即可，避免引入大量可选字段和模式分支。

## Consequences

新 UI 继续使用现有持久化、授权、版本、幂等和审计合同；没有新增接口或临床字段。正式记录和未确认输入可并存，确认 revision 或 Prescription 才决定阶段，组件挂载与查询刷新须保留当前输入。

公开页面交互回归覆盖选择、主次、包装、修订、整张处方动作、错误恢复和只读；真实服务器旅程验证持久化和刷新。Surface 以 React 18／19、ShadowRoot、长中英文、两种主题、三档字号及桌面／窄分栏合同验证焦点和布局。
