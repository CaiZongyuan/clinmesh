# Agent Note: 全病历整理的统一来源与自动写入

Status: implemented

## Problem

患者回答是现有整理任务的唯一持久来源，任务与增量直接外键关联 Consultation Turn。医生向助手补充查体、评估及安排时，需要既证明真实输入与病例归属，又保留独立于患者对话的来源。把补充伪装成患者问答会改变待回答状态；仅凭浏览器 permit 写入无法证明文字真正提交到宿主。全病历自动写入同时需要保留人工片段、来源、逆操作和签署冻结，正式要求由 [#177 规格](../../../../docs/spec/2026-10-14-doctor-full-document-recording.md)拥有。

## Decision

将患者、医生和报告统一为病例级整理来源，复用同一持久任务、outbox 和共享 Command。旧患者来源的 ID 保持 Consultation Turn ID，历史任务、引用和模型绑定不改身份；医生补充独立保存，以 Session 与 RPC 防重复，不插入患者对话。引用继续使用兼容的 `sourceTurnId` 字段，实际归属与正文由服务端来源索引解析。

宿主通过公开原生 inbox hook 将实际输入与已有 permit 的 Session、RPC、原文 hash、消息及病例目录绑定配对，签发独立、短期的来源证明。Server 依据证明和当前认证上下文派生病例，在 Command 幂等回放之前重新检查原任务锚点。来源证明不消费 Tool 执行或代问许可；无 Tool 的正常聊天也能进入整理。短期输入索引有界，未接受输入随丢弃、取消与卸载清理，已经持久接受的来源不因主会话正常结束丢失。

无冲突新增、相关补充及有明确来源的自动片段更正定向写入草稿，保留来源与未核对状态；人工改写和事实冲突保持待处理。保留字段内布局、局部确认与撤销，不重新引入跨字段的大面板。模型仅整理来源中已有信息，查体与后三类医生计划字段有更窄的来源规则，不推断新诊疗方案。

## Alternatives considered

- 将医生补充保存成发给患者的 Consultation Turn：复用表更少，但会污染问答语义与患者待回答状态。
- 直接使用浏览器申请的输入 permit：缺少真实原生输入证明，伪造正文仍可能取得 permit。
- 等待主会话调用写入 Tool：没有 Tool 的讨论无法持续整理，来源处理会受主模型行为影响。
- 为每类来源建立新任务运行器：重复顺序、重试、模型绑定、签署和恢复合同。
- 全部结果先手动应用：减少自动改写，但增加逐项点击，不能满足已确认的自动更新目标。
- 重写整篇病历：来源和人工归属难以保留，逆操作会影响无关内容。

## Consequences

公开 HTTP 与真实 SQLite 覆盖统一来源迁移、自动写入、局部人工保护、拒绝与撤销、暂停恢复、重启和签署。Host 输入证明覆盖原文/Session/RPC 伪造、两种到达顺序、无 Tool、正常结束、丢弃与重复。Web 与 React 18/19 ShadowRoot 验证八字段、来源身份、未保存输入和焦点；实际 DSH 右侧无 Tool 的医生补充触发左侧草稿更新，组合旅程保持原有问诊、核对、局部撤销、暂停补录及签署边界。

引用完整且归属正确仍不保证语义忠实，独立模型核验与医生核对继续必要。来源范围扩大须同步持久化、统计与签署摘要，否则医生补充可能绕过剩余内容检查。迁移须保留旧增量归属、拒绝证据、逆操作及任务模型身份；当前进度与长期事实分别由实现和 owning 文档记录。

原始报告快照的保存不等于启用病历整理。已启用的来源进入持久任务与签署核对；未启用时的患者问诊和真实医生补充也需要核对。仅有原始报告的旧病例继续沿用原报告已阅与兼容签署规则，全部来源数量仍作为预览后的变化屏障。
