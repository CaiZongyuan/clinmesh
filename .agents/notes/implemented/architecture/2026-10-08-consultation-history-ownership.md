# Agent Note: 病史片段归属与定向核对

Status: implemented

## Problem

[病史增量基础边界](2026-10-08-consultation-history-increments.md)在草稿并发变化或同字段存在人工内容时保守地留下待核对建议。这能保护人工内容，但不能满足[自动记录规格](../../../../docs/spec/2026-10-08-consultation-auto-record.md)要求的局部保护：编辑一句现病史不应停止同字段其他片段的补充与更正。

## Decision

普通新增按完整句拆分，所有拆分片段通过输出合同验证后才保存 UTF-16 文本范围、当前片段和自动／人工归属，模型将多句放进同一引用时也不会连带锁定未修改句子。草稿保存仍使用原 expectedDraftVersion，通过共享 Command 同事务按字符差异移动范围，并把实际修改的片段标为人工；删除后保留零长度锚点和人工归属。手动恢复原措辞不清除人工归属。

旧增量仅在原始片段完整且唯一存在时恢复范围，多句原引用保留为 superseded 历史并生成独立句级范围，原草稿措辞与排版不变。病例 Query 和共享 Command 使用同一确定性恢复结果，句级标识绑定旧增量、句序与原话；Query 只投影，不写库。医生可直接用 Query 返回的标识核对或撤销，无须先保存草稿或等待新回答。恢复在内部 Command、草稿保存、核对或增量应用事务中落盘；模型获取历史目标时使用同一组句级标识，避免单句更正误替换旧多句范围。无法定位或拆分不符合合同的旧片段持久化人工归属；未能安全拆分的多句目标不能自动或定向替换，需要医生编辑原文。这避免恢复原措辞后重新取得自动覆盖权限或删除其他句子。

无冲突新增追加到当前字段，草稿其他部分的版本变化不阻止追加。辅助模型只接收截至任务回答的 Consultation 文本与已有患者原话的增量标识；每条更正或矛盾必须绑定同字段、较早来源的一个增量并引用一个完整句子，缺失目标或跨多句的输出被拒绝并重试。明确更正仅替换仍由自动记录拥有的有效范围；人工归属、失效目标和模糊矛盾留下待核对建议，保留原文及对应回答。所有写入仍重新验证责任、岗位、Epoch、文书状态和签署准备。

增量身份绑定字段、原话、来源、关系和目标，同一增量重试或同批重复只处理一次。未拒绝的普通新增继续按字段与原话去重；新来源的更正或矛盾即使复用历史措辞，也按其绑定目标和当前归属处理。[持续核对与局部撤销](2026-10-10-consultation-history-review-undo.md)进一步限定拒绝只绑定原来源证据，并拥有持久审阅状态和逆操作。

核对 Command 接受单条增量标识、accept／ignore、Encounter 与草稿版本和幂等键。接受仅替换当前仍有效的目标范围，保留其他文本，结果归人工所有；忽略只改变建议状态。失效范围或版本冲突要求重新核对，不按整个字段覆盖。旧目标标为 superseded，已忽略建议保留历史状态；确认、撤销及历史来源展示见[持续核对与局部撤销](2026-10-10-consultation-history-review-undo.md)。

服务端状态仍由 TanStack Query 拥有。浏览器合并基线分别保留前次持久值与当时显示的预填；显式保存前，某字段的持久值仍为空且首次收到已应用自动内容时，将该内容追加到已改写的预填之后，其他字段是否已有自动草稿不影响此规则。字段已有持久内容时计算三方文本合并，只接收不与未保存编辑重叠的后台变化；重叠时保留本地编辑。核对界面展示原片段、新建议和患者原回答；目标字段存在未保存修改时先保存，再允许接受替换。

## Alternatives considered

- 整字段人工锁定：无法让同一病史的未修改部分继续更新。
- 每次重生成整篇文书：难以维护原话来源和人工归属，会扩大覆盖范围。
- 只用字符串查找替换：重复文字或人工改写后无法可靠定位；唯一精确匹配仅用于旧数据恢复。
- 浏览器单独保护编辑：刷新、重连和无浏览器的后台任务会丢失保护，因此归属保存在 SQLite，客户端只保留未保存输入。

## Consequences

本决策替代基础边界中的整字段和全草稿版本门禁，沿用其来源验证、授权及签署不变量。公开 HTTP、病例 Query 与 file-backed SQLite 验证局部修改、更正、矛盾、版本竞争、幂等和服务重启；真实 Web 旅程验证未保存片段合并与核对，React 18/19 ShadowRoot 合同验证来源展示、禁用状态和键盘操作。暂停、补录与任务恢复见[记录恢复决策](2026-10-08-consultation-recording-recovery.md)，持续提示、来源展开与撤销见[审阅和撤销决策](2026-10-10-consultation-history-review-undo.md)；签署提示由签署切片拥有。
