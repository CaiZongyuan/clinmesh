# Agent Note: 病史增量来源、持续核对与局部撤销

Status: implemented

## Problem

[片段归属与定向核对](2026-10-08-consultation-history-ownership.md)保护局部人工编辑，但仅有 applied／pending 不能区分医生尚未核对的自动内容与已确认内容，也不能安全逆转更正。刷新后失去新增提示或整篇回滚都会破坏[自动记录规格](../../../../docs/spec/2026-10-08-consultation-auto-record.md)要求的来源追溯与人工保护。

## Decision

增量分别持久化应用状态、`reviewStatus` 和拒绝事实。自动应用从 unreviewed 开始，医生逐条 confirm 后变为 confirmed；显式接受替换本身完成核对。人工编辑归属继续独立保存。页面根据持久状态显示未核对数量、自动新增或自动更正标记；查看来源沿 `sourceTurnId` 展开同一 Consultation 的完整患者回答与时间，已忽略、被替代或已撤销的历史仍可追溯。这些历史保留审阅与拒绝事实，但不计入当前待核对状态，也不显示当前手工核对请求；撤销后续更正、恢复旧条目时，原有待核对需求随旧条目重新生效。来源对话框使用现有 Surface Portal，支持 React 18/19 的 ShadowRoot。

`encounter.consultation-history.review` 保留窄输入，在 accept／ignore 之外支持 confirm／undo，所有决定通过原共享 Command、当前 Encounter 与草稿版本、岗位责任、签署状态和幂等回执执行。旧多句增量沿用[片段归属决策](2026-10-08-consultation-history-ownership.md)的只读恢复投影，审阅与 Query 使用同一句级标识。undo 只逆转当前有效且仍属自动所有的精确范围，普通新增删除该片段；只有片段结束于行尾或字段末尾时才删除前方追加分隔符，连续旧句子或相邻人工文字的换行保留。更正恢复应用时持久保存的前一片段原文，并重新激活前一增量的范围。更正链必须从当前有效增量逆序撤销，不能通过撤销已被替代的祖先覆盖后续更正。Command 已知的替换范围直接移动其他锚点，避免字符 diff 将重复的“患者自述”前缀错配到相邻句子、误标为人工修改；医生自由编辑仍使用原字符差异跟踪。人工编辑与之后的无关新增保留。

人工改写、删除或无法可靠定位的片段不被强制覆盖；undo 只记录拒绝并转为 undo-pending，医生手工核对后 confirm 保留当前内容。撤销前按草稿合同校验完整恢复结果：超出字段长度上限时同样记录拒绝并转为 undo-pending，保留当前正文、草稿版本、前一增量的替代状态及其他锚点；恰好达到上限仍可撤销。未保存的目标字段编辑先保存，再核对或撤销；其他字段的未保存输入仍由原三方合并保留。历史审阅状态和拒绝事实互不替代，确认手工核对不会使同一拒绝证据再次可自动写入。

正常增量身份保留字段、来源回答、原话、分类和目标；同一句更正或矛盾指向多个旧片段时分别处理，同一目标的重复结果仍去重。拒绝证据另外按字段、来源回答与去除末尾句界标点和空白的原话识别，不因合法引用包含或省略句号、更换目标标识或更正／矛盾分类恢复同一拒绝建议。普通未拒绝内容继续按字段与原话去重；拒绝绑定原回答，新回答即使重复相同措辞也可以形成新增量。旧数据升级默认尚未核对，已有显式接受的替换保持已核对与人工归属；旧更正从持久前一片段恢复逆操作原文，无法恢复则进入人工核对。旧 Command receipt 中缺省的 reviewStatus 由响应 schema 补齐，原键仍能重放。

## Alternatives considered

- 回滚整篇草稿：会删除人工修改及之后的无关自动内容，不能表达局部意图。
- 只删除更正后的文字：会丢失被替换的原陈述，因此保存应用时的逆操作原文。
- 浏览器临时高亮或打开页面即视为已读：刷新失效，且查看不等于核对，因此核对由显式持久 Command 完成。
- 永久封禁同一措辞：会丢弃后续新增证据，因此拒绝按来源回答限定。
- 所有建议都按来源原话跨目标去重：会丢弃一句患者更正涉及的其他目标，因此只有拒绝证据使用跨目标身份。
- 对人工改写做模糊字符串删除：可能误删医生的其他内容，因此保留原文并要求人工核对。
- 截断恢复原文或删除后续内容来满足长度上限：会丢失病史或人工编辑，因此超限撤销进入人工核对。
- 将被替代的待核对条目标为已确认：会制造未发生的人工核对事实，并丢失撤销更正后的原核对需求，因此保留历史审阅状态，仅在条目有效时产生当前处理提示。

## Consequences

SQLite migration、Operation Catalog 与运行时医生 Skill 同步增加持久审阅与局部撤销合同；不新增通用写工具。HTTP／file-backed SQLite 覆盖逐条核对、来源持久化、普通与链式更正撤销、人工修改或删除、三个病史字段超限后的保留与持续核对、长度上限内恢复、版本与岗位拒绝、幂等、同句多目标更正与矛盾、拒绝后的句界表示变化、新证据和旧数据／回执升级；旧多句回归直接用 Query 返回标识确认或撤销，并验证读取不落盘、相邻文字与换行保留、重启和幂等重放。待撤销核对项被自动或人工接受的更正替代后不再产生当前待核对状态；逆序撤销更正后恢复原待核对需求，重启保持同一结果。Playwright 从生产 Web 入口验证刷新后提示、完整来源、确认与撤销，React 18/19 合同验证 ShadowRoot Portal、键盘关闭及窄宽度，并验证已替代历史不显示当前手工核对请求。签署前的综合提示仍由签署切片拥有。
