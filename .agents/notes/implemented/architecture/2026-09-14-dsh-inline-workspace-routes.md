# Agent Note: DSH 侧栏平铺岗位导航

Status: implemented

## Problem

岗位导航需要常驻 DSH 侧栏，位于新会话与工作区之间；设置和外观适合保留在底部菜单。本决策取代[宿主承接工作台导航](2026-09-14-dsh-host-workspace-navigation.md)中的岗位入口位置，保留其权限、路由、全屏与生命周期合同。任务合同见 [issue #88](https://github.com/CaiZongyuan/clinmesh/issues/88)。

## Decision

DSH adapter 把已授权的岗位路由渲染为独立导航区，底部“医院工作台”菜单只提供设置、外观与应用操作。展开时显示图标和名称，折叠时显示带可访问名称和标题的图标，当前页面使用选中样式与 `aria-current`。路由和图标复用 Web 的定义，权限与当前页面仍由 Web 发布的注册状态决定。

固定版本 DSH `0.1.5-rc.1` 没有该位置的扩展插槽。兼容层从官方 footer 入口定位同一 `sidebar` 内的 `sidebar.workspaces` 标记，在其区域前插入插件拥有的独立节点，并用 React portal 与 ShadowRoot 渲染。它不覆盖、移动或重新挂载宿主工作区。局部 MutationObserver 在宿主重绘时重新定位节点；锚点消失时移除节点，插件卸载时断开观察并删除节点。导航区限制高度并独立滚动，工作区保留可用空间。

## Alternatives considered

**全部放入底部菜单。** 减少兼容代码，但隐藏了高频岗位导航，不符合常驻位置要求。

**使用全局 panel 插槽。** 该插槽虽然位于目标位置，但其点击语义是切换 DSH 主面板，不能代替 ClinMesh 的内部导航。

**替换工作区或复制宿主侧栏。** 会扩大宿主会话状态和维护范围。直接修改全局安装包又无法由项目构建和插件卸载可靠恢复，因此不采用。

## Consequences

兼容边界依赖固定版 DSH 的 slot 标记和工作区区域层级；升级宿主时必须验证真实入口中的顺序、折叠和卸载。宿主提供对应的常驻导航插槽后，应以官方插槽替代该兼容层。入口不存在或会话撤销时不展示失效岗位操作。

Adapter 测试覆盖导航顺序、底部菜单分工、展开与折叠、工作区节点替换和卸载；真实 DSH 浏览器证据验证宿主布局。未新增业务状态、持久化数据或权限规则。
