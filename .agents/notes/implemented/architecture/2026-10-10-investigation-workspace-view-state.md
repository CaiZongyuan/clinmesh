# Agent Note: 检验检查工作区的阶段派生与视图状态

Status: implemented

## Problem

检验、放射和病理使用不同草稿、临床规则与报告结构。统一工作区需要区分未开立时的目录编辑和已有申请时的跟踪阅读，但草稿、取消记录、筛选为空和后台报告到达都不能改变临床事实或丢失操作入口。需求见[正式规格](../../../../docs/spec/2026-10-08-investigation-workspace.md)。

## Decision

按当前病例、当前分类的完整已签发申请集合派生阶段，不持久化阶段字段。取消和失败记录仍属于申请集合；列表搜索和待阅筛选仅改变可见项。TanStack Query 拥有申请、草稿与报告，分类、搜索、选中申请和历史展开只保存视图选择，不复制服务端 DTO。

三类页面复用列表与追加容器，各自保留目录、表单验证和 Command。分类切换保留已挂载表单，病例切换隔离组件和视图状态。页面 Tools 的外层 section 仍为 `laboratory`；分类和选中申请进入页面状态与 revision，工具导航先选分类和申请，再打开既有阅读器。已阅资格仍绑定实际显示的 DiagnosticReport ID。

## Alternatives considered

- 服务端保存阶段：增加跨客户端同步和迁移成本，并可能在取消、任务返回或刷新后与申请事实不一致；阶段没有独立业务含义。
- 用草稿或筛选后的列表判断阶段：草稿尚未签发，待阅清空也不代表未开立，会使用户失去已有报告入口。
- 合并三类通用申请模型和写命令：抹平病理来源、放射指征和检验报告定义，增加业务合同变化，超出本需求。
- 分类切换时卸载页面：减少挂载内容，但会丢失尚未保存的申请信息；保留表单挂载，隐藏非当前分类，阅读器沿用现有按需读取。

## Consequences

`DoctorCaseController` 持有按病例隔离的分类、申请与报告选择，并将实际选中项及检验输入纳入页面 revision；默认选择从完整 Query 事实恢复。显式导航与申请选择分开，后台签发只更新原分类的选中申请，保留用户当前分类及其他分类正在读取的报告。未初始化输入与显式取消选择分别使用 `undefined` 和空字符串，取消后不会被已保存草稿重新选中，人工与 Tool 都须等当前输入匹配已保存草稿才开立。迟到的保存、签发和删除回调只能调整原病例的输入，服务端事实仍由 Query 更新。

`InvestigationRequestWorkspace` 只拥有搜索、筛选和追加弹窗的显示。三类页面在分类切换时保持挂载，隐藏分类不挂载阅读器或弹窗；切换病例恢复该病例已保存的草稿。目录失败的同条件重试显式触发 `refetch`，列表筛选清空后仍可返回完整集合。放射与病理的已阅资格继续绑定实际显示的 DiagnosticReport ID；工具同时导航两个阅读器时，病理成为当前分类，放射保留待打开的选择，不宣称两者同时可见。

两阶段布局没有数据库迁移、服务端阶段字段或跨类别写命令。旧病例继续使用原兼容入口；已完诊的读取与纠错仍服从既有权限。回归通过医生工作台、各类别公开页面、真实 HTTP 浏览器旅程和 React 18／19 Surface 合同观察行为；原生 DSH 宿主还验证同一构建的真实登录、开立、报告、已阅、追加与刷新恢复，测试范围见[测试策略](../../../../docs/testing.md#用户界面验证)。
