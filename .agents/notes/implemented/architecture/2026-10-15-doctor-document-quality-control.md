# Agent Note: 病历质控的输入归属与人工处理

Status: implemented

## Problem

自动整理的写入前来源校验只覆盖本次整理增量，不能代表整份病历没有缺项、遗漏或矛盾。整理控制版本只随控制动作变化，不能识别正文保存、未保存编辑或来源新增。Agent 直接设置病历草稿又与人工保存共用入口，单靠自动整理片段无法判断所有 Agent 新增事实的来源。

## Decision

按[批准规格](../../../../docs/spec/2026-10-15-doctor-document-quality-control.md)建立独立的病例质控状态，复用现有 Command、outbox、模型绑定、输入哈希与授权校验。检查输入绑定实际候选正文、已保存草稿版本和可见来源；未保存候选只用于检查，不隐式写入临床草稿。持久任务完成前重新核对输入和授权，旧代次、旧来源或旧 Epoch 的结果不成为当前结果。

确定性规则校验适用模板和引用归属，语义问题必须带可复核的正文位置、原文和时间。Agent 直接设置的新增内容保留其归属；客户端声明的来源不是可信事实，仍需服务端核对引用及语义。人工文本不因没有引用被归为 Agent 无来源内容。

医生核实保留的决定绑定该问题的相关正文和证据，记录处理人、时间及选填原因。重算复用仍然适用的决定；相关事实变化后重新核对。该决定不成为患者事实，不自动修改病历或解除原有签署门禁。

签署预览显示其实际正文的质控摘要以及尚未完成、过期或失败状态。质控任务完成不改变预览正文，也不单独让预览失效；新的提示不要求额外勾选或阻断正式签署。

正文只为当前具体待处理问题显示一条医生可理解的短提示，多处问题按需展开；影响、处理建议、依据、已核实历史和检查状态统一放入说明。没有具体问题时隐藏质控块，检查未完成、过期或失败仍在说明内保留真实状态；隐藏不是检查通过，签署预览也沿用此展示边界。

问题定位只响应医生点击，限定当前病历的对应字段，滚动并聚焦输入框。只有该字段内唯一、精确匹配的病历证据原句才建立选区；空字段、已编辑原文、重复引文或异字段证据仅定位当前字段，不猜测文字位置。定位不保存、修改正文或采纳自动整理，说明关闭后的延迟定位还绑定原病例与授权范围。

十字段直接记录与变动提醒继续拥有病历录入体验，质控的依据与核实保留仅属于独立问题，不恢复自动整理的逐条确认、来源或撤销界面。质控后台任务使用独立的医生任务授权校验，与自动记录共享身份、Workspace/Epoch 和 Grant 有效性验证，分别保留窄操作白名单。

只读病例思路、分类限制与具体质控说明的增量取舍见[临床说明决策](2026-10-16-clinical-explanations.md)；可采纳建议、编辑与签署合同保持各自归属。

## Alternatives considered

- 直接把质控加入诊疗建议的 kind：该输入强依赖目录和指南，且不包含尚未整理的医生补充，无法准确表示纯文书质控。
- 复用整理控制版本作为检查版本：控制版本不涵盖完整输入，会接受旧正文或旧来源的结果。
- 为实时质控自动保存编辑：改变现有显式保存语义，可能提交或覆盖医生尚未决定的内容。
- 永久忽略某类问题：相关事实更新后仍可能压制有效提示，不能代替对具体证据的人工核实。
- 让模型检查结果成为签署门禁：超出本期范围，也无法保证医学判断正确。
- 用系统检查状态常驻提醒医生病历有问题：检查能力和具体文书问题含义不同，因此状态按需查看，正文只显示可处理的问题。
- 按旧字符偏移选中问题：未保存编辑会使偏移指向无关内容，因此定位时重新核对当前字段的唯一原句。

## Consequences

语义核对仍会误报和漏报，不能把空提示列表标为全面临床或监管合规通过。不同时间的事实变化、来源中的否定与不确定性必须保留；输入超出单次检查能力时说明不完整，不以静默截断给出通过结论。官方条款的门诊适用边界由[研究记录](../../../../docs/research/2026-10-15-outpatient-record-quality-rules.md)拥有。

公开 HTTP、真实 SQLite 与外部模型网络边界拥有语义、来源、版本、幂等、权限和恢复矩阵。真实 Web、React 18/19 ShadowRoot 与原生 DSH 拥有输入保留、键盘依据、核实与签署集成；测试入口由[测试策略](../../../../docs/testing.md)维护。
