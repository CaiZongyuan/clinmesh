# Agent Note: 待开具项目的原子确认与资料防过期

Status: implemented

## Problem

问诊回答和检查报告可以在 Encounter 版本不变时发布。浏览器最后一次读取建议后再调用独立保存与开具接口，会留下新资料到达而旧自动项目仍被开具的窗口；把整个建议指纹直接传给先保存后开具流程，又会因目标草稿自身改变而失效。业务需求由[诊疗建议规格的 R 条件](../../../../docs/spec/2026-10-13-doctor-guideline-recommendations.md#自动准备与待开具清单)拥有，既有证据与生成边界见[建议来源决策](2026-10-13-doctor-guideline-recommendations.md)。

## Decision

医生页面通过病例、种类限定的 `POST recommendations/:kind/actions/confirm` 显式提交选中项目。请求固定当前 Encounter 和目标草稿版本；每条选择区分 `agent` 与 `manual`，包含自动项目时另固定准备代次和完整资料指纹。自动项目必须引用当前已核验建议，并保留诊断、药品或检查服务身份；病理还保留已核验手术来源。诊断自动行恢复原已核验的参考快照，人工行从当前真实目录解析；客户端可带参考快照供一致性检查，但不能用它替代目录。处方允许携带产品快照以保留编辑展示，正式保存仍从真实 Reference 目录解析产品，不信任客户端规格。医生修改的具体字段仍经过既有目录和正式提交校验。完整处方字段才可提交，缺项不从目录默认值补齐。

`doctor.recommendations.confirm` 在一个 `BEGIN IMMEDIATE` Command 事务中重新读取负责身份、病例、资料、目录与建议状态，核对完整指纹及代次，然后保存显式选择并正式确认或开具。确认服务与原独立接口共用同一组事务内领域内核，内核保留原权限、CAS、目录、禁忌、诊断适应规则和 FHIR R5 资源创建。只由最外层 Command 写幂等回执、审计和 Action Trace，不嵌套 Command 事务，也不另建执行状态机。回执返回种类、最终草稿版本、Encounter 版本及正式记录身份。

一批检查使用同一事务依次执行现有单项领域内核，任何一项失败都回滚全部项目和草稿。页面先把已有草稿完整列入统一清单，医生明确调整、选择或移除后，通过 `resolveExistingDraft` 和草稿预期版本表达本次替换；检查草稿的删除、保存与开具复用原公开删除操作的事务内核，一起提交或回滚。未明确处理时保留原草稿保护，不能仅提交自动行就隐式覆盖人工内容。

全人工选择不读取推荐任务、不检索指南、不要求模型证明；任务不存在、暂停、处理中、失败或建议读取失败都不阻断手动开具。人工条目没有建议身份，仍受当前负责身份、Encounter 与草稿版本、真实目录、诊断主次、处方适应规则、过敏和既有临床校验约束。混合选择只要含一个自动项目，就继续核对完整代次、资料指纹及全部自动身份，不能用人工行绕过自动结果防过期。已有正式诊断、申请和用药结论仍由各自不可覆盖的记录与修订规则拥有，不因后台更新自动改写。

生成输入包含已开具检验、放射和病理申请的公开事实与当前状态，独立加入已发布报告。新建或取消尚无报告的申请也改变指纹，避免重复准备；没有报告不成为伪阴性或缺乏开立该项的依据。新生成的诊断候选必须提供主次角色并参与独立语义核验，历史持久建议允许缺少角色，读取不凭列表位置制造主次。输入策略版本推进使旧生成结果失效。已有指南来源不可用时，读取和旧生成幂等回执的投影返回可选 `hidePreviousResults: true` 并隐藏旧派生结果，客户端据此清除该病例和种类保留的旧自动结果，医生明确修改的临床字段保持原归属；普通资料过期及新一轮 pending 不带该标记。

新确认入口限定医生 Session 和受信 mutation origin，不增加 CLI、Agent Grant 或页面 Tool 权限；Operation Catalog 对该页面组合入口显式登记排除原因。既有正式操作的公开协议、CLI 及运行时 Skill 保持原合同。响应中断时以原路径、原请求和原幂等键重放，返回同一审计回执与正式记录。

## Alternatives considered

- 只在浏览器提交前 GET 建议或只比较 Encounter 版本，不能拦截 GET 后新问诊或报告发布。
- 先保存自动草稿再用原完整指纹开具，会把自身草稿写入误判为外部资料变化；分离两个事务仍保留竞态窗口。
- 在新 Command 内调用原有保存、开具 Command，会产生嵌套事务或分散回执；复制正式状态机则导致校验漂移。共享事务内领域内核保留单一行为 owner。
- 在浏览器循环覆盖一个检查草稿，会覆盖人工输入并产生部分提交。单事务批量只在原草稿为空时临时使用该内核，失败恢复原状态。
- 禁止全人工选择，会使医生已修改但新一轮未再推荐的项目无法按现有规则确认；把旧自动项悄悄改标人工则丢失明确选择边界。

## Consequences

浏览器每个栏目只有一份待办清单。医生从“添加”按钮打开既有目录和填写表单，完成后返回清单；清单调整回传同一手动字段，父表单的新值优先于旧编辑缓存，正式记录另行展示。既有草稿保存、删除与失败恢复继续由原模块拥有；仅在明确修改已确认诊断时加载正式快照，不把正式记录默认重填为新待办。点击统一确认入口直接提交本轮明确选择；若先自动保存草稿，应重新读取和准备，不能继续复用旧指纹。失败保留原草稿，旧自动项需要重新核对。相同幂等键的重放返回原回执，不再次核对生成或重复创建正式资源；其他新意图使用新键。

调整回调明确返回原表单是否接受该项目。由表单接管的调整在该项目从表单删除或被替换时同步清除，并抑制相同依据与方案的自动副本；单个检查表单已占用而未接管的其他项目仍由清单保存。清理结果写回病例偏好，切换病例再返回也不会恢复已删除的旧编辑。

正式成功只消费仍属于该次提交、尚未被后来编辑的本地行，回传正式记录身份供页面定位。受信清理造成的一次字段变化可以继续完成 Query 同步，后续手改或切换病例仍使旧同步失效。已消费人工项同时抑制相同依据下的旧自动副本，避免表单清空后重新出现；新相关依据可以重新提出项目。未选项目和提交期间的新编辑保持原样。

编辑身份绑定授权、病例和栏目，后台保存或提交的临时忙碌状态只禁用相应操作，不关闭正在填写的对话框。带 Consultation 的独立诊断与处方栏目保留挂载以保存尚未自动持久化的输入；旧复诊组合流程继续沿用原挂载规则，避免复制同一份复诊表单。处方手动目录通过原生 Dialog Portal 的隐藏挂载保留包装选择，关闭时停止主动检索；多行诊断备注在两处编辑器都使用多行控件。同病例其他检查分类的正式成功可以更新对应记录选择，清理表单仍要求完整编辑归属，不能跳转当前分类或清除后来填写的内容。

页面级准备器持续覆盖当前接诊病例的五种建议。连续已保存资料变化合并为一次读取，后台整理进度等非来源状态不推进读取版本；旧结果在读取开始时即不可提交，切换患者和返回的迟到响应由单调视图版本隔离。TanStack Query 拥有当前与历史就绪结果，病例级本地偏好只保存医生编辑、选择、移除和暂停。来源失效指令优先于代次比较，同时清理保留的自动结果。确认请求分别计入正在提交的身份，旧请求结束不能解锁新请求；正式成功先刷新真实病例，再重建对应编辑器。

自动项目的移除绑定相关病例原文、指南内容及可执行临床方案，来源编号、排列、建议代次和无关资料变化不撤销移除。相关依据或方案改变时，项目重新显示核对提醒并保持未选中，由医生明确选择或核对保存后再提交；再次移除按当前依据生效。人工条目的移除只绑定其临床内容，不因全局资料指纹改变而反复恢复。

记录核对提示只表达可证实的时间关系：当前医生可见问诊、保存病历、正式报告或临床结论的时间晚于该记录。检查读模型从既有 ServiceRequest.authoredOn 投影可选 authoredAt，不新增持久化副本；缺失时间的旧记录不制造警告。提示连接既有记录选择、聚焦与人工处理入口，不断言原决定错误，也不自动修改、撤回或重复开具。

检查、诊断和处方仍分别提交，单个辅助确认接口不会跨种类正式开具。模型主次和独立核验不保证临床判断绝对正确；已经正式开具的项目遇到新资料，只能显示可证实的核对状态或核验结果，不凭资料变化自动判断原决定错误。

公开 HTTP、真实文件 SQLite 和模型网络替身验证原子确认、批量回滚、幂等重放、问诊与报告在 Encounter 未变时使旧项目失效、显式人工输入、目录和身份隔离；原门诊、影像、病理 HTTP 回归验证共享内核的既有合同。
