# Agent Note: 待开具项目的原子确认与资料防过期

Status: implemented

## Problem

问诊回答和检查报告可以在 Encounter 版本不变时发布。浏览器最后一次读取建议后再调用独立保存与开具接口，会留下新资料到达而旧自动项目仍被开具的窗口；把整个建议指纹直接传给先保存后开具流程，又会因目标草稿自身改变而失效。业务需求由[诊疗建议规格的 R 条件](../../../../docs/spec/2026-10-13-doctor-guideline-recommendations.md#自动准备与待开具清单)拥有，既有证据与生成边界见[建议来源决策](2026-10-13-doctor-guideline-recommendations.md)。

## Decision

医生页面通过病例、种类限定的 `POST recommendations/:kind/actions/confirm` 显式提交选中项目。请求固定当前 Encounter、准备代次、完整资料指纹和目标草稿版本；每条选择区分 `agent` 与 `manual`。自动项目必须引用当前已核验建议，并保留诊断、药品或检查服务身份；病理还保留已核验手术来源。医生修改的具体字段仍经过既有目录和正式提交校验。完整处方字段才可提交，缺项不从目录默认值补齐。

`doctor.recommendations.confirm` 在一个 `BEGIN IMMEDIATE` Command 事务中重新读取负责身份、病例、资料、目录与建议状态，核对完整指纹及代次，然后保存显式选择并正式确认或开具。确认服务与原独立接口共用同一组事务内领域内核，内核保留原权限、CAS、目录、禁忌、诊断适应规则和 FHIR R5 资源创建。只由最外层 Command 写幂等回执、审计和 Action Trace，不嵌套 Command 事务，也不另建执行状态机。回执返回种类、最终草稿版本、Encounter 版本及正式记录身份。

一批检查使用同一事务依次执行现有单项领域内核，任何一项失败都回滚全部项目和草稿；原有人工检查草稿非空时直接拒绝，不把它当作批量临时槽位。明确选择的全人工诊断或处方可以在最新 `ready` 或 `missing-evidence` 代次下提交，沿用完整正式校验；人工条目没有建议身份，不能借旧候选冒充当前自动核验。已有正式诊断、申请和用药结论仍由各自不可覆盖的记录与修订规则拥有，不因后台更新自动改写。

生成输入包含已开具检验、放射和病理申请的公开事实与当前状态，独立加入已发布报告。新建或取消尚无报告的申请也改变指纹，避免重复准备；没有报告不成为伪阴性或缺乏开立该项的依据。新生成的诊断候选必须提供主次角色并参与独立语义核验，历史持久建议允许缺少角色，读取不凭列表位置制造主次。输入策略版本推进使旧生成结果失效。已有指南来源不可用时，读取和旧生成幂等回执的投影返回可选 `hidePreviousResults: true` 并隐藏旧派生结果，客户端据此清除该病例和种类保留的旧自动结果，医生明确修改的临床字段保持原归属；普通资料过期及新一轮 pending 不带该标记。

新确认入口限定医生 Session 和受信 mutation origin，不增加 CLI、Agent Grant 或页面 Tool 权限；Operation Catalog 对该页面组合入口显式登记排除原因。既有正式操作的公开协议、CLI 及运行时 Skill 保持原合同。响应中断时以原路径、原请求和原幂等键重放，返回同一审计回执与正式记录。

## Alternatives considered

- 只在浏览器提交前 GET 建议或只比较 Encounter 版本，不能拦截 GET 后新问诊或报告发布。
- 先保存自动草稿再用原完整指纹开具，会把自身草稿写入误判为外部资料变化；分离两个事务仍保留竞态窗口。
- 在新 Command 内调用原有保存、开具 Command，会产生嵌套事务或分散回执；复制正式状态机则导致校验漂移。共享事务内领域内核保留单一行为 owner。
- 在浏览器循环覆盖一个检查草稿，会覆盖人工输入并产生部分提交。单事务批量只在原草稿为空时临时使用该内核，失败恢复原状态。
- 禁止全人工选择，会使医生已修改但新一轮未再推荐的项目无法按现有规则确认；把旧自动项悄悄改标人工则丢失明确选择边界。

## Consequences

浏览器自动清单使用本地编辑，点击确认时直接提交本轮明确选择；若另走既有自动保存接口，应重新读取和准备，不能继续复用旧指纹。失败保留原草稿，旧自动项需要重新核对。相同幂等键的重放返回原回执，不再次核对生成或重复创建正式资源；其他新意图使用新键。

检查、诊断和处方仍分别提交，单个辅助确认接口不会跨种类正式开具。模型主次和独立核验不保证临床判断绝对正确；已经正式开具的项目遇到新资料，只能显示可证实的核对状态或核验结果，不凭资料变化自动判断原决定错误。

公开 HTTP、真实文件 SQLite 和模型网络替身验证原子确认、批量回滚、幂等重放、问诊与报告在 Encounter 未变时使旧项目失效、显式人工输入、目录和身份隔离；原门诊、影像、病理 HTTP 回归验证共享内核的既有合同。
