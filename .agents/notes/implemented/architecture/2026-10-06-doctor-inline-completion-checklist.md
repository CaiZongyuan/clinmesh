# Agent Note: 门诊医生完诊清单置于患者信息下方

Status: implemented

## Problem

病例上下文栏重复中央页签中的患者信息和诊疗概况，挤占编辑空间；DSH 原生患者标签的自动打开也会打断诊疗。其独有价值是汇总服务端完诊条件。

## Decision

患者横幅内，基本信息、过敏与分诊标签下方，生命体征数据上方，横向展示 Encounter Completion 清单及完成数量。七项使用等宽状态块，文案明确描述完成内容，以绿色和中性灰背景分别表示满足和未满足，不额外展示“已完成／待完成”；宽度不足时自动换行，服务端原因保留在悬停提示和无障碍名称中。条件独立汇总，不表达线性步骤。Web 与 DSH Surface 使用同一组件，病例主区始终单列。既有完诊确认和阻断项导航继续由原组件执行，不新增业务状态或 Command。

删除内嵌病例上下文栏、窄屏抽屉、患者信息显示按钮，以及 DSH 患者标签注册、快照通道和自动打开逻辑。DSH 的会话、文件及其他原生右栏仍归宿主管理。本决策完整取代[病例上下文原生标签页](2026-09-17-dsh-host-case-context-tab.md)的患者面板机制。

## Alternatives considered

- 只禁止自动弹出并保留右栏：仍重复中央内容，并要求医生打开另一个面板才能查看完诊条件。
- 只在完诊确认框显示清单：减少常驻内容，但诊疗过程中无法直接观察剩余条件。

## Consequences

清单随现有 Query 更新，不保存第二份患者快照；未接诊、旧版病例等没有完诊预览时不展示。患者切换和页签切换不创建或聚焦宿主右栏标签。标签在窄屏换行后仍需给业务区域保留可滚动空间，浏览器合同覆盖七项无需横向滚动即可完整展示、患者横幅稳定和业务末尾操作可达性，兼容 React 18/19 与 ShadowRoot。
