# Agent Note: 低延迟增量记录与异步语义核对

Status: implemented

## Problem

普通问诊需要持续出现已保存的病历增量。每轮发送全部旧来源、串行等待整理与独立语义核对，以及共用 outbox 消费循环，会放大持续输入的排队时间。来源保护和持久恢复仍然必要，但不要求每次重复整理全部历史。

需求和性能目标由[低延迟记录规格](../../../../docs/spec/2026-10-15-low-latency-document-recording.md)拥有。本决策取代[总结溯源](2026-10-12-consultation-agent-summary-sources.md)和[直接记录](2026-10-14-consultation-direct-recording.md)中的同步语义闸门与整轮自动重试；保留其原始引用、人工片段归属、版本、授权及签署保护。质量提示补充[移除来源界面](2026-10-14-consultation-recording-without-source-ui.md)，不恢复逐条应用或确认流程。

## Decision

来源先保存，按病例固定有界小批及版本快照。输入包含新增来源、必要相邻上下文、全部有效事实和可恢复的原始引用；超限明确失败，不丢弃旧证据。批次快照、每来源处理结果和候选失败独立持久化。通过确定性校验的独立候选经共享 Command 写草稿，并在同一事务完成对应来源进度；重复消费与重启沿用原批次。互相竞争同一替换目标的候选整组拒绝，其他候选可继续，失败来源不阻塞后续来源。

模型请求使用仅在固定批次内有效的短引用，服务端在校验前恢复持久身份。未变化的目标事实允许以位置索引保留，由服务端复制其确切内容和原始引用；模型只输出新增或更正事实。索引越界与竞争替换整组失败，不能借短引用引入新证据。完整快照保留原始文字，核对与重启仍使用完整证据，避免反复生成累计事实造成延迟和引用漂移。并发人工修改按字段隔离，受影响候选保留失败结果，其他字段可继续。

独立语义核对在草稿保存后执行，绑定片段身份、内容哈希和原批次来源版本。它只更新核对状态，不改正文。内容变化使旧核对失效；授权失效、暂停、控制代次变化和签署准备限制迟到结论。页面与签署预览显示尚未核对、疑点或核对请求失败，疑点关联原句，沿用现有正式签署门禁。只有请求失败可显式重试；否定结论不会通过反复询问改成肯定。

实时整理使用独立模型配置和共享的首次请求/一次格式修复预算。实时、核对、历史补录、建议和其他 outbox 工作分别设置有界槽位，每个空闲槽位可在下一次调度启动，慢后台任务不独占消费循环。常规失败停止并保留来源，服务器关闭造成的中断才沿用 outbox 恢复。

Command 提交后的通知只加速 Query 刷新。DSH 代理会缓冲响应，因此使用最长 10 秒的有界等待 JSON 请求，比较可重读的 revision；客户端取消、服务器关闭和断线均清理订阅。断线重连及正常 Query 轮询恢复当前事实，通知无须可靠送达。React 18/19 共享组件保持普通编辑和滚动，不逐条播报。

## Alternatives considered

- 保持同步语义核对，只压缩上下文：保留原写入保障，但无法消除两次模型串行等待。
- 仅更换模型：能降低单次耗时，但无法解决全量重处理和慢任务占用消费循环。
- 每份来源并发覆盖全文：会造成旧结果覆盖新结果、重复事实和人工编辑丢失。
- 流式显示临时文字：不能证明完整候选已校验并持久保存。
- SSE 通知：当前 DSH 代理会缓冲正文，无法提供相同的刷新时效；有界等待可复用正常 JSON 边界及代理。

## Consequences

草稿先于语义核对可见，引用正确仍不保证语义忠实，医生必须能够识别未核对及疑点状态。并发上限保护进程容量，不能保证上游模型在负载下满足延迟目标；性能达标必须使用固定真实模型、完整来源集合和真实页面证明。

公开 HTTP 与 file-backed SQLite 回归覆盖部分失败、后续来源继续、共享取消预算、显式恢复、迁移和重启；真实 Web 问诊旅程及 React 18/19 Surface 签署合同覆盖页面与人工编辑保护。可复现真实模型负载入口为 `apps/web/e2e/recording-benchmark.ts`，模型替身的结果仅证明合同，不证明真实延迟。
