# Agent Note: Agent 环绕柔光与静态人工审阅

Status: implemented

## Problem

逐个控件的流动渐变边框难以表达 Agent 正在整个工作区操作，人工审批沿用同样动效又会混淆操作主体。视觉层需要区分真实 Agent 执行与人类决定，同时保持临床内容可读、输入可用以及现有调用和上下文隔离。事件、编辑与授权边界继续沿用 [Agent 操作反馈与编辑控制边界](2026-09-20-agent-action-feedback.md)；本决策取代其中的视觉呈现与审阅强调方式。

## Decision

使用固定版本 `ai-motion@0.4.8` 提供工作区边缘 WebGL2 柔光，保留透明中心，并以淡边框和菱形标记指示本次可见目标。Web adapter 拥有 Canvas 生命周期，工具事件仍由原包装器发出；视觉层不复制业务状态机。一个可见工作区只保留一个 Canvas，目录弹窗打开时由弹窗内部承载。边界限制在 Surface 与临床工作区内，不抬高宿主层级、不拦截输入、不模拟点击或逐字输入。

只有非 proposal 的 `executing` 事件维持柔光流动；`.propose` 准备、等待审阅、人工批准提交、拒绝和结果均为静态状态。执行结束即暂停持续绘制，成功完成后保留静态柔光与落点，再淡出并释放 GPU 资源。执行和完成被 React 合并的快速动作也绘制一帧结果，尺寸变化时重新绘制静态帧，不延长业务执行或伪造进行中状态。页面隐藏时暂停，卸载、主题或减少动效偏好变化时清理实例。减少动效或 WebGL2 不可用时保留静态边缘。

状态融入既有页头，详情按需展开。摘要分别保留正在执行、待确认、人工提交中和需查看的数量，避免最后一个完成结果掩盖其他事项。具体时限与恢复语义由 [能力参考](../../../../docs/agent-capabilities.md#反馈时序) 拥有。已接受的独立 HTML 保留在本地任务隔离预览目录，作为设计参考，不进入正式应用路由或构建。

## Alternatives considered

- 延续每个字段的移动渐变：复杂表单会同时出现多条流光，缺少工作区整体活动信号；保留静态落点并把持续动态集中到一个边缘。
- 只用 CSS 旋转渐变仿制参考：无法保持参考的透明边缘混色与柔光质感，采用原库并提供无 GPU 的降级。
- 人工批准提交也维持柔光：会把人类决定呈现为 Agent 操作，静态状态足以表达待确认与提交结果。
- 执行结束立即隐藏工作区柔光：快速动作可能根本没有可见执行帧，保留真实完成的静态帧才能让用户看清反馈；停留独立于业务执行和持续绘制。
- 复制 page-agent 的全屏输入遮罩或模拟点击延迟：会阻碍人工协作并改变业务时序，参考仅提供视觉依据。
- 持续展开全部操作历史：抢占临床内容空间，采用摘要与按需详情；反馈不是持久审计历史。

## Consequences

新增的依赖只由 Web adapter 直接导入，DSH 仍复用同一应用。React 18/19 浏览器合同使用合成内容证明真实绘制、停止与释放、ShadowRoot 坐标、减少动效、人工等待/批准/拒绝的静态性，以及当前输入保持可编辑；调用级上下文和并发语义继续由组件与真实页面 Tool 测试拥有。WebGL2 不可用会降低视觉丰富度，但不影响状态、表单或业务动作。
