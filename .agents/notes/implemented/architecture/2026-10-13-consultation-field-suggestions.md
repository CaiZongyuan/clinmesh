# Agent Note: 字段内问诊建议与显式应用

Status: implemented

## Problem

问诊结果集中在病历表单外，医生需要来回对照字段。无冲突内容自动写入又使建议与已确认正文混在一起；只移动面板不能满足[字段内建议规格](../../../../docs/spec/2026-10-13-consultation-field-suggestions.md)要求的全部先确认再写入。

## Decision

后台生成与独立忠实性核对只持久化 pending 建议，不创建或修改病历草稿。模型上下文包括有效待应用建议与已应用片段；新一轮更新替代旧 pending，保留目标链，避免同一内容作为多个独立目标反复生成。模型既可指向上一建议，也可再次指向其人工或已应用目标，因此同字段、同最终有效范围的旧 pending 一并替代；无目标新增保持彼此独立。被替代建议不可应用；解析链时以最终有效已应用片段或人工句子为范围，pending 本身不拥有正文。人工目标锚点在被替代后仍随无关编辑移动，人工改写或失去句界时失效。

医生通过原共享 review Command 显式 accept 或 ignore。无目标 addition 应用时追加到当前字段；有目标建议只替换仍有效的范围。应用使用当前 Encounter、草稿版本、责任、签署状态与幂等回执，完整草稿校验通过后原子写入，首次应用可创建草稿。应用本身完成核对，automatic 表示来源和可逆范围归属，后续人工改写仍转为 manual。操作目录版本推进至 4，同步运行时 Skill 与命令漂移测试；wire schema 与数据库结构复用已有合同。

应用将目标绑定到最终已应用片段或人工逆操作标识，保存被替换全文。新增撤销删除自己的范围，片段替换撤销恢复前一版本与来源，人工句子替换撤销恢复原文。无关新增保留，人工改写或恢复超限进入 undo-pending，不能强制覆盖。旧已应用和未核对内容继续读取、核对与撤销，不通过升级重写正文。拒绝、片段恢复与签署协议继续由既有模块拥有。

主诉、现病史、既往史的字段容器分别呈现自己的建议、来源与操作；页头仅提供紧凑整理状态、暂停、恢复、补录与重试。pending 与旧未核对条目展开，已应用和其他历史默认折叠；无建议字段不创建空面板。来源沿用 Surface Portal，完整原话、跨轮引用和医生问题可按需查看，签署准备期间仍可只读。目标字段未保存时就地提示先保存，其他字段输入由原三方合并保护，失败按条目反馈。

本决策部分取代[增量记录](2026-10-08-consultation-history-increments.md)、[片段归属](2026-10-08-consultation-history-ownership.md)、[病史总结](2026-10-12-consultation-agent-summary-sources.md)及[审阅与撤销](2026-10-10-consultation-history-review-undo.md)中的无冲突自动应用、显式接受后归人工与集中面板；这些记录的持久任务、来源忠实性、片段保护、拒绝证据及逆操作理由继续适用。

## Alternatives considered

- 只搬迁面板，保留无冲突自动写入：减少视觉占用，但生成仍改变正文，医生无法逐项选择全部新增、补充与更正。
- 在浏览器中暂存建议或把建议混入输入框值：刷新或切换病例丢失选择事实，保存可能把未确认内容写入；建议与选择由服务端持久化。
- 每轮独立追加 pending：同一语义组积累互相矛盾的可操作版本。显式替代保留历史与最终目标，只让最新建议可应用。
- 应用时重写整个字段：会覆盖无关人工内容。沿用片段锚点与局部逆操作，无法可靠定位时要求重新核对。
- 显式应用后全部归为 manual：可以表达医生已经确认，但会使没有人工改写的内容也无法安全撤销。核对状态与来源归属分别保存。

## Consequences

每条新内容需要医生选择，后台完成整理不再代表草稿已经更新。待应用的链与当前正文锚点分别持久化，允许重启、版本冲突后重读和局部撤销；长度超限应用原子失败，保留建议与正文。签署摘要继续包含尚未应用建议和未整理回答，人工核对不等于自动应用。

公开 HTTP 与 file-backed SQLite 回归验证无草稿生成、待应用多轮替代、已应用更新等待确认、忽略重放、新证据、陈旧版本、人工目标移动与失效、首次应用和逆操作，并复用医生显式应用后的来源、恢复、隔离及签署矩阵。真实 Web 入口验证未保存保护、来源与刷新、应用和局部撤销；React 18/19 的 ShadowRoot 合同覆盖字段归属、长内容、窄屏、中英文、字号、键盘、焦点返回、就地失败和只读来源。原生 DSH 合成旅程验证真实宿主入口及 Tool → 人工批准 → Command，常规 CI 不调用付费模型。
