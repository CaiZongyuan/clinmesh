# Agent Note: 乳腺病例的病理切片匹配与定向生成

Status: implemented

## Problem

乳腺切片病理会诊（[issue #135](https://github.com/CaiZongyuan/clinmesh/issues/135)）要为 Synthea 乳腺随访病例配一张真实切片。Synthea 已经为病例写下了受体状态、淋巴结与 T 分期，这些是不能被素材改写的固定事实；素材的临床字段来自另一个公开数据集，二者必须逐项相符才可以配在一起。医生开单时还要从病例的既往手术里选择送检对应的那一次，可选项不能透露本次病例真值，也不能随素材多少而变化。

满足全部条件的病例在随机生成中很少：固定版本 Synthea 的乳腺癌模块里，受体三项相互独立（ER 阳性 0.8、PR 阳性 0.65、HER2 阳性 0.2），淋巴结与 T 类别又各有分布，首批切片对应的组合占乳腺癌患者的 0.25%–7.5%。[按影像适配条目定向生成患者](2026-10-02-targeted-imaging-generation.md) 的保留条件只能表达疾病与操作编码，筛不了受体。

本决策由 [issue #141](https://github.com/CaiZongyuan/clinmesh/issues/141) 交付。当前行为的详细归属是 [系统架构 10.7 节](../../../../docs/architecture.md) 与 [病理切片素材清单](../../../../pathology-assets/README.md)；本记录只保留取舍。

## Decision

**适配条目由素材的临床字段派生。** 病理清单的 `matching.json` 只写两类内容：哪些来源病例适用会诊（性别、诊断编码、可送检的手术编码），以及五项固定事实各自对应的来源 Observation 编码和编码值。它不列举条目，也不把素材挂到条目上。每份素材的五项事实由清单条目中的临床字段按固定规则派生（受体沿用报告自动检查的派生规则，淋巴结取病理 N 分期的阴性或阳性，肿瘤取 T1–T4 类别），事实组合相同的素材属于同一个条目，条目标识和名称由组合决定。素材的事实因此只有清单条目一个来源，报告检查、病例匹配、覆盖清单和定向生成读到的是同一份。

**逐项比较，区分相符、矛盾与无法确认。** 病例的五项事实取既往来源病史中对应 Observation 的最新结果。对每份已发布素材逐项比较：全部一致可用；任一项双方都有且不同为矛盾；一方缺少某项而其余不矛盾为无法确认。有可用素材时就绪；否则只要存在无法确认的素材就记为未覆盖（`FACT_UNKNOWN`），全部素材都矛盾时记为冲突。缺少字段的素材不形成条目，在覆盖清单中单独列出。组织学类型来自素材，作为补充事实与来源固定事实分开记录。

**匹配只读取既往来源病史。** 诊断、手术和五项 Observation 都来自 Index Encounter 之前、医生本已可见的来源病史；本次病例真值只用来取就诊开始时间，判断手术是否早于本次就诊。送检手术清单使用同一个函数、只传入可见病史，因此不依赖隐藏病情、匹配结论或素材占用。

**绑定以来源手术为键。** 一次会诊对应医生所选的一次来源手术，准备结果为每个可送检手术各记一份素材选择，绑定键是病例、来源身份、会诊项目和来源手术引用。多份素材同样可用时按病例来源身份与来源手术稳定取一份。冻结规则与放射相同：病例开始前跟随最新准备，开始后已有绑定不替换，只为尚未绑定的手术首次追加。

**病理准备有自己的修订表和绑定表。** 两个素材包各有清单身份和规则版本，准备结果的形态也不同（放射按检查，病理按来源手术）。放在各自的表里，任一素材包缺失或清单无效只影响自己的准备与覆盖清单。

**保留条件增加 Observation 编码值。** 定向目标增加病理适配条目。Server 由条目推导保留条件：做过任一可送检手术，且五项 Observation 的最新结果取条目对应的编码值；Provider 把它们写进同一个 keep module，由 Synthea 在一次运行内部筛选。是否满足条目仍由病例匹配函数复核，例如手术恰在本次就诊中的患者不合格，沿用换 seed 重试。定向任务完成后只运行目标所属素材包的病例准备，失败时的警告按素材包区分。

**定向生成导出足够长的病史。** Synthea 按患者一生的记录判断保留条件，导出时只保留历史起始日期之后的记录。乳腺癌最早 39 岁确诊，患者最大 80 岁，确诊与手术可能在 40 年前；起始日期晚于它们时，Synthea 保留下来的患者导出后缺少诊断、手术和受体结果，被匹配函数拒绝。真实 Provider 验收中，三阴性条目以 2020 年为起点时 Synthea 六次保留到患者，全部因此被拒，十次尝试后失败；同一患者把起点改到 1990 年即被正确导出并配到切片。服务规则因此规定定向生成至少导出的病史年数（45 年）：目标选项带出该要求，生成表单选择条目时把起始日期前移，起点太晚时表单提示并禁止提交，Server 在调用 Provider 前同样拒绝。导出的病史随之变长（约 0.4 MB 到 2.7 MB），生成耗时基本不变；患者档案模型只读取前 100 条历史，不受影响。

## Alternatives considered

**在 `matching.json` 中手写条目并列出素材。** 与放射的写法一致，但条目上的受体组合会成为素材临床字段之外的第二份事实，签署复核覆盖的是素材字段，两者可能不一致而不被发现。

**找不到相符素材时一律记为未覆盖。** 管理员看到的补救方式相同（增加素材），但规格要求把“素材与病例矛盾”和“缺少信息无法确认”分开：前者说明素材库与这类病例不相容，后者说明来源或素材的字段不全。

**把淋巴结计数或肿瘤大小纳入匹配。** Synthea 的淋巴结计数是区间内的浮点数，肿瘤大小只有分段；TCGA 临床数据没有肿瘤最大径。类别级的 N0/N+ 与 T1–T4 是两边都有且含义一致的最细粒度。

**复用放射的准备表并加素材包列。** 少一个迁移，但放射的绑定键和检查枚举要放宽，已发布的放射读取路径都要带上素材包条件；两类准备没有共享的查询。

**只靠 Server 换 seed 重试命中受体组合。** 不需要改 Provider，但最常见的组合也只占乳腺癌患者的百分之几，乳腺癌本身又只出现在约一成女性中，十次重试几乎不可能命中。

**让保留条件支持数值比较或任意逻辑。** 可以表达淋巴结计数等条件，但 Provider 协议会接近任意模块 JSON；Synthea 对类型不符的比较直接抛出异常。只接受“某 LOINC 的最新结果是所列 SNOMED 编码值之一”，有界且足够。

## Consequences

增加素材即增加条目，不需要改规则文件；改动素材的临床字段会同时改变条目归属并使复核失效。规则文件只在 Synthea 的编码或服务适用范围变化时修改。

最常见的病例组合（ER 阳性、PR 阳性、HER2 阴性、淋巴结阴性、T1）首批没有切片，这类病例准备为冲突。稀有组合的定向生成仍可能耗尽重试：Synthea 的内部重试不换年龄，抽到的年龄尚未发病时整次运行落空。年龄范围取 45–80 岁以提高命中率。

Provider 镜像需要重新构建和发布后才能按受体定向；旧镜像收到 Observation 条件会以请求无效拒绝，Server 报告为不支持定向生成，不影响放射条目。

送检手术清单的医生入口和开立时的校验随会诊申请（[issue #143](https://github.com/CaiZongyuan/clinmesh/issues/143)）提供，使用本决策中的同一个函数。
