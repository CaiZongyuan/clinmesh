# Agent Note: 患者档案驱动自由对话问诊

Status: implemented

## Problem

固定问题代码无法表达自由病史采集，也无法呈现患者性格和表达差异。自由生成必须同时保持病例真值隔离、历史原文稳定和 Command 恢复能力。任务合同见 [#106](https://github.com/CaiZongyuan/clinmesh/issues/106)。

## Decision

Patient Persona 是唯一的版本化患者扮演档案，复用已有生成任务、修订链与 Brief 模型配置槽。病例开始绑定所选修订；管理员编辑产生新修订，诊断泄漏警告允许明确强制保存。存量 Brief 内容保留用于历史回看。

自由问诊由服务端独立 consultation 模型完成。模型输入包含档案、对话与患者可知事实；Case Truth 只供独立出口检查使用。出口命中隐藏诊断术语时重生成一次，再命中使用安全应答。整轮共享 30 秒期限，失败保留医生发言。

共享 Command 分别拥有医生发言、患者回答与公开请求完成回执。医生发言先提交，模型调用在事务外执行，回答追加使用绑定医生轮次的稳定幂等键。未回答时禁止新发言；报告卡片独立追加，不参与文本回答的配对与版本前置条件。完整回执使用公开请求的原幂等键；未完成生成的已接受请求可查询为 executing 并通过病例详情恢复。

对话原文冻结，复诊延续原线程，完诊只读。报告卡片引用 DiagnosticReport 历史版本。存量选择题记录迁移为带 legacy 来源的轮次，来源枚举预留 ASR 与外部同步。Canonical hash 排除对话原文及回执中的同一文本，备份仍保留全文。详细接口由[系统架构](../../../../docs/architecture.md#81-门诊闭环)拥有。

## Alternatives considered

- 保留问题代码并让模型润色：不能支持自由提问，也继续维护两个问诊模型。
- 把 Case Truth 交给患者模型后仅依靠提示词限制：模型直接持有完整答案，不能建立上下文隔离。
- 在一个数据库事务内等待模型：外部等待占用 SQLite 写锁，故障时无法保留已发送的医生发言。
- 把报告卡片视为患者回答：异步报告会错误结束待回答轮次，并使重试丢失目标。

## Consequences

模型不可用时该轮问诊暂不可用，其他临床流程仍可继续；不存在离线规则扮演引擎。已生成回复的原文保持可回看，同病例 reset 后措辞可以变化。最近 40 个轮次限制模型输入长度，长期沟通记忆不等同于无限上下文。

HTTP 测试使用临时 SQLite 与 fake provider 覆盖冻结、重放、报告并发、超时和泄漏出口；Web 测试覆盖自由输入与档案编辑。真实外部模型的口语质量不由这些确定性测试证明。
