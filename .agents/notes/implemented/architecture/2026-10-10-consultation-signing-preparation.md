# Agent Note: 问诊病史的签署准备与取消恢复

Status: implemented

## Problem

[自动记录规格](../../../../docs/spec/2026-10-08-consultation-auto-record.md)要求医生签署前看到遗漏与冲突，并阻止迟到提取改变预览或已签文书。只在后台提交时检查预览有效期，会把未应用的回答误记为完成；关闭浏览器弹窗也不能释放持久准备状态。

## Decision

结构化病历的 preview-sign、sign 与 cancel-sign 由共享 Workflow Command 执行。准备仍校验完整草稿、当前 Encounter、责任医生与草稿版本；同一事务结束此前未消费预览，保存正文与问诊核对摘要，并推进所有未完成提取任务的代次、清除调度资格。准备期间不调度新提取，也不允许控制整理或审阅增量；其他会话通过既有 API 人工修改草稿仍推进版本，使旧预览失效。模型在途结果失去代次资格，既不修改草稿、来源和待签预览，也不把回答记为已整理。正式签署再次失效化未完成任务，已签文书沿用不可变 Composition、Bundle 与 Provenance。

核对摘要固定 Consultation 版本、未整理与失败回答数量、暂停状态、待核对冲突和未核对自动内容数量；它与正文共同绑定预览。存在遗漏或未核对内容时，提交必须携带医生人工确认的 `consultationReviewed: true`，并在审计和幂等输入中保存该确认。确认不修改逐条审阅事实，也不替代完整性、岗位责任、版本、预览有效期与正文一致性要求。准备后新问诊或核对事实变化使摘要失配，必须返回核对并重新预览。旧预览没有摘要时无法用于签署当前问诊；旧幂等回执缺少摘要仍可通过响应默认值重放，但不创造新的签署资格。

cancel-sign 绑定当前责任岗位、Encounter 与指定未消费 previewId，允许同一责任岗位的新受信 Actor 取消已过期预览。它消费准备、再次推进任务代次，并以本次受信医生上下文恢复未完成队列；显式暂停和失败保留，分别通过原恢复或重试控制处理。取消回执可幂等重放。病例 Query 暴露未消费准备的标识、期限和当前有效性；重连、刷新、签署失败或预览过期后，医生均可通过可见入口取消并恢复，后台任务不会永久冻结。前端取消旧读取后按回执移除同标识准备，再刷新 Query；读取失败仍能使用已提交事实，较新准备继续保留。

人工签署与 Agent 签署提案显示同一核对摘要，并要求本次预览的显式勾选；聊天回复无法代替确认。人工关闭弹窗调用取消 Command，同一岗位、预览与 Encounter 版本的取消重试沿用幂等键，响应丢失后仍可重放已提交回执。取消失败时重新读取病例：成功读取确认旧准备已结束或被替换后关闭对应本地预览；较新准备保留恢复入口，读取失败或旧准备仍有效时保留预览与重试入口。Agent 在预览返回后检查工作台是否仍挂载、终止信号和病例／Actor 范围，提前退出也尝试取消；审阅取消、终止或提交失败时同样尝试取消持久准备，未成功释放的准备仍由 Query 提供恢复入口。审阅正文按当前宿主语言渲染提示和文书字段标签，语言切换保留固定正文、核对摘要及本次人工勾选。界面与提交共用既有受信上下文和权限路径，不新增任意写工具。

## Alternatives considered

- 只在浏览器停止自动记录：其他会话、服务重启与在途模型不受约束，因此由持久预览和任务代次共同控制。
- 只判断有效预览而不推进代次：取消或过期后旧结果重新取得写入资格，因此每次准备、取消与正式签署都使旧代次失效。
- 把被冻结的结果保存为待核对并记为处理完成：医生尚未看到的新建议会改变待签核对摘要，也丢失取消后正常补录的资格，因此保留未完成回答。
- 自动确认全部增量或清空冲突：会制造未发生的逐条核对事实，因此签署确认只属于本次提交。
- 取消时总是恢复并重试全部回答：会违背显式暂停、掩盖失败和重复处理完成回答，因此保留原控制与进度。
- 弹窗关闭只丢弃本地 token：刷新后无法解释冻结原因，因此取消是公开、版本保护和受审计的 Command。
- 取消失败后始终保留旧弹窗：服务端可能已经提交取消或由其他会话结束准备，继续使用旧预览会遮挡恢复入口；只有成功的病例读取才能据此结束本地准备，读取失败则通过同一取消回执重试。

## Consequences

Operation Catalog、医生运行时 Skill 与命令示例测试同步维护 preview、commit 和 cancel 合同。公开 HTTP、病例 Query 和 file-backed SQLite 回归验证准备竞态、人工确认门禁、取消后的新代次恢复、暂停保留、失败重试、问诊变化、过期与重启，以及迟到结果前后已签正文和 FHIR 资源不变。生产 Web 旅程验证取消已提交但响应丢失后的恢复、刷新恢复和人工签署；React 18/19 的 ShadowRoot 浏览器合同验证核对摘要、窄宽度、键盘勾选、取消失败重试，以及 Agent 提案的确认门禁与宿主语言同步。完整原生 DSH 问诊与真实模型质量验收仍由规格的整体验收切片负责。
