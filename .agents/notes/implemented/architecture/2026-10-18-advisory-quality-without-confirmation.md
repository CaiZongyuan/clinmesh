# Agent Note: 病历质控只提示，医生直接编辑

Status: implemented

## Problem

自动记录的既定体验是直接保存病历草稿，医生发现错误时自行修改。独立质控提供“已核实，保留”、选填原因和确认保留，虽然不阻止写入或签署，仍增加了逐条人工处理动作，使提示看起来成为录入流程的一部分。

本决策取代[原质控决策](2026-10-15-doctor-document-quality-control.md)的界面人工核实入口；质控输入、来源、授权及既有公开协议继续由原决策拥有。当前验收合同由[质控规格](../../../../docs/spec/2026-10-15-doctor-document-quality-control.md)拥有。

## Decision

本文保留可选依据入口的取舍由[安静质控提示决策](2026-10-18-quiet-document-quality-hints.md)取代；该决策同时拥有待补充提示的隐藏范围。本文继续拥有直接编辑、无逐条确认及历史处理兼容的理由。

Web 与 DSH 共享病历界面只显示辅助提示及可选依据，不提供逐条核实保留、确认或原因填写。医生直接编辑正文或补充信息，质控按实际正文和来源重新检查；自动记录继续直接保存草稿，语义核对异步反馈，页面不调用保留接口生成新处理记录。

已有核实回执不删除、不改写，以只读历史展示。保留既有服务端公开接口与持久数据合同，避免局部界面调整破坏已有调用方和审计。旧决定仍只适用于其相关正文及证据，不能扩展为永久忽略。

“查看依据”只展开说明、原文与时间，不是确认动作，不保存病历、不触发采纳或改变提示状态。签署摘要继续提供信息，不增加勾选或门禁；正式文书签署保持原有流程。

## Alternatives considered

- 保留按钮并解释其可选：仍让医生承担额外的逐条处理动作，与直接编辑的要求不符。
- 删除全部依据：提示失去可追溯的解释，医生修改正文时无法核对原句和时间。
- 同时删除服务端接口和旧处理数据：对公开协议与审计的破坏超出界面调整所需范围。

## Consequences

医生认为提示不适用时可继续录入或签署，无需额外处理；没有正文或来源变化时，同一提示可能继续显示。系统不能将未点击或忽略提示解释为医生确认。

组件回归验证直接编辑后提示更新及旧回执只读展示；真实 Web 旅程验证正文保存、没有保留写请求及未处理问题不阻断签署。界面提示与依据入口的当前回归由[安静质控提示决策](2026-10-18-quiet-document-quality-hints.md)拥有。
