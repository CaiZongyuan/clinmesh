# Agent Note: 可追溯诊疗建议与医生草稿边界

Status: implemented

## Problem

医生需要同时核对建议的指南依据、当前病例资料和院内执行条目。模型记忆、可点击链接、目录默认值以及隐藏仿真答案都不能代替临床依据；病例或目录变化后迟到的结果也不能进入当前草稿。详细需求由[基于权威指南与当前病例的诊疗建议](../../../../docs/spec/2026-10-13-doctor-guideline-recommendations.md)拥有。

## Decision

复用现有官方发布源的已核验短条款和 DSH 辅助模型；跨专科全文与可用性增量由[免费全文检索决策](2026-10-16-free-guideline-corpus.md)拥有。来源保留文献性质、发布者、版本、原文定位与文件哈希，具体取得方式和覆盖缺口由[研究记录](../../../../docs/research/2026-10-13-clinical-recommendation-guidelines.md)拥有。国家标准、卫生行业标准、诊疗方案、指南和药品说明书分别标识；未取得的中华医学知识库全文服务不作为已有输入，也不阻塞已取得来源的使用。

共享建议服务从负责医生的公开读模型收集问诊、病历、报告与历史，按实际院内目录归一化候选。病理来源限定为现有公开元数据允许的手术；药品规格从 owning 目录的冻结产品记录读取，执行允许值和默认值与规格、临床依据分开。模型只接收本次提供的证据，结果必须引用当前清单中的身份；独立核验前按真实目录固定候选名称、编码和所选检查来源，核验请求同时提供对应项目、授权手术或药品规格，核验后不替换临床身份。后续独立请求核对最终条目的临床支持和限定语。结构化校验只验证完整性和形状，合法 `false` 保持否定结果，不能修复成通过；处方字段逐项缺证时保留 `null`。

`doctor_recommendation_state` 与持久 outbox 保存建议身份、输入、状态与代次，复用 Command 幂等回执和模型绑定。动态目录等待后同步收集当前公开资料，排队与完成事务再次核对指纹；新代次、资料变化、目录消失、授权撤销和 Epoch reset 阻止旧结果覆盖当前建议。后台重启和自动重试保持本次模型，新代次采用当前选择。

浏览器按病例资料与目录变化推进独立读取版本，不把病历全文放入 Query key，也不重新挂载草稿编辑器。采纳使用新 GET 核对当前可见条目与最新权限，单调 view revision 阻止身份、资料和启用状态往返后恢复旧回调；迟到的 POST 保留较新代次和同轮已完成结果。异步检验目录查找绑定实际已核验的建议身份，在目录返回后、写入草稿前再次 GET 核对指纹、代次和条目，两个等待阶段都保留手改、身份及卸载保护。人工手改继续拥有草稿内容，正式临床事实由既有医生确认 Command 创建。

## Alternatives considered

- 直接把模型输出填入正式诊断、申请或处方，会把候选和临床决定混用，并绕过已有确认与校验。
- 只核对引用 ID 或展示链接，无法证明条款适用、病例支持或限定语未被删除。
- 将否定语义当作结构错误重试，会诱导同一候选改为通过；将目录默认值补入处方会掩盖缺少依据。
- 引入通用抓取服务或向量库，增加维护与内容许可边界；免费全文增量使用独立本地 SQLite，不改变生成和临床操作的归属。
- 只用 Encounter 版本、字符串身份或重新挂载编辑器，无法覆盖独立草稿变化、身份往返和未保存输入保护。

## Consequences

来源覆盖限于实际取得的条款，无法据此承诺全病种或全面药学质控。相同模型的独立请求和确定性目录、身份校验能阻止明确不一致，不能证明所有医学判断正确；医生仍需核对适用性并作最终确认。

建议更新与临床草稿分开持久化，复用当前 SQLite、outbox、授权与 Command。大病例的完整来源清单、无损打包、轻量目录、分批读取、核验与预算由[分批证据读取决策](2026-10-15-recommendation-context-budget.md)拥有；必要输入仍不能完整容纳时明确缺证，不截断来源或限定语。

验证由公开 HTTP、真实 SQLite 与 DSH Provider 网络边界拥有来源、目录、否定、授权、版本、失败和恢复矩阵；Web 真实入口与 React 18/19 ShadowRoot 合同拥有采纳、编辑保护、缺项及人工正式确认。原生宿主和真实模型样本的证据范围见[测试策略](../../../../docs/testing.md#end-to-end)。
