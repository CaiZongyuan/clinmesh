# Agent Note: Agent 操作反馈与编辑控制边界

Status: implemented

## Problem

DSH 原生 Session 可以操作 ClinMesh 表单并发起人工审阅，连接可用却不能说明正在执行哪个动作。读取持久草稿也不能代表人工尚未保存的输入。任务背景见 [issue #108](https://github.com/CaiZongyuan/clinmesh/issues/108)。

## Decision

页面 Tool 包装器从真实授权、动作返回和独立审阅结果发出调用级事件，Web 视图拥有目标映射和短暂反馈。上下文清理只撤下视觉状态，不声称取消业务请求；主动导航与选择只向明确目标转移完成反馈。执行回执不能确认时保留未知语义，不以动画结束推断业务成功。

问诊反馈在执行事件到达时记录当前可见视图已挂载的消息 ID，后续按本次调用的临时基线识别新气泡，避免把旧回复误标为新回复。该基线不保存消息内容，也不是业务归因或并发编辑保护。目录弹窗使用自身的 Portal 层承载边框，避免页面反馈被遮挡；弹窗存在时只强调其中的目标，关闭后恢复页面目标。

表单 owner 注册结构化当前输入，页面读取只合并同页同病例且仍挂载的表单。未保存编辑不复制到服务器或第二份客户端业务状态，也不开放 DOM 查询工具。Tool 描述约定先读再按意图决定覆盖沟通，正式 Command 的既有人类审阅仍然独立。

## Alternatives considered

- 从连接状态或模型 transcript 驱动动画：连接空闲时也可能 active，模型文本不能证明动作发生，且会复制 DSH 的会话责任。
- 锁定人工输入并引入覆盖授权状态机：需要额外的并发、恢复与所有权合同，超出当前协作边界；仅有视觉提示也不能承诺防覆盖。
- 为动画延迟动作或模拟逐字输入：会改变业务时序并制造不真实进度，快速动作直接展示完成结果。
- 通过任意 DOM 快照读取输入：缺少可靠的岗位与患者边界，改由已有业务表单明确声明结构化值。
- 总是强调最后一条消息或提高页面覆盖层的全局层级：前者在等待新回复时会误标旧消息，后者可能把背景页面边框绘制在模态框之上。临时消息 ID 基线与弹窗内覆盖层分别限定这两个视觉边界。

## Consequences

用户可以在操作期间继续编辑，但没有独占编辑、自动合并、并发编辑防覆盖或持久来源追踪。页面、病例、会话和 Surface 生命周期共同限定反馈；旧结果不能污染新页面。React 18 与 19 共用普通 hooks，浏览器合同覆盖焦点、完成淡出、独立等待与人工批准后的提交。完整操作与失败行为由[能力参考](../../../../docs/agent-capabilities.md)拥有。
