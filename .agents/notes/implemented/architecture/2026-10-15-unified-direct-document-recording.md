# Agent Note: 十字段统一来源直接记录

Status: implemented

## Problem

病历字段与直接记录扩展新增家族史、过敏史并取消逐条核对；统一来源扩展支持医生补充、报告和八字段，但保留待采纳建议及来源界面。两者分别重建同一增量表，直接采用任一侧会遗漏字段或来源，存量开发库也可能无法升级。

## Decision

患者回答、带原生输入证明的医生补充与固定版本报告共用持久来源、任务、outbox、独立语义校验和共享 Command，覆盖十个病历字段。家族史与过敏史独立分类；体格检查、评估、处置、随访只接受明确医生来源。正式过敏记录、诊断、医嘱和签署仍保持原授权。

通过校验的内容直接记录，定向替换有效自动片段；人工正文与未保存输入受到保护，人工内容的更正或矛盾追加并保留来源及待核实措辞。页面显示正文、整理状态和字段变动提醒，不恢复来源、应用、忽略、核对、撤销入口。来源关联、历史拒绝与逆操作数据仍保存在后台；本决策部分取代[统一来源决策](2026-10-14-doctor-full-document-recording.md)的核对交互，沿用[直接记录](2026-10-14-consultation-direct-recording.md)与[未保存合并](../bug-fix/2026-10-14-consultation-unsaved-summary-merges.md)规则。

签署预览在后台固定 Consultation 版本及来源数量，提交时拒绝已变化的快照；不要求医生额外勾选。准备冻结在途整理，取消恢复原身份和未完成来源，正式签署保留责任、完整性、令牌、期限及版本校验。

已存在的三份分支迁移保持名称与 SQL 校验和。排序位于两份 `0061` 之前的过渡迁移先持久保存增量及原 rowid 顺序，避免旧五字段约束拒绝主线医生或报告来源、旧八字段约束拒绝家族或过敏史。后续迁移恢复十字段表和统一来源外键，再按新来源索引重新排队旧有效 pending。迁移全部完成后才开放 runtime，过渡表随最终迁移删除；重启可从已提交的迁移继续，不读取原始患者库或修改既有校验记录。

## Alternatives considered

- 只选择五字段或八字段实现：分别丢失全病历整理或独立病史字段。
- 恢复待应用与来源核对界面：与已确认的直接记录和变动提醒交互不符。
- 改写已执行的迁移或重建演示库：破坏校验和、来源关联、任务身份与既有数据。
- 只新增最终扩表迁移：中间两份旧迁移仍会因字段 CHECK 或来源外键拒绝另一分支的非空数据。

## Consequences

升级验证覆盖主线来源库、独立字段开发库与更早的患者来源库，检查非空数据、顺序、Grant、模型绑定、回执、来源和外键完整性。HTTP 覆盖十字段、医生证明、报告快照、暂停恢复、重启和签署；Web 与 React 18/19 合同覆盖直接正文、无来源入口、变动提醒及人工编辑保护。自然语言忠实性仍依赖独立语义核对，来源归属不能替代医学质量判断。
