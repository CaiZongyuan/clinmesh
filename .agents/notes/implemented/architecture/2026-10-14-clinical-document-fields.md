# Agent Note: 独立家族史、过敏史与字段内建议边界

Status: implemented

## Problem

独立病史字段需要进入保存与不可变签署链，而旧文书没有这些章节。继续把过敏自述放进既往史会让新增字段缺少可审阅的来源。字段内建议还需在窄分屏里与正文明确区分。

## Decision

家族史、过敏史是可缺失、可为空的病历文本，最大 4,000 字，不增加签署必填项。缺失和空值均表示未记录；明确阴性只能来自医生输入或患者有依据的陈述。新签署件使用 `family-history`、`allergy-history` 章节编码，体格检查标题统一为“体格检查”；读取继续按稳定编码恢复，不改写旧 Composition、Bundle 或 Provenance。

新病史总结分别定位家族史、过敏史，既往史保留疾病、手术和用药。新增 SQLite 迁移只扩展建议字段 CHECK，保留所有原有来源、状态、锚点、逆操作和顺序。旧过敏建议保留原字段，不搬迁已应用正文。过敏史文本不等于正式 AllergyIntolerance，不改变正式用药过敏校验。

字段内建议面板以标题、待处理计数、边框、内边距和主题语义背景区分正文。待应用建议与旧未核对内容展开，已应用及历史默认折叠。更正、补充和冲突显示当前片段及拟应用内容，应用只影响所示片段；来源、未保存输入、版本与签署保护沿用[字段内建议决策](2026-10-13-consultation-field-suggestions.md)。规格及验证入口见[正式规格](../../../../docs/spec/2026-10-14-clinical-document-fields.md)。

## Alternatives considered

- 新字段签署必填或自动补“无”：会把缺失资料制造为临床阴性，也阻断存量草稿签署，拒绝。
- 迁移旧过敏文字与建议到新字段：旧混合片段没有可靠的可分割语义，且可能改变已核对正文与撤销范围，拒绝。
- 只增加背景颜色或继续重复字段名称：无法稳定表达正文、建议和历史的层级，主题与色觉差异下仍不清楚，采用文字和结构边界。

## Consequences

新字段沿用同一共享 Command、CAS、预览和审计链。旧文书可保持章节缺失，新文书保留明确录入或清空状态。模型生成与独立核对都需采用五字段分类；字段内面板增加高度，长内容通过正常页面滚动到达，不能压缩正文或将待处理事项折叠隐藏。
