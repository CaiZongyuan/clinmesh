# Agent Note: 实时质控限于本次就诊，自动记录按需说明未完成内容

Status: implemented

## Problem

实时质控随问诊、编辑和病例读取反复建立快照。自动枚举来源历史和本院完诊病历全文，会让少量本次问诊携带数百条旧资料，在调用模型前就超过预算；批量 SQL 只能缓解读取成本，不能消除不必要的输入。自动记录又以任一未恢复的旧失败决定整体状态，问诊栏长期显示失败且逐来源重复列出错误，妨碍正常录入。

本决策取代[原质控输入决定](2026-10-15-doctor-document-quality-control.md)中自动读取全量既往资料的范围；该文继续拥有身份、授权、版本与兼容边界。[无逐条确认决定](2026-10-18-advisory-quality-without-confirmation.md)继续拥有医生直接编辑的交互。当前需求由[质控规格](../../../../docs/spec/2026-10-15-doctor-document-quality-control.md)和[低延迟记录规格](../../../../docs/spec/2026-10-15-low-latency-document-recording.md)拥有。

## Decision

实时质控只检查当前正文、本次问诊患者回答、医生明确补充、已发布报告，以及当前过敏、就诊表现、分诊和已确认诊断摘要。不自动读取来源历史、本院完诊病历全文或全量既往诊断清单；在本次来源中主动补充的既往史仍按原文检查。范围说明随结果展示，模型指令不因未提供既往资料而要求补录，也不声称完成全历史检查。历史浏览、助手工具和诊疗建议继续使用各自的授权读取边界。

删除实时质控的历史读取依赖，避免在病例切换、轮询和后台重新核对时无意恢复全历史装配。完整本次来源继续进入固定快照、输入指纹和引用校验；输入确实超限时仍标为不完整，不截取前若干条或放宽预算。新范围改变输入指纹，旧结果变为过期，旧任务不能发布为当前结果。

问诊与病历共用的自动记录入口在后台失败时只显示入口名称，不常驻“整理失败”，也不逐来源展开错误列表。医生主动展开后获得一条部分内容尚未写入、原文已保存的说明、进度与重试入口。公开状态、安全错误码、失败来源与签署快照保持真实，不清除旧失败或改成成功；授权连接恢复和用户主动操作失败仍反馈，已写入片段的尚未核对及具体疑点也继续展示。

## Alternatives considered

- 继续把全部历史送入实时质控，再扩大预算或延长模型等待：使实时录入的成本随患者历史增长，没有解决当前检查的范围问题。
- 静默截取历史前若干条：既不能保证相关性，又容易让医生误以为全部历史已经检查。
- 只删除报错而把后台状态设为成功：丢失未写入事实和恢复能力，不能解决自动记录可靠性。
- 按错误类型去重但仍在问诊旁挂失败：保留了正常录入中的持续干扰，不能满足安静辅助的要求。

## Consequences

实时质控不负责发现只存在于未提供旧病历中的遗漏或矛盾；医生明确补充相关事实后才进入本次检查。当前过敏摘要仍保留，不能将本次范围误解为禁止使用任何已知临床信息。模型超时和来源校验失败的可靠性问题并未因界面安静而消失，仍须从后台指标与真实模型验收评估。

公开 HTTP 与真实 SQLite 回归使用 596 条历史观察和 210 条既往诊断，验证历史不进入实时输入、本次患者原文进入模型、实际检查完成及有界 SQL；实际本次正文超限仍不调用模型、不截断保存内容。Web 真实入口与 React 18/19 ShadowRoot 回归验证超时、校验失败、刷新、合并说明和恢复入口，不以模型替身证明真实延迟或临床准确性。
