# Agent Note: 人工病史冲突比较与句级核对

Status: implemented

## Problem

[规格](../../../../docs/spec/2026-10-08-consultation-auto-record.md)只允许无冲突内容直接进入草稿，要求医生决定与人工病史冲突的修订。仅给辅助模型提供患者原话与自动增量，无法识别纯手写病史；人工改写过的自动片段也可能与其原始引文不同，比较原话会遗漏当前矛盾。

## Decision

提取输入分别提供患者 Consultation 文本、自动来源历史与 `manualHistory`。人工比较上下文包含已归人工的片段当前文本，以及草稿中未被现有增量范围覆盖的手写句子；仅限主诉、现病史和既往史。人工内容是不可信比较上下文，不能成为新增病史的引文或来源；输出仍通过既有完整患者引用校验。

归属已持久化的片段沿用其增量标识，未归属的手写句子用字段、UTF-16 范围与原文摘要生成 `manual:` 目标绑定。模型的 `targetAdditionId` 必须匹配此次输入中的同字段目标，不能自由指定文本范围。每条人工冲突保留为 pending，无关新增继续追加。模型仍负责语义分类，确定性绑定与来源校验不能保证模型识别全部矛盾。

可写增量应用前，在共享 Command 事务中重新核对涉及字段的人工比较上下文。提取期间人工上下文变化时丢弃本次可写结果，复用持久 outbox 的最多三次自动尝试，以最新草稿重新提取；持续变化后进入可显式重试的失败状态，不追加旧分类结果。其他字段的修改不阻止应用，当前任务代次仍沿用已绑定模型。只留下待核对冲突的结果不写正文，沿用范围失效保护。

纯手写目标的范围和当前文本复用 pending 建议已有的 `start_offset`、`end_offset`、`current_text`，不创建伪造患者来源的人工增量，也不增加数据库迁移。提取期间和之后的草稿编辑都移动其范围；重复前缀使字符差异误判目标被修改时，只有原句在编辑前后均完整且唯一存在才恢复精确范围。目标自身被编辑或与新限定语连成同一句时清除范围，使 `reviewable` 变为 false，旧建议只能进入人工重新核对。无关独立句子的编辑和自动追加不使目标失效，服务重启后绑定仍可用。

接受使用既有共享核对 Command、Encounter 与草稿版本及幂等键，只替换仍完整匹配且保持句界的当前单句，结果归人工所有；人工扩写成多句的已有片段和其他无效目标不写正文，需医生编辑原文，不能按旧引文句数允许整段替换。忽略保留来源与拒绝证据。调用方提交建议的 `id`，将 `targetAdditionId` 视为不透明服务端绑定，不假定所有目标都对应公开增量列表中的另一条记录。

## Alternatives considered

- 将同字段所有新增一律置为待核对：保护了手写内容，但会阻止无关信息直接追加，违反局部保护要求。
- 为人工句子伪造患者来源增量：混淆手写草稿与患者自述，破坏来源可信边界。
- 每次接受时重新搜索原文：重复句子或后续编辑可能误替换，因此持久范围随编辑移动，范围失效后要求重新核对。
- 增加一套人工目标表或公开文本范围写入合同：既有 pending 范围可表达绑定，新增状态与外部范围写入没有必要。

## Consequences

手写病史参与冲突判断但不扩大患者事实来源。公开 HTTP/SQLite 回归覆盖来源隔离、同字段无关新增、局部接受、服务重启、幂等回执、提取期间和之后的人工修改、并发新增人工上下文、有界重试与恢复、限定语及多句保护和伪造目标；真实 Web 使用原有原文展示、accept/ignore 与保存门禁。Operation Catalog 与医生 Skill 同步说明人工目标及失效恢复。
