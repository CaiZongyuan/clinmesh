# Agent Note: Surface 手动全屏与容器响应式

Status: implemented

## Problem

DSH 原生右栏占用空间后，应用最小宽度与会话最小宽度可能无法同时满足。自动全屏会隐藏用户正在操作的宿主区域。应用内部共用整个 Surface 的断点又无法表达导航、候诊列和上下文列各自消耗的空间，导致病历被挤压。任务合同见 [issue #84](https://github.com/CaiZongyuan/clinmesh/issues/84)；此决策取代[原生 Surface 集成](../architecture/2026-08-30-dsh-native-clinmesh-surface.md)中的自动全屏回退，保留其状态与权限所有权。

## Decision

ClinMesh 默认使用左右分屏并显式选择通用 Surface runtime 的 `shrink` 策略。空间不足时应用与会话按最小宽度比例分配可用横向空间，不上下排列，不修改 DSH 原生侧栏状态，也不覆盖用户保留的分栏尺寸。足够宽时恢复原分栏偏好。全屏通过 registry 的布局接口手动切换，ClinMesh 左侧导航栏底部提供全屏与返回按钮，窄屏时随导航进入抽屉，不占用顶部独立工具栏；登录页没有导航栏时，登录卡片底部保留全屏返回入口；同一个应用实例保持挂载，保留病例、页面与草稿。

导航、医生工作台和病例详情分别观测自己的容器断点。窄导航通过抽屉访问，候诊列表与病例详情切换显示但保持挂载，病例上下文按需通过抽屉访问。病历内部表单和生命体征使用所属内容区的容器查询；表格与标签栏保留局部滚动。

布局解析在 runtime 纯函数入口测试。应用测试使用真实 React、ShadowRoot 和浏览器帧，验证容器连续缩放、导航及面板入口、手动全屏往返和草稿保留。业务工作流测试继续拥有数据、临床动作与状态机合同；布局浏览器 fixture 不连接业务服务。DOM 导出的虚拟时间不能证明 ResizeObserver 更新，动态布局测试以 Playwright Core 驱动系统 Chrome。

## Alternatives considered

**继续自动全屏或改成上下分区。** 两者改变用户选择的宿主布局，且自动全屏会隐藏正在使用的原生侧栏，因此不采用。

**只降低应用最小宽度。** 固定多列仍可把中间病历压缩成不可操作的区域，不能替代应用内部自适应。

**由 ClinMesh 直接修改 DSH 侧栏状态或复制宿主 DOM 控制。** 会形成第二个状态 owner，并依赖插件初始化顺序；宿主几何仍由通用 Surface adapter 处理。

## Consequences

极窄空间的分屏栏仍受物理宽度限制，用户可手动全屏或收起 DSH 侧栏获取更多空间；应用不会替用户改变布局。布局模式切换与容器缩放不进入医院 Command、Query cache 或业务持久化。
