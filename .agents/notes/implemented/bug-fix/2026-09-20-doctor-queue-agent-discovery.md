# Agent Note: 医生病例选择的队列发现

Status: implemented

## Problem

医生 Surface 的病例选择 Tool 要求当前已加载队列中的 `caseId`。只有当前病例详情和队列总数时，Agent 无法发现另一病例的合法标识。医生工作台还区分包含待诊与在诊的队列和当前标签筛选列表，选择目标后需要保持标签与病例状态一致。关联 [issue #108](https://github.com/CaiZongyuan/clinmesh/issues/108)。

## Decision

通用页面读取和医生病例读取共享选择 Tool 已有的医生队列 Query 结果，包含条目与分页信息，不另设缓存或扩大服务器查询范围。医生读取保留现有病例详情字段，新增队列字段。病例选择校验队列成员后，根据目标状态切换待诊或在诊标签，再选择病例。字段与范围由[能力参考](../../../../docs/agent-capabilities.md)拥有。

## Alternatives considered

- 从患者姓名猜测病例标识：姓名不唯一，不能形成可验证的选择参数。
- 增加任意患者查询或遍历全部分页：超出当前页面工具的队列范围，不是修复发现缺口所必需。
- 只返回当前标签的筛选列表：与现有选择 Tool 接受的队列不一致，无法发现另一分组中已经可选的病例。

## Consequences

真实 WebApp 回归分别在普通 DOM 和 ShadowRoot 中执行读取、按合成患者身份选取 `caseId`、切换和重新读取，验证目标病例与标签一致，并确认队列外标识仍被拒绝。接口返回已加载队列页，不承诺全量患者搜索或跨页导航；病例详情继续通过既有授权接口读取。
