# Agent Note: 诊疗建议的记录级筛选与有限限流恢复

Status: implemented

## Problem

按证据包选择历史时，一条相关记录会连带保留同包的其他记录，筛选结束后仍可能超过生成预算。让模型复制完整哈希身份还会增加输出并产生错误编号，导致格式修复后仍无法完成读取。模型桥将上游限流归为通用不可用时，Provider 与 outbox 的重试又会叠加，放大等待和请求数量。详细需求由[诊疗建议规格](../../../../docs/spec/2026-10-13-doctor-guideline-recommendations.md)拥有。

## Decision

全部资料可容纳时沿用直接生成。溢出时按单条完整原记录筛选，所有本次及必读安全资料继续进入每批。记录使用本次完整输入内唯一的短句柄；历史与目录筛选的模型可见 JSON Schema 均枚举本批合法编号，服务端另行拒绝重复编号，再映射回真实来源身份。模型只选择记录，不改写或裁剪其内容；完整筛选结束后，所选原记录通过现有 packer 重新无损打包，生成与独立核验引用实际重打包的证据。

筛选前重新读取原历史并与 snapshot 的全部历史包核对，变化后停止。输入策略版本进入指纹及筛选缓存键，完整未选来源也继续参与失效判断。缓存仅保存稳定的单条证据身份；短句柄在当前输入中重新绑定。持久审计同时保留原包、已读记录身份与来源条目、短句柄、所选记录和最终证据包身份，能够从最终引用追溯原文。

历史筛选仍最多八批、两并发，每批最多一百条完整记录。必要资料、所选记录或最终核验仍无法容纳时明确缺证，不按数量截掉相关记录。诊断参考目录的模型投影移除 CSV 来源定位串，保留完整临床身份、名称、版本、状态和领域；原始目录与定位继续参与指纹和服务端最终编码归一化。来源授权、必读分类、完整目录覆盖与临床确认继续由[原分批读取决策](../architecture/2026-10-15-recommendation-context-budget.md)拥有；本文取代其中按整包选择历史的规则。

DSH 模型桥只根据 `RATE_LIMIT` 及有界 `providerRetryAfterMs` 返回 HTTP 429、`MODEL_RATE_LIMIT` 和可选等待时间，拒绝传出私密错误原文。Provider 从一次 `completeJson` 开始固定截止时间，路由解析、初次生成、格式修复及限流等待共享该时限；每次实际生成只向宿主传递剩余预算，不足宿主最小一百毫秒时不再调用。HTTP 传输另留一秒收取安全超时响应，不增加模型执行预算。此规则取代[自动病史调用决策](2026-10-08-consultation-model-output-budget.md)的独立修复预算。

同一次结构化生成及格式修复最多共用一次限流重试；没有服务端提示时等待一秒，剩余预算不足时直接返回限流。取消与宿主卸载停止后续调用，认证、配额及未知失败不触发限流重试。

有限重试后仍为 429 时，建议任务直接结束为明确失败并保留草稿和静态限流说明；不再叠加 outbox 重试。新的人工作业沿用当前模型选择，临床采纳与正式确认边界保持有效。

## Alternatives considered

- 继续按整包选择，无法排除同包内明确无关的记录，也会浪费生成与核验容量。
- 通过扩大单次预算、截断原文或取最近若干条制造成功，会越过传输和临床完整性边界。
- 用改写摘要替代原文，会改变本任务对完整事实、限定语和来源的要求。
- 静默切换 Provider 或模型，会改变用户选择，也不能证明原有服务恢复。
- 无限重试或让 Provider 与 outbox 分别重试，会增加上游压力和等待；一次有限恢复保留了可取消、可观察的失败终点。

## Consequences

单条筛选减少同包放大和长编号复制，但临床相关原文仍可能超过预算；有限重试也不能保证持续限流的上游恢复。真实模型验收必须分别记录读取、生成、核验和最终状态，最小连通性或模型替身结果不证明大病例可用或医学质量。验证入口由[测试策略](../../../../docs/testing.md)拥有。
