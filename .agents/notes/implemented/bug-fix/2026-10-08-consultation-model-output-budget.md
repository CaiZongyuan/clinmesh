# Agent Note: 自动病史结构化修复与调用预算

Status: implemented

## Problem

DSH 的文本模型可能在严格 JSON 对象中附带 `$schema` 注解，导致有来源依据的病史整体被拒绝。无效输出再生成没有收到校验反馈，首次响应、修复、持久任务和宿主各层又共同受 60 秒上限约束。后台把错误统一归类并重排，医生只能看到长时间处理中。

本决策补充[持久增量边界](../architecture/2026-10-08-consultation-history-increments.md)，保留其来源、授权与共享 Command 不变量。

## Decision

DSH Provider 仅移除顶层字符串 `$schema` 注解，其余业务对象保持完整校验；未知属性、非法类型和病史来源校验仍拒绝。最多修复一次，在同一路由、同一原始数据上反馈有界的校验 code/path，不回传原始失败输出或模型私有消息。修复成功后仍由共享 Command 校验患者逐字来源、编辑归属、签署状态及幂等。

每次模型生成具有独立的配置预算，可信 loopback 请求把该预算传给宿主。宿主默认兼容旧请求的 60 秒，上限十分钟；Server 的 DSH 默认每次生成 120 秒，可由 `CLINMESH_AI_TIMEOUT_MS` 在 100 毫秒至十分钟之间覆盖，OpenAI 默认仍为 60 秒。HTTP 传输另留一秒收取安全超时响应。持久任务总预算为三倍「单次预算加一秒」，覆盖路由解析、初次生成和一次修复，outbox lease 再留五秒；宿主断开或卸载取消实际模型流。

自动病史任务保存静态安全错误码，并通过版本化 `doctor.case.get` 的 `consultationRecording.failures` 返回来源和是否正在自动重试。超时、认证拒绝、请求／响应过大与耗尽的结构化修复直接收敛为待更新；暂时调用失败及记录服务的输出／来源拒绝最多尝试三次，重排期间仍显示原因。成功清除失败状态。服务关闭在剩余尝试预算内保留任务供重启处理，不把生命周期取消当成模型超时；最后一次尝试被关闭打断时转为待更新，避免 outbox 已终止但病例仍显示处理中。已有失败任务仍保持待更新，不因打开病例自动回写；历史补录和显式重试由对应恢复功能拥有。

## Alternatives considered

- 将业务 schema 改成宽松对象：会掩盖未知业务字段；只规范化已知注解更容易保持安全边界。
- 无效结果原样重试或在病史中直接写入自由文本：没有修复反馈，也破坏来源和结构约束。
- 仅延长 `.env` 或共享整个请求的超时：宿主和持久任务仍可能提前中止，首次响应也可能耗尽修复预算。
- 所有模型错误自动尝试三次：慢速超时和已经用尽修复次数的输出会放大等待，无法给医生及时、明确的失败状态。

## Consequences

有效病史仍须通过来源与人工编辑保护。较慢的 DSH 模型可以完成初次生成或有界修复，持续失败会明确停在待更新，患者回答独立保存。运维可从安全错误码区分访问、超时、输出、来源和编辑状态，无需持久化模型原始输出。

确定性回归通过真实 loopback 桥接、问诊 HTTP、file-backed SQLite 和病例 Query，覆盖 `$schema`、未知业务属性、慢速输出修复、宿主取消、失败持久化、重复消费及人工编辑保护。Playwright 覆盖失败收敛与刷新，并在 React 18/19 ShadowRoot 合同中核对提示。真实模型调用与原生 DSH 入口验收单独记录，网络替身不能证明提取质量。
