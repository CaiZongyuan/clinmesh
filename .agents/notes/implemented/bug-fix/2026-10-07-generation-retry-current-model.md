# Agent Note: 人工重试采用当前模型并保留本次尝试绑定

Status: implemented

## Problem

问诊先保存医生消息，再生成患者回复。旧模型不可用时，人工重试复用医生轮次的原模型绑定，改设置仍无法恢复；界面禁止越过未回答的消息继续发问。检验申请同样在人工重试时复用旧请求绑定。问诊还把认证、调用失败与超时统一转换成通用服务错误，使用户难以采取有效恢复操作。

## Decision

新的人工重试是独立生成尝试，开始生成时采用当前 ClinMesh 模型。问诊以受信 Actor 与幂等键区分重试意图，检验以共享 Command 推进后的申请版本区分尝试并保存到 outbox。相同意图的传输重发、内部修复、后台自动重试和进程恢复保留本次已解析模型。医生消息与患者回复的提交幂等键保持原轮次身份，已完成回复与报告快照继续复用。

本决定部分取代[DSH 模型绑定决策](../architecture/2026-10-07-clinmesh-dsh-model-binding.md)中的人工重试规则；该 Note 继续拥有其余桥接与来源决策。当前实现合同由[系统架构](../../../../docs/architecture.md#103-场景定义)拥有。

问诊只传递封闭的模型错误码和固定安全消息，界面按错误码显示认证、服务失败、超时、输出无效或大小限制提示，保留未答消息供用户重试；未知异常继续使用通用提示。

## Alternatives considered

- 所有人工重试沿用原模型：来源稳定，但旧路由不可用时会阻塞问诊恢复，即使用户已选择可用模型。
- 每次网络重发或自动重试读取设置：同一尝试会混用模型，后台切换和重启也会改变来源。
- 改设置时删除或覆盖既有绑定：破坏已执行尝试的恢复依据，还会影响正在运行的任务。
- 自动重生成已有成功结果：改变已冻结业务事实，且无法表达用户是否希望重新生成。

## Consequences

用户保存新模型后，可以通过已有人工重试入口恢复失败问诊和检验；患者档案与目录补全继续通过新生成任务应用新设置。后台自动重试不受设置切换影响，正在执行的请求保持原模型。旧绑定无需数据库迁移，新的尝试拥有独立绑定。

验证覆盖真实 HTTP 桥接与 SQLite 的设置切换、同意图重发与已完成回复复用，检验人工重试的新路由及结果来源，以及问诊错误分类不泄漏原始 Provider 消息。CLI 漂移测试验证医生使用新意图恢复、相同 key 重发不再调用模型；浏览器合同覆盖问诊重试提示。
