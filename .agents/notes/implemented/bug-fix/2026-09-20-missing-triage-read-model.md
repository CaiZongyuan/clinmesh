# Agent Note: 缺失分诊记录的医生读取边界

Status: implemented

## Problem

已持久化的门诊病例可能没有分诊记录。医生队列与详情若强制从分诊生成临床表现，会让单条缺失记录阻断整页读取；用版本冲突文案解释所有业务冲突也无法准确指导处理。

## Decision

医生队列与病例详情保留病例身份、状态、分页计数和已有临床事实。没有分诊记录时，`presentation` 显式返回 `null`；有分诊时继续按完整 schema 校验，不吞掉无效数据错误。页面用缺失提示代替主诉与体征，病历初始值只采用已存在的可见证据，已保存草稿优先。读取不写入分诊、不回退病例状态，也不扩大接诊 Command 的前置条件。

普通业务冲突提示当前状态或前置条件不满足；具有结构化版本或状态上下文的冲突继续展示具体信息。接口的空值合同由 `doctor.queue.list`、`doctor.case.get` 的 Operation Catalog 输出 schema 拥有，医生 Skill 说明消费规则。

## Alternatives considered

- 排除缺分诊病例：会隐藏已接诊患者，破坏队列完整性和分页语义。
- 填充默认主诉或正常体征：将未知信息伪装成临床事实。
- 从 Case Truth 或 Patient Persona 自动补写分诊：混淆仿真输入与实际护理记录，还会改变审计来源。
- 仅调整错误文案：仍无法读取正常病例，病例详情也继续失败。

## Consequences

所有消费者必须处理空临床表现。缺失分诊不会自动修复持久数据，也不代表其他诊疗前置条件已满足。HTTP 回归覆盖正常和缺失记录共存的队列、分页与详情，Web 回归覆盖队列、病例侧栏、问诊和空白病历初始值。
