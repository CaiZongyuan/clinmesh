# Agent Note: 已知病史与隐藏诊断的文字边界

Status: implemented

## Problem

患者档案、管理员编辑与患者问诊回复共用隐藏诊断保护。本次隐藏的“2 型糖尿病”会扩展为“糖尿病”简称，但简单子串匹配把可见既往史中的“糖尿病前期”也当成泄漏。另一种误判是既往 Condition 已明确记录“2型糖尿病引起的神经病”，却因其编码和完整病名不同于本次基础疾病，拒绝患者陈述已经获知的糖尿病。

## Decision

三个入口共用同一文字检查。检查只豁免由可见 Condition 完整病名覆盖的那一次提及；同段其他位置或其他字段出现未知诊断，仍须拒绝。已知病名匹配仅忽略横向空白，保留全部标点与换行；括号、破折号等不能把不同短语拼成病名，来源病名自身包含的标点仍可原样匹配。匹配区间按全文归一化的前缀长度映射，避免跨标点的“一／二型”转换造成偏移。禁词按全文归一化检查，插入标点拆开未知诊断不能绕过拦截。已知泛称不能覆盖更长的未知子型。糖尿病术语扩展只识别明确命名 1/2 型糖尿病本身或“引起的”并发症记录，不从“糖尿病前期”、用药或检查值推断确诊。产品边界由[系统架构](../../../../docs/architecture.md#103-场景定义)拥有。

Patient Persona 按实际文本字段检查，避免 JSON 属性名和不同字段拼接形成命中。生成失败仍不保存内容，不创建成功修订，也不覆盖已有修订；人工编辑的明确强制保存与问诊的有界重生成保持原合同。

## Alternatives considered

- 关闭泄漏检查或仅建议换模型：前者暴露未知诊断，后者不能消除确定性的误判。
- 只要历史里含有诊断子串，就全局删除对应禁词：既往糖尿病前期会放行真正新增的糖尿病，同段中的另一处泄漏也会被放过。
- 依靠模型判断既往疾病关系：增加外部调用，且把保护边界交给不稳定输出。当前仅接受来源病名中的明确表达，不实现医学术语本体推理。

## Consequences

合成回归覆盖已知前期病名、已知并发症基础疾病、同段新增诊断、未知子型及诊断编码；HTTP 回归保持泄漏拒绝、不可变修订、人工编辑警告和问诊安全应答。仍然不识别所有同义词或疾病层级，也不根据检查、药物、家族史等间接证据放行诊断。失败任务的原始模型输出不持久化，不能仅凭错误码认定模型泄露，排查须同时核对可见史与隐藏术语。
