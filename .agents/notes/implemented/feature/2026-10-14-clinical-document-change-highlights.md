# Agent Note: 病历变动字段的延迟查看提醒

Status: implemented

## Problem

问诊整理直接写入草稿后，医生可能仍在问诊、检验或其他病例中。按后台完成时间立即淡出会让医生切回病历时看不到变化；整页高光又不能定位实际改动。当前需求由[病历字段规格](../../../../docs/spec/2026-10-14-clinical-document-fields.md)拥有。

## Decision

采用已确认 HTML 方案 B“贴近内容”的字段边缘局部流光和标签短提示。工作台按病例比较实际显示正文，累计变动字段的提醒代次，人工输入同步推进比较基线并只消退该字段的提醒。同值响应和初次读取不产生提示；自动记录、Agent 草稿保存和其他页面插入的检查摘要可形成提醒。

字段挂载后通过 IntersectionObserver 和页面可见性启动显示计时，离开可见区域或切走页面时取消；未查看字段保留到下一次展示。淡出完成只消退对应代次，旧回调不能清除新更新。病历标签提示尚有更新，不自动切换分区、滚动、聚焦或要求确认。计时和减少动效合同由规格拥有。

流光使用遮罩内的旋转渐变，几何由 CSS 容器单位计算，在 ShadowRoot 内无需向宿主注册自定义属性，也不改变输入框的尺寸、可编辑性或焦点边框。Web 和 DSH 共用样式。

## Alternatives considered

- 更新后立即计时：后台整理可能在其他分区完成，医生查看时提醒已经消失。
- 整个病历或每个提交字段都高光：不能区分真正变化、同值保存和当前人工输入。
- 把查看持久化为医生核对：重新引入已移除的确认语义；提醒只属于客户端视图状态。

## Consequences

提醒在工作台内跨分区和病例切换保留，刷新建立新基线，已签文书不保留草稿提醒。Query 继续拥有服务端状态，提醒不改变 Command、审计或正式签署合同。真实 Web 回归覆盖隐藏期间更新、字段定位、人工编辑和淡出；React 18/19 ShadowRoot 合同覆盖滚动后查看、流光、减少动效、主题、语言、字号和长文本。
