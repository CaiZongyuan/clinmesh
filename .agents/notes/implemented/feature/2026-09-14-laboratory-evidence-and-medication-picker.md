# Agent Note: 检验底账门禁与药品选择反馈

Status: implemented

## Problem

缺少合成结果底账的病例不能完成检验生成，签发后才发现该事实会形成无法通过重试恢复的申请。药品包装逐行展开与显式提交搜索使选择过程冗长。任务合同见 [#93](https://github.com/CaiZongyuan/clinmesh/issues/93)。

## Decision

检验草稿保存和签发都由共享 Workflow 校验底账。已发布服务要求病例物化，兼容老项目仍使用隐藏结果事实；缺少底账返回 `LABORATORY_GENERATION_UNSUPPORTED`。在途已发布服务请求缺少物化时，生成器返回 `INVESTIGATION_UNSUPPORTED`；请求不存在及兼容老项目的无物化回退仍返回空结果。

Outbox 只把 `INVESTIGATION_UNSUPPORTED` 判为确定性失败并立即记录生成失败。模型输出不合法及传输失败保留原重试次数。医生页面按持久化错误码显示原因，确定性失败没有重试入口，暂时失败可重试。

药品按现有临床产品键分组，每组一行，在包装下拉中默认显示首个可选包装。停用和已添加包装不可选；整组无可选包装时禁用该行。默认显示包装不创建处方行，仍需明确选择产品并确认加入。

药品搜索在输入停止 300ms 后请求，关闭弹窗取消尚未触发的请求。服务端按空白分词并要求全部命中：三字符以上的词用 trigram FTS，两字符及更短词用参数化 substring 过滤；含 FTS 条件时按 BM25 相关度排序，再用名称、编码和 ID 稳定排序。批准文号不进入搜索索引。此决策取代[目录 Dialog 决策](2026-08-31-doctor-clinical-catalog-dialogs.md)的药品显式搜索约束，诊断和检验保持显式提交。

药品弹窗通过 Table 的可选单滚动容器模式把两轴滚动交给有界视口，横向滚动条位于视口底部。其他 Table 调用者继续使用默认内部横向滚动。

## Alternatives considered

- 只在生成阶段拒绝：不能防止新增必失败申请，因此保存和签发都执行门禁，生成器仍处理已有在途请求。
- 所有生成异常立即失败：会取消不合法模型输出和临时请求异常的恢复机会，只对确定性错误提前终止。
- 保留显式药品搜索：降低短词扫描频率，但反馈依赖额外提交；采用防抖和有界分页，仍保留短词扫描的性能约束。
- 更改 Table 默认滚动：会改变所有表格调用者的布局，采用可选模式限制影响范围。

## Consequences

HTTP 回归覆盖两条检验入口、在途生成失败与老项目回退，以及搜索分词和相关度。组件回归覆盖包装禁用、选择确认、防抖取消、错误提示和重试可见性；滚动位置需由真实浏览器布局验证。没有增加持久化格式、AI 服务配置或药品分组合同。
