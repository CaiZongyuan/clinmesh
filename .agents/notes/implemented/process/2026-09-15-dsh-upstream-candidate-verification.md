# Agent Note: DSH 上游候选与验收分离

Status: implemented

## Problem

公开正式版、RC 和源码默认分支独立推进，直接更新日常 Profile 会把尚未兼容的组合投入使用。机器人重复创建 PR、覆盖人工适配，或者误认为自己的 PR 会触发完整 CI，都会使升级失去可追溯的验收边界。[Issue #92](https://github.com/CaiZongyuan/clinmesh/issues/92) 要求在 [#91](https://github.com/CaiZongyuan/clinmesh/issues/91) 的必要组件清单上自动发现并提交可验证的升级。

## Decision

发现、隔离验收与人工合并是三个独立步骤。发现只追加候选文件，npm 候选来自所有正式版与 `rc.N`，源码候选来自公开默认分支的完整 SHA；撤销版本、内容改变、非法响应或历史分叉都失败关闭。main 的上游锁拥有已验证基线，候选携带基线摘要和完整目标。目标分支与基线摘要决定升级分支身份，同一活动 PR 的后续更新以当前 HEAD 为父提交，Git ref 只允许快进。

普通 Actions 执行确定性的安装、构建和检查，不自动修复上游代码。候选在干净独立 checkout 中准备，宿主和 Profile 在新临时目录中安装；人工依赖或支持提交冲突时拒绝覆盖。只有全部自动检查通过才生成升级 checkout 的目标锁并追加提交。检查后的 HEAD 变化导致重跑，不覆盖并发人工提交。日常 Profile、凭证与医院数据库不参与升级执行。

发现工作流显式调用候选验收，并把自动状态与日志绑定到精确 commit，不依赖机器人 PR 的事件递归。人工追加提交由 PR 事件进入同一验收。自动通过与完整人工验收分别表达，PR 始终由维护者决定合并。操作与恢复细节由[部署指南](../../../../docs/deployment.md#dsh-持续升级)拥有。

## Alternatives considered

**发现后直接替换已验证锁或日常 Profile。** 网络成功不能证明插件兼容；隔离候选允许保留失败和人工适配，而不改变日常环境。

**重建或强制推送机器人分支。** 这会丢失维护者的适配。基于当前 HEAD 的追加提交保留其他文件，快进约束使竞争显式失败。

**仅依赖 pull_request 触发 CI。** `GITHUB_TOKEN` 创建的 PR 不保证触发其他工作流。显式调用复用验收 job 可以对机器人创建的精确 HEAD 运行检查，专用验证分支可实测权限与触发路径。

**让 Actions 自动修复并合并。** 模型凭证、业务判断和人工验收不属于普通定时任务。失败保留待适配状态，维护者追加代码与证据后决定合并。

## Consequences

受控 npm/GitHub adapter 测试覆盖候选、无更新、非法响应、权限与重复发布；独立安装和 Linux CI 证明实际构建及检查路径。自动 status 明确保留人工验收要求，不能被解释为原生 Session 与真实人工 review 已完成。临时安装与失败补丁保留以便恢复，需要维护者按目录归属清理。源码默认分支落后于支持提交时不会回退该支持提交，分叉需要人工协调。
