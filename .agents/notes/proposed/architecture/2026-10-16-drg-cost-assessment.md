# Agent Note: DRG 评估复用业务事实并固定数据版本

Status: proposed

## Problem

ClinMesh 当前以门诊闭环为主。医生端的住院费用提示需要同时读取临床事实、医嘱、收费、公开价格和支付规则；直接在前端按病名减药费，会把参考额变成固定诊疗限额，也无法解释分组变化、未记费项目或成本差异。PDF 和公开中选名单的存在不能证明已具备可执行分组器、院内有效价格或完整成本。

## Proposal

应用内合成住院评估已由[模拟实现决策](../../implemented/architecture/2026-10-18-drg-simulation.md)拥有；本文继续保存正式地区接入与复用已有临床、执行、账务事实的提案边界。

将方案中的评估能力作为现有模块化单体内的服务端只读计算职责：临床、处方、执行和账务 owner 继续拥有业务事实，评估结果引用其稳定标识和版本，不形成第二套可独立修改的费用账。开具仍经过共享 Command 的受信上下文、幂等和版本校验；界面展示费用进度，由医生结合临床需要判断。

外部目录、分组规则和公开报价延续全局 Reference 与本院业务数据分离的架构。原件与派生数据分开保留，运行时读取经验证的固定版本；本院项目、单位、收费与成本另做显式映射。模拟规则、外省报价、历史报价和未知字段持续保留各自身份，不能因为数据成功导入就转为浙江正式标准。

先验证独立交互与应用内合成住院评估，再验证目标地区的分组、支付和全病例数据。本文为待实施取舍，不发布新增接口、表结构或住院权限；具体契约随实施补充。产品行为、阶段与验收的唯一 owner 为 [DRG 设计方案](../../../../docs/spec/2026-10-15-drg-prescription-budget.md)，现有系统边界由[系统架构](../../../../docs/architecture.md)拥有。

## Alternatives considered

| 方案 | 未采用的原因 |
| --- | --- |
| 在前端按疾病名称维护固定金额并扣减处方 | 无法表达主次诊断、操作和规则优先级；其他科室费用及并发变更容易遗漏 |
| 在 DRG 模块复制一份收费账和处方状态机 | 临床撤回、记费、支付与成本发生时点不同，复制会造成重复计费和双向同步 |
| 让大模型直接决定病组、价格和剩余金额 | 不能提供可重复的分组和定点金额运算，来源检索也不能替代规则执行 |
| 先完成完整住院 HIS 与正式医保清算再验证页面 | 推迟了当前可独立验证的医生工作流程；同时仍无法省略本地规则与价格核验 |
| 把公开挂网价或历史中选价统一覆盖到院内价格 | 产品粒度、地区、时间、单位及价格类型不同，无法保证收费或盈亏口径成立 |

## Acceptance criteria

实施验收以[设计方案的验收条件和测试策略](../../../../docs/spec/2026-10-15-drg-prescription-budget.md#验收条件)为准，特别验证金额桶互斥、临床确认与推演分离、版本变化、冲销、幂等和病例隔离。没有完成目标分组器与当地支付参数验证时，保持模拟身份；未覆盖的价格与成本保持缺项。

## Risks

住院评估范围、目标统筹区、年度和正式分组器尚未确定。高精度单价、包装拆零、部分执行和后续预留替换可能造成舍入或重复计数；具体实现必须沿用业务 owner 的时点与稳定引用。当前参考价无法替代本院收费、实际采购及完整住院成本，正式对照还需要匹配字典和可复现的分组样例。
