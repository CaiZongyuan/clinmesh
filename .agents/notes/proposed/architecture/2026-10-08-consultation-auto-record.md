# Agent Note: 问诊病史自动记录归属

Status: proposed

## Problem

患者回答完成后当前仅刷新病例，DSH 虽可读取 Consultation Record 并调用草稿填写工具，但没有自动提取和保存触发。完整文书填写不能表达持续记录的增量来源与人工修改保护。

## Proposal

ClinMesh 在完整患者回答保存后主动编排病史提取，使用现有 DSH 辅助模型桥接。业务输入是 Consultation Record，宿主 Session transcript 和 Assistant reasoning 不参与。ClinMesh 拥有提取范围、来源校验、部分编辑保护、增量合并、持久处理进度及受审计 Command；DSH 拥有模型调用能力。已确认需求见 [规格](../../../../docs/spec/2026-10-08-consultation-auto-record.md)。

优先复用持久 outbox，使患者回复不等待整理，并能从失败或重启恢复。事件中的行动上下文必须来自服务端可信绑定，执行时校验与事件的 Workspace/Epoch、Scenario Run 及病例归属一致，不能直接相信客户端传入的身份。迟到结果重新校验草稿、人工修改和签署状态。

来源和编辑归属需在服务端持久化。自动内容以可追溯的增量组织；具体存储表示由实施切片决定。签署准备需要阻止后台修改待签草稿，并保留取消后恢复处理的途径。

## Alternatives considered

- 仅在 DSH preset 要求每次填写：依赖主会话 Agent 的后续工具调用与页面工具可见性，不能保证每个患者回答触发。
- 监听 DSH 全部 Session transcript：容易混入助手推理和非问诊内容，也重复宿主所有权。
- ClinMesh 新建自有模型配置：重复现有辅助模型能力，本次没有必要。
- 每轮重写整篇草稿：难以保护人工编辑、关联来源和撤销局部变化。
- 只在浏览器保存编辑保护：刷新、重连与并发入口会丢失归属，不能约束后台写入。

## Acceptance criteria

满足规格中的自动触发、明确自述、来源、增量提示、部分编辑保护、补录、恢复、隔离与签署要求。主要行为通过公开 HTTP/Query 和真实 SQLite 验证；真实 DSH 入口提供平台验收。

## Risks

模型可能臆造阴性或把医生提问当成患者事实，需要结构化输出和原回答来源校验。仅检查引用存在不足以保证语义正确，仍需确定性错误样本和真实模型验收。并发未保存编辑、签署准备冻结与旧 Epoch 结果必须有明确恢复合同。
