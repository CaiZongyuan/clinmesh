# 随问诊与检查结果联动的待开具清单原型

状态：本轮已确认先制作原型，尚未接入正式业务，也未批准将该页面布局用于生产。原型保存在 `prototype/recommendation-ready-to-order` 分支，保留 [v2](recommendation-ready-to-order-v2.md) 供对照。

打开 [v3 单文件 HTML](recommendation-ready-to-order-v3.html)，点击顶部“保存下一轮问诊”，停留问诊栏目观察诊断、检查检验和处方自动准备。进入相关栏目可以调整、移除、确认或开具合成项目；再点击顶部“模拟检查结果返回”，观察三类待办联动更新。顶部按钮只模拟既有资料保存、报告发布和接诊结束事件，不是新增问诊业务入口。

## 已确认的原型行为

1. 当前接诊病例的三类待办在后台准备，不依赖进入某个建议页面或点击“准备”。已保存问诊原文、医生保存的病历、已发布报告、已确认诊断和已开具记录变化，均会重新评估相关清单；连续变化合并处理。检查结果需要影响诊断、后续检查和处方，而非只更新检查栏目。
2. 自动准备限于当前接诊病例。切换诊疗栏目继续执行；切换患者暂停旧患者的新任务并保留草稿，返回时重新核对。支持暂停和恢复，接诊结束后停止。单文件仅在当前页面内存保存这些状态，重新加载会重置，不模拟服务端持久化。
3. 清单直接呈现待确认或待开具项目，不再增加单独采纳步骤。完整且核验通过的项目默认选中；医生可调整、取消或移除，按模块确认。正式业务仍需沿用现有目录、证据标准、服务端校验和必需确认，本文件中的“开具”只写入页面内合成记录。
4. 更新期间保留旧清单；该模块旧自动项暂不可开具，医生仍可编辑。未更新的其他模块可以继续操作。人工修改和移除不会被后台覆盖或复原；新结果与人工选择冲突时要求医生核对。
5. 已确认、已开具记录保持原样，新结果影响已有决定时显示短提醒和处理入口；是否调整或撤回由医生决定。原型只演示定位与核实保留，不模拟完整撤回流程。
6. 明确项目缺少必要字段时显示简短待补充提示，不能自动开具；推测性诊断和检查思路收进说明。主次诊断由 Agent 预拟、医生调整确认。沿用当前证据规则和免费来源范围，不承诺每次三类均产生可执行项目。
7. 默认只呈现清单和一行任务状态。依据、待核实思路、质控详情与工作记录统一在“依据与说明”内查看。失败保留草稿，旧自动项目等待核对，提供刷新；一个模块失败不影响其他已就绪模块。
8. 沿用既有问诊补问与病历整理方式，不添加“委托 Agent 补问”流程或病历字段整理状态。病历仅提供原有编辑和质控定位落点。质控无具体问题时隐藏；未完成检查不等于通过，状态只在说明内展示。有多个问题时默认一条短句和“另有 N 处”；点击问题切到字段、滚动、聚焦并突出问题原句，缺项定位空字段。核实保留不改写正文。

## 合成演示内容与边界

主流程以高血压复诊为例：初始问诊只支持诊断候选；下一轮透露续方和复查需求，准备检验与处方候选；发布血钾异常的合成报告后，新增诊断和后续检查候选，移出尚未手改或开具的自动续方候选，人工修改或已开具记录则保留并提示核对。该情节用于观察交互，临床项目、用法用量、目录及核验结果都是预设 fixture，不能作为诊疗方案或真实指南接入证据。

场景菜单包含从问诊开始、保留手改、已有开具记录、必要字段缺失、多处质控问题、质控未完成和单模块更新失败。可从队列切换两个合成病例，检查草稿隔离、任务暂停与返回恢复。

正式行为仍由[诊疗建议规格](../docs/spec/2026-10-13-doctor-guideline-recommendations.md)和[病历质控规格](../docs/spec/2026-10-15-doctor-document-quality-control.md)拥有；此文件只记录本轮原型范围，不改写正式规格。真实模型、后台任务、临床安全判断、证据检索、实际目录映射、持久化与正式 Command 均未接入。
