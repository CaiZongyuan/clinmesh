# 诊疗业务内嵌 Agent 与质控问题定位原型

状态：等待用户评估。原型保存在 `prototype/recommendation-ready-to-order` 分支，未接入真实业务。

交互主张：Agent 在诊断、检查检验和处方模块内准备本次待办，展示当前步骤及需要医生补充的信息；医生调整、移除或完成正式确认。依据、思路及 Agent 过程统一收在“依据与说明”中。问诊和病历自动整理沿用现有实现，本原型不新增委托补问或字段整理状态；病历页只作为质控定位落点。

质控没有具体问题时不显示主页面提示。检查未完成但没有问题提示时，同样保持主页面清爽；状态仅在按需查看的说明里呈现，不宣称检查通过。有问题时只显示一句简短提醒及“查看位置”；点击后切到病历、滚动到对应字段，聚焦并选中问题原文。“已核实，保留原文”只收起提示，不改写病历。

双击 [自包含 HTML](recommendation-ready-to-order-v2.html) 可运行。顶部场景包含资料齐全、项目待补充、已有手改、病历有一处问题、检查未完成但无问题提示。可点击“让 Agent 准备”观察当前业务模块的准备步骤；切换模块不会中断演示任务。所有数据及任务均为页面内合成演示，无网络请求或持久化。

已检查脚本语法，并用 `agent-browser` 核对默认说明收起、无问题与检查未完成时无质控横幅、问题跳转及原句选中、核实保留不改原文、业务内准备步骤、跨栏目任务继续、手改保留，以及 800 像素宽度无横向溢出。未见页面错误；这些操作未单独计时。真实服务、临床判断、目录读取和开具 Command 尚未接入。

后续正式需求仍由现有[诊疗建议规格](../docs/spec/2026-10-13-doctor-guideline-recommendations.md)和[病历质控规格](../docs/spec/2026-10-15-doctor-document-quality-control.md)拥有。此文件只保存原型意图和可观察交互，设计确认后再修订对应正式规格并实施。
